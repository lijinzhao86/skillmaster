# CLI（`skillmaster-cli/`）

两个 workflow，管的是两件不同的事。

| Workflow | 什么时候跑 | 做什么 |
|---|---|---|
| `cli.yml` | PR / push | `CLI changes` 判断是否碰了 CLI；碰了才跑 `Test and vet`（Go 版本取自 `go.mod`、格式检查、vet、测试）和 Windows 那个 job |
| `cli-release.yml` | **只在打 tag `cli/v*` 时** | 构建六个平台的包 → 校验和 → 检查几条不变量 → 传进 OSS 暂存区 → 提升到根 |

**合并不发布。** 发布只由 tag 触发，所以「上线」这一步是一个**人打 tag**。

## 发布时的几条硬规矩

- **tag 必须在 main 的历史里**，否则拒绝——不然可以从一个没合入的分支切出一版。
- **二进制里带着服务端地址**，job 会断言这一点（本地构建默认 `localhost:8080`，发布版必须是生产地址）。
- **先传暂存区，再提升**：包先到 `dl:<bucket>/releases/<版本>/`，核对九个对象都在、且与构建产物逐字节
  一致，然后才提升到桶根目录。
- **`version.txt` 最后写。** 它是「这一版正式上线」的标记；站点只向前走，这个标记就是判据。写它之前
  读一遍现有的标记，读不到就拒绝发布（不盲发）。

## 上线后从哪拿

`https://dl.skillmasterai.com` —— nginx 反代到 OSS 桶（桶本身不能绑自定义域名）。安装脚本
`install.sh` / `install.ps1` 也在这个地址下。

## 回滚

**站点只往前走。** 要回退不是把旧包传回去就行：`version.txt` 是判据，安装器按它挑版本。真要回退，
先想清楚怎么让标记与包一致——这一步没有现成的自动化。
