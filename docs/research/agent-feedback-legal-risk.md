# agent 自动提交反馈的法律风险：条文、场景与做法

> **核对日期**：2026-11-13。
> **用途**：决定 v63「提交前是否必须由用户确认」，以及隐私条款怎么写；为第 3 关的 ADR 提供事实底稿。
> **口径**：条文来自全国人大、国务院、国家网信办公开文本及官方转载；「解读」类只作线索，标 **[转引]**。本文**不下决定**。
> **不是法律意见**：具体措辞与合规方案由律师定。

## 三句话结论

1. **有风险，风险不在「agent 代用户操作」本身，在「没有可证明的告知—同意」。** 平台是个人信息处理者，处理前要告知、要取得自愿明确的同意；agent 自己按一下提交，不构成用户的同意。
2. **反馈内容不可预知**：可能含敏感个人信息、他人的个人信息、商业秘密，甚至不满 14 周岁未成年人的信息。**一般同意不够**，敏感信息要单独同意，向他人提供也要单独同意。
3. **最稳的做法**：提交前由用户显式确认并记录同意版本；内容侧做提示、脱敏与最小必要；转发运营按委托处理或用邮件的性质做评估；长期保留要写成「至少 N 个月 + 确定方法」，不写「永久」。

## 一、先定角色

| 角色 | 是谁 | 法律地位 |
|---|---|---|
| 个人信息处理者 | SkillMaster 平台 | 决定处理目的与方式，承担 PIPL 的主要义务 |
| 个人 | 用户 | 有权知情、同意、查阅、复制、更正、删除、撤回同意 |
| agent / 宿主 | 用户使用的工具（Claude Code、Codex 等） | 用户的工具；若由第三方提供，第三方可能是共同处理者或受托方，取决于它是否决定处理目的 |
| 运营邮箱服务商 | 收件方 | 只做传输与存储时是受托方（PIPL 第 21 条）；若自行决定处理目的则是接收方（第 23 条） |

**关键点**：agent 是工具，不是法律上的代理人。用户点过一次「安装并同意服务条款」，不等于授权 agent 把任何内容提交给平台。

## 二、直接相关的条文

| 法 / 条 | 要求（摘要） | 对「agent 自动提交」的含义 |
|---|---|---|
| **PIPL 第 13 条** | 处理个人信息须有合法性基础，同意是其中之一 | 自愿反馈不属于「履行合同所必需」，只能靠同意 |
| **PIPL 第 14 条** | 同意须在**充分知情**前提下**自愿、明确**作出；目的、方式、种类变更要重新取得同意 | agent 自行提交，平台无法证明用户「充分知情」 |
| **PIPL 第 17 条** | 处理前以显著方式、清晰易懂的语言告知：处理者身份与联系方式、目的、方式、种类、保存期限、权利行使方式 | 隐私政策是告知；但**告知不等于同意** |
| **PIPL 第 6 条** | 目的明确合理、与目的直接相关、影响最小；收集限于**最小范围**，不得过度收集 | 不能借反馈之名收对话全文、文件与参数值 |
| **PIPL 第 19 条** [转引] | 保存期限应为实现目的所必需的**最短时间** | 「永久保留」容易被认定超出必要 |
| **PIPL 第 21 条** | 委托处理要约定目的、期限、方式、种类、保护措施并监督；受托人不得超范围处理 | 运营邮箱、对象存储都应有委托处理条款 |
| **PIPL 第 23 条** | 向其他处理者提供个人信息，要告知接收方并取得**单独同意** | 把反馈转给外部服务商或合作方时触发 |
| **PIPL 第 28、29 条** | 敏感个人信息（生物识别、宗教信仰、特定身份、医疗健康、金融账户、行踪轨迹等）须有特定目的、充分必要、严格保护，并取得**单独同意** | 用户可能把这类信息写进反馈；平台无法预知，必须提示与拦截 |
| **PIPL 第 31 条** | 不满 14 周岁未成年人的个人信息，须取得**监护人同意**，并制定专门处理规则 | 现有条款已写未成年人，但提交时仍要提示 |
| **PIPL 第 47 条** | 目的实现、服务停止、期限届满、撤回同意、违法处理等情形应主动删除；个人有权请求删除 | 长期保留必须有期限或确定方法，并保留删除路径 |
| **PIPL 第 55、56 条** | 处理敏感信息、自动化决策、委托处理、向他人提供、跨境、其他重大影响 → **事前**做个人信息保护影响评估并记录，报告至少保存 **3 年** | 反馈可能含敏感信息 + 转发邮箱，触发评估 |
| **PIPL 第 66 条** | 一般违法：责令改正、警告、没收违法所得，拒不改正处 **100 万元以下**罚款，责任人 **1 万–10 万元**；情节严重：**5000 万元以下或上一年度营业额 5% 以下**，责任人 **10 万–100 万元**，可禁业 | 罚则与「未经同意收集」同一梯度 |
| **PIPL 第 69 条** | 造成损害，处理者**不能证明自己没有过错**的，承担损害赔偿等侵权责任（过错推定） | 平台要自证合规，举证责任在平台 |
| **《网络安全法》第 41 条** | 收集、使用个人信息遵循合法、正当、必要，公开规则，明示目的、方式、范围，并**经被收集者同意** | 与 PIPL 同向，处罚可叠加 |
| **《网络安全法》第 42 条** | 未经被收集者同意不得向他人提供；泄露要补救、告知、报告 | 转发与泄露场景 |
| **《民法典》第 1035 条** | 处理个人信息遵循合法、正当、必要，不得过度处理；须征得本人或监护人同意、公开规则、明示目的方式范围 | 民事层面的同一条原则 |
| **《网络数据安全管理条例》第 18 条** | 使用自动化工具访问、收集网络数据，应评估影响，不得非法侵入或干扰服务 | 「自动化提交」本身要评估 |
| **《网络数据安全管理条例》第 21 条** | 个人信息处理规则要集中公开展示、易于访问、置于醒目位置；告知目的、方式、种类、保存期限与到期处理方式；向他人提供要以**清单**列明接收方 | 隐私政策新增一节要按这个口径写 |
| **《网络数据安全管理条例》第 22 条** | 同意限于服务所必需、不得超范围、不得误导欺诈胁迫；敏感信息**单独同意**；不满 14 周岁监护人同意；不得超出同意范围；**明确拒绝后不得频繁征求**；目的方式种类变更重新同意 | 提交时的确认必须是「单独、明确」的一次动作 |
| **《网络数据安全管理条例》第 24 条** | 自动化采集无法避免采到非必要或未获同意的个人信息，以及注销账号的，应删除或匿名化；期限未满或技术难删的，停止除存储与必要安全措施外的处理 | 反馈里混入的非必要信息要处理 |
| **《生成式人工智能服务管理暂行办法》第 9、11 条** | 涉及个人信息的，提供者承担个人信息处理者责任；对用户输入与使用记录依法保护，不得收集非必要个人信息，不得非法留存可识别身份的输入与记录，不得非法向他人提供 | 若 agent 由平台提供，平台要为用户输入负责 |
| **《个人信息保护合规审计管理办法》**（2025-05-01 施行） | 处理 **1000 万人以上**个人信息的，每两年至少审计一次；监管可要求审计 | 达到规模后是持续义务 |

## 三、可能引发的问题（按场景）

1. **没有有效同意**：agent 未经用户确认提交 → 违反第 13、14、17 条 → 第 66 条罚则 + 第 69 条民事赔偿（过错推定，平台举证）。
2. **敏感个人信息**：用户把健康、金融、行踪、身份证号写进反馈 → 需要**单独同意**（第 29 条）与影响评估（第 55 条）；只靠一次笼统勾选不够。
3. **他人的个人信息**：反馈里出现同事姓名、客户资料、聊天记录 → 平台「向他人提供」或「处理他人信息」都缺合法性基础；平台也无法核验用户是否取得同意。
4. **商业秘密**：反馈里带公司代码、密钥、内部文档 → 不是 PIPL 问题，但可能触发**反不正当竞争法**与合同/侵权索赔；用户也可能反过来追究平台。
5. **未成年人**：不满 14 周岁的信息需要监护人同意（第 31 条）；现有条款只写了「请让监护人同意」，没有核验。
6. **转发运营**：把反馈发到邮箱、存到对象存储 → 是委托处理（第 21 条）还是提供（第 23 条）取决于服务商角色；若邮箱或存储在境外，还要走跨境路径（第 38、39 条）。
7. **长期保留**：写「永久保留」与第 6、19 条的最小必要、最短期限冲突；写「至少 N 个月 + 到期处理方式」更稳（《网络数据安全管理条例》第 21 条要求告知保存期限或确定方法）。
8. **删除与撤回**：用户撤回同意或要求删除时，要有可执行的路径（第 15、47 条）；技术难删时，至少停止除存储与安全措施外的处理。
9. **泄露**：反馈里含他人信息或敏感信息，一旦泄露，第 57 条与《网络安全法》第 42 条要求补救、告知、报告。
10. **规模义务**：处理 1000 万人以上个人信息后，要按《个人信息保护合规审计管理办法》定期审计。

## 四、对 v63 的具体建议

| # | 建议 | 对应的条文 |
|---|---|---|
| 1 | **提交前由用户本人显式确认**，记录同意版本与时间；agent 不能代替用户点这个确认 | 13、14、17；条例 22 |
| 2 | 确认文案写清：收集什么、用途、保存期限、是否转发、如何删除与撤回 | 17；条例 21 |
| 3 | 诊断字段**白名单**，默认不带；不收集对话、文件、参数值 | 6；条例 24 |
| 4 | 模板里写明「不要写」：密钥、密码、私有代码、他人信息、敏感个人信息 | 28、29 |
| 5 | 提交时做基础检测：命中身份证号、银行卡号、手机号、密钥前缀等给出警告或要求确认 | 29；条例 24 |
| 6 | 隐私政策新增一节，按条例第 21 条的口径写，转发邮箱以清单列明 | 17；条例 21 |
| 7 | 转发运营邮箱与对象存储前，签委托处理条款或确认服务商角色；确认都在境内 | 21、23、38、39 |
| 8 | 做一次个人信息保护影响评估，报告保存至少 3 年 | 55、56 |
| 9 | 保留期写「至少 N 个月 + 到期处理方式」，并保留删除/撤回路径 | 19、47；条例 21 |
| 10 | 未成年人提示沿用现有条款，提交时再提示一次 | 31 |
