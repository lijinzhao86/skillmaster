# 本地文件 `Edit` 的字节级机制

> **核对日期**：2026-10-30。**方法**：在 macOS 上用本机 Claude Code 的 `Edit` 工具改一组构造样本，每次前后 `od -tx1` 对比字节。
> **用途**：决定服务端版 `skill edit` 要照抄哪些行为、哪些可以不同。
> **口径**：这是**实测**，不是官方文档；Claude Code 会变，结论过期就重测。

## 三句话结论

1. **匹配是文本级的，但换行符被归一化**：LF 写法的 `old_string` 能匹配 CRLF 文件；大小写、行尾空格都精确（不模糊）。
2. **写回时整个文件按主流换行风格重编码**：混合换行的文件会被统一——CRLF 行数多于 LF 就全 CRLF，否则全 LF（平票判 LF）。匹配之外的字节也会因此改变。
3. **其余字节不动**：BOM 保留、末尾没有换行的不加、非 UTF-8 文件改不动；`old == new` 直接拒绝；空 `old_string` 是「新建文件」语义。

## 实测样本

| 样本（改前 hex） | 操作 | 改后 hex | 结论 |
|---|---|---|---|
| `61 0d 0a 62 0d 0a 63 0d 0a`（全 CRLF） | `old="a\nb"`（LF）→ `"A\nB"` | `41 0d 0a 42 0d 0a 63 0d 0a` | **LF 的 old 匹配 CRLF 文件**；未动的行仍是 CRLF |
| 同上 | `old="c"` → `"C\nD"` | 末尾变成 `43 0d 0a 44 0d 0a` | 新插入的 `\n` 按文件风格写成 CRLF |
| `61 0d 0a 62 0a 63 0d 0a`（CRLF 多） | `old="b"` → `"B\nX"` | `61 0d 0a 42 0d 0a 58 0d 0a 63 0d 0a` | **原本那一行是 LF，也被改成了 CRLF** |
| `61 0d 0a 62 0a 63 0a 64 0a`（LF 多） | 同上 | `61 0a 42 0a 58 0a 63 0a 64 0a` | 全文件归一成 LF（CRLF 那行也被改） |
| `61 0d 0a 62 0a`（1:1） | `old="b"` → `"B"` | `61 0a 42 0a` | **平票判 LF** |
| `ef bb bf 61 0a 62 0a`（BOM） | `old="a"` → `"A"` | `ef bb bf 41 0a 62 0a` | **BOM 保留** |
| `61 0a 62`（末尾无换行） | `old="b"` → `"B"` | `61 0a 42` | **不补末尾换行** |
| `61 0d 62 0d`（CR-only） | `old="b"` → `"B"` | `61 0d 42 0d` | 单行替换可行；CR-only 的多行匹配未测 |
| `ff fe 61 0a`（非 UTF-8） | `old="a"` → `"b"` | 不变 | **找不到**；非 UTF-8 文件改不动 |
| `61 0a 62 0a` | `old="b "`（多一个空格） | — | 找不到：**空白不做模糊匹配** |
| 同上 | `old="b\n"` → `"B\n"` | 成功 | old 带结尾换行可以匹配 |
| 同上 | `old="b"` → `"b"` | — | 拒绝：`No changes to make: old_string and new_string are exactly the same.` |
| 同上 | `old=""` → `"x"` | — | 报 `Cannot create new file - file already exists.`：空 old 是**新建文件**语义 |

## 另外三件与本工具无关、但决定「服务端版怎么做」的事实

- **唯一性**：多处匹配且没开 `replace_all` 时拒绝，报「Found N matches … provide more context」。本次实测 6 处时触发。
- **读前约束**：文档说「本会话读过才能改」，**这一版没有强制**——用 shell 建的文件直接改也成功。真正生效的是宿主对文件的跟踪：文件被外部改过时，宿主把 diff 注进对话，但不拒绝编辑。
- **失败即无改动**：匹配失败时文件一个字节都不变（上面「找不到」的样本 hex 与改前一致）。

## 对服务端 `edit` 的含义

要「跟本地一样」，服务端必须做到：

1. 按 UTF-8 文本解码；**非 UTF-8 拒绝**（不是按字节替换）。
2. 匹配前**归一化换行**（LF 的 old 匹配 CRLF 内容）。
3. 写回时按文件的主流风格**重编码整个文件**（CRLF 多→全 CRLF，否则全 LF，平票 LF）；BOM 保留；末尾换行不增不减。
4. 精确匹配（空白与大小写不模糊）、唯一性、`replace_all`、`old == new` 拒绝、空 old 拒绝。
5. 基线用 `If-Match`（本地靠宿主跟踪，服务端靠 digest）。

**但第 3 条有一个代价要明确**：匹配之外的行也会因为换行归一化而改变字节——一个只改了 `b` 的编辑，可能把另一行的 LF 改成 CRLF，digest 变化超出「只改一处」的直觉。两种选法：

| 选法 | 匹配 | 写回 | 与本地一致 | 代价 |
|---|---|---|---|---|
| **A. 完全照抄** | 归一化后匹配 | 整文件按主流风格重编码 | 是 | 匹配外的字节会被改动；混合换行的文件每次编辑都在变 |
| **B. 只宽容匹配** | 归一化后匹配 | 只替换匹配那一段，其余字节原样 | 否（混合换行文件与本地不同） | 要额外把归一化后的匹配位置映射回原始字节，实现更复杂 |

## 未核实

- CR-only 文件的多行匹配行为。
- 非常大的文件（几百 MB）下是否仍然整文件重编码。
- 「读前约束」在别的 Claude Code 版本里是否强制。
- 换行风格判定是否严格按「出现次数」；目前只观察到多数与平票两种情况（平票判 LF）。
