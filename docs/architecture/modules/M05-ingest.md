# M05 · 上传与校验

> **状态**：已实现 · **拥有表**：无 · **对外的发布类型**：`ReservedPaths`、`Utf8Probe`

## 职责

接收上传物（zip 或单文件），解析完整的 YAML frontmatter，校验路径、大小与符号链接，并在入库前做内容归一化（LF、BOM、NFC、路径规则、打包垃圾）。产物是「一批 `(relpath, bytes)`」，不落库。

## 边界

- **不做**：存字节——那是 M06（blob）；建版本——那是 M07（version）。
- **依赖 canon**：文本与路径的归一化规则由 canon（无表的支持包，不在 `ModuleMap` 里）拥有，ingest 只是调用者。
- **不做**：判断这个上传有没有权限——那是用例层与 M12 的事。

## 对外契约

`ReservedPaths` 是保留路径的查询；其余类型是上传校验的内部产物。

## 为什么这样切

上传校验是一次性的、无状态的转换：输入字节，输出校验过的一批文件。它不拥有任何表，也不承担版本语义；把它并进 M07 会让版本模块同时负责「收什么」和「存什么」，而这两件事的失败模式不同。
