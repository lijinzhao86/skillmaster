# M10 · 审计与统计

> **状态**：已实现 · **拥有表**：`audit_event` · **对外的发布类型**：`AuditEvent`、`AuditLog`

## 职责

留痕：谁在什么时候对什么做了什么。它只增不改，不参与业务判定。

## 边界

- **不做**：统计表——P1 需要时另建，本版没有。
- **不做**：从审计反推业务状态；审计是旁路，不是权威。
- **被多个模块调用**：account 与 token 在模块内写审计；skill / version 的动作由 usecase 层写。它们只依赖 `AuditLog` 的接口，不读 `audit_event` 的表。

## 对外契约

`AuditEvent` 是一条事实；`AuditLog` 是写入接缝。

## 为什么这样切

审计的写入必须与业务写入同事务（否则会出现「授权行写进去了而审计没有」）。**例外**：令牌端点的框架过滤器里没有事务，审计行紧随其后写；见 [M02](M02-token-and-as.md) §已知的不精确。把它做成独立模块，让所有业务模块依赖同一个窄接口，而不是各自拼一条 INSERT。
