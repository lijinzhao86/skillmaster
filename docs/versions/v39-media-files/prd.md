## 用户与场景

**谁在用**：写 skill 的作者，和加载 skill 的 agent。作者可能在控制台里点，也可能只有终端（CLI）。

**在什么场景下用**：

- **作者**手里有一份产品手册 PDF、一页界面设计图、一段演示录音，想把它们放进 `references/`，让 skill 在需要时取用。他打开控制台的文件树，点「上传文件」或直接把文件拖进去，希望能像上传网盘一样看到进度、失败原因，以及传完之后文件长什么样。
- **agent** 加载了一个带图片的 skill，被要求「看一下 `references/design.png`，按图里的布局改代码」。它需要用一条命令把图片取到本地，让能渲染图片的宿主看见它。
- **维护者**要替换一份 PDF，只需在草稿里删掉旧的、传上新的、再上线一版——和改一个 Markdown 文件没有区别。

**现在的替代做法是什么**：

| 做法 | 差在哪 |
|---|---|
| 本地打包成 zip，走「导入」 | 控制台一次只收 `.zip`；改一张图也要重新打包整包；看不到单个文件的进度与错误 |
| 把图片转成 base64 塞进 Markdown | 文件膨胀、阅读器渲染不了；版本 diff 变成一堵墙 |
| 放到外部图床 / 网盘，在 SKILL.md 里写链接 | 链接会腐烂；skill 不再是自包含的一份包；平台看不到、管不了、也审计不到 |
| CLI `cat` 取出字节再重定向 | 只能写文本；大文件没有进度，失败要从头再来 |

**为什么这一版还要做**：模型里字节本来就是文件（[`model.md`](../../current/model.md)），但 16 MiB 的总量、只收 zip 的导入、只渲染文本的编辑器，把「媒体文件」挡在了产品体验之外。这一版把这道门打开。

## 范围

### 做

| # | 做什么 | 交付形态 |
|---|---|---|
| 1 | **上限**：每文件 100 MiB、**每版本**（含 `SKILL.md`）512 MiB；文件数仍为 512。上限对控制台、CLI、服务端三处一致，服务端为准；同一 skill 的多个版本不合计。反向代理是第 4 个执行点（`client_max_body_size`，数字见部署配置） | 服务端 + 控制台 + CLI |
| 2 | **任意类型**：不按扩展名白名单拦截；任意字节都可以进版本清单 | 服务端 |
| 3 | **存储分流**：不超过 1 MiB 的 blob 留在 PostgreSQL；超过 1 MiB 的 blob 进 OSS（按大小，不看类型；仅在 OSS 开启的部署里）。读路径对调用方透明，按 sha256 去重。`grep` 对超过 16 MiB 的文本文件明确跳过并说明；`wc` 流式计数、不受此限（[ADR 0130](../../decisions/0130-large-blobs-live-in-object-storage.md)、[ADR 0133](../../decisions/0133-wc-streams-and-is-not-text-capped.md)） | 服务端 |
| 4 | **控制台上传**：文件树提供「上传文件」入口并支持拖拽；可多选；落到**当前打开文件所在的文件夹**（树没有「选中文件夹」这一状态）；逐个文件显示进度，失败走上传失败横幅（标题「上传失败。」，样式同 `editor-error`）并在其中带路径与原因；超限在发请求前就拦下 | **控制台** + 服务端 |
| 5 | **控制台预览**：png / jpg / jpeg / gif / webp 与 PDF 在编辑器内嵌显示；其他类型显示下载入口；二进制文件在编辑器里只读 | **控制台** |
| 6 | **CLI 上传**：`skmr skill put <地址> <本地路径>... <远端路径>`——单文件、多文件、任意字节；默认拒绝覆盖，`--overwrite` 才覆盖；只写草稿；`If-Match` 冲突回 409 | **CLI** |
| 7 | **CLI 下载**：`skmr skill get <地址> <远端路径> [-o <本地路径>]`——逐字节一致；`-o` 省略时落到当前目录的 basename；`-o -` 写 stdout；本地已存在时默认拒绝，`--overwrite` 才覆盖 | **CLI** |
| 8 | **流式读写**：上传与下载都不把整份文件读进堆内存；大文件先落服务端临时文件、边读边算 sha256；下载客户端提前断开时服务端停止读取 | 服务端 + CLI |
| 9 | **类型与响应头**：只有位图（不含 SVG）与 PDF 可以内联；其余一律 `application/octet-stream` + `Content-Disposition: attachment` + `X-Content-Type-Options: nosniff`。`MediaTypes` 不再为任意扩展名猜类型，只保留内联白名单与正文类型（[ADR 0131](../../decisions/0131-any-file-type-is-accepted-but-only-safe-types-render.md)） | 服务端 |
| 10 | **错误一致**：超限、路径非法、冲突、文件不存在在控制台、CLI、API 三处使用同一错误码与同一条能读懂的话（文案按 [`voice-spec.md`](../../../design/voice-spec.md)） | 服务端 + 控制台 + CLI |
| 11 | **回收**：版本被丢弃或删除后，没有任何 `version_file` 引用的 OSS 对象与数据库 blob 被清扫；清扫可重试，失败不阻塞发布 | 服务端 |
| 12 | **审计**：每次上传留一条（谁、哪个 skill、哪个路径、写了多少字节、动作是新增还是覆盖） | 服务端 |
| 13 | **命令分工写进帮助与技能**：文档与代码用 `write`（文本，服务端会做换行 / BOM / NFC 归一）；图片、PDF、Office、音视频等二进制用 `put` / `get`；`get` 取单个文件，`download` 取整版。帮助与 `skills/skillmaster/` 的说法必须一致 | **CLI 帮助** + `skills/skillmaster` + prompt 规则段 |

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | 服务端抽文本、OCR、全文索引 | 解析是另一条产品线：要解析库、要处理失败与派生数据，还要决定派生文本算不算版本内容。产品负责人 2026-11-02 确认本版只当字节文件 | 若出现「agent 读不了扫描件」的真实需求 |
| 2 | Office（Word / Excel / PPT）在线预览 | 浏览器不能原生渲染，要服务端转 PDF 或图片，多一套转换服务与缓存 | 未定 |
| 3 | 音视频内嵌播放 | 先给下载；播放器涉及 Range 请求、拖拽进度与带宽成本 | 未定 |
| 4 | 断点续传、分片上传、秒传 | 单文件 100 MiB、整包 512 MiB 以内的整包上传体验可以接受；分片要改协议与存储两层 | 若出现 >100 MiB 的单文件需求，或 512 MiB 整包的上传体验不可接受 |
| 5 | 每账号总容量配额 | 产品负责人 2026-11-02 确认不设；早期靠监控，真出现异常账号再补 | 付费体系落地时 |
| 6 | 独立素材库（可替换、跨版本共享的引用） | 会让同一个版本 digest 不再代表同一份内容，破坏可复现性（[ADR 0132](../../decisions/0132-media-files-are-version-files.md)） | 不做 |
| 7 | 匿名直链 / 预签名 URL | 字节层的可达性取决于谁引用了它，只能在 API 层鉴权（ADR 0010 的论证仍然成立） | 不做 |
| 8 | 病毒与恶意软件扫描 | 平台只存字节、不执行；强制下载与 `nosniff` 已挡住浏览器执行面。扫描要接第三方服务，成本与误报都要单独评估 | 若开放公开下载或出现滥用 |
| 9 | 目录成为一等对象（`mkdir`、目录级 `mv` / `rm`） | 目录仍由路径派生；这是 v34 已记的 TODO，不在本版混进来 | 独立一版 |
| 10 | MCP 服务器 | CLI 是 agent 的入口（[ADR 0081](../../decisions/0081-every-console-operation-has-a-cli-command.md)）；MCP 是一整条新链路 | 未定 |
| 11 | 历史字节迁移到 OSS | 旧 blob 留在数据库直到被清扫，读路径两种都认；主动迁移是独立的运维动作 | 若数据库体积成为问题 |
| 12 | 缩略图、图片压缩、转码 | 预览显示原图；生成缩略图是另一条处理流水线 | 未定 |
| 13 | 已安装旧技能的自动更新 | 技能随安装交付，不自动更新（v38 的口径）；本版把分工写进**帮助**，就是让没重装技能的人也能发现 `put` / `get` | 若做技能自更新那一版 |
| 14 | CLI `download` 的流式落盘（>17 MiB 整包） | 服务端归档已支持 512 MiB，但 `download` 客户端仍把整包读进内存并在 17 MiB 处拒绝；它与整包导入的流式化是同一类改造 | P3；在此之前大包用 `skill get` 逐个取（K5） |
| 15 | 整包导入超过 128 MiB（压缩包本身或解压后；P3 解除） | P1/P2 仍把压缩包读进内存、`ZipReader` 仍把每个条目读成 `byte[]`；128 MiB 是临时护栏，不是产品上限。更大的包逐个文件上传，单文件 100 MiB / 每版本 512 MiB 仍然可用 | P3 流式化后解除（K1/T24） |
| 16 | **以「新建草稿」为独立动作的 CLI 命令**（`draft create`，默认从线上版本起稿）——本版仍是 `write` / `edit` 以第一次内容改动建草稿，`put` 只写已经存在的草稿 | 产品负责人 **2026-11-02** 确认本版不改，放 TODO 后续做。这一步真正的阻塞是模型而不是命令：一版至少要有一个文件，且 `UNIQUE (skill_id, digest)`（[ADR 0064](../../decisions/0064-a-draft-may-change-a-published-version-may-not.md) §5）让「与底稿同内容的草稿」插不进去。方向已定：新建草稿是独立动作（含底稿，默认线上版本，不改 skill），修改 skill 不能建草稿 | 后续版本：先一条新 ADR 取代 ADR 0064 §5 的半条，再改控制台「第一次内容改动前不落库」那一态（[TD Q8](technical-design.md)） |

**范围里不许出现「后续再看」「视情况而定」。** 不确定的进 [`technical-design.md`](technical-design.md) §开放问题，并且必须是一个**能回答的问法**。

## 控制台操作与 CLI 对应

**这一版新增或改动的每一处控制台操作，都要有 CLI 命令对应**（[ADR 0081](../../decisions/0081-every-console-operation-has-a-cli-command.md)）。整表在 PRD 阶段填完；写不出命令的，说明需求还没定完。

| # | 控制台操作 | CLI 命令 | 备注 |
|---|---|---|---|
| 1 | 上传一个或多个文件（按钮或拖拽） | `skmr skill put <地址> <本地路径>... <远端目录或路径>` | 覆盖要带 `--overwrite`。写的是**已经存在的草稿**。新版本的第一份内容是二进制时，本版的 CLI 是三步：`printf '占位\n' | skmr skill write <地址>@new _placeholder.txt --name <名称>`（`write` 从 stdin 读内容，占位路径**不要用 `SKILL.md`、不要与目标文件同路径、不要用底稿里已有的路径**——后者会覆盖底稿里的那份文件）→ 用打印出的 `@<版本码>` 跑 `skmr skill put <地址>@<版本码> <本地文件> <目标路径>` → `skmr skill rm <地址>@<版本码> _placeholder.txt`。一条命令的形态（`draft create`）是已确认的本版不做，见 不做 #16 与 TD Q8 |
| 2 | 下载当前文件 | `skmr skill get <地址> <路径> [-o <本地路径>]` | `-o -` 等价于 `cat` |
| 3 | 预览图片 / PDF | `skmr skill read <地址> <路径>` | 二进制落到临时目录并打印路径，宿主据此渲染；要原样字节用 `skill cat` |
| 4 | 删除文件 | `skmr skill rm <地址> <路径>` | 已有命令 |
| 5 | 重命名 / 移动文件 | `skmr skill mv <地址> <源> <目标>` | 已有命令 |
| 6 | 新建文本文件 | `skmr skill write <地址> <路径>` | 已有命令，从 stdin 读 |
| 7 | 新建文件夹 | 无新增命令 | 它不是服务端操作：目录由路径派生，CLI 用 `write` / `put` 的路径即可产生同一个目录。因此不构成 ADR 0081 的例外 |
| 8 | 导入整包 zip | `skmr skill submit` | 已有命令 |

**分工**：控制台上传对文本和二进制是同一个入口；CLI 上把两类分开——**文档与代码走 `write`**（服务端会归一换行 / BOM / NFC），**图片、PDF、Office、音视频走 `put` / `get`**。读取时，只想看文本用 `read` / `cat`（stdout），要落盘用 `get`；要整版打包用 `download`。

**例外只有两类**：高风险（不可逆，或改变“谁能看见 / 调用”），以及产品负责人逐条确认的。

**本版没有申请例外；有一处欠账**（[ADR 0081](../../decisions/0081-every-console-operation-has-a-cli-command.md) §决定 5）：新版本的第一份内容就是二进制时，控制台一步建出草稿，CLI 没有一条命令**直接**建出草稿（`write` / `edit` / `mv` / `rm` 的 `@new` 形态都以文本开草稿，`put @new` 拒绝）。产品负责人 **2026-11-02** 确认本版不改、先记为欠账并入 TODO（拆分「新建草稿」与「修改草稿」，见 不做 #16 与技术设计 Q8）。

## 验收与指标

### 验收标准

每条都必须是**能判定过没过**的。写成"在什么条件下、观察到什么、就算通过"。

| # | 验收标准 | 怎么判定 |
|---|---|---|
| A1 | **任意类型上传**：在控制台文件树里多选或拖拽 png / pdf / docx / mp4 各一个到当前目录，全部成功后文件树出现这四项，类型与大小正确；重新打开页面仍在（草稿） | 控制台用例：四项各一，含多选与拖拽两条路径 |
| A2 | **CLI 上传**：`skmr skill put` 能传单文件、多文件到远端目录；目标已存在且没有 `--overwrite` 时拒绝并说明；带 `--overwrite` 成功；`If-Match` 过期时回 409；非草稿地址被拒绝 | CLI 用例：成功 / 已存在 / 覆盖 / 冲突 / 线上版本 |
| A3 | **CLI 下载**：`skmr skill get` 取任意类型文件，本地字节与清单里的 `sha256` 一致；`-o` 省略时落到当前目录 basename；`-o -` 写 stdout；本地已存在且没有 `--overwrite` 时拒绝 | CLI 用例 + 逐字节断言 |
| A4 | **上限**：单文件 >100 MiB 或单版本 >512 MiB 被拒；文件数 >512 被拒；`SKILL.md` 计入总量；控制台与 CLI 在发请求前就给出同样的数字与上限，服务端对绕过客户端的请求同样拒绝。整包导入在 P1/P2 按 128 MiB 的临时上限判定（压缩包本身与解压后各一道），P3 才验 512 MiB 的整包 | 三端用例：每种上限一例 + 客户端预检一例；P1/P2 的整包用例用 T24 的 128 MiB 分支，512 MiB 分支在 P3 |
| A5 | **存储分流**（需 OSS 开启；关闭时全部落库，T15/T25 的 OSS 部分标「未执行」）：大于 1 MiB 的 blob 进 OSS，`blob_content` 里没有它；不超过 1 MiB 的留在数据库（不论类型）；同一份内容被两个 skill 引用时只有一份；读取两种来源的文件都成功；OSS 里的大文本仍能被 `grep` 扫到（受 16 MiB 文本上限约束） | 服务端用例 + 数据库查询断言 + OSS 对象清单 |
| A6 | **控制台预览**：png / jpg / jpeg / gif / webp / pdf 在编辑器内嵌显示；docx / mp4 显示下载入口而不是乱码；二进制文件在编辑器里只读 | 控制台用例：六种可预览 + 两种只下载 |
| A7 | **响应头与执行面**：位图与 PDF 可以内联；html / svg / js / exe 一律 `application/octet-stream` + `attachment` + `nosniff`；用浏览器打开这些类型的文件地址不会执行脚本 | 服务端用例断言三个响应头 + 浏览器手工验证一例 |
| A8 | **流式与内存**（需 OSS 开启；关闭时大文件仍整份进库，T18 标「未执行」）：上传、下载 100 MiB 文件时，服务端单请求堆内存峰值不超过 32 MiB；下载中途断开后服务端停止读取（OSS 请求不再继续） | 压测/观测用例：堆采样 + 断开后日志 |
| A9 | **错误一致**：超限、路径非法、冲突、文件不存在在控制台、CLI、API 三处返回同一错误码；文案能读懂且带具体数字（例如「文件 120 MiB，超过单文件上限 100 MiB」） | 三端各取四类错误比对 |
| A10 | **既有契约不变**：文本文件的读、写、编辑、diff、submit、download、权限矩阵、invoke 行为不变；改造前写入的 blob 仍能读出。**有意的行为变化只有两处**：① html / svg / js 等不再以可渲染类型内联（见 A7）；② 非媒体文件（`.md` / `.json` 等）的单文件响应从按扩展名推测的类型变成 `application/octet-stream` + `attachment`，要拿正文请走正文接口或 CLI（[ADR 0131](../../decisions/0131-any-file-type-is-accepted-but-only-safe-types-render.md)） | 既有测试全绿 + 旧数据读取一例 + html/svg 响应头比对 + `.md` / `.json` 响应头比对 |
| A11 | **回收**：丢弃或删除一个引用了 OSS blob 的版本后，没有其它引用的 OSS 对象与数据库行被清扫；仍被其它版本引用的对象不被删；清扫失败后下一次能重试成功 | 服务端用例 + OSS 对象清单 |
| A12 | **审计**：每次上传留一条审计记录，含 skill、路径、字节数与新增/覆盖 | 审计表查询断言 |
| A13 | **命令分工可发现**：`skmr skill write --help` 说明它只写文本，`skmr skill put --help` 说明它传二进制；`skmr help` 的主流程里出现 `put` / `get`；`skills/skillmaster/SKILL.md` 的索引有对应 SOP，且说法与帮助一致；不再出现「二进制要先进草稿再写」这种只说不做的提示 | 帮助断言 + 技能内容断言 |

**成立条件**：A1 与 A3 是「不满足就不算交付」——任意类型能传上去、也能逐字节取回来，是本版存在的理由。

### 指标

| 指标 | 定义 | 怎么量 | 目标 |
|---|---|---|---|
| 数据库增长 | 媒体字节有多少进了 `blob_content`（口径：只统计本版上线后新写入、`blob.storage = 'db'` 且 `size > 1 MiB` 的行，单位 GB） | 审计 SQL | 0 |
| 上传耗时 | 50 MiB 文件在 10 Mbps 链路上从点击到成功（口径：单文件、无并发、含服务端落盘与 OSS 写入） | 控制台与 CLI 各测一次 | < 60 s |
| 单请求堆内存 | 100 MiB 上传/下载期间服务端堆内存峰值（口径：单请求、GC 后采样） | JVM 采样 | < 32 MiB |
| 错误可诊断 | 超限类错误中带具体文件大小与上限的比例 | 三端用例统计 | 100% |

## 依赖与前置

- **外部依赖**：阿里云私有 OSS 桶（与 CLI 下载桶分开）、ECS 的 RAM 角色或最小权限 AK；服务端临时目录（`SKILLMASTER_BLOB_TEMP_DIR`）至少可容纳一次 512 MiB 的导入。上传的临时文件写在**本机**，请求失败即删；进程崩溃的残留由该目录的清理策略兜底，桶里没有 `tmp/` 对象。
- **内部前提**：[ADR 0130](../../decisions/0130-large-blobs-live-in-object-storage.md)（存储分流）、[ADR 0131](../../decisions/0131-any-file-type-is-accepted-but-only-safe-types-render.md)（类型与执行面）、[ADR 0132](../../decisions/0132-media-files-are-version-files.md)（媒体是普通版本文件）、ADR 0005（内容寻址）、ADR 0047（权限档位）、ADR 0081（控制台与 CLI 对应）。
- **排除了什么前置**：不需要对象存储的 CDN、不需要预签名、不需要内容解析服务、不需要新的权限模型。
