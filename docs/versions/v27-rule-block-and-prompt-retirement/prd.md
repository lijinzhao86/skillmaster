# v27 · 产品需求

## 用户与场景

**谁在用**：装好 SkillMaster CLI、在自己的 AI 里配置过「先来 SkillMaster 找技能」那段说明的人；以及还没配、正要配的人。

**在什么场景下遇到问题**：agent 遇到任务时**不查**，直接凭自己的本事做。它并不是不知道自己有这个库，而是规则段把「这次要不要查」交给它自己判断——而模型在这件事上系统性偏保守：说「我需要查」要花一次调用，说「这次不用」什么都不用付，越是能干的模型越容易直接动手。结果是用户明明把技能托管到了 SkillMaster，日常里却用不上。

**现在的替代做法**：用户手动提醒「先查一下 SkillMaster」；或者在全局记忆里自己写一份更强的规矩（本机实测过，写「任何任务都先查」之后调用率明显上升）。

## 范围

### 做

| # | 做什么 | 为什么 |
|---|---|---|
| 1 | **规则段改成默认先查**：除闲聊（打招呼、情绪、没有任务的对话）外，任何任务动手前都先 `skillmaster skills search`；不判断「拿不拿得准」，不因「一次性的」「手边有现成工具」跳过；拿不准算不算闲聊时，当作任务去查 | 把「查不查」从模型的判断改成默认动作，这是这一版的全部目的 |
| 2 | **规则段不再带标记**：`block.md` 是一段普通正文 | 它是用户自己文件里的一段话，不该有机器标记 |
| 3 | **`prompt` 组只留 `print`**：`install` / `status` / `update` / `uninstall` 退役，命令仍在但只回答退役说明并退出 2，帮助页不再列出；记录文件 `prompt.json` 的写入路径一并删除（只剩读） | 没有标记就没有可靠的边界去定位、替换、删除这段拷贝；与其猜，不如不管理 |
| 4 | **删掉 `startup --plan`**（连同 `--agent`、`--file`）：`skillmaster startup` 不再带任何参数 | 清单早已搬进旅程技能（v26 迭代 0004）：`--plan` 里的七项、「下一步」指针、`steps/0N` 路径全是跟进不上的副本。删除前核查过：安装说明页、旅程正文与 CLI 的输出都不再引导人跑它，剩下的只有它自己的帮助条目、README 与历史文档 |
| 5 | **`submit` 打出的审批地址指向这一版草稿的页**（`?tab=versions&version=<草稿码>&sub=actions`） | 原来打的是技能主页，人还要自己找版本、点开子标签；同一条命令的 `pending` 提示却是深链接，两个说法互相打架 |
| 6 | **首页那条指令句改成「…安装 SkillMaster。」** | 「开始旅程」是内部说法；用户要做的事是安装 |

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | **规则段的自动更新**（`prompt update` 那种） | 没有标记就没有可靠边界：用户会改这段说明，模糊匹配判错就是替换错位置 | 客户端提供「我的指令文件里的某一段」的稳定标识时 |
| 2 | **清理用户文件里遗留的旧标记段** | 同上：CLI 没有命令读用户文件，也就不知道那段标记在哪；人自己删，或重跑 `startup` 时选「换成 SkillMaster 的」 | 不做 |
| 3 | **改 `startup` 技能的目录与话术** | 属于 v26 迭代 0004，已单独记录 | 不做 |
| 4 | **把「闲聊」的边界写成清单** | 列举永远漏（代码、设计一漏，等于暗示没列到的不必查）；用「拿不准就当任务」收口 | 不做 |
| 5 | **给公开库默认加 `--scope public`** | 别人的库不该默认进入检索范围；只有用户明确说「搜公开库」才加，且加载前确认 | 不做 |
| 6 | **在 CLI 里补回一份「还差几步」的清单** | 清单的权威在旅程技能的正文里；CLI 再算一份就是第二份副本，第一步改动就会与正文打架（v26 迭代 0004 已把清单搬走） | 旅程技能不再自带清单时 |

## 控制台操作与 CLI 对应

这一版**不新增控制台操作**，也不删任何一处控制台操作。它改的四处用户可见行为都在 CLI 与站点文案：

| 行为 | 在哪做 | CLI / 命令 |
|---|---|---|
| 规则段正文 | 随 CLI 二进制发布（[ADR 0102](../../decisions/0102-the-rule-block-ships-with-the-cli.md)） | `skillmaster prompt print` |
| 写进用户文件 | **旅程**（平台技能 `skillmaster/startup`） | agent 自己写；`prompt` 组不写文件 |
| 审批地址 | 网页（上线仍只能由人在网页上点） | `skillmaster skill submit` 打印的地址 |
| 旅程正文与清单 | 平台技能（控制台上线） | `skillmaster startup` |

## 验收与指标

| # | 验收标准 | 怎么判定 |
|---|---|---|
| 1 | **默认是查**：规则段正文含「除了闲聊」「任何任务都先查 skill」「不判断「拿不拿得准」」，且不含「拿不准就查」这类条件式说法 | 读 `internal/prompt/block.md`；`prompt print` 逐字对照 |
| 2 | **正文没有标记**：`prompt print` 的输出不含 `<!--`，也不以空行开头；结尾恰好一个换行 | 断言 `prompt print` 的输出 |
| 3 | **四个命令退役**：`prompt install` / `status` / `update` / `uninstall` 都在 stderr 输出三行退役说明（首行含「已经退役」，另两行给出 `prompt print` 与 `startup` 两个去处）并退出 2，stdout 为空；目标文件一个字节不变、不新建文件 | 四条命令各跑一次，比对文件与文件系统 |
| 4 | **命令面收窄**：帮助页里 `prompt` 的子命令只有 `print`；可执行命令路径从 65 条减到 61 条 | `prompt --help`；`declarations_test.go` 的计数 |
| 5 | **`startup` 不带参数**：`startup --plan`、`startup --agent X`、`startup --file Y` 都是未知参数，退出 2，且输出点名被拒的那个参数；裸 `startup` 的正文与两行 stderr 见验收 6 | 三条带参数的命令各跑一次；裸 `startup` 由验收 6 的用例覆盖 |
| 6 | **`startup` 仍认得旧记录**：`prompt.json` 里有一条记录时，stderr 出现「这台电脑上写过这段说明的 Agent：…」，且不出现路径 | 夹具：一条 `agent: "codex"` 的记录 |
| 7 | **审批地址是草稿页**：`skill submit` 打出的「审批地址」等于 `…/skills/<ns>/<name>?tab=versions&version=<草稿码>&sub=actions` | 单元测试 |
| 8 | **首页那句话**：首页演示件、站点与设计检查里的安装指令句都是「根据 https://www.skillmasterai.com/install/skillmaster.md 安装 SkillMaster。」 | `home-check`；站点测试 |

**指标**（这一版没有服务端指标）：

| 指标 | 定义 | 怎么量 | 目标 |
|---|---|---|---|
| 首次调用率 | 在一组「有对应技能」的任务里，agent 动手前先跑 `skills search` 的比例 | 人工走查 10 个任务 | 10/10（此前实测偏低） |
| 误触发代价 | 每个任务多出的 `skills search` 次数 | 同一组任务计数 | ≤ 2 次/任务（由「两次没中才自己做」封顶） |
| 规则段体积 | `block.md` 的行数 | `wc -l` | ≤ 12 行（现值 9） |

## 依赖与前置

- **规则段随 CLI 发布**（[ADR 0102](../../decisions/0102-the-rule-block-ships-with-the-cli.md)）：改正文必须出 CLI 版本。
- **写这段说明的是旅程**（v26 迭代 0004）：本期不改变「谁写」。
- **旧记录仍在**：`prompt.json` 里的历史记录只读保留，`startup` 用它打出「这台电脑上写过这段说明的 Agent」，不再写新的。
- **`startup` 技能的目录**（`memory/`、`import/`）与清单由 v26 迭代 0004 定义；这一版删掉的是 CLI 里那份跟不上的副本，旅程正文一个字节不动。
