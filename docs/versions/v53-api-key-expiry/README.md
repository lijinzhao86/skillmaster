# v53-api-key-expiry · API 密钥的有效期选项

> **最后更新**：2026-11-09
> **状态**：实现已完成；改动面测试已通过，完整结果见 [`test-plan.md`](test-plan.md) §结果。等待合并。
> **含收费**：否

## 目标

把新建 API 密钥的「有效期」从「只能选 90 天内的某一天」改成与 GitHub 对齐的一组选择：**30 / 60 / 90 / 365 天、自定义日期、不过期**；默认 90 天，上限固定 365 天，部署可禁止不过期；并对长期不用的密钥加自动撤销。细节见 [`prd.md`](prd.md)。

## 这一版明确不做什么

| 不做 | 理由 | 什么时候可能做 |
|---|---|---|
| 到期前与自动撤销前的提醒 | 没有邮件或站内信通道；控制台只有打开页面才看得到 | 有通知通道时 |
| 修改已有密钥的有效期（编辑日期） | 现在只能续期换新；编辑要新增接口与审计 | 有明确需求时 |
| CLI 侧 API key 管理（签发、列出、续期、撤销） | 现在都只在控制台（[ADR 0040](../../decisions/0040-api-key-in-the-cli-now-the-browser-path-later.md)）；本版 CLI 零改动（已评估）。**签发已记 [TODO](../../current/TODO.md)** | 后续开版做签发 |

其余不做项（7 天档、对已有密钥追溯新配置）与逐条理由见 [`prd.md`](prd.md) §不做。

## 验收标准

摘要：期限下拉与默认值可用；不过期可签、可调用、续期后仍不过期；部署能禁止不过期，但**上限固定 365 天**；365 天未使用的密钥被自动撤销。完整验收见 [`prd.md`](prd.md) §验收与指标。

**成立条件**：A3（不过期可签可用）、A6（续期保持不过期）、A7（365 天未使用自动撤销）**不满足就不算交付**——它们分别是这次新增能力、续期一致性与安全兜底本身。
