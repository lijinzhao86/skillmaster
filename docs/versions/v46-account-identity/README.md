# v46-account-identity · 授权时写清身份，退出时说清还剩什么

> **最后更新**：2026-11-05
> **状态**：进行中（已实现；自动化用例通过。T6 的浏览器半与授权页的视觉验收未执行，留产品负责人；待 PR 合并）
> **含收费**：否
> **来源**：从 [`docs/current/TODO.md`](../../current/TODO.md) 的「控制台账号切换与 CLI 多账号」搬入三件——授权页写身份、退出引导页、`skmr logout` 结束服务端那次登录（2026-11-05）。

## 目标

授权页在签发凭据之前写出「以谁的身份授权」，并给一个当场换成另一个账号的出口；浏览器退出登录后停一页，说明这台电脑的 CLI 如果还没退出就仍然可用，并给出一句交给 agent 的 `skmr logout`——这条命令同时结束服务端那次登录。细节见 [`prd.md`](prd.md)。

## 验收标准

十三条（A1–A13），摘要其中五条：浏览器登着 A 时跑 `skmr login`，授权页用账号卡片把 A 显示成卡片里最大的字；点「不是我，换一个账号」后能登成 B 并回到同一张授权页；终端打印「已登录为 B」；网页退出后停在引导页，说明 CLI 如果还没退出就仍然可用，并给出一句交给 agent 的 `skmr logout`；这条命令跑完，控制台「登录设备」里那一行消失。完整验收见 [`prd.md`](prd.md) §验收与指标。

**成立条件**：A2 与 A11 不满足就不算交付——这一版要解决的就是「页面上写的身份」与「实际签发的身份」脱节，以及「退出登录」只退了一半。判据见 [`prd.md`](prd.md) §验收与指标。

## 这一版明确不做什么

摘要三条最要紧的；**完整范围与每条的理由在 [`prd.md`](prd.md) §范围**。

- 不做 CLI 多份凭据（profile）——`skmr login` 的替换语义已经能换账号，还没有「一台机器同时用两个账号」的需求。
- 不做控制台账号菜单的「切换账号」——本版只在授权页与退出页两处补说法，菜单是另一屏。
- 不做 CLI 退出时注销浏览器会话；API 密钥仍只清本机；退出引导页也不提 API 密钥——前两条会误伤其他设备，第三条是产品负责人 2026-11-05 的决定。

## 与目标态的关系

[`target/`](../../target/) 描述的是产品完整形态。本版不改变它的形态：它是「登录设备／凭据」那条在两个时刻的补齐——授权时把身份写出来，退出时说明还剩什么，没有新增身份模型。

- 保留的部分：浏览器会话仍是授权身份的唯一来源（[ADR 0040](../../decisions/0040-api-key-in-the-cli-now-the-browser-path-later.md)、[ADR 0043](../../decisions/0043-the-browser-session-is-bounded-and-revocable.md)）。
- 已经分叉的部分：无。

## 影响最大的未决问题

没有未决的产品问题。第 3 关留的五个实现问题已按倾向全部落地：身份随 `AuthenticatedSubject` 走、撤销失败退出码 `0`、已结束的登录按「已经结束」处理、环境里的 key 不影响撤销本机登录、账号名随交换响应到达。完整清单见 [`technical-design.md`](technical-design.md) §开放问题。
