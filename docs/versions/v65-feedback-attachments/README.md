# v65-feedback-attachments · 反馈可以带图片或视频

> **最后更新**：2026-11-13
> **状态**：进行中（已实现；已执行的自动化测试全绿，T3 真实剪贴板、T4 三路都空、T12 路由清单、T13 视觉、T15/T16 真机与 T18 配置断言未执行，见 [`test-plan.md`](test-plan.md) §结果）
> **含收费**：否

## 目标

让用户在 agent 里贴的图片或视频，跟着反馈一起到达平台：agent 自动取图、预览、提交，用户不需要手敲 CLI。细节见 [`prd.md`](prd.md)。

## 验收标准

`skmr feedback attach` 能从消息路径、会话缓存或剪贴板取到媒体；`send --attach` 能提交并落库；类型与大小在客户端和服务端都拦得住；撤回删掉对象；隐私政策升到 1.3；Claude Code 与 WorkBuddy 真机各验一次。完整验收见 [`prd.md`](prd.md) §验收与指标。

**成立条件**：验收 #4（收得下）、#6（拦得住）、#8（删得掉）、#11（说清楚）、#13 与 #14（两个宿主真机可用）任一条不满足就不算交付。

## 这一版明确不做什么

摘要三条最要紧的；完整范围与每条的理由在 [`prd.md`](prd.md) §范围。

- 不做自动内容审核 —— 反馈是私有收件箱，桶私有、只有运营可读；先接受残余风险并写进 ADR
- 不做图片元数据剥离 —— v65 原样保存并在预览里提示；这是记在案上的已知残余
- 不做控制台反馈入口与附件查看器 —— v65 只做 agent/CLI；入口已记进 TODO，等反馈量起来再单开一版

## 与目标态的关系

[`target/design.md`](../../target/design.md) §2.8 的治理模型里有关键对象 `Report` 与「举报下架」；**附件不改变那套模型**，它只是 v64 反馈受理面的证据补充，不是对某个 skill 的处置请求。

- 保留的部分：目标态的治理模型不变。
- 已经分叉的部分：无。
