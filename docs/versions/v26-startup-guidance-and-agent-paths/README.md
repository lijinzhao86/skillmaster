## 目标

把 startup 的五个现场问题一次解决（本版只覆盖跑在自己电脑上的 AI 工具）：**先按本机实际状态出一张清单，已完成的不重走**；**清单先给「下一步」，已完成收起，每步报进度**；**对非技术用户说的话有固定范本（口语、短句、一次一个问题；开场 / 请示 / 进度 / 失败 / 收尾）**；**安装时给 `.skillmaster` 一次权限，以后读写这个文件夹不再逐次审批**；**每一步动手前说清审批的是什么、有什么风险**；**换一个 agent 时知道规则段要各写一份**；**WorkBuddy 写到它真正会加载的文件**；**不再用一张会过期的路径表把错误地址塞进流程**。做法是：`startup --plan` 只读地算清单，每步做完重算并报进度；**旅程不给 agent → 文件的表**，让每个 agent 写进它自己的用户级指令/记忆文件（不确定就先查配置/上下文，仍不确定就问『你用的是哪个 AI』，再直接写用户级记忆）；CLI 负责计划、审批、记录与更新。交互口径见 [`docs/research/onboarding-interaction.md`](../../research/onboarding-interaction.md)，措辞范本见 [`prd.md`](prd.md) §给用户的措辞，细节见 [`prd.md`](prd.md)。

## 验收标准

一句话摘要：`startup --plan` 在「Claude 已完成、切到 Codex」的机器上只剩 1 件待做（让 AI 先来 SkillMaster 找技能），其余已完成或跳过；每步做完重算并报进度；给出的每句话按面向非技术用户的范本；`.skillmaster` 权限只在安装时申请一次、只给这个文件夹；线上第三步没有任何「agent → 文件」对照表；WorkBuddy 在真机上写进按账号分目录的 `MEMORY.md`，新任务里生效；`prompt install` / `prompt uninstall` 不给 `--yes` 时文件一个字节不变；一台机器写过几份就更新几份。完整验收见 [`prd.md`](prd.md) §验收与指标。

**成立条件**：验收 2（WorkBuddy 真机生效）、4（计划先行）、5（多文件记录与更新）、10（五句话请示）、12（换 agent 时清单只列缺的）、14（清单只读且不谎报）、15（每步报进度）、18（措辞按面向非技术用户的范本）——任一条不过即不算交付。

## 这一版明确不做什么

摘要最要紧的几条；**完整范围与每条的理由在 [`prd.md`](prd.md) §范围**。

- **不维护 agent → 用户级文件的对照表**（CLI 与旅程里都不放）——WorkBuddy 那一行证明了表会过期，还会把错误地址塞进流程、盖过 agent 自己上下文里的信息
- **不做 `prompt install --all` / 自动扫描本机 agent**——没有表就不知道「本机有哪些 agent、各自读哪」；扫描只会扫出另一张表
- **不按已知路径拒绝**——没有表就没有「已知路径」；CLI 只做通用检查（目录、父目录、主目录），并对项目级路径警告。代价是「看起来像」的错误路径不会被 CLI 拦住，靠五句话请示与新任务里的实际使用
- **不存进度文件**——清单每步重新计算，事实变了清单就变，不会和一份「做到第几步」的记录漂移
- **不拿清单确认当全部批准**——清单确认的是顺序；每个写 / 删 / 上线动作仍要单独请示
- **不做云端 / 远程 AI 的安装**（例如 Grok bot、WorkBuddy 云端模式）——它们没有本机用户级文件、一般不能从会话里打开浏览器登录，凭据要用 API key；本版先把本机终端跑通，云端单独开一版

## 影响最大的未决问题

1. **agent 能不能说出自己的用户级文件**：WorkBuddy 的提示词里直接给了路径；Claude Code、Codex 等知道自己的约定；Cursor、OpenHands 知道自己只能在应用内设置。**说不出来时，旅程要求它先查自己的配置或上下文；仍不确定就问『你用的是哪个 AI』，再直接写用户级记忆**——这是撤掉表之后唯一的新风险，也是 WorkBuddy 真机验收要回答的问题。
2. **WorkBuddy 的真机验收**：路径由源码与日志核实（`~/.workbuddy/user-<uid>-personal/MEMORY.md`），但「agent 在自己会话里取到这个路径、写进去、新任务里规则真的被加载」必须由人在 WorkBuddy 里走一次，本版验收 2 不接受推断。
3. **平台内容的发布顺序**：技能 `@1.3.1` 已上线；CLI beta `1.1.0-beta (1cd1b83)` 已发同一提交。窗口期里老 CLI 的 `prompt install` 首次写不会先出计划（v25 行为），但能写入；新 CLI 发布后计划先行生效。
4. **控制台是否也要改成非技术口语**：本版只改启动旅程，控制台仍按 `voice-spec`（[ADR 0107](../../decisions/0107-startup-speaks-to-non-technical-users.md)）。如果产品负责人确认控制台的读者同样不懂技术，那要另开一条决策；本版不回答。
