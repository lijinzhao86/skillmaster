# 0002 · 状态行不猜「写提示词」，改成指向清单

- **日期**：2026-10-27
- **关联**：[0001](0001-import-is-optional.md)、[ADR 0108](../../../decisions/0108-importing-local-skills-is-optional.md)

## 改了什么

- `state.go` 的 `whereYouAreLine`：没有草稿、本机有技能时，下一步从「写提示词、验证，然后下线。」改成「看看还差几步。」；什么都没有时也从「写提示词、验证。」改成同一句。有草稿时仍是「上线。」，没有本机技能、库里有线上时仍是「已完成」。
- `state_test.go` 的六处断言跟着改。
- TD 的状态行一节改成同一口径。

## 为什么

2026-10-27 在真机上跑完 `startup --plan`（清单写「必做项都好了；旅程完成」）之后，紧接着跑 `startup`，stderr 仍打「下一步：写提示词、验证，然后下线。」——说明其实早就写好了。原因是这一行只读本机扫描、线上列表和草稿，读不到 `prompt.json`，所以它无法知道说明写没写。以前所有本机技能都传上去时也会出现同样的错，只是传技能改成可选后，这个分支变成了常见路径。

不猜「写提示词」，改成让清单回答：清单是唯一能同时看到本机、平台、记录与当前 AI 的地方。

## 影响

- **只影响 `startup` 的 stderr 一行**：旅程正文、`startup --plan` 的清单、`prompt` 子命令都不变。
- **有草稿时仍然直接说「上线」**：那是确定的下一步。
- **要重发 CLI beta**：这一行是编译进二进制的；平台技能正文不用动。
