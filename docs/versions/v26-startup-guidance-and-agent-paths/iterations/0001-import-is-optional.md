# 0001 · 传技能改成可选，不挡后面的旅程

- **日期**：2026-10-27
- **决策**：[ADR 0108](../../../decisions/0108-importing-local-skills-is-optional.md)

## 改了什么

- **CLI `startup --plan`**：`planSubmit` 不再返回「待做」；本机没技能 → 跳过「本机没有可上传的技能」；还有没传的 → 跳过「可选；还有 N 个没传，想传的时候再跑一次」；未登录 / 服务端读不到 → 跳过「可选；登录后 / 稍后再看」；都已上线 → 已完成。`renderPlan` 在没有待做项时，如果还有没传的技能，补一句「还有技能没传，想传的时候再跑一次」；有旧副本时仍问可选清理。
- **状态行**：`whereYouAreLine` 的下一步改成「有草稿 → 上线；没有草稿但有本机技能 → 写说明；库里有线上、本机没有副本 → 已完成；都没有 → 写说明」。本机还有没传的副本不再压过草稿与说明；`其中 0 个已上线` 仍然显示。
- **平台技能**：`SKILL.md`、`steps/01-import.md`、`voice.md` 写明「传技能可选」；人拒绝、只传一部分、部分失败都不停，继续走正式上线（只针对已传的草稿）或写说明。
- **安装说明页**：`skillmaster-site/public/install/skillmaster.md` 第 4 步不再说「按步骤把已有 skill 搬到平台上」，改成「想搬的时候搬，不搬也能先配置 AI」。
- **文档**：PRD 的清单表、流程图、典型旅程、验收 11/12/15/17/22、不做第 17 条；TD 的七项表、输出说明、状态行；test-plan 的 T11/T12/T15/T22。

## 为什么

2026-10-27 用真实机器走查 Claude 的旅程：本机唯一的技能 `huashu-design` 有 62 MB（`.git` 31 MB、音频 27 MB），`skill submit` 被服务端以 413 拒绝；用户明确说「我不传那个技能，但是我想把流程走完」。当时清单仍写「还差 1 件」，后面的正式上线、写说明都走不到。把传技能改成可选，第一次旅程就不会因为一个大文件或用户不想迁移而卡死；已经传上去的草稿仍然可以正常上线。

不选「加一个这次跳过的状态」：v26 已经决定不存进度（[ADR 0106](../../../decisions/0106-the-checklist-is-recomputed-not-recorded.md)），记住拒绝会新增一份会漂移的状态。不选「保持必做」：它把存量技能当成使用 SkillMaster 的前提，而真正的前提是说明写进 AI、AI 会从平台取用。

## 影响

- **清单的「还差」少了传技能**：第一次走的用户可能直接看到「全部好了」，而本机技能一个都没传；这是有意的。要迁移时仍跑 `startup --plan`，`steps/01-import.md` 与 `skill submit` 不变。
- **状态行的 KI-1 防线换位置**：从「必须指向搬运」换成「必须显示本机有多少已上线」；KI-1 的原始 bug 仍由名字集合防住。
- **正式上线只算真实草稿**：没传技能时自然为 0，清单写已完成；只传一部分时只针对那部分草稿。
- **旅程完成条件**：说明已写入并验证 + 已经告知用户「以后新任务会用 SkillMaster」；不再要求本机技能全部上线。
- **需要重新发布的产物**：CLI beta（新的提交号）、平台技能 `skillmaster/startup` 的新版本、站点上的安装说明页。三者要同一提交发，避免旧技能配新 CLI 或反过来。
