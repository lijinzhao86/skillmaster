## 用户与场景

**谁在用**

| 角色 | 在这一版里做什么 |
|---|---|
| **第一次装 SkillMaster 的人** | 不懂技术，在 Claude Code 或其他 Agent 里按安装说明装完；接下来不知道该用 SkillMaster 做什么 |
| **重装或换 Agent 的人** | 换了电脑或换了 Agent，重新装完；可能想再走一遍，也可能直接跳过 |
| **Agent（客户端与它运行的模型）** | 执行安装与引导：替用户跑命令，用选项卡让用户做选择，用平实的话解释每一步得到了什么 |

**在什么场景下用**

- 安装文档走到最后：CLI 已装好、已登录。Agent 问一次「要不要花 10 分钟做一次新人引导？」。
  - 选「现在开始」→ 运行 `skmr startup`，加载重构后的引导正文，走 3 块。
  - 选「以后再说」→ 安装结束；CLI 已经能用，以后随时运行 `skmr startup` 再进入。
- 中途中止：用户说停就停；Agent 说清做到哪、没做什么、以后怎么接着来，不把停下说成失败。

**现在的替代做法是什么**

装完后 `skmr startup` 只做「把电脑上的技能传上来」。用户想学怎么找、怎么用、怎么写，只能自己翻 `skillmaster/skillmaster-guide` 或摸索；营销首页只有安装那一句。替代做法的代价是：新用户装完仍然不知道 SkillMaster 能做什么，第一次真正用起来靠运气。

### 引导的内容要求

这三块是**正文必须包含的顺序**；具体措辞在第 5 关写进 `skills/skillmaster-startup/`，但下面这些是需求，不是文风偏好。

| 块 | 用户得到什么 | Agent 做什么 | 完成信号 |
|---|---|---|---|
| 1 找 + 加进库 + 用一次 | 看到公开库里真有现成的做法；知道「加到库里」有什么用，并亲手搜一次、加载一次；知道**以后直接说需求就会被自动找** | 用选项卡问需求 → 搜公开库 → 用选项卡让他挑结果 → 用选项卡确认「加进库」→ `join` → 解释库 → 用选项卡让他选一句想做什么 → 搜自己的库 → `skill invoke` 刚加的那条 → 告诉他以后直接问就行。搜不到用「做 PPT」兜底 | 他用自己的话搜到并加载了刚加的那条，并听完「以后怎么用」那一句 |
| 2 做一条自己的 + 发布 | 自己的一条 skill 上线、搜得到 | 选项卡：`从头写` / `从电脑上导入`。从头写：用选项卡问需求（带 2–3 个例子）→ 起草最小 `SKILL.md` → 给他看 → `skill create` → `skill write`。从电脑上导入：扫出本机技能，用选项卡让他挑 → 找到目录 → `skill submit`。然后 `skill check` → `version publish`（**唯一一次网页确认**）→ `skills search` 验证 | 搜得到自己的 skill |
| 3 可选批量搬本机技能 | 电脑上原来的技能也跟着账号走 | 只在发现本机有可迁移技能时问；同意后沿用 `import/01–04` | 搬进来的都上线了，或用户明确跳过 |

**贯穿三块的七条**：

1. **用户只做选择和确认，命令由 Agent 跑。** 用户不需要自己敲命令。
2. **每步说完「你得到了什么」。** 不是报命令，是报结果。
3. **不出现技术词。** 必须出现时（例如「公开库」）先用一句人话解释。
4. **中途停下是合法结果。** 说清做到哪、没做什么、以后怎么接着来；不说「失败」。
5. **能用卡片就用卡片，每张卡片带推荐项。** 凡是需要用户表态的地方，都用 Agent 自己的选项卡组件（Claude Code 是 AskUserQuestion 这类卡片）；每张卡片至少一个推荐项，放第一个并写「（推荐）」。需要他说需求时，给 2–3 个常见例子当卡片，最后放「我自己说」；只有点「我自己说」才让他打字。目标是**一路点卡片就能走完主线**，全程不用打字。
6. **卡片要让他知道自己在点什么。** 问句里带上判断需要的信息（名字、数量、页面上该看到什么），不要让他往上翻；选项写「点下去会发生什么」，不写内部状态。判断式卡片最多两个选项，第二个是「还没好」这类出口——他卡住时能说话，而不是只能猜。
7. **教他用 `/skillmaster`，缺了就补装。** **只在收尾提一次**（第 1 块不提，避免技能还没确认在就先许诺）：走完主线后告诉他，想直接叫出 SkillMaster 就输入 `/skillmaster`。收尾前确认这个 Agent 实际加载的技能目录里有没有 `skillmaster`（项目级也算）；没有就按安装说明问一次要不要装，同意才照那份文档的第 1–2 节补装；他拒绝或装不上，收尾时不说 `/skillmaster`。

**其他功能指向 guide**：正文开场和收尾都要说一句「SkillMaster 还有别的功能，想了解就跟我说，我可以加载使用指南」；Agent 需要时加载 `skillmaster/skillmaster-guide`，不在引导正文里展开。

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | 不新增 CLI 命令、不改 CLI 代码 | `skills search` / `skill join` / `skill submit` / `skill create` / `skill write` / `skill check` / `version publish` / `skill invoke` 已经覆盖；本版是内容与安装话术 | 不做 |
| 2 | 不改控制台界面 | 引导全程在 Agent 对话里；上线用现有的网页确认页 | 不做 |
| 3 | 不在引导里教 `copy` | 第 1 块默认 `join`：先学会「收进库、直接能用」；要做自己的，第 2 块走「从头写」或「从电脑上导入」。想复制别人的，按 guide 的 `copy` 篇自己学 | 用户明确要求时再开 |
| 4 | 主线（第 1–2 块）不在第 2 块之外再做一次上线 | 第 2 块已经完整走完「检查 + 上线 + 搜得到」；第 3 块迁移沿用现有 import 流程，它自己的上线不算进这条 | 用户明确要求时再开 |
| 5 | 不记录引导进度 | 沿用 v26 的「按实际状态重算、不存进度」（[ADR 0106](../../decisions/0106-the-checklist-is-recomputed-not-recorded.md)）；已上线的 skill 搜得到，就是进度 | 有数据说明重走成本太高时 |
| 6 | 不覆盖云端 / 远程 Agent 的安装 | 沿用 v26 / v38 的边界：它们没有本机技能目录，登录方式也不同 | 云端安装单独开版 |
| 7 | 不做网页版教程 / 控制台向导 | 引导的载体是 Agent 对话；第二个界面会让用户离开对话 | 文档站（TODO「面向人的使用说明书」）另开 |
| 8 | 不自动把练习 skill 设为公开 | 新建的 skill 默认私有；上线后只有自己和协作者看得见。公开与否由用户以后自己决定 | 不做 |
| 9 | 不在引导里教 `secret set`、沙箱配置 | 它们与「找 → 加 → 做 → 发布」不是同一条线，各有 guide 篇 | 人侧旅程的下一次迭代 |

## 控制台操作与 CLI 对应

本版**不新增、不修改任何控制台操作**——控制台没有「新人引导」这一屏。引导里的动作全部由 CLI 完成；只有第 2 块的发布要到网页上确认一次，那是现有的 `skmr version publish`，不是新操作。

为了让 Agent 在引导里只走已存在的命令，把三块用到的命令列在这里：

| 块 | 引导里的动作 | CLI 命令 | 备注 |
|---|---|---|---|
| 1 | 搜公开库 | `skmr skills search "<原话>" --scope public --limit 5` | 只读 |
| 1 | 加进自己的库 | `skmr skill join <地址> --yes` | 不上线 |
| 1 | 核对结果 | `skmr skills list` | 只读 |
| 1 | 自己库搜索（用户原话） | `skmr skills search "<原话>"` | 默认就是自己的库，不加 `--scope public` |
| 1 | 加载刚加的 | `skmr skill invoke <地址> --yes` | 在库里，不用复制 |
| 2 | 从头建 | `skmr skill create <名字> --description <描述>` | 得到私有 skill + 草稿 |
| 2 | 写正文（从头写） | `skmr skill read <地址>@<版本码> SKILL.md` → `skmr skill write ... --overwrite` | 先读再写 |
| 2 | 从电脑上导入 | `skmr skill submit <目录> --name <名字>` | 得到草稿；`--name` 是版本名 |
| 2 | 检查 | `skmr skill check <地址>@<版本码>` | 上线前跑一次；标准输出没有断链行才算过 |
| 2 | 上线 | `skmr version publish <地址>@<版本码>` | 打开网页确认；**主线唯一一次** |
| 2 | 搜索验证 | `skmr skills search "<名字>"` | 自己的库 |
| 2 | 失败核对 | `skmr skills pending` / `skmr version list` | 只读 |
| 3 | 批量搬本机技能（可选） | `skmr skill submit`（逐条，沿用现有 import 流程） | 只在有可迁移技能时；它自己的上线不算进主线的「唯一一次」 |

命令语法以 [`docs/current/cli.md`](../../current/cli.md) 为准；这张表只回答「引导用了哪些动作」。

## 验收与指标

### 验收标准

| # | 验收标准 | 怎么判定 |
|---|---|---|
| 1 | 安装收尾问一次「要不要做新人引导」；选「以后再说」时，`skmr startup` 没有被运行 | 走查安装对话：出现选项卡；选「以后再说」后对话以一句收尾结束；随后 `skmr --version` 有输出 |
| 2 | 选「现在开始」时加载 `skillmaster/skillmaster-startup`；正文按 1–3 块排列，第 3 块标明可选 | 读加载到的正文：三块的标题与顺序都在；第 3 块有「可选」字样 |
| 3 | 第 1 块只执行会改变状态的操作（`skmr skill join`）；`skills list` / `skills search` / `invoke` 只用于核对和加载；不产生副本、不上线；join 后他用自己的话搜到并加载了它 | 走查：命令记录里改变状态的只有 join；他用自己的话搜自己的库，搜到并 `invoke` 了刚加的那条；`skmr skill versions` 没有新版本 |
| 4 | 第 2 块两条路径（从头写 / 从电脑上导入）都能走到发布；从头写得到最小正文，导入得到草稿 | 分别走两条路径各一次，都能到达 `version publish` |
| 5 | 第 2 块恰好一次 `skmr version publish`；上线后 `skmr skills search "<自己的 skill 名>"` 能搜到 | 第 3 块未执行时，命令记录里只有一次 publish；搜索结果显示自己的 skill |
| 6 | 第 3 块只在发现本机有可迁移技能时出现；没有时不出现 | 两台机器各走一次：有本机技能的机器出现这一问；没有的不出现 |
| 7 | 全程不改用户的全局记忆文件 | 走查前后对 `~/.claude/CLAUDE.md` 取 sha256，值相同 |
| 8 | 中途停下是合法结果 | 走到第 2 块说「先停一下」：Agent 说清做到哪、没做什么、以后怎么接着来；不说「失败」 |
| 9 | 用户的需求搜不到时，用「做 PPT」兜底，不空手结束 | 用一个搜不到的需求走第 1 块：Agent 改用「做 PPT」，给出至少一条可 join 的结果 |
| 10 | guide 的 `start/agent.md` 不再把 startup 说成迁移 | 读发布后的 guide 源：它说 startup 是新人引导，完成信号是三块主线 |
| 11 | 主线（第 1–2 块）全程只用选项卡点选就能走完：每个需要表态的地方都出卡片，每张卡片都有推荐项且在第一张；用户不打字也能到「发布上线」之后的搜索验证 | 按住「回车 / 点推荐项」走一遍第 1–2 块：不需要输入任何文字就能走到搜索验证；卡片记录里每处提问都有「（推荐）」项且在第一个 |
| 12 | 每张卡片都说得清「我在点什么」：问句带上判断所需的信息，选项写点下去会发生什么；网页那一步的确认是「页面上『<名字>』这一版标成当前版本了吗？」而不是「弄好了吗？」 | 读一遍第 1–2 块的卡片问句：每张都能脱离上下文读懂；上线确认卡的两个选项是 `好了（推荐）` / `还没好` |
| 13 | 走完主线后告诉用户 `/skillmaster` 能直接叫出 SkillMaster；收尾前查到这个 Agent 实际加载的目录里没有 `skillmaster` 时，先问一次要不要装，同意才按安装说明第 0 步判定、第 2 节装 | 两台机器各走一次：有的机器只听到 `/skillmaster` 这一句；删掉 `skillmaster` 目录的机器先被问一次，装好后收尾；拒绝或装不上时收尾不提 `/skillmaster` |

**成立条件**：#1、#2、#5 不满足就不算交付——它们分别是「安装后真的问了」「引导正文真的换成三块」「主线真的只上线一次」。

### 指标

| 指标 | 定义 | 怎么量 | 目标 |
|---|---|---|---|
| 首次引导完成率 | 走完第 1、2 块的人数 ÷ 开始第 1 块的人数 | 每次人工走查记录结局 | ≥ 3/5 |
| 中位时长 | 从第 1 块开始到第 2 块搜索验证完成的分钟数 | 人工计时；5 位首次使用者；中位数 | ≤ 10 分钟 |
| 一次上线成功率 | 第 2 块一次上线成功的人数 ÷ 走到第 2 块发布的人数 | 人工记录是否一次通过网页确认 | ≥ 4/5 |

## 依赖与前置

- **外部依赖**：平台上的 `skillmaster/skillmaster-startup` 可发布新版；`skillmaster/skillmaster-guide` 可发布 patch；安装文档部署到下载桶（`skillmaster-dl` 的 `beta/` 前缀）。
- **内部前提**：ADR 0206（startup 是引导程序；安装先问；公开库默认 join）；v68 云登录已合并（`63db993`），安装文档的登录话术已在这一版里；合并本版时再核对一次同一文件的相邻改动。
- **从 TODO 搬入**：[`docs/current/TODO.md`](../../current/TODO.md) 的「新人旅程（人侧引导）」里，第一次搜索、第一次 join、第一次写/上线、第一次 invoke 由本版覆盖；沙箱权限与 `secret set` 不在本版，仍留在 TODO。
- **排除了什么前置**：不需要新的服务端接口；不需要新的 CLI 命令；不需要控制台改动；公开库已有可 join 的 skill（例如「做 PPT」搜到的 `skillmaster/baoyu-slide-deck`），不需要为引导新建示例 skill。
