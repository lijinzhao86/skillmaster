## 用例

### T1 · 安装后选「以后再说」

- **前置**：一台干净机器（没有 SkillMaster 凭据）；用安装说明走完技能与 CLI 安装、确认登录；账号未执行过引导。
- **步骤**：安装文档走到「交棒」；出现选项卡；选「以后再说」。
- **期望**：对话以一句收尾结束；没有运行 `skmr startup`；随后 `skmr --version` 有输出。
- **判定**：通过／失败（失败时记录实际观察到的现象）。

### T2 · 安装后选「现在开始」，读完三块正文

- **前置**：同 T1，选「现在开始」。
- **步骤**：运行 `skmr startup`；读加载到的正文。
- **期望**：正文按第 1–3 块排列；第 3 块标明可选；开场列出三块；Agent 说出第一句引导话术。
- **判定**：通过／失败。

### T2b · 首次安装、登录后选「现在开始」

- **前置**：一台干净机器（`auth status` 返回 1，没有凭据）；安装说明走到「交棒」。
- **步骤**：按「退出码 1」分支登录；重跑 `auth status` 得到 0；选「现在开始」。
- **期望**：Agent 按「退出码 0」分支说第 28 行并运行 `skmr startup`；没有停在「只问一句」就结束。
- **判定**：通过／失败。

### T3 · 第 1 块：找、加进库、用自己的话搜到并加载

- **前置**：T2 进入第 1 块；用户挑中一条公开 skill。
- **步骤**：出现「加进库」确认卡，选推荐项；`skmr skill join <地址> --yes`；`skmr skills list`；让用户用自己的话说一句想做什么；`skmr skills search "<他的原话>"`；`skmr skill invoke <地址> --yes`；`skmr skill versions <地址>`。
- **期望**：改变状态的只有 join；用户在自己库的搜索结果里看到刚加的那条；`invoke` 成功；没有产生新版本、没有上线；加载后 Agent 说了「以后直接把你要做的事说出来就行」。`/skillmaster` 留到收尾再说，第 1 块不提。
- **判定**：通过／失败。

### T4 · 第 2 块走「从头写」

- **前置**：第 1 块完成；用户选「从头写」。
- **步骤**：Agent 先问「你想让它帮你做什么」，起草最小 `SKILL.md` 并给用户看；用户点头后 `skmr skill create <名字> --description <描述>`；`skmr skill read <地址>@<版本码> SKILL.md`；`skmr skill write ... --overwrite`。
- **期望**：得到私有 skill + 草稿；正文有 frontmatter 与 3–5 句做法；进入发布。
- **判定**：通过／失败。

### T5 · 第 2 块走「从电脑上导入」

- **前置**：第 1 块完成；用户选「从电脑上导入」；本机有一个带 `SKILL.md` 的技能目录。
- **步骤**：用户说一条本机技能；Agent 找到目录；`skmr skill submit <目录> --name <名字>`。
- **期望**：得到草稿；地址与版本码可读；进入发布。
- **判定**：通过／失败。

### T6 · 第 2 块恰好一次上线，并搜得到

- **前置**：T4 或 T5 完成；用户同意上线。
- **步骤**：`skmr skill check <地址>@<版本码>`；`skmr version publish <地址>@<版本码>`；在网页确认；`skmr skills search "<名字>"`。
- **期望**：第 3 块未执行时，命令记录里只有一次 publish；搜索结果显示自己的 skill。
- **判定**：通过／失败。

### T7 · 有本机技能时出现第 3 块

- **前置**：一台本机有可迁移技能的机器（例如 `~/.claude/skills/` 下有一个非 `skillmaster` 的技能）；走完第 2 块。
- **步骤**：听 Agent 的收尾；确认是否问批量搬。
- **期望**：问了「要不要一起搬进来」；同意后进入 `import/01–04`；第 2 块已经导入过的那条没有重复传。
- **判定**：通过／失败。

### T8 · 没有本机技能时不出现第 3 块

- **前置**：一台本机没有可迁移技能的机器；走完第 2 块。
- **步骤**：听 Agent 的收尾。
- **期望**：没有出现批量搬这一问；直接收尾。
- **判定**：通过／失败。

### T9 · 第 3 块批量搬的中途停下

- **前置**：T7 进入第 3 块；传了一个技能后说「先停一下」。
- **步骤**：听 Agent 的收尾。
- **期望**：Agent 说清做到哪、没做什么、以后怎么接着来；没有把用户带回第 2 块的「检查、发布」或再点一次上线。
- **判定**：通过／失败。

### T10 · 全程不改全局记忆

- **前置**：T2 开始前，对 `~/.claude/CLAUDE.md`（或当前 Agent 的全局记忆文件）取 sha256。
- **步骤**：走完 T2–T6；再取一次 sha256。
- **期望**：两次值相同。
- **判定**：通过／失败。

### T11 · 第 2 块中途停下

- **前置**：T2 走到第 2 块。
- **步骤**：用户说「先停一下」。
- **期望**：Agent 说清做到哪、没做什么、以后怎么接着来；不说「失败」。
- **判定**：通过／失败。

### T12 · 搜不到时的兜底

- **前置**：T2 走到第 1 块。
- **步骤**：用户给一个公开库搜不到的需求（例如「帮我写一份工作总结」）。
- **期望**：Agent 改用「做 PPT」搜索，给出至少一条可 join 的结果（当前为 `skillmaster/baoyu-slide-deck`）。
- **判定**：通过／失败。

### T13 · 沙箱里打不开上线确认页

- **前置**：一个会拦 `open` 的沙箱客户端（例如 Claude Code 的沙箱）；T6 走到 publish。
- **步骤**：先正常运行 `skmr version publish`；如果命令说「没能自动打开浏览器」或无法打开浏览器，改用 `--print`。
- **期望**：Agent 把打印出的地址给用户；用户在自己的浏览器里确认；上线成功。
- **判定**：通过／失败。

### T14 · 第 2 块名字不合法或被占用

- **前置**：T4 或 T5 走建名。
- **步骤**：先用中文名试一次，再用一个已存在的名字试一次。
- **期望**：两次都被拒绝；Agent 第一次认出错因是「名字只能用英文字母、数字和连字符」，不是「被占用」；换一个 ASCII 名字后成功。
- **判定**：通过／失败。

### T15 · guide 不再把 startup 说成迁移

- **前置**：v71 发布后。
- **步骤**：读 `skmr skill show skillmaster/skillmaster-guide` 的 `start/agent.md`。
- **期望**：它说 startup 是新人引导，完成信号是「找 → 加进库并加载 → 做一条并发布」。
- **判定**：通过／失败。

### T16 · 全程点卡片走完主线

- **前置**：同 T2；账号未执行过引导。
- **步骤**：选「现在开始」后，**全程不输入任何文字**——每一处提问都点第一个选项（推荐项）或直接回车；第 1 块的结果选择点推荐的那条；第 2 块走到搜索验证为止。
- **期望**：第 1–2 块每个需要表态的地方都出卡片；每张卡片第一项带「（推荐）」；不打字也能走到「上线后搜得到自己的 skill」；只在用户主动点「我自己说」时才出现要求打字的提问。
- **判定**：通过／失败（失败时记录哪一处没有卡片、或哪张卡片没有推荐项）。

### T17 · 卡片问句自带上下文

- **前置**：同 T2。
- **步骤**：走第 1–2 块，每张卡片只看问句和选项、不看上文，判断自己能不能回答。
- **期望**：每张卡都能独立读懂；挑结果那张带用户刚才那句话；起草确认那张带名字和一句话概括；上线确认那张问的是「页面上『<名字>』这一版标成当前版本了吗？」，选项是 `好了（推荐）` / `还没好`。
- **判定**：通过／失败（失败时记下哪张卡脱离上下文读不懂）。

### T18 · 收尾教 `/skillmaster`；缺技能时补装

- **前置**：一台技能目录里有 `skillmaster` 的机器；一台删掉 `~/.claude/skills/skillmaster` 的机器。
- **步骤**：两台各走完主线。
- **期望**：第一台只在收尾听到「输入 `/skillmaster` 就能直接叫我」，没有多余动作；第二台先被问一次「要不要装」，同意后按安装说明第 0 步判定、第 2 节装，装好才收尾；拒绝时按安装说明第 3 行再问一次，再拒绝就收场且收尾不提 `/skillmaster`；装不上时按那份文档的失败话术停下，不自编命令。
- **判定**：通过／失败。

## 环境与数据

- **环境怎么造**：一台 macOS 或 Linux 机器；装 CLI 并登录一个测试账号；再准备第二台没有本机技能的机器（T8）。两台都用安装说明从干净状态开始。
- **数据**：
  - 公开库里的 `skillmaster/baoyu-slide-deck`（2026-11-14 验证公开、可 join）；若它下线，换一条同为公开的官方 skill。
  - 一个普通用户需求（如「做 PPT」）用于第 1 块；一个搜不到的需求用于 T12。
  - 一个带 `SKILL.md` 的本机技能目录，用于 T5 和第 3 块（T7）。
  - 测试账号的库在开始前清空或确认没有同名 skill，避免 T14 以外的重名干扰。
- **清理**：测试产生的私有 skill 与草稿留在测试账号里；不删用户真实数据。测试账号可整体弃用。

**真跑抓到两个静态评审没抓到的问题，已修进正文**：

1. `02-join.md` 加载完只说「它就在你的库里」，用户不知道「以后怎么用」。现在第 1 块补一句「以后直接说要做的事就行」；`/skillmaster` 留到收尾（先确认技能在）再说，见 T18。
2. `04-publish.md` 没写「网页要登录」：命令行登录不等于浏览器登录，`skmr version publish` 打开的控制台会弹登录页。现在 `04-publish.md` 的步骤与失败表都补了这一条，并写明「别让他把密码发给你」。
