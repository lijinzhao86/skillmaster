# v4-cli-login · 产品需求

> **最后更新**：2026-10-16
> **所属版本**：[`README.md`](README.md)

> **这一版的来源是一句已经写下的话。** [`v3-sessions`](../v3-sessions/prd.md) §不做 #1 记着：CLI 那条浏览器路签发的**凭据**改成**不自动续期、寿命 1–7 天、出现在列表里**，什么时候做写着 **vN+1**。
>
> 注意那句话说的是**凭据**，不是 key。「把它做成一把 key」是 [ADR 0040](../../decisions/0040-api-key-in-the-cli-now-the-browser-path-later.md) §决定 3 给的答案——**本版不采用它**（理由见 §范围 不做 #1）：那个答案与下面第 1 条事实相抵。

## 用户与场景

**谁在用**：两类，分法与 [ADR 0040](../../decisions/0040-api-key-in-the-cli-now-the-browser-path-later.md) §背景 相同——

- **坐在自己电脑前、有浏览器的人**（这一版的主要受益者）
- **在没有浏览器的机器上跑 agent 的人**（这一版**不动他们**：他们手里是一把**长期凭证**，见 §范围 不做 #4）

**在什么场景下用**：

- **第一次把一台机器接上。** 今天他要走六个概念：去控制台签一把 key → 起名字 → 选权限 → 选有效期 → 复制 → 回终端粘贴。这一版之后是：`skillmaster login` → 浏览器自己开 → 点一下。
- **把一份不再用的凭据收回来**（**这一版真正的理由**）。他在一台后来不用的机器上点过一次授权——借给同事的笔记本、卖掉的那台、公司的台式机。这份凭据今天：控制台**看不见**，**撤不掉**（唯一能连带撤掉它的动作是重置密码，而那会把这个账号**所有设备**的登录一起踢掉），而且会**自己续命**，一路活到 180 天。
- **它该死了而它不死。** 机器丢了、人离职了、只是忘了——今天这条路换来的凭据不会到点。

**现在的替代做法是什么**：去控制台签一把 key → `login --with-key` 粘过去。它今天**能用**，代价是**要人理解 key 那一套**，而那正是 ADR 0040 §理由 说这一版要免掉的东西。另一条替代做法是**重置密码**——为了撤掉一台而清掉全部。

**一件必须一起说清的事**：这一版之后，浏览器那条路拿到的**仍然是短期凭证**，不是 key。所以天天用 CLI 的人**每 7 天要在浏览器里点一下**；两天以上才用一次的机器，**每次都要点**。

**这是设计要的，不是它的缺陷。** 那条路产出的是**登录态**，而登录态就该会死——它的寿命与浏览器会话同一套尺子（绝对 7 天 / 闲置 24 小时，见 [`v3-sessions`](../v3-sessions/prd.md)）。**要一个不会死的凭据，那条路本来就是错的工具**：去控制台签一把 key（它的寿命是与用途相称的 90 天）。**两条路各自服务于不同的处境，这不方便，但它是诚实的。**

## 范围

### 做

| # | 做什么 | 交付形态 |
|---|---|---|
| 1 | **浏览器点一下，给这台机器一个短期凭证**：`skillmaster login`（不带参数）打开浏览器 → 一屏**「授权请求」**（一个**预填、可改**的「**名称**」——默认值由 **CLI 从那台机器上读**（macOS 的 `ComputerName`、Linux 的 pretty hostname、Windows 的 `COMPUTERNAME`），随地址一起来，**清空则按钮点不动**；权限**来自地址、不可勾选**——它是 CLI 申请的，不是人在这一屏上选的）→ 点「**同意并继续**」→ 经 loopback 用**一次性码**换回**一个短期凭证** → CLI 存下。**寿命不是这一屏上的可选项**（见 #3）：两条尺子是定值，页面只**说清**它是什么 | 网页一屏 + 服务端两条接口 + CLI 换实现（含**按平台读机器名**） |
| 2 | **它不自动续期**：这条路**不再发 refresh token**，所以今天那条刷新链、那把刷新锁、那个"同时刷新会留下两把活的"的竞态窗口，对**第一方**不再有读者 | CLI 退休一段实现；服务端那条路不再发第二张令牌 |
| 3 | **两条尺子，与浏览器会话同一套**（2026-10-16 定）：**绝对 7 天**（从签发那一刻算）**＋ 闲置 24 小时**（这台机器上一次用它之后，24 小时没再用就失效）。碰到任何一条都要**重新点一下** | 见 [`technical-design.md`](technical-design.md) §数据模型 |
| 4 | **它看得见、撤得掉**：有一个入口列出这台账号**所有以你的名义登录着的东西**，并能**单独结束其中一份**——结束之后那台机器**下一次请求即被拒** | 控制台一屏（v3 的「登录设备」，见 [Q6](technical-design.md)）+ **服务端新增一条"结束一份登录"的接口**——今天**没有**这条路：`TokenRevocation` 只暴露 `revokeAllFor(userId)`（全撤），`/web/sessions/{id}/revoke` 结束的是**浏览器会话** |
| 5 | **删掉 `login --with-key`**：它存在的理由是"浏览器那条路产出的东西不好用"，而这一版之后浏览器那条路**产出的是一个会死的登录态**——把一把长期凭证粘到本机这件事，**不属于这条路**（见 §不做 #4） | CLI 的 help / README / 错误消息 |
| 6 | **无浏览器机器上 `login` 的失败语只指一条路**（环境变量 + 一把 key），**不再指向一条被删掉的命令** | CLI 的一句提示语 |
| 7 | **过渡期残留有归宿**，而**残留有两种、说的话不一样**（2026-10-16 校正）：<br>**(i) 旧的浏览器登录留下的 OAuth 令牌**（**有**刷新令牌）——说清它是什么、为什么不再能用、下一步做什么，**并且顺手把它结束掉**（`auth.RevokeAuthorization` 拿刷新令牌就能撤，**撤得掉**）；<br>**(ii) v3 删掉的那条无人值守路留下的**（**没有**刷新令牌）——**撤不掉**（它的认证是一个已经不在的 client secret），只能说清、让它自己过期。**说成"上一份已撤销"在 (ii) 上是不成立的话**，而那正是今天代码里已经写着的那句 | CLI 的两条分支 + 两句不同的话 |
| 8 | **没有凭据时，命令自己把登录引起来**：CLI 发现本机没有可用的凭据时**调起登录**，登录完成后**继续执行原来那条命令**（不是"登录好了，请你再敲一次"） | CLI（能开浏览器的判据是既有的 `BrowserAvailable`） |
| 9 | **两条只读的查询命令**：查**当前**凭据是什么、能做什么；查**这份凭据对某一个 skill** 能做什么。**规矩只有一条**（2026-10-16 校正）：能做什么 = **这份凭据的 `scope` ∩ 账号此刻的权限**——**两种凭据都带 scope**（`access_token.scope` 是 `NOT NULL`，签发时写入、校验时读成权限），差别在**值**：key 的 scope 是签发时勾的，登录态的是 CLI 申请的那两个。所以**同一个账号换一份凭据，答案可以不同**——原因不是公式不同，是 scope 不同 | CLI（第二条服务端今天没有现成答案，形状见 [Q9](technical-design.md)） |
| 10 | **把一个 skill 从所有人手里拿走这件事，收回到浏览器里**（2026-10-16 加）：**撤掉 API 平面那条 `DELETE /api/v1/skills/{ns}/{name}` 路由**；「授权请求」那一屏随之不再把「删除 skill」列进凭据的能力（**只是不再列，不在那一屏上另说一句"它不能删"** —— 见下）。**控制台那处入口不在本版**，见 §不做 #8 与 [ADR 0046](../../decisions/0046-deleting-a-skill-happens-in-the-browser.md) | 服务端撤一条路由 + 同意页文案 |
| 11 | **凭据死了要分四种说清，而这条凭据今天拿不到那四种**（2026-10-16 校正，**新工作量**）：本版要求「**闲置太久 / 已到期 / 被结束 / 账号停用**」四句不同的话（验收 #5(a) 与 #11），而服务端**只有 API key 那条路**产生具名拒绝（`IssuedTokenValidator` 的 key 分支给 `TOKEN_EXPIRED` / `TOKEN_REVOKED` / `ACCOUNT_SUSPENDED`）；`access_token` 那条路的拒绝**全部收敛成一个**（那个类的注释自己写着 *this path's refusals are all the same one*）。**要让这份凭据也分四种，得改服务端那一段。** 第四句是**闲置**：验收 #5(a) 要它**不是**「已到期」，因为两句指向不同的下一步；而本版把闲置做成**滑动 `expires_at`**（[`technical-design.md`](technical-design.md) §数据模型），两种到点在库里长得一样，所以判定靠**封顶**——过了 `created_at + 绝对` 就是「已到期」，没过就是「闲置太久」 | 服务端一条校验路径 + 一个具名拒绝 |
| 12 | **这一族词统一到「授权」，回环页那两句标题跟着改**（2026-10-16 定，**当天改过两次**）：请求那一屏叫「**授权请求**」，回答之后落的两页就叫「**授权成功** / **授权未完成**」——**同一族词**，不再一处说"登录"、一处说"授权"。那次来回的理由与代价（动作说授权、产物仍叫「登录设备」）记在 [`design/README.md`](../../../design/README.md) §怎么打开「授权请求」。**改的是用户会看到的句子**，CLI 那两个字符串（`internal/auth/callback.go`）与设计件必须一起对 | CLI 两个字符串（设计件跟着改） |
| 13 | **结果页自己收场，而关不掉时说的是实话**（2026-10-16 定）：落在回环页上之后，它**先把话说明白**——「这个页面将在 3 秒后自动关闭。」，**那个数字每秒往下走**——到点自己关；**关不掉当场改口**，把那句换成「这个页面没有自动关闭，请手动关闭它。」。**为什么必须改口**：`window.close()` 只对**由网页内容创建**的窗口有效，而这一页是 CLI 交给**操作系统启动器**打开的（`exec.Command("open", …)`），所以**关不掉是常态**；一句说好要关闭却一动不动地待着的承诺，出现在一张报告"授权成没成"的屏幕上就是假话 | CLI 那一页的脚本与两句文案（**设计件先定**，见 [`design/README.md`](../../../design/README.md) §授权结果） |

**第 6、7 条为什么写进范围而不是留给实现**：它们是**用户会看到的句子**。删掉一个参数、换掉一种凭据，实际影响落在"那台老机器上的人会读到什么"——那是需求，不是实现细节。（[`v3-sessions`](../v3-sessions/prd.md) §范围 为同一件事记过一笔，这里是同一个形状。）

**第 10 条是这一版里唯一一处"跟本版目标没有直接关系、但必须同一次做掉"的事**，写在这里的原因是它在**同一屏**上：同意页的权限清单原先写着「以你的名义提交新版本、管理共享、**删除 skill**」，而**那是真的**——`DELETE /api/v1/skills/{ns}/{name}` 存在，网关只要 `skills:write`，资源层再要求你是 owner（`SkillVersionService.softDelete`，editor 不行）。产品对「**会把东西从别人手里拿走的动作**」有一条现成的规矩（由人做、在浏览器里做、再确认一次），而它只用在了**上线**上：上线在浏览器面有路由、在 API 平面没有（[ADR 0031](../../decisions/0031-submitting-and-publishing-are-two-actions.md) §决定 2），所以凭据上线不了；删除**正好相反**——只在 API 平面有。把「删除」从凭据的能力里划掉，就必须**同一次**撤掉那条路由：同意页上不再出现「删除」，**而沉默只有在它确实做不到的时候才算实话**——路由还在的那一天，凭据仍然删得了，那份清单就只是没提它。（这一屏原先另外有一行灰字说它**做不到什么**——HEAD 上那句是「它不能上线——把版本对外公开，是你在网页上确认的动作。」；2026-10-16 当天先把「删除」也加进那一行、随后**整行删掉**，所以它两个动作都不再提。见 [`design/README.md`](../../../design/README.md) §怎么打开「授权请求」。）**这一条的原因、被否掉的两种做法、以及那个空档的代价，写在 [ADR 0046](../../decisions/0046-deleting-a-skill-happens-in-the-browser.md)。**

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | **把短期凭证做成 API key** | **两种凭证技术上不是一回事**：一个是**登录态**（一次授权、会死、要重新点），一个是**长期凭证**（签发时定寿命、粘到各处、给无人值守用）。合起来之后，「API 密钥」那一屏上会同时住着这两样，而两者都叫 key——**「key 是长期凭证」这句话就不成立了**，而它是 [`v2-credentials`](../v2-credentials/prd.md) 整版的前提 | 不做 |
| 2 | **用短期凭证去造长期凭证**（在 CLI 里签发 key） | 泄漏之后**撤不干净**：攻击者用你泄漏的那把造出新的，你撤销原凭据只杀掉原凭据。要堵住必须引入家族/血缘，那是另一块机制。**签发仍然只有会话**这一个入口（[ADR 0040](../../decisions/0040-api-key-in-the-cli-now-the-browser-path-later.md) §决定 1、§理由） | 要做必须先有家族/血缘 |
| 3 | **撤掉 `/oauth/*`**（授权码、同意页、轮换、loopback） | 那是**第三方**要走的路（[ADR 0041](../../decisions/0041-third-parties-reach-us-through-the-cli.md)）。**第一方不再借它**——[Q4](technical-design.md) 已经定下：`/oauth/*` 只留给第三方、不删，第一方走 `/cli-sign-in` 那一族新路由 | 不做 |
| 4 | **改控制台签的那把 key**（它的形态、它的寿命、它那一屏） | 它是**长期凭证**，本版**一个字节不动**。要一把不会死的凭据，那条路才是正解——这也正是 §用户与场景 里那句话的落点 | 不做 |
| 5 | **无浏览器机器的设备码流程**（RFC 8628） | 那里已经有**通的路**——环境变量 + 一把 key。往一个能用的地方加第二种做法，买不到任何东西，只多一套要解释的概念 | 真有"有浏览器但打不开"的场景时 |
| 6 | **会话带 scope** / **记住我** / **到期邮件提醒** | 前两条的理由**全部继承** [`v3-sessions`](../v3-sessions/prd.md) 与 [`v2-credentials`](../v2-credentials/prd.md)；第三条是因为**本产品没有邮件通道** | 同各自的原地 |
| 7 | **MCP 适配器与 CIMD** | 继承 [`v2-credentials`](../v2-credentials/prd.md) §不做：第三方**就是通过我们的 CLI** 接进来的，被推迟的是那一个适配器 | 同 v2 |
| 8 | **控制台的删除入口与二次确认**（2026-10-16 定：**挪出本版**） | 删除这个动作属于 **skill 管理模块**，而本版做的是凭据那条线；本版只把凭据那一侧的入口关掉（做 #10 + [ADR 0046](../../decisions/0046-deleting-a-skill-happens-in-the-browser.md)）。**代价如实记**：入口画出来之前，**删除在整个产品里无处可做**——今天也只有凭据能删，所以这不是"少了一条路"，是这条路暂时不存在 | **skill 管理模块那一版**（本版只在文档里挂着这条待办） |

## 一次操作有哪几种结果

**这一节是权威。** 每一条要鉴权的命令，结果只有下面这几种；**每一种说的话不一样，因为它们指向的下一步不一样**。凭据有两个来源，所以同一个"权限不够"在两边**是两件事**。

| # | 情形 | 协议上的表达 | 终端该说什么 | 下一步 |
|---|---|---|---|---|
| 1 | 有 env，权限够 | 200 | — | — |
| 2 | 有 env，**key 的 scope 不够** | **403 `insufficient_scope`**，**带** `WWW-Authenticate` 点名缺的那个 | 「这把 key 没有 `skills:write`」 | **换一个凭据**：到控制台签一把带它的，或换环境变量里的那一把。**不提登录**——登录解决不了这件事 |
| 3 | 没有 env，**没登录过** | **本地就失败，连接都没发** | 「本机没有可用的凭据」 | **CLI 调起登录鉴权**（见下） |
| 4 | 已登录，权限够 | 200 | — | — |
| 5 | 已登录，**账号对这个资源没有这个权限** | **403 `forbidden`**，**不带** challenge | 「你对这个 skill 没有这个权限」 | **换一个凭据没有用**——所以**不许提示重新授权** |
| 6 | 凭据**已经死了**（闲置太久 / 已到期 / 被结束 / 账号停用） | **401**，服务端点名是四种里的哪一种（**这条凭据今天只答得出一种——见 做 #11**） | 四句各不相同：**闲置太久** → 重新点一下（这台机器一天多没用它）；**已到期** → 重新点一下，**或者去控制台签一把 key**（登录态**没有续期**这条路，要一把不会死的凭据就得换形态）；被结束 → 重新点一下；账号停用 → **不是这份凭据的问题** | 重新取得凭据。**这一类在新设计里是常见的**：登录态 7 天就死、闲置 24 小时就死 |
| 7 | env 里**装的不是一把 key** | **本地就失败** | 「`SKILLMASTER_API_KEY` 里装的不是一把 API key（应以 `skm_` 开头）」 | 改对或去掉那个变量 |

**2 与 5 为什么必须分开**（这一节最容易做错的一处）：`insufficient_scope` 的意思是**换一个凭据能解决**；`forbidden` 的意思是**问的是谁在问**——服务端**故意不给它 challenge**，因为带了它客户端就会「re-authorize, get the same 403」。**把两句合成一句泛泛的 403，等于把"换一把就行"和"换什么都没用"说成了同一件事。**

**3 与 6 为什么都要有**：它们的下一步一样（重新取得凭据），**但要说的话不一样**——"你还没登录"与"你那份凭据过期了"是两件事，而**前者指向"下一步做什么"、后者指向"为什么昨天还能用"**。

**第 3 条是本版的一处显式改动**：今天 CLI **不会**替你开浏览器——命令失败，让你自己跑 `login`（代码里的理由是「在 `search` 里弹出浏览器是**惊讶**不是服务」）。本版改成**调起登录**，登录完成后**继续执行原来那条命令**。**一条边界**：只有在**能开浏览器**时才这么做（既有的 `BrowserAvailable` 就是判这件事的），既没有终端也没有浏览器的环境里**不弹**，照样失败并指向环境变量。

**第 9 条问的是"当前这份凭据能做什么"，不是"我这个账号能做什么"**——**权限取决于走的是哪条鉴权路径**：key 是 `scope ∩ 账号权限`，登录态是账号权限。所以同一个账号、同一台机器，**换一份凭据答案就可以不同**，而这条命令要答的正是**当前生效的那一份**（见 [Q9](technical-design.md)）。

查**当前凭据**那一半，`auth status` 已经答了 key 的那部分；查**对某一个 skill** 那一半，**服务端今天没有这个答案**——能不能读某个 skill 是 M4 在用例里现算的，而"读不到"渲染成 **404**（不泄露存在性），不是一张权限表。

## 验收与指标

### 验收标准

| # | 验收标准 | 怎么判定 |
|---|---|---|
| 1 | **在一台有浏览器的机器上，点一下就能用上 CLI** | 干净环境里跑 `skillmaster login`（不带参数）→ 浏览器打开那一屏 → 点一下 → 终端说已登录，并印出**它的名字 / 权限 / 什么时候到期** → `skill list` 通。**全程没有出现过"复制粘贴一串字符"这一步** |
| 2 | **它出现在控制台上，而且能单独结束**（成立条件） | 登录后打开**它那一屏**：**多出一行**，名字是页面上填的那个，写着它的登录地址与**最近活动**；**结束它** → 这台机器上的**下一次请求即被拒**（不是等过期）。结束之后那一行**消失**、计数跟着变——**这一屏不另写一句"已结束"**，结果是**状态本身**说的（[`v3-sessions`](../v3-sessions/technical-design.md) §接口：原话是「行没了…这三件事就是结果」，设计件与它的断言都按这个来） |
| 3 | **它不会自己续命**（成立条件） | 让它到期（把库里的到期时间改到过去）→ 这台机器上的下一次命令说清是**到期**，**而且它不会自己换回一个能用的**；再跑一次 `login` 才恢复。**反证**：同样的手法用在**今天**这条路上，它**不会过期**——它会自己刷新回来。**这两条行为必须不同**，否则这一版等于什么都没改 |
| 4 | **它是短期凭证，不是一个 key** | **「API 密钥」那一屏一个字节不动**——**不多一行、不少一行、没有新的标记**；`api_key` 表**没有新行**；它落在**令牌那一族**（具体哪条路见 [Q5](technical-design.md)：我们自己写那一行，不动框架的授权服务器）；**没有任何"从 CLI 来的"东西落在 key 上** |
| 5 | **两条尺子各自到点，而且都可配** | （a）把它的最后活动推到 24 小时以外 → 下一次命令说清是**闲置太久**，**不是**「已到期」（两句指向不同的下一步：一句是"重新点一下"，一句是"重新点一下或去签一把 key"）；（b）把它推到**绝对上限之外**——**签发时间**一起推到 7 天前，`expires_at` 也随之到点 → 说「**已到期**」；（c）把绝对配得比闲置**短** → **启动失败**，不是静默禁用其中一条（判定方式与 [`v3-sessions`](../v3-sessions/prd.md) §验收 #9 逐字相同） |
| 6 | **`login --with-key` 不再存在** | 在 CLI 里搜这个形状：**用户可见的文本**（帮助输出、README、错误消息）**零命中**。参数名本身会留在断言它被拒的那条测试里——**那正是要的答案**（判定方式与 [`v3-sessions`](../v3-sessions/prd.md) §验收 #10 逐字相同） |
| 7 | **那两句提示语说的是实话**（**两种残留，两句不同的话**，见 做 #7） | （a）在没有浏览器的环境里跑 `skillmaster login` → 当场失败，信息**只指向环境变量 + 一把 key**，不指向任何已删除的形状；（b）**旧的浏览器登录令牌**（有刷新令牌）：跑一条需要凭据的命令 → 那句话**说清它是什么、为什么不再能用、下一步做什么**，**而它确实被结束了**（再跑一次 `login` 时上一份**不再活着**）；**反证**：把这句话改成"撤不掉"，这条当场失败——它撤得掉（`auth.RevokeAuthorization`）；（c）**无人值守路的残留**（**没有**刷新令牌）：说清它是什么、**为什么从这台机器撤不掉**、以及**它会自己过期**——**不许说"上一份已撤销"**，那是一句不成立的话 |
| 8 | **权限不够的两条路，说的话不一样** | （a）用一把**只勾了 `skills:read`** 的 key 跑 `skill submit` → 终端说清**是这把 key 缺 `skills:write`**，并指向"换一把带它的"，**且不提登录**；（b）用登录态去改一个**你读得到、但没有编辑权的** skill（**前置要造"viewer 而不是 editor"那一种共享**——完全没共享给 A 的话它读不到，那是 404、不是 403，判定会落错格）→ 终端说**你对这个 skill 没有这个权限**，**且不提重新授权**。**两句一样就等于这条没做**——它们的区别正是人能采取的动作不同 |
| 9 | **没有凭据时，命令自己把登录引起来，登录完继续执行** | 干净环境里跑 `skill list` → 浏览器打开那一屏 → 点一下 → **原来那条 `skill list` 自己跑完并给出结果**（不是"登录好了，请你再敲一次"）。**一条边界**：既没有浏览器也没有终端的环境里**不弹**，照样失败并指向环境变量 |
| 10 | **查询命令答的是"当前这份凭据能做什么"** | （a）**当前凭据**：印出它来自哪里（环境变量还是本机存储）、**是 key 还是登录态**、服务端认它是谁、它能做什么；（b）**对某一个 skill**：说清**这份凭据**对这个地址能不能读、能不能写。**判定这一条的关键**：同一台机器上，先用一把**只读的 key**、再用**登录态**，各查一次同一个 skill——**两个答案必须不同**（前者答"不能写"、后者答"能写"）。要是两次一样，说明它答的是"账号能做什么"，而不是"当前凭据能做什么"。对一个**我读不到**的地址，答案与"真不存在"同一个 |
| 11 | **凭据死了的四句话，各不相同**（**这条要求今天做不到——见 做 #11**） | 分别造出四种：把最后活动推到 24 小时以外、把签发时间推到绝对上限之外、结束它、把账号停用 → **对这份登录凭据**四句**互不相同**，且**账号停用那一句不栽给这份凭据**。**前两句必须不同**——那正是 #5(a) 量的那件事。判定方式与 [`v2-credentials`](../v2-credentials/prd.md) §验收 #1 的后半逐字相同。**今天这几句只有 key 那条路给得出**（`access_token` 那条路的拒绝收敛成一个），所以这一条**先要服务端能分四种**，否则它会以"几句一样"失败——而那正是它要量的东西 |
| 12 | **删除只在浏览器里发生，凭据删不了**（对应 §范围 做 #10） | （a）分别**用登录态**和**用一把勾了 `skills:write` 的 key** 发一次 `DELETE /api/v1/skills/{ns}/{name}` → **两边都拿不到 204**（路由已不在）；（b）「授权请求」那一屏的权限清单里**不含「删除」**（那一屏不再另说一句"它不能删"，所以清单就是全部）——(a) 与 (b) 必须同时成立，**只有一边成立就是这一条没做**。**控制台那处入口不在本版判定**（§不做 #8） |
| 13 | **回环页那两句标题与这一族词一致**（对应 §范围 做 #12） | 同意与拒绝之后各落一页：标题是「**授权成功**」/「**授权未完成**」。**四处同词**：请求那一屏、两页结果、以及产品里那一屏（`/consent`）的标题。**设计件与 CLI 两处都要对**（设计件那两页是 CLI 回环页的照抄）——**这一族词 2026-10-16 当天改过两次**（授权 → 登录 → 授权），判它时以最终那一边为准 |
| 14 | **名称是预填的，点一下就能授权**（对应 §范围 做 #1） | 在**三个平台各跑一次** `skillmaster login` → 那一屏的名称框里**已经填着这台机器在人系统里的名字**（macOS 是系统设置里那个 `ComputerName`、Linux 是 pretty hostname、Windows 是 `COMPUTERNAME`），**点「同意并继续」即可，不必先打字**。**反证一**：清空那个框 → 按钮**点不动**（空名称在「登录设备」里是一行没有东西可以认的记录）。**反证二**：在一台读不到名字的机器上 → 退回"空框 + 按钮点不动"，**不是**拿一个内部主机名顶上——`lijinzhaodeMBP.lan` 这种字不该出现在「登录设备」里 |
| 15 | **结果页会自己关掉，关不掉时说的是实话**（对应 §范围 做 #13） | 走完一次 `skillmaster login`、停在结果页上 → 那行字是**会走的倒计时**（3 → 2 → 1），**不是**一句静止的「这个页面将在 3 秒后自动关闭。」（**第一版就是写死的，而当时那条只问"这句话在不在"的断言照样通过**——一个不动的倒计时和一张已经卡住的页面在屏幕上长得一样）。三秒之后**两种情况都算通过**：真关掉了，或者那句话**当场变成**「这个页面没有自动关闭，请手动关闭它。」。**失败的是第三种**：承诺还在原地 |

**成立条件：#2 与 #3 合起来。** 它们就是 [`v3-sessions`](../v3-sessions/prd.md) §不做 #1 那句原话落地后的两半——**出现在列表里**、**不自动续期**。少了前一条，人没有收尾手段（撤不掉的东西等于没换）；少了后一条，这一版只是把一种长命的凭据换成了另一种长命的凭据。**两条都不满足就不算交付。**

### 指标

| 指标 | 定义 | 怎么量 | 目标 |
|---|---|---|---|
| 重新登录频率（CLI 这条路） | 同一个账号、相邻两次 `login` 之间的间隔，**只统计一周内登录过两次以上的账号**（口径与前作一致，见 [`v3-sessions`](../v3-sessions/prd.md) §指标） | 登录事件的时间差中位数 | **这是一条有形状的分布，不追一个数**：天天用 CLI 的机器约 **7 天**一次（绝对上限主导）；**两天以上才用一次的机器，每次都要重新点**（24 小时闲置主导）。**「每天一次」在天天用的机器上出现就是错的**——那说明闲置窗口定短了 |
| 这份凭据被主动结束的比例 | 这条路发出去的凭据中**被主动结束过的**占比 ÷ 同一条路发出的总数 | 审计事件计数（结束一份凭据记一条，照 `audit_event` 既有形状） | **先观察，不设目标**。它是这一版存在理由的度量：**撤得掉，才会有人撤**。长期为 0 而这条路使用量不小，那说明人不需要它——那是要回头看的信号，不是失败 |
