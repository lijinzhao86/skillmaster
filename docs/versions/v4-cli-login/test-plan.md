## 用例

### T1 · 点一下，然后它真的能用

- **前置**：干净环境（本机没有凭据、没有 `SKILLMASTER_API_KEY`），服务端与网页都在跑，且这批 fixture 里有一个能登录的账号。
- **步骤**：`skillmaster login`（不带参数）→ 浏览器打开**「授权请求」**那一屏 → 名称框里**已经预填着这台机器在人系统里的名字**（权限来自地址，**没有可勾选的东西**）→ 直接点「**同意并继续**」→ 回到终端。
- **期望**：终端说已登录，并印出**这份凭据的名字 / 权限 / 到期时间**；`skill list` 通。**全程没有出现过"复制一串字符"这一步，也不必先打字。** **名称空着时按钮是点不动的**（设计件与产品同一处：空 → `disabled`），这一条也在这一步里判——清空那个框再点。
- **判定**：通过／失败

### T2 · 它出现在「登录设备」那一屏上，而不是「API 密钥」上

- **前置**：T1 刚跑完。
- **步骤**：在浏览器里打开控制台的**「登录设备」**那一屏，刷新；再打开「API 密钥」那一屏，刷新。
- **期望**：「登录设备」里**多出一行**：第二段是 `CLI · <T1 里填的那个名字>`，写着**登录于**与**最近活动**，**没有"从 CLI 来的"标记**（这一屏的规矩是活跃的行什么都不显示）；它与浏览器那次登录**并排、同一种行、同一个计数句**。**「API 密钥」那一屏一个字节不动**——不多一行、不少一行、没有新标记；`api_key` 表**没有新行**。
- **判定**：通过／失败

### T3 · 退出它，下一个请求即被拒

- **前置**：T1 刚跑完。
- **步骤**：在「登录设备」那一屏退出 T2 那一行 → 回到终端跑 `skill list`。
- **期望**：**401**（不是 403、也不是等到过期），终端说的是「**已被结束**…重新点一下」（不是「过期」——两句指向不同的下一步）。退出之后**那一行消失、计数跟着变**，这一屏**不另写一句"已结束"**——结果是**状态本身**说的（[`v3-sessions`](../v3-sessions/technical-design.md) §接口的原话：「**行没了**…这三件事就是结果」；设计件与它的断言都按这个来）。
- **判定**：通过／失败

### T4 · 它不会自己续命（成立条件）

- **前置**：T1 刚跑完；能直接改库里那一行（测试脚手架可以写这些表，见 §环境与数据）。
- **步骤**：把 T1 那份凭据推到**绝对上限之外**——`created_at` 与 `expires_at` 一起改到 8 天前（**只改 `expires_at` 已经不是这个状态**：滑动之后 `expires_at` 永远等于 `min(最后一次使用 + 闲置, created_at + 绝对)`，见 [TD](technical-design.md) §数据模型「两种到点要靠封顶分辨」）→ 跑 `skill list` → **再跑一次** `skill list`。
- **期望**：第一次说「**已过期**」并指向**重新点一下**（**不许指向续期**——登录态没有续期这条路，见 T5 与 T20）；**第二次还是这句话**——它**不会自己换回一个能用的**。重跑一次 `skillmaster login` 之后才恢复。
- **反证**：同一手法用在**今天**那条路上（OAuth 令牌：把库里那条授权撤销、把 access 的到期时间改到过去）→ 它**不会**报过期，它会**自己刷新回来**。**这两条行为必须不同**，否则这一版等于什么都没改。
- **判定**：通过／失败

### T5 · 它没有"续期"这个动作

- **前置**：T1 刚跑完。
- **步骤**：在「登录设备」那一屏上找延长它的操作；找不到就再跑一次 `skillmaster login`，然后回终端跑 `skill list` 与 `auth status`。
- **期望**：**这一屏上没有续期**（只有退出，与浏览器那次登录同一套动作）——登录态不续，到点就得重新点一下。再跑一次 `login` **不是**把它延长：它换来的是**另一份**，旧的那一份**当场被结束**（[Q7](technical-design.md)），所以终端能用，靠的是新的那一份。
- **判定**：通过／失败

### T6 · 它落在令牌那一族，不进 `api_key`

- **前置**：T1 刚跑完。
- **步骤**：直接查库——`api_key` 表，以及 [`technical-design.md`](technical-design.md) §数据模型 指的那一族（`access_token`）。
- **期望**：`api_key` 表**一行都没多**。这条凭据落在 `access_token` 一族里，**与那一族共表**，两条尺子全由 **`expires_at`**（滑动、封顶在 `created_at + 7d`）表达——**没有新表、没有新列**（见 TD §数据模型：这么定是因为那一族**本来就没有** `last_used_at`，而加一列要动的是别人也在用的表）。**别在这一条里写 `last_used_at`**：那一列在这张表上不存在。
- **判定**：通过／失败

### T7 · 整串只出现过一次，而且不留副本

- **前置**：T1 刚跑完。
- **步骤**：找遍它能出现的地方——服务端的响应日志、`cli_sign_in_code` 表、`audit_event` 表、本机那份凭据文件。
- **期望**：**服务端一处都没有整串**（库里是哈希，审计记的是"登录了一次"——谁、什么时候、哪个名字，**不是那串是什么**）。本机那一份是**唯一**的副本，权限 `0600`，且**没有刷新令牌**与它存在一起。
- **判定**：通过／失败

### T8 · 两条尺子都可以配，而且配错起不来

- **前置**：服务端可重启，配置可改。
- **步骤**：（a）把闲置窗口调到 1 小时、重启 → 让这份**登录凭据**被用过一次，然后隔 65 分钟再跑一条命令；（b）把绝对上限调到 1 天、重启 → 用一份签发超过 1 天的；（c）**把绝对配得与闲置相等**（例如两个都 24 小时）→ 启动。
- **期望**：（a）说清是**闲置太久**（**不是**「已过期」——两句指的下一步不同，见 prd 验收 #5(a)）；（b）说「**已过期**」；（c）**启动失败**，而不是静默禁用其中一条尺子——判定方式与 [`v3-sessions`](../v3-sessions/prd.md) §验收 #9 逐字相同（`SessionPolicy` 是那件事的先例，这里是同一个形状）。**另判**：(a) 与 (b) 必须是**两句不同的话**——滑动之后那两种到点在库里长得一样，分辨靠的是封顶（[TD](technical-design.md) §数据模型）。
- **（c）的输入为什么是"相等"而不是"更短"**（2026-10-16 校正）：`skillmaster.properties.sessions` **就是 M1 的 `SessionPolicy`**，它在属性绑定时就已经拒了"绝对短于闲置"——所以照原稿写（闲置 7 天、绝对 1 天），启动失败会带着 **M1 的那一句**先发生，`CliSignInPolicy` 的构造器根本走不到，**用例会变绿而不验它点名的那条规则**。能分开两条规则的输入正是**相等**：`SessionPolicy` 允许，而这一版拒绝——相等会让滑动第一次就把到期时间顶到封顶，闲置那条尺子从此不再决定任何事。原文那一对仍由 `SessionPolicyStartupIT` 原样覆盖着，但那是 M1 的事实。
- **判定**：通过／失败

### T9 · `login --with-key` 不再存在

- **步骤**：在 CLI 里搜这个形状。
- **期望**：**用户可见的文本**（帮助输出、README、错误消息）**零命中**。**参数名本身会留在断言它被拒的那条测试里**——那正是要的答案（判定方式与 [`v3-sessions`](../v3-sessions/prd.md) §验收 #10 逐字相同）。另：`skillmaster login --with-key` 的失败语是**未知的选项**，不是"从标准输入读一把 key"。
- **起步不是一个零**：今天是 **32 行 / 5 个文件**（`cmd/skillmaster/main.go` 28、`README.md` 1，另三处各 1——口径与全表见 [`technical-design.md`](technical-design.md) 附录 C），所以这一条的判定是"**清到零**"，不是"本来就干净"。
- **判定**：通过／失败

### T10 · 无浏览器机器上的失败语只指一条路

- **前置**：`PATH` 里既没有 `open` 也没有 `xdg-open`（容器那个形状），`DISPLAY`/`WAYLAND_DISPLAY` 也没设。
- **步骤**：`skillmaster login`。
- **期望**：**在打印任何链接与开始监听之前**就失败，并**只指向 `SKILLMASTER_API_KEY`**——**不指向任何已删除的形状**。（这一条是 [`v3-sessions`](../v3-sessions/test-plan.md) T17 的同一个错：删除之后还把人指向一条不存在的命令，比不提示更糟。）
- **判定**：通过／失败

### T11 · 重复 `login` 不攒行

- **前置**：T1 刚跑完。
- **步骤**：在同一台机器上**再跑一次** `skillmaster login`，走完点一下。
- **期望**：本机那份被**替换**（`auth status` 指向新的名字 / 到期时间），而**上一份在控制台被结束**——「登录设备」里它标着已结束（或按 [Q7](technical-design.md) 定下的形态处理），**不是**多出一行活的。**活着的行数不增**。
- **注意**：结束发生在**浏览器那一下**（[Q7](technical-design.md)：替换并结束上一份），所以这一条的判定要看**服务端那一次请求有没有把上一份一起结束**，而不是看 CLI 有没有调结束。
- **判定**：通过／失败

### T12 · 过渡期残留得到一句实话 —— **而残留有两种，两句话不一样**

对应 [`prd.md`](prd.md) §验收 #7(b)(c)。**这一条校正于 2026-10-16**：原先它只写了一种残留，而那种的形状取自**另一种**（见下）。

- **前置**：各造一份。（i）**旧的浏览器登录**留下的 OAuth 令牌（**有**刷新令牌）；（ii）v3 删掉的那条无人值守路留下的（**没有**刷新令牌）。
- **步骤**：（i）跑一条需要凭据的命令，然后**再跑一次 `skillmaster login`**；（ii）同样两步。
- **期望**：
  - **(i)** 那句话**说清它是什么、为什么不再能用、下一步做什么**（重跑一次 `login`），而**这一次登录顺手把它结束掉**——它有刷新令牌，`auth.RevokeAuthorization` 撤得掉。**反证**：把这句话写成"撤不掉"，这一条当场失败。
  - **(ii)** 那句话**说清它是什么、为什么从这台机器撤不掉、以及它会自己过期**——**不许说"上一份已撤销"**，那是一句不成立的话（它的认证是一个已经不在的 client secret，发撤销请求只会被拒）。今天代码里已经写着这句话。
- **两种都要说清，因为它们都在野**（TD Q8 的两种残留表）：把两种当成一种，就会对其中一种说假话。
- **判定**：通过／失败

### T16 · key 的 scope 不够时，说的是"换一把"

- **前置**：一把**只勾了 `skills:read`** 的 key，放进 `SKILLMASTER_API_KEY`。
- **步骤**：跑 `skill submit`。
- **期望**：**403**，终端说清**是这把 key 缺 `skills:write`**——服务端的 `WWW-Authenticate` 已经点名了缺的那个，CLI 照着说——并指向"到控制台签一把带它的，或换环境变量里的那一把"。**不提登录**。
- **反证**：把那一段改回今天那句**泛泛的 403**，这条用例当场失败。
- **判定**：通过／失败

### T17 · 账号没这个权限时，说的是"你没有这个权限"

- **前置**：一个能登录的账号 A，以及另一个账号 B 的 skill；A **没有被共享为编辑**。
- **步骤**：（a）用登录态；（b）用一把带着 `skills:write` 的 key——两条各跑一次 `skill submit --to B/那个 skill`。
- **期望**：两次都是 **403**，终端说**你对这个 skill 没有这个权限**；**不提重新授权**（服务端故意不给 challenge，带了它会死循环）。**两条说同一句话**——因为这件事与手里是哪种凭据无关。
- **判定**：通过／失败

### T18 · 没有凭据时，命令自己把登录引起来

- **前置**：干净环境（没有凭据、没有环境变量），并且**有浏览器**。
- **步骤**：直接跑 `skill list`（**先不跑 `login`**）。
- **期望**：浏览器自己打开那一屏 → 点一下 → **原来那条 `skill list` 自己跑完并给出结果**（不是"登录好了，请你再敲一次"）。
- **边界（同一条用例里一起判）**：`PATH` 里既没有 `open` 也没有 `xdg-open`、且没有 `DISPLAY`／`WAYLAND_DISPLAY` 的环境里，**不弹**，失败并指向环境变量（既有的 `BrowserAvailable` 判这件事）。
- **判定**：通过／失败

### T19 · 查询命令答的是"当前这份凭据能做什么"

- **前置**：同一台机器上能切换两种凭据——一把**只读的 key**（放进环境变量）与**登录态**（本机那份）。
- **步骤**：（a）跑"查当前凭据"的那条 → 它印出来源、**是 key 还是登录态**、服务端认它是谁、它能做什么；（b）**先用只读的 key、再用登录态**，对**同一个我读得到的地址**各跑一次"查这份凭据对某个 skill 能做什么"；（c）对一个**我读不到**的地址再跑一次。
- **期望**：（a）四项都说清；（b）**两次答案必须不同**——只读的 key 答"能读、不能写"，登录态答"能读、能写"。**这一条就是判定它答对了没有**：两次一样，说明它答的是"账号能做什么"，而不是"当前凭据能做什么"；（c）读不到的那个答案与"真不存在"**同一个**——不泄露存在性。
- **注意**：命令名与入参留到设计之后定；**但它要答的那句话已经定了**（[Q9](technical-design.md)）。
- **判定**：通过／失败

### T20 · 凭据死了的四句话，各不相同

- **前置**：一份能用的凭据。
- **步骤**：分别造出四种——**把最后活动推到闲置窗口之外**（T8(a) 那手法）、**把签发时间推到绝对上限之外**（T4 那手法）、把它结束掉、把账号停用——各跑一次命令。
- **期望**：四句**互不相同**，且**账号停用那一句不栽给这份凭据**。**前两句尤其要不同**——那正是验收 #5(a) 量的那件事（闲置 → **重新点一下**；已到期 → 重新点一下，**或者去签一把 key**）。**另判**：被结束 → 重新点一下；停用 → 那是账号的问题，不是这份凭据的。**登录态没有"续期"这条路**，所以那两句都**不许**指向续期（与 T16 的 key 那一句不同——那一种确实能换个凭据解决）。
- **这条今天会以"几句一样"失败，而那正是它要量的东西**：服务端**只有 key 那条路**产生具名拒绝，`access_token` 那条路的拒绝收敛成一个（TD §接口「这条凭据今天的拒绝只有一种」）。所以这一条**先要 做 #11 那段服务端改动**才可能通过。
- **判定**：通过／失败

### T21 · 删除只在浏览器里发生，凭据删不了

对应 [`prd.md`](prd.md) §验收 #12 与 §范围 做 #10。

- **前置**：一个能登录的账号 A，A 名下有一个自己的 skill；另外准备**一把勾了 `skills:write` 的 key** 与**一份登录态**。
- **步骤**：（a）分别用那把 key 和那份登录态，对 `DELETE /api/v1/skills/A/<那个 skill>` 各发一次；（b）打开「授权请求」那一屏（`?client_id=skillmaster-cli&state=…&scope=skills:read%20skills:write`），读权限清单。
- **期望**：（a）**两边都拿不到 204**——那条路由已不在（对应它们的是"没有这条路由"的答案，不是 403：区别在于**这条能力对凭据根本不存在**，不是"你的凭据不够"）；（b）权限清单里**不含「删除」**——这一屏不再另说一句"它不能删"（那一行 2026-10-16 删掉了），所以**清单里没有就是全部**。
- **本版不判、也不该判的那一半**：控制台的删除入口与它的二次确认**不在本版**（[`prd.md`](prd.md) §不做 #8、[ADR 0046](../../decisions/0046-deleting-a-skill-happens-in-the-browser.md)），所以它在哪个界面、确认时说什么，等那个模块的测试方案。**本版要接受的代价**在这一条里一并记着：撤掉路由之后、入口画出来之前，**删除无处可做**。
- **判定**：通过／失败
- **范围外的一句**：删除在数据层是**软删**——`version_file` 与对象存储里的字节都留着（回收的引用集是 `SELECT DISTINCT blob_sha256 FROM version_file`，**不看 `deleted_at`**），所以"没有恢复入口"是**产品**的结论，不是"数据没了"。这一条**不要求**本版做恢复。

### T22 · 回环页那两句标题跟上了这一屏的名字

对应 [`prd.md`](prd.md) §验收 #13 与 §范围 做 #12。

- **前置**：能在浏览器里走完一次 `skillmaster login`。
- **步骤**：（a）点「同意并继续」；（b）重来一次，点「拒绝」。
- **期望**：两页的标题分别是「**授权成功**」/「**授权未完成**」。**两处都要判**：CLI 那两个字符串（`internal/auth/callback.go`）与设计件里照抄它们的那一屏（`#consentDoneView`）。**这一族词 2026-10-16 当天改过两次**（授权 → 登录 → 授权），所以这条要按**最终**那一边判——顺带看第四处：产品里 `/consent` 那一屏的标题也该是「授权请求」。
- **判定**：通过／失败

### T23 · 结果页自己收场，而关不掉时说的是实话

对应 [`prd.md`](prd.md) §验收 #15 与 §范围 做 #13。

- **前置**：能在浏览器里走完一次 `skillmaster login`。
- **步骤**：（a）点「同意并继续」或「拒绝」，**停在结果页上不要动**；（b）盯着那行字**看满三秒**。
- **期望**：（a）那行字是**会走的**——3 → 2 → 1，**不是**一句静止的「这个页面将在 3 秒后自动关闭。」；（b）三秒之后，页面**要么没了**，**要么**那行字换成了「这个页面没有自动关闭，请手动关闭它。」。**失败的是第三种：承诺还留在原地。** 两处都要判：CLI 那一页（`internal/auth/callback.go`）与设计件里照抄它行为的那一态（`#consentDoneView` 的 `#consentDoneClose`）。
- **为什么它不能靠"看有没有那句话"过**：**第一版正是写死的，而当时那条只问"这句话在不在"的断言照样通过**——一个不动的倒计时和一张已经卡住的页面，在屏幕上长得一模一样。所以判定必须包含"数字动过没有"。
- **判定**：通过／失败

### T13 · 码是一次性的、短命的，而且不泄露存在性
- **步骤**：（a）同一个码兑换**两次**；（b）用**过期的**码兑换；（c）用**错的** `code_verifier` 兑换；（d）用一个**从不存在的**码兑换。
- **期望**：（a）（b）（c）（d）**四个得到同一个答案** `code_not_found`。区分它们听起来更有用，但它同时告诉了一个拿着随机码的人"这个码存在过"——与 `/web/keys` 对"不是你的 key"的处理一致。
- **另判**：`cli_sign_in_code` 表里存的是哈希，**不是**码的原文；兑换成功那一次的响应之外，**任何地方都没有整串**。
- **判定**：通过／失败

### T14 · 兑换那条路自带限流

- **前置**：能对 `/cli-sign-ins/exchange` 连打。
- **步骤**：从一个来源连续提交大量随机码。
- **期望**：被限流，且**限流本身不区分"码存在"与"码不存在"**（否则限流就成了存在性探针）。
- **判定**：通过／失败

### T15 · 会话面的两条边

- **步骤**：（a）**没登录**时直接打开那一屏的地址 → 先走登录，**回到这一屏**（参数活过登录）；（b）用 **A 的会话**铸出的凭据属于 A——`auth status` 报的账号是 A，B 的「登录设备」里看不到它；（c）`POST /web/cli-sign-ins` 缺 CSRF → **403**。
- **期望**：三条都成立。
- **判定**：通过／失败
