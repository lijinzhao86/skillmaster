## 架构

这一版**不引入新组件类型**：把 CLI 那条登录路的目的地与产出换掉，其余全是既有机器。

```
   ┌──────────────── 浏览器（人在，登录着） ────────────────┐
   │  「登录请求」那一屏：必填的名称 / 权限（来自地址）      │
   └───────────────────────┬────────────────────────────────┘
                           │ ① POST /web/cli-sign-ins（会话 + CSRF）
                           │    铸一个短期凭证 + 发一个一次性码
                           ▼
              302 → http://127.0.0.1:<固定端口>/callback?code=…&state=…
                           │
   ┌───────────────────────▼────────────────────────────────┐
   │  CLI 的回环监听（既有：internal/auth/callback.go）       │
   └───────────────────────┬────────────────────────────────┘
                           │ ② POST /cli-sign-ins/exchange
                           │    码 + code_verifier → 凭证本身
                           ▼
              存本机（既有：internal/credentials，钥匙串优先）
```

**三个边界各自为什么这么放**：

- **铸那一下在会话面**。这是 [ADR 0040](../../decisions/0040-api-key-in-the-cli-now-the-browser-path-later.md) §决定 1 在接口上的样子：能造凭据的东西必须是**会话**。一次性码只是把**已经铸好的那一个凭证**递给 CLI 的运载工具——**不是**"有码就能造凭据"。
- **递回来的绝不能被直接读走**。码走 URL，而 URL 会进浏览器历史、Referer 与服务端日志；所以 URL 里是**码**不是凭证，码短命、一次性、兑换时还要 CLI 出示 PKCE 的证明。这是 [ADR 0028](../../decisions/0028-cli-uses-a-fixed-loopback-port.md) 那个固定端口当初留的用法。
- **兑换那条路不带会话**（CLI 没有会话），所以它**不在 `/web/**` 链上**，也不在 `/api/v1/**`（那条要求 Bearer 权限）。它是新的一条**公开面**——因此**必须自带限流**，见 §接口。

**数据流（文字）**：CLI 生成 verifier/challenge → **先监听**再开浏览器（顺序与今天一致，见 `auth.Login` 的注释：回调比监听先到就永远丢了）→ 人在页面上点一下 → 服务端铸凭证 + 发码 → 浏览器 302 回本机 → CLI 拿码 + verifier 换凭证本身 → 存。

## 数据模型

**`api_key` 那一族一个字节不动。** 这一版不往它上面加列、不往里写行——短期凭证**不是** key（见 [`prd.md`](prd.md) §不做 #1）。

**短期凭证住在令牌那一族**：`oauth_authorization`（**一次同意**：谁、哪个 client、哪些 scope、框架自己的属性袋）＋ 它下面挂着的令牌行（`access_token` / `refresh_token`，两张表都**只存 sha256**）。

**两条尺子怎么表达——不加列**：

| 尺子 | 怎么落 |
|---|---|
| **绝对 7 天** | 上限 = `created_at + 7d`（`created_at` 已有；7 天是配置） |
| **闲置 24 小时** | **滑动 `expires_at`**：每次使用时把它推到 `now + 24h`，**并封顶在 `created_at + 7d`** |

- **`access_token` 没有 `last_used_at` 这一列**（V1 建的是 `token_hash / client_id / user_id / scope / audience / expires_at / revoked_at / created_at`，V5 又加了 `authorization_id`），所以闲置那条**不用再加一列**——滑动 `expires_at` 就是它的表达，而 `expires_at` **本来就有索引**（`idx_at_expiry`）。**注意别把索引说成"清扫"**：今天**没有任何按时间清扫 `access_token` 的任务**（全库没有 `@Scheduled`；这张表上唯一的 DELETE 是按 `authorization_id` 走的，按时间过期的只有 `captcha`）。所以这一列的既有读者**只是索引与校验查询**。
- **滑动必须采样**，照 **`IssuedTokenValidator` 里那条 `noteUse`** 的形状（只在记录值比一个窗口更老时才重写；它不叫 `ApiKeyRegistry.noteUse`——那个类里没有这个方法）——请求路径今天是"近乎只读"的，**这一点不能丢**。**口径**：滑动最多滞后一个窗口，所以闲置这条尺子的判定**最多早一个窗口**；那个窗口必须远小于闲置窗口，**启动时校验这一对**（照 `SessionPolicy` / `TokenPolicy` 的先例）。
- **不发 refresh token**（[`prd.md`](prd.md) §做 #2）：所以那个凭证的寿命就是它自己的，没有第二条命。**这也是"绝对"那条尺子能被上面这个封顶表达出来的前提**——没有刷新链，就不需要另一处记上限。
- **它怎么被铸出来是 §开放问题 Q5**：改授权服务器给这条路发的令牌的寿命，还是我们自己铸一行。**两条路落到库里都是同一张表的同一行**，区别在**谁写的**。
- **`TokenPolicy` 的启动校验**要加一条：绝对不得短于闲置（照 [`v3-sessions`](../v3-sessions/technical-design.md) 那条 `SessionPolicy` 的形状）。

**新增一张一次性码表**（**一次性**这件事本身就需要状态）：

```sql
CREATE TABLE cli_sign_in_code (
  code_hash      TEXT PRIMARY KEY,   -- sha256，照三张令牌表与 api_key 的既有做法
  authorization_id TEXT NOT NULL,    -- 已经铸好的那一次授权；兑换只是把凭证交出去
  code_challenge TEXT NOT NULL,      -- PKCE，兑换时比对 verifier
  expires_at     TEXT NOT NULL,
  used_at        TEXT,               -- 非空即已用；重复兑换按"没这张码"处理
  created_at     TEXT NOT NULL
);
```

- **只存哈希**：与三张令牌表同一条规矩——库被看走不等于凭据被看走。
- **`authorization_id` 不加外键**：一张**一次性的、几分钟就死**的码，不该因为授权行被删而连带消失——**码失效应由它自己的 `expires_at` 说了算**，而不是由另一张表的生命周期说了算。**代价如实记**：会留下指向已结束授权的码行，靠 `expires_at` 过期（今天也没有清扫任务读它，同上）。
  （**别拿 `access_token.client_id` 当先例**：那条注释说的是另一件事——"a token outlives a client row being re-registered"，令牌比客户端行活得久；而且 `access_token.authorization_id` **今天是有外键的**（`V6`），拿这张表举例"不加外键"正好说反。）
- **不建索引**：按主键查；行数是"几分钟内点过几下"的量级。
- **表归 M2（token）**，与 `oauth_authorization`、`access_token` 同属一处——**照 `ModuleMap` 现在的分法**（`new Module("M2", "token", …, Set.of("oauth_client", "oauth_authorization", "auth_code", "access_token", "refresh_token", "oauth_authorization_consent", "api_key"))`）；**`ModuleMap` 要加一行**，否则 `TableOwnershipTest` 会红（它要求迁移里的表与 `ModuleMap` 的表集合**完全相等**）。

## 接口

| 方法 | 路径 | 作用 | 鉴权 |
|---|---|---|---|
| `GET` | `/cli-sign-in`（网页路由） | 那一屏：**必填的「名称」/ 权限（来自地址、不可勾选）** + 「**同意并继续**」（寿命是两条定死的尺子，这一屏只**说清**它） | 会话。没登录时先走登录，**回到这一屏**（参数要活过登录） |
| `POST` | `/web/cli-sign-ins` | 铸一个短期凭证 + 发一个一次性码；返回 `{redirect_to}` | **会话 + CSRF**（与 `/web/keys` 同一套） |
| `POST` | `/cli-sign-ins/exchange` | 码 + `code_verifier` → **凭证本身**（只此一次） | **无**（凭码 + PKCE）；**必须有独立限流** |
| `POST` | `/web/cli-sign-ins/{id}/revoke` | **结束一份登录**（「登录设备」那一屏上那一行的动作） | **会话 + CSRF**（与 `/web/sessions/{id}/revoke` 同一套） |

**错误形状**：码的问题（不存在 / 过期 / 已用过 / verifier 不匹配）**一律同一个答案** `code_not_found`——与 `/web/keys` 对"不是你的 key"的处理一致：不泄露存在性。"你这个码用过一次了"听起来更有用，但它同时告诉了一个拿着随机码的人"这个码存在过"。

**出参的形状**：凭证本身**只在这一条响应里出现一次**（不落库、不进日志、不进审计——审计记的是"签了一份"，不是那份是什么）。

**结束一份登录是**新增的一条路由**（2026-10-16 校正——这一格原先写着"走已有的那条路，不新造接口"，那是错的：**今天没有任何接口能单独结束一条授权**。`TokenRevocation` 只暴露 `revokeAllFor(userId)`（全撤，它的注释自己写着那个 per-thing 接口是 deferred），而 `/web/sessions/{id}/revoke` 结束的是**浏览器会话**（`spring_session`），不是令牌。它与 `/web/keys/{id}/revoke` 也不是同一个端点：那把结束的是 key，这条结束的是**一次授权**——这正是本版不合并两种凭证的直接后果。**它必须进 P1 的交付**，否则验收 #2 的"单独结束其中一份"无处可做。

### 这条凭据今天的拒绝只有一种（对应 [`prd.md`](prd.md) §范围 做 #11）

`IssuedTokenValidator` 里**两条路是分开的**：key 那条（`validateApiKey`）产生三种**具名**拒绝（`TOKEN_EXPIRED` / `TOKEN_REVOKED` / `ACCOUNT_SUSPENDED`），而 `access_token` 那条（`validateIssuedToken`）的拒绝**全部收敛成一个**（那个类的注释写着 *this path's refusals are all the same one*），`BearerAuthenticationEntryPoint` 的文案也是**硬编码给 key 的**（"This API key has been revoked./expired."）。所以 验收 #11 的三句不同的话**对这条凭据今天给不出**——那是本版要改的一段服务端代码，不是既有能力。

### 本版撤掉的一条路由（对应 [`prd.md`](prd.md) §范围 做 #10）

| 方法 | 路径 | 处置 |
|---|---|---|
| `DELETE` | `/api/v1/skills/{namespace}/{name}`（`SkillsController`，实现是 `SoftDeleteSkillUseCase`） | **撤掉**。它今天只由 `skills:write` + owner 把关，也就是**任何凭据**都能删——包括 `skillmaster login` 换来那一份。删除改为**只在浏览器面**发生，而**控制台那处入口不在本版**（属于 skill 管理模块，见 [`prd.md`](prd.md) §不做 #8）——所以在本版与那处入口之间，**删除无处可做** |

**为什么撤而不是加一道闸**：「这个动作只有一个主体能做（人），而且他要在浏览器里做、还要再确认一次」——这是产品对**上线**已经定下的规矩（[ADR 0031](../../decisions/0031-submitting-and-publishing-are-two-actions.md) §决定 2 让 API 平面**没有** publish 路由）。给删除再加一个 scope 会留下第二种答案（"换个凭据就能删"），而这一条要的答案是**唯一**的：凭据删不了。**代价如实记**：无人值守的删除**从此不存在**（今天也只有凭据能删），要删就得人在浏览器里点；如果将来真有自动化删除的需求，那要另开一条 ADR，而不是把它塞回这个 scope 里。

> 这一条**要一条 ADR**：它改的是 [`v2-credentials`](../v2-credentials/prd.md) **已经交付**的能力（拿一把 key 删 skill），属于跨版本的取舍。

### 一次操作的结果落在谁身上

[`prd.md`](prd.md) §一次操作有哪几种结果 是**需求**的权威；这里写**它落在哪些既有的处理器上**——**本版新增的机制是两处**（最后两行，2026-10-16 校正：原先写的是"只有一处"）。

| 情形 | 谁产生的 | 为什么是它 |
|---|---|---|
| key 的 scope 不够 | **既有** `InsufficientScopeAccessDeniedHandler`：403 + `WWW-Authenticate`，**点名缺的那个 scope** | 它是**唯一**一条"换一个凭据能解决"的 403 |
| 账号对这个资源没有权限 | **既有** `NotPermittedException` → `ApiExceptionHandler`：403，**故意不带** challenge | 注释原话：带了它客户端会「re-authorize, get the same 403」——**死循环** |
| 读不到某个 skill | **既有**：渲染成 **404**，不是 403 | 不泄露存在性；判定在 M4 的用例里，不在安全层 |
| 凭据死了 | **半既有**：`BearerAuthenticationEntryPoint` 的 401 **有**，但那三种具名原因码**只由 key 那条路产生**——`access_token` 这条路的拒绝全收敛成一个（见上面「这条凭据今天的拒绝只有一种」） | 三句各不相同，下一步也不同。**这条凭据要分三种是本版的新工作** |
| 没有凭据 / env 里不是 key | **既有**，且**在 CLI 本地**：`ErrNotSignedIn` / `environmentKeyProblem`——**连接都不发** | 这两件事不需要问服务端 |
| **权限不够时说的话** | **本版要改的一处** | CLI 今天把 403 **合成一句泛泛的话**（`internal/api/client.go`：`403, which stays generic on purpose`）。**那条理由是为登录态写的**（重新授权还是同样的 scope）——**对 key 不成立**：key 的 scope 是签的时候选的，换一把就有。所以第 2 种要**按服务端给的理由分开说** |
| **这条凭据的三种死法** | **本版新增的第二处**（做 #11） | 上表第四行：具名拒绝今天只给 key，这段要改 |

## 分期

| 期 | 交付 | 验收 |
|---|---|---|
| **P0** | 服务端：令牌那一族的两条尺子 + 一次性码表 + **三条接口**（发、兑、结束一份）+ **这条凭据的三种具名拒绝**（做 #11）+ 审计 + 启动校验；**撤掉 API 平面那条删除路由**（做 #10） | #2 的一半（库里那一行在、**服务端撤得掉**）、#3、#4（服务端那半）、#5、#11、#12 |
| **P1** | 网页：那一屏（**设计交付之后**）+ 它进的那一屏（[Q6](technical-design.md)）+ **「登录设备」上"结束一份"那个动作**（做 #4 的界面那半）+ 从这一屏起的登录回跳 | #1 的界面那一半、#2（含"行消失、计数跟着变"）、#4（界面那半） |
| **P2** | CLI：`login` 的目的地换成这一屏、换码取凭证、存；**删掉 `--with-key`**；三句提示语（#6、#7、#8）；**回环页那两句标题**（做 #12）；第一方那条刷新链退休 | #1、#3、#6、#7、#13 |

**每期明确不做**：P0 不做界面；P1 不碰「API 密钥」那一屏（本版对它一个字节不动）；P2 不做设备码、不做"凭据造凭据"、不动 `/oauth/*`。

**做 #10 只撤路由，不画控制台入口**（2026-10-16 定：入口属于 skill 管理模块，见 [`prd.md`](prd.md) §不做 #8）。**代价是明摆着的、也是接受了的一条**：在入口画出来之前，删除在整个产品里无处可做。反过来说，**先画入口、把路由留着**是那条被否掉的路——同意页那张清单就成了沉默的假话（它不再提「删除」，而凭据仍然删得了，见 [`design/README.md`](../../../design/README.md) §怎么打开「登录请求」与 [ADR 0046](../../decisions/0046-deleting-a-skill-happens-in-the-browser.md)）。

**P0 与 P1 的先后**：契约先成立，界面才有东西可点。**P2 必须在 P1 之后**——CLI 换实现那一刻，那一屏必须已经在线上，否则 `login` 会指向一个不存在的页面（这正是 [`v3-sessions`](../v3-sessions/test-plan.md) T17 给 `--client-credentials` 定的那种错）。

## 开放问题

### 已定（2026-10-16）

**Q1 · 这个凭证的寿命怎么给？** —— **两条尺子，与浏览器会话同一套**：**绝对 7 天**（从签发那一刻算）**＋ 闲置 24 小时**。
**代价如实记**：它让使用稀疏的机器变短——**两天以上才跑一次的机器，每次都要重新点一下**（闲置主导）；天天用的机器由绝对上限主导，约 **7 天**一次。这是这条尺子买到的那个性质的价钱，不是它的缺陷。

**第二条代价，与旧设计正面对照**：今天每条命令在网络上送的是那张 **1 小时的 access 令牌**（短的存在的理由就是"被截获也只值一小时"），而长命的那张 refresh 每 1 小时过一次网。新设计里**送出去的就是凭证本身**，所以：

| | 今天 | 这一版 |
|---|---|---|
| 每条命令在线上送的那个（最常见的截获物） | 值 **1 小时** | 值 **最多 7 天** |
| 线上能捞到的最值钱的那个 | refresh，值 **180 天** | 没有了——**最值钱的就是那 7 天** |
| 撤销它 | **没有入口**（只有重置密码能连带撤，而那会踢掉所有设备） | 控制台上单独结束 |

**两条都要放在一起看**：单次截获的价值上升了，但**天花板降了**（180 天 → 7 天），而**撤得掉**是今天完全没有的东西。这个交换是这一版的主题本身，不是它的副作用。

**Q2 · 它是不是就做成一把 API key？** —— **不是。两种凭证不合并**（[`prd.md`](prd.md) §不做 #1）。
一个是**登录态**（一次授权、会死、要重新点），一个是**长期凭证**（签发时定寿命、粘到各处、给无人值守用）。合起来之后，「API 密钥」那一屏上会同时住着这两样而两者都叫 key——**「key 是长期凭证」这句话就不成立了**，而它是 [`v2-credentials`](../v2-credentials/prd.md) 整版的前提。**本版对 `api_key` 那一族一个字节不动。**

**Q3 · 无浏览器机器怎么办？** —— **不变**：环境变量 + 一把 key（[`v2-credentials`](../v2-credentials/prd.md) §验收 #2 验过）。**不做**设备码流程。

**Q4 · `/oauth/*` 那套还在，谁在用？** —— **只留给第三方**（[ADR 0041](../../decisions/0041-third-parties-reach-us-through-the-cli.md)）。**不删**。

**Q5 · 「往库里写下那一行」由哪段代码执行？** —— **我们自己的代码**（不动框架的授权服务器）。

它问的**不是"谁决定签发"**——决定权永远在浏览器会话那一边，这一版不动。它问的是**哪段代码写 `access_token` 那一行**。

**为什么自己写**：这一版的主题是**第一方这条路与第三方那条路分开**（与"两种凭证不合并"是同一条思路）。让框架的授权服务器去发一个"第一方特例"，正好把两件事重新缠在一起；而改动落在**我们自己的代码**里，比落在**框架的扩展点**里好查。

**代价如实记**：「往 `access_token` 写一行」从此**有两个作者**（框架一份、我们一份）。接受它只是承认一件本来就成立的事——按 [ADR 0023](../../decisions/0023-spring-authorization-server-with-our-own-storage.md) 的分工，**那张表是我们的**。

**它与"一次性码"是两件事**：不管谁写那一行，投递仍然要走码——**凭证不能经过 URL**（浏览器历史，以及任何一层想记就能记的日志）。

**Q7 · 同一台机器重复 `login` 会攒出多份吗？** —— **不会：替换本机那一份，并结束上一份**。结束发生在**浏览器那一下**，由服务端在同一个动作里做（CLI 永不撤销凭据，[ADR 0040](../../decisions/0040-api-key-in-the-cli-now-the-browser-path-later.md) §决定 4）。这与今天 `revokeReplaced` 的行为一致（它撤的就是上一次的授权），也防止控制台上攒出多行。

**Q8 · 过渡期残留怎么办？—— 先说清"残留有两种"，它们的话不一样**（2026-10-16 校正；原先这一问只写了第一种，而 prd 与 T12 又按第二种的形状描述它，两边对不上）：

| | 是什么 | 撤得掉吗 | 该说什么 |
|---|---|---|---|
| **(i)** | **旧的浏览器登录**留下的 OAuth 令牌（**有**刷新令牌） | **撤得掉**——`auth.RevokeAuthorization` 拿刷新令牌就能结束那次授权 | 说清它是什么、为什么不再能用、下一步做什么，**并且结束它**。这是这一问原来说的那一种 |
| **(ii)** | v3 删掉的**无人值守路**留下的（**没有**刷新令牌，认证是一个已经不存在的 client secret） | **撤不掉**——发一次撤销请求只会被服务端拒 | 说清它是什么、**为什么从这台机器撤不掉**、以及**它会自己过期**。今天代码里已经写着这句话（`ErrNotRenewable`、`revokeReplaced` 的那条分支），而它明确**不许**说"上一份已撤销"——那是一句不成立的话 |

**两种都要说清，因为它们都在野**：(ii) 是 v3 那次清理留给在跑机器的，(i) 是本版要取代的今天这条路。**把它们当成一种，就会对其中一种说假话**——而这正是校正前 prd 做 #7 与 T12 的问题。
（(ii) 那条与 [`v3-sessions`](../v3-sessions/prd.md) §范围 #5 的"撤不掉的残留"是同一类东西：那一份只能自己失效，所以 v3 也只能"说清"。）

**Q9 · 「查我对某一个 skill 的权限」答什么？** —— **答"当前这份凭据，对这个 skill，能做什么"**，并且**说清是哪一份凭据在起作用**。

**权限不是一个静态的账号属性**：能做什么 = **这份凭据的 `scope` ∩ 账号此刻的权限**（[`v2-credentials`](../v2-credentials/prd.md) §范围 #4 那条规矩）。**公式对两种凭据是同一条**（2026-10-16 校正：原先这里写"登录态不带 scope、就是账号的权限"，那是错的——`access_token.scope` 是 `NOT NULL`，签发时写入、校验时读成权限）；差别在 **scope 的值**：key 的是签发时勾的，登录态的是 CLI 申请的那两个。所以**同一个账号换一份凭据，答案可以不同**——原因不是公式不同，是 scope 不同；而这条命令要答的正是**当前生效的那一份**。

它是那条既有规矩的一次**查询式暴露**，不是一张新的权限表。**读不到的地址与"真不存在"给同一个答案**（既有的 404 规矩）。**命令名与入参留到设计之后**，但它**答的是上面这一句**——这一点已经定了。

**Q6 · 它进哪一屏？** —— **并进 v3 的「登录设备」那一屏**（2026-10-16 定）。

**理由是两条尺子完全一样**——不是"相似"，是**同一个数**：

| | 闲置 | 绝对 |
|---|---|---|
| v3 的浏览器会话 | 24 小时 | 7 天 |
| 这一版的 CLI 凭证 | 24 小时 | 7 天 |

而那一屏的标题就是**「登录设备」**，它自己的分组理由写着「一个登录会话正是一种以你的名义做事的东西」（[`design/README.md`](../../../design/README.md) §登录设备）。**CLI 那一条是同一种东西**：一台机器以你的名义登录着，同样的两条尺子，同样的动作（退出 → 它要重新登录）。

**那一行的形状是"上下两行"**（2026-10-16 起；原先设计件是"一行竖着堆三段"，改的理由与量到的数见 [`design/README.md`](../../../design/README.md) §登录设备）：**上行是完整地址**，**下行是一句话**「什么设备　·　登录于 …　·　最近活动 …」。两行之间**只有第一段不同**——浏览器那一行是从 User-Agent **猜**出来的 `Chrome · macOS`，CLI 那一行是 **`CLI · ` ＋ 人自己填的那个名称**（而设计件有一条规矩：不画设备类型图标，因为"画错比不画更糟"，人填的名字没有这个问题）。**「最近活动」正是"闲置 24 小时"这条尺子存在的意义**。**「当前设备」那一条 CLI 没有**：你在浏览器里看这一屏，而那一行说的是另一台机器。

**代价如实记**：那一屏是 v3 刚交付、照设计稿做的，所以标题、计数句、空态句与**每一行的第二段**要一起改，v3 的实现（`AccountSessionsPage.vue`）跟着改。

### 仍未决

**没有。** 这一版没有悬着的取舍。
