# v4-cli-login · CLI 的登录凭据有界、看得见、撤得掉

> **最后更新**：2026-10-16
> **状态**：进行中（**四份文档已起草、开放问题已定、设计件已到齐；尚未实现**）。下一步是实现（P0 → P1 → P2，见 [`technical-design.md`](technical-design.md) §分期）。
> **含收费**：否

## 目标

**CLI 要一个凭证才能干活，而凭证有两种来源、两种形态**（2026-10-16 定）：

- **浏览器登录**（`skillmaster login`）→ 一份**短期登录凭据**：**绝对 7 天**、**闲置 24 小时失效**、**不自动续期**
- **控制台签发** → 一把 **API key**：**长期凭证**，本版**一个字节不动**

这一版做的是前者——也就是 [`v3-sessions`](../v3-sessions/prd.md) §不做 #1 那句原话（**不自动续期、寿命 1–7 天、出现在列表里**），并让它**看得见、撤得掉**。细节见 [`prd.md`](prd.md)。

**两种凭证不合并。** 一个是登录态，一个是长期凭证；混进同一张表、同一屏，会把「key 是长期凭证」这句话毁掉。

## 验收标准

一句话：**点一下就有一个凭证，而它控制台看得见、撤得掉、到点就死、不会自己续命——同时「API 密钥」那一屏一个字节不动；另外把一个 skill 删掉这件事从凭据手里收回**（[ADR 0046](../../decisions/0046-deleting-a-skill-happens-in-the-browser.md)，做 #10 / 验收 #12——那一版只关掉凭据那一侧的入口，控制台的删除入口属于 skill 管理模块，见 §不做 #8）。

完整验收见 [`prd.md`](prd.md) §验收与指标——**其中 #2 与 #3 合起来是成立条件**（为什么，见那一节）。

## 这一版明确不做什么

摘要三条最要紧的；**完整范围与每条的理由在 [`prd.md`](prd.md) §范围**。

- 不做 **把短期凭证做成 API key** —— 两种凭证**技术上不是一回事**（一个是登录态、一个是长期凭证）。混在一起，那一屏上就会同时住着「90 天的长期凭证」和「24 小时不用就死的登录态」，而两者都叫 key
- 不做 **撤掉 `/oauth/*`** —— 它是**第三方**要走的路（[ADR 0041](../../decisions/0041-third-parties-reach-us-through-the-cli.md)）。第一方**不再借它**（那是 [Q4](technical-design.md) 定下的：`/oauth/*` 只留给第三方、不删），第一方那条路走 `/cli-sign-in` 那一族新路由
- 不做 **无浏览器机器的设备码流程** —— 那里已经有**通的路**（环境变量 + 一把 key），往一个能用的地方加第二种做法买不到任何东西

## 与目标态的关系

[`target/`](../../target/README.md) 描述的是**完整形态**。这一版碰的是**登录凭据那一族**（它的形态、寿命、可撤销性），另外把**一条删除路由**从凭据手里收回（做 #10，[ADR 0046](../../decisions/0046-deleting-a-skill-happens-in-the-browser.md)）——**不碰身份与权限模型**。

- 保留的部分：凭据的**签发入口仍然只有会话**（[ADR 0040](../../decisions/0040-api-key-in-the-cli-now-the-browser-path-later.md) §决定 1）——本版改的是会话那一页**长什么样、产出什么**，不是这条规矩。
- 没有分叉的部分：本版不给会话加权限模型，也不引入角色/组织。目标态里那套组织与角色机制按 [`target/README.md`](../../target/README.md) 自己的说法**不是当前版本的实现依据**。
