# v14-skill-tags · 产品需求

> **最后更新**：2026-10-22
> **所属版本**：[`README.md`](README.md)
> **开工基线**：`main@2811293`（v13「收口 CLI 命令面」已合并；本版描述“现在”时，均指这个提交）

> **范围说明**：本需求原记为 `v13-skill-tags`，只做两套标签。恢复时发现**我的标签依赖一层今天没有的东西**：一个「我这边的 skill 目录」——今天 `skills list` 把公开 skill 和自己的、共享的混在一起，没有“加入”这个动作，我的标签就没有稳定的归属面。所以本版把**公域/私域、我的库、标签**一次做完；版本名沿用原需求的 `skill-tags`。

## 用户与场景

**谁在用**：五类，要分开说，因为验收对象不同。

- **整理自己目录的人**：名下有自己的 skill，也有别人共享的和从公域加进来的。他要按“客户项目”“这周要用”这类**只有自己懂**的分组来找东西，并且不希望这层分组被任何人看见。
- **公域里的读者/消费者**：想找一个公开 skill 来用。公域**不能整表列出**（公开 skill 会多到无法加载），只能先搜到、再决定要不要加入自己的库。
- **公开 skill 的作者/所有者**：希望别人能按领域找到自己的 skill；今天只有关键词，而关键词只在名字、标题、描述里做子串匹配。
- **管理员协作者**：帮别人维护一个 skill，需要调整它的公开分类，但不该看到或改动别人的标签或库。
- **agent（经 CLI）**：在会话开始或任务需要时拿一份有边界的目录；今天 `skills list` 是被公开 skill 淹没的“所有我能读的”，`skills search` 是字面子串。

**在什么场景下用**：

- 一个人有几十个 skill，想对 agent 说“这次只加载我库里的这一组”，而不是把整个公域塞进上下文：`skills list --my-tag 客户项目 --all`。
- 一个读者在公域搜“做 PPT”，找到「文档与演示」分类下的一个公开 skill，**加入我的 skill**，然后它出现在自己的库里；以后可以直接 `skills list` 看到它，也可以给它贴「我的标签」。
- 作者发布一个公开 skill，希望它出现在「文档与演示」这个公开分类下；读者按这个分类能找到它。
- 两个同事都在一个公开 skill 上贴了自己的标签：一个写“待评估”，一个写“设计组”；彼此看不到，也不影响公域检索。
- agent 在本库里找不到，再 `skills search` 去公域找；找到的那一个不需要加入也能直接 `skill invoke`。

**本版开工前（`main@2811293`）的替代做法是什么**：

- **目录**：`skills list` 的谓词是「自己的 ∨ 被授权 ∨ 公开」（`SkillCatalogRepository.java:108-111`），所以**公开、有当前版本、未下线、未删除**的 skill 会混进列表；没有“加入”这个动作，也没有“我的库”这一层。
- **公域**：公开 skill 只能靠关键词碰运气；`GET /api/v1/skills?q=` 对 name / title / description 做 `ILIKE` 整串子串匹配，不拆词，也不看 `when_to_use`。
- **控制台**：列表是**作者面**——自己的 + `write` 及以上共享的；公开 skill 与 `browse` / `invoke` 共享的 skill 不在列表里。没有「发现」页；侧栏是 SKILL 组（项名「管理」）与设置组（账号、权限）。列表今天只有「最近更新 / 名称」两种排序，**没有调用次数**——设计稿里的那一列是前瞻字段，产品没有这个数据。
- **标签**：没有。个人组织只能靠命名前缀、记忆，或者把 skill 名字抄在别处。
- **加载**：公开 skill 不需要任何动作就能 `skill invoke`（[ADR 0048](../../decisions/0048-visibility-hands-out-a-rung.md) §决定 5）。这一版**不改这条**：加入是组织，不是门禁。

## 范围

### 做

| # | 做什么 | 交付形态 |
|---|---|---|
| 1 | **公域发现**：只有**公开、有当前版本、未下线、未删除**的 skill 进入公域；只能**搜**（关键词和/或公开分类，至少一个），不能整表列；结果分页（`p` 进地址）、卡片式；结果卡片有「加入」；已在库里的结果只读显示**来源**（我创建的 / 共享给我的 / 我加入的） | 服务端 + 控制台「发现」页 + CLI |
| 2 | **我的库（私域）**：库 = **我创建的 / 共享给我的 / 我加入的**。`skills list`（CLI）只列**可消费的库**——这三类里有当前版本、未下线、未删除的；草稿与下线只出现在控制台「我的 skill」。控制台「我的 skill」是完整库（含草稿、下线、作者面的「已删除」），每条标明来源；CLI 卡片格式不变。公开但未加入的不出现 | 服务端 + 控制台「我的 skill」+ CLI + 网关 |
| 3 | **加入 / 移除**：加入是**引用**（不复制内容、不产生版本、不改变访问权、不挡加载）；加入幂等；只能加入**同时满足**这些条件的 skill：`visibility = public`、有当前版本、未下线、未删除、我不拥有、**没有任何 `skill_grant` 行**（公开档不算授权）、**没有库加入引用（含休眠）**。已在库是 no-op；不可见或非公开是 404；**可见但当前不可加入（下线 / 没有当前版本）是 409 + 可读原因**。移除只删“我加入的”这条引用（显示来源被更高的“共享给我的”盖住时，加入关系仍在，但不显示移除入口）；移除用**普通弹窗（不染红）**，写明标签保留、重新加入后回来 | 服务端 + 控制台 |
| 4 | **库的生命周期**：我加入的条目有**生效 / 休眠**；**移除是动作，结果是引用删除、不留墓碑**；我的标签按“人 + skill”保留并休眠。下线时：我加入的与 `browse` / `invoke` 共享的休眠；我创建的与 `write` 及以上共享的留在「在用」并显示「已下线」。软删除时：我创建的进作者面「已删除」，其余休眠。撤销共享时共享来源直接消失（有加入引用且仍可读则条目留下、来源变我加入的，**标签继续生效**；否则条目离开库、标签休眠）。两个谓词见 §两个谓词 | 规则 + 服务端 + 测试 |
| 5 | **公开分类**：平台预置词表（10 个，见 §公开分类词表）；贴在 skill 上；所有者与 `admin`（界面写「管理」）协作者可加/减；每个 skill 最多 5 个；**所有能看见该 skill 的人都能看到**；改完立即生效 | 服务端 + 控制台信息页 |
| 6 | **我的标签**：每个用户在自己库里的 skill 上的一套标签（界面与本文叫**我的标签**，模型 / 代码 / ADR 叫**私人标签**，CLI 是 `skills my-tags`）；可新建、改名、删除；每个 skill 最多 20 个（只算生效中的）、每个账号最多 100 个（**含只有休眠贴法的定义**）；名字 1–24 字（按 Unicode 码点，去首尾空格，内部连续空格压成一个）、同一用户大小写不敏感唯一、不得与公开分类重名；只有本人可见 | 服务端 + 控制台信息页 + 「我的标签」页 |
| 7 | **标签生命周期**：定义与贴法的状态、范围出生即定、改名原地生效、删除连坐、休眠与恢复、删除时清除 | 规则 + 服务端 + 测试 |
| 8 | **控制台「发现」页**：搜索框 + 公开分类过滤 + 结果卡片（含公开分类）+ 加入动作；首次进入是“输入关键词或选分类”的空态，**空态保留搜索框与分类选择器**，不自动列出全部公开 skill；卡片区分「未加入 / 加入中 / 已在库（显示来源）/ 加入失败」，失败可原地重试 | 控制台（新页面） |
| 9 | **控制台「我的 skill」= 库**：页面标题保持「我的 skill」；侧栏 SKILL 组的库入口仍叫「管理」。来源是**行内标签**（我创建的 / 共享给我的 / 我加入的），不是第三个页签；「在用 / 已删除」两份页签保留，「已删除」只含我创建的软删除 skill，共享/加入没有已删除态，且 `show=deleted` 时隐藏标签筛选并从地址去掉 `tag` / `my-tag`；**库本身为空 → 库空态（新建 + 去发现），不画页签（沿用现状）；库非空但没有已删除 skill → 页签保留、已删除列表显示空态**。作者管理（草稿、版本）仍在；公开未加入的不出现。行内：我创建的行有作者管理入口与「已下线」状态；`write` 及以上共享的行同样显示「已下线」；共享/加入的行行内只有一个「打开」入口，打开后能做什么由档位决定；移除只在信息页；已删除行只有「恢复」。**本版不显示调用次数、不提供「调用最多」排序**——产品今天没有这个数据；排序只有最近更新 / 名字，默认最近更新；排序项「名称」改为「名字」。空库空态同时给「新建 skill」与「去发现公开 skill」 | 控制台（列表页） |
| 10 | **控制台信息页**：公开分类所有能看见该 skill 的人可见、所有者/管理可编辑；我的标签**只有库条目生效的 skill 才有这一区**、本人可编辑；条目休眠时这一区不显示。按钮矩阵：不在库 →「加入」；我加入的 →「移除」；共享给我的 → **不显示加入/移除**；我创建的 → **不显示加入/移除**；可见但当前不可加入（下线 / 无当前版本）→ 不显示「加入」，说明原因。加入是独立于「申请更高档位」的动作，位置由设计定但必须与申请块分开。0 个公开分类时只读视图不画空块、所有者/管理始终有编辑入口；0 个我的标签时只读视图不画、本人有添加入口；非库 skill 不画我的标签区。公开分类选择器：10 个词、最多 5 个、0 计数也显示、第 6 个禁用；我的标签编辑器：1–24 字、20/100 上限、重名可读错误；**筛选与选择器都是多选**。现有 `#infoTags` 槽位只承接**公开分类的只读胶囊**；两组标签的分组标题、编辑入口与弹窗是设计新增 | 控制台（信息页 + 编辑弹窗） |
| 11 | **控制台「我的标签」页**：路由 `/my-tags`，侧栏 SKILL 组一级项；列出全部定义与「用在 N 个 skill 上」的计数，按计数降序、同数按名字；**新建标签**、改名、删除标签（删除是**红色危险弹窗**，写清 N 个可见 + M 个当前不显示的会一起清除）；六态完整：正常有标签 / 空（0 个定义）/ 加载中 / 加载失败 / 只有休眠（0 个生效，文案写成用户能懂的话）/ 达到 100 个（新建禁用并说明） | 控制台（新页面） |
| 12 | **服务端与 CLI**：库关系与查询；公域/私域两种检索；标签定义与关联的存储、过滤、CRUD、权限、审计。`skills list [q] [--all] [--namespace] [--tag] [--my-tag]`（**可消费的库**；默认一页 50 行，不返回游标）；`skills search [q] [--tag]`（**只搜公域**，q 或公开分类至少一个；一页 + “还有更多”，不返回游标）；`skills tags`（公开词表与公域计数）、`skills my-tags`（我的标签与「用在 N 个 skill 上」的计数）**两者一次给全**、拒绝 `--json`、有帮助；四个读命令都接受 `--no-login`；未知标签名按空结果 + 可读提示处理（指向 `skills tags` / `skills my-tags`）；**列表卡片不打印标签与来源**（L1 预算），词表与计数只由 `skills tags` / `skills my-tags` 给；**CLI 不写标签、不加入/移除库** | 服务端 + CLI |
| 13 | **检索增强**：多词取“且”；`when_to_use` 纳入匹配；文本索引；标签过滤在 SQL 的访问谓词内，不做结果后过滤；公域检索必须有关键词或公开分类；**标签词不参与关键词匹配**（`q` 只匹配 name / title / description / `when_to_use`）。`when_to_use` 是平台元数据（frontmatter），不是正文或文件——这是对 ADR 0006 显式枚举（name / description / title）的一次**有意扩展**，写进新 ADR | 服务端 |
| 14 | **网关 skill**：第 1 步是 `skills list --no-login`（我的库）；库里斯没有时再 `skills search --no-login` 去公域；补上按标签收窄；`metadata.platform_api_version` 从 9 加到 10；`setup` 重装时提示版本变化 | `gateway/skillmaster/SKILL.md` |
| 15 | **设计稿与检查**：发现页、库列表的来源/页签/过滤/行内动作与**行内状态（含「已下线」）**、信息页两组标签与编辑弹窗、「我的标签」页、窄屏（约 400px）。设计件要补**六种库归属**（不在库 / 我加入的 / 共享给我的 / 我创建的 / 可见但当前不可加入 / **库条目休眠**）与**加入中 / 加入失败**；列表补 `offline` 行状态与 `write+` / `browse`·`invoke` 两种共享夹具；空库空态文案随 #9 更新（含「去发现公开 skill」）。**删掉调用次数列、「调用最多」排序、相关夹具与 `console-states.mjs` 的两条断言**，并更新 `design/README.md` 的前瞻字段说明；排序项「名称」改「名字」；库搜索框 placeholder 改成能搜「名字、说明或适用场景」，夹具补 `when_to_use`；**标签筛选与公开分类选择器是多选，不能复用单选 `MenuSelect`**；`console-states.mjs` 的“标签这一版不显示”拆成两条断言（公开分类可见，跑在能看见且有分类的 skill 上；我的标签仅在库内可见且可编辑，**新增 skill 页夹具：库内成员 + 有我的标签**），另加一条「休眠条目隐藏我的标签区」；旧 `as=invoke` 断言替换；为发现页、我的标签页新建检查组与夹具；`design/README.md` 与 `design/voice-spec.md` 更新（「发现」= 导航名对名词短语规则的例外；「管理」= 一词两义的已批准用法；排序项「名称→名字」这条待改项一并处理）；删除标签弹窗的标题「删除标签？」与确认按钮「确认删除标签」按现有 DangerConfirm 骨架补；移除加入的 skill 弹窗标题「从我的 skill 移除？」、确认按钮「确认移除」；出图由人验收 | `design/` |
| 16 | **决策记录与配套**：三条新 ADR——「公域/私域与我的库」（引用、不挡加载、默认列库、公域只搜不列）、「两套标签」（范围出生即定、只属于库、休眠与删除）、「检索的 L1 扩展」（`when_to_use` + 多词）；CLI README、`skills help` / `skills tags help` / `skills my-tags help`、QA 探针随实现更新 | 文档 |

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | 向量 / 语义检索 | 新基础设施（embedding、向量存储、重算、模型升级），而 ADR 0006 要求排序可解释、可回归；先用回归集与真实查询日志证明关键词 + 标签不够 | 单独一版，前置是回归集与查询日志 |
| 2 | 开机自动加载（SessionStart hook） | 网关 skill 已经能引导 agent 按需调用；配置钩子要处理每台机器的断网、未登录、超时，收益没有证据 | 有用户明确要求“一开会话就知道”时 |
| 3 | 我的标签转公开 / 申请审核 | 范围出生即定：标签一旦公开，所有贴过它的人的组织方式就暴露了 | 不做；如果以后要做，只能“新建公开分类”，不转换已有贴法 |
| 4 | 用户自建公开分类 | 公开分类是公域发现的稳定入口，词表必须由平台控制 | 有社区治理需求时 |
| 5 | 标签合并 | 改名撞名先拒绝；合并要批量改关联、处理休眠贴法、给出确认，属于另一套动作 | 有真实重复数据后 |
| 6 | 按标签排序 / 标签影响权重 | 标签是过滤条件，不是排序信号；ADR 0006 要求排序可解释、可调、可回归 | 有使用信号、且能解释“为什么它排在前面”时 |
| 7 | 平台词表管理后台 | 这一版词表是迁移种子；停用/退役的状态留着，但没有界面 | 词表需要频繁变更时 |
| 8 | CLI 写标签、CLI 加入/移除库 | 管理动作在控制台；CLI 只读，避免 agent 在会话里改用户的分组与库 | 明确需要脚本化管理时 |
| 9 | 团队 / 组织共享标签或共享库 | 这一版的库与标签都是“人 + skill”；共享是另一套模型，依赖组织模型 | 组织模型落地时 |
| 10 | 标签历史 / 版本 | 标签是发现用的元数据，改完立即生效；变更留在审计里，不进版本 | 不做 |
| 11 | 导入 SKILL.md 里的 `metadata.tags` | 两套来源会打架：作者写了、控制台又改，最后不知道谁说了算；这一版控制台是唯一入口 | 不做 |
| 12 | 标签多语言 / 同义词 | 先用平台词表 + 用户自定义；同义词与翻译是搜索质量话题 | 与语义检索一起评估 |
| 13 | 公开分类的停用 / 退役界面 | 状态存在，但这一版只由平台通过迁移操作；用户不需要看见 | 词表需要在线运营时 |
| 14 | **新增 `skills discover`** | 它与 `skills list` / `skills search` 回答同一批问题；ADR 0077 允许它只作薄别名，本版不留第二套方言 | 如果 `list` / `search` 以后长出与“发现”明显不同的语义，再评估 |
| 15 | 给列表/检索加 `--json` | v13 已把这条列为既有例外（§10），本版没有改变理由：agent 读文本，`--all` 能一次取全；加 `--json` 是新的对外契约 | 出现明确的脚本/管道消费者、或把 `--json` 升级为共同契约时 |
| 16 | **复制 / 派生公开 skill** | 加入是引用：作者发新版，库里跟新版；复制会切断更新、带来内容归属与许可问题 | 需要“以别人的 skill 为起点改一份”时，单独一版 |
| 17 | **未加条件的公开全量列表** | 公域 skill 会多到无法加载；公域只搜不列，是这个版本的上下文预算前提 | 有分页的公开目录需求、且能证明预算够时 |
| 18 | **公开 skill 的加载门禁** | 未加入的公开 skill 仍可直接 `skill invoke`（ADR 0048 不动）；加入是组织，不是权限 | 如果以后要收回“公开即可调用”，先改 ADR 0048 |
| 19 | **匿名公域发现** | 今天 API 与控制台都要求登录；这一版保持。公域发现是登录后的能力 | 公开市场面向未登录访客时 |
| 20 | **作者更新通知** | 引用会自动跟到作者的新版；通知（站内信/邮件）是另一套机制 | 有订阅需求时 |
| 21 | **库的团队 / 共享视图** | 库是个人私域，别人（含所有者与 `admin`）看不到 | 组织模型落地时 |
| 22 | **把 `--my-tag` 放进 `skills search`** | search 只搜公域，我的标签只属于库；把它放进公域检索只会制造“筛不到任何东西”的空查询 | 如果以后 search 重新覆盖库 |
| 23 | **调用次数 / 「调用最多」排序** | 产品今天没有用量信号，设计稿里的那一列是前瞻字段；这一版不采数据、不建表、不显示 | 用量信号落地后（P1） |

**词表规则**：

- **数量与稳定**：本版 10 个（首日种子；停用/退役后可见数量会变）。增删改只由平台在迁移里做，本版没有管理界面（不做 #7）。
- **可贴数量**：一个 skill 最多 5 个分类，可以是 0 个；词表外的词不能被添加。
- **命名**：名词短语，2–6 个汉字；不出现版本号、品牌名、客户名。

- **一种语言**：词表是中文，控制台与 CLI 共用同一组词；不做翻译与同义词（不做 #12）。

## 库与标签的生命周期

**三个对象，不能混用**：

- **库条目**——「我的库」里的一行。来源有三种：我创建的、共享给我的、我加入的。
- **标签定义**——那个词本身（“文档与演示”“客户项目”）。它有范围（公开分类 / 我的标签）和主人（平台 / 某个人）。
- **贴法**——这个词贴在哪个 skill 上。我的标签的贴法还要记住“是谁贴的”。

### 两个谓词，不能混用

- **能看见**（用于公开分类与信息页）：**（我创建的 ∨ 有显式授权 ∨ 公开）且未删除**。下线仍算能看见（作者面可见，消费面调用返回 503）；软删除后不再能看见——**作者面的「已删除」列表是作者视图，不算“能看见”，那一行不可打开**。公开但没有当前版本的 skill 能看见地址，**消费面（API）详情打不开**，但**控制台信息页仍可打开**，用来显示不可加入的原因；它不进公域检索。
- **库条目生效**（用于我的标签是否生效）：
  - **我创建的**：未软删除。下线仍生效，列表显示「已下线」。
  - **共享给我的、`write` 及以上**：未软删除。下线仍生效，列表显示「已下线」。
  - **共享给我的、`browse` / `invoke`**：有授权 ∧ 未下线 ∧ 未删除 ∧ 有当前版本。
  - **我加入的**：引用存在 ∧ 可读（未下线 ∧ 未删除 ∧ 有当前版本）。
- **我的标签只在库条目生效时生效**；条目休眠，标签休眠，信息页**不显示这一区**。

### 库条目

| 来源 | 何时在库里 | 能不能移除 |
|---|---|---|
| **我创建的** | 始终；下线仍在「在用」并显示「已下线」；软删除后进作者面「已删除」页签 | 不能（删除是另一件事） |
| **共享给我的** | 有任何档位的授权时；授权撤销后这条来源就消失。`write` 及以上下线仍在库并显示「已下线」；`browse` / `invoke` 失去可消费性（下线 / 软删除 / 没有当前版本）则休眠 | 不能（那是别人的 skill） |
| **我加入的** | 我显式加入后；失去可消费性（下线 / 软删除 / 没有当前版本）时休眠；我移除后引用消失 | 能 |

**没有当前版本与下线、软删除一样，按休眠处理**（它与「能看见」不是一回事：地址仍能看见，但消费不了）。

**加入条目的状态**：

| 状态 | 含义 |
|---|---|
| **生效** | 满足上面「库条目生效」的谓词 |
| **休眠** | 库条目不生效，隐藏但引用保留；恢复可见后回来 |
| **已移除** | 不是状态，是动作结果：引用删除、不留墓碑；我的标签按 (人, skill) 保留并休眠 |

**核心规则**：

1. **库是私域。** 只有本人看得见自己的库，包括所有者与 `admin` 都看不到别人的库。
2. **加入是引用。** 不复制内容、不产生版本、不改变访问权、不挡加载；作者发新版，库里跟新版。
3. **加入不是授权。** 移除一条加入的 skill，不会改变我对它的访问权；它仍然可能在公域里被搜到、被调用。
4. **共享来源是派生的。** 有授权就在库里，撤销就不在；不额外存一行，也不需要“移除共享”。
5. **下线 / 软删除 / 撤销共享，分来源说。** 下线时：我加入的与 `browse` / `invoke` 共享的条目休眠；我创建的与 `write` 及以上共享的留在「在用」并显示「已下线」。软删除时：我创建的进作者面「已删除」，其余休眠。撤销共享时：共享来源直接消失；若还有加入引用且 skill 仍可读，条目留下（来源变我加入的），**我的标签继续生效**；否则条目离开库，我的标签休眠。
6. **公开但未加入的不在库里。** 它只在公域检索里出现；要让它进库，必须显式加入。
7. **显示来源与能不能移除是两件事。** 来源按“我创建的 > 共享给我的 > 我加入的”显示；移除入口只在**没有更高来源、且加入引用存在**时出现。加入过、后来又被授权的 skill 显示为“共享给我的”，移除入口隐藏，但加入引用仍在——授权撤掉且 skill 仍公开时，它会重新成为“我加入的”。
8. **“已删除”不是库的状态。** 它是我创建的 skill 的作者面视图；软删除的 skill 不在生效库里，我的标签在它上面休眠，恢复后回来。

### 标签定义与贴法

#### 状态

| 对象 | 状态 | 含义 |
|---|---|---|
| 公开分类（标签定义） | **启用** | 在平台词表里，可以往 skill 上加 |
| | **停用** | 不能再新增；已有的贴法保留，仍可筛、仍可摘；选择器里置灰 |
| | **退役** | 从所有 skill 上摘除，不再出现、不可筛；终点 |
| 我的标签（标签定义） | **可用** | 在个人的标签库里，可以往库里的 skill 上贴；0 次也还在，直到本人删掉；改名是原地改，不是新状态 |
| | **已删除** | 名字可以重新用；旧记录留在审计里；终点 |
| 公开分类的贴法 | **生效** | skill 上有这个分类，所有能看见该 skill 的人都看得到 |
| | **已摘除** | 被所有者/管理员拿掉 |
| 我的标签的贴法 | **生效** | 对应的库条目生效；标签出现在本人的列表、计数与筛选里 |
| | **休眠** | 库条目不生效（休眠或被移除）；标签不丢，只是不显示、不计数；恢复可见/重新加入后自动回来 |
| | **已摘除** | 本人把它从这个 skill 上拿掉 |
| | **已清除** | 标签定义被删除时连带清除；skill 若未来出现永久删除，也走清除 |

#### 核心规则

1. **我的标签只属于库。** 只有库里的 skill（我创建的、共享给我的、我加入的）能贴我的标签；公开但未加入的 skill 不能在它上面建我的标签。
2. **范围出生即定，永不改变。** 我的标签一辈子是私人的；公开分类只能由平台创建。**不存在“把我的标签改成公开”这个动作**。
3. **skill 变公开，不会让任何人的我的标签变公开。** 变的只是公开分类的可见范围：skill 公开后，公开分类才进入公域搜索；我的标签仍然只有贴的人看得到。
4. **改名不是新建。** 同一个标签 id，所有贴过的地方一起变；筛选、计数、链接都跟着走。
5. **删除是连坐的。** 删掉一个我的标签，它在所有 skill 上的贴法（含休眠的）一起消失；删之前说清影响：**N 个当前生效的贴法，另有 M 个当前不生效的贴法也会一起清除**。
6. **同一个名字不能两用。** 我的标签不能和公开分类重名，避免列表里出现两个“文档与演示”。改名撞名先拒绝；合并以后再说。
7. **公开分类的停用和退役是平台动作。** 停用＝不再接受新的贴法，已有的还在；退役＝从所有 skill 上摘掉。这一版没有界面，只由迁移 / IT 造状态。

#### 事件表

| 发生了什么 | 库条目 | 公开分类 | 我的标签 |
|---|---|---|---|
| 作者发新版 | 不变；引用跟到新版 | 不变 | 不变 |
| 我加入一个公开 skill | 新增一行（来源：我加入的） | 不变 | 原先休眠的我的标签恢复 |
| 我移除一个加入的 skill | 引用消失 | 不变 | 进入休眠，不丢；重新加入后回来 |
| skill 从私有变公开 | 共享/我创建的条目不变 | 进入公域搜索 | 不变 |
| skill 从公开变私有 | 我加入的条目：没有授权则休眠；有授权则留下（来源变共享给我的） | 退出公域搜索；能看的人仍看得到 | 跟着库条目休眠/保留 |
| 别人撤销对我的共享 | 共享来源消失；若 skill 仍公开且我加入过，条目留下（来源变我加入的）；否则条目离开库 | 不变 | 条目留下 → 继续生效；条目离开 → 休眠 |
| skill 下线 | 我创建的与 `write` 及以上共享的留在「在用」并显示「已下线」；`browse` / `invoke` 共享的与我加入的休眠 | 退出公域检索；能看的人仍看得到 | 条目生效的继续生效；条目休眠的继续休眠 |
| skill 软删除 | 我创建的进作者面「已删除」；共享/加入的条目休眠 | 对所有读路径不可见 | 休眠，恢复后回来 |
| 我删掉一个我的标签 | 不变 | 不受影响 | 所有 skill 上一起摘掉（含休眠） |
| 平台停用一个公开分类 | 不变 | 不能再新加，已有的还在，仍可摘 | 不受影响 |
| 平台退役一个公开分类 | 不变 | 从所有 skill 上摘掉 | 不受影响 |

| 上限 | 每 skill 20 个我的标签（只算生效中的）；每账号 100 个定义（含只有休眠贴法的定义）。 |

## 验收与指标

### 验收标准

| # | 验收标准 | 怎么判定 |
|---|---|---|
| 1 | **库的组成**：`skills list`（CLI）只列**可消费的库**——我创建的、任何档位共享给我的、我加入的，且已发布 / 未下线 / 未删除；公开但未加入、草稿、下线的不出现。控制台「我的 skill」是完整库（含草稿、下线、作者面「已删除」）。`--all` 取全；空库空态同时给「新建 skill」与「去发现公开 skill」 | 三账号矩阵：公开未加入 / 加入 / 移除 / 共享（invoke、browse、admin 各一）+ 草稿/下线条目只在控制台出现；逐条断言 + 空态断言 |
| 2 | **加入是引用**：不复制内容、不产生版本、不改变访问权；作者发新版后，库里的 skill 跟到新版；重复加入是幂等的 | 加入前后 DB（版本数、digest）+ 作者发新版后库内读到的版本 + 重复加入 |

**成立条件**：**#1、#4、#7、#12、#22、#23 是“不满足就不算交付”的六条。** #1/#4 是这套模型的定义——库不能把公开 skill 混进来，加入也不能变成加载门禁；#7/#12/#22/#23 是隐私底线——库与我的标签一旦泄露，或者我的标签能贴到库外，整个“公域 / 私域”的分层就失去意义。**#6 与 #21 是生命周期的心脏**：休眠与恢复不成立，用户丢一次共享就丢一次组织，产品会教人不要用标签。

### 指标

| 指标 | 定义 | 怎么量 | 目标 |
|---|---|---|---|
| 库列表预算 | `skills list` 默认一次返回的行数与字节 | 200 个 skill 的库夹具上各跑 10 次，取中位数与最大值 | 默认 ≤50 行（本版从 v13 的 100 收到 50，见 §依赖与前置）；超过时必须出现截断提示；不返回游标 |
| 公域检索的响应 | 公开 scope、带关键词或分类时 p50 / p95 | 5000 个公开 skill 的夹具上各跑 10 次 | p95 不超过同等私域检索的 2 倍 |
| 检索回归集 | 30 条代表性查询的 top-5 命中率；单关键词与多词分开记 | 实现前先量一次基线；实现后同一集合同口径复量 | 单关键词不低于基线；新增的多词/`when_to_use` 用例全部按预期命中 |
| 标签过滤的查询成本 | 同一数据集、同一环境下，带标签过滤与不带标签的同查询 p95 之比 | `EXPLAIN (ANALYZE)` + 压测；记录 p50/p95 | p95 不超过不带标签查询的 1.5 倍 |

## 依赖与前置

- **外部依赖**：无新服务。库、标签与关联都落在 PostgreSQL（[ADR 0010](../../decisions/0010-storage-in-postgres.md)），不引向量库、不引搜索引擎。
- **内部前提**：
  - **三条新 ADR**（编号在写入时分配）：
    1. **公域 / 私域与我的库**：库是引用、不复制、不授权、不挡加载；`skills list` 默认列库；公域只搜不列。
    2. **两套标签**：公开分类与我的标签的范围、出生即定、只属于库、休眠与删除的取舍。
    3. **检索的 L1 扩展**：`when_to_use` 与多词匹配；`when_to_use` 是平台元数据（frontmatter），不是正文或文件，不违反“不索引正文/文件”的安全理由。
  - [ADR 0006](../../decisions/0006-search-server-side.md)：检索在服务端、只索引 L1、排序可解释可回归。它的 L1 枚举是 name + description + title；本版的 `when_to_use` 扩展见上面第 3 条 ADR。
  - [ADR 0002](../../decisions/0002-gateway-skill-and-cli.md)：网关 skill + CLI 是 agent 的入口；本版改第 1 步与检索。
  - [ADR 0047](../../decisions/0047-permissions-are-a-ladder.md) / [0048](../../decisions/0048-visibility-hands-out-a-rung.md)：公开分类的写权限沿用梯子；公开即被搜到、可直接调用——本版不改 0048 的访问语义。
  - [ADR 0034](../../decisions/0034-skill-level-sharing.md)：**skill 级共享（读可跨命名空间；命名空间成员关系仍未生效）**——共享来源与休眠规则依赖它。
  - [ADR 0053](../../decisions/0053-skill-metadata-is-its-own-module.md)：新的关联表落 M12（`skill` 所在模块）；**标签与库条目的表必须与 `skill` 同模块**，否则“标签过滤在 SQL 的访问谓词内”与“一条 SQL 不得点两个模块的表”会冲突。落别处需要新 ADR，由 TD 细化。
  - [ADR 0056](../../decisions/0056-dangerous-actions-are-confirmed-in-a-modal.md)：删除我的标签是红色危险弹窗；移除加入的 skill 是普通弹窗（不染红）。
  - [ADR 0031](../../decisions/0031-submitting-and-publishing-are-two-actions.md)：标签改完立即生效，不走提交/上线。
  - [ADR 0077](../../decisions/0077-the-cli-grammar-is-singular-and-plural.md)：集合侧命令进 `skills` 组；`discover` 只能作薄别名，本版不采用。
  - **v13 的 CLI 契约**（[`../v13-cli-grammar/prd.md`](../v13-cli-grammar/prd.md) §CLI 命令行为规范）：`skills list` / `skills search` 的新参数与 `skills tags` / `skills my-tags` 要过 §1（分组）、§2（地址与例外）、§3（输出流与退出码）、§4（分页/一次给全）、§6（凭据与浏览器）、§7（帮助）、§9（新增命令检查清单）。**本版对 v13 契约有六处有意变更**：
    1. `skills list` 的**结果集**从「自己的 ∨ 授权 ∨ 公开，且已发布 / 未下线 / 未删除」改成「**可消费的库**：我创建的 / 共享给我的 / 我加入的，且已发布 / 未下线 / 未删除」——公开未加入不再出现，加入的公开开始出现。这是本版最大的行为变更。
    2. `skills list` 的默认页从 **100 收到 50**（v13 §4/验收 #14 钉的是 100）。
    3. `skills list` 新增 `q`（库内关键词）。
    4. `skills list` 新增 `--tag` / `--my-tag`（库内标签过滤）。
    5. `skills search` **收窄为只搜公域**；关键词从必填变为“q 或公开分类至少一个”，新增 `--tag`，不再接受 `--my-tag`（v13 里它本来也没有标签参数）。
    6. `skills list` / `skills search` **新增 `--no-login`**；默认行为不变（缺凭据仍自动登录，无浏览器时快速失败）。
  - [ADR 0075](../../decisions/0075-the-browser-client-is-react.md) / [0076](../../decisions/0076-the-design-file-is-react-source.md)：浏览器端是 React，设计稿源码也是 React——发现页与标签界面照设计源码搬。
- **产品口径**：界面名词、过滤地址、多选语义、排序、空态、确认文案、上限全部定在 §展示与计数口径，这里不复述；对 v13 契约的变更以上面六条为准。
- **排除了什么前置**：
  - **不需要向量库或新的检索服务**：这一版只加库、标签过滤与关键词增强。
  - **不需要开机钩子**：网关 skill 已能引导 agent 调用。
  - **不需要导入 SKILL.md 的 tags**：控制台是唯一入口，避免两个来源。
  - **不需要组织/团队模型**：库与标签都是“人 + skill”。
  - **不需要新的顶层命令组**：`tags` / `my-tags` 都进既有 `skills` 组。
  - **不需要 `skills discover`**：公域发现是 `skills search` 的 scope，不是第二个命令。
  - **不需要采集调用次数**：产品今天没有用量信号，本版不显示这一列、不提供「调用最多」排序（不做 #23）。

- **版本编号**：本版原记为 `v13-skill-tags`，因 v13 编号给了 CLI 命令面而顺延为 **v14**（见 [`../v13-cli-grammar/prd.md`](../v13-cli-grammar/prd.md) §依赖与前置）。范围从“两套标签”扩到“公域/私域、我的库、两套标签”，因为标签依赖库这一层；这是需求补全，不是另起一版。
