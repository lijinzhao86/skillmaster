## 用户与场景

**谁在用**：五类，要分开说，因为验收对象不同。

- **整理自己目录的人**：名下有自己的 skill，也有别人共享的和从公域加进来的。他要按“客户项目”“这周要用”这类**只有自己懂**的分组来找东西，并且不希望这层分组被任何人看见。
- **公域里的读者/消费者**：想找一个公开 skill 来用。公域**不能整表列出**（公开 skill 会多到无法加载）：控制台先给一段**有界的「为你推荐」**（不在我库里、最近更新的），要找别的就搜索或按分类；搜到之后才决定要不要加入自己的库。
- **公开 skill 的作者/所有者**：希望别人能按领域找到自己的 skill；今天只有关键词，而关键词只在名字、标题、描述里做子串匹配。
- **管理员协作者**：帮别人维护一个 skill，需要调整它的公开分类，但不该看到或改动别人的标签或库。
- **agent（经 CLI）**：在会话开始或任务需要时拿一份有边界的目录；今天 `skills list` 是被公开 skill 淹没的“所有我能读的”，`skills search` 是字面子串。

**在什么场景下用**：

- 一个人有几十个 skill，想对 agent 说“这次只加载我库里的这一组”，而不是把整个公域塞进上下文：`skills list --my-tag 客户项目 --all`。
- 一个读者在公域搜“做 PPT”，找到「文档与演示」分类下的一个公开 skill，**加入我的 skill**，然后它出现在自己的库里；以后可以直接 `skills list` 看到它，也可以给它贴「我的标签」。
- 作者发布一个公开 skill，希望它出现在「文档与演示」这个公开分类下；读者按这个分类能找到它。
- 两个同事都在一个公开 skill 上贴了自己的标签：一个写“待评估”，一个写“设计组”；彼此看不到，也不影响公域检索。
- agent 在本库里找不到，再 `skills search` 去公域找；找到的那一个不需要加入也能直接 `skill invoke`。

**本版开工前（`main@2811293`）的替代做法是什么**：

- **目录**：`skills list` 的谓词是「自己的 ∨ 被授权 ∨ 公开」（`SkillCatalogRepository.java:108-111`），所以**公开、有当前版本、未下线、未删除**的 skill 会混进列表；没有“加入”这个动作，也没有“我的库”这一层。
- **公域**：公开 skill 只能靠关键词碰运气；`GET /api/v1/skills?q=` 对 name / title / description 做 `ILIKE` 整串子串匹配，不拆词，也不看 `when_to_use`。
- **控制台**：列表是**作者面**——自己的 + `write` 及以上共享的；公开 skill 与 `browse` / `invoke` 共享的 skill 不在列表里。没有「发现」页；侧栏是 SKILL 组（项名「管理」）与设置组（账号、权限）。列表今天只有「最近更新 / 名称」两种排序，**没有调用次数**——设计稿里的那一列是前瞻字段，产品没有这个数据。
- **标签**：没有。个人组织只能靠命名前缀、记忆，或者把 skill 名字抄在别处。
- **加载**：公开 skill 不需要任何动作就能 `skill invoke`（[ADR 0048](../../decisions/0048-visibility-hands-out-a-rung.md) §决定 5）。这一版**不改这条**：加入是组织，不是门禁。

## 范围

### 做

| # | 做什么 | 交付形态 |
|---|---|---|
| 1 | **公域发现**：只有**公开、有当前版本、未下线、未删除**的 skill 进入公域；只能**搜**（关键词、公开分类或公开标签，至少一个），不能整表列；结果分页（`p` 进地址）、卡片式；结果卡片有「加入」；**原本就在库里**的结果只读显示**来源**（我创建的 / 共享给我的 / 我加入的），不提供移除；刚加入的那张可以再点一次书签移除 | 服务端 + 控制台「发现」页 + CLI |
| 2 | **我的库（私域）**：库 = **我创建的 / 共享给我的 / 我加入的**。`skills list`（CLI）**默认只列可消费的库**——这三类里有当前版本、未下线、未删除的；`--show draft/offline/deleted/all` 可看控制台的那份完整库（验收 #50）。控制台「我的 skill」是完整库（含草稿、下线、作者面的「已删除」），每条标明来源；CLI 默认卡片格式不变。公开但未加入的不出现 | 服务端 + 控制台「我的 skill」+ CLI + 网关 |
| 3 | **加入 / 移除**：加入是**引用**（不复制内容、不产生版本、不改变访问权、不挡加载）；加入幂等；只能加入**同时满足**这些条件的 skill：`visibility = public`、有当前版本、未下线、未删除、我不拥有、**没有授予我的 `skill_grant` 行**（公开可见不算授权）、**没有库加入引用（含休眠）**。已有加入引用（含休眠）是 no-op；来源是创建 / 共享（没有加入引用）是 409 + 可读原因（它已经在库里，加入不会多出什么）；不可见或非公开是 404；**可见但当前不可加入（下线 / 没有当前版本）是 409 + 可读原因**。移除只删“我加入的”这条引用（显示来源被更高的“共享给我的”盖住时，加入关系仍在，但不显示移除入口）；移除（信息页；库的行内没有移除入口）用**普通弹窗（不染红）**，写明标签保留、重新加入后回来；**发现页刚加入的那张再点一次书签是“加入的回退”**——只回退刚刚这一次加入，立即生效、不弹窗，不是一次独立的移除；**CLI 用 `skill join` / `skill leave`，没有 `--yes` 时只打印后果与完整命令、不执行** | 服务端 + 控制台 + CLI |
| 4 | **库的生命周期**：我加入的条目有**生效 / 休眠**；**移除是动作，结果是引用删除、不留墓碑**；我的标签按“人 + skill”保留并休眠。下线时：我加入的与 `browse` / `invoke` 共享的休眠；我创建的与 `write` 及以上共享的留在「在用」并显示「已下线」。软删除时：我创建的进作者面「已删除」，其余休眠。撤销共享时共享来源直接消失（有加入引用且仍可读则条目留下、来源变我加入的，**标签继续生效**；否则条目离开库、标签休眠）。两个谓词见 §两个谓词 | 规则 + 服务端 + 测试 |
| 5 | **公开分类**：平台预置词表，**平级 10 个词、每个 skill 只贴一个**（2026-10-23 收窄，见 §公开分类词表）；所有者与 `admin`（界面写「管理」）协作者可加/换/清除；**所有能看见该 skill 的人都能看到**；改完立即生效 | 服务端 + 控制台信息页 |
| 6 | **我的标签**：每个用户在自己库里的 skill 上的一套标签（界面在信息页那一组、库的筛选与管理页的页签里叫**我的标签**，侧栏的「管理 › 标签」与那一页的标题仍是「标签」；目标态文档与模型里称**私人标签**；界面上带限定语的那几处叫**我的标签**（页名与侧栏仍叫「标签」）；CLI 与决定正文叫**我的标签**（CLI 是 `skills my-tags`））；可新建、改名、删除；每个 skill 最多 20 个（只算生效中的）、每个账号最多 100 个（**含只有休眠贴法的定义**）；名字 1–24 字（按 Unicode 码点，去首尾空格，内部连续空格压成一个）、同一用户大小写不敏感唯一、不得与公开分类重名；每个标签可以有一句**说明**（选填，≤200 字）：说**什么时候该贴它**，人和 agent 读同一句；改说明不是改名，不动任何贴法；只有本人可见（说明与名字一样）。**公开标签是另一层，本版做最小闭环**（见 #17 与 §公开标签） | 服务端 + 控制台信息页 + 「标签」页 |
| 7 | **标签生命周期**：定义与贴法的状态、范围出生即定、改名原地生效、删除连坐、休眠与恢复、删除时清除 | 规则 + 服务端 + 测试 |
| 8 | **控制台「发现」页**：搜索框 + 公开分类过滤 + 结果卡片（含公开分类与 `#公开标签`）+ 加入动作；首次进入是「搜索框 + 分类入口 + **为你推荐**」——推荐是**一段按更新时间倒序的流**（游标分页，一批 6 张，滚到底取下一批，规则见 §展示与计数口径），**接口一次只返回一批，不是全量目录**；**空态保留搜索框与分类选择器**；卡片区分「未加入 / 加入中 / 已在库（显示来源）/ 加入失败」，失败可原地重试 | 控制台（新页面） |
| 9 | **控制台「我的 skill」= 库**：页面标题保持「我的 skill」；侧栏 SKILL 组的库入口叫「我的 skill」，与页面标题一致。来源是**行内标签**（我创建的 / 共享给我的 / 我加入的），不是第三个页签；「在用 / 已删除」两份页签保留，「已删除」只含我创建的软删除 skill，共享/加入没有已删除态，且 `show=deleted` 时隐藏标签筛选并从地址去掉 `tag` / `my-tag` / `public-tag`；**库本身为空 → 库空态（新建 + 去发现），不画页签（沿用现状）；库非空但没有已删除 skill → 页签保留、已删除列表显示空态**。作者管理（草稿、版本）仍在；公开未加入的不出现。行内只有行名链接（打开这个 skill）与来源 / 状态章，不另画按钮；作者管理在打开后的页面里，打开后能做什么由档位决定；我创建的与 `write` 及以上共享的行显示「已下线」；移除在信息页或 CLI（`skill leave`）；已删除行只有「恢复」，CLI 用 `skill restore`。**本版不显示调用次数、不提供「调用最多」排序**——产品今天没有这个数据；排序只有最近更新 / 名字，默认最近更新；排序项「名称」改为「名字」。空库空态同时给「新建 skill」与「去发现公开 skill」 | 控制台（列表页） |
| 10 | **控制台信息页**：三组词按**分类 → 公开标签 → 我的标签**排。公开分类与公开标签所有能看见该 skill 的人可见、所有者/管理可编辑（公开标签每 skill ≤10、显示成 `#名字`）；我的标签**只有库条目生效的 skill 才有这一区**、本人可编辑；条目休眠时这一区不显示。按钮矩阵：不在库 →「加入」；我加入的 →「移除」；共享给我的 → **不显示加入/移除**；我创建的 → **不显示加入/移除**；可见但当前不可加入（下线 / 无当前版本）→ 不显示「加入」，说明原因。加入是独立于「申请更高档位」的动作，位置由设计定但必须与申请块分开。0 个公开分类或公开标签时只读视图不画空块、所有者/管理始终有编辑入口；0 个我的标签时只读视图不画、本人有添加入口；非库 skill 不画我的标签区。**三组词都就地编辑，不开弹窗**（2026-10-22 定）：分组标题右边只有一颗「+」。公开分类是固定词表、**单选** → 点「+」开**单选菜单**（10 个词、公域计数、停用的置灰不可新增；点一个就换掉原来那个并关上菜单，已选分类时菜单里另有一行「清除」；再点已选中的那个不会拿掉）；公开标签与我的标签都是自由标签 → 点「+」后**输入框排在最后一颗标签右边、与标签同高**（一颗可以打字的胶囊），聚焦时下面浮出候选下拉（全部还没贴上的标签，打字就筛，选中即贴）；打一个没有的名字回车即新建（精确命中已有词则贴上），1–24 字、重名与撞公开分类给可读错误；公开标签每 skill 最多 10 个、我的标签最多 20 个；胶囊带「×」；**焦点离开这一组就回到普通状态**（用「×」删一颗不算，焦点留在输入框里），也可以点那颗已变成「✓」的按钮收工。**筛选仍然是多选**（可以同时看几个货架）；**分类本身的编辑是单选**。现有 `#infoTags` 槽位只承接**公开分类的只读胶囊**；三组词的分组标题与这三套就地编辑器是设计新增 | 控制台（信息页） |
| 11 | **控制台「标签」页**：路由 `/my-tags`，侧栏「管理」下面的一项（二级）；**页头两个页签**——`我的标签`（默认，下面这份可编辑清单）与 `公开标签`（只读：我在自己创建的、生效中的 skill 上用过的词，名字、用在 N 个 skill 上、去那些 skill 的链接；没有新建/改名/删除，贴与摘在信息页或 CLI）；页名与侧栏仍叫「标签」；**清单本身点得动**（2026-10-22 定）：页头一个搜索框按**名字与说明**筛、「用在 N 个 skill 上」是去库里筛这些 skill 的链接、点名字**就地改名**（回车保存，Esc 或失焦取消，错误落在那一行）、**名字右边同一行常显一句说明**（2026-10-22 加，住在名字与计数之间那段空白里，空时是「加一句说明」；窄到 720px 以下（含网页缩放）才落到名字下面那一行）——点说明就地写（回车保存，Esc 或失焦取消，≤200 字、可以留空、可再清空）、**新建是清单最上面的一行小表单**（名字 + 说明 + `取消` / `新建` 同一条线；名字空着时 `新建` 不可点；名字回车落到说明，说明回车收下；收下后清空、焦点回到名字，可以接着打下一个；焦点离开整块才收起）、**删除仍是红色危险弹窗**（写清 N 个可见 + M 个你现在看不到的也会一起删除）；六态完整：正常有标签 / 空（0 个定义）/ 加载中 / 加载失败 / 只有休眠（0 个生效，文案写成用户能懂的话）/ 达到 100 个（新建禁用并说明）；公开标签那一份有自己的搜索（按名字）、空态（「还没有公开标签。在你创建的 skill 的信息页贴上一个，它会出现在这里。」）与无匹配态（「没有匹配的公开标签。换个词试试。」）；读不到数据时不画页签 | 控制台（新页面） |

### 公开分类词表

**这是产品词表，不是实现细节。** 词表是**平级 10 个词、每个 skill 只贴一个**（2026-10-23 改）：分类是一个「货架」，粗、稳定、单选；召回交给公开标签。调研过的平台都在往这个方向收——B 站 2025 年取消了二级分区，抖音的分类在用户端不可见，小红书与 TikTok 由平台自动归类；保留分类的（B 站一级分区、YouTube、ClawHub）也都是单选。所以这里**不预留层级**：以后真要加层，那是重新决定的一件事。控制台选择器与 CLI `skills categories` 看到的就是下面这 10 个词。**界面上的名字只有两个字：「分类」**——这一层只有一种（平台的词表），限定语不重复；公开标签与我的标签各自带着限定语（2026-10-23 改）。`admin` 档在界面上写「管理」。

| # | 词 | 覆盖什么 | 不覆盖什么 |
|---|---|---|---|
| 1 | 文档与演示 | 读写、转换、排版、提取 PDF / Office / Markdown / 演示文稿 | 纯文字创作（见「写作与翻译」） |
| 2 | 数据与分析 | 取数、清洗、统计、图表、报表、SQL | 工程测试数据 |
| 3 | 研发与测试 | 编码、重构、代码审查、测试、调试、构建 | 部署与线上运维 |
| 4 | 设计与界面 | 视觉、交互、设计系统、前端界面实现 | 后端与基础设施 |
| 5 | 写作与翻译 | 文案、改写、校对、翻译 | 文档格式转换 |
| 6 | 研究与检索 | 网络检索、资料整理、综述、事实核查 | 数据统计 |
| 7 | 办公与协作 | 日历、邮件、会议、任务与项目管理 | 文档生成；这里的「协作」不指协作者 / 共享 |
| 8 | 运维与云 | 部署、容器、监控、云资源、CI/CD | 应用代码开发 |
| 9 | 图像与音视频 | 生成、编辑、转码、识别 | 设计稿与界面实现 |
| 10 | 安全与合规 | 安全审计、漏洞、隐私、合规检查 | 一般运维 |

**词表规则**：

- **层级**：**平级，没有父子**。多级分类明确不做（不做 #24）：B 站 2025 年取消了二级分区，而 SkillMaster 没有分类树页面，加层没有收益。
- **数量与稳定**：本版 10 个（首日种子；停用/退役后可见数量会变）。增删改只由平台在迁移里做。
- **每个 skill 只贴一个**：可以是 0 个；词表外的词、停用的词不能被新增；再选一个会**替换**原来的，不是追加。
- **筛选**：可以同时选几个货架——公域取「或」（放宽），库里与我的标签组合取「且」。
- **命名**：名词短语，2–6 个汉字；不出现版本号、品牌名、客户名；**词表里唯一**。
- **能看见 / 库条目生效**：两个谓词的定义见 §两个谓词；词表规则不重复。
- **停用 / 退役**：语义见 §库与标签的生命周期；本版只由迁移 / IT 造状态。停用写在词上。**选择器显示全部启用与停用的首日种子词（停用置灰、不可新增，已有贴法可换可筛）；退役的词从选择器与 `skills categories` 里消失，不可筛。退役的词名继续占用**，不释放给私人标签。
- **新增一个词的前置**：不得与任何现存我的标签重名，也不得与词表里任何一个词重名；撞名时**迁移拒绝这个词**，由平台另选——要求用户改名比平台换一个词更糟。
- **存量不回填**：首日所有 skill 都是 0 个分类，没有任何自动归类；选择器仍显示全部启用与停用的首日种子词（计数可以是 0），位置稳定。
- **一种语言**：词表是中文，控制台与 CLI 共用同一组词；不做翻译与同义词（不做 #12）。

## 公开标签（本版做最小闭环）

**三样东西各干各的**（2026-10-23 定）：**分类**是平台收拢的窄词表，负责「这一屏归在哪」；**公开标签**是作者给 skill 贴的自由词，公开可见，负责**搜索的召回**（这一版的推荐仍是「最近更新」的固定规则，算法落地后也会用它；抖音、B 站、GitHub Topics 都是这一层）；**我的标签**是本人私有、用来整理自己的库。2026-10-23 产品负责人决定**本版就做最小闭环**；设计稿已按这一形状画好。

| | 分类 | 公开标签 | 我的标签 |
|---|---|---|---|
| 谁产生 | 平台词表 | **作者**（所有者与 `admin`） | 本人 |
| 谁看得见 | 能看见该 skill 的人 | **所有人** | **只有本人** |
| 用途 | 归类、导航 | **搜索召回**（推荐以后可用） | 整理自己的库 |
| 数量 | 每 skill 1 个（可以没有） | 每 skill ≤10 | 每 skill ≤20 / 每账号 ≤100 |
| 词表 | 平台维护（10 个平级词） | 自由词，1–24 字 | 自由词，1–24 字 |

**本版做的（最小闭环）：**

- **名字只有一个**：**公开标签**。界面、文档、CLI 都用这一个词——不叫话题、不叫主题，也不叫关键词。作者的这一层叫「公开标签」，本人的那一层叫「我的标签」。**界面上写成 `#名字`**（卡片、信息页、管理页）；搜索、文档与 CLI 里写名字本身。
- **数据**：`skill_public_tag(skill_id, tag_key, tag_name)`。`tag_key` = NFKC 归一 → 去首尾空格 → 内部连续空格压成一个 → 小写；`tag_name` = 作者写的那一串。`(skill_id, tag_key)` 唯一；每 skill ≤10；不得与公开分类重名。公开可读；所有者与 `admin` 可增删；增删写审计。**没有独立的标签定义表**——一行就是「这个 skill 上有这个词」，所以没有「改名一条定义」这回事。
- **检索**：`q` 命中 `tag_name`；`skills search --public-tag <名字>`、`skills list --public-tag`（可重复，取「且」）；`skills public-tags` 列出词与公域计数。过滤在 SQL 的访问谓词内，不做结果后过滤。**分类过滤用 `--category`**（v14 新增；v13 没有分类参数）。
- **界面**：信息页右栏在「分类」与「我的标签」之间多一组「公开标签」（作者可贴与摘，其他人只读；0 个时只读视图不画、作者视图说「还没有」）；结果卡片上多一行 `#名字`；管理页变成两个页签——`我的标签` 与 `公开标签`（**我在自己创建的、生效中的 skill 上用过的词**：名字、「用在 N 个 skill 上」、去那些 skill 的入口；**只读**，贴与摘在信息页或 CLI）；库的 `public-tag` 筛选只由管理页那条计数链接带进来，筛选条上没有这一项。
- **立即生效**：贴 / 摘不产生版本、不动 `current_version_id`。
- **已知限制（如实记）**：只做名字归一，不做同义词合并——`PDF` 与 `pdf` 是同一个词，`PDF处理` 与 `PDF` 是两个词。作者在输入框里能看到已有的词，靠这个收敛写法。

**不做与理由：** 同义词合并、改名 / 合并、审核、全局标签页（不做 #25、#27）——它们是用户生成内容的治理，需要独立的信号与运营；本版先把「贴、摘、搜到」跑通。

**两种标签并存之后，限定语重新必要**（2026-10-23）：信息页那一组、库的筛选与管理页的页签写「我的标签」；**侧栏的「管理 › 标签」与那一页的标题仍是「标签」**——那是一页管两份清单的页面名。公开标签那一层叫「公开标签」，不叫话题、不叫主题、也不叫关键词；界面上写成 `#名字`。这与 2026-10-22「标签只有一种，所以去掉限定语」的决定不冲突，因为那时确实只有一种。

## CLI 命令面（2026-10-23 锁定）

**两组，各管各的。** `skills` 管多个 skill / 词表，写的是 `skills my-tags add` / `rename` / `describe`（定义的新建、改名、改说明）；`skill` 管一个 skill：读 / 写它的标签，加入 / 移除库。**定义的删除仍在控制台**：我的标签的删除，CLI 没有（不做 #8）。

### `skills`：词表与检索

| 命令 | 作用 | 输出 |
|---|---|---|
| `skills categories` | 公开分类词表（平级 10 个词；启用 + 停用，退役不列） | Markdown 表格，两列 `分类` / `公域`；按词表顺序；停用的词在名字后标 `（停用）`；计数是**公域里可发现**的 skill 数，0 也列 |
| `skills public-tags [q] [--all]` | 公开标签词表 | Markdown 表格，两列 `公开标签` / `公域`；按计数降序、同数按名字；计数口径同 `skills categories`；默认 50 行 + “还有更多”，`--all` 取全；`[q]` 按名字筛 |
| `skills my-tags [q]` | 我的标签 | Markdown 表格，三列 `标签` / `用在` / `说明`；按计数降序、同数按名字；`用在` 写 `N 个 skill 上`（N 只算**生效中的贴法**）；说明为空时该格留空；`[q]` 按名字 / 说明筛；≤100 一次给全 |
| `skills my-tags add <名字> [--describe <说明>]` | 新建一个我的标签定义（**不贴 skill**） | stdout 一句人话；本人；名字 1–24 字、同一用户唯一、不撞公开分类；说明选填 ≤200 字；账号 ≤100 个定义；不删除；改名 / 改说明见下两行 |
| `skills my-tags rename <旧名> --name <新名>` | 给一个我的标签定义改名 | stdout 一句人话；本人；所有贴法跟着变、计数不变；旧名在 CLI 里失效；名字规则同新建；重名 / 撞分类拒绝；没有 `--yes` |
| `skills my-tags describe <名字> --text <说明>` | 写 / 改 / 清空一个我的标签定义的说明 | stdout 一句人话；本人；≤200 字，空串清空；不动名字、计数与贴法；没有 `--yes` |

三条命令的输出形状（示例）：

```markdown
$ skills categories
| 分类 | 公域 |
|---|---|
| 文档与演示 | 12 |
| 数据与分析 | 9 |
| 运维与云（停用） | 0 |

$ skills public-tags
| 公开标签 | 公域 |
|---|---|
| pdf | 7 |
| 批量处理 | 4 |

$ skills my-tags
| 标签 | 用在 | 说明 |
|---|---|---|
| 客户项目 | 6 个 skill 上 | 交付期内客户随时要用的 skill |
| n8n | 1 个 skill 上 |  |
```

`skills my-tags add` 成功时一句人话，例如「已新建标签「客户项目」，并写了说明。」；`rename` 说「已改名：「旧名」→「新名」。」；`describe` 说「已更新「X」的说明。」（清空时说「已清空「X」的说明。」）。

- **列头就是口径**：`公域` 与 `用在` 不解释成别的意思；`（停用）` 是状态，不是名字的一部分。
- **参数取名字本身**：`--category` 不带 `（停用）` 后缀（停用的名字仍可筛，已有贴法可换可筛）；`--public-tag` 不带 `#`（界面上才写 `#名字`）。
- **一次给全 vs 截断**：`skills categories`（10 个）与 `skills my-tags`（≤100）一次给全；`skills public-tags` 默认 50 行，截断时 stdout 说“还有更多，用 `--all` 取全”，`--all` 取全；都不返回游标；一个词一行；0 个词时仍画表头（空集合不是错误）。
- **搜索**：`skills public-tags [q]` 按名字筛；`skills my-tags [q]` 按名字或说明筛；无命中时画表头 + 一句「没有匹配的公开标签 / 标签。换个词试试。」
- **来源筛选**：`skills list` 新增 `--source created|shared|joined`，可重复取「或」，按**显示来源**（我创建的 > 共享给我的 > 我加入的）筛；默认全部。`skills search` 没有这个参数（公域没有库来源）。
- **列表视图**：`skills list --sort recent|name`（默认最近更新）；`--show live|draft|offline|deleted|all`（默认 `live` 可消费；`all` = 在用（live + draft + offline），不含已删除；`deleted` 只含我创建的、并拒绝 `--category` / `--my-tag` / `--public-tag`，与网页「已删除」页签一致；`--show deleted` 时 `--source` 只接受 `created` 或省略，其它值给空结果 + 提示；其余情况下的非法值一律拒绝，见 #45）。`skills search` 没有 `--show` / `--sort`（公域检索只有相关度）。
- **`--verbose`**：`skills list --verbose` 与 `skills search --verbose`；**默认卡片不变**，每张卡多一行 `来源 · 状态 · 版本 · 更新时间 · 分类 · 公开标签`；`--show deleted` 时「更新时间」那一项写「删除于」而不是「更新于」；搜索结果的来源只在该结果已在库时出现；不打印我的标签。
- **新建定义**：`skills my-tags add` 只新建定义，不贴 skill；要贴用 `skill tag add`；名字已有定义时拒绝（不静默返回旧的）；新建后 `用在` 是 0。
- **说明是给 agent 选标签的那一句**：原样输出；说明里的 `|` 转义成 `\|`，换行压成空格。
- `skills list` / `skills search` **仍是 v13 的卡片格式**（第一行地址，第二行描述与适用场景），不改成 Markdown 表格——那是网关依赖的稳定契约。
- 未知名字：`--category` / `--my-tag` / `--public-tag` 给空结果 + 一句可读提示，分别指向 `skills categories` / `skills my-tags` / `skills public-tags`。

### `skill`：一个 skill 的标签与库

| 命令 | 作用 | 权限与语义 |
|---|---|---|
| `skill tags <地址>` | 读三组词 | 分类与公开标签：能看见这个 skill 的人都能读；我的标签：只有**库条目生效**的调用者能读 |
| `skill tag add <地址> <名字> [--public]` | 贴一个标签；默认我的标签 | 我的标签：本人 + 库条目生效；公开标签：所有者 / 管理；归一化后已存在是 no-op |
| `skill tag remove <地址> <名字> [--public]` | 摘一个标签 | 同上；要摘的标签不在这个 skill 上是可读错误 |
| `skill category set <地址> <名字>` | 放到一个分类（替换原来的） | 所有者 / 管理；新设只能取启用词；同一个词是 no-op |
| `skill category clear <地址>` | 清除分类 | 所有者 / 管理；本来没有分类是 no-op |
| `skill join <地址>` | 把公开 skill 收进我的库（**引用**） | 满足 #3 的条件；已有加入引用（含休眠）是 no-op；来源是创建 / 共享时拒绝；**没有 `--yes` 只打印后果与完整命令、不执行** |
| `skill leave <地址>` | 把「我加入的」移出库 | 只对显示来源为「我加入的」且条目生效；标签休眠、重新加入后回来；**没有 `--yes` 只打印后果与完整命令、不执行** |
| `skill show <地址>` | 读完整信息（描述 / 适用场景 / 环境 / 版本 / 分类 / 公开标签 / 我的标签） | 能看见这个 skill 就能读；我的标签只在库条目生效时出现；空字段不打印 |
| `skill restore <地址>` | 恢复一个软删除的 skill | 所有者；只对已删除的 skill；可逆；无 `--yes` |

**地址**：所有 `skill` 命令用 `<命名空间>/<名字>`，不接受版本钉。

**`skill tags` 的输出**：Markdown 表格，两列 `组` / `名字`，一个词一行；顺序是分类 → 公开标签（按名字，与 `skills public-tags` 同一口径）→ 我的标签（按名字，与 `skills my-tags` 同一口径）。CLI 里名字不带 `#`；名字里的 `|` 转义成 `\|`；一次给全、不返回游标；拒绝 `--json`。

```markdown
$ skill tags dev/pdf-tools
| 组 | 名字 |
|---|---|
| 分类 | 文档与演示 |
| 公开标签 | pdf |
| 公开标签 | 批量处理 |
| 我的标签 | 客户项目 |
```

我的标签那一组读不到时（不在库 / 条目休眠），表后一句说明原因，不画那一组；0 个词时只有表头，表后一句「这个 skill 还没有分类或标签。」（我的标签不可读时换成它自己的原因）。

**`skill show` 的输出**：一张小卡片，**第一行是地址**，字段按 **描述 / 适用场景 / 运行环境 / 版本 / 分类 / 公开标签 / 我的标签** 排；空字段不打印；我的标签不可读时写一行原因。`skill show` 接受 `--no-login`，不接受版本钉，拒绝 `--json`。

```markdown
$ skill show dev/pdf-tools
dev/pdf-tools
  把 PDF 拆页、合并与压缩。
  适用场景：需要拆分、合并或压缩 PDF 时。
  运行环境：需要 Python 3.10+ 与 poppler。
  版本：1.2.3
  分类：文档与演示
  公开标签：pdf、批量处理
  我的标签：客户项目
```

**写命令的共同规则**：

- **“修改”就是换词**：分类用 `set` 替换；标签先 `remove` 再 `add`。**标签定义本身**的改名用 `skills my-tags rename`，改说明用 `skills my-tags describe`；删除仍只在控制台。
- **我的标签**：名字 1–24 字，按用户的规范化名字唯一，不得与公开分类重名；每 skill 最多 20 个生效贴法、每账号最多 100 个定义；`add` 一个没有的名字会新建定义（**没有说明**；要新建时写说明，先用 `skills my-tags add --describe`，或事后在控制台补），名字已有定义但没贴在这个 skill 上就贴上；`remove` 只解除这个 skill 上的贴法，定义与说明保留。
- **公开标签**：名字 1–24 字，NFKC + 去首尾空格 + 压缩连续空格 + 小写后唯一；每 skill ≤10；不得与公开分类重名；没有定义表，`remove` 只解除这个 skill 上的贴法，没有“定义”可删。
- **分类**：一个 skill 只有一个；`set` 是替换，不是追加；**新设只能取启用的词**；已经贴着的停用词可以保留，`set` 同一个停用词是 no-op，换走或清除都可以；退役的词不在词表里，拒绝。
- **匹配按规范化名字**：`add` / `remove` 的写法与已贴的写法不同、但归一化后相同，视为同一个词；不会改掉原来的写法。
- **立即生效**：不产生版本、不动 `current_version_id`；审计沿用 #32（**我的标签的审计不存名字**）。
- **成功**：stdout 一句人话（我的标签贴：「已把「客户项目」贴到 `dev/pdf-tools`。」；摘：「已从 `dev/pdf-tools` 摘掉「客户项目」。」；公开标签带上「公开标签」；分类：「已把 `dev/pdf-tools` 放到「文档与演示」。」；清除：「已清除 `dev/pdf-tools` 的分类。」；no-op 时说「已经贴过」/「已经是这个分类」/「本来就没有分类」）；**没有 `--yes`**（贴 / 摘一个 skill 上的标签是可逆的）；**拒绝 `--json`**。
- **错误**：400（名字 / 上限 / 词表外 / 停用词 / 带 `#`）、401、403（权限或库归属）、404（看不见的 skill / 要摘的标签不在这个 skill 上）、409（库条目休眠）；stderr 一句人话 + 下一步，stdout 为空，非 0。
- **加入 / 移除库**：`skill join` 是引用，不复制、不产生版本、不改变访问权；`skill leave` 只删“我加入的”引用，标签休眠、重新加入后回来；已有加入引用（含休眠）是 no-op「已经在你的库里。」；来源是创建 / 共享（没有加入引用）时按 #3 拒绝并说明（409）；不可见 / 非公开 404；可见但当前不可加入 409。**两条都要求 `--yes`**：没有它时只打印后果与完整命令，不执行；有它才执行。成功：join「已把 `X` 收进你的库。」；leave「已把 `X` 移出你的库。」
- **新建定义**：`skills my-tags add` 只新建定义（不贴 skill），没有 `--yes`；名字已有定义时拒绝，指引用 `skill tag add` 贴；新建后 `用在` 是 0。
- **定义改名 / 改说明**：`skills my-tags rename <旧名> --name <新名>` 让所有贴过它的 skill 一起显示新名字，计数不变，旧名在 CLI 的 `--my-tag` 里失效（网页链接用 id，不受影响）；重名或撞公开分类拒绝，不做合并。`skills my-tags describe <名字> --text <说明>` 写说明，空串清空；不动名字、计数与贴法。两者都没有 `--yes`，写审计（**不存名字**），不产生版本。
- **定义删除不在 CLI**：`skills my-tags delete` 仍只在控制台（会摘掉所有 skill 上的贴法，含休眠的，不能恢复）。
- **恢复**：`skill restore` 只对软删除的 skill，所有者可执行；恢复后回到库 / 作者视图，休眠的我的标签回来；不是已删除的给可读错误；没有 `--yes`；写审计；拒绝 `--json`。

**共同点**：七个读命令（`skills list` / `skills search` / `skills categories` / `skills public-tags` / `skills my-tags` / `skill tags` / `skill show`）都接受 `--no-login`；所有新命令（三条词表、`skills my-tags add` / `rename` / `describe`、`skill tags` / `tag` / `category` / `join` / `leave` / `show` / `restore`）拒绝 `--json`。`skill join` / `leave` 要求 `--yes`；其余写命令缺凭据时按 v13 的业务命令自动登录。

## 库与标签的生命周期

**三个对象，不能混用**：

- **库条目**——「我的库」里的一行。来源有三种：我创建的、共享给我的、我加入的。
- **标签定义**——那个词本身（“文档与演示”“客户项目”）。公开分类与我的标签有定义与主人（平台 / 某个人）；**公开标签没有独立的定义表**——一行就是「这个 skill 上有这个词」，所以没有改名/合并一条定义这回事。
- **贴法**——这个词贴在哪个 skill 上。我的标签的贴法还要记住“是谁贴的”。

### 两个谓词，不能混用

- **能看见**（用于公开分类与信息页）：**（我创建的 ∨ 有显式授权 ∨ 公开）且未删除**。下线仍算能看见（作者面可见，消费面调用返回 503）；软删除后不再能看见——**作者面的「已删除」列表是作者视图，不算“能看见”，那一行不可打开**。公开但没有当前版本的 skill 能看见地址，**消费面（API）详情打不开**，但**控制台信息页仍可打开**，用来显示不可加入的原因；它不进公域检索。
- **库条目生效**（用于我的标签是否生效）：
  - **我创建的**：未软删除。下线仍生效，列表显示「已下线」。
  - **共享给我的、`write` 及以上**：未软删除。下线仍生效，列表显示「已下线」。
  - **共享给我的、`browse` / `invoke`**：有授权 ∧ 未下线 ∧ 未删除 ∧ 有当前版本。
  - **我加入的**：引用存在 ∧ 可读（未下线 ∧ 未删除 ∧ 有当前版本）。
- **我的标签只在库条目生效时生效**；条目休眠，标签休眠，信息页**不显示这一区**。

### 库条目

| 来源 | 何时在库里 | 能不能移除 |
|---|---|---|
| **我创建的** | 始终；下线仍在「在用」并显示「已下线」；软删除后进作者面「已删除」页签 | 不能（删除是另一件事） |
| **共享给我的** | 有任何档位的授权时；授权撤销后这条来源就消失。`write` 及以上下线仍在库并显示「已下线」；`browse` / `invoke` 失去可消费性（下线 / 软删除 / 没有当前版本）则休眠 | 不能（那是别人的 skill） |
| **我加入的** | 我显式加入后；失去可消费性（下线 / 软删除 / 没有当前版本）时休眠；我移除后引用消失 | 能 |

**没有当前版本与下线、软删除一样，按休眠处理**（它与「能看见」不是一回事：地址仍能看见，但消费不了）。

**加入条目的状态**：

| 状态 | 含义 |
|---|---|
| **生效** | 满足上面「库条目生效」的谓词 |
| **休眠** | 库条目不生效，隐藏但引用保留；恢复可见后回来 |
| **已移除** | 不是状态，是动作结果：引用删除、不留墓碑；我的标签按 (人, skill) 保留并休眠 |

**核心规则**：

1. **库是私域。** 只有本人看得见自己的库，包括所有者与 `admin` 都看不到别人的库。
2. **加入是引用。** 不复制内容、不产生版本、不改变访问权、不挡加载；作者发新版，库里跟新版。
3. **加入不是授权。** 移除一条加入的 skill，不会改变我对它的访问权；它仍然可能在公域里被搜到、被调用。
4. **共享来源是派生的。** 有授权就在库里，撤销就不在；不额外存一行，也不需要“移除共享”。
5. **下线 / 软删除 / 撤销共享，分来源说。** 下线时：我加入的与 `browse` / `invoke` 共享的条目休眠；我创建的与 `write` 及以上共享的留在「在用」并显示「已下线」。软删除时：我创建的进作者面「已删除」，其余休眠。撤销共享时：共享来源直接消失；若还有加入引用且 skill 仍可读，条目留下（来源变我加入的），**我的标签继续生效**；否则条目离开库，我的标签休眠。
6. **公开但未加入的不在库里。** 它只在公域检索里出现；要让它进库，必须显式加入。
7. **显示来源与能不能移除是两件事。** 来源按“我创建的 > 共享给我的 > 我加入的”显示；移除入口只在**没有更高来源、且加入引用存在**时出现。加入过、后来又被授权的 skill 显示为“共享给我的”，移除入口隐藏，但加入引用仍在——授权撤掉且 skill 仍公开时，它会重新成为“我加入的”。
8. **“已删除”不是库的状态。** 它是我创建的 skill 的作者面视图；软删除的 skill 不在生效库里，我的标签在它上面休眠，恢复后回来。

### 标签定义与贴法

#### 状态

| 对象 | 状态 | 含义 |
|---|---|---|
| 公开分类（标签定义） | **启用** | 在平台词表里，可以往 skill 上加 |
| | **停用** | 不能再新增；已有的贴法保留，仍可筛、仍可摘；选择器里置灰 |
| | **退役** | 从所有 skill 上摘除，不再出现、不可筛；终点 |
| 我的标签（标签定义） | **可用** | 在个人的标签库里，可以往库里的 skill 上贴；0 次也还在，直到本人删掉；改名是原地改，不是新状态 |
| | **已删除** | 名字可以重新用；旧记录留在审计里；终点 |
| 公开分类的贴法 | **生效** | skill 上有这个分类，所有能看见该 skill 的人都看得到 |
| | **已摘除** | 被所有者/管理员拿掉 |
| 我的标签的贴法 | **生效** | 对应的库条目生效；标签出现在本人的列表、计数与筛选里 |
| | **休眠** | 库条目不生效（休眠或被移除）；标签不丢，只是不显示、不计数；恢复可见/重新加入后自动回来 |
| | **已摘除** | 本人把它从这个 skill 上拿掉 |
| | **已清除** | 标签定义被删除时连带清除；skill 若未来出现永久删除，也走清除 |

#### 核心规则

1. **我的标签只属于库。** 只有库里的 skill（我创建的、共享给我的、我加入的）能贴我的标签；公开但未加入的 skill 不能在它上面建我的标签。
2. **范围出生即定，永不改变。** 我的标签一辈子是私人的；公开分类只能由平台创建。**不存在“把我的标签改成公开”这个动作**。
3. **skill 变公开，不会让任何人的我的标签变公开。** 变的只是公开分类的可见范围：skill 公开后，公开分类才进入公域搜索；我的标签仍然只有贴的人看得到。
4. **改名不是新建。** 同一个标签 id，所有贴过的地方一起变；筛选、计数、链接都跟着走。
5. **删除是连坐的。** 删掉一个我的标签，它在所有 skill 上的贴法（含休眠的）一起消失；删之前说清影响：**N 个当前生效的贴法，另有 M 个当前不生效的贴法也会一起清除**。
6. **同一个名字不能两用。** 我的标签与公开标签都不能和公开分类重名，避免列表里出现两个“文档与演示”。改名撞名先拒绝；公开标签之间的同义词合并以后再说（不做 #25）。
7. **公开分类的停用和退役是平台动作。** 停用＝不再接受新的贴法，已有的还在；退役＝从所有 skill 上摘掉。这一版没有界面，只由迁移 / IT 造状态。
8. **公开标签只有贴与摘。** 它出生即公开，没有定义表、也没有“转成私有”这回事；贴与摘立即生效、不产生版本。skill 下线或删除时，标签跟着 skill 一起离开公域检索，但数据还在（恢复后回来）。

#### 事件表

| 发生了什么 | 库条目 | 公开分类 | 我的标签 |
|---|---|---|---|
| 作者发新版 | 不变；引用跟到新版 | 不变 | 不变 |
| 我加入一个公开 skill | 新增一行（来源：我加入的） | 不变 | 原先休眠的我的标签恢复 |
| 我移除一个加入的 skill | 引用消失 | 不变 | 进入休眠，不丢；重新加入后回来 |
| skill 从私有变公开 | 共享/我创建的条目不变 | 进入公域搜索 | 不变 |
| skill 从公开变私有 | 我加入的条目：没有授权则休眠；有授权则留下（来源变共享给我的） | 退出公域搜索；能看的人仍看得到 | 跟着库条目休眠/保留 |
| 别人撤销对我的共享 | 共享来源消失；若 skill 仍公开且我加入过，条目留下（来源变我加入的）；否则条目离开库 | 不变 | 条目留下 → 继续生效；条目离开 → 休眠 |
| skill 下线 | 我创建的与 `write` 及以上共享的留在「在用」并显示「已下线」；`browse` / `invoke` 共享的与我加入的休眠 | 退出公域检索；能看的人仍看得到 | 条目生效的继续生效；条目休眠的继续休眠 |
| skill 软删除 | 我创建的进作者面「已删除」；共享/加入的条目休眠 | 对所有读路径不可见 | 休眠，恢复后回来 |
| 我删掉一个我的标签 | 不变 | 不受影响 | 所有 skill 上一起摘掉（含休眠） |
| 平台停用一个公开分类 | 不变 | 不能再新加，已有的还在，仍可摘 | 不受影响 |
| 平台退役一个公开分类 | 不变 | 从所有 skill 上摘掉 | 不受影响 |

| 来源标签 | 界面只用三个词：**我创建的 / 共享给我的 / 我加入的**。来源按“我创建的 > 共享给我的 > 我加入的”取一个显示。 |
| 排序 | 库列表只有**最近更新 / 名字**两种，默认最近更新；**不显示调用次数、不提供「调用最多」**（产品今天没有这个数据）。公域检索按相关度（同分按更新时间）。公开分类按词表顺序；管理页与 `skills public-tags` 的公开标签清单按计数降序、同数按名字；我的标签按计数降序、同数按名字。**「用在 N 个 skill 上」的 N 只算生效中的贴法**（与 20 的口径相同）。 |
| 为你推荐 | 「发现」第一次进入的那一段流：**公开、有当前版本、未下线、未删除、不在我库里**，按更新时间倒序，**游标分页、一批 6 张**；**六张铺不满一屏时首屏自动补齐下一批**，往下滑到底再取下一批——**没有「加载更多」按钮，滑动就是唯一的取数手势**（2026-10-22 定）。接口一次只返回一批，**不是全量目录**，也没有排序参数；推荐的理由必须说得出来。**推荐算法（个性化 / 协同 / 向量）不在本版**——换的时候只换这一段背后的排序，位置与卡片不动。 |
| 空态 | **库为空 = 没有任何条目（含休眠）** → 库空态，同时给「新建 skill」与「去发现公开 skill」，不画页签；**有条目但全部休眠** → 在用列表空态，页签保留，文案：「这里暂时没有能显示的 skill。它们可能已下线或暂时不可见，恢复后会回来。」；**库非空但没有已删除 skill** → 页签保留、已删除列表空态。**发现页首次进入 = 搜索框 + 分类入口 + 为你推荐（有界）**，没有结果区；推荐段一条都不剩时说「没有可推荐的了。用上面的搜索或分类继续找」；取到最后一批时推荐段末尾说「没有更多了。用上面的搜索或分类继续找。」。标签页的「我的标签」那一份 0 个定义有独立空态（「还没有标签。新建一个，用来归类你库里的 skill；只有你看得到。」）、0 个生效时写清原因与去向（「这些标签对应的 skill 现在都看不到（可能已下线或暂时不可见）。skill 回来时，标签会重新出现。」）、加载失败给下一步（「无法加载你的标签，请稍后重试。」）、满 100 个说清上限与出路（「标签最多 100 个。删掉一个，才能新建。」）；公开标签那一份 0 个时说「还没有公开标签。在你创建的 skill 的信息页贴上一个，它会出现在这里。」，搜索无命中说「没有匹配的公开标签。换个词试试。」。**TD 的库查询要能区分「无条目」与「有休眠条目」**（返回总条目数 / 生效条目数），否则这三种空态无法区分。 |
| 确认文案 | 不把内部状态名念给用户，并且**先说后果**。删除我的标签（**红色危险弹窗**，标题「删除标签？」，确认按钮「确认删除标签」）：「删除后，这个标签会从 N 个你能看到的 skill 上移除，不能恢复；另有 M 个 skill 上的这个标签你现在看不到，也会一起删除。那些 skill 本身不会被删除。」（M 为 0 时只留前半句；**不写「名字可以重新使用」**——那是系统的性质，不是用户会失去的东西）移除加入的 skill（信息页；**普通弹窗，不染红**，标题「从我的 skill 移除？」，确认按钮「确认移除」；发现页书签的回退不弹窗）：「标签会保留，重新加入后会回来。这个 skill 仍在公域，仍可直接调用。」 |
| CLI 输出 | 卡片第一行是地址，第二行是描述与**适用场景**（`when_to_use` 的值；v13 §3 的稳定格式）；**第二行只在描述或适用场景非空时出现，两者都为空时只有地址一行**；默认不打印标签与来源，`--verbose` 多一行；词表与计数由 `skills categories` / `skills public-tags` / `skills my-tags` 给；**单个 skill 的完整信息由 `skill show` 给，三组词由 `skill tags` 给**，写命令的输出见 §CLI 命令面。 |
| 上限 | 每 skill 20 个我的标签（只算生效中的）；每账号 100 个定义（含只有休眠贴法的定义）；每 skill 10 个公开标签。 |
| 公开标签的计数 | **管理页**的「用在 N 个 skill 上」只算**我创建的、生效中的** skill（公开标签是作者的词，别人 skill 上的不归我管）；**CLI `skills public-tags`** 的公域计数算**公域里可发现**的 skill（公开、有当前版本、未下线、未删除）。两个口径不同，各自说清。`skills categories` 的 `公域` 列同 CLI 口径；`skills my-tags` 的 `用在` 列同管理页口径。 |

## 验收与指标

### 验收标准

| # | 验收标准 | 怎么判定 |
|---|---|---|
| 1 | **库的组成**：`skills list`（CLI）只列**可消费的库**——我创建的、任何档位共享给我的、我加入的，且已发布 / 未下线 / 未删除；公开但未加入、草稿、下线的不出现。控制台「我的 skill」是完整库（含草稿、下线、作者面「已删除」）。`--all` 取全；空库空态同时给「新建 skill」与「去发现公开 skill」 | 三账号矩阵：公开未加入 / 加入 / 移除 / 共享（invoke、browse、admin 各一）+ 草稿/下线条目只在控制台出现；逐条断言 + 空态断言 |
| 2 | **加入是引用**：不复制内容、不产生版本、不改变访问权；作者发新版后，库里的 skill 跟到新版；重复加入是幂等的 | 加入前后 DB（版本数、digest）+ 作者发新版后库内读到的版本 + 重复加入 |

| 7 | **库是私域**：另一个用户（包括所有者与 `admin`）看不到我的库；API、CLI、控制台都不泄露 | 两账号跨用户矩阵 |

- **内部前提**：
  - **七条新 ADR**：
    1. **公域 / 私域与我的库**：[0082](../../decisions/0082-public-and-private-with-my-library.md)：库是引用、不复制、不授权、不挡加载；`skills list` 默认列库；公域只搜不列。
    2. **两套标签**：[0083](../../decisions/0083-two-tag-layers.md)：公开分类与我的标签的范围、出生即定、只属于库、休眠与删除的取舍；并更正 [ADR 0077](../../decisions/0077-the-cli-grammar-is-singular-and-plural.md) 里 `tags` 的归属。
    3. **检索的 L1 扩展**：[0084](../../decisions/0084-l1-search-extension.md)：`when_to_use` 与多词匹配；`when_to_use` 是平台元数据（frontmatter），不是正文或文件，不违反“不索引正文/文件”的安全理由。
    4. **分类是一个货架**：[0078](../../decisions/0078-a-category-is-one-shelf.md)：平级、单选、不预留层级；召回交给公开标签。
    5. **CLI 管贴法、新建、定义编辑与库引用，不管删除**：[0079](../../decisions/0079-cli-manages-tags-and-library-references.md)：单个 skill 的贴 / 摘 / 换、`skills my-tags add` / `rename` / `describe`、`skill join` / `leave` 进 CLI；定义的删除留控制台。
    6. **CLI 覆盖所有非高风险操作**：[0080](../../decisions/0080-cli-covers-non-high-risk-operations.md)：可逆且不改可见性的操作进 CLI；推荐流不进 CLI（消费型页面流，不是解决问题）；v13 的页面动作另开一版评估。
    7. **每处控制台操作都要有 CLI 对应**：[0081](../../decisions/0081-every-console-operation-has-a-cli-command.md)：版本的 PRD 必须带一张「控制台操作 → CLI 命令」映射表；例外只有高风险与产品负责人逐条确认的，且要记进「不做」。
  - **v13 的 `version restore` 与本版的 `skill restore` 是两件事**：前者是作者面的版本重新上架（v13 仍只交接、不在 CLI 执行），后者恢复一个软删除的 skill（本版新增）。本版不改变 v13 的页面动作契约。
  - [ADR 0006](../../decisions/0006-search-server-side.md)：检索在服务端、只索引 L1、排序可解释可回归。它的 L1 枚举是 name + description + title；本版的 `when_to_use` 扩展见上面第 3 条 ADR。
  - [ADR 0002](../../decisions/0002-gateway-skill-and-cli.md)：网关 skill + CLI 是 agent 的入口；本版改第 1 步与检索。
  - **推荐段需要一条分批的读路径**：控制台首次进入要按游标一批批取「为你推荐」（一批 6 张，并告诉客户端还有没有下一批），而 `skills search` 必须有 `q`、公开分类或公开标签至少一个，拿不到这一段。具体形状（`GET /web/discover/recommended?cursor=`，或给检索加一个 `recommended` scope）由 TD 定；排序规则与批次口径见 §展示与计数口径。
  - [ADR 0047](../../decisions/0047-permissions-are-a-ladder.md) / [0048](../../decisions/0048-visibility-hands-out-a-rung.md)：公开分类的写权限沿用梯子；公开即被搜到、可直接调用——本版不改 0048 的访问语义。
  - [ADR 0034](../../decisions/0034-skill-level-sharing.md)：**skill 级共享（读可跨命名空间；命名空间成员关系仍未生效）**——共享来源与休眠规则依赖它。
  - [ADR 0053](../../decisions/0053-skill-metadata-is-its-own-module.md)：新的关联表落 M12（`skill` 所在模块）；**标签与库条目的表必须与 `skill` 同模块**，否则“标签过滤在 SQL 的访问谓词内”与“一条 SQL 不得点两个模块的表”会冲突。落别处需要新 ADR，由 TD 细化。
  - [ADR 0056](../../decisions/0056-dangerous-actions-are-confirmed-in-a-modal.md)：删除我的标签是红色危险弹窗；移除加入的 skill（入口在信息页；库的行内没有移除）是普通弹窗（不染红）；发现页书签的回退不弹窗。
  - [ADR 0031](../../decisions/0031-submitting-and-publishing-are-two-actions.md)：标签改完立即生效，不走提交/上线。
  - [ADR 0077](../../decisions/0077-the-cli-grammar-is-singular-and-plural.md)：集合侧命令进 `skills` 组；`discover` 只能作薄别名，本版不采用。
  - **v13 的 CLI 契约**（[`../v13-cli-grammar/prd.md`](../v13-cli-grammar/prd.md) §CLI 命令行为规范）：`skills list` / `skills search` 的新参数与 `skills categories` / `skills public-tags` / `skills my-tags` / `skills my-tags add` / `skills my-tags rename` / `skills my-tags describe` / `skill tags` / `skill tag` / `skill category` / `skill join` / `skill leave` / `skill show` / `skill restore` 要过 §1（分组）、§2（地址与例外）、§3（输出流与退出码）、§4（分页/一次给全）、§6（凭据与浏览器）、§7（帮助）、§9（新增命令检查清单）。**本版对 v13 契约有六处有意变更**：
    1. `skills list` 的**结果集**从「自己的 ∨ 授权 ∨ 公开，且已发布 / 未下线 / 未删除」改成「**可消费的库**：我创建的 / 共享给我的 / 我加入的，且已发布 / 未下线 / 未删除」——公开未加入不再出现，加入的公开开始出现。这是本版最大的行为变更。
    2. `skills list` 的默认页从 **100 收到 50**（v13 §4/验收 #14 钉的是 100）。
    3. `skills list` 新增 `q`（库内关键词）。
    4. `skills list` 新增 `--category` / `--my-tag` / `--public-tag` / `--source`（库内过滤）、`--sort` / `--show` / `--verbose`（排序、完整库视图、逐行字段）；`skills search` 新增 `--verbose`。
    5. `skills search` **收窄为只搜公域**；关键词从必填变为“q / 公开分类 / 公开标签至少一个”，新增 `--category` 与 `--public-tag`，不再接受 `--my-tag`（v13 里它本来也没有标签参数）。
    6. `skills list` / `skills search` **新增 `--no-login`**；默认行为不变（缺凭据仍自动登录，无浏览器时快速失败）。
  - [ADR 0075](../../decisions/0075-the-browser-client-is-react.md) / [0076](../../decisions/0076-the-design-file-is-react-source.md)：浏览器端是 React，设计稿源码也是 React——发现页与标签界面照设计源码搬。
- **产品口径**：界面名词、过滤地址、多选语义、排序、空态、确认文案、上限全部定在 §展示与计数口径，这里不复述；对 v13 契约的变更以上面六条为准。
- **排除了什么前置**：
  - **不需要向量库或新的检索服务**：这一版只加库、标签过滤与关键词增强。
  - **不需要开机钩子**：网关 skill 已能引导 agent 调用。
  - **不需要导入 SKILL.md 的 tags**：控制台是唯一入口，避免两个来源。
  - **不需要组织/团队模型**：库与标签都是“人 + skill”。
  - **不需要新的顶层命令组**：`categories` / `public-tags` / `my-tags`（含 `my-tags add` / `rename` / `describe`）进既有 `skills` 组；`tags` / `tag` / `category` / `join` / `leave` / `show` / `restore` 进既有 `skill` 组。
  - **不需要 `skills discover`**：公域发现是 `skills search` 的 scope，不是第二个命令。
  - **不需要采集调用次数**：产品今天没有用量信号，本版不显示这一列、不提供「调用最多」排序（不做 #23）。

- **版本编号**：本版原记为 `v13-skill-tags`，因 v13 编号给了 CLI 命令面而顺延为 **v14**（见 [`../v13-cli-grammar/prd.md`](../v13-cli-grammar/prd.md) §依赖与前置）。范围从“两套标签”扩到“公域/私域、我的库、两套标签”，因为标签依赖库这一层；这是需求补全，不是另起一版。
