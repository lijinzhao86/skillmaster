**编号与范围说明**：本需求原记为 `v13-skill-tags`，只做两套标签。v13 编号后来给了「CLI 命令面」（[`../v13-cli-grammar/`](../v13-cli-grammar/README.md)），本版顺延为 **v14**。恢复时发现私人标签依赖一层今天没有的东西——一个「我这边的 skill 目录」；所以本版把**公域/私域、我的库、标签**一次做完。这是需求补全，不是另起一版。

## 目标

把 skill 分成两层：**公域**只搜不整表列（`skills search`），搜到后可以**加入我的库**；**我的库**是我创建的 + 共享给我的 + 我加入的那一份私域目录（`skills list`）。在库里贴**我的标签**（只有本人可见），skill 上贴**公开分类**（平台词表，用于公域发现）。加入是引用，不是复制，也不是加载门禁。细节见 [`prd.md`](prd.md)。

## 验收标准

一句话：**公域不整表、私域是库、加入是引用；同一份标签数据，换一个人、换一个可见性看，结果必须不同——我的标签零泄露，公开分类只让公开上线的 skill 进入公域检索，而能看见该 skill 的人都能看到它的分类。**

完整 35 条与判定方式见 [`prd.md`](prd.md) §验收与指标。

**成立条件六条：#1 / #4 / #7 / #12 / #22 / #23**；另 **#6 与 #21 是生命周期的心脏**（同样不能丢）。每一条为什么这样分，写在 [`prd.md`](prd.md) §验收与指标，本页不复述。

## 这一版明确不做什么

摘要五条最要紧的；**完整范围与每条的理由在 [`prd.md`](prd.md) §范围**。

- 不做**复制 / 派生公开 skill** —— 加入是引用；复制会切断作者更新，并带来内容归属问题
- 不做**未加条件的公开全量列表** —— 公域 skill 会多到无法加载；公域只搜不列
- 不做**公开 skill 的加载门禁** —— 未加入仍可直接 `skill invoke`（[ADR 0048](../../decisions/0048-visibility-hands-out-a-rung.md) 不动）
- 不做**我的标签转公开 / 用户自建公开分类** —— 范围出生即定；公域词表由平台控制
- 不做 **CLI 写标签 / CLI 加入移除库 / 向量检索** —— 管理在控制台；检索先用关键词 + 标签，且排序要可解释可回归

## 与目标态的关系

[`target/design.md`](../../target/design.md) §2.6「发现与浏览」把 `Tag` 列为关键对象，但没有区分公开与私人，也没有「我的库」这一层。这一版落成两层，并在差异清单里登记：

- **保留的部分**：公开分类对应目标态里的「分类与标签」；发现层只索引 L1（外加 `when_to_use`，是本版的显式扩展），不做推荐与榜单（M3 之前）。
- **新增的部分**：我的标签是「人 + skill」的个人组织层；「我的库」是“我创建的 + 共享给我的 + 我加入的”私域目录，不复制内容、不挡加载。两者都是目标态没有的扩展，已登记在 [`target/README.md`](../../target/README.md) §五。
- **明确不做**：标签不参与排序与权重；目标态里 M3 的推荐/榜单不因这一版提前。
