# v37-cli-page-actions · 网页专属的动作，在 CLI 里有一个会打开网页的入口

> **最后更新**：2026-11-01
> **状态**：已实现；视觉验收待做（同意屏换行后的那一屏还没人看过）
> **含收费**：否

## 目标

把「只能由人在网页上确认」的八个动作补齐成 CLI 命令（四个版本动作、三个 skill 动作、`skills publish`）：命令存在、打开那一页、明确说动作还没发生；另加一条受限的真实删除（从未上线过的 skill，owner 用 `--yes`）。细节见 [`prd.md`](prd.md)。

## 验收标准

- 七个带地址的页面动作**最多两次只读**做预检（作者面一次；读不到时消费者面再一次，拿档位）：够档位就打开、退出 0，不够就说明并退出 1，判定不了就打开并写明没能预检；`skills publish` **零请求**直接打开 `/publish`。
- `skill delete` 不带 `--yes` 只说明后果与命令；带 `--yes` 由服务端判定，从未上线过才删。
- 新增的八个页面动作命令首句说明「还没执行」（`skill open` / `version open` 的首行仍是地址），落到正确的页面；`skill delete` 不带 `--yes` 时首句是后果，带 `--yes` 时首句是结果；旧的三个错位名字移除。

完整验收见 [`prd.md`](prd.md) §验收与指标。

成立条件：**页面动作零写入；一次预检最多两个只读请求（作者面，失败时消费者面）。** 边界没有变是这一版的前提。

## 这一版明确不做什么

- 不做上线 / 回滚 / 下架 / 重新上架 / 下线 / 恢复 / 改可见性的真实执行——API 平面仍无这七个动作的路由（[ADR 0061](../../decisions/0061-what-a-credential-may-do-to-versions.md) §决定 1，其中「删除 skill」一项由 [ADR 0127](../../decisions/0127-never-published-skills-may-be-deleted-by-a-credential.md) 修订）。
- 不让凭据删除**上线过**的 skill——网页上 owner 仍可确认删除，控制台不变（ADR 0127）。
- 不留旧名别名——未正式发布，产品负责人 2026-11-01 确认可以直改。
- 不做 C 组（审批访问申请）与账号面命令——需要单独确认。

## 与目标态的关系

[`target/`](../../target/) 的完整形态里，agent 能完成「准备」，人只做「改变调用者读到什么」的最后一步。这一版把这个分工**显式化**：agent 不再读一句拒绝，而是拿到一张要去确认的页面。

- 保留的部分：提交与上线分开、高风险动作在网页确认。
- 已经分叉的部分：无。
