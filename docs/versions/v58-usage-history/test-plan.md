## 用例

### W · 采集与关联（写入侧）

#### W1 · 搜索写出一条完整事件

- **前置**：账号甲已登录；库里至少 12 条公开 skill。
- **步骤**：`GET /web/discover?q=pdf 合并&p=1`；随后查 `activity_event` 与 `GET /api/v1/usage/interactions`。
- **期望**：恰好多一条 `kind='search'`；`target` 是查询词；`detail.total=12`、`returned=本页条数`、`pages=1`；`results` 与 `skill_ids` 顺序一致、`rank` 从 1 起；接口里这一条的 `query` / `total` / `results` 与库一致。
- **判定**：通过 / 失败。

#### W2 · 不带 `q` 的浏览不记搜索

- **前置**：同 W1。
- **步骤**：`GET /web/discover?category=doc&p=1`（无 `q`）；再查库。
- **期望**：新增 `kind='browse'`，**没有**新增 `search`；`browse` 不出现在 `/usage/interactions`，也不参与 W13 的关联。
- **判定**：通过 / 失败。

#### W3 · 0 条结果仍记一条搜索

- **前置**：库中没有匹配词。
- **步骤**：搜索一个肯定没有结果的词。
- **期望**：`search` 行存在，`results=[]`、`skill_ids=[]`、`total=0`；接口返回这一条；网页这一行**没有折角、整行不可点**（R9）。
- **判定**：通过 / 失败。

#### W4 · 超过 50 条只存前 50

- **前置**：造 60 条匹配的公开 skill。
- **步骤**：用 API 搜索，`limit=50` 翻到第 2 页（网页每页 6 条，翻到第 9 页才够 54 条）。
- **期望**：`results` / `skill_ids` 各 50 条；`total` 按当次响应写（网页是 60；API 没有总数，是 `null`，见 W5）；`returned` 累加但不超过 50；接口与 CLI 都说明「只记录前 50 个」。
- **判定**：通过 / 失败。

#### W5 · API 搜索没有总数

- **前置**：账号甲有 API key。
- **步骤**：`GET /api/v1/skills?scope=public&q=pdf`（这条响应没有 `total`，见 `SearchResponse` 注释）。
- **期望**：事件 `total` 为 `null`（JSON 里是 `null`，不是 0）；界面用 `returned` 显示「N 个结果」，工具提示写「本次响应返回 N 个」。
- **判定**：通过 / 失败。

#### W6 · 匿名不记

- **前置**：不带凭据、不带会话。
- **步骤**：匿名搜索、匿名 `GET /body`。
- **期望**：`activity_event` 没有新增行；业务响应照常。
- **判定**：通过 / 失败。

#### W7 · 搜索失败不记

- **前置**：让搜索端点返回 500（测试替身）。
- **步骤**：请求搜索。
- **期望**：没有新增 `search`；错误响应照常。
- **判定**：通过 / 失败。

#### W8 · 调用写出一条事件

- **前置**：账号甲对 `dev/pdf-tools` 有可见性。
- **步骤**：`GET /api/v1/skills/dev/pdf-tools/body`。网页的 `/web/.../body` 是控制台预览，归 W10 的 `file_read`。
- **期望**：新增一条 `kind='invoke'`：`skill_id`、`skill_address`、`version_id`、`version_label` 与当时的解析结果一致；`at` 是整秒 RFC3339 UTC；接口与页面立刻能读到（A1）。
- **判定**：通过 / 失败。

#### W9 · 客户端中途断开仍记为调用

- **前置**：同 W8；用能读到响应头后立刻关闭连接的客户端。
- **步骤**：发起 `/body` 请求并中止读取。
- **期望**：服务端解析成功后即写入 `invoke`；客户端断开不影响这一行（`ReadSkillUseCase.streamFile` 已解析出内容）。
- **判定**：通过 / 失败；若实现把写入放在流结束后，这一条失败。

#### W10 · 读 `SKILL.md` 记为 `file_read`

- **前置**：同 W8。
- **步骤**：`GET /api/v1/skills/dev/pdf-tools/files/SKILL.md`；再打开控制台里的 SKILL.md 预览（`/web/skills/dev/pdf-tools/body`）。
- **期望**：两次都新增 `kind='file_read'`、`detail.path='SKILL.md'`；**没有**新增 `invoke`；不进调用统计（B8）。预览不等于使用。
- **判定**：通过 / 失败。

#### W11 · 整版归档记为 `download`

- **前置**：账号甲对 `dev/pdf-tools` 有下载权限。
- **步骤**：`GET /api/v1/author/skills/dev/pdf-tools/archive`（作者面）或 `skmr skill get`。
- **期望**：新增 `kind='download'`；不进调用统计、不出现在「调用的 skill」里。
- **判定**：通过 / 失败。

#### W12 · 登录 / 登出

- **前置**：网页会话。
- **步骤**：登录一次；分别用网页登出与 `/api/v1/logout` 登出。
- **期望**：三次各写一条 `login` / `logout`；`login.detail.method` 有值。它们不进调用与搜索统计。
- **判定**：通过 / 失败。

#### W13 · 关联：取最近一次包含它的搜索

- **前置**：直接调用 `RecordActivityUseCase`（固定 `at`，见「环境与数据」）。
- **步骤**：T0 写入搜索 S1（结果含 skill X）；T0+5min 写入 `invoke X`。
- **期望**：`invoke.search_event_id = S1.id`、`search_rank = X 在 S1 里的名次`；不再是「直接调用」。
- **判定**：通过 / 失败。

#### W14 · A 后 B，只挂最近的 B

- **前置**：同 W13。
- **步骤**：T0 搜 A（含 X）；T0+1min 搜 B（也含 X）；T0+2min 调 X。
- **期望**：挂 B，不挂 A；A 的 `invocations` 为空，明细显示「未调用」。
- **判定**：通过 / 失败。

#### W15 · 30 分钟窗口的闭区间

- **前置**：同 W13。
- **步骤**：T0 搜 S（含 X）；T0+30:00 调 X；另起一轮 T0 搜 S、T0+30:01 调 X。
- **期望**：恰好 30 分钟**关联**；30 分 01 秒**不关联**（按 `at` 的整秒比较）。
- **判定**：通过 / 失败。

#### W16 · 先调用后搜索

- **前置**：同 W13。
- **步骤**：T0 调 X；T0+1min 搜一个含 X 的结果。
- **期望**：调用仍是「直接调用」；后写的搜索不回填它。
- **判定**：通过 / 失败。

#### W17 · 跨入口：网页搜、CLI 调

- **前置**：同一账号在网页与 CLI 都登录。
- **步骤**：网页搜索（结果含 X）；10 分钟内 `skmr skill invoke <X>`（即 API 的 `/body`）。
- **期望**：关联；与入口无关（只看账号、时间、结果）。
- **判定**：通过 / 失败。

#### W18 · 一次搜索、三次调用

- **前置**：同 W13；搜索 S 的结果含 X、Y、Z。
- **步骤**：T0 搜 S；随后依次调 X、Y、Z（都在 30 分钟内）。
- **期望**：三条 `invoke` 的 `search_event_id` 都是 S；接口的 `invocations` 长度 3、按 `at` 升序；统计里「搜索 1 次、调到 1 次、调用 3 次」。
- **判定**：通过 / 失败。

#### W19 · 搜索行写失败时退化为直接调用

- **前置**：让 `ActivityRecorder` 对 `search` 抛异常（测试替身）；调用写入正常。
- **步骤**：搜索后调用结果里的 X。
- **期望**：搜索缺失（best-effort）；`invoke` 的 `search_event_id` 为 `null`，显示为直接调用；读路径不报错（B10）。
- **判定**：通过 / 失败。

#### W20 · 没翻到的那一页不关联

- **前置**：搜索结果第 2 页才有 X，用户只请求了第 1 页。
- **步骤**：调用 X。
- **期望**：不关联，显示为直接调用（B16）。
- **判定**：通过 / 失败。

#### W21 · 同一秒的两条搜索

- **前置**：同 W13。
- **步骤**：同一秒写入 S1、S2，两者都含 X；随后调 X。
- **期望**：挂后写入的 S2（`id DESC`）。
- **判定**：通过 / 失败。

#### W22 · 别人的搜索不参与关联

- **前置**：账号乙在 5 分钟前搜过含 X 的结果。
- **步骤**：账号甲调用 X。
- **期望**：甲的调用是直接调用；`actor_user_id` 必须相等。
- **判定**：通过 / 失败。

### P · 翻页并入

#### P1 · 网页第 2 页并入同一次搜索

- **前置**：一个查询第 1 页 6 条、第 2 页 4 条（共 10 条）。
- **步骤**：`?q=…&p=1`，再 `?p=2`。
- **期望**：**只有一条** `search`；`results` / `skill_ids` 共 10 条、顺序为先第 1 页再第 2 页；`pages=2`、`returned=10`、`total=10`；「搜索次数」是 1，明细只有一行（A23）。
- **判定**：通过 / 失败。

#### P2 · API cursor 第 2 页并入

- **前置**：公开搜索 `GET /api/v1/skills?scope=public&q=…` 返回 `nextCursor`。
- **步骤**：带 `cursor` 再请求一次。
- **期望**：与 P1 相同：一条 `search`、结果追加、`pages=2`；游标请求带上与第 1 页相同的筛选才并入，换了筛选另起一条。
- **判定**：通过 / 失败。

#### P3 · 重复请求同一页不重复追加

- **前置**：同 P1。
- **步骤**：第 2 页请求两次。
- **期望**：结果仍 10 条（按 `skill_id` 去重），`pages` 可以增加但明细不重复。
- **判定**：通过 / 失败。

#### P4 · 翻页也不突破 50 条

- **前置**：一个查询共 80 条（测试替身直接造；每页至少 10 条，网页每页 6 条则翻到第 9 页）。
- **步骤**：翻页直到累计超过 50 条（测试替身每页 10 条时翻到第 6 页）。
- **期望**：已存结果停在 50；`total=80`；`pages` 继续记录；面板头说「只记录前 50 个」。
- **判定**：通过 / 失败。

#### P5 · 31 分钟后翻页另起一条

- **前置**：同 W13 的固定时间能力。
- **步骤**：T0 第 1 页；T0+31min 第 2 页。
- **期望**：两条 `search`；第二条只含第 2 页结果；搜索次数是 2。它们是两段查询会话。
- **判定**：通过 / 失败。

#### P6 · 不同查询词不并入

- **前置**：T0 搜「pdf 合并」；T0+1min 搜「季度报表」并翻页（同一 `p=2` 参数不构成同词）。
- **期望**：两条 `search`，各自结果独立。
- **判定**：通过 / 失败。

#### P7 · 并发翻页不丢结果

- **前置**：第 2、3 页各自返回不同结果。
- **步骤**：两个请求几乎同时到达（两个线程）。
- **期望**：`FOR UPDATE` 串行化；最终 `results` 同时含两页内容（顺序按提交先后），没有读改写丢失。
- **判定**：通过 / 失败（重复跑 20 次，不允许丢页）。

#### P8 · 翻到的那一页里的 skill 被调用时照常关联

- **前置**：X 只在第 2 页；第 2 页已并入。
- **步骤**：调用 X。
- **期望**：挂到这条并入后的搜索；`search_rank` 是 X 的全局名次（> 第 1 页条数）。
- **判定**：通过 / 失败。

### R · 本人读路径

#### R1 · 只返回本人；三种 skill 关系

- **前置**：账号甲、乙；甲有自己创建的、别人分享的、公开的三种 skill，且三种都调用过。
- **步骤**：甲与乙分别请求 `/usage/interactions`；再让乙请求甲那条 skill 的所有者聚合与使用者表。
- **期望**：甲看到自己的三条（三种关系都在）；乙只看到乙自己的行，看不到甲的任何一条；乙请求甲 skill 的所有者接口得到 404，与请求不存在的 skill 同一答案（A2、A5）。
- **判定**：通过 / 失败。

#### R2 · 明细倒序与分页

- **前置**：造 120 条交互。
- **步骤**：请求第 1、2、3 页（`limit=50`）。
- **期望**：按 `at DESC, id DESC`；三页不重不漏；`total=120`；`page_size=50`；第 4 页为空且 `items=[]`。
- **判定**：通过 / 失败。

#### R3 · 明细的形状

- **前置**：W1 + W8 的数据。
- **步骤**：请求 `/usage/interactions`；对照页面。
- **期望**：`search` 行带 `query` / `total` / `returned` / `results` / `invocations`；直接调用是 `kind='direct'` 带 `skill` / `version`；被挂上的调用不出现在顶层（只出现在所属搜索的 `invocations` 里）；页面是时间 / 操作 / 调用的 skill 三列（A1、A17）。
- **判定**：通过 / 失败。

#### R4 · 统计口径

- **前置**：W18 的「一搜三调」加两条直接调用、一次未调用的搜索。
- **步骤**：请求 `/usage/stats`。
- **期望**：`calls = 3 + 2`；`searches = 2`；`converted = 1`；`missed = 1`；`skills = 去重后的 skill 数`；`latest` 是最晚的调用；`top` 按次数降序、同次数最近在前（A18）。
- **判定**：通过 / 失败。

#### R5 · 90 天窗口

- **前置**：造 89 天、90 天、91 天各一条。
- **步骤**：请求明细与统计。
- **期望**：89 天与 90 天在内；91 天不在；统计只算窗口内（A4 读侧）。
- **判定**：通过 / 失败。

#### R6 · 统计与明细同源

- **前置**：R4 的数据。
- **步骤**：把明细里的调用行数、搜索行数手算；与 `/stats` 对照。
- **期望**：`calls` 等于明细里调用行数；`top` 各行之和等于 `calls`；`converted + missed = searches`；`skills` 等于明细里去重后的 skill 数。
- **判定**：通过 / 失败。

#### R7 · 参数边界

- **前置**：已登录。
- **步骤**：`page=0`、`limit=0`、`limit=101`。
- **期望**：三个都按契约返回 400 `invalid_request`，不返回部分数据。
- **判定**：通过 / 失败。

#### R8 · 时区

- **前置**：一条 `at=2026-11-10T01:41:00Z` 的记录。
- **步骤**：接口原样查看；网页打开使用记录；CLI 在 `TZ=Asia/Shanghai` 与 `TZ=America/New_York` 各看一次。
- **期望**：线上是 `…Z`；网页显示 `09:41`（`formatTime` 固定 `Asia/Shanghai`）；CLI 按本机时区显示（B13）。
- **判定**：通过 / 失败。

#### R9 · 0 条结果的行不可展开

- **前置**：W3 的行。
- **步骤**：控制台点这一行、按 Enter / 空格。
- **期望**：没有折角、没有面板、地址里不出现 `open`。
- **判定**：通过 / 失败。

#### R10 · 截断说明

- **前置**：W4 的行。
- **步骤**：展开面板；`skmr usage --expand`。
- **期望**：面板头写「搜索返回 60 个结果，这里只记录前 50 个」；CLI 同一句意思；都不是假装只有 50 条。
- **判定**：通过 / 失败。

#### R11 · 长内容单行省略

- **前置**：一个 60 字符的查询词与一个长地址的 skill。
- **步骤**：控制台查看明细。
- **期望**：搜索词与地址都单行省略，`title` 里是全文；不撑破行高、不换行。
- **判定**：通过 / 失败（截图归 U1）。

#### R12 · 行内展开的交互

- **前置**：一条有结果的搜索行。
- **步骤**：点行任意位置展开；在面板里选字并拖动复制；在面板里点链接；点行外；按 Esc。
- **期望**：整行都能开合；面板内的 mousedown **不收起**；选字后点行不切换；Esc 收起并把焦点还给折角；面板与表格同宽、把后面的行往下推（不是浮层）。
- **判定**：通过 / 失败（A17）。

#### R13 · 多调用分行展示

- **前置**：W18 的行。
- **步骤**：控制台查看；CLI 查看。
