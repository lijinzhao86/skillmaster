# v55-help-layer · 帮助层：两层结构与可执行检查

> **最后更新**：2026-11-10
> **状态**：进行中（实现已完成；验证与 C4 在进行中）
> **含收费**：否

## 目标

把 Agent 读到的帮助分成两层——**单命令参考**（`--help`）与 **Guide 手册**（主要读者是 Agent，人也可以读）；把 Guide 的源搬进仓库；用全 Go 检查兜住退役命令、命令路径、列对齐、重复语义与题表失效。这一版**不改 Guide 正文**，已知问题用“只减不增”的基线兜住；Guide 内容修复与发布另开一轮。细节见 [`prd.md`](prd.md)。

## 验收标准

摘要：两层有唯一权威；Guide 的内容文件原样进仓库；全 Go 检查在 `go test ./...` 里跑，兜住退役命令、命令路径与 flag、Guide 能力入口、列对齐与重复语义、题表失效、Token 预算；Guide **机器可检的**已知违规全部进“只减不增”的清单，新增违规让检查红；CLI 帮助的 `help workflow`、四个失效例子、列宽、`secret set` 的 32 KiB、凭据失败说法在本版修好；评测题表去掉退役题并补上新能力。完整验收见 [`prd.md`](prd.md) §验收与指标。

**成立条件**：A1（两层与唯一权威）、A2（Guide 源原样进仓库）、A4（基线只减不增）**不满足就不算交付**——它们分别是结构、搬移与防漂移本身。

## 这一版明确不做什么

摘要三条最要紧的；完整范围与每条的理由在 [`prd.md`](prd.md) §范围。

- 不改 Guide 正文——退役命令与缺失的能力入口进基线；首次上线“先读后写”、协作闭环这类语义问题基线抓不到，记在 `test-plan.md` §已知问题，下一轮一起修
- 不发布 Guide——线上仍是 1.0.1；发布草稿与官方账号点上线留给内容轮
- 不单独写人向手册——Guide 就是手册，读者以 Agent 为主

## 影响最大的未决问题

完整列表见 [`technical-design.md`](technical-design.md) §开放问题。按重要性排前三条：

1. **基线用什么粒度**——按文件 + 片段，不按行号，避免行移动就失效。
2. **Guide 源放在 `skills/` 会不会和站点打包冲突**——`changed-paths.sh` 仍把整个 `skills/` 归到 `site`；若站点开始校验 skills 结构，再决定是否排除。
3. **CLI 帮助的五处修复会不会牵动其他测试**——四个失效例子改用 `@<版本>` 后，golden 与示例解析测试要一起看（`go test ./...` 已验证为绿）。
