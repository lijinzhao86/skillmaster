# 0008 · 对齐「不可见空白」的判据：服务端改用 Unicode White_Space

> **日期**：2026-10-02
> **所属版本**：[`../README.md`](../README.md)
> **类型**：小版本迭代——**未改变对外可验收的能力边界**

## 改了什么

### 1. 新增 `common/Text.java`

`isBlank(String)`：判据是 **Unicode 的 White_Space 属性**（显式写出，不用 `String.isBlank()`），`null` 也算空。三个字段策略改用它：`PasswordPolicy`（含内部两条派生规则的守卫）、`UsernamePolicy`、`PhoneNumberPolicy`。

### 2. 前端 `validation.ts` 的 `isBlank` 从 `trim() === ''` 改成**显式写出的同一个集合**

不与服务端「各自用语言内置」，而是两侧都声明同一张表。前端那版踩了一个坑并写进了注释：**U+2028/U+2029 是 JavaScript 的行终止符，写成字面量会让正则字面量断行、整个文件解析失败**——所以全部用转义写。

### 3. 测试

- 新增 `TextTest`（3 条）：**逐字符覆盖整个 White_Space 集合**（25 个码点，含 U+0085 这个两个 Java 判据都漏掉的），加两个「语言内置会答错」的反例——U+001C–U+001F 是 Java 的 whitespace 但不是 White_Space，U+FEFF 是 JavaScript 的 whitespace 但不是 White_Space。
- 前端 `validation.test.ts` 加 4 条：同一集合；U+FEFF 对 `trim()` 是空、对镜像不是；U+0085 对 `trim()` 不是空、对镜像是。

## 为什么

这不是设计出来的，是**核查「前后端都适配了吗」时用差分法发现的**：把同一批 22 条输入同时喂给两份真实实现逐条比码——20 条一致、3 条是**有意**的黑名单缺口（客户端不下发名单）、1 条是真分歧：

| 输入 | 服务端（改前） | 前端 |
|---|---|---|
| 8 个不换行空格（NBSP, U+00A0） | `invalid_format` | `required` |

顺着查发现**用户名与手机号同样分家**，所以这是三个字段共有的问题，不是密码独有。

根因很具体：Java 的 `String.isBlank()` / `Character.isWhitespace` **故意不认不换行空格**，而 JavaScript 的 `trim()` / `\s` 认。两侧各跟了一个**不同的定义**（一个是 Java 关于换行的规则，一个是 JS 的空白集合），于是只在「不换行空白」这一族上分家。

**影响为零**：两边都是拒绝，只是理由不同；而客户端先判、判完根本不发请求。所以这条修的是**镜像的纯度**，不是用户看得见的行为——这一点在选择修之前就说明过。

**修在服务端一侧**，理由是选**有定义的那个集合**：White_Space 是 Unicode 的字符属性、有规范文档；`Character.isWhitespace` 是 Java 关于换行的规则，恰好更窄。反过来要在 TS 里硬编码 Java 那串例外（还得排除 U+2007、U+202F）是把一份语言怪癖冻进第二种语言。

**第一版改法是错的，测试当场打回来了**：我先写成「两个 Java 判据取并集」，跑测试就红在 U+0085——那两个判据**都**漏掉它，所以并集并不等于 White_Space。最终两侧都改成**显式列出集合**，谁也不吃内置：Java 侧 `isSpaceChar ∪ {0009–000D, 0085}`，前端侧一个全转义的字符类。**这是「靠内置」与「靠定义」的差别，而它只有在把集合逐字符写出来之后才看得见。**

## 影响

- **服务端**：8 个 NBSP（以及 U+2007 figure space、U+202F narrow no-break space）现在得到 `required` 而不是 `invalid_format`；U+0085 归入空白。用户名与手机号同步。U+001C–U+001F 由「空白」变为「有值」（它们确实占位，只是不显示）。
- **前端**：U+FEFF（BOM）不再算空白（`trim()` 会删掉它），U+0085 算空白。
- **判序与规则集未变**，密码规则本身（ASCII 字符集、8–72、黑名单、派生）一条没动。
- **计数**：服务端 **304 → 307**（169 单测 + 138 集成，`clean verify` 11.9 秒）；前端 **113 → 117**。
- **文档同步**：[`M01-account-login.md`](../../../architecture/modules/M01-account-login.md) §密码 的判序那句补一句「空白按 Unicode White_Space 判」；[`test-plan.md`](../test-plan.md) §结果记这一轮与差分法的结论。
- **不需要 ADR**：这不是跨版本取舍，是让实现去符合一个已有意图（「看起来像没填的」算没填），并且它把两侧从「各自跟语言内置」改成「声明同一张表」。
