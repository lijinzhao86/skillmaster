# 0007 · 密码字符集收成 ASCII 可打印字符

> **日期**：2026-10-02
> **所属版本**：[`../README.md`](../README.md)
> **类型**：小版本迭代——**未改变对外可验收的能力边界**

## 改了什么

### 1. 策略多一条字符集规则

`PasswordPolicy.problemWith` 在**长度之前**加一步：不是 ASCII 可打印字符（U+0020–U+007E）就回 `invalid_format`。空判断同时从 `isEmpty` 改成 `isBlank`——八个空格与八个全角空格都算「没填」。

判序变成：**空/纯空白 → 字符集 → 太短 → 太长 → 与用户名相同 → 与手机号相同 → 常见**。

### 2. 前端镜像同改

`validation.ts` 的 `passwordIssue` 加同一个判断（同顺序，否则同一个密码两侧会得到不同的码）；`FIELD_SPECIFIC.password.invalid_format` 加一句写明规则的文案；**注册页与找回密码页的密码提示**写明「只能用英文字母、数字和符号（不能用中文或全角字符）」。这条限制是**用户看得见**的，所以要在敲的时候就说明，而不是事后拒绝。

### 3. 测试

| 位置 | 加了什么 | 条数 |
|---|---|---|
| `PasswordPolicyTest` | 键盘上的字符全收（含空格）；**中文与全角被拒**（含 `ｐａｓｓｗｏｒｄ`）；字符集先于长度（`密码` 得到的是字符集错而不是「太短」）；纯空白算没填（半角与全角各一） | 12 → 16 |
| `WebRegistrationIT` | **端点真的按新规则拒**：全角 `ｐａｓｓｗｏｒｄ` → 400 `password`/`invalid_format` | +1 |
| 前端 `validation.test.ts` | 键盘字符全收；中文/全角/emoji/制表符被拒；字符集先于长度；纯空白算没填 | +4 |
| 前端 `register-flow.test.ts` | 页面上写明规则并**不发请求**（用全角密码，因为那正是用户自己看不出来的那一种） | +1 |

**计数**：服务端 **299 → 304**（166 单测 + 138 集成，`clean verify` 整条 12.0 秒）；前端 **109 → 113**。

### 4. 四条旧测试被改写，而不是改值

以中文密码为 fixture 的用例全部作废：服务端 `countsBytesRatherThanCharacters`、前端两条字节边界用例、两个页面里拿 25 个汉字当「太长的密码」的用例。它们测的属性是「**字节与字符不一致**」——而这条**现在已经不可观测**，因为非 ASCII 到不了长度那一步。所以：

- 长度那几条改用 ASCII 压线值（72/73 字符），字节语义移回它还能被观察的地方（`BCryptPasswordHasherTest` 的 72 字节截断）；
- 两个页面的用例保留原意（「本地拒绝 → 一个请求都不发」），fixture 换成 73 个 ASCII 字符，另加一条**全角密码**的用例去钉新规则。

## 为什么

[ADR 0016](../../../decisions/0016-password-blocklist-not-composition.md) 记完黑名单的当天就发现，「只看长度、字符集不管」这个默认有三处问题，而其中最要命的一条是**实测出来的**：全角 `ｐａｓｓｗｏｒｄ` 每字符 3 字节、长度合法、名单是 ASCII 的查不到——**绕过黑名单**。而它对中文用户根本不是刁钻输入，输入法留在全角模式打出来就是这个。

取舍、被否掉的归一化为什么被否、以及「这不是规范推荐做法」都记在 [ADR 0017](../../../decisions/0017-password-printable-ascii-only.md)。本文只记两件过程上的事：

1. **调研先于决定，而且中途改过建议。** 我先推荐归一化（PRECIS），是「复杂度压住了」这句话让我重新查了一遍——结果查到国内站点的通行做法**本来就是限 ASCII**（学信网注册页、流传最广的中文密码正则明确排除中文与全角），另有国内线上事故给出了全角空格那类失败的具体数字（客服日均 5–8 起、失败请求长度多 1）。**证据支持了产品方的直觉，我据此改了建议。**
2. **时机是决定的一部分。** 现在没有真实用户，迁移成本为零；上线之后再收紧字符集，用中文或全角设过密码的人**会直接登不进去**。所以这条看似可以往后拖的决定，其实是「现在不做、以后几乎做不了」。

## 影响

- **对外契约**：密码多一条被拒的理由。**存量账号不受影响**（没有真实用户，且登录不校验形态）。
- **中文口令不再可用**，方向不可逆：将来若要支持，必须连同归一化一起做，并处理存量。
- **与 NIST / OWASP 相悖**，这一点写在 ADR 0017 里，也不要在对外材料里说成「符合最佳实践」。
- 文档同步：新增 [ADR 0017](../../../decisions/0017-password-printable-ascii-only.md) 与索引行、0016 头部加一条相关引用（正文不动）、[`M01-account-login.md`](../../../architecture/modules/M01-account-login.md) §密码 改写、[`test-plan.md`](../test-plan.md) §结果记这一轮。
- **不需要新开大版本**：没有新增任何用户可以做的事，验收标准未变。
