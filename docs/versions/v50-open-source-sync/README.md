## 目标

平台按人工维护的清单，从外部来源同步开源 skill 到官方命名空间：先过许可闸与内置安全扫描，再落成**草稿**，由运营者人工发布；需要时可从 GitHub Actions 手动触发一次。导入时可选配来源前缀（`<prefix>-<上游 name>`），让不同来源的同名 skill 能共存；不配前缀就保持上游裸名。**同步是来源无关的底座，本版只交付第一个来源适配器 GitHub**；以后接 SkillHub 只加适配器，不动底座（[ADR 0157](../../decisions/0157-sync-is-a-source-neutral-pipeline.md)）。细节见 [`prd.md`](prd.md)。

## 验收标准

二十六条验收（A1–A26），摘要三条：合规内容能按上游 revision 幂等地变成官方草稿；非白名单许可与扫描阻断的内容进不来；同步产物必须人工发布才可能进入公域。另有 A12 证明底座与来源无关、A13 覆盖 CI 手动触发、A14 覆盖并发度、A15/A16 覆盖旧草稿清理与丢弃/撤销不重建、A17 覆盖目录展开、A18–A21 覆盖导入重命名（可选前缀、跨来源同名、地址稳定、只改 `name`）、A22–A26 覆盖来源状态在同步时定稿（快照完整、元数据每轮每仓库一次、发布与回滚不调 GitHub、按 skill 目录判断变更、每日只补缺口）。完整验收见 [`prd.md`](prd.md) §验收与指标。

**成立条件**：A5（许可闸）、A8（安全闸）、A9（人工发布）不满足就不算交付——这一版存在的理由就是把未经审查的开源内容挡在公域之外。

## 这一版明确不做什么

摘要三条最要紧的；**完整范围与每条的理由在 [`prd.md`](prd.md) §范围**。

- **不做自动发现、自动发布或自动公开** —— 谁进公域是平台背书，必须人工选定并确认。
- **不做 SkillHub 等第二个来源** —— 先把 GitHub 一条链路跑通；来源扩展沿用适配器模型。
- **不做同步管理页与 CLI** —— 复用现有发布流程；手动触发只走 GitHub Actions，结果先看日志与草稿列表。
- **不改写上游 `name` 以外的内容** —— 重命名只解决地址冲突；正文与其它字段保持上游原样。
- **不做强制前缀或自动后缀** —— 清单不配 `prefix` 就保持上游裸名；两者都不配又重名时仍阻断，不自动加 `-2` 或随机后缀。
- **不做来源介绍与作者命名空间** —— 公域来源卡、`mattpocock/<skill>` 这类作者命名空间留在 [`TODO.md`](../../current/TODO.md)。
- **不做发布时刷新，也不每日重取 `ok` 的旧快照** —— 来源状态在同步建草稿时定稿；发布与回滚不读 GitHub，每日任务只补 `pending` / `error` / `stale` 的缺口。周刷新与批量发布的超时留在 [`TODO.md`](../../current/TODO.md)。

## 与目标态的关系

[`target/`](../../target/README.md) 描述的是完整形态：公开市场、平台审核、可解释排序。这一版补上「官方收录」的第一个入口，但仍然没有用户申请公开、审核队列与多来源生态。

- 保留的部分：公域只搜不列（[ADR 0082](../../decisions/0082-public-and-private-with-my-library.md)）、公开只留给官方（[ADR 0146](../../decisions/0146-public-is-platform-endorsement.md)）、来源与许可的展示口径（v49）。
- 已经分叉的部分：目标态允许用户申请收录与多来源同步；本版只做人工白名单 + GitHub。差异登记在 [`target/README.md`](../../target/README.md) 的差异清单（第 22 条）。
