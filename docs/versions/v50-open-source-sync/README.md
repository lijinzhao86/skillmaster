# v50-open-source-sync · 开源 skill 按许可与安全闸收进官方账号

> **最后更新**：2026-11-06
> **状态**：进行中（**已实现**，`./mvnw verify` 已通过，数量与证据见 [`test-plan.md`](test-plan.md) §结果；循环审计已跑五轮，真机与 CI 启用路径未跑）
> **含收费**：否

## 目标

平台按人工维护的清单，从外部来源同步开源 skill 到官方命名空间：先过许可闸与内置安全扫描，再落成**草稿**，由运营者人工发布；需要时可从 GitHub Actions 手动触发一次。**同步是来源无关的底座，本版只交付第一个来源适配器 GitHub**；以后接 SkillHub 只加适配器，不动底座（[ADR 0157](../../decisions/0157-sync-is-a-source-neutral-pipeline.md)）。细节见 [`prd.md`](prd.md)。

## 验收标准

十七条验收（A1–A17），摘要三条：合规内容能按上游 revision 幂等地变成官方草稿；非白名单许可与扫描阻断的内容进不来；同步产物必须人工发布才可能进入公域。另有 A12 证明底座与来源无关、A13 覆盖 CI 手动触发、A14 覆盖并发度、A15/A16 覆盖旧草稿清理与丢弃/撤销不重建、A17 覆盖目录展开。完整验收见 [`prd.md`](prd.md) §验收与指标。

**成立条件**：A5（许可闸）、A8（安全闸）、A9（人工发布）不满足就不算交付——这一版存在的理由就是把未经审查的开源内容挡在公域之外。

## 这一版明确不做什么

摘要三条最要紧的；**完整范围与每条的理由在 [`prd.md`](prd.md) §范围**。

- **不做自动发现、自动发布或自动公开** —— 谁进公域是平台背书，必须人工选定并确认。
- **不做 SkillHub 等第二个来源** —— 先把 GitHub 一条链路跑通；来源扩展沿用适配器模型。
- **不做同步管理页与 CLI** —— 复用现有发布流程；手动触发只走 GitHub Actions，结果先看日志与草稿列表。

## 与目标态的关系

[`target/`](../../target/README.md) 描述的是完整形态：公开市场、平台审核、可解释排序。这一版补上「官方收录」的第一个入口，但仍然没有用户申请公开、审核队列与多来源生态。

- 保留的部分：公域只搜不列（[ADR 0082](../../decisions/0082-public-and-private-with-my-library.md)）、公开只留给官方（[ADR 0146](../../decisions/0146-public-is-platform-endorsement.md)）、来源与许可的展示口径（v49）。
- 已经分叉的部分：目标态允许用户申请收录与多来源同步；本版只做人工白名单 + GitHub。差异登记在 [`target/README.md`](../../target/README.md) 的差异清单（第 22 条）。

完整列表见 [`technical-design.md`](technical-design.md) §开放问题。按重要性排前两条：
