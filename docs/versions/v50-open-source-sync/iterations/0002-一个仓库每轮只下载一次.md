# 0002 · 一个仓库每轮只下载一次整包

> **日期**：2026-11-07
> **所属版本**：[`../README.md`](../README.md)
> **类型**：小版本迭代——**未改变对外可验收的能力边界**，改变的是取数粒度（[ADR 0163](../../../decisions/0163-a-repository-is-downloaded-once-per-run.md)）

## 改了什么

- `usecase/sync/ContentSource.java`——新增 `beginRun()` / `endRun()` 默认空实现：一轮同步开始与结束时给来源一个持有运行内状态的窗口。
- `usecase/sync/ContentSourceRegistry.java`——`beginRun()` / `endRun()` 转发给每个来源。
- `usecase/sync/SyncPipeline.java`——展开前调用 `sources.beginRun()`；正常路径在任务池的 `finally` 里 `shutdownNow()` + `awaitTermination(30s)`，`endRun()` 在外层 `finally`，展开阶段抛异常也会调用。
- `usecase/sync/GitHubContentSource.java`——一轮里每个 `locator`（大小写与首尾空格归一后）只下载一个整包（`ConcurrentHashMap` + `computeIfAbsent`，失败也缓存），该仓库的每个条目从同一个文件里解出自己的目录；`beginRun()` / `endRun()` 删除本进程内残留的临时文件（被强杀留下的由系统临时目录清理）。
- `modules/skill/GitHubContentReader.java`——拆成 `download(locator)`（取默认分支 tip、下载到临时文件、600 秒是整条下载的绝对上限、`max-repo-bytes` 约束）与 `filesIn(archive, …)`（从文件解出目录与许可）；删掉按 revision 下载的 `fetch(...)`。
- `.github/workflows/server.yml`——把 `SKILLMASTER_SYNC_MAX_REPO_BYTES` / `SKILLMASTER_SYNC_MAX_UNPACKED_BYTES` 两个可选仓库变量渲染进 `server.env`（不设就用 `application.yml` 的默认值），校验为正整数。
- 测试：`GitHubContentReaderTest` 改为「一次下载、多次读取」，新增「同仓库两个条目只下载一次」与「下载失败只尝试一次、全仓同因」；`SyncPipelineIT` 新增生命周期成对调用的用例（第二轮在展开阶段真的抛异常）。
- 文档：新增 [ADR 0163](../../../decisions/0163-a-repository-is-downloaded-once-per-run.md)；TD 的 §架构（超时、内存/磁盘上界、数据流）、§接口（`ContentSource`、`GitHubContentReader`）与许可/整包两段同步改写；test-plan 新增 T29。

## 为什么

2026-11-07 首次全量导入里，`K-Dense-AI/scientific-agent-skills` 的 177 个 skill 一条都没进来，全部 `upstream_timeout`。核实后是取数粒度的问题：

- revision 是「该目录最后一次提交」，177 个目录落在 **128 个不同 revision** 上；
- 每个 revision 都要下一个**完整仓库**：实测 **232 MB**，部署机到 codeload 约 1.2 MB/s，**191 秒**一次，而超时是 **60 秒**——每一次都超时；
- 128 × 232 MB ≈ **30 GB**，即使调大超时也得以小时计。

考虑过：按 `(locator, revision)` 缓存（128 个 revision，等于没修）、只调大超时（流量与时间都不变）、改回逐文件 API（2026-11-06 已实测不划算）。选择「每个仓库每轮一次、取默认分支 tip」，代价是许可与内容来自仓库 tip 而不是 skill 目录自己的提交，已写进 ADR 与 TD。

## 影响

- **影响哪些已交付行为**：`unchanged` / 变化检测不变（仍按 skill 目录的 revision）；上游删掉目录时，那一条改为 `skipped`（`missing_skill_md`），不再按旧 revision 重建；许可可能比 skill 的 revision 新。
- **大仓库需要放宽上限**：232 MB 的包超过默认 `max-repo-bytes` 64 MB、280 MB 解压超过默认 `max-unpacked-bytes` 256 MB。要让 K-Dense 进来，部署时把两个仓库变量调到 `268435456` / `536870912` 以上；默认值不变。
- **需要同步改哪些文档**：已改 TD、PRD（做 #9/#10、依赖与 A2）、test-plan（T29）、`deploy/README.md` 的配置表、v50 的 `README.md` 文档表；新增 ADR 0163。
- **是否需要新开 ADR**：需要，见 [ADR 0163](../../../decisions/0163-a-repository-is-downloaded-once-per-run.md)。
