# v61-skill-deletion · 删除释放名字与下线生命周期

> **状态**：进行中（已实现，待视觉验收与合并）

- **目标**：删除后同名可以立即重建、数据仍然保留；公开、有线上版本且有入库者的 skill 退场前有 30 天预告与迁移出路。详见 [`prd.md`](prd.md)。

## 这一版明确不做什么

| 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|
| 真删 / 物理清除内容 | 用户明确要求系统层保留数据；删除仍是软删 | 隐私或合规提出清除要求时另开 ADR |
| 单独的「弃用」状态 | 折进「下线中」，避免同一个状态机两个名字 | 不做 |
| 有入库者时禁止删除 | 所有权优先，用通知与迁移保护调用方 | 未定 |
| 产品内提供「立即下线」通道 | 紧急情况走官方邮箱、平台后台处理 | 不做 |
| 所有权转移 / 交接 | 独立产品面，超出本版范围 | 未定 |
| 已发布 skill 的 CLI 删除 | 高风险，保留控制台由人确认（[ADR 0047](../../decisions/0047-permissions-are-a-ladder.md)） | 未定 |

## 验收标准

一句话：删除后同名可立即重建、恢复冲突自动改名；公开、有线上版本且有入库者的 skill 必须先走完 30 天下线中才能删除，期间调用有警告、入库者与授权者有通知与迁移出路。逐条判据见 [`prd.md`](prd.md) §验收与指标。

## 与目标态的关系

[`docs/target/`](../../target/README.md) 没有单独描述删除生命周期；本版只补齐当前产品面，不改变目标态里「服务端权威、本地不落 skill 副本」的模型。
