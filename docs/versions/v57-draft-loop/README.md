# v57-draft-loop · 草稿一次写完，发布前能跑一遍

> **最后更新**：2026-11-10
> **状态**：进行中（**已实现、已自测**；T1–T11 通过、T12 未执行，见 [`test-plan.md`](test-plan.md) §结果；待合并）
> **含收费**：否

## 目标

修好草稿上的两个断点：批量覆盖不必再 read→write 交替 N 轮；草稿在发布前能用 `skmr run` 真跑一次。细节见 [`prd.md`](prd.md)。

## 验收标准

A1（一条命令带多个 `--from` 一次过）与 A5（草稿版本码可 run）是不满足就不算交付的两条；完整验收见 [`prd.md`](prd.md) §验收与指标。

## 这一版明确不做什么

- 不做 `--force` —— 读凭证是许可证，不提供绕过开关（[ADR 0136](../../decisions/0136-cli-file-verbs-follow-intent.md)）
- 不做整批原子落盘 —— 服务端逐文件 PUT，没有跨文件事务
- 不改服务端 —— 作者面已经认版本码

## 与目标态的关系

[`target/`](../../target/) 描述完整形态，其中没有单独描述 CLI 的草稿读写循环。本版修的是已发布 CLI 的行为，不改变目标态的其他设计：

- 保留的部分：草稿是唯一可改的版本、发布只能由人在网页确认、执行按 digest 确认一次。
- 已经分叉的部分：无新增分叉。
