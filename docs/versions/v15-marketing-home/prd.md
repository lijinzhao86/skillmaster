## 用户与场景

**谁在用**：开发者 / 技术用户，尤其是第一次听说 SkillMaster 的人。他们通常在 GitHub、Hacker News 或同事的 Slack 里点进来，手上有一个正在复用的 `SKILL.md` 目录，或者正在找一个能交给 agent 的 skill。

**在什么场景下用**：页面要在三十秒内回答一个问题——「这东西凭什么比我直接拷文件夹好？」答案是三件事：版本不会漂、谁能读由作者决定、一行地址就能加载。读完之后，他要么登录（已经有账号），要么注册（第一次来）。

**想知道怎么用，不用先读文档**：首页给一句可复制的 prompt，让 agent 下载并安装 SkillMaster CLI。这一句就是首页唯一的「教学」；启动与 skill 迁移放在 CLI 文档里。

**现在的替代做法是什么**：今天没有官网。`/` 就是控制台，未登录的人被直接送到登录页；对外没有一个可以发出去的介绍页，产品能力只能靠口头或仓库文档解释。替代做法不是「另一个页面」，是**没有页面**。

**这一版的产品面**：**官网**（`www.skillmasterai.com`），不是控制台。控制台在 `console.skillmasterai.com`——分域由本版文档定，[ADR 0085](../../decisions/0085-rename-web-to-console.md) 只定了项目改名。

## 范围

### 做

| # | 做什么 | 交付形态 |
|---|---|---|
| 1 | 公开营销首页：导航、满屏 Hero（含一句可复制的「安装 CLI」prompt，prompt 下面直接接三张解释「随时在场」的卡片，分别对应托管 / 分享 / 市场，但不挂眉标）、页脚三列（产品 / 文档 / 关于）——结构、类名、文案、尺寸照 `design/` | 新的静态站点项目 `skillmaster-site/` |

| 3 | 首页**不持有会话，只做一次只读的会话查询**（[ADR 0086](../../decisions/0086-the-homepage-reads-the-session.md)）：启动时 `GET {CONSOLE_URL}/web/session`，拿不到就按未登录；**不发起任何写**，没有登录表单、没有浮层、没有 `?client_id` 授权入口 | 同上 |

| 5 | 响应式：设计稿的 1000px / 720px 两个断点，外加已登录账号控件在 480px 以下只留头像 | 同上 |
| 6 | 设计稿内容回写：`viewer / editor` → 梯子档名（浏览 / 写入）；`发布` → `上线`；控制台「管理」的指路改成 v14 后的「我的 skill」；首页不再使用控制台截图 | `design/` 与首页演示 |
| 7 | 首页演示改成纯营销：去掉浮层与 `?client_id` 入口，以及地址线 / 终端演示 / 痛点 / 卖点 / 步骤；授权请求屏搬进控制台演示；**保留一个演示用的已登录变体**（`?signed-in`，从演示条进入），它对应产品中标 3 的已登录态 | `design/src/home/`、`design/src/console/` 与检查脚本 |
| 8 | 深色系统下**保持浅色**：设计稿只有浅色态，这是一处有意的分叉，记录在案 | 同上 |

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | 首页上的登录 / 注册 / 找回密码浮层或表单 | www 不持有会话；www 读不到 console 的 CSRF cookie，做表单就要新造跨源认证契约（或把 www 变成有后端的代理）。DeepSeek 的 www 同样没有登录表单 | 只有产品明确要求「在首页完成登录」时；要先开一条跨源认证 ADR |
| 2 | 在首页完成登录 / 注册 / 退出（任何会话写） | www 只读；写就要在 www 上再造一套跨源 CSRF 与错误处理契约（[ADR 0086](../../decisions/0086-the-homepage-reads-the-session.md)） | 只有产品明确要求「在首页完成登录」时 |
| 3 | **未登录时**导航里的「控制台」入口 | 未登录的人点它只会被送去登录，等于第二个「登录」。页脚的 `控制台` 链接保留——页脚是站点地图，不是主操作 | 已登录态已经有这一入口（做 #2）；未登录时不做 |
| 4 | 文档 / CLI / 协议 / 更新日志的真实页面 | 本版只做首页；这些页面属于同一个 `skillmaster-site` 的后续内容 | 下一版公开站点迭代 |
| 5 | 占位链接的真实落点 | 产品负责人 2026-10-23 明确「先保留，后续逐渐补齐」 | 有真实地址时逐条替换 |
| 6 | 深色首页 | 设计稿只定义了浅色态；不自己发明一套深色 | 设计稿补深色态之后 |
| 7 | 服务端渲染 / 预渲染 / 内容 CMS | 首页是静态内容，SPA 足够；没有内容团队与多语言需求 | 出现 SEO 硬指标或内容运营需求时 |
| 8 | 分析、埋点、A/B、多语言 | 没有转化指标要追，也没有第二语言的内容 | 有明确指标与内容之后 |
| 9 | 手机端原生 App / 完整移动形态 | 本版只覆盖设计稿的 720px 断点，不是原生 App | 独立的手机端版本 |
| 10 | 修改控制台、服务端、CLI 的**业务行为** | 本版只新增公开面；允许的改动只有三处基础设施：会话 cookie 的 `Domain`、一条只读 CORS、控制台一个 `/logout` 页面路由（做 #11） | 需要改业务行为时另开版本 |
| 11 | 首页上的终端演示、三步教学与卖点段落 | 用户 2026-10-23 看过设计后明确「太复杂了」，要求内容照 DeepSeek 的密度；怎么用由一句可复制的 prompt 回答，细节留在 CLI 文档 | 文档页做出来后，可在文档里展开 |
| 12 | 为首页的「退出登录」（`/logout`）提供 CLI 命令 | `skillmaster logout` 删的是**本机凭据**，不是浏览器会话（[ADR 0038](../../decisions/0038-default-credential-is-an-api-key.md) §决定 7）；同一件事给两个命令，会让人以为退出了其实没退。它不属于 ADR 0081 的两类现成例外，因此由产品负责人逐条确认 | **2026-10-24 产品负责人确认不做**；要改时与 `sessions` 那组命令一起设计 |

## 控制台操作与 CLI 对应

**本版新增一处控制台操作：退出登录（`/logout` 页面路由，做 #11）。** 它不可由 CLI 完成——CLI 有自己的 `skillmaster logout`（删本机凭据），与浏览器会话是两件事（[ADR 0038](../../decisions/0038-default-credential-is-an-api-key.md) §决定 7）。首页其余入口都是**链接**（登录 / 开始使用 / 进入控制台），不是新的控制台操作。

| # | 控制台操作 | CLI 命令 | 备注 |
|---|---|---|---|
| 1 | 退出登录：结束当前浏览器会话后回首页 | **刻意不做** | CLI 的 `logout` 删的是本机凭据，不是浏览器会话；两条路指向两个不同的东西，给它们同一个命令会让人以为退出了却没退出（ADR 0038 §决定 7）。**不是** [ADR 0081](../../decisions/0081-every-console-operation-has-a-cli-command.md) 的高风险例外：退出登录是可恢复的（重新登录即可），影响面也只在本机这一个浏览器。它属于 ADR 0081 的第二类例外（产品负责人逐条确认），核心理由是「CLI 侧已经有同名的另一件事」；**2026-10-24 由产品负责人确认不做** |

## 验收与指标

### 验收标准

| # | 验收标准 | 怎么判定 |
|---|---|---|
| 1 | `www` 的 `/` 渲染营销首页：导航、满屏 Hero（含 prompt 与紧接其下的三张卡片）、页脚三部分；三张卡片与 Hero 同属首屏，卡片上方没有单独标题；Hero 至少一屏高，页脚在首屏之下；三张卡片的标题 / 正文与设计稿逐字一致，且没有眉标；页脚三列（产品 / 文档 / 关于）；没有控制台外壳、侧栏、登录表单或浮层，也没有地址线 / 终端 / 卖点 / 步骤 | 浏览器打开首页；DOM 中无 `.app` / `.sidenav` / `.dialog` / `<form>` 登录表单；无 `.horizon` / `.term` / `.split` / `.points` / `.steps`；无 `#whyTitle` / `.cards-head`；`.card` 为 3 张且整块位于首屏内，无 `.card-eyebrow`；`.foot-col` 为三列 |
| 2 | 首页运行时只发起一次会话读 `GET {CONSOLE_URL}/web/session`；不请求 `/api/v1/*`、`/oauth/*`，不发起任何写 | 浏览器 Network 面板只多这一条请求；测试里 stub `fetch` 并断言调用清单恰好是它 |
| 3 | 导航的 `登录` 指向 `${CONSOLE_URL}/login`，`开始使用` 指向 `${CONSOLE_URL}/register`；页脚「产品」列的 `控制台` / `开始使用` / `登录` 也指向 console 的对应地址 | 读 `<a href>`；生产构建下 `CONSOLE_URL=https://console.skillmasterai.com` |
| 4 | 页面结构、类名、文案、尺寸、各状态与 `design/` 逐处一致，含 ≤480px 时已登录账号控件只留头像（做 #5） | 1440 / 1000 / 720 三档与设计稿对照；≤480px 下对照账号控件；设计检查通过；**由人看图验收** |
| 5 | 占位链接可渲染、但点击不导航、不改变页面 | 点击后地址不变、页面不跳转；PRD 与设计稿都标注为占位 |
| 6 | 深色系统下首页颜色与浅色一致 | 用 `prefers-color-scheme: dark` 打开，计算样式与浅色相同 |

| 8 | 控制台零回归：既有路由与行为不变（新增的只有做 #11 的 `/logout`） | `skillmaster-console` 的 `type-check`、`build` 全绿，`npm test` 通过且用例数不少于实现前的 **538**（本版后 544）；既有路由的地址与行为不变 |
| 9 | `skillmaster-site` 的构建产物是纯静态文件，不含服务端代码，也不持有会话（唯一一次只读会话查询见 #2） | `npm run type-check`、`test`、`build` 通过；产物只含 HTML/CSS/JS/图片 |
| 10 | 设计交付件与源逐字节一致，三套检查通过，图重出 | `build-demo.mjs` 重建后 `diff` 为空；`home-check` / `interaction-check` / `console-states` 通过；`design/shots/` 更新 |
| 11 | 页面标题是设计稿那一句 | 浏览器标签显示「SkillMaster — 把你的 skill 托管起来，任何 agent 一行加载。」 |
| 12 | 本版没有新增 CLI 命令：唯一新增的控制台操作（`/logout`）由产品负责人确认豁免 | 对照本文件「控制台操作与 CLI 对应」表——表里有一行，写明「刻意不做」与理由（ADR 0081 的豁免，2026-10-24 由产品负责人确认）；`skillmaster logout` 的语义不动 |
| 13 | 首页的 prompt 可复制：复制内容与页面显示逐字一致，复制后有可见反馈 | 点「复制」；剪贴板内容等于 `#agentPrompt` 的文本；按钮显示「已复制」（失败时显示「复制失败」） |
| 14 | 打开时是首屏（Hero + 三张卡片）；一次下滑切到页脚（整屏，无中间位置），页脚入场，顶栏固定不动 | 1440 下测量 Hero 高度 ≥ 视口、页脚 top ≥ 视口、三张卡片整块在首屏内；触发一次滚轮或 ArrowDown 后，`.deck` 有 `is-second`、页脚 top 0、Hero top = -视口，`#foot` 有 `is-visible` 且 opacity 1；切换前后 `#nav` 的 rect、`position`、背景与圆角一致 |
| 15 | 已登录端到端可用：带 console 会话的浏览器访问 `www` 首页，导航显示 `进入控制台` + 账号；会话 cookie 带 `Domain=skillmasterai.com`，`GET /web/session` 的响应带 www 源的 `Access-Control-Allow-Origin` 与 `Access-Control-Allow-Credentials: true`；`XSRF-TOKEN` 仍是主机级 cookie（不带 `Domain`） | 带会话访问并读导航；读 `Set-Cookie` 与 `/web/session` 的响应头；读两个 cookie 各自的作用域 |
| 16 | `skillmaster-site` 的构建与检查有 CI 覆盖（做 #10 的仓库内那一半）：只在改动站点或该 workflow 的 PR 上触发，依次跑 install → type-check → test → build | 读 `.github/workflows/site.yml`；四步在本机逐条跑通；GitHub 上的实跑要在推送后看 Actions（**托管与 apex 301 由部署侧执行**，见 §依赖与前置） |

**成立条件**：**#2 的「只读一次、不发起写」、#3 的「入口指对」、以及 #15 的「带 console 会话访问首页确实看到已登录态」这三条不满足就不算交付**——第三条是前两条的端到端证明：少了 cookie `Domain` 或那条 CORS，请求照样发得出去、入口照样是对的，而首页会**安静地**永远显示未登录。

### 指标

| 指标 | 定义 | 怎么量 | 目标 |
|---|---|---|---|
| 首页 API 请求数 | 打开首页到 `load` 之间，发往后端的请求数（含方法） | 浏览器 Network 或测试里的 `fetch` stub | **恰好 1 条 `GET /web/session`；写请求 0** |

| 控制台回归 | 控制台测试通过数 | `npm run test` | **不少于 538**（实现前 538；本版后 544） |

## 依赖与前置

- **外部依赖**：`www.skillmasterai.com` 与 `console.skillmasterai.com` 的 DNS 与 TLS；静态托管（nginx/CDN）要能把 `www` 的 `/` 指到 `skillmaster-site` 的产物。当前仓库没有部署配置，需与部署侧确认。
- **内部前提**：
  - **分域由本版文档定**：`www` 与 `console` 是两个产品面（[ADR 0085](../../decisions/0085-rename-web-to-console.md) 只定了项目改名，分域不在它的射程里）；首页读取会话这条取舍见 [ADR 0086](../../decisions/0086-the-homepage-reads-the-session.md)；
  - 控制台的 `/login` 与 `/register` 已存在且行为不变（v1–v14）；
  - `SkillMaster CLI` 的安装方式由 CLI 仓库 / 文档提供；首页的 prompt 只让 agent 去下载并安装，不写具体命令，也不新增 CLI 能力；
  - 设计稿 `design/src/home/` 是首页的权威；本版先按第 6、7 条回写它；
  - v14 后的控制台导航是「我的 skill / 发现 / 管理（标签）/ 设置」，不是旧的「管理」入口。
- **参考产品**：`deepseek.com`（2026-10-23 实地核对）——www 无登录、所有 CTA 是跳子域的普通链接；页面密度是一个 Hero、少量入口与页脚。这是本版交互与内容的依据，不是依赖。用户同日明确：想知道怎么用，直接贴一句 prompt 让 agent 安装 CLI——这是 prompt 的来源。
- **排除了什么前置**：
  - 不需要 CMS：首页内容由代码与设计稿维护；
  - 服务端只需要两处配置（会话 cookie 的 `Domain`、只读 `GET /web/session` 的 CORS），**没有新接口**；
  - 不需要 SSR：本版没有 SEO 硬指标，静态 SPA 足够；
  - 不需要改 CLI：本版唯一新增的控制台操作（`/logout`）是 ADR 0081 的已确认豁免，CLI 语义不动。
