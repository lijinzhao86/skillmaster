## 用户与场景

**谁在用**

| 角色 | 在这一版里做什么 |
|---|---|
| 用户（一个自然人） | 注册 / 登录（**与 v1 完全相同**）；**在控制台给自己签发 API key**——起名、写一句说明、勾权限、选有效期；把整串交给自己的机器；在列表里看见每一把的名字、说明、权限、有效期与**最后使用时间**，并单独撤销 |
| 同一个用户，在 agent 里 | 提出任务；agent 自己搜到 skill、读到正文、按需取文件并完成任务。**这一步与 v1 完全相同**——换的是 CLI 手里那张凭据从哪来，不是 agent 做什么 |
| 同一个用户带来的**第三方 agent**（别人的 Claude Code、别人写的 agent、CI 里的一段脚本） | **与上一行同一条路**：装我们的 CLI、拿一把 key。本版不为第三方另开接入方式（[ADR 0041](../../decisions/0041-third-parties-reach-us-through-the-cli.md)）——所以「第三方接得进来」是这一版就成立的事，被推迟的只是 MCP 那一个适配器 |

**v2 仍然只有这一个角色。** 组织、成员、角色体系与公共发现仍不做（见 §范围 不做）。

**在什么场景下用**

v1 那条链路里，凭据是**用户在一次浏览器登录里换来的**，而它要求**浏览器和 CLI 在同一台机器上**——`login` 把浏览器领到一个 `127.0.0.1` 的回调上，重定向由**浏览器所在的那台机器**去连。于是：

- `ssh` 到一台开发机上跑 `skillmaster login`：浏览器开不起来，把地址粘到笔记本上，重定向打到笔记本的 `127.0.0.1`——那儿没人听。**断了**
- 容器里、agent 沙箱里：同上
- CI：只能走 `--client-credentials`，而那条路要求**运维先种好一行客户端**

**v1 的 CLI 没有任何退路**（没有「不开浏览器」，也没有「手动粘贴授权码」的入口）——这不是漏做，是那条路的形状本身决定的。

本版把凭据的取得方式与使用地点**解耦**：

```
控制台（浏览器，一次，任何机器）
  → 新建 API key → 写说明 → 勾权限 → 选有效期 → 整串只显示这一次 → 复制
机器上（可以是任何地方，不需要浏览器）
  → skillmaster login --with-key（粘贴）  或  设 SKILLMASTER_API_KEY
  → 此后每条命令带着它；agent 全程无感
```

**作者那一侧**（提交与上线）与 v1 相同，只换了凭据来源：

```
CLI submit <本机目录>            → 服务端存下一个 draft 版本（此刻 agent 读不到它）
  → 网页 /skills/<用户名>/<名字>  → 看到一个 skill 的全部版本与各自状态、看这一版相对线上版本的 diff
  → 点「上线」                    → 指针前移，agent 从此读到的就是它
```

**现在的替代做法**

同 v1 的两条（把 skill 下载到本地、或不托管）。**本版不改变它们的代价**，只解决 v1 自己引入的一条摩擦：**凭据只能在一台有浏览器的机器上取得**。

## 范围

### 做

| # | 做什么 | 交付形态 |
|---|---|---|
| 1 | **API key 的签发与管理**：控制台新建（名字 + 说明 + scope + 有效期）、整串只显示一次、列表（名字 / 说明 / scope / 有效期 / **last-used**）、**单把撤销**、续期（换一把新的、scope 继承）。整串带可识别前缀 `skm_`；库里只存 sha256 | 服务端 key 表 + 控制台一屏 |
| 2 | **默认最小权限，而且写蕴含读**：新建时默认只勾 `skills:read`，`skills:write` 要显式选；**勾了写就在签发时自动补上读**——一把「只写」的凭据连 `list` 都做不了，而错在词表不在用户 | 签发端点 + 那一屏的默认值 |
| 3 | **有效期是部署可配**：界面预选 **90 天**（可另选），关掉开关则允许签一把不过期的；**这个数同时是上限**——超过它的日期会被拒绝，而不是被接受（[ADR 0042](../../decisions/0042-the-expiry-setting-is-a-cap.md)）；**配置只约束新建、不溯及已有的 key**；续期是换一把新的、scope 继承，而且**原子**（新的建不出来就不撤旧的） | 配置 + 签发端点 |
| 4 | **权限实时取交集**：一次请求能用什么 = `key 声明的 scope ∩ 账号此刻的权限`；并且**每次请求都看 `app_user.status`**——停用当场生效 | 鉴权路径 |
| 5 | **CLI 收凭据，并且说得清自己在用什么**：`login --with-key` 从 **stdin** 读，或读环境变量 `SKILLMASTER_API_KEY`；**不收命令行参数**（会进 shell history 与 `ps`）。**收下之前先拿它请求一次 `/api/v1/me`**——验不过就不存（存一把不工作的凭据，等于把问题推迟到下一次命令）。`auth status` 两半都说清：本机这份从哪来、服务端那把是谁。**过期的 key 与被撤销的 key 要说清是哪种，而且两条指向不同的下一步**：过期的**去控制台续期**，被撤销的**只能新签一把**（撤销过的东西没有可延续的——[ADR 0039](../../decisions/0039-api-key-defaults-and-their-edges.md) §决定 3）。我们没有邮件通道，所以到期那一刻是用户唯一会知情的机会 | CLI |
| 6 | **`logout` 只删本机那一份**，不再撤销服务端；**撤销在控制台**。这句话对 key 成立；**对过渡期的 `login` 不成立**——那类授权在控制台**没有入口**能单独撤销（只有重置密码那一类会连带撤掉全部授权），而本版推荐的路是 `--with-key`（[ADR 0040](../../decisions/0040-api-key-in-the-cli-now-the-browser-path-later.md) §后果） | CLI + 控制台 |
| 7 | **使用痕迹**：列表显示 `last-used`；并且**第一次从新地址使用**、**一把已撤销的 key 再次出现**，各记一条审计——这是对「换成静态凭据就失去轮换检测」的补偿 | 鉴权路径 + 审计 |
| 8 | **快到期在控制台看得见**：**14 天**内到期的 key 单独计数，并在列表那一行上标出来 | 控制台那一屏 |
| 9 | **OAuth 那条路保留**（授权码 / 同意页 / 轮换 / loopback 全部原样）；本版**不新增** CIMD 与 MCP 适配器。**它在本版的用户只有那个过渡期的 `login`**——第三方走的是 CLI + key（[ADR 0041](../../decisions/0041-third-parties-reach-us-through-the-cli.md) §决定 3） | 不新增代码 |
| 10 | **托管、检索、读取面、作者面**：**继承 v1，本版一个字不改** | — |

> **第 10 条为什么也写在这里。** 一份范围表只列改动，读起来像是这一版把别的都拿掉了。托管与读取面是本版**依然要成立**的东西，只是它们的需求与设计权威在 [`v1-hosting`](../v1-hosting/prd.md)，不在这里复述。
>
> **第 8 条为什么有这个数。** 原本没有这个概念——参照产品的页面上有它，而这正是我们比它更需要它的原因：**我们没有邮件通道**（[ADR 0038](../../decisions/0038-default-credential-is-an-api-key.md) §决定 11 把提醒排在范围外），所以控制台是用户唯一会知道「快到期了」的地方。**阈值取 14 天，而且只准有一个数**：参照产品自己那两处不一致（行徽章 14 天、统计卡 15 天，调研核到，不是有意为之），我们不重复那个错。

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | **组织拥有的 key**（不属于任何个人、人走了它还要活） | 它要一个**合成用户**作为行主——参照产品证明这**不必改主体类型**，但那属于组织模型，且要新增「合成用户不能登录」一类规则。[ADR 0038](../../decisions/0038-default-credential-is-an-api-key.md) | 组织模型进来时 |
| 2 | **个人 / 群组 / 项目三级归属** | 那是参照产品被它的规模塑形出来的形状；本产品只有个人命名空间 | 未定 |
| 3 | **设备授权码**（RFC 8628） | 它没有独占场景：它只在「有人、浏览器在别处」时能顶，而那种情况 key 也能用且更简单 | 不做（已否决） |
| 4 | **过期邮件提醒** | 本产品**没有邮件通道**。过期的状态只在控制台显示，不主动通知 | 有邮件通道时 |
| 5 | **MCP 适配器与 CIMD** | **第三方接入不是 P2——本版第三方就是通过我们的 CLI 接进来的**（装 CLI + 一把 key，[ADR 0041](../../decisions/0041-third-parties-reach-us-through-the-cli.md)）。被推迟的是 MCP 这一个**适配器**，而它买不到它看上去能买到的东西：**MCP 无法注入 skill**，它只能把同一批文本当工具结果返回，而 CLI 已经在原生地做这件事 | 真有只支持 MCP 的宿主时（那时它仍是薄封装，接口形状早就对齐了） |
| 6 | **在终端里管理 key**（签发 / 列出 / 撤销 / 续期） | **能造凭据的东西必须是浏览器会话**；用一把 key 去造另一把，泄漏之后撤不干净（撤了旧的那把，它造出来的还活着——要堵住就得有家族/血缘）。四件事都在控制台（[ADR 0040](../../decisions/0040-api-key-in-the-cli-now-the-browser-path-later.md) §决定 1、4） | 未定；要做必须先有家族/血缘 |
| 7 | 收费、脚本执行、正文细切、在线编辑器、私有 skill 的免客户端访问 | **理由全部继承 v1**（见 [`v1-hosting/prd.md`](../v1-hosting/prd.md) §范围 不做） | 同 v1 |

> **不做 #1 要特别记一笔。** 它看起来像漏做，其实不是：本版只答「用户签自己的」，而组织那半需要一个本文档范围外的东西。这一条同时写进了 [ADR 0038](../../decisions/0038-default-credential-is-an-api-key.md) §后果——放在三处是为了它不会被读成遗漏。

## 验收与指标

### 验收标准

**本版自己的六条**（v1 的验收 #1 被第 1 条取代，其余八条原样继承）：

| # | 验收标准 | 怎么判定 |
|---|---|---|
| 1 | 用户能注册并登录，**并在控制台签出第一把 API key**，CLI 用它调通一个需鉴权的接口 | 干净环境里走完注册（手机号 + 短信验证码 + 密码 + 用户名）→ 登录 → 控制台新建一把 key → 复制 → 交给 CLI → `skill list` 成功。**另两条一起判，而且它们必须给出不同的下一步**：把这把 key 的到期时间改到过去 → 终端说清是「**过期**」并指向控制台**续期**；在控制台把它**撤销** → 终端说清是「**已撤销**」并指向**新签一把**（撤销过的东西没有可延续的，续期不适用于它）。**两句一样就等于这条验收没做**——它们的区别正是人要采取的动作不同。**我们没有邮件通道，所以到期那一刻是用户唯一会知情的机会**。**短信签名与模板仍要先审核通过**——本版没有免掉这一步（注册本身没变）。**开发期验证码不比对**（`accept-any-code`），这一条要在那个开关关掉之后才算真的成立 |
| 2 | **在一台没有浏览器的机器上，只用一把粘贴进来的凭据就能走完读链路**（成立条件） | 在一台没有浏览器、也没有显示器的环境里（容器即可）：只设 `SKILLMASTER_API_KEY`（不跑任何登录命令）→ `skill list` → `skill invoke` → `skill files` → `skill read` 全通，且**全程没有打开过浏览器**。反证：同一环境里 `skillmaster login`（不带 `--with-key`）**必须失败**，且失败信息指向 `--with-key` 与环境变量 |
| 3 | **key 的权限 = 声明的 scope ∩ 账号此刻的权限**，且停用当场生效 | 四件事各走一遍：（a）用**只读**的 key 提交一个版本 → **403**；（b）把该账号停用 → 同一把 key 的下一次请求立刻 401（不需要等任何过期）；（c）恢复账号 → 同一把 key 又能用；（d）一把**只勾了 `skills:write`** 的 key 也能 `skill list`——写蕴含读在签发时就补进了库里那一行 |
| 4 | **撤销立刻生效，而且列表看得见它** | 控制台撤销 → 下一次请求 401（不是 403、也不是等过期）；撤销后列表里它仍在，标着「已撤销」；**last-used 显示的是真实用过的时刻**（用一次之后刷新列表能看到它前进）。**另判一条**：把一把 key 的到期时间改到 14 天以内，它**在列表上被标出来、并计入那一格统计**——两处说的是同一件事、同一个阈值 |
| 5 | **整串只在创建那一屏出现一次，库里只有哈希** | 创建后刷新页面 / 再进列表，拿不到整串；直接查库，`api_key` 里那一列是 64 位十六进制，**不是**那把 key |
| 6 | **粘贴进来的凭据是活的，而且人说得清自己在用哪一把** | 拿一把**已撤销**的 key 跑 `login --with-key` → **拒绝存**，信息说清是撤销，**本机原有的凭据一个字节没动**；换一把好的 → 存下，并印出用户名与这把 key 的名字 / 权限 / 到期日。此后 `auth status` **两半都说清**：本机这份是来自环境变量还是本机存储；服务端那把叫什么名字、什么权限、什么时候到期 |

**继承 v1 的八条**（v1 验收 #2–#10）：`setup` 装网关、agent 自主搜索命中、按需读取并完成任务、**全程无本地副本**（v1 的成立条件，本版继续成立）、提交与上线、版本名、`list` 与共享、`invoke` 钉版与 `versions`、`files` 枚举——**判定方式与 v1 逐字相同**，权威在 [`v1-hosting/prd.md`](../v1-hosting/prd.md) §验收与指标。

**成立条件：第 2 条。** v1 那条成立条件（无本地副本）继续成立，但**本版的成立条件是第 2 条**——它是这一版之所以存在的全部理由：如果一把粘贴进来的凭据在无浏览器环境里跑不通，这一版就没有换对。

### 指标

| 指标 | 定义 | 怎么量 | 目标 |
|---|---|---|---|
| 一个账号持有多少把 key | 同一 `user_id` 下未撤销的 `api_key` 行数，取分布而不只取均值 | 直接查库 | **不设目标**——先看「用户可以签发多个」这条设计有没有真的被用上；如果绝大多数账号只有一把，说明「多把」这个能力没有价值，那本身是结论 |
| 网关 skill 的常驻成本 | 同 v1 的口径（见 [`v1-hosting/prd.md`](../v1-hosting/prd.md) §指标） | 同 v1 | < 200 tokens |
| 搜索命中率 | 同 v1 的口径 | 同 v1 | 不设目标（先测基线） |

**本版不加别的指标。** 撤销的生效延迟不是指标——它是结构性的（下一次请求即生效），不是要调的量。要加时另开一条迭代记录。

## 依赖与前置

- **内部前提**：本版的取舍来自四份 ADR，**这里不重列理由**——列一份就等于给它们第二个会漂的副本：[ADR 0038](../../decisions/0038-default-credential-is-an-api-key.md)（为什么把默认凭据换成 key、为什么 `logout` 只删本机、为什么不做组织 key）、[ADR 0039](../../decisions/0039-api-key-defaults-and-their-edges.md)（缺省 90 天、写蕴含读、配置只约束新建、续期重新定日期）、[ADR 0042](../../decisions/0042-the-expiry-setting-is-a-cap.md)（部署的有效期配置是上限，不只是默认值）、[ADR 0040](../../decisions/0040-api-key-in-the-cli-now-the-browser-path-later.md)（签发只在控制台、CLI 只从 stdin 与环境变量收 key、那条「点一下」的浏览器路推迟但要做）、[ADR 0041](../../decisions/0041-third-parties-reach-us-through-the-cli.md)（第三方走 CLI，本版不做 MCP 适配器）。
- **外部依赖**：
  - GitHub 仓库、阿里云 ECS + RDS PostgreSQL：**同 v1**（见 [`v1-hosting/prd.md`](../v1-hosting/prd.md) §依赖与前置）
  - **阿里云短信**：**仍是验收 #1 的前置**。本版换了凭据形态，但**注册没变**，所以签名与模板的审核周期照样挡在 #1 前面——这一点容易被「凭据那部分已经跟短信无关了」误读
- **排除了什么前置**：支付通道、实名合规、内容审核（理由同 v1）。**本版新增排除的一项：邮件通道**——它不做，所以「key 快过期了提醒你」这一条明确不做（§范围 不做 #4）
