## 用例

### T1 · 签发 → 使用 → 撤销（走完一条链）

- **前置**：一个已登录的账号（控制台会话）；一个已上线、该账号可读的 skill。
- **步骤**：
  1. 控制台新建一把 key（名字 `test`，scope 只勾 `skills:read`）→ 记下整串
  2. `SKILLMASTER_API_KEY=<整串> skill list` → 期望成功
  3. 控制台撤销它
  4. 同一条命令再跑一次
- **期望**：2 成功且结果里含那个 skill；4 得到 `401`，**不是 `403`**（它是没认证，不是权限不足），且**立刻**——不等任何过期。
- **判定**：通过／失败（失败时记下实际状态码与响应体）

### T2 · 只读的 key 写不了

- **前置**：一把只勾了 `skills:read` 的 key。
- **步骤**：用它跑 `skill submit <目录>`；再用一把**只勾了写**的 key 跑 `skill list`。
- **期望**：前者 `403`，且响应的 `WWW-Authenticate` 里 `scope` 说的是它缺的那个（`skills:write`）——与 v1 的 `InsufficientScopeIT` 同一个形状；**后者成功**（写蕴含读，而且是签发时补进库里的，不是鉴权层特判）。
- **判定**：通过／失败

### T3 · 停用当场生效，恢复当场恢复

- **前置**：一把可用的 key，且该账号此刻 `status = 'active'`。
- **步骤**：用它请求一次（期望成功）→ 把 `app_user.status` 置为 `suspended` → 再请求一次 → 恢复为 `active` → 再请求一次。
- **期望**：成功 / `401` / 成功。**第二跳是这条用例的全部要点**：它验的是「每次请求都看 status」，而不是「登录那一刻看过」。
- **判定**：通过／失败
- **附带**：同一个账号走 **OAuth 那条路**的令牌也要同时失效——`status` 这条判断对**两条路**都加了，只验一条等于没验。

### T4 · 整串只出现一次，库里只有哈希

- **前置**：无。
- **步骤**：新建一把 key 并记下整串 → 刷新页面、重新 `GET /web/keys` → 直接查库 `SELECT token_hash FROM api_key`。
- **期望**：两个响应里**都拿不到整串**；库里那一列是 64 位十六进制，**不等于**那把 key，也**不等于**它的任何可还原形式。另：`last_used_at` 在用过之后**会前进**（这是「列表看得见它」那一半）。
- **判定**：通过／失败

### T5 · 无浏览器环境里只用环境变量走完读链路（成立条件）

- **前置**：一台**没有浏览器、也没有显示器**的环境（容器即可）；一把已签发、勾了 `skills:read` 的 key；一个已上线的 skill。**这台机器上不跑任何登录命令。**
- **步骤**：只设 `SKILLMASTER_API_KEY` → `skill list` → `skill invoke <地址>` → `skill files <地址>` → `skill read <地址> <相对路径>`。
- **期望**：四步全通，**全程没有打开过浏览器**，也没有任何东西落盘（环境变量那条路不该写本机存储）。
- **判定**：通过／失败

### T6 · 反证：不带 `--with-key` 的 `login` 在这种机器上必须失败

- **前置**：同 T5 那台机器。
- **步骤**：跑 `skillmaster login`（不带参数）。
- **期望**：**失败**，而且失败信息**指向 `--with-key` 与环境变量**——不是一句浏览器打不开的裸错误。这条用例证明「v1 那条路在这种情况下确实走不通」，也就是 T5 通过是有意义的。
- **判定**：通过／失败

### T7 · 前缀路由与前缀本身

- **前置**：一把 key 与一张 OAuth 令牌。
- **步骤**：分别用它们请求；另造一串「以 `skm_` 开头但不存在」的字符串、以及一串「不含前缀的随机串」各请求一次。
- **期望**：两个真凭据各自成功；两个假串都是 `401`。**要点**：路由错**不构成放行**——决定权在哈希查询。
- **判定**：通过／失败

### T8 · 合约负例

- **前置**：两个账号 A、B；A 有一把 key。
- **步骤**：逐个发起：未登录调 `POST /web/keys`；写请求不带 CSRF；`scope` 传一个不认识的值；`expires_at` 传过去的时间；**用 B 的会话去 `revoke` A 的那把 key**；撤销一把已撤销的。
- **期望**：`401` / `403` / `400 invalid_scope` / `400 invalid_expiry` / **`404`（与「这个 id 不存在」同一个答案——不泄露存在性）** / `204`（幂等）。
- **判定**：通过／失败

### T9 · 继承 v1 的八条验收重跑

- **前置**：同 v1 的环境要求（一台没有装过任何 skill 的干净机器）。
- **步骤**：按 [`v1-hosting/test-plan.md`](../v1-hosting/test-plan.md) §用例 里的 T1–T4b 与各期用例，**在 v2 的凭据形态下**逐条重跑。
- **期望**：判定方式与 v1 **逐字相同**。**其中 T4（全程无本地副本）是 v1 的成立条件，本版继续成立**——注意「粘贴了一把凭据」不算副本，它是凭据不是 skill 内容。
- **判定**：通过／失败／未执行（每条单独记）

### T10 · 过期的 key 说清是「过期」，并指向续期

- **前置**：一把 key，把库里它的 `expires_at` 直接改到过去（不走时间机器）。
- **步骤**：用它请求一次。
- **期望**：`401`，而终端那句话**说清是「这把 key 过期了」并指向控制台续期**——不是裸的 `invalid_token`，也不是把它说成「已被撤销」（那是另一回事，处理方式不同）。
- **判定**：通过／失败

### T11 · 续期把一把过期的 key 换回来

- **前置**：一把 key，把库里它的 `expires_at` 直接改到过去（同 T10）。
- **步骤**：对它的 id 调一次 `POST /web/keys/{id}/rotate`，然后用返回的新整串请求一次。
- **期望**：`200`；新整串能调通；**新的 `expires_at` 是重新按签发默认值算出来的将来时间，不是旧日期搬过来的**（旧日期搬过来 = 仍旧过期 = T10 那句「指向续期」是句空话）；旧整串在下一次请求里 `401`；`GET /web/keys` 里那一行仍是**同一个 id 之外的一行新记录**、名字与 scope 不变，而旧的 `revoked_at` 非空。
- **判定**：通过／失败

### T12 · `GET /api/v1/me` 说得清「我是谁、手里是什么」

- **前置**：一个账号；一把 key（只勾了 `skills:write`，用来顺带验签发时补的读）；一张 OAuth 令牌（过渡期的 `login` 换来）。
- **步骤**：用 key 请求一次 `GET /api/v1/me`；用 OAuth 令牌再请求一次；再拿同一个会话去请求一次 `/web/session`。
- **期望**：都 `200`。`user` 三个字段与 `/web/session` 对同一账号给出的**逐字相同**（同一个 record，不是两份自述——两份会漂）。key 那次 `key` 非空，`name` / `expires_at` 与库里那一行一致，**`scope` 里含 `skills:read`**（只勾了写的那把，读是签发时补进去的）；OAuth 那次 `key` 为 **`null`**。两个响应里**都没有整串、也没有哈希**。
- **判定**：通过／失败

### T13 · 401 的五个取值与两处优先级

- **前置**：一把已撤销的、一把已过期但没撤销的、一个被停用账号下的可用 key；另外造两把复合的：**已撤销且已过期**、**账号已停用且已过期**。
- **步骤**：逐把请求一次，读信封里的 `error.code`；再各请求一次「不带凭据」与「一串以 `skm_` 开头但库里没有的」。
- **期望**：依次 `token_revoked` / `token_expired` / `account_suspended` / **`token_revoked`** / **`account_suspended`** / `unauthenticated` / `unauthenticated`。**两处优先级都要判**——只验单独成立的那三个等于没验优先级，而优先级正是「先报那个有人做过的决定」这条理由的全部内容（撤销、停用是人做过的动作，过期只是时间到了）。另：`WWW-Authenticate` 与今天**逐字相同**（`error="invalid_token"`，不带 description）——原因只有一处权威，就是信封的 `code`。
- **判定**：通过／失败
- **附带**：这条同时是「存活判断搬进代码」的回归网——那三条判断如今没有 SQL 谓词兜底，漏掉任何一条就是**放行一把死 key**，而这条用例会让它当场现形。

### T14 · `login --with-key` 先验后存；验不过就什么都不动

- **前置**：一台**本机已有一份可用凭据**的机器；一把已撤销的 key；一把好的 key。
- **步骤**：① `printf '%s' '<已撤销的那把>' | skillmaster login --with-key`；② 紧接着跑一条需要鉴权的命令；③ 换成好的那把再登一次；④ `skillmaster auth status`。
- **期望**：① **失败**，信息说清「已撤销」并指向控制台新签一把；**本机原来那份凭据一个字节没动**——② 证明这一点（命令照常成功）。③ 成功，印出用户名与这把 key 的名字 / 权限 / 到期日。④ **两半都说清**：本机那份来自本机存储、服务端那把的名字与到期日与 ③ 印出的一致。
- **判定**：通过／失败
- **附带（反证）**：把 stdin 喂成一串**形状对但库里没有**的（`skm_` + 43 个字符）→ 同样必须**拒绝存**。只校验形状会让一把打错的 key 悄悄进钥匙串，而失败要等到下一次命令才现形。

### T15 · 撤销之后终端说的是「已撤销」，不是「过期」

- **前置**：T10 那把**已过期**的 key，与另一把**已撤销但离过期还早**的 key。
- **步骤**：分别用它们跑一条需要鉴权的命令；再对第二把跑一次 `auth status`。
- **期望**：第一把 → 说清「**过期**」并指向控制台**续期**；第二把 → 说清「**已撤销**」并指向**新签一把**。**两句话必须不同**——它们指向的动作不同，一样就等于验收 #1 没做。而且**两句都不是 `ErrNotRenewable`** 那句「请重新运行 `login --client-credentials`」：key 这条路本版不走续期。`auth status` 对第二把要说清「服务端不认它（已撤销）」。
- **判定**：通过／失败
- **附带**：这条同时钉住「本机存的那份 `expires_at` 不是判据」——第二把离过期还早，本地那个日期推不出「撤销」，只有服务端答得上来。

### T16 · 有效期是上限，不只是默认值

- **前置**：一个按 ADR 0042 配了 `lifetime`（默认 90 天）的部署。
- **步骤**：① 带 `expires_at = 9999-12-31T00:00:00Z` 签发；② 带**控制台表单会送的那一天**（`lifetime` 天之后那一天的 23:59:59，控制台写日期的那个时区）签发；③ 带那之后一天的同一时刻签发；④ 不带日期签发。
- **期望**：① `400 invalid_expiry` / `beyond_maximum`——**拒绝而不是截断**：截断会交回一把不是所问的那把 key，而响应里没有一个字说这件事。② **成功**——这一条是这条用例真正的边界：上限是「某一天的结束」而不是 `now + lifetime`，后者会在当天已过去的那几秒上把②拒掉，而②正是控制台一个字都不改点提交时送的那一次（第二轮审计实测过这个失败）。③ 拒绝（界是闭的，且只到那一天为止）。④ 成功，到期日 = `now + lifetime`。
- **判定**：通过／失败
- **附带**：这一条钉的是**运维的配置不被调用方绕过**。`expire: false` 的部署没有上界（关掉开关就是「这个部署不管有效期」），那条由 `ApiKeyPolicyTest` 钉住。

## 环境与数据

- **环境怎么造**：T5/T6 需要一台**没有浏览器**的机器——容器最省事（`docker run` 一个只有 CLI 的镜像）。**这台环境本身就是被测对象**，所以在有浏览器的开发机上跑等于没跑。T9 另需一台**没有装过任何 skill** 的机器（同 v1）。
- **另需两样**：T14 要求那台机器**本来就已经有一份可用凭据**（「验不过什么都不动」这句话只有在有东西可动的时候才验得出来）；T12 要求手上**同时有一张 OAuth 令牌**——用那个过渡期的 `login`（不带 `--with-key`）在一台有浏览器的机器上换一张，它正是 `key: null` 那一半的被测对象。
- **数据**：至少一个真实的、含 L3 文件的已上线 skill。**不要用手写的玩具 skill**——理由同 v1（测不出渐进加载的真实收益）。
- **清理**：T1–T8 会产生 key 行与审计行；它们**不需要清理**（撤销是状态不是删除，撤了就行）。T9 的清理同 v1（两次目录快照都要留档）。

## 结果

**三个组件都实现完了；「真机联调」那条主线 2026-10-15 在本机真服务端上走通过一遍，剩下的几条按下面的口径未执行。** 那天走的是验收 #1 的整条链，全部对着 `:8080` + 本地 Postgres：控制台签发一把真 key → `login --with-key` 先验后存 → `skill list` 读通 → 用可写的 key `skill submit` 提交一版 → 在控制台（会话 + CSRF）把它上线 → 用只读的 key `list` / `invoke` / `read` 读回正文与引用的文件；途中把三句拒绝语各触发一次（撤销 / 过期 / 停用），并验证只读的 key 写被拒（服务端回 `skills:write`）、可写的那把在 `auth status` 里显示 `skills:read skills:write`（只发了 write——写蕴含读是服务端签发时补的）。**「本机」不等于「线上」**：这一遍不含 TLS、不含反代、不含托管库，所以它是 T14/T15/T6 那几条的真机证据，不是部署环境的证据。**仍没跑的**：T5（一台真的没有浏览器的机器）、T9（v1 的八条重跑）、以及部署环境上的一切。 本版分四期（[`technical-design.md`](technical-design.md) §分期）：服务端（P0）在真实 HTTP 上跑通；控制台（P1）与 CLI（P2）**代码写完、各有测试覆盖**（控制台 318 条、CLI 176 条顶层用例），但用例原文要的那几台机器（没有浏览器的容器、本来就有凭据的机器）**一台都还没跑**——下表把这两件事分开写，因为组件测试证明不了的正是「这台环境本身就是被测对象」那部分。

**四个数字各自的口径**（§2.3 规则 6，定义变了数字就变）：服务端单元 = surefire 的 `Tests run` 合计（`mvn -o verify`，跑在真实 PostgreSQL 上）；服务端集成 = failsafe 的合计；控制台 = `npx vitest run` 报的 `Tests` 数；CLI = `go test ./... -v` 输出里顶层的 `--- PASS` 行数（表驱动的子用例不另算）。都取最近一次全量跑。

**三轮独立审计（2026-10-15）。** 第一轮 4 个互相不知情的审计者分头读（服务端内部 / CLI 内部 / 控制台内部 / 三端接缝），**34 条报告、去重后 29 条**；第二轮 3 个全新审计者、且被告知第一轮改了哪些地方，**16 条报告、去重后 15 条**；第三轮 2 个全新审计者盯第二轮的修复与「文档与代码是否字字相符」，**10 条报告、去重后 9 条**。**三轮各有 blocker/high，而其中两条 blocker 与一条 high 是上一轮的修复自己带出来的**（见下）——这正是「每轮换新人、并告诉他们上一轮改了什么」要抓的东西。每条都由我复核后才动手，**每条修掉的都配一条会因它而失败的测试**：把修复回退、看那条测试当场失败（三轮共 24 处反证，记在下面各行的证据里）。三条最贵的：

- 并发续期会留下**两把活的 key**（`ApiKeyIT.twoRenewalsAtOnceLeaveExactlyOneLiveKey` 在回退后当场复现出两个 201、两个不同的整串）；
- 「离开那一刻时只放下筛选、没放下搜索」——刚建的 key 在落回的列表上不可见，而屏幕上一秒前刚说「已创建」；
- **第一轮自己引入的 blocker**：ADR 0042 的上限实现成 `now + lifetime`（一个瞬间），而控制台表单送的是「那一天的结束」——默认表单**每一次提交都 400**。第二轮的服务端与网页两位审计者各自独立算出了同一个结论，两边的算术都对（差的正是当天已过去的那些秒）。修法见 ADR 0042 §决定 2（并把这一天改成服务端算好、随 `latest_day` 公布），反证是把上限改回那个瞬间、`the date the console's form preselects` 那条断言当场 400；
- **第一轮自己引入的 high**：`logout` 把「读不到本机凭据」折成了「本机没有凭据」，于是在钥匙串锁着的机器上打印「本机没有凭据，没什么可清的」并退出 0，而凭据还在、后续命令照常认证成功。删掉这一步的报错在 `responsiveKeychain.Delete` 里**按设计返回成功**，所以下游也不会补报；
- **第二轮自己引入的 blocker**：`login` 里那条「以 `-` 开头一律拒绝」的兜底写在了 `--with-key` 与 `--client-credentials` **之前**，Go 的 switch 按顺序求值，于是本版唯一的凭据来源被它自己的守卫拒掉——而 `go test ./...` 全绿，因为测试都直接调 `loginWithKey`/`loginWithBrowser`，没有一条走 `login` 的派发（现在有了）。同一条兜底还把 `--with-key=skm_…` 的密钥原文回显进 stderr，而它存在的理由正是「别让密钥出现在能被人看到的地方」。

**判定为「不改」的**见 §已知问题。

**第四轮（同日，收尾轮）。** 第三轮出了 CONFIRMED 的 blocker/high，按同一规则再起一轮：2 个全新审计者（CLI + 服务端 / 控制台 + 文档），**17 条报告、没有 blocker/high**——循环到此收敛（四轮，上限五轮）。四条 medium 与一批 low，全部已修，各配一次「把修复回退、看测试当场失败」的反证（本轮 13 处）。四条 medium：

- **`defaultExpiry` 能返回一个已经过去的时刻**：`lifetime` 的 `toDays()` 截断为 0 时（例如 `PT12H`），上限落在**今天**，而今天在 23:59:59 之后已经过去了；**续期请求不带日期、必然走默认值**，于是铸出一把出生即过期的 key、控制台一列出来就是「已过期」。修在启动时——不到一整天的 `lifetime` 直接拒绝（[ADR 0042](../../decisions/0042-the-expiry-setting-is-a-cap.md) §后果）。
- **三个上层派发点仍把整串参数回显**（`未知的子命令 %q`）：`--with-key=skm_…` 写漏一层，整把密钥就进了终端与 CI 日志——正是上一轮给 `login` 兜底要挡的那件事，差一层没做。修成 `namedArgument`：像密钥的参数只描述不重复，普通拼写错误照旧引号回显。
- **`logout` 可以在钥匙串删不掉时报「已清除本地凭据」**：`responsiveKeychain.Delete` 超时那条分支按设计返回成功，而它的理由——「撤销已经发生，留下的是死令牌」——属于 v1；v2 的 `logout` 根本不联系服务端（ADR 0038 §决定 4），留下的是**一把可用**的 key。改成把「文件那份清了、钥匙串那份没动」说出来并退出非 0。
- **控制台在响应里没有 `policy` 时抛异常**：异常发生在 `state = 'ready'` 之后，所以列表照常渲染、看着正常，而 `onMounted` 剩下的部分再没执行——Escape 从此不能取消确认，异常只落在控制台里。

还有一条**测试自己的缺陷**，记在这里是因为它的症状不在 CI 里：`go test ./...` 会读**本机真实钥匙串**（走真 `login` 的那条派发用例），而 macOS 对每次新编出的未签名二进制都要重新授权，于是开发机上**每跑一次测试就弹一次钥匙串授权框**。修法是在 `openStore` 上开 seam、`TestMain` 指向内存 store，并配一条 canary 钉住它（删掉那一行，测试当场红）——那条用例的耗时从 5.05 秒（`keychainDeadline` 打满）回到 0.00 秒。

**一条口径上的自陈。** [ADR 0042](../../decisions/0042-the-expiry-setting-is-a-cap.md) 的正文在第三、四轮里被**就地改写过**（§决定 1、2、5 与 §后果各一处），而 `docs-architecture` §2.2 说 ADR 正文一经写下不再改动。判断是：这条 ADR 与它描述的实现**都还没进版本库**，此刻它仍在「写」的阶段，改它等于把话说准；提交之后正文就不该再动。若认为该按字面办，正确做法是把这几处拆成一条 0043——我没有这么做，并把这件事写在这里，而不是留在提交记录里。

## 已知问题

- **「那一刻」用「选中」这条回退路时，「完成」永远点不动**（`已修复`，2026-10-15）。两种复制 API 都够不到时（明文 http 的非安全来源、被 iframe 策略挡住的嵌入），页面说「已选中，请按你的复制快捷键」，而出口仍然绑在「复制过」上——人按了 Ctrl+C 也点不动它，只能走那一刻屏自己的面包屑或侧栏。**它原先记的是 `已接受`，理由是「与参照产品一致」（它的 `Done` 也绑在 `copied` 上），而那个理由只说了出口的初始前提，没说「选中」这条回退路该怎么办**：设计稿自己那条回退路里，出口是开的（打开它、并把按钮文案换成「完成」），也就是说设计稿把**「选中」也算整串已经在读者手上**。现在产品与设计稿同一条：出口的前提从「复制过」改成「已在手上」（复制成功，或已选中并说清了要按哪个键），**一个事实一处表达**——出口禁用与「离开前是否要问」由同一个 `held` 决定，而这两条原先各写各的（于是同一个状态下，出口锁着、离开却不问）。复现（修复后应为：点复制 → 出口变「完成」可点 → 离开不再被问）：`navigator.clipboard` 与 `document.execCommand` 都取不到的环境里，新建一把 key 并点复制。
- **`BrowserAvailable` 仍在近似一件事**（`部分修复`）。第一轮它只问「打开链接的程序在不在」，于是装了 `xdg-open` 却没有 `$DISPLAY` 的容器（CI 常见）会走到五分钟超时；**第二轮补上了 Linux 那一半**（无 `DISPLAY` 也无 `WAYLAND_DISPLAY` 即视为没有浏览器，`internal/auth/browser_test.go` 钉住五种组合）。剩下的缺口是反过来的：有显示器、`xdg-open` 在、但**没有装任何浏览器**——那时 `xdg-open` 自己失败，cli 仍会等超时。要覆盖它只能真去调一次启动器（会真开窗或真失败），而那样的探针在有浏览器的机器上有副作用，所以这一版不做。复现：Linux 桌面、`DISPLAY` 已设、`xdg-open` 在、没有任何浏览器。

范围外的历史代码缺陷在 [`v1-hosting/known-issues.md`](../v1-hosting/known-issues.md)。
