# v2-credentials · 第一方的默认凭据换成用户自己签发的 API key

> **最后更新**：2026-10-15
> **状态**：进行中（设计已定稿，**尚未实现**）
> **含收费**：否

## 目标

把**第一方的默认凭据**从「CLI 走浏览器拿一对 OAuth 令牌」换成「**用户在控制台自己签发的 API key**」：控制台签发、粘贴给 CLI、任何环境都能用、撤销与 last-used 看得见。

**托管、检索、读取面与作者面继承 [`v1-hosting`](../v1-hosting/README.md)，本版不动。** 完整需求见 [`prd.md`](prd.md) §用户与场景。

## 验收标准

一句话：**在一个没有浏览器的环境里，只用一把粘贴进来的 API key，agent 自己搜到、读到、用完某个 skill。**

完整验收见 [`prd.md`](prd.md) §验收与指标（映射见 [`test-plan.md`](test-plan.md) §验收映射）。

**成立条件是新增的那条「无浏览器环境」。** 它不是附带要求——v1 那套（loopback 回调）在那样的机器上**结构性地跑不起来**，所以这一条验的正是「换形态有没有换对」。v1 那条成立条件（全程无本地副本）同时继续成立。

## 这一版明确不做什么

最要紧的三条；**完整范围与每条的理由见 [`prd.md`](prd.md) §范围**。

- 不做**组织拥有的 key**——它要一个合成用户，而那属于组织模型（[ADR 0038](../../decisions/0038-default-credential-is-an-api-key.md)）
- 不做**设备授权码**——它没有独占场景，key 覆盖了它的全部（同上）
- 不做 **CIMD 与 MCP 适配器**——第三方接入仍是 P2；OAuth 那条路本版**保留但不新增**

## 与目标态的关系

[`target/`](../../target/README.md) 描述的是完整形态。本版与 v1 站在同一处：**v1 是目标态的真子集，v2 与 v1 的差别只在凭据形态**，所以 v1 那几条分叉（`l2#n` 已砍、本地 Gate 模型已换掉、`unlisted` 已放弃）本版照旧。

**本版新引入的一处分叉**：目标态的权限是「个人 / 组织 / 公开」三层再叠权益与钱包，而本版的 key **只属于一个人**——组织那一档明确留给组织模型。差异记在 [`target/README.md`](../../target/README.md) 的差异清单里（第 9/10 条那一带）。

## 影响最大的未决问题

完整列表与当前倾向见 [`technical-design.md`](technical-design.md) §开放问题。最要紧的三条：

1. **「谁有权签发」只答了一半**——第一方（用户签自己的）由本版答；**组织那半**要等组织模型，而它一旦到来，key 的行主会从「一个人」变成「一个合成用户」。这一条要写进 ADR 与 TD，否则半年后会有人以为只是漏做。
2. **`last_used_at` 的写入节流窗口取多少。** 它是**鉴权路径上的写**，而那条路今天只读。窗口太短等于每次请求写一次，太长则「刚用过没有」会骗人。参照产品的取值是 10 分钟。
3. **`app_user.status` 每次请求都看**之后，「停用」的语义才真正闭合——但**停用一个账号的入口至今只有一个用例**，而本版让它的必要性从「债」变成「必需」。
