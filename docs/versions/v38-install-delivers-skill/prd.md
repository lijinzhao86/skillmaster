> **最后更新**：2026-11-02
> **所属版本**：[`README.md`](README.md)

## 用户与场景

**谁在用**：第一次接触 SkillMaster 的人。官网首页给的是一句话：「根据 https://skillmaster-dl.oss-cn-hangzhou.aliyuncs.com/beta/skillmaster.md 安装 SkillMaster。」他把这句话交给自己的 Agent。

**在什么场景下用**：Agent 读那份安装文档 → 装 CLI → 跑 `skmr startup` → 接上这个 Agent。

**现在的替代做法是什么**：`skmr startup` 会往用户的全局记忆文件（Claude Code 是 `~/.claude/CLAUDE.md`）写一段说明。

替代做法的四个代价：

1. **改了用户的文件**——装一个工具顺手改了他的全局配置；
2. **写进去就旧了**——那是一份快照，CLI 行为变了也传不到老用户；
3. **不跨端**——每个 Agent 的路径与格式都不一样，要各写各的；
4. **难撤销**——要删就得从用户自己的文件里挑出那几行。

第 1 条对本产品的目标用户（不懂技术）格外重：这是整个过程里唯一一次动他自己的东西。

## 范围

### 做

| # | 做什么 | 交付形态 |
|---|---|---|
| 1 | 技能源进入仓库 | `skills/skillmaster/`（SKILL.md + `sop/01…06`） |
| 2 | 构建一个可分发的技能包并放到站点 | `skillmaster-site/public/skill/skillmaster.tgz`，部署时上传到下载桶，公网地址 `https://skillmaster-dl.oss-cn-hangzhou.aliyuncs.com/beta/skillmaster.tgz`（`www` 上留同一次构建的副本，文档不指向它） |
| 3 | 改写安装文档的流程：欢迎 → 确认 → 装技能 → 装 CLI → 登录 → 迁移 → 收尾 | `skillmaster-site/public/install/skillmaster.md` |
| 4 | 技能**优先装到用户级技能目录**（所有项目都能用）；客户端只有项目级目录时，装到当前项目，并告诉用户「只在这个项目里生效」 | 同一份文档的步骤与验收 |
| 4b | 装技能那一步要覆盖**所有客户端**：能直接写目录的、只能通过界面导入的、根本没有技能机制的，三种各有分支 | 同一份文档的步骤 |
| 4c | **两个前提都放在欢迎之前检查（任一不满足就停）**：客户端能装技能、这台电脑能装客户端（64 位且系统受支持）。任一不满足就说一句「装不了」并结束，不再请人确认 | 同一份文档的「0 · 先做两个检查」 |
| 5 | 安装文档的「话术定稿」相应更新，含「Agent 会自动按需查找技能；要强制调用时用 `/skillmaster`；这个技能只对这台电脑的这个 Agent 有效，换电脑或换 Agent 要再装一次」 | 同一份文档 |
| 6 | `skmr startup` 旅程去掉「写全局记忆」一步，只留登录与导入技能 | 在线技能 `skillmaster/skillmaster-startup` 创建并发布 |
| 7 | 技能正文 `sop/06-install.md` 与安装文档对齐（话术仍以文档为准） | `skills/skillmaster/sop/06-install.md` |

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | 维护「Agent → 技能目录」的路径表 | 每个 Agent 自己知道自己的技能目录在哪，维护一张表等于把它的知识抄一份到我们这里，还会过期 | 不做 |
| 2 | 技能的自动更新 | 更新要判断「用户改过没有」，那是另一个问题；本期只有重走安装 | 未定 |
| 3 | 改首页那句**提示** | 提示语「复制下面这句，发给你常用的 agent。」不变；安装指令正文的地址随本版改到下载桶（ICP 未过期间的临时办法），控制台没有安装页 | 不需要 |
| 4 | 删除 `skmr prompt` 命令 | 它暂时没有调用方，但删命令属于对外契约变更，与本版目的无关 | v39 或确认无人使用后 |
| 5 | Windows 真机验证 | 本机没有 Windows 机器；`tar` 与 `install.ps1` 的行为未验 | 有机器时 |

## 控制台操作与 CLI 对应

本版**不新增、不修改任何控制台操作**——控制台没有「安装」这一屏，安装全程在用户的 Agent 里完成。因此本节没有映射行。

（本表存在本身是 ADR 0081 的要求：新增控制台操作必须附 CLI 命令。本版没有新增，故为空。）

## 验收与指标

### 验收标准

| # | 验收标准 | 怎么判定 |
|---|---|---|
| 1 | 在装过 SkillMaster 的干净 Agent 上走完流程，技能文件落在该 Agent 的技能目录 | 目录里存在 `skillmaster/SKILL.md` 与 `sop/01`–`06` 共 7 个文件 |
| 2 | 装完后，SkillMaster 出现在这个 Agent 的技能清单里 | 新开一个会话，让 Agent 列出技能，列表含 `skillmaster` |
| 3 | **用户的全局记忆一个字节没变** | 流程前后对 `~/.claude/CLAUDE.md` 取 sha256，值相同；且文件内不含旧说明的首句「SkillMaster 管我的全部 skill」 |
| 4 | CLI 装上并能跑 | `skmr --version` 有输出；`skmr auth status` 能给出登录状态 |
| 5 | 技能包可复现 | 同一份技能源构建两次，`tar.gz` 的 sha256 相同 |
| 6 | 解包失败时不留半套 | 目标目录不可写时，话术说清「停在哪、什么都没装成、以后怎么继续」，且技能目录里没有残缺文件 |
| 7 | `startup` 不再写记忆 | 新版 `skillmaster/skillmaster-startup` 正文里不出现「写进记忆」「全局说明」这类步骤 |
| 8 | 用户级目录可用时，技能装**用户级**而不是项目级 | 在一个项目目录里新开会话能看到 `skillmaster`；该项目的技能目录里没有 `skillmaster/` |
| 8b | 客户端只有项目级目录时，装到当前项目并告知只在本项目生效 | 该客户端上：当前项目的技能目录里有 `skillmaster/`；对话里出现了「只在这个项目里生效」这句 |
| 9 | 装完告诉用户「自动按需查找」「`/skillmaster` 强制调用」，以及**适用范围**（只对这台电脑的这个 Agent 有效；换电脑或换 Agent 要再装一次） | 话术定稿含这三句，且装机时确实说过 |
| 10 | 两个前提（客户端支持技能、电脑能装客户端）任一不满足，**都在欢迎之前**停下 | 对话第一条话术是第 22 行（不支持技能）或第 16 行（机器装不了）；没有开场白、没有确认、没有任何安装动作 |
| 11 | 判断不出技能目录时不装，也不向用户索要路径 | 文档里有该分支与话术；走查时这一路不会出现「告诉我要装到哪」这类问句 |

**成立条件**：**第 3 条不满足就不算交付**——本版的目的就是去掉这次改写。

### 指标

| 指标 | 定义 | 怎么量 | 目标 |
|---|---|---|---|
| 首次安装完成率 | 从说出开场那句，到 `skmr --version` 成功 | 人工记录每次装机的结局 | 10 次里 ≥9 次 |
| 安装耗时 | 从开场到 CLI 可用 | 同上，记录分钟数 | 中位数 ≤5 分钟 |

（两个指标都以人工装机为口径，不包含自动化测试；样本量写清是因为它只来自个位数装机。）

## 依赖与前置

- **外部依赖**：站点能托管静态文件（现在 `public/install/skillmaster.md` 就是这么发的）；安装文档、技能包与安装脚本都走下载桶（`skillmaster-dl` 的 `beta/` 前缀）——`www` 会重置只用 TLS 1.2 的客户端，而 ICP 备案尚未通过。`www` 上留同一份。
- **内部前提**：本版的核心取舍见 [ADR 0129](../../decisions/0129-onboarding-delivers-a-skill-not-a-memory-line.md)；控制台与 CLI 的对应规则见 [ADR 0081](../../decisions/0081-every-console-operation-has-a-cli-command.md)。
- **排除了什么前置**：不需要新的服务端接口——技能包是静态文件；不需要新的 CLI 命令——安装仍然由 `install.sh` / `install.ps1` 完成。
