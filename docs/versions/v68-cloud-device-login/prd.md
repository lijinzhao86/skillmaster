# v68-cloud-device-login · 产品需求

> **最后更新**：2026-11-14
> **所属版本**：[`README.md`](README.md)

## 用户与场景

**谁在用**：在云端设备上使用 agent 的人——云主机、容器、云端沙箱（如 WorkBuddy 云端工作）、云电脑（如 Grok Bot）。其中多数不写代码，也不维护服务器。

**在什么场景下用**：agent 装好 SkillMaster 的技能后，第一次需要凭据。这台机器没有可用的浏览器，或者浏览器不在这台机器上；用户手上通常有一台能上网的手机或笔记本。

**现在的替代做法是什么**：桌面走浏览器回环登录；服务器只能去控制台「API 密钥」页新建一把、复制、回终端粘贴。对不写代码的新用户，这条路要求他知道「密钥」是什么、去哪找、粘到哪；对共享的云电脑，一把 key 还会被所有 agent 共用。替代做法不足以覆盖这一版要解决的人。

## 范围

### 做

| # | 做什么 | 交付形态 |
|---|---|---|
| 1 | 设备批准登录：CLI 发起，打印一条**一次性链接**，用户在任意浏览器打开并批准，CLI 轮询取回凭据 | CLI + 服务端 |
| 2 | 链接直通现有「授权请求」屏（带一次性令牌）；未登录先登录或注册，再回到同一页 | 控制台 |
| 3 | 待批准状态：10 分钟过期、一次性、轮询限速；页面的 GET 不改变任何状态；**Ctrl-C 取消让票根立刻不能批准**（与批准同时到达时，先落下的赢，取消把已批准未领取的那次收尾） | 服务端 + CLI |
| 4 | 桌面与云桌面自动打开浏览器；打不开不影响流程，链接始终在屏幕上 | CLI |
| 5 | 登录进入控制台「登录设备」，可单独撤销；「退出其他所有设备」也结束它 | 控制台 + 服务端 |
| 6 | 回环登录退役：CLI 不再监听 `127.0.0.1`，固定回环端口不再使用 | CLI + 服务端 |
| 7 | 安装说明增加云端分支：什么时候会看到链接、终端里该说什么 | 文档 |
| 8 | 决策记录：新 ADR 取代 [ADR 0028](../../decisions/0028-cli-uses-a-fixed-loopback-port.md) 与 [ADR 0044](../../decisions/0044-the-cli-serves-desktops-and-servers.md) §决定 1 | 文档 |

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | 移动端 App | 批准只需要一张网页；App 会带来第二套客户端、授权与存储，收益不成比例 | 不做 |
| 2 | 终端二维码 | 链接点一下就到；二维码只省打字 | 未定，先看真实反馈 |
| 3 | 宿主注入凭据（如 WorkBuddy 沙箱的令牌） | 需要逐个宿主适配，不能作为通用解 | 未定；通用流程成立之后再叠 |
| 4 | 取消 API Key | 无人值守（CI、常驻服务）没有人在场，设备码的前提不成立 | 不做，长期保留 |
| 5 | 保留第二套回环登录 | 两套流程会漂；回环在沙箱里等满五分钟是已发生过的故障 | 不做 |
| 6 | 第三方 OAuth 客户端改用设备批准 | 那是另一条授权路径（同意页），本版不动 | 未定 |
| 7 | 撤销某一条登录的 CLI 命令 | 撤销改变「谁能调用」，属 ADR 0081 的高风险例外，留在控制台；CLI 的 `logout` 只结束本机这一次 | 未定；要做先定命令形状 |
| 8 | 短码与短码输入页 | 链接已经带一次性令牌，让用户抄写只会多一步出错；短码也不比链接更安全 | 不做 |

## 控制台操作与 CLI 对应

| # | 控制台操作 | CLI 命令 | 备注 |
|---|---|---|---|
| 1 | 打开一次性链接并发起一次登录批准 | `skmr login` | 同一件事的两端：CLI 发起并等待，网页是人的同意。批准本身不由命令代替，CLI 侧对应的是 `Ctrl-C` 取消 |
| 2 | 「登录设备」撤销一条 | 无 | 高风险例外（[ADR 0081](../../decisions/0081-every-console-operation-has-a-cli-command.md)）：撤销改变谁能调用；见「不做」第 7 条 |
| 3 | 「退出其他所有设备」 | 无 | 高风险例外，同上 |

## 验收与指标

### 验收标准

| # | 验收标准 | 怎么判定 |
|---|---|---|
| 1 | 在没有可用浏览器（无启动器或无显示服务器）的 Linux 机器上运行 `skmr login`，不尝试打开浏览器、不监听端口，打印一条含完整链接的句子，进入等待 | 在无 `DISPLAY` 的容器里跑，观察终端输出与端口 |
| 2 | 用户在另一台设备批准后，CLI 在 2 秒内完成登录并打印账号 | 记录服务端标记批准到 CLI 打印「已登录」的时间 |
| 3 | 等待期间 `Ctrl-C` 可取消；取消后这次待批准不可再被批准（取消与批准同时到达时，先落下的赢，取消会把已批准未领取的那次结束掉） | 取消后在浏览器打开该链接，页面说明已失效 |
| 4 | 链接一次性、10 分钟过期；第二次打开、过期后打开、批准后再次打开，页面各有固定文案，CLI 各以同一句「这次登录没有完成…」和退出码 1 结束 | 分别构造四种情况，核对页面文案、终端输出与退出码 |
| 5 | 在批准页点「拒绝」，不产生授权，CLI 报「这次登录没有完成」并让人重新运行 `skmr login` | 走一次拒绝，检查授权表无新行、终端输出 |
| 6 | 批准页显示设备名（可改）、**请求来源地址与发起时间**、权限的人话、当前账号，并写明「这条链接别转发」 | 打开页面逐项核对 |
| 7 | 未登录或没有账号的人能在同一页完成登录或注册并回到批准；全过程不需要新建 API Key | 用全新手机号走一遍注册 → 批准 |
| 8 | 登录出现在「登录设备」；撤销后，那台机器下一条命令失败（401）并提示重新运行 `skmr login`，**不会自己发起新的批准** | 撤销后在原机器运行 `skmr auth status` 与一条读命令 |
| 9 | 桌面有浏览器时自动打开；打不开时链接仍在屏幕，流程不受影响 | 在桌面跑一次；再模拟启动器缺失跑一次 |
| 10 | **命令自己发起的登录**只在「有人在场且能打开浏览器」时发生：检测到沙箱、`CI` 环境变量、或没有可用的浏览器时都不发起，改为指向 `skmr login` 与 API Key；**用户明写的 `skmr login` 到哪都打印链接**，因为链接可以在别的设备上打开；这套门禁只约束「命令要不要自动起登录」，不是按浏览器的凭据分流（ADR 0200 §决定 3 管的是登录流程本身） | 在 `CI=true`、沙箱、无浏览器的环境各跑一条需要凭据的命令 |
| 11 | 两台设备不在同一网络（CLI 在云上、浏览器在手机上）也能完成 | 用云主机与手机构造 |

**成立条件**：第 1、2、5、8 条全部满足才算交付。

### 指标

| 指标 | 定义 | 怎么量 | 目标 |
|---|---|---|---|
| 批准到完成的时间 | 服务端把待批准标为 approved，到 CLI 打印「已登录」 | CLI 日志与审计时间戳之差 | ≤ 2 秒 |
| 新用户不建 key 的比例 | 用设备批准完成登录的账号里，没有新建 API Key 的比例 | 对比同账号的 key 创建记录 | 100% |

## 依赖与前置

- **外部依赖**：控制台域名与 HTTPS；手机号短信验证码（注册已有）；用户手上有一台能上网的设备。
- **内部前提**：[ADR 0200](../../decisions/0200-cloud-device-login-approves-on-a-web-page.md)（本版新增，取代 0028 与 0044 §决定 1）；现有授权请求屏与「登录设备」列表；[ADR 0185](../../decisions/0185-credentials-default-to-a-file.md) 的凭据存储。
- **排除了什么前置**：不需要移动端 App；不需要宿主（WorkBuddy / Grok Bot / 千问 Go）配合；不需要二维码。
