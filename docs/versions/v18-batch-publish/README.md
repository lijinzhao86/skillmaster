# v18-batch-publish

> **状态**：进行中，**实现已完成、循环审计已走完第三轮**（2026-10-25）。三份文档、设计稿（`design/` 的待上线页与「确认 → 执行 → 结算 → 流断了」四态）、服务端 / CLI / 控制台都已落地；服务端与 CLI 的自动化测试跑过，控制台页面**已由产品负责人看过并确认**（2026-10-25；见 [`test-plan.md`](test-plan.md) §结果）。**2026-10-26 修了一处本版范围内的缺陷**：批量上线的行在真实传输上没有逐条到达（`iterations/0001`）。

## 目标

一句话：**让「攒了一批草稿，一次发出去」成为一件做得完的事**——版本号在发布那一刻按草稿声明的版本类型算，一处队列看全、一次确认、逐条结果。细节见 [`prd.md`](prd.md)。

## 这一版明确不做什么

| 不做 | 原因 |
|---|---|
| 提交流程之外预分配版本号 | ADR 0055 否掉过：草稿占号、丢弃烧号。`release_type` 不占号，这是两者的分界 |
| 从预发布版本往上递增 | 各家做法不同；基线带预发布标记时要求显式给号 |
| 批量丢弃草稿 | 丢弃一票不可反悔（ADR 0031 决定 5），不该批量放行 |
| 批量下架 / 上架 | 是另一个动作（ADR 0058），没有被要求 |
| 定时 / 自动发布 | 发布要保持"人在场的一次动作" |
| 批量的 CLI 命令 | 高风险例外（[ADR 0081](../../decisions/0081-every-console-operation-has-a-cli-command.md) 例外 1）：发布改变 agent 能读到什么，ADR 0031 规定它只在浏览器面。**队列的读**不在例外里，有 `skills pending` |

## 验收标准

见 [`prd.md`](prd.md) §验收与指标——26 条，分成「版本类型」与「待上线队列」两组。核心语义是三条：**算号在发布那一刻**、**逐条成功或失败**、**结果回实际号而不是预演**。

## 与目标态的关系

与 `docs/target/` 无直接关系。这一版改的是「发布」这个既有动作的两个面：号从哪来、以及一次能做几次。
