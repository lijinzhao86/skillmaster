# v64-feedback · agent 卡住时，把问题写下来交给平台

> **最后更新**：2026-11-13
> **状态**：进行中（已实现；服务端与 CLI 自动化测试通过，隐私页视觉验收（T8）与无凭据指引（T11）未执行，见 [`test-plan.md`](test-plan.md) §结果）
> **含收费**：否

## 目标

给 CLI 一组 `skmr feedback`（`send` / `template` / `delete`）：agent 或用户遇到解决不了的问题时，写一份反馈文档提交给平台，平台落库；运营按回执号或时间范围查库。细节见 [`prd.md`](prd.md)。

## 验收标准

模板可打印；能按文件或标准输入提交并返回受理编号；不带 `--consent` 只预览不发送；提交后给用户回执与「撤回并删除」；同账号按小时限流；隐私政策新增一节；内容长期保留并归档对象存储。完整验收见 [`prd.md`](prd.md) §验收与指标。

**成立条件**：验收 #2、#5、#7、#8、#14 任一条不满足就不算交付（提交、预览、运营可查、隐私条款、回执与删除各一）。

## 这一版明确不做什么

摘要三条最要紧的；完整范围与每条的理由在 [`prd.md`](prd.md) §范围。

- 不做对外举报入口 —— 举报是另一条路径；今天公域内容以开源导入为主，有问题可以回到上游仓库
- 不做未登录与匿名提交 —— 不知道是谁提交的会产生噪声、污染数据，也无法回访；登录不可用时指引发邮件
- 不做浏览器批准与严格模式 —— 本版选 agent 通道 + 事后回执，平台不宣称「每次都有用户本人同意」
- 不做运营邮件推送 —— 运营直接查库；邮件要额外配发信域名与 SMTP，收益低
- 不自动收集日志全文、对话或文件内容 —— 只收用户写下的文档与显式选择的诊断字段
