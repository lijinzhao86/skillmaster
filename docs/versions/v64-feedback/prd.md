# v64-feedback · 产品需求

> **最后更新**：2026-11-13
> **所属版本**：[`README.md`](README.md)

## 用户与场景

**谁在用**

1. **终端用户**：在终端里运行 `skmr`，或让 agent 帮忙做事；命令持续失败、行为与说明不符、或 agent 卡在某一步。
2. **agent**：被用户驱动执行任务，遇到自己解决不了的错误或不确定性，需要把现场交给平台。
3. **平台运营**：本版只作为收件方，没有界面。

**在什么场景下用**

- agent 按文档与 `--help` 都解决不了问题：错误反复出现、提示与实际不符、某个命令在特定客户端或沙箱里不可用。
- agent 写一份**反馈文档**：想做什么、发生了什么、怎么复现、环境是什么、已经试过什么。把文档交给用户看一眼，得到同意后运行 `skmr feedback send --file <文件> --consent`。
- 没有文件时，也可以把文档从标准输入交给命令；命令返回受理编号。

**现在的替代做法是什么**

没有。用户与 agent 卡住后只能停下来，或去别处反馈；平台拿不到现场，也没法按错误码统计「哪一类问题最多」。这条链路断了，CLI 的失败就永远停在用户那一侧。

## 范围

### 做

| # | 做什么 | 交付形态 |
|---|---|---|
| 1 | CLI `skmr feedback send`：`--file <路径>` 或标准输入读一份反馈文档；可选 `--skill <地址>`、`--attach-diagnostics`；提交后返回受理编号 | CLI |
| 2 | CLI `skmr feedback template`：打印反馈文档模板（写什么、不要写什么） | CLI |
| 3 | 提交前预览与同意记录：不带 `--consent` 只预览（完整内容、同意说明、将发送的字段），不发送；带 `--consent` 才发送。服务端记录同意版本、内容哈希、时间与来源（CLI）；政策改版后，下一次预览显示新的同意说明 | CLI + 服务端 |
| 4 | 服务端受理接口与存储：`user_feedback` 表，按账号限流 | 服务端 |
| 5 | 运营读路径：反馈落库后可按回执号或时间范围直接查库；本版不加运营命令、不做推送 | 数据库 |
| 6 | 隐私政策新增「你主动提交的反馈」一节：收集什么、用途、保留期、不向第三方提供 | 官网法务页 |
| 7 | agent 引导：`skills/skillmaster/SKILL.md` 增加「卡住时写反馈文档并运行 `skmr feedback send`」，`skillmaster-guide` 增加一节 | skill 文本 |
| 8 | 长期保留：反馈内容**不设删除期限**；数据库行保留，另把每条反馈归档到对象存储作为耐久副本 | 服务端任务 |
| 9 | 提交时的敏感信息检测：身份证号、银行卡号、手机号命中时提示并要求确认；密钥前缀在发送前替换为 `[已隐藏]`，并提示替换了几处 | CLI + 服务端 |
| 10 | 提交后的回执与撤回：给用户一条站内通知，含回执号与可运行的撤回命令；撤回即删除数据库行与归档副本 | 服务端 + 站内通知 |

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | 对外举报入口（内容错误 / 安全 / 许可） | 举报是另一条路径，面向「某个 skill 有问题、要求平台介入」；今天公域内容以开源导入为主，有问题可以回到上游仓库 | 出现需要平台介入的内容（付费、闭源、托管）时；与治理模型（TODO #37）一起定 |
| 2 | 运营侧处理队列与工作台 | 归「运营侧策展工作台」（TODO #30）；本版只保证「收得到」 | #30 开版 |
| 3 | 未登录提交与匿名提交 | 必须登录：不知道是谁提交的会产生噪声、污染数据，也无法回访。未登录或登录不可用时，CLI 指引先去登录；登录本身坏了就联系运营邮箱 | 出现明确的匿名需求时，由新 ADR 定 |
| 4 | 附件 / 截图上传 | 需要对象存储与内容审核；反馈文档本身是文本，已够定位 | 反馈需要图片或大文件时 |
| 5 | 自动收集日志全文、对话内容或 skill 文件 | 隐私：只收用户写下的文档与显式选择的诊断字段 | 不做 |
| 6 | 反馈处理进度与结果回执 | 需要新的通知类型与状态机，且处理方还没有界面 | #30 |
| 7 | 控制台里的反馈入口与列表 | 本版只做 agent 与终端这一条链路；控制台入口归反馈的下一步 | 反馈量起来、需要人直接在网页提交时 |
| 8 | 营销站上的公开页面 | 本版不涉及公域浏览 | 公域匿名浏览开版时 |
| 9 | 浏览器批准与「严格模式」 | 本版选 agent 通道 + 事后回执：平台不宣称「每次提交都有用户本人同意」，举证靠条款、审计与撤回；浏览器批准留作可选 | 企业或敏感用户要求可举证的本人同意时 |
| 10 | 运营邮件推送 | 运营可直接查库；邮件要额外配发信域名与 SMTP，收益低 | 需要主动提醒运营时 |

## 控制台操作与 CLI 对应

本版**没有新增控制台操作**，因此没有需要映射的 CLI 命令；[ADR 0081](../../decisions/0081-every-console-operation-has-a-cli-command.md) 不触发。

反馈只有 CLI 面：`skmr feedback send` / `template` / `delete`。

## 反馈文档模板

`skmr feedback template` 打印的内容，也就是 skill 引导 agent 去写的内容：

| 节 | 写什么 |
|---|---|
| 我想做什么 | 一句任务目标，不带实现细节 |
| 发生了什么 | 原始错误、命令、退出码；按发生顺序 |
| 怎么复现 | 最小步骤；能稳定复现就写，不能就说不能 |
| 环境 | CLI 版本、操作系统、客户端（Claude Code / Codex / 其它）、是否在沙箱里 |
| 已经试过什么 | 查过的文档、改过的参数、结果 |
| 不要写 | API 密钥、密码、私有代码、个人信息、对话全文 |

## agent 引导

调研结论（[`docs/research/agent-skill-triggering.md`](../../research/agent-skill-triggering.md)）：**确定性只有三个来源——显式调用、宿主 hook、自建 router；写在 SKILL.md 里的散文只能提高概率。**

本版按可靠性排序落地：

1. **预览与发送分离**（做 #3）：不带 `--consent` 只打印完整内容与同意说明，不发送；这一步只能防「顺手发」，不能证明用户本人同意。
2. **显式命令**（做 #1、#2）：agent 可以 `skmr feedback template` 拿模板、再 `skmr feedback send --file <文件> --consent` 提交。
3. **skill 正文**（做 #7）：写一条「卡住时先写反馈文档」，作为概率兜底。
4. **宿主 hook**：不做——只在支持 hook 的宿主可用，成本高，收益不确定。

**隐私边界与残余风险**：skill 必须要求 agent 在提交前把文档给用户看并得到同意；但**我们无法核验 agent 是否真的问了**。选 agent 通道的代价就是：平台不宣称「每次提交都有用户本人同意」，靠事后回执、撤回、最小必要与条款分配责任来兜底（见 §依赖与前置）。

## 验收与指标

### 验收标准

| # | 验收标准 | 怎么判定 |
|---|---|---|
| 1 | `skmr feedback template` 打印模板，含「不要写」一节 | CLI 用例 |
| 2 | `skmr feedback send --file f.md --consent` 提交成功并打印受理编号；库里有对应行，内容与文件逐字一致（密钥前缀替换为 `[已隐藏]` 的位置除外） | CLI 用例 + 库表断言 |
| 3 | `cat f.md \| skmr feedback send --consent` 也能提交 | CLI 用例 |
| 4 | 文档为空、超过文本上限（见 [`limits.md`](../../current/limits.md)，按 Unicode 码点）、或同意版本已过期时被拒，返回可读原因与退出码非 0 | CLI 用例 + 接口测试 |
| 5 | 非交互且不带 `--consent` 时，打印**将发送的完整内容（密钥前缀已替换）**、同意说明与将发送的字段清单并**不提交**，退出码非 0；带 `--consent` 时记录同意版本、内容哈希、时间与来源（`cli`）。预览会 `GET /consent` 取当前同意说明，但没有任何 POST | CLI 用例 + 抓包断言无 POST + 库表断言 |
| 6 | 同账号 1 小时内第 11 条被拒，返回可读错误与重试时间 | 接口测试 |
| 7 | 运营可按回执号与时间范围从库里查到该条，内容与诊断字段完整 | 接口测试 + 库表查询 |
| 8 | 隐私政策页新增一节，含收集范围、用途、保留期（长期保留、至少 6 个月）、不向第三方提供 | 站点用例 + 人工对照 |
| 9 | `skillmaster` 的正文含反馈引导，`skillmaster-guide` 有对应一节 | 文档检查 |
| 10 | 不带 `--attach-diagnostics` 时请求里没有任何诊断字段；带上时只含白名单字段 | 抓包断言 + 接口测试 |
| 11 | 未登录运行 `skmr feedback send` 时拒绝提交，并给出「先登录」与「登录不可用则发邮件到运营邮箱」两条指引 | CLI 用例 |
| 12 | 反馈内容不设删除期限；数据库行保留，另有一条对象存储副本且可查 | 接口测试 + 归档任务测试 |
| 13 | 文档命中身份证号、银行卡号、手机号时，先给出提示并要求再次确认；拒绝确认则不提交。密钥前缀不要求确认，但必须替换为 `[已隐藏]` 后才发送 | CLI 用例 + 抓包断言无 POST |
| 14 | 提交成功后用户收到站内通知，含回执号与 `skmr feedback delete <回执> --yes`；运行该命令后记录与归档都被删除，接口再查不到 | 接口测试 + 通知测试 |

**成立条件**：#2、#5、#7、#8、#14 任一条不满足就不算交付——提交、预览、运营可查、隐私条款、回执与删除各一。

### 指标

| 指标 | 定义 | 怎么量 | 目标 |
|---|---|---|---|
| 反馈量 | 按自然周计数，只算成功受理的记录 | 查 `user_feedback` | 本版不设目标，先建立基线 |
| 高频错误码 | 反馈里出现最多的前五个 CLI 错误码（仅当提交时附了诊断） | 查诊断字段 | 用来决定下一版修什么 |

## 依赖与前置

- **外部依赖**：无。运营读库；对外联系邮箱 `contact@skillmasterai.com` 只用于登录不可用时的兜底。
- **法律依据**：[`research/agent-feedback-legal-risk.md`](../../research/agent-feedback-legal-risk.md)——平台是个人信息处理者，提交前要有告知同意；敏感个人信息、向他人提供与跨境各有额外要求。
- **同意与责任的分配**：本版选 agent 通道 + 事后回执（不做浏览器批准，见「不做 9」）。**平台不宣称「每次提交都有用户本人同意」**：服务条款写明「用户指示 agent 提交，视为用户提交；用户对自己让 agent 做的事负责」；隐私政策写明我们无法核验 agent 是否征求过同意；影响评估如实记录这条残余风险。
- **内部前提**：
  - v56 的 `legal_consent`：隐私政策 1.1 → 1.2；按 v56 PRD 不做 #10，**存量账号不强制重新同意**，新注册记录 1.2，反馈提交按当次版本记录。版本号在 `SkillmasterProperties`。
  - 「必须登录」「诊断字段白名单」「敏感信息提示」与「同意在 agent 通道记录」是跨版本取舍，见 [ADR 0188](../../decisions/0188-feedback-consent-lives-on-the-agent-channel.md)。
  - 长期保留与对象存储副本见 [ADR 0189](../../decisions/0189-feedback-is-kept-indefinitely-with-an-object-copy.md)。
  - 保留期与「隐私政策保留期只写下限」（TODO #44）同一方向：**反馈内容长期保留、不设删除期限，隐私政策写「至少保留 6 个月」**；在线数据另存一份到对象存储，数据库行不删。账号注销时账号行去标识化、反馈内容按提交内容保留（密钥前缀已脱敏），与 v56 的「个人数据 30 天清理」的边界见 ADR 0189。
  - 对象存储：复用现有冷归档机制，落在**境内阿里云 OSS**；它是**受托方**（按 PIPL 第 21 条委托处理，不构成第 23 条向他人提供），不触发跨境条款。隐私政策 §五 已按这一口径披露。
  - 个人信息保护影响评估：反馈可能含敏感信息且会写入受托对象存储，按第 55 条做一次，报告保存至少 3 年。
  - 文本上限按 [ADR 0181](../../decisions/0181-text-limits-use-unicode-code-points.md) 的 Unicode 码点口径。
- **排除了什么前置**：不需要新通知类型、不需要运营界面、不需要控制台页面、不需要附件上传。
