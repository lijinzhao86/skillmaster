# v28 · 产品需求

> **最后更新**：2026-10-29 · **所属版本**：[v28](README.md)

## 用户与场景

**谁在用**：登录控制台的人在找一个「出去」的入口；以及第一次从营销站点进来、想再回首页看一眼介绍或安装说明的人。

**在什么场景下遇到问题**：控制台左上角的「SkillMaster」看起来是回首页的链接（每个产品的品牌都这么用），点下去却回到控制台根——也就是「我的 skill」列表；人本来就在那一页时，它只是把页面重载一遍。真正的首页在营销站（`www.skillmasterai.com`），而控制台里能回到它的地方只有一个：**退出登录之后**，那条「回到首页」。

**现在的替代做法**：自己改地址栏；或者先退出登录——那会真的结束会话，代价太大。

## 范围

### 做

| # | 做什么 | 为什么 |
|---|---|---|
| 1 | **顶栏品牌点回营销站首页**：`href` 从 `/` 改成构建变量 `VITE_SITE_URL` 的值（`https://www.skillmasterai.com`，尾斜杠由 `siteUrl.ts` 补） | 品牌回首页是它本来就该做的事；`/` 回的是控制台自己的「我的 skill」列表 |
| 2 | **品牌与 `/logout` 的「回到首页」读同一个值**：抽成 `src/siteUrl.ts` | 两个「首页」必须是同一个首页；两处各写一份，改一处就会分叉 |
| 3 | **设计稿记下这条规则，并标明演示件是替身** | 演示件没有外部站点，它的 `?page=skills` 不能照抄进产品 |
| 4 | **补一条守卫用例**：密钥还没复制时，点品牌仍然先问「离开后取不回来」 | 品牌变成外链之后，不能多出一条悄悄走掉的路 |
| 5 | **给品牌一个可访问名称**：`a.brand` 带 `aria-label="SkillMaster 首页"` | 640px 以下品牌名收起、标记是装饰性的，这个链接在窄屏**没有名字**；它现在是离开控制台的出口，读屏用户不该听到一个没名字的链接 |

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | **做一屏「控制台首页」** | 控制台里没有一个「总览」屏，`/` 就是「我的 skill」；给人一个空首页是把出口变成一堵墙 | 真的需要总览数据时另开一版 |
| 2 | **改成新窗口打开**（`target="_blank"`） | 它是「回首页」，与控制台里那条同义的出口（`/logout` 之后落到站上）走同一个 tab；新窗口是「去别处看看」的形状，会把控制台一直留在身后 | 用户提出「想边看控制台边看首页」时 |
| 3 | **动视觉**：标记、字号、字距、颜色、悬停态 | 这一版只改去向；设计稿的取值一个都不动 | 不做 |
| 4 | **改演示件的运行行为**（让它真跳外部站点） | 演示件是单文件、没有外部站点；跳走就没得看了，也带不走它自己的假路由 | 演示件将来能起多页站点时 |
| 5 | **在顶栏加营销站的其它入口**（产品 / 文档 / 定价） | 控制台的顶栏只有品牌、搜索与账号；多一个入口就要重新定一次顶栏长什么样 | 不做 |
| 6 | **改窄屏下品牌名的显示**（把它放回去） | 那是 640px 以下的版式，不是这一版的话题；名字由 `aria-label` 补上，视觉不动 | 不做 |

## 控制台操作与 CLI 对应

这一版**不新增、不删除任何控制台「操作」**。按 [ADR 0081](../../decisions/0081-every-console-operation-has-a-cli-command.md) 仍然给出映射表（下面一行）：表里这一行是导航而不是操作，**没有 CLI 对应，也不需要**——CLI 里没有「控制台」这个概念。

| 行为 | 在哪 | CLI |
|---|---|---|
| 点品牌回营销站 | 控制台顶栏 | 没有对应命令，也不需要：CLI 里没有「控制台」这个概念 |

## 验收与指标

| # | 验收标准 | 怎么判定 |
|---|---|---|
| 1 | **点品牌回到营销站**：`a.brand` 的 `href` 等于 `SITE_URL`，运行时是 `https://www.skillmasterai.com/`（产物里是 `…com` 加运行时补的 `/`） | `tests/brand.test.tsx`（测试环境用兜底值）；`npm run build` 后在 `dist/` 里 `grep -o 'https://www.skillmasterai.com[^"]*'` 得到不带斜杠的那个 origin |
| 2 | **一个值两个用的人**：品牌与 `/logout` 都从 `src/siteUrl.ts` 读；两处不再各写一份 | `grep -rn "VITE_SITE_URL" skillmaster-console/src` 只命中 `siteUrl.ts` |
| 3 | **构建仍然拒收缺值**：没有 `VITE_SITE_URL` 的构建失败 | `vite.config.ts` 的 `requireSiteUrl`；`npm run build` 成功、去掉变量后失败 |
| 4 | **守卫仍然拦住品牌**：「还没复制的密钥」那一刻点品牌，问题出现、地址不动 | `tests/app.test.tsx` 的密钥用例（新增步骤） |
| 5 | **演示件不变**：DOM 与产物逐字节不变，`console-states --only layout` 组全绿 | 重出演示件后 `diff` 一致；`console-states --only layout` `failed: 0` |
| 6 | **视觉没有变化**：标记 `19×19`、字号 `15px/600`、字距 `0.04em`、颜色、悬停态与改前一致 | 人工对照；取值在 `design/src/console/styles.css` 的 `.brand` / `.brand-name` 规则里（README 的正文不重复这些数） |
| 7 | **品牌有可访问名称**：`a.brand` 的 `aria-label` 是「SkillMaster 首页」，且含可见文字「SkillMaster」 | `tests/brand.test.tsx`；README 里 640px 以下的规则仍是「只留标记」 |

**指标**：这一版没有服务端指标，也没有需要量的行为变化。要量的话只有一条，且本版不打算量——「品牌点击之后留在控制台的比例」，需要一段埋点，而那件事要先有一版关于「控制台要不要埋点」的决定。

## 依赖与前置

- **`VITE_SITE_URL` 已经存在**：`.env.production` 里有它，`vite.config.ts` 早已在构建时强制要求——这一版只是让**第二个入口**用上这个值（仍然只有 `src/siteUrl.ts` 一个文件读环境变量）。
- **ADR 0086**：控制台与营销站的会话关系；「回到首页」这个出口是它定的，起点在 `/logout`。
- **设计稿是权威**：规则写进 [`design/README.md`](../../../design/README.md) §控制台演示 › 顶栏的品牌回首页；演示件的替身也在那里写明。
