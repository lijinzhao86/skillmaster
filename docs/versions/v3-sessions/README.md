# v3-sessions · 浏览器会话有两条尺子，而且设备可撤销

> **最后更新**：2026-10-16
> **状态**：进行中。**前三步都已交付并从此作为实现的依据**：`prd.md` / `technical-design.md` / `test-plan.md` 定稿（2026-10-15），前端交互设计交付（[`design/`](../../../design/README.md) §登录设备，`?page=sessions`，2026-10-16），**范围 #5/#6 的欠账在同一天清掉并验过**（验收 #10 通过，证据在 [`test-plan.md`](test-plan.md) §结果）。**会话那一半（范围 #1–#4）尚未实现**——下一步是 P0，见 [`technical-design.md`](technical-design.md) §分期。
> **这四份现在锁着**：它们是实现要照的东西，改动只在有理由时**就地修订并留痕**（版本内文档是活文档，见 [`docs-architecture`](../../../.claude/skills/docs-architecture/SKILL.md) §四）。
> **含收费**：否

## 目标

给浏览器会话加上**第二条尺子**（绝对上限 7 天，今天是滑动 7 天、等于永久），把空闲尺子收到 **24 小时**，并让人**看得见、能退出**自己登录过的设备——因为「签发一把 API key」是控制台里最重的一件事，而它今天唯一的收尾手段是重置密码。

**另加一条**：把两笔**已经决定、却没人执行**的欠账清掉（CLI 的 `--client-credentials` 那一簇、以及进了基线却没人读写的 `skill_stat` 表）。它单独占一条范围，因为删掉一个 CLI 参数是**对外契约的改动**。细节见 [`prd.md`](prd.md)。

## 验收标准

一句话：**会话到点必死（7 天绝对 / 24 小时空闲），任何一台设备都能立刻退出，欠账清完之后三处组件的测试仍然全绿。**

完整验收见 [`prd.md`](prd.md) §验收与指标。

**成立条件**：验收 #4（从 A 退出 B，B 的下一个请求即被要求登录，A 不受影响）是「不满足就不算交付」。理由是这一版存在的理由本身——只缩短寿命而不给撤销手段，等于把人挡在门外却还留着钥匙（[ADR 0043](../../decisions/0043-the-browser-session-is-bounded-and-revocable.md) §理由）。

## 这一版明确不做什么

摘要三条最要紧的；**完整范围与每条的理由在 [`prd.md`](prd.md) §范围**。

- 不做 **CLI 那条路凭据的寿命改造** —— 它不能单独做：CLI 今天拿的是一对 OAuth 令牌，「不自动续期」要求那条路先改成「铸一把 key」（[ADR 0040](../../decisions/0040-api-key-in-the-cli-now-the-browser-path-later.md) §决定 3），那是另一版的工作量
- 不做 **「保持登录多久」的用户旋钮** —— 它要求人理解两个寿命概念，而真正起作用的是默认值
- 不做 **会话的权限收窄（会话带 scope）** —— 会话是「账号全权、不带 scope」，那条规则属于架构轴的事实，不是本版的能力

## 与目标态的关系

[`target/`](../../target/) 描述的是**完整形态**。这一版只碰**会话的寿命与可撤销性**，不碰身份与权限模型。

- 保留的部分：会话在服务端、因此可撤销——这是 v1 起的形状（[ADR 0014](../../decisions/0014-browser-session-via-spring-session.md)），本版只是把它的入口补上。
- 没有分叉的部分：本版不给会话加权限模型，也不引入角色/组织。目标态里那套组织与角色机制按 [`target/README.md`](../../target/README.md) 自己的说法**不是当前版本的实现依据**，因此本版与它无从冲突。
