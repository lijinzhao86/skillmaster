# v3-sessions · 产品需求

> **最后更新**：2026-10-15
> **所属版本**：[`README.md`](README.md)

## 用户与场景

**谁在用**：控制台的使用者——第一方账号的主人。今天只有这一类人：组织与成员那半还没到（[`README.md`](README.md) §与目标态的关系）。

**在什么场景下用**：三种，都是同一个人：

1. **天天在控制台工作的人**：看自己的 skill、发布、管 API key。他今天登录一次之后就**再也不用登录**了——那条 7 天的规则是滑动的，他每次点一下就重新数 7 天。
2. **在一台不属于自己的机器上登录的人**：公司的公用机、同事的电脑、演示机、酒店里的电脑。他在那儿登录、办完事、走。
3. **「我好像在哪台机器上登录过」的人**：他没有任何办法知道是哪台，也没有任何办法收回来。

第二种人是这一版真正要服务的。他的处境今天最糟：**他做了正确的事**（在别人的机器上用完后离开），而系统里没有任何东西能让这件事结束。

**现在的替代做法是什么**：清浏览器 cookie、换浏览器、或者去重置密码。第一个把**所有站点**都登出了（代价远超必要），第二个只是换个地方留下同一个问题，第三个是为了改密码的，代价是要求换一个密码并把自己也退出去。**三种都不是「让那台机器退出」这件事**——而这件事本身是普通且应该可做的。

## 范围

### 做

| # | 做什么 | 交付形态 |
|---|---|---|
| 1 | 会话有两条尺子：空闲 24 小时、绝对 7 天；绝对那条不滑动，从登录时刻算 | 服务端配置 + 启动校验 + 每个请求执行 |
| 2 | 列出当前账号的登录设备：设备/浏览器、登录地址、登录时间、最后活动、哪一台是当前这台 | 控制台一屏 + `/web/sessions` 三个接口 |
| 3 | 退出单台设备；退出其他所有设备 | 同上，退出后**下一个请求**即被要求登录 |
| 4 | 重置密码继续结束所有会话（回归），并且这一屏上看得见它清空 | 已有行为，本版让它可见 |
| 5 | **清掉两笔已经决定、却没人执行的欠账**：CLI 的 `--client-credentials` 那一簇（连同服务端为它留的 `client_credentials` 授权与 `oauth_client.user_id`）、以及进了基线却没有任何读写的 `skill_stat` 表 | 三处组件各删一批 + **改 `V1__baseline.sql` 的建表语句、不加 drop 迁移**（还没有部署，但本机 dev 库跑过 V1，所以一并重建它）+ 集成测试改用**签发的 key** 取令牌 |
| 6 | **这笔删除不是纯减法**（读代码时发现的两处，都记在下面）：CLI 里有两句提示语会把人指向**已经删掉的命令**，要改成实话；一台钥匙串里还存着无人值守凭据的机器要得到一个**诚实的说法**，而不是一个死胡同 | 两处提示语改写 + `revokeReplaced` 多一条分支 |

### 范围 #5 不是纯减法（读代码时发现的两处）

一开始它看起来只是"删掉没人用的东西"。读到实现时发现有两处**必须一起处理**，否则删除本身会制造两个新缺陷：

1. **有一句报错会把人指向一条不存在的命令。** `ErrNotRenewable` 的文案写着「请重新运行 `skillmaster login --client-credentials`」——那是删掉的那个形状自己报的错。删除之后这句话就成了**教人去跑一条不存在的命令**，比不提示更糟。**它前面那道守卫要留**（正是它在"凭据没有刷新令牌"时挡在前面，不让一个空的刷新令牌发出去换来一句 `invalid_client`），改的是文案。
2. **有一类凭据会失去归宿。** 今天用过无人值守登录的机器，钥匙串里那份凭据**不是 key、也没有刷新令牌**。它过期时会走到上面那道守卫；替换凭据时 `revokeReplaced` 还会想去撤销它——而撤销它需要客户端密钥，那个环境变量**也在这批删除里**。所以：它**撤不掉**（从这台机器），只能自己失效。这一条必须**说出来**，因为沉默会被读成「上一份已经撤销了」。

**为什么这两条值得写进范围而不是留给实现**：它们是**用户会看到的句子**。删除一个参数的决定，实际影响落在"那台老机器上的人会读到什么"——那是需求，不是实现细节。

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | CLI 那条浏览器路签发的**凭据**改成不自动续期、寿命 1–7 天、出现在列表里 | 它**不能单独做**：CLI 今天拿的是一对 OAuth 令牌（有刷新链），「不自动续期」要求那条路先改成「铸一把 key」（[ADR 0040](../../decisions/0040-api-key-in-the-cli-now-the-browser-path-later.md) §决定 3） | vN+1 |
| 2 | 登录时多问一句「这台设备是共用的吗」（per-login 选择寿命） | 那会把判断交给一个当下没法判断的人；而设备列表把同一件事变成了**事后能纠正**的。加一项也是一次设计交付 | 有真实需求时 |
| 3 | 「保持登录多久」的用户旋钮（一周/一月/长期） | 它要求人理解**两个**寿命概念，而真正起作用的是默认值；它与绝对上限的要求相抵 | 未定 |
| 4 | 会话带 scope（权限随登录/同意收窄） | 会话今天就是「账号全权、不带 scope」，这是刻意的。把它写成一条**显式规则**属于架构轴的事实，不是本版能力 | 架构轴单独处理 |
| 5 | 敏感动作（签发/撤销 key）要求重新验证（sudo 模式） | 独立机制；有了「绝对上限 + 能退出」之后它的优先级下降 | 未定 |
| 6 | 记住我 / 长期免登录 | 与「短」的方向相反 | 不做 |
| 7 | 会话列表里显示「通过哪个应用授权」（第三方/OAuth 宿主） | 本版没有第三方宿主在用（[ADR 0041](../../decisions/0041-third-parties-reach-us-through-the-cli.md)），组织模型也还没到 | vN+1 |
| 8 | **会话数的人为上限** | **两条尺子已经把它限住了**：被遗忘的机器最多活 24 小时，而常用的浏览器只占一行（同一浏览器里反复登录是复用同一行、只把会话 id 转一下）。再定一个数只是照抄参照产品的 100，**而它那边的绝对上限默认是关的**——尺子不一样，数字也不该照搬 | 不做。真实行数是「几个」；若真出现异常增长，那本身就是要看一眼的信号 |

## 验收与指标

### 验收标准

| # | 验收标准 | 怎么判定 |
|---|---|---|
| 1 | 登录满 7 天的会话必须重新登录，**哪怕它天天在被使用** | 把会话的创建时间推到 7 天前、最后活动是刚刚，下一个请求被要求登录 |
| 2 | 差一点没到 7 天的会话仍然可用 | 创建时间推到 6 天 23 小时前，下一个请求成功。**这条防的是「把上限算错一位」** |
| 3 | 登录后 24 小时没有任何请求 → 该会话失效 | 把最后活动时间推到 25 小时前，下一个请求被要求登录 |
| 4 | 从 A 设备退出 B 设备 → B 的下一个请求即被要求登录，且 **A 不受影响** | 两处登录，A 让 B 退出，两边各请求一次 |
| 5 | 「退出其他所有设备」→ 除当前这台外全部失效，当前这台继续可用 | 三处登录，执行一次，逐一请求 |
| 6 | 列表与响应体里**不出现任何会话 id**，也不出现其它能直接当凭据用的串 | 拿库里真实的会话 id 去比对页面与响应体 |
| 7 | 拿别人的 `device_id`（或一个不存在的）发起退出，什么都不发生，且**对方不受影响** | 从 A 发一个 B 的 id，断言返回与「不存在」同一个答案、B 仍可用 |
| 8 | 重置密码结束所有会话，且列表随之清空（回归） | 重置后旧 cookie 全部失效、列表为空 |
| 9 | 把绝对上限配得比空闲短 → **启动失败**，不是静默禁用一条尺子 | 用错误配置启动上下文 |
| 10 | 欠账清完之后 **三处组件的测试全绿**，且 CLI 里 `--client-credentials` 及其两个环境变量**不再存在** | `go test ./...`、`mvn -o verify`、`npm test`（`skillmaster-web`）全绿；在 CLI 里搜这两个形状，**用户可见的文本**（帮助输出、README、错误消息）零命中——**参数名本身会留在断言它被拒的那条测试里**，那正是要的答案 |
| 11 | 一台**还存着无人值守凭据**的机器：过期时读到的那句话**不再让人去跑一条已删除的命令**；替换凭据时也不会假装「上一份已撤销」 | 造一份「不是 key、也没有刷新令牌」的本机凭据，跑一条需要凭据的命令、再跑一次 `login --with-key`，读那两句输出 |

**成立条件**：**#4 是「不满足就不算交付」**。它是这一版存在的理由——只缩短寿命而不给撤销手段，等于把人挡在门外却还留着钥匙。

### 指标

| 指标 | 定义 | 怎么量 | 目标 |
|---|---|---|---|
| 重新登录频率 | 同一个账号、相邻两次登录之间的间隔（含被退出或过期后的那次），只统计一周内登录过两次以上的账号 | 登录事件的时间差中位数 | 约 7 天一次（由绝对上限主导）；**不出现「每天一次」**——出现就说明 24 小时空闲定错了 |
| 「退出其他所有设备」的使用率 | 用过至少一次的账号占比 | 审计事件计数 ÷ 有会话的活跃账号数 | 先观察，不设目标（它是个逃生门，多数人一次都不该用） |

## 依赖与前置

- **外部依赖**：无。不依赖任何第三方服务或上游发布。
- **内部前提**：
  - [ADR 0043](../../decisions/0043-the-browser-session-is-bounded-and-revocable.md) —— 两条尺子与设备可撤销（范围 #1–#4 由它推出）
  - [ADR 0014](../../decisions/0014-browser-session-via-spring-session.md) —— 会话在服务端，因此撤得掉；这是「能退出」成立的前提
  - [ADR 0038](../../decisions/0038-default-credential-is-an-api-key.md) §决定 9 —— **范围 #5 的授权来源**：它判了 `client_credentials` 与手工种的那行客户端「被取代」，本版只是把那个判决执行掉。**这一版不重新论证它**，只执行
  - **前端交互设计**：设备这一屏的界面必须先定（本版第二步），实现排在它之后
- **范围 #5 为什么值得占一条范围**：删掉一个 CLI 参数是**对外契约的改动**。它必须在某处的范围里看得见，否则下一个人只会看到"某个参数不见了"
- **排除了什么前置**：「保持登录多久」的旋钮、记住我、组织模型、邮件通道——都不需要。**这一版不发任何邮件、不引入任何新的外部通道。**
