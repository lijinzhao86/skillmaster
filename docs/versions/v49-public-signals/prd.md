# v49-public-signals · 产品需求

> **最后更新**：2026-11-06
> **所属版本**：[`README.md`](README.md)
> **来源**：产品负责人 2026-11-05 的方向——公域 skill 多起来之后，用户与 agent 需要「可信、看得懂、有人用」的信号；首批做来源、说明书、使用信号与 CLI 同一口径。

## 用户与场景

**谁在用**：公开 skill 的读者（普通用户，以及替他们执行命令的 agent）、平台运营者。

**在什么场景下用**：

- 读者在「发现」页或 `skmr skills search` 里看到一条公开 skill，要在十几条候选里判断「这条是谁维护的、靠不靠谱、是不是我要的、有没有人在用」。
- agent 在没有网页的环境里搜索 skill，只能读到描述；它需要与网页同一组来源与使用事实，才能替用户做初筛。
- 运营者把一条外部来源（GitHub、SkillHub 等）的 skill 接进官方命名空间时，要能说清「它从哪来、许可是什么、现在对应哪个版本」，而不是在每个来源上加一批字段。

**现在的替代做法是什么**：

- 公域卡片只有 `namespace / name`、描述、适用场景、公开标签、版本与更新时间；「公开」代表平台背书，但页面没有说清背书的范围。
- 没有来源概念：skill 从哪个仓库、哪个平台来，用户看不到；许可与上游版本也无处安放。
- 没有使用信号：卡片上没有调用量、加入数，也没有「最近有没有人用」。
- CLI 的 `skills search` 与网页读的是不同粒度的信息，agent 只能看到描述与标签。

## 现在的问题、诱因与改法

### 问题 1：用户无法判断「谁给的、平台担保什么」

**现在的流程**：读者看到卡片 → 只有描述与标签 → 点进去看正文 → 自己猜来源与可信度。

**问题**：公开已经是平台背书（[ADR 0146](../../decisions/0146-public-is-platform-endorsement.md)），但页面没有把「官方维护 / 来自 GitHub 的某个仓库 / 来自 SkillHub」说清；用户把「公开」误读成「平台审过内容、保证效果」。

**为什么会这样**：公开范围刚刚收口，信息层还停在 v14 的卡片；数据模型里没有来源这一层。

**怎么改能解决**：新增**来源卡**：官方维护、外部平台与仓库、许可证。来源用「类型 + 定位 + 通用信号」表达，不按平台加字段。对应版本/commit、指标（如 GitHub stars）与最近校验时间只在 CLI——信息页只回答「它从哪来、能不能带走」。许可证单独占一行，并说清「平台内可见」与「平台外再分发」是两件事。

### 问题 2：信息页没有分工，读的人不知道先看哪里

**现在的流程**：打开 skill 信息页，描述、适用场景、运行环境、来源、许可证、使用量与申请权限全在一屏。

**问题**：读的人要做的其实是两件事——先判断「它是什么、要不要用」，再按需「查一下来源与许可」。两者挤在一起：来源与许可这类低频信息占着首屏，申请块压在页尾，使用量贴着标题、看起来和描述同级。

**为什么会这样**：v49 往信息页加了来源、许可、使用三组事实，却没有重新分过层次。

**怎么改能解决**：**信息页重排**——首屏只答「它是什么」（描述、适用场景、运行环境）；来源与许可收进**右栏、标签下面**的一次展开，默认收起；申请收成同样的一行「需要更高权限？」；使用量不单独占一块，留在结果行与页头证据行上。

### 问题 3：用户无法判断「有没有人在用」

**现在的流程**：卡片没有使用信号；推荐流按更新时间倒序。

**问题**：一条 2024 年上传、从没人用过的 skill，与一条每周都有人用的 skill，在页面上看起来一样。

**为什么会这样**：服务端没有记录调用与加入的聚合；审计事件是安全流水，不是用量。

**怎么改能解决**：新增**使用信号**：按账号去重的调用与加入，聚合成累计调用次数分桶、近 30 天不同账号数与入库数；结果行显示「累计调用分桶 + 入库数」，详情页页头的证据行同值——不显示精确次数，不暴露个人，账号分桶不上**控制台界面**（CLI 的 `skill show` 仍打印）。

### 问题 4：agent 读不到网页上的同一组事实

**现在的流程**：`skmr skills search` 只给地址与一句简介；`skmr skill show` 给元数据，但没有来源与使用信号。

**问题**：人能在网页上做的初筛，agent 做不了；同一个 skill，人与 agent 得到两套信息。

**为什么会这样**：CLI 的输出契约停在 v14；来源与使用信号还没有进入 CLI 的读模型。

**怎么改能解决**：`skills search --verbose` 与 `skill show` 增加来源、许可证与使用事实；取值来自同一组 API 字段，CLI 不做自己的判断。

## 范围

**本版由两个需求单元组成**：公域信号（来源、许可、信息页）与使用度量（调用、账号、入库）。它们放在同一个版本交付，但在代码上是两个模块——公域只决定「哪些加载算公域信号」，度量模块只决定「怎么记、怎么聚合」；拆法与依赖方向见 [`technical-design.md`](technical-design.md) §架构。

**一个东西一个名字**：产品说法是「使用信号」；代码里的模块名是 M15「使用度量」。两者指同一组事实，模块名只在讲边界时用。

**边界与 scope**（2026-11-06 用户定）：

- 度量模块 **M15 `metrics`** 只认「一次加载发生了」与「这次度量属于哪个 scope」，**不认识公开 / 私有**。
- `scope` 是**度量的用途**，不是「谁能看」。本版只启用 `public`：只有公开、有线上版本、非作者的加载进入它。
- 将来作者与协作者的使用（给用户自己管理用的 `owner` scope）走**同一个接口**，不改 M15 的采集与聚合；新增 scope 是**一次 ADR**，不是改表。
- 入库数留在库模块（它是库关系，不是行为度量），由读模型拼装。
- 度量写失败不得让正文读失败——这是「独立模块」的硬判据。
- 公域侧只保留**策略**：由读路径判断这次加载是否属于公域信号，再调用度量模块的记录接口。

### 许可证怎么展示

**先分清两件事。** 「公开」决定平台内谁能看到、能不能加入；「许可证」决定你能不能把内容带到平台外使用、修改、再分发。页面必须把这两句话分开写，不能让别人把「公开」读成「随便用」。

**两个位置，两种粒度**：

| 位置 | 画什么 | 不画什么 |
|---|---|---|
| 信息页「来源与许可」 | 许可证名 + SPDX、版权行、站外全文链接（[ADR 0151](../../decisions/0151-full-license-text-links-to-its-source.md)） | 不画「你可以做什么 / 要履行什么」（2026-11-06 用户定），不写法律意见，不替用户判断能否商用 |
| CLI `skill license` | 许可证、状态、版权、允许与义务、全文链接 | 不打印全文本身；不在 `skills search` 结果里展开 |

**结果行不画许可**（2026-11-05 用户定）：列表要逐行比较，而许可与更新时间不是「先看哪一条」的判据；它们回答的是「点开之后能不能用」，落在信息页与 `skill show` 上。

**四种状态；页面只写名字，状态与解释在 CLI**（2026-11-06 用户定）：

| 状态 | 页面写法 | `skill show` | `skill license` | 依据 |
|---|---|---|---|---|
| 已识别 | 信息页 `MIT · © 2025 Corey Haines · 查看许可全文`；摘要行 `GitHub · MIT` | `许可证：MIT` | 许可名 + 状态「已识别」+ 版权 + 可做 + 要履行 + 全文链接 | 来源仓库的 LICENSE / SPDX |
| 仅声明 | 只写许可名 `MIT`；摘要行 `GitHub · MIT` | `许可证：MIT（仅声明，未附全文）` | 同 `skill show` 的写法，不加允许与义务 | SKILL.md 有 `license`，但没有许可文件 |
| 未声明 | 留空：摘要行只写来源，展开不画「许可证」一项 | `许可证：未声明` | `许可证：未声明` + 「来源没有声明再分发许可；可以按平台可见性使用，不要复制到平台外。」 | 没有 LICENSE，或 SKILL.md 没有 `license` |
| 不支持 / 自定义 | `其他许可` + 查看许可全文链接 | `许可证：其他许可` | 状态「其他」+ 全文链接 + 「以全文为准」 | 不在固定口径表里的许可 |

**本版不判「声明与来源文件不一致」。** 有来源许可文件时以文件为准；声明只作保留，不用来拦截。冲突校验是下一版入库流程的事（见 `TODO.md`）。

**固定口径表**（小、常用、可维护）：MIT、Apache-2.0、BSD-2-Clause、BSD-3-Clause、ISC、MPL-2.0、GPL-2.0、GPL-3.0、AGPL-3.0、Unlicense、CC0-1.0、CC-BY-4.0。表只写「允许 / 义务」的事实摘要，每一行都带「以全文为准」。

**优先级**：离 skill 最近的 LICENSE 优先（`skills/<name>/LICENSE` > 仓库根 `LICENSE`）；SKILL.md 的 `license` 是作者声明。有 LICENSE 就用它的值；没有才用声明。官方自建 skill 没有声明时 CLI 返回「未声明」、页面只写来源，不默认 MIT。

**不要只看 GitHub 仓库的 `license` 字段。** 它只报仓库根许可，可能漏掉 skill 目录里的独立 LICENSE；导入时要按「skill 目录 → 上级目录 → 仓库根」找最近的许可文件，并记录它所在的路径与版权行。

### `skill show` 输出什么

`skill show` 是「这个 skill 的公开可读卡」，不是作者面。字段顺序固定，空字段不打印：

```text
skillmaster/ab-testing
  设计、规划或实现 A/B 实验，判断两个方案哪个更好。
```

|---|---|
| 地址 | `namespace/name`；来源仓库与目录是另一组事实，写在「来源」行 |
| 描述 | SKILL.md 的 `description` |
| 适用场景 | `when_to_use` |
| 运行环境 | `compatibility` |
| 版本 | 线上版本 |
| 分类 | 平台公开分类 |
| 公开标签 | 作者写给搜索的词 |
| 来源 | 外部平台 + 定位；官方自建写「官方」 |
| 对应版本 | GitHub 是 commit；官方来源不打印 |

| 最近校验 | 快照的 `fetched_at`，只打日期；没有快照就省略这一行 |
| 许可证 | `MIT` / `未声明` / `其他许可` / `MIT（仅声明，未附全文）`；只给名字与状态，要点与全文在 `skill license` |
| 使用 | 累计调用分桶 + 账号分桶 + 最近使用 + 入库数；没有记录写「还没有人用过」 |
| 我的标签 | 只有调用者自己看得到：库条目生效时打印标签；不生效时打印一句原因，不打印标签 |

**不打印相似度。** 它是内部排序细节，服务端保留 `score`，CLI 不展示。

### `skill license` 输出什么（本版新增命令）

`skill show` 是卡，`skill license` 是那一块许可的全文摘要。它读的是 `/metadata` 里同一个 `license` 块，**不加接口**；字段顺序固定，空字段不打印：

```text
dev/pdf-tools
  许可证：MIT
  状态：已识别
  版权：© 2025 Corey Haines
  可做：可商用 · 可修改 · 可再分发
  要履行：保留版权与许可声明
  全文：https://github.com/coreyhaines31/marketingskills/blob/main/LICENSE
```

- 四种状态各有固定说法：`仅声明` 写「MIT（仅声明，未附全文）」、不给要点；`未声明` 只给一句「来源没有声明再分发许可；可以按平台可见性使用，不要复制到平台外」；`其他许可` 只给全文链接。
- **不打印全文本身**：要看原文去下载包里的 `.skillmaster/LICENSE`，或点 `全文` 那一条（[ADR 0151](../../decisions/0151-full-license-text-links-to-its-source.md)）。
- 用法：`skmr skill license <命名空间>/<名字> [--no-login]`。

## 控制台操作与 CLI 对应

**本版不新增写操作；新增一条读命令（`skill license`）。** 来源由服务端在发布/同步时写入（写入路径见技术设计 §来源解析与刷新）；控制台这一版新增的都是读，写操作仍是既有的入库、移出库与申请。

| # | 控制台操作 | CLI 命令 | 备注 |
|---|---|---|---|
| 1 | 读公域结果行 / 信息页的来源、许可证与使用事实 | `skmr skills search --verbose`、`skmr skill show` | 同一组 API 字段；两处取值不做各自判断 |
| 2 | 入库（结果行书签 / 页头主按钮） | `skmr skill join <地址> --yes` | 既有命令；控制台用词改为「入库」，命令名不变 |
| 3 | 移出库（已入库 ▾ → 移出库，弹窗确认） | `skmr skill leave <地址> --yes` | 既有命令 |
| 4 | 申请更高档位 / 撤回申请 | `skmr skill request <地址> --role <档位>` / `skmr skill request <地址> --cancel` | 本版新增规则：未入库时 400 `invalid_request`，`details[].issue = not_in_library`（[ADR 0150](../../decisions/0150-requesting-a-higher-rung-needs-library-membership.md)） |
| 5 | 按分类浏览（点结果行上的分类胶囊） | `skmr skills search <词> --category <分类>` | 既有筛选；没有「只看某个分类」的清单页 |
| 6 | 打开来源网页（点右下来源标识） | **没有对应命令**：`skill show` 只打 `来源：GitHub · owner/repo`，不打 URL | 见本文件 Q7 / TD Q11 |
| 7 | 复制名字（名字旁按钮） | 不需要：地址本身就是 `namespace/name`，是所有命令的入参 | 不是操作 |
| 8 | 读许可证细节（信息页展开里的状态、版权、全文链接） | `skmr skill license <地址>`（本版新增） | 读 `/metadata` 的同一个 `license` 块，不加接口 |

### CLI 命令变更（v49）

**新增一条读命令**；三个既有命令的输出或行为变，一个既有下载面多三个文件：

| 命令 | 变更 | 形态 |
|---|---|---|
| `skmr skill license`（**新增**） | 打印结构化许可：许可证、状态、版权、可做、要履行、全文链接；不打印全文；四种状态各有固定说法 | 新命令；读 `/metadata` 的 `license` 块，不加接口、不加迁移 |
| `skmr skill show` | 输出增加来源、对应版本、指标、许可证（只给名字与状态）与使用；**许可要点与全文移到 `skill license`**。顺序固定为「地址 → 描述 → 适用场景 → 运行环境 → 版本 → 分类 → 公开标签 → 来源 → 对应版本 → 指标 → 最近校验 → 许可证 → 使用 → 我的标签」；空字段不打印 | stdout；帮助里的 Output 文案已同步 |
| `skmr skills search --verbose` | 每条多一行「公域来源：GitHub · MIT · 100+」（来源标签 · 许可 · 累计调用分桶）；**不再打印相似度** | stdout；`--verbose` 的说明从「来源、状态与版本」改成「来源、许可证与使用」 |
| `skmr skill request` | 未入库时拒绝：400 `invalid_request`，`details[].issue = not_in_library`，并给一句可照做的指引（先 `skmr skill join`） | 退出码与错误形状不变 |
| `skmr skill get`（整版下载 / 落到目录） | 包与落地目录里多 `.skillmaster/license.json` 与 `attribution.md`（上游没有许可文件时另有 `LICENSE`）；`skmr skill ls` 默认不列 `.skillmaster/`。**`skill invoke` 不在此列**：它只流式读正文、不落盘 | 归档内容变化，命令与参数不变 |

## 验收与指标

### 验收标准

| # | 验收标准 | 怎么判定 | 对应用例 |
|---|---|---|---|
| A1 | 公开 skill 有一条来源，页面说清平台与仓库，CLI 另说清 commit 与许可证 | 信息页的「来源与许可」展开后是 `GitHub · 仓库`，仓库链到 GitHub；`skill show` 另有对应版本、许可证与指标 | T1 |
| A2 | 加一种来源不需要加列、改页面分支 | 代码评审：来源表只有通用列；CLI `skill show` 按 `signals` 渲染，控制台只显示「平台 · 仓库」；新增一个假适配器的测试不改 schema | T2 |
| A3 | 来源指标缺失不拖垮页面 | 适配器超时/404 时信息页仍显示平台、仓库与许可证（指标本来就不上这一页）；`skill show` 省略指标行，不报错 | T3 |
| A4 | 信息页首屏只答「它是什么」 | 首屏只有描述、适用场景、运行环境；来源与许可默认收起、点开可读；申请只在梯子上还有更高档时出现一行；使用量正文不单独占一块，页头证据行按数据画 | T4 |
| A5 | 使用信号按账号去重，分桶计算，不暴露个人 | 两个账号同一天多次调用只算 2；结果行与信息页页头的证据行显示累计调用分桶与入库数，且只对公开、有线上版本的 skill 显示（自己创建的公开 skill 也一样）；账号分桶只给分桶值，控制台不展示，CLI 的 `skill show` 仍打印；API 不返回账号；公域聚合只读 `scope=public`，其他 scope 的数据不参与 | T5 |
| A6 | 使用信号只给分桶，不下发精确账号数 | 累计调用数只给分桶（不到 10 写「少于 10」），不显示精确次数；近 30 天账号数只给分桶，不下发精确值；入库数是一个公开的整数 | T6 |
| A7 | CLI 与控制台读到同一组来源与使用值 | 共有字段一致；CLI 可以多打印账号分桶与最近使用 | T7 |
| A8 | 既有公域搜索、入库、信息页行为不变（动词由「加入」改为「入库」） | 原有用例全绿 | T8 |
| A9 | 设计件与源码一致，相关设计检查组全绿 | `design/` 构建与 `--only discover`（结果行与页头）、`--only skill`（skill 页的页面逻辑）通过 | T9 |
| A10 | 文档检查全绿 | `check_docs.py`、`impact.py --check`、生成视图幂等 | T10 |
| A11 | 许可证状态说法正确：已识别 / 仅声明 / 未声明 / 其他 | 信息页只写许可名：已识别加版权行与站外全文链接，仅声明只写名字，未声明留空（摘要只写来源），其他给「其他许可」+ 全文链接；状态与允许/义务的说法在 `skmr skill license`；未声明不默认 MIT；声明与来源文件不一致时用文件的值 | T11 |
| A12 | 下载与安装带上 `.skillmaster/` 侧车，正文目录不被污染 | 浏览器下载的 zip 与 `skill get` 落地的目录里都有 `license.json` 与 `attribution.md`；上游没有许可文件时另有 `LICENSE`；正文文件不被改动；`skill ls` 默认不列 `.skillmaster/`；`skill invoke` 不落盘，不产生侧车 | T12 |
| A13 | CLI 不再打印内部相似度 | `skills search` 无论是否 `--verbose`，输出都不含「相似度」；服务端响应仍带 `score`，排序不变 | T13 |
| A14 | 默认头像稳定 | 同一条 skill 刷新后首字母与底色不变；不同名字即使首字母相同也尽量不同色 | T14 |
| A16 | 申请更高档位要先入库 | 未入库的公域详情页没有申请块；接口在未入库时拒绝（400 `invalid_request`，`details[].issue = not_in_library`），入库后同一申请通过 | T16 |
| A17 | 度量与公域解耦：公域读路径不直接访问度量表 | 代码评审：读路径、三个响应类、控制台与 CLI 只通过 M15 的接口取数；`skill_usage_day` / `skill_usage_total` 的 SQL 只出现在 M15（迁移与 `ModuleMap` 除外）；给 M15 加一个假 scope 的测试不改公域代码 | T17 |

**成立条件**：A2（来源模型可扩展）、A5（使用信号按账号去重）、A11（许可证不误导）与 A17（度量与公域解耦）不满足就不算交付——A2 是本版与「每来一个平台加一批字段」的分界线，A5 是隐私底线，A11 是「不把公开误读成随便用」的底线，A17 是「统计指标不重新长回公域需求」的分界线。

### 指标

| 指标 | 定义 | 怎么量 | 目标 |
|---|---|---|---|
| 来源覆盖率 | 公域中带来源的 skill 数 / 公域 skill 数 | 查库与页面 | 100%（官方 skill 都有来源） |
| 来源适配器新增成本 | 接一个新平台改动的文件数 | 代码评审 | 只新增适配器与测试，不改表结构与页面 |
| 使用信号可读性 | 结果行上能看到累计调用分桶的公开 skill 比例 | 页面抽检 | 有信号即显示；无信号行上不挂空行 |
| 许可证标注率 | 公域中许可证状态不是「未声明」的 skill 数 / 公域 skill 数 | 查库与页面 | 外部来源 100% 有状态；官方未声明时 CLI 返回「未声明」，页面只写来源 |
| 许可证误导率 | 抽样检查「已识别」的许可结论与全文是否一致 | 人工抽检 | 0 条把限制读成允许 |

## 依赖与前置

- **决策**：[ADR 0146](../../decisions/0146-public-is-platform-endorsement.md)（公开 = 平台背书）是本版信息层的前提；[ADR 0082](../../decisions/0082-public-and-private-with-my-library.md) 的「只搜不列」与 [ADR 0080](../../decisions/0080-cli-covers-non-high-risk-operations.md) 的 CLI 边界不变。
- **模块边界**：使用度量是本版新增的独立模块 M15 `metrics`，接口按 `scope` 扩展，兼容将来的作者 / 协作者使用；边界与依赖方向见 [`technical-design.md`](technical-design.md) §架构。新增 scope 需要一条 ADR。
- **调研**：[`docs/research/skill-trust-and-effectiveness-signals.md`](../../research/skill-trust-and-effectiveness-signals.md) 记录跨平台事实：流行度不等于质量与安全；效果证据要用对照实验；策展与可解释排序在下一版。
- **GitHub API**：公开仓库的 stars / forks / license / pushed_at 用 REST 读；需要可选 token 提高限额，token 只放服务端配置。
- **现有数据**：公域目前只有官方 skill；使用信号样本会很少，分桶与阈值必须允许「少于 10 个账号」。
- **排除的前置**：不需要先做开源同步、评测 runner 或用户反馈；本版只做读模型与一个来源适配器。
