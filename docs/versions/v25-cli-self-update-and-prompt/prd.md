## 用户与场景

**谁在用**

| 角色 | 在这一版里做什么 |
|---|---|
| **装了 CLI 的人（大多数是 Windows）** | 装完之后不再关心版本。他希望它自己变新，也希望在它做不到的时候被告知一次，而不是每次都被弹一下 |
| **用 agent 的人** | 指令文件里粘过一段规则。CLI 改了命令之后，他希望这段规则跟着变——但**不希望它被悄悄改掉** |
| **agent（常常无人值守）** | 跑 CLI 命令。发现规则段过期时，它要知道「先问人，再落笔」 |
| **发版的人** | 发一次版本之后，不用再一个个教用户重跑安装命令 |

**在什么场景下用**

- 一个人三周前按安装说明装好 CLI，之后再没跑过安装命令。这期间我们发了两版，其中一个修了他天天遇到的错误——他拿不到，而且没有任何地方告诉他。
- 内测期的更新方式是「重跑同一条安装命令」（[`skillmaster-site/public/install/skillmaster.md`](../../../skillmaster-site/public/install/skillmaster.md) §1 原文：「更新就是重跑同一条命令」）。它要求用户记得、也要求他知道有新版本。
- 规则段（粘进指令文件的、`<!-- skillmaster:begin -->` 与 `end` 之间的三行）是 `skillmaster/startup` 的内容，从粘进去那天起就停在那一版。CLI 后来新增了命令、改了主流程，规则段没有任何机制跟着走；唯一的重获方式是重走一遍旅程。
- 反过来也成立：规则段今天写在平台上，改完对所有人生效，所以它**可能领先于用户装的 CLI**——提示词让 agent 去跑一条它那版二进制里没有的命令。

**现在的替代做法是什么**：没有机制，靠人。安装说明写着「更新就是重跑同一条命令」；规则段过期连「怎么知道」都没有。CLI 的 Go 源码里没有任何 `dl.` 地址、没有 `version.txt`、没有更新逻辑（本版核实：`rg "skillmasterai|version\.txt|checksums" skillmaster-cli --glob '*.go'` 无结果）。

## 范围

### 做

| # | 做什么 | 交付形态 |
|---|---|---|
| 1 | **二进制自更新**：读 `dl.` 通道上的 `version.txt`，比本机新就下载对应产物、核对 SHA-256、换位；**默认自动装**，下一条命令生效 | CLI |
| 2 | **检测时机与节流**：进程启动后、执行命令前；24 小时一次；跳过帮助、版本与 `prompt` 组命令；`SKILLMASTER_AUTO_UPDATE=0` 关闭；`dev` 构不参与（[ADR 0088](../../decisions/0088-cli-major-version-is-the-api-generation.md)）；传输失败静默（校验失败说一次）；检查点通常每天写一次，下载失败后一小时内重试 | CLI |
| 3 | **换位方式**：macOS / Linux 下载到同目录后 `rename` 覆盖（全程不调删除原语，[ADR 0101](../../decisions/0101-the-cli-never-deletes-files.md)）；Windows 由父进程退出后、新二进制以 helper 模式把自己换到位；用锁文件防并发 | CLI |
| 4 | **写不进去时退化**：只读安装目录、沙箱拒绝 → 命令照常成功，stderr 每个新版本提示一次「重跑安装命令」 | CLI |
| 5 | **显式入口**：`skillmaster update`（立即装，打印 `旧 → 新`）与 `update --check`（只报告）；两者都不受节流与开关影响 | CLI |
| 6 | **规则段搬进二进制**：权威位置从平台技能改为 CLI 源码，随版本发布；**文本逐字不变**（v20 批准的三行，含两行标记） | CLI 源码 |
| 7 | **本机记录**：记住规则段写进了哪个文件、写的是哪一段的摘要；记录的摘要与二进制自带的不一致、且那个文件还在时，**任何未被排除的命令**都会在 stderr 提示一行（`prompt` 组、帮助与 `--version` 除外；dev 构与关掉开关时也一样），**同一个新摘要只提示一次** | CLI |
| 8 | **查看**：`skillmaster prompt status` 显示记录的路径、本机摘要、二进制摘要与差异；`skillmaster prompt print` 打印二进制自带的规则段（断网可用） | CLI |
| 9 | **首次写入**：`skillmaster prompt install --file <路径>` 写入并记录；文件里已有标记段时走第 10 条的 diff + 确认 | CLI |
| 10 | **更新**：`skillmaster prompt update` 用记录的路径更新；**不给 `--yes` 只打印 diff、不落笔、退出 1**；只替换两个标记之间的内容，段外一个字节不动；写入前先比对文件在这期间有没有被改过，改过就不写、让重跑；**全程不读 stdin、不问 y/N、不等任何输入**（同意在进程之外发生） | CLI |
| 11 | **旅程第三步改为调用 CLI**：`skillmaster/startup` 的 `steps/03-prompt.md` 不再携带规则正文，改成一条 `skillmaster prompt install --file <路径>` 与一句「先问人」 | 平台技能内容 |
| 12 | **新 ADR**：规则段随 CLI 版本走，取代 [ADR 0096](../../decisions/0096-guidance-lives-on-the-platform.md) 决定 1 里「规则段在平台上」那一半（旅程正文仍留在平台） | ADR |
| 13 | **新 ADR**：CLI 自己更新自己——只更新官方安装位置、只 `rename` 不删、Windows 用 helper 换位 | ADR |
| 14 | **Windows CI 作业**：`windows-latest` 上构建并端到端验证换位 | CI |
| 15 | **同步文档**：`skillmaster-cli/README.md`、`RELEASE.md`（通道与自更新一节）、安装说明页里「更新就是重跑同一条命令」那一句 | 仓库 |

**这一版会在本机多三个文件，都要说清楚**（[ADR 0101](../../decisions/0101-the-cli-never-deletes-files.md)：原地覆写、不删）：

- **`update.json`（节流与状态）**：平时每次检查写一次（最多每天一次）；一次成功的安装会再写两次（记下待换位、清掉待换位）；**下载失败时把检查点前移，一小时后重试，所以失败期间它可能每小时写一次**；**一个起了却一直换不成的 helper，会让它每条命令写一次**（最多四次 helper，之后丢掉记录）。
- **`prompt.json`（规则段记录）**：`prompt install` / `prompt update` 时写；**另外，任一命令发现记录里的摘要与二进制自带的不同时，会打一行提示并把「已提示过这个摘要」记下来**——不记就会每条命令重复提示。同一个摘要只写这一次。
- **`update.lock`（更新互斥）**：第一次检查时创建，之后一直存在；锁是内核的，文件在不在不代表有没有人持有它。

**这一版新增的路径都不等人。** 不读 stdin、不问 y/N、不打开浏览器，每个网络请求都有上限（检查 1.5 s、下载收尾最多 10 s），失败即退。需要人同意的那一步放在**进程之外**：agent 看到 diff 与退出码 1，去问人，人同意后带 `--yes` 重跑。**这不是保守，是有先例的**：v22 的 A4 记录过「无凭据时自动打开浏览器、等满 5 分钟」在沙箱里把 agent 的任务挂死——任何无上限等待在无人值守环境里都是事故。

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | **Windows 代码签名（Authenticode）** | 证书与发布流程是另一件事，本版拿不到；风险如实记进 [`test-plan.md`](test-plan.md) §已知问题 | 出现第一批杀软误报，或正式版对外推广之前 |
| 2 | **降级与回滚** | 正式版没有可回的旧版本：`dl.` 的 `version.txt` 守卫让站点只往前走（[`RELEASE.md`](../../../skillmaster-cli/RELEASE.md) §6）。**内测版是例外**：它的身份是提交号，任何一个不同的提交都算「更新」（ADR 0099），所以把内测标记改回旧提交等于让内测用户回退——本版不做这件事，也不提供入口 | 出现「新版坏了要退回旧版」的真实需求 |
| 3 | **通道切换（beta ↔ 正式）** | 二进制自带的通道就是它的身份（[ADR 0099](../../decisions/0099-the-cli-has-a-beta-channel.md)）；换通道 = 重跑另一条安装命令。做成开关会让「这台机器装的是哪条通道」有两个真相。**一个例外要说明白**：`SKILLMASTER_UPDATE_BASE` 覆盖更新基址，它是给镜像与测试用的接缝（TD §接口），不改变二进制自称的身份，但它确实能把一台机器指到另一条轨道——所以它写进文档、不宣传 | 若内测用户需要不重装就切通道 |
| 4 | **更新官方安装位置以外的二进制**（brew / winget / 手工拷到别处） | 官方位置 = 安装脚本写的那两处（macOS / Linux 的 `~/.local/bin`、Windows 的 `%LOCALAPPDATA%\SkillMaster\bin`）。往别处写文件，是替用户改他不想改的东西；那些装法的更新本来就该由它们的包管理器负责。行为：**自动路径一声不响**，`skillmaster update` 明确拒绝并给重跑安装命令的办法，`update --check` 仍可只读地报告 | 我们自己上 brew / winget 时 |
| 5 | **规则段的多文件管理**（一台机器只记一个指令文件） | 一个人可能给多个 agent 各粘一份，但「哪一份是权威」没有答案；本版只管理被指定过、且 CLI 写得进去的那一份 | 出现「同一台机器要维护多份」的真实需求 |
| 6 | **无条件改写用户的指令文件** | 那是用户的文件；更新必须经人同意（`--yes` 或终端里的确认） | 不做 |
| 7 | **自动保留标记段里用户自己加的行** | 分辨「哪一行是用户写的」不可靠；更新替换整个标记段，落笔前逐行显示旧段与新段，让人自己看清再决定 | 若「只使用带某标签的 skill」那类个性化行成为常态 |
| 8 | **更新成功率遥测** | 本版不引入任何上报；验收全靠端到端行为 | 有了遥测基础设施之后 |
| 9 | **在沙箱里绕过写限制去装更新** | 沙箱的拒绝就是审批边界；写不进去就退化成提示（第 4 条） | 不做 |

## 验收与指标

### 验收标准

| # | 验收标准 | 怎么判定 |
|---|---|---|
| 1 | **静默**：远端没有更新时不打印、不下载；远端比本机新时才有一行 stderr | 假发布源（本地 HTTP）上放同版与新版各跑一次，比对 stderr 行数与下载请求数 |
| 2 | **自动装（macOS / Linux）**：远端有新版时，当前命令的 **stdout 逐字节不变、退出码不变**，stderr 只有一行说明；**这条命令最多多等 10 秒**，下载没完成就放弃、不阻塞；紧接着跑 `--version` 显示新版，且跑完的旧进程没有报错 | 真实二进制 + 假发布源，端到端跑；与不更新时同一命令的 stdout 逐字节比对；用一个限速的假服务端计时 |
| 3 | **校验和不符不装**：篡改产物或 `checksums.txt` → 不替换，stderr 一行，`--version` 仍是旧版，退出码不变 | 同上，故意改一个字节 |
| 4 | **节流**：24 小时内连跑三条命令，只发出一次 `version.txt` 请求 | 假服务端计请求数 |
| 5 | **关闭开关**：`SKILLMASTER_AUTO_UPDATE=0` 时请求数为 0，命令照常 | 同上 |
| 6 | **dev 构不参与**：不带版本信息的本地构建请求数为 0 | 同上 |
| 7 | **跳过帮助与版本**：`--help`、`-h`、`--version`、`help`、`help <命令>`、裸 `skillmaster` 都不触发检查 | 请求数为 0 |
| 8 | **写不进去只提示**：安装目录只读时，命令照常成功、退出码不变；stderr 每个新版本提示一次，第二次不再提示 | 把安装目录 chmod 只读，连跑两次 |
| 9 | **显式入口**：`update --check` 只报告不下载；`update` 立即装并打印新旧版本；已是最新时打印「已是最新」并退出 0 | 假发布源上各跑一次 |
| 10 | **Windows 换位**：父进程退出后完成换位；换位期间**目标路径从不缺失**（10 ms 轮询）；安装目录里没有 `.new` / `.old` 残留；下一条命令是新版 | `windows-latest` 作业端到端跑（需要真机或 CI） |
| 11 | **并发**：两个进程同时发现新版时只有一次换位，完成后二进制版本正确、没有残留 | 同时起两条命令，查版本与目录 |
| 12 | **规则段随二进制**：断网、无凭据时 `prompt print` 的输出与源码里的文件逐字节一致（含两行标记） | 断开网络跑一次，`cmp` 比对 |
| 13 | **过期提示只在「摘要不同、且记录的文件还在」时出现**：把记录里的摘要改成另一个值后，任一命令 stderr 有一行提示；同一摘要连跑两次只有第一次有。**文件不见了不在任一命令上提示**，只在 `prompt status` 里报告（退出 1）。**标记段被删掉但文件还在**时仍会提示一次——命令只做一次 `stat`，不读内容；内容的事由 `prompt status` 回答 | 手工改记录 / 删掉文件后各跑两条命令；再把文件里的标记段删掉、重置「已提示」后跑一次，确认它按「摘要不同」提示 |
| 14 | **审批**：`prompt update` 不带 `--yes` 时打印 diff、**文件字节不变**、退出 1；带 `--yes` 时只替换标记段，段外字节不变；**两种调用都不读 stdin**——在 stdin 关闭、无终端的环境里 1 秒内返回，不挂起 | 前后 `sha256` 比对；夹具里标记段前后各有内容；`</dev/null` 与「伪终端」两种环境下各跑一次并计时 |
| 15 | **定位与幂等**：`prompt install --file` 对「已有逐字相同标记段」的文件**只记录、不写**（mtime 与字节都不变）；对没有标记段的文件追加到末尾；对已有不同标记段的文件走 diff + 确认 | 三种夹具各跑一次 |
| 16 | **不删文件**：`go test ./internal/nodelete` 绿；`strace` 下 `update` 与 `prompt` 全部子命令的 `unlink`/`rmdir` 为 0 | 既有测试 + Linux 容器 strace |
| 17 | **旅程指向 CLI**：`steps/03-prompt.md` 里不再有可粘贴的规则正文，只有 `skillmaster prompt install --file <路径>` 与「先问人」；`skill read` 能读到 | 线上读该文件 |
| 18 | **契约不回退**：新命令满足 v16 帮助契约（八项、≤ 2 KB、无 ANSI、退出码契约）；`check_docs.py` 退出 0 | 既有测试 + 校验器 |
| 19 | **官方安装位置之外不动手**：把二进制放在别处（临时目录、`/usr/local/bin`）时，自动路径零请求、文件不变；`update` 退出 1 并说「不在官方安装位置」；`update --check` 仍能报告 | 一处非官方位置的夹具（官方位置由验收 2 / 9 覆盖），查请求数与文件哈希 |

**成立条件**：**2、10、14、16** 是「不满足就不算交付」——2 是这一版的存在理由（装完真的会更新），10 是用户最多的平台（Windows），14 是「更新必须经人同意」这条产品原则，16 是 [ADR 0101](../../decisions/0101-the-cli-never-deletes-files.md) 不能被这一版打破。

### 指标

| 指标 | 定义 | 怎么量 | 目标 |
|---|---|---|---|
| 检测带来的额外延迟 | 24 小时内**第一条**命令，在远端可达但迟迟不回包时被拖多久 | 假服务端人为延迟，跑 20 次取 p95 | ≤ 1.5 s（检查自己的超时上限） |
| 其余命令的额外延迟 | 节流窗口内的命令 | 同上，第二条起 | 0（纯本地判断，无请求） |
| 触发更新的那条命令的额外等待 | 从发现新版到命令退出，多等的时间上限（**不装常驻进程的代价**） | 限速的假服务端，量端到端耗时 | ≤ 10 s，且下载未完成时不阻塞退出 |
| 换位后的可用时点 | 换位完成到新版本可用 | 端到端 | 下一条命令 |

本版**没有服务端指标**：没有任何新接口，服务端零改动。

## 依赖与前置

- **外部依赖**：`https://dl.skillmasterai.com/`——根的 `version.txt`、`checksums.txt` 与六个产物包；内测通道是其下的 `beta/`，同构（[`RELEASE.md`](../../../skillmaster-cli/RELEASE.md) §4、§6）。产物名不带版本号、`Cache-Control: no-cache`、`version.txt` 最后写——这三条保证「读到标记时它担保的东西都在位」。
- **内部前提**：
  - [ADR 0099](../../decisions/0099-the-cli-has-a-beta-channel.md)：内测的版本串不动，**提交号才是构建身份**——检测必须按它比较，否则内测用户永远停在第一次装的构建上；
  - [ADR 0101](../../decisions/0101-the-cli-never-deletes-files.md)：换位只能用 `rename`，旧文件不能删；
  - [ADR 0088](../../decisions/0088-cli-major-version-is-the-api-generation.md)：`dev` 是开发构建，不参与；
  - [ADR 0096](../../decisions/0096-guidance-lives-on-the-platform.md)：本版取代它关于「规则段在平台上」的那一半；
  - [ADR 0087](../../decisions/0087-cli-exit-codes-are-a-public-contract.md) 与 v16 帮助契约：新命令要满足既有契约。
- **需要什么前置**：`internal/version` 要新增「通道」与「下载基址」（编译期注入，发布流水线已有 `-ldflags` 注入的同一条路）；Windows 真机或 `windows-latest` 跑一次换位验收。
- **排除了什么前置**：不需要服务端改动、不需要数据库迁移、不需要控制台页面、不需要签名证书（风险自担并记录）。
