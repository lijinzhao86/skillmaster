## 目标

CLI 装到用户机器上之后能自己变新（默认自动装，下一条命令生效），并且把「系统提示词里那段规则」从平台技能搬进二进制、随版本走——发现用户的文件里是旧版时只提示，**经人同意才改写**。细节见 [`prd.md`](prd.md)。

## 验收标准

一句话摘要：假发布源上验证「检测 → 下载 → 校验 → 换位 → 下一条命令生效」全链路（mac/Linux 与 Windows 各一条），以及规则段过期的提示与「不给 `--yes` 不落笔」。完整验收见 [`prd.md`](prd.md) §验收与指标。

**成立条件**：验收 2（真的会自动装）、10（Windows 换位）、14（没有 `--yes` 不动用户的文件）、16（不引入删除）——任一条不过即不算交付。

## 这一版明确不做什么

摘要三条最要紧的；**完整范围与每条的理由在 [`prd.md`](prd.md) §范围**。

- 不做 Windows 代码签名 —— 证书与发布流程是另一件事，本版只把杀软误报记成已知风险
- 不做降级与回滚 —— 正式通道只往前走；内测按提交号比较，改回旧提交等于让内测用户回退，本版不做这件事
- 不做通道切换 —— 二进制自带的通道就是它的身份，换通道靠重跑另一条安装命令（`SKILLMASTER_UPDATE_BASE` 只是测试与镜像的接缝）

## 与目标态的关系

[`target/`](../../target/) 描述的是完整形态。这一版只改「客户端怎么拿到新的自己」与「规则段的权威在哪」：

- 保留的部分：内容仍只在服务端，CLI 仍是 agent 的入口（[ADR 0089](../../decisions/0089-no-local-skills.md)）；旅程仍是平台上的技能（[ADR 0096](../../decisions/0096-guidance-lives-on-the-platform.md) 关于旅程的那一半不变）。
- 已经分叉的部分：**规则段不再在平台上**，改为随 CLI 版本发布——差异清单见 [`target/README.md`](../../target/README.md) §六。

## 影响最大的未决问题

完整列表见 [`technical-design.md`](technical-design.md) §开放问题。按重要性排前三条：

1. **Windows 真机验收（T10）**：helper 换位这条路径只能在 Windows 上跑，本机无法验证；它是这一版的成立条件之一。
2. **平台内容（T17）**：`skillmaster/startup` 的第三步仍带着规则正文，要由技能主人改成指向 `skillmaster prompt install` 并上线——这不在本仓库，也不随 CLI 发版。
3. **内测通道的「更新」包含回退**：内测按提交号比较，标记改回旧提交等于让内测用户回退；正式通道没有这个问题（见 TD Q7 与 PRD 不做 #2）。
