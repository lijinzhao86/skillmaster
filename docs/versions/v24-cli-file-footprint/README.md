# v24-cli-file-footprint · CLI 的文件脚印：永不删除，pin 一 skill 一文件

> **最后更新**：2026-10-27
> **状态**：进行中（**已实现并合入 main**，merge `1485383`，2026-10-27；**CLI beta 已发同一提交**：`1.1.0-beta (1485383)`；验收 1、2 与行为契约已验，验收 3 的两个沙箱实测待做——见 [`test-plan.md`](test-plan.md) §结果）
> **含收费**：否

## 目标

发布出去的 `skillmaster` 二进制在任何路径上都不发起文件删除；pin 从「一个 server 一张表」改成一 skill 一文件、原地覆写。细节见 [`prd.md`](prd.md)。

## 验收标准

非测试源码里删除原语为 0、一组命令在 `strace` 下的 unlink/rmdir 为 0、两个目标沙箱的审批里没有删除；完整验收见 [`prd.md`](prd.md) §验收与指标。

**成立条件**：上面三条任一条不过即不算交付——它们是这一版的存在理由。

## 这一版明确不做什么

摘要三条最要紧的；**完整范围与每条的理由在 [`prd.md`](prd.md) §范围**。

- 不做读命令零写 —— 产品负责人 2026-10-27 定：写可以接受，记住版本必须落一次
- 不做状态目录搬迁与钥匙串开关 —— 本版只解决删除，另开一版评估
- 不做安装脚本的 `rm -rf` —— 那不是 CLI 二进制，是一次性安装脚本

## 与目标态的关系

- 保留的部分：CLI 仍是 agent 的入口，内容仍只在服务端，钉仍在本机（[ADR 0035](../../decisions/0035-the-pin-lives-on-the-client-machine.md)）。
- 已经分叉的部分：无新增。这一版只收紧本地副作用与存储形状，不改产品能力边界。

## 影响最大的未决问题

完整列表见 [`technical-design.md`](technical-design.md) §开放问题。按重要性排前三条：

1. **同一 skill 并发写的交错**：原地覆写把「后写者赢」换成「可能读到一份坏文件」。当前倾向不加锁，理由与代价写在 ADR 0101 §后果。
2. **Windows 上替换已存在的空目录**：改为把旧空目录改名留作 `.replaced-*`，人看得见、CLI 不删。
3. **`strace` 那条验收在哪里跑**：不做成 Go 测试，写成 test-plan 里的可复现命令，在 Linux 上跑并如实记结果。
