# v44-cli-read-write-contract · 建草稿独立成动作，CLI 读写按意图收口

> **最后更新**：2026-11-04
> **状态**：已实现（服务端 + CLI + 生成物；单测与集成测试通过，端到端 T1/T2/T6/T7 待本地环境跑）
> **含收费**：否

## 目标

让“建草稿”成为一个独立命令，`write` 只写已有草稿；建草稿前先看自己是否已有未上线草稿，不自动攒重复草稿。再把 `skmr` 的文件读写命令从“按内容从哪来”改成“按意图”选用：`write --from` 收编 `put`，`get --all` 收编 `download`，覆盖前先让人看见将改什么；`edit` 补上 stdin、`--stdin-json` 与批量输入；裸地址读 `SKILL.md` 拒绝并提示先 `invoke`。细节见 [`prd.md`](prd.md)。

## 验收标准

十三条验收（A1–A13），摘要其中三条：`draft create` 能从线上版本起一份内容不变的草稿并给出可直接复制的下一步命令；旧动词真的退场并给迁移提示；`edit` 的三种输入通道都能用且批量原子。完整验收见 [`prd.md`](prd.md) §验收与指标。

**成立条件**：A1（建草稿独立成动作）、A5（旧动词退场）、A8（`edit` 三种输入通道）与 A13（重复草稿拦截）不满足就不算交付。

## 这一版明确不做什么

- 不改控制台界面与设计件 —— 控制台仍按“第一次改动落草稿”工作，要改得先出设计稿
- 不在控制台加同样的“已有草稿”拦截 —— 网页上点“新建版本”是人的明确动作，不是 agent 的循环
- 不让 `draft create` 自动复用已有草稿 —— 本版选择“拒绝 + 列出 + `--new`”，由人决定
- 不让写命令省略 `@<版本码>` —— 版本码是草稿身份，多份草稿是常态，省略只能靠猜
- 不保留 `put` / `download` 别名 —— 2026-11-04 定硬删，保留会让混淆多活一版

## 与目标态的关系

[`target/`](../../target/) 描述的是**完整形态**。这一版是它的一个子集，只收口 CLI 的草稿创建与文件读写面：

- 保留的部分：服务端权威、版本钉、内容在草稿上就地改都不变。
- 已经分叉的部分：无新增分叉；本版消除的是“建草稿必须顺手写内容”与词表、输入通道上的历史包袱。

## 三个关键取舍（已定）

完整论证见 [`technical-design.md`](technical-design.md) §开放问题与三条 ADR：

1. **草稿唯一约束的形状**：`UNIQUE (skill_id, digest)` 改成排除草稿的局部唯一索引；重复内容的冲突在**上线时**由发布路径检查（[ADR 0135](../../decisions/0135-a-draft-may-be-copied-from-a-version.md)）。
2. **“本机读过”的记录形状**：单独放在版本钉目录旁的 `reads/`，按 `(地址, 版本码, 路径)` 记 ETag，不塞进版本钉本身（[ADR 0136](../../decisions/0136-cli-file-verbs-follow-intent.md)）。
3. **`get --all` 的内存上限**：沿用 `download` 的约 17 MiB，整版读进内存；更大版本用单文件逐个取（本版不做流式）。
