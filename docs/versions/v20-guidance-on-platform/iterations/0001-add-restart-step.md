# 0001 · 加第六步：重启 agent 才加载新提示词

> **日期**：2026-10-26
> **所属版本**：[`../README.md`](../README.md)
> **类型**：小版本迭代——**未改变对外可验收的能力边界**

## 改了什么

- `skillmaster/startup` 新增 `steps/06-restart.md`：旅程最后一步，只有人能做——重启 agent，第三步写进系统提示词的那段才会被加载。
- `steps/05-retire.md`：前置条件不再说「提示词已经生效」，改成「是否生效要等第六步重启后才知道」；收尾从「旅程完成」改成指向第六步。
- `SKILL.md`：现场状态「已完成」那一行从「不用读，直接告诉人」改成指向第六步（`@1.1.0`）；随后 `@10K2Y2XB` 草稿再收窄成先确认第三步那段提示词在不在指令文件里：在 → `steps/06-restart.md`，不在 → `steps/03-prompt.md`。状态行既判断不到重启，也判断不到提示词写没写，不能让它直接收工。
- `technical-design.md` §CLI：把「步骤是 1–5」改成 1–6，并写明状态行判断不到重启，这一态由技能首页先确认提示词再映射。
- `README.md` §状态：把 P0 的现状更新到 `@1.1.0` 已上线、`@10K2Y2XB` 草稿待上线。

## 为什么

- 系统提示词只在**会话开始**时加载。第三步写完，当前会话用的仍是旧提示词；原来的旅程没有这一步，也没有在任何地方告诉人「要重启」。
- 第五步的前置条件还写着「提示词已经生效」，在没重启时是假的；这会让人以为规则已经生效，从而放心删掉本机副本。
- 把重启单独成一步，而不是塞进第三步：它只有人能做，且必须放在下线之后——先重启会中断当前旅程。
- 「已完成」态不只出现在走完旅程的人身上：本机没有副本、库里有线上 skill 就会报它，包括从没写过提示词的人。所以这一态要先确认提示词，不能无条件指到重启。

## 影响

- **影响哪些已交付行为**：旅程从 5 步变 6 步，`@1.1.0` 已上线；`skillmaster startup` 的状态行本身不改（仍然判断不到重启）。1.1.0 的「已完成」态直接指 06；`@10K2Y2XB` 草稿再改成先确认提示词、再分流到 03 或 06。按 1.0.2 走过第三步的人不会自动知道要重启，不过他们的规则在下一次会话本来就会加载，没有破坏性影响。
- **需要同步改哪些文档**：`README.md`、`technical-design.md`、本条迭代记录已改；`prd.md` 与 `test-plan.md` 没有新的对外验收项，不改。
- **是否需要新开 ADR**：不需要。这是同一旅程的内容调整，没有改变跨版本的取舍。
- **验证**：线上 `@1.1.0` 的 `version diff ... --from 1.0.2` 只报 `SKILL.md`、`steps/05-retire.md`、新增 `steps/06-restart.md` 三处；`skill read skillmaster/startup@1.1.0 steps/06-restart.md` 首行为「# 第六步 · 重启 agent」，`steps/05-retire.md` 收尾指向 06。草稿 `@10K2Y2XB` 对照 `1.1.0` 只改 `SKILL.md` 一行（「已完成」态先确认提示词）。
