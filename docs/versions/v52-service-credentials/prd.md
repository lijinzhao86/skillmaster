# v52-service-credentials · 产品需求

> **最后更新**：2026-11-09
> **所属版本**：[`README.md`](README.md)
> **调研依据**：[`docs/research/third-party-credentials.md`](../../research/third-party-credentials.md)（2026-10-31，事实底稿）

## 用户与场景

**谁在用**：两类人。

- **用 skill 的人**：agent 用户。其中相当一部分是非技术用户——会装 CLI、会让 agent 跑 skill，但不会去第三方控制台申请 key，也不会 `export`。
- **写 skill 的人**：作者，以及被他邀请的协作者（个人对个人，最多小团队）。

**在什么场景下用**：

1. **换机器、换 agent**。同一份 skill，昨天在笔记本上跑通，今天在公司的台式机上、或者换一个 agent 跑，就要重新找 key、重新设一遍。
2. **协作者接手**。作者把 skill 共享给同事，同事没有那把 key；作者不能直接把 key 发给他——发了就收不回，也不知道他有没有再转出去。
3. **skill 正文要求「把 key 发我」**。`lijinzhao/byted-web-search` 的说明原文就是这么写的；key 一旦发进对话，就进了模型上下文与对话记录。
4. **作者把 key 写进包**。2026-10-31 实测：`skmr skill download lijinzhao/byted-web-search` 落下的 `.env` 里就是那把 key。包一共享就泄露，作者轮换后旧包仍是旧值。
5. **登录态类凭据**。用户在小红书网页上登录后拿到的是 cookie，它不在用户手上（在浏览器的存储里），但 agent 能找到；这类值不是「一把 API key」，而是一段文本，skill 自己决定怎么用它发请求。

**现在的替代做法是什么**：粘进聊天框、写进 `.env` 随包走、各自 `export`、作者发明文给协作者。前两条是泄漏；后两条不可持续（换机器重来、撤销不了、没有审计）。

平台今天没有任何一张表、一个接口、一个界面承接「用户 → 第三方」的凭据。现有「API 密钥」是反方向（用户 → 我们，`api_key` 表只存哈希），两者不能混用。

**这一版要保证的一句话**：**同一份 skill，在任何一台已登录的机器上跑，用户不用重新填 key；值不进对话、不随包下发、作者随时能撤销。**

## 范围

**「凭据」与「绑定」是两层**（2026-11-08 定）：

- **凭据** = 用户的一条值（一段不透明密文），有名称、有每日用量。同一把 key 用在几个 skill 上，只存**一条**。
- **绑定** = `(凭据, skill, 环境变量名)`，一条值可以有**多条**绑定。它回答「这个人跑这个 skill 时，往哪个环境变量放什么值」。
- **绑定是唯一的暴露途径**：没绑过的 skill 拿不到值，协作者也不能自己给别人的凭据加绑定。所以「值属于用户」不会变成「谁都能取」。
- 注入按「这个用户**实际可用**的绑定」算：自己的绑定优先于共享来的，撤销后立刻不算。

### 做

| # | 做什么 | 交付形态 |
|---|---|---|
| 1 | **平台保险箱**：一条凭据 = 用户的一段**不透明密文**，通过**绑定** `(凭据, skill, env 名)` 暴露给 skill；一条值可以绑多个 skill、多个变量名。平台不解析内容——API key、cookie、JSON、任意文本都同一种处理；根密钥在华为云 KMS | 新模块 M16 + `service_credential`、`credential_binding`、`credential_use`、`credential_share` 四张表 |
| 2 | **注入只在有绑定时发生**：`skmr run` 先看这个用户在这个 skill 上有没有绑定；**没有 → 与今天的运行路径完全一致**（不多一次凭据请求、不多一个失败点）；有 → 取租约，把值放进子进程环境变量，skill 自己决定怎么用它发请求 | `run` 的注入路径 |
| 3 | **值的输入方式**：`skmr secret set` 只从 **stdin** 读——支持 `< 文件` 与管道；**不接受命令行参数传值**，避免值进 shell 历史与对话 | CLI 命令 |
| 4 | **管理命令**：`skmr secret set / list / rotate / rm`；列表只显示名称、绑定 skill、env 名、今日用量与上次使用；**没有 `secret get`** | CLI 命令 |
| 5 | **可选声明**：skill 可在 `metadata.requires.credentials` 写 env 名列表（如 `[WEB_SEARCH_API_KEY]`）。它是**平台扩展**、可选、**只用于提示**；不声明不影响使用 | 服务端从版本的 frontmatter 解析，`Metadata` 响应给 `credentials_required`（作者声明的）与 `credentials_missing`（对**当前调用者**还缺的）；`skmr run` 与 `skmr skill check` 打印提示，点名 env 名并给出让**用户**执行的 `skmr secret set` 命令，**不拦运行** |
| 6 | **审计**：生命周期各一条事件（`credential_create` / `credential_rotate` / `credential_delete` / `credential_bind` / `credential_unbind` / `credential_share` / `credential_unshare`）；**使用不逐次写审计表**，只按天聚合 + `last_used_at` | M10 `audit_event` + 聚合 |
| 7 | **共享按「凭据 + skill」**：凭据主人可以把一条凭据在**某一个 skill 上**共享给该 skill 的已接受协作者；默认不共享；只在这一个 skill 上生效，同一把值给三个 skill 用就要共享三次（更精确，也避免「以后绑到新 skill 对方自动能用」）；协作者不能给别人的凭据加绑定；他自己有绑定的优先用自己的；撤销对下一次运行立即生效 | `credential_share` 表（凭据 + skill + 被授权人）+ 接口 |
| 8 | **共享必须显式确认**：确认文案说清「对方能在他的机器上使用，也能提取明文」；不确认不生效 | 控制台的确认弹窗；CLI 的 `secret share` 只把页面打开，不在命令行里完成（见「不做 13」） |
| 9 | **配额是安全阀，不是设置项**：每条凭据默认 **500 次取用/天**（覆盖日常与批量）；用户可通过 CLI / 控制台调大调小（平台硬上限 10,000）。**在 CLI 与控制台上，提高上限必须由用户确认**：CLI 交互确认，非交互环境直接拒绝并打印让用户执行的命令；控制台就地输入并保存。API 平面不另设确认——持写权限 key 的人本来就能取租约拿明文（见「不做」与开放问题 6 的结论）。超出时租约失败，提示同时面向 agent 与用户——给当前上限、原因、提高的命令，并明确告诉 agent「不要自行提高」。**计量单位是「取用次数」**（每次 `skmr run` 用一条凭据算一次），不是第三方请求次数——注入模式下平台看不到请求。日配额**不防死循环**（十分钟就能烧完），那一层是平台级速率限制，不是用户要配的项 | `credential_use` + 设置接口 |
| 10 | **控制台「权限 › 服务凭据」页**：列表（名称 / 用于 / 环境变量 / 今日用量 / 操作）、新建、更新值、绑定、删除（弹窗确认）、共享面板（含撤销）、上限就地调整；**技能设置 › 服务凭据**面板管「这一个 skill 用了哪些」。设计稿见 `design/src/console`（v52 已出），实现照抄 | `/account/secrets` 页面 + 技能设置子页 + `/web/secrets*` |
| 11 | **别人共享给我的凭据看得见**：技能设置页对每一行标明来源（`你` / `共享自 <某人>`），由服务端列出「仍然算数的共享」——不再是协作者就为空；CLI 对应 `skmr secret incoming` | `GET /api/v1/secrets/incoming`、`GET /web/secrets/incoming`、`skmr secret incoming` |

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | **CLI 本地反代**（`127.0.0.1` + 一次性 token） | 只覆盖「脚本自己发 HTTP 请求 + 地址取自注入变量 + 凭据是固定 header」的一小类；浏览器自动化、body/query、写死域名的 skill 都用不上，却要为每家客户端做沙箱探测与降级（[ADR 0169](../../decisions/0169-the-first-version-injects-without-proxying.md)） | 不做 |
| 2 | **平台代转**（请求经我们转发，key 永不离开平台） | 成本（流量、隐私与保留期、IP 白名单、可用性）在个人 / 小团队场景不划算；留到允许用户公开 skill 时做增值功能（[ADR 0169](../../decisions/0169-the-first-version-injects-without-proxying.md)） | 公开 skill 重新开放时 |
| 3 | **服务注册表**（上游域名、认证形状） | 注入模式不需要它；引入它只为反代服务，而反代这一版不做 | 与「不做 2」同版 |
| 4 | 托管身份密码（登录第三方的密码） | 与 API 凭据不是同一类数据：不能轮换、通常不可撤销、责任面完全不同（[ADR 0168](../../decisions/0168-hosted-credentials-are-api-keys-not-identity-passwords.md)） | 未定，需要新 ADR |
| 5 | 平台解析凭据内容、替 skill 生成请求、判断凭据是否有效 | 平台存的是不透明字节，用法在 skill 里；凭据失效（401）由 skill 自己报 | 不做 |
| 6 | 组织级共享 | 还没有组织模型，共享是个人对个人 | 组织模型落地后 |
| 7 | 公开 skill 使用某个人的 key / 平台代付 | 等平台代转；否则等于一把 key 给陌生人用 | 与「不做 2」同版 |
| 8 | 控制台查看明文、任何「读回值」的接口、`skmr secret get` | 一旦有读回值的口子，「托管」就不成立。**唯一的例外是取租约那一次响应**——它必须给运行中的 skill 明文，所以它 `no-store`、只按需发一次 | 不做 |
| 9 | 凭据需求自动发现（猜 skill 用了哪些环境变量） | 没有可靠依据；声明可选，没声明时平台保持沉默 | 不做 |
| 10 | 自动刷新 / 续期（cookie 过期后自动换新） | 依赖每个服务的登录流程，是另一类工程；第一版只提供 `rotate` | 有稳定的服务适配时 |
| 11 | 上传时扫描凭据文件、存量治理、轮换已泄露的 key | 平台尚未上线，整体治理放进一个大版本；已记 [`TODO.md`](../../current/TODO.md) | 那个大版本 |
| 12 | 异常使用告警（速率、异地） | 先有审计数据，再定阈值 | 审计数据积累后 |
| 13 | **在命令行里直接写共享**（`share` 直接调接口、不经过页面） | 高风险：它把一把凭据交给另一个人，对方能在自己的机器上使用并提取明文；不由 agent 代做（[ADR 0081](../../decisions/0081-every-console-operation-has-a-cli-command.md) 第一类例外，**2026-11-08 产品负责人确认**）。**命令本身存在**——`skmr secret share` 是页面动作（[ADR 0126](../../decisions/0126-page-only-actions-open-the-page.md)），首句写「还没执行」，把控制台那一页打开，确认在页面上由人做；服务端的 `POST /api/v1/secrets/{id}/shares` 在 P2 下线，所以没有绕开页面的路 | 未定；再议时需要重新确认风险承担方式 |
| 14 | **`secret share` 不做 ADR 0127 那种预检** | 那条预检读的是作者页上的档位，属于 skill 级动作；凭据共享是账号级动作，没有可读的档位。页面本身按登录状态只列自己的凭据——真跑错，人看到的是「没有这一条」，不是一个能按下去的按钮（[ADR 0127](../../decisions/0127-never-published-skills-may-be-deleted-by-a-credential.md) 的例外，2026-11-09 实现时定） | 若以后凭证页也有可预检的状态，再补 |

**开发期怎么用（不是新功能）**：作者在调试时，先发一个**私有版本**，用 `skmr run <地址>@<版本>` 钉住它跑——绑定挂在 skill 上，草稿期也能绑，钉版本就能注入。**不为此加草稿期运行、也不加独立的注入命令**；如果作者的调试循环重到不可接受，再单独评估一条更小的命令。

**一条措辞约束（不是功能）**：「agent 看不到值」**不是**这一版的承诺。注入模型下 agent 能读到值；产品文案只能写「不进对话、不随包下发、换机器不用重贴、作者可撤销、每次使用有审计」（[ADR 0169](../../decisions/0169-the-first-version-injects-without-proxying.md) §后果）。

**范围里没有「后续再看」「视情况而定」**；不确定的进 `technical-design.md` §开放问题。

## 控制台操作与 CLI 对应

| # | 控制台操作 | CLI 命令 | 备注 |
|---|---|---|---|
| 1 | 新建服务凭据（值不回显），并绑定到第一个 skill | `skmr secret set --skill <地址> --env <NAME>` | 值从 stdin 读；不接受 `--value` |
| 2 | 列出我的凭据（名称、绑定 skill、env 名、今日用量） | `skmr secret list [--skill <地址>]` | **永不输出值**；控制台不设「最后使用时间」列，CLI 会打印上次使用 |
| 3 | 更新值（替换值，保留绑定） | `skmr secret rotate <id>` | 从 stdin 读新值；命令名 `rotate` 保留，界面与提示用「更新」 |
| 4 | 删除 | `skmr secret rm <id> --yes` | 高风险，[ADR 0056](../../decisions/0056-dangerous-actions-are-confirmed-in-a-modal.md)；控制台弹窗确认 |
| 5 | 共享给协作者（高风险，**只在控制台完成**） | `skmr secret share <id> --skill <地址> [--user <用户名>]` | **页面动作**（[ADR 0126](../../decisions/0126-page-only-actions-open-the-page.md)）：首句「还没执行：共享只能在网页上由人确认」，然后打开控制台并带上 `?state=share&secret=&share=&user=`。`--print` 只打印地址，`--json` 给 `{action, performed:false, url, opened}`。对象必须是这个 skill 已接受的协作者 |
| 6 | 撤销共享 | `skmr secret unshare <id> --skill <地址> --user <用户名>` | 直连 `DELETE /api/v1/secrets/{id}/shares`：拿回的是自己给出的授权，可重新共享，不需要页面确认。控制台里仍需弹窗（ADR 0056） |
| 7 | 查看谁在用它（共享面板） | `skmr secret shares <id> [--skill <地址>]` | 只读，可以留在 CLI |
| 8 | 把一条凭据再绑到一个 skill / 一种变量名 | `skmr secret bind <id> --skill <地址> --env <NAME>` | 已有绑定则报错，不静默改 |
| 9 | 解除一个绑定 | `skmr secret unbind <id> --skill <地址> --env <NAME>` | 删的是绑定，值还在 |
| 10 | 调整某条凭据的每日取用上限 | `skmr secret quota <id> --per-day <N>` | 默认 500；提高需交互确认，非交互拒绝；硬上限 10,000 |
| 11 | 看别人在这个 skill 上共享给我的凭据（技能设置页的「来源」列） | `skmr secret incoming --skill <地址>` | 只读，不带值 |

**P1 的边界（照实说）**：共享与撤销写在 P1 只在产品面留在控制台，但 `/api/v1` 的端点对持有写权限 API key 的客户端仍然开放。**P2 把共享的写收进会话平面**：`POST /api/v1/secrets/{id}/shares` 下线（405），只有 `/web/secrets*`（会话 + CSRF）能写共享。**撤销共享不跟着关**——拿回授权不是高风险（见上表第 6 行），`DELETE` 两个平面都留着。**配额也不关**：持有写权限 key 的人本来就能取租约拿到明文，关掉提额只是让 agent 少一条路，收益很小（开放问题 6 的另一半因此结论相反）。

**例外：共享只在页面上完成**（[ADR 0081](../../decisions/0081-every-console-operation-has-a-cli-command.md) 的第一类：改变「谁能调用」——高风险动作只在页面上做）。**2026-11-08 产品负责人确认**：这是高风险操作——它把一把凭据交给另一个人，对方能在自己的机器上使用并提取明文；**不让 agent 代做**，用户必须自己在页面上点。**但「只在页面上做」不等于「CLI 没有命令」**（2026-11-08 用户纠正）：`skmr secret share` 存在，它是页面动作，只负责把那一页打开并说清动作还没发生。CLI 是前端的第一用户，页面独占的动作也必须有命令才找到得去。

其余每一处控制台操作都有 CLI 对应。

**命令收的是 id，不是名称。** 名称是给人看的标签（可以中文、可以带空格），id（一个不透明串，形如 `01J…`，与仓库里其它资源的 id 同一种）才是身份；`skmr secret list` 两栏都打印。这样两个同名凭据、或名字里有空格时，命令都不用加引号和猜。

## 验收与指标

### 验收标准

| # | 验收标准 | 怎么判定 | 用例 |
|---|---|---|---|
| 1 | **跨机器、跨 agent**：A 机 `secret set` 之后，B 机（同一账号）`skmr run` 同一个 skill 成功，不需要额外配置 | 两台机器、同一份 skill；B 机第一次运行退出码 0；换一个 agent 同理 | T1 |
| 2 | **值不进对话、不随包下发**：`set` 只从 stdin / 文件 / 管道取值；任何命令与输出都不打印值；错误提示里**不出现值**（名称、id、env 名、上限可以出现） | 逐条命令检查；日志扫描；审查所有错误路径 | T2 |
| 3 | **任意文本可用**：一段 4 KB 的 cookie、一段多行 PEM、一段 JSON 都能存，并在 `run` 后逐字注入到环境变量 | 三类值各存一次，子进程里比对逐字相同 | T3 |
| 4 | **没有读回出口**：控制台、CLI、日志、错误提示里都不出现值；唯一的明文出口是取租约那一次响应（`no-store`） | 逐条检查接口与命令；日志扫描；检查响应头 | T4 |
| 5 | **共享是高风险、只在页面上完成**：共享页常驻一条高风险提示（含「对方能提取明文」）；共享需要显式确认；`skmr secret share` 只打开页面、自己不写共享，且 `POST /api/v1/secrets/{id}/shares` 已下线（绕过页面没有路）；协作者能用自己的身份跑通（且只在这一个 skill 上）；换到同一条凭据绑定的另一个 skill 上不生效；他不能给**作者的**凭据加绑定（绑自己的可以）；撤销后下一次运行失败 | 两个账号，真服务端；检查提示、确认、CLI 命令面与请求路径、撤销后的运行 | T5 |
| 6 | **声明只提示**：声明了凭据但没绑定时，输出点名 env 名，并给出让**用户**执行的命令；`skill check` 同；不阻止运行 | 无绑定直接 run，观察输出与退出码 | T6 |
| 7 | **未声明的 skill 仍可用**：没有 `metadata` 的 skill，用户手动绑定后照样跑通 | 用一个不含声明的 skill 做同一流程 | T7 |
| 8 | **控制台与 CLI 一一对应**：上表每一行都有可执行命令。第 5 行（共享）的命令只把页面打开、在页面上确认；第 6 行（撤销）直连生效 | 逐行执行 | T8 |
| 9 | **删除承诺**：删除后生产库立即查不到；备份按 **30 天**保留期过期的说法与隐私政策一致 | 删除后查表、查 API；对照文案 | T9 |
| 10 | **审计**：创建 / 更新值 / 删除 / 绑定 / 解绑 / 共享 / 撤销共享各有一条事件；使用只在 `credential_use` 里按天聚合 | 查 `audit_event` 与聚合 | T10 |
| 11 | **一条值绑两处，一处生效于两处**：同一把值绑到两个 skill（或两个变量名），更新一次值两边都拿到新值；删除一次两边都取不到 | 同一把值绑到两个 skill，各跑一次；更新值后各跑一次；删除后再各跑一次 | T13 |
| 12 | **没有绑定的 skill 不受影响**：`run` 发出的请求与今天一致，不多一次凭据相关请求 | 对比有无绑定的两次运行，抓请求 | T11 |
| 13 | **配额默认 500、可调、提高需用户确认**：第 501 次租约失败，提示含当前上限、原因、提高命令与「不要自行提高」；CLI 在非交互环境尝试提高被拒；控制台就在那一行就地输入并保存，且该凭据在列表上标「已达上限」 | 真服务端；连续取用；用 agent 非交互地尝试提高 | T12 |
| 14 | **别人共享给我的看得见、也散得掉**：技能设置页对每一行标明来源，服务端只列仍然算数的共享——协作者身份被撤销后，这个列表立刻为空（与租约一致）；`skmr secret incoming` 同 | 两个账号，真服务端；共享后看列表、撤销协作者后再看 | T5、T8 |
| 15 | **生产封存由华为云 KMS 完成**：`sealer=huawei` 时服务端调华为云 `EncryptData`/`DecryptData`（华东-上海一，一把 AES_256 CMK）；`sealer=aliyun` 的实现保留但生产不用；`prod` profile 下 `sealer=local` 启动失败；部署工作流拒绝 `local`、缺密钥 ID / 地域即失败，`sealer=huawei` 时缺 AK/SK 也失败（`aliyun` 可留空走同机 RAM 角色）；测试仍用 `local`；KMS 不可达时回答 503 `credential_vault_unavailable`，异常映射由单测覆盖，客户端超时为 2 s 连接 / 5 s 读 | 真机一次加解密往返；用 `prod` + `local` 起一次服务；干跑部署闸门；KMS 失败的 503 映射由单测覆盖，客户端超时值（2 s / 5 s）在配置里核对（真机断网未跑，未列入验收） | T14、T15 |

**成立条件**：**验收 1 与验收 5 不满足就不算交付**——它们是「换机器不用重贴」与「共享前说真话」这两句承诺本身。

### 指标

| 指标 | 定义 | 怎么量 | 目标 |
|---|---|---|---|
| 首次运行成功率 | 绑定凭据后第一次 `skmr run` 退出码为 0 的比例 | 运行回执（不含值） | ≥ 95% |
| 共享撤销延迟 | 从撤销到下一次运行失败的时间 | 真服务端计时 | 下一次运行立即生效（无等待窗口） |
| 租约延迟 P95 | `lease` 从请求到返回的 P95 | 服务端指标 | ≤ 500ms；2026-11-09 本机实测单次 KMS 解密 92–267ms、加密 69–104ms（4 次，含 SDK 与跨云公网），一个凭据仍在预算内，两个凭据余量不大 |

## 依赖与前置

- **外部依赖**：华为云 KMS（一把 CMK，华东-上海一）；控制台设计稿（第 10 条实现前）；隐私政策里的备份保留期（30 天）。
