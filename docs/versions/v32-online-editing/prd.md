## 用户与场景

**谁在用**：手里有 `write` 档的 agent 与作者。agent 只有终端，没有网页。

**在什么场景下用**：agent 被要求「把 `SKILL.md` 里那句命令改掉」「把 `references/api.md` 里过期的字段删掉」。它需要先看一眼原文、再改一处、然后确认自己改对了——这三步都在服务端完成，改出来的仍是同一份草稿。

**现在的替代做法是什么**：

| 做法 | 差在哪 |
|---|---|
| `skill read` → `skill edit --old --new` | 读是带行号的渲染（`1\t…` + 页脚），不能直接引用；`--old` 走 shell 参数，多行要靠转义；改完只回「已修改（digest）」，agent 无法自查，只能再读一遍——再读又是行号渲染 |
| 本地写好一个目录 → `skill submit` | 每条命令都要草稿码；`submit` 永远按内容建**新版本**（幂等只对同内容成立），本地往返落不回同一个草稿；多轮修改会持续产生新草稿 |
| 本地 `download` → 改 → `submit` | 同上，而且 `download` 是一次性快照（[ADR 0068](../../decisions/0068-export-is-a-one-shot-snapshot.md)），与草稿身份无关 |

**实测（2026-10-30）**：本机一次真实修改里，agent 用 `read` 的输出（含 `N\t`）覆盖整份 `SKILL.md`，行号被写了进去；`skill write` 原样上传，服务端只校验 frontmatter 与路径，**没有任何一层拦住它**。

## 范围

### 做

| # | 做什么 | 期 | 交付形态 |
|---|---|---|---|
| 1 | `skill edit` 接受 `--old-file` / `--new-file`：内容从文件读，绕开 shell 引号与多行转义 | 一期 | CLI |
| 2 | 改完回显实际改动：stderr 打 `@@ -a,b +c,d @@` 与 `-`/`+` 行（3 行上下文，最多 60 行），再打一句「这一版现在是 `<地址>@<码>`；再读拿到的就是这份内容」。`@new` 路径同样回显，码是新建出来的那一份 | 一期 | CLI |
| 3 | 0 匹配的诊断：`--old` 带着 `read` 的行号（非空行全是 `N\t` 且编号连续，并且去掉后是整行或多行，或末尾带着 `read` 的注记）；只差空白（按行去掉行尾空白后**恰好一处**，或多处时取唯一的整行对齐那处，给出实际行号与原文）；否则给最接近的一行与行号（相似度 ≥ 0.6）；都不成立时给出取原文的命令 | 一期 | CLI |
| 4 | 多处匹配时区分「出现几次」与「在第几行」：同一行只列一次，超过 6 行时列前 6 个并说总数 | 一期 | CLI |
| 5 | 帮助同步：Usage 增两个文件参数，Output 写明回显的顺序与三行上下文，失败说明写明三种诊断 | 一期 | 帮助 |
| 6 | `skill read --raw`：原始字节、无行号、无页脚。与 `skill cat` 的差别是它**只接一个路径**，并与 `read` 共用同一套版本解析 | 二期 | CLI |
| 7 | `skill write` 拒绝「整份像 `read` 渲染」的内容（行号连续且末行是页脚），错误指向取原文的命令 | 二期 | CLI |
| 8 | `skill write --content-file <文件>`：内容从文件读，规则与 `skill edit` 的 `--old-file` / `--new-file` 相同（原始字节、UTF-8 校验）；**空文件例外**——write 写空内容，edit 的 `--old` 为空仍是用法错误 | 二期 | CLI |
| 9 | `@new` 成功后打印下一条带草稿码的完整命令；**不移动本机钉**（[ADR 0035](../../decisions/0035-the-pin-lives-on-the-client-machine.md)） | 三期 | CLI |

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | patch 语法（`--patch`、统一 diff 输入） | 缺的是反馈，不是提交形态；aider 的数据显示格式合规**单独**就是一个失败面 | 若出现「一次要改十几个文件」的实际需求 |
| 2 | 一次调用改多个文件、或多文件原子操作 | 逐文件各有独立结果，错在哪一步一目了然；原子性需要服务端事务，代价远大于收益 | 不做 |
| 3 | undo / 编辑历史 | 客户端存第二份真相就会漂；Anthropic 在 Claude 4 的文本编辑器工具里删掉 `undo_edit` 也是这个理由 | 不做 |
| 4 | 改「只有 `invoke` 移动本机钉」这条规则（[ADR 0035](../../decisions/0035-the-pin-lives-on-the-client-machine.md)） | `@new` 只打印下一条完整命令即可；改规则要动既有 ADR，收益不抵 | 若出现**一次**因漏写 `@code` 而写到别的草稿上的实例 |
| 5 | 服务端校验「行号渲染」内容 | 这是启发式，服务端拒绝会误伤合法内容；防线放在 CLI 入口 | 不做 |
| 6 | 把本地导入下线 | 首次导入（没有草稿可改的用户）仍需要它（[ADR 0108](../../decisions/0108-importing-local-skills-is-optional.md)） | 不做 |
| 7 | 改 `skill cat` / `skill read` 的既有渲染 | 第二期只**增加** `--raw`，不改变默认输出 | 不做 |
| 8 | 本地目录的 `checkout` / `commit`（把本地目录绑到同一份草稿） | 见 [ADR 0116](../../decisions/0116-editing-happens-online.md)：草稿身份只在服务端成立，目录要回落同一份草稿就得维护第二个真相源 | 若出现「一次要改十几个文件」的实际需求 |

**为什么不做本地往返**：见 [ADR 0116](../../decisions/0116-editing-happens-online.md)。

## 控制台操作与 CLI 对应

本版没有新增控制台操作。版本编辑页已有的「改一个文件」对应 `skill edit`，本版只是把 CLI 侧的反馈补齐。

## 验收与指标

### 验收标准

| # | 验收标准 | 怎么判定 |
|---|---|---|
| A1 | `--old-file` / `--new-file` 可从文件取内容；二者与 `--old` / `--new` 按「参数是否出现」互斥（`--new ""` 也算出现）；文件读不到或非 UTF-8 时报错且不写；空 `--old`（含空文件）拒绝 | 单元用例 + 退出码：缺参数 / 同时给 / 空文本 → 2；读文件失败 / 非 UTF-8 → 1 |
| A2 | 改成功时 stderr 依次是：已修改那一行、hunk（含 `@@ -a,b +c,d @@`、`-`/`+` 行、3 行上下文）、「这一版现在是 `<地址>@<码>`」；stdout 为空；`@new` 也打这句，码是新建的 | 逐行断言输出（普通与 `@new` 各一例） |
| A3 | 0 匹配且 `--old` 是 `read` 的渲染（非空行全为 `N\t`、编号连续，且去掉后是整行或多行）时，错误点名这是行号并给出 `skill cat` 的取原文命令 | 单元用例（含「内容本身就是 `3\tfoo`」的反例） |
| A4 | 0 匹配、去掉行尾空白后**恰好一处**（多处时取唯一的整行对齐那处）时，错误给出实际行号与那一行原文；不发出写请求（PUT） | 单元用例 + PUT 计数为 0 |
| A5 | 0 匹配时拿 `--old` 的首行（跳过开头空行）逐行比较，相似度 ≥ 0.6 时给出该行与行号；低于阈值时给「没找到」+ 取原文的命令 | 单元用例（两条分支各一例） |
| A6 | 多处匹配：说明出现次数与各自行号（同一行只列一次；超过 6 行时列前 6 个并说总数） | 单元用例 |
| A7 | 帮助同步：Usage 有 `--old-file` / `--new-file`；Output 写明回显顺序；`not_found` 的下一步指向 `skill cat` | 读帮助页 + flag 归属用例 |
| A8 | 既有契约不变：精确匹配、唯一性、0 匹配拒绝、`If-Match` 409、`@new` 建草稿与「一读一写」 | 既有用例全绿 |
| A9 | `read --raw` 与 `cat` 对同一文件的 **stdout** 逐字节相同；默认 `read` 仍带行号（二期） | 单元用例 + 真二进制 `cmp` |
| A10 | `write` 拒绝行号渲染内容；同样的文本去掉行号后可以写入（二期） | 单元用例 |
| A11 | `@new` 成功后打印的下一条命令可直接执行（带草稿码），且本机钉不变（三期） | 单元用例 + 钉文件前后对比 |
| A12 | `write --content-file` 从文件取内容，空文件写入空内容、非 UTF-8 拒绝（二期） | 单元用例 |

### 指标

| 指标 | 怎么量 | 目标 |
|---|---|---|
| 一次修改的调用数 | 读原文（`cat` 或二期后的 `read --raw`）+ 一次 `edit`；改了相对引用、或移动/删除了文件时再加一次 `check` | 不带 `check` 时 2；带 `check` 时 3 |
| 行号污染 | 提交内容里出现连续 `N\t` 行 | 0 次 |
| 诊断命中 | 构造四类样本各一例（行号 / 空白 / 最接近 / 多发），每类都必须命中 | 4/4 |
