## 目标

定清 agent 的两层引导各自负责什么——系统提示词只触发与指路，CLI help 承载流程与参考——并按六个问题组（五条旅程 30 条 + 顶层导航与契约 5 条）把 **35 条问题**（12 BLOCKER / 16 HIGH / 6 MEDIUM / 1 LOW）逐条修掉（其中 D9 就是 `grep` 的范围）；另新增一条命令 `skill check`，检查一版内部的相对引用（链接 / 路径）是否都成立。细节见 [`prd.md`](prd.md)。

## 验收标准

一句话摘要：一个只读过帮助的 agent，能自己选对凭据、走完消费 / 本地创作 / 在线编辑三条主流程，能在能读到的版本里搜索、能检查一版的内部相对引用，并在 401 时按自己的凭据形态找到正确的下一步。完整验收见 [`prd.md`](prd.md) §验收与指标。

## 这一版明确不做什么

摘要四条最要紧的；**完整范围与每条的理由在 [`prd.md`](prd.md) §范围**。

- 不新增官方技能 —— 引导只有这两层，用户 2026-10-27 明确不加第三个入口
- 不把多步流程写进规则段 —— 规则段是每次会话的上下文税，且改完不会传播
- 不让 agent 上线 / 回滚 / 改可见性 —— 高风险仍在控制台（ADR 0061）
- 不做全库内容搜索 / 「谁引用了这个 skill」 —— 服务端扫全库的成本与权限要另设计，留到下一版

## 与目标态的关系

[`target/`](../../target/) 描述的是完整形态。这一版的主体是引导内容的分层方式，**另扩两处能力**：`grep` 能搜的版本放宽到「作者面能读到的」（S8，服务端），新增 `skill check` 做版本内部引用检查（S9，客户端）：

- 保留的部分：agent 不装本地副本、按需拉取。
- 已经分叉的部分：无——`target/README.md` 的差异清单不因本版而变化（这两处都不改变「谁看得见、谁能调」）。
