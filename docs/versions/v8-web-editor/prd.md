## 用户与场景

**谁在用**：已经有一个 skill、在浏览器里登录的人——作者（`write` 及以上）与维护者（`maintain` 及以上）。他们不一定装了 CLI，也不一定愿意为一个错字打包一份 zip。

**在什么场景下用**：

- 改一个错字：线上 `SKILL.md` 里有一条命令写错了，作者点「新建版本」，从线上那一版开始，改掉那一行，保存。
- 补一份参考：agent 缺一份 `references/api.md`，作者在编辑页新建文件、粘进去、保存。
- 删掉过时的内容：一份 `references/legacy.md` 已经不适用，作者删掉它。
- 重命名与整理：把 `references/split.html` 改成 `references/split.md`，或者移到另一个目录。
- 补一句说明：改完内容才发现说明还停在上一次提交的那句话，同一个人在同一个页头里改掉它，不来回跳。
- 维护者在版本列表里看到别人提交的草稿，发现它缺了一份文件，直接在那份草稿上补。

**现在的替代做法是什么**：v7 起，CLI 可以在已有的草稿上 `write` / `edit` / `rm` / `mv` / `cp`；新草稿仍要 `skill submit` 从一份打好包的 zip 产生。网页只能读：文件栏是只读的，「新建版本」是占位。对没有 CLI、或手里只有一个浏览器的人，这条路径不存在。

**这一版为什么还要做**：编辑一份 skill 的最小动作是「看到它、改一处、存下来」。要求终端 + 打包 + 重新提交，比这件事本身贵得多；而网页已经有文件树、版本页与权限面，缺的只是写入口。

## 范围

### 做

| # | 做什么 | 交付形态 |
|---|---|---|
| 1 | **新建版本**：版本列表的「新建版本」从占位变成真入口。它以**线上版本**为底稿（没有线上版本时取这一档能看到的最近一版草稿；已下架 / 已丢弃不作底稿；这一档一版草稿都看不到时从空白开始），打开编辑页。新版本在**第一次内容改动前不落库**：不占一个草稿、不出现在版本列表；第一次内容改动（保存正文，或新建 / 重命名 / 删除文件）时把「底稿 + 这次改动」一次写成一份草稿。页面标题旁写「尚未保存」，并说明第一次内容改动后才会出现在版本列表。**只新建空文件夹不算内容改动**：它不落库，也不触发建行（见做 #2、#4）。 | 网页 + 服务端「从底稿建草稿」 |
| 2 | **编辑页**：一条整页的编辑面。页头是这一版的**名称与说明**两个输入（已有草稿里就地改，失焦或回车写入；新版本随第一次内容改动一起写入）；已有草稿的页头另有「查看版本详情」，回到那一版（受离开保护）。**底稿是草稿时，页头写「基于草稿 <版本码>」并显示提交人。** 左边是**递归的文件夹树**（照 VS Code：文件夹默认收起、点开/收起、悬停整行高亮、子项按层缩进；搜索能按路径或文件夹名筛，匹配到的祖先自动展开；树顶有新建文件与新建文件夹两个图标；文件夹通常没有操作菜单，**空文件夹是例外，只有「删除文件夹」**——空文件夹只是页面内的分组，删掉不改变版本内容；有文件的文件夹里，文件自己有重命名/删除）。右边是编辑器（等宽、行号、当前文件路径、未保存标记；底栏写光标位置与文件大小/编码）。默认打开 `SKILL.md`。 | 网页 |
| 3 | **逐文件保存**：正文改动后出现「未保存的改动」；「保存」（按钮与 `⌘/Ctrl+S`）把当前文件写到服务端；保存成功后标记消失，刷新仍读到新内容。没有改动时「保存」不可用，也不发请求。 | 网页 + 服务端单文件写 |
| 4 | **文件操作**：新建、重命名、删除都是立即写入这一版的显式动作（不是本地草稿）；删除要确认；**删除一个还有未保存正文的文件时，确认框说明这些改动也会一起丢失**。`SKILL.md` 不能改名、不能删除；不能删到一个文件都不剩；重命名到已存在的文件或文件夹、或到某个文件内部被拒（编辑页的写路径保证文件与目录不重名）；重命名到原路径是空操作（页面短路，不发请求）。**新建文件夹只是页面内的分组**：不发请求、不落库、刷新即消失，不触发建行；里面放进第一个文件之后才真正存在。**新版本的第一次内容改动需要先有名称**：名称为空时，新建文件 / 重命名 / 删除先提示填写版本名称，不写服务端；新建空文件夹不受影响（它不建行）。 | 网页 + 服务端单文件写 |
| 5 | **冲突与重复内容**：草稿在编辑期间被别的会话改过，保存时给出冲突，不清空本地内容；可以「重新加载」或「覆盖」。写出来的内容若已经是同一 skill 的另一版，明确告诉作者是**哪一版（版本号 `@1.2.3`）**，不合并、不覆盖。 | 网页 + 服务端 409 |
| 6 | **权限**：`write` 及以上能新建版本；`write` 只改自己提交的草稿，`maintain` 及以上能改任何草稿；线上 / 历史版本 / 已下架 / 已丢弃的版本不能编辑。没有权限的草稿不画编辑入口；**直接访问编辑地址时，页面按档位与提交人判断，不能编辑就显示与「没有这一版」同一屏**——读接口仍返回这一版的内容（它与版本页共用），第一次写返回 403 `forbidden`。 | 网页 + 服务端 |
| 7 | **入口**：可编辑草稿的版本页有「编辑文件」；版本列表里那一行的「更多操作」有「编辑」。两者都打开编辑页并默认 `SKILL.md`。 | 网页 |
| 8 | **校验与上限**：沿用 v7 的 512 文件 / 16 MiB、路径规范、根 `SKILL.md` 的 frontmatter 校验（缺 frontmatter、`name` 仍须与地址一致）；失败不写入。二进制文件可见、可下载，但不能在编辑器里改。 | 服务端规则 + 网页提示 |
| 9 | **窄屏与键盘**：400px 宽下文件树收成可展开的一条，编辑器占满宽度，没有横向溢出；`⌘/Ctrl+S` 保存，`Esc` 关闭菜单与弹窗，焦点可见。 | 网页 |
| 10 | **离开保护**：有未保存的正文改动时，页面内的返回链接与关闭标签页都要先问一次；选择留下则原样留下。 | 网页 |
| 11 | **名称与说明**：编辑页里能改这一版的**名称与说明**。已有草稿失焦或回车即写（各走一条 `PATCH …/versions/{version}/name` 与 `…/note`），字段下面说结果；新版本的名称与说明留在页面上，随第一次内容改动写成。**底稿只提供内容，名称与说明从空开始**——它们是这一版自己的字段，不是上一版的副本。名称必填（1–40 个码点），清空后恢复原值并说明；说明可选（至多 200 个码点，空着表示没有）。**页面按码点挡在上限**（第 41 个名字字符、第 201 个说明字符进不去）；服务端对绕过页面的超长仍回 400 `draft_name_too_long` / `note_too_long`，不静默截断。两者都不进 digest、不进地址，也不改状态。**只改了名称或说明、正文没有任何改动时，新版本的「保存」仍不可用**：建行必须带着一次内容改动，否则摘要与底稿相同（§范围 #1 的那条约束）。 | 网页 + 服务端两条既有 PATCH |

**「第一次内容改动才落库」是有意的，不是实现偷懒。** 直接把线上版本复制成一份草稿会得到与线上相同的 `digest`，而 `UNIQUE (skill_id, digest)` 与 [ADR 0064](../../decisions/0064-a-draft-may-change-a-published-version-may-not.md) 明确拒绝「同一 skill 的两行拥有同一份内容」。本版不改这条规则，于是把「新版本」做成一张**还没有行 id 的底稿**：第一次内容改动把改动与建行放在同一个事务里，结果必然与底稿不同。代价写在验收 #3：它在第一次内容改动前不在版本列表里。

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | **上传 zip / 从本地目录导入** | 导入已经是 `skill submit` 与 API 的能力；本版解决的是「在网页里改已有的内容」，把两种入口塞进同一页会让「保存」有两种语义 | 不做（两条路各自有家） |
| 2 | **在编辑页上线、丢弃** | 改变版本状态的动作都在那一版自己的版本页（[ADR 0054](../../decisions/0054-lifecycle-actions-happen-on-a-version-page.md)）；编辑页只编辑这一版的内容、名称与说明（见 §做 #11），上线与丢弃仍回版本页 | 不做 |
| 3 | **语法高亮、Markdown 预览、代码折叠、多光标** | 编辑器先解决「能改、能存、冲突不丢」；高亮与预览要引入一套编辑器内核，是一次独立的设计与依赖决定 | 未定 |
| 4 | **多文件批量保存 / 本地工作区 / 离线草稿** | 服务端的写接口是单文件的，基线是整版 digest；批量保存要先有一套本地暂存与冲突合并，不是这一版的量 | 未定 |
| 5 | **从任意版本挑选底稿** | 最常见的起点是线上版本；固定规则（线上 → 最近一版草稿 → 空白）比一个每次都要选的下拉更省事。要从历史版本开始，可以回滚上线后再新建 | 下一版 |
| 6 | **编辑线上 / 历史版本 / 已下架 / 已丢弃的版本** | 内容冻结是 [ADR 0064](../../decisions/0064-a-draft-may-change-a-published-version-may-not.md) 的结论：地址与摘要必须始终指向同一份内容 | 不做（结构性） |
| 7 | **在网页里新建一个 skill** | 新 skill 仍由提交产生；这一版只给已有 skill 加版本 | 不做 |
| 8 | **编辑二进制文件（图片、PDF、脚本的二进制资源）** | 浏览器里的文本编辑器没有安全的二进制编辑面；二进制仍然只能通过 CLI / 上传进入 | 未定 |
| 9 | **多人实时协作 / 光标共享** | 冲突用「保存时发现、由人决定」处理；实时协作是另一套基础设施 | 未定 |
| 10 | **自动保存** | 用户明确选择显式保存：写什么、什么时候写由人决定。自动保存会让冲突出现在打字过程中，也会让「离开」失去意义 | 未定 |
| 11 | **版本内的编辑历史 / 撤销重做** | 本版保存的是当前这份草稿的内容；要回看一版带来了什么，用版本页的改动对照。版本内历史需要一套本地历史与撤销栈，不在这一版的量 | 未定 |

**范围里没有「后续再看」「视情况而定」。** 需要先定的技术选择都在 [`technical-design.md`](technical-design.md) §开放问题里，写成能回答的问法。

## 验收与指标

### 验收标准

| # | 验收标准 | 怎么判定 |
|---|---|---|
| 1 | **「新建版本」只在能建的人面前可点**：`write` 及以上看得到并点得动；`browse` / `invoke` 看不到；点它进入新版本的编辑页，不再是没有反应的占位 | 四个档位分别打开版本列表，看按钮；点它，地址进入编辑页 |
| 2 | **底稿正确**：新版本编辑页的文件树列出线上版本的全部文件，默认打开 `SKILL.md`；页头写明「基于线上版本 @1.2.3」。没有线上版本时取这一档能看到的最近一版草稿（页头写「基于草稿 <版本码>」并显示提交人；已下架 / 已丢弃不作底稿）；这一档一版草稿都看不到时页头写「空白底稿」，树里只有 `SKILL.md` | 有线上版、只有草稿、没有可作底稿的版本三种夹具各打开一次，核对文件数与页头 |
| 3 | **第一次内容改动才成为草稿**：第一次内容改动前，版本列表与版本页都没有这一版；保存正文、或新建 / 重命名 / 删除文件之后，列表多出一行草稿，名称是页头填的，状态「草稿」，地址是 8 位版本码；刷新编辑页仍打开这份草稿与同一个文件。**只新建空文件夹不算内容改动**，列表不变 | 保存前后各读一次版本列表；再用「先新建一个文件」走一遍；新建空文件夹看列表与地址不变 |
| 4 | **名称必填**：名称为空时「保存」不可用；绕过页面直接请求时，服务端以 400 `draft_name_required` 拒绝并说明缺少名称 | 清空名称看按钮；发一次没有名称的请求 |
| 5 | **保存能回读**：改动正文后出现「未保存的改动」；保存成功后标记消失；刷新页面、或从版本页重新进入，内容与保存时一致 | 改一行、保存、刷新、再读 |
| 6 | **没有改动就不写（已有草稿）**：正文没有变化时「保存」不可用；即使发请求，服务端也把它当作无操作，不产生新的 digest。**新版本的第一次内容改动若与底稿完全相同，返回 409 `content_already_exists`**——建行必须带来一次不同的内容 | 看按钮；发一次相同内容的写请求；在新版本上保存一段与底稿相同的正文 |
| 7 | **新建文件与文件夹**：合法路径创建成功并打开；`..`、绝对路径、反斜杠、空路径段、空名称被拒并指出路径；目标已存在被拒（新建这一路由页面判断，不发请求）；新建文件夹到某个文件内部被拒。新建文件夹只在页面上成立：不落库、刷新即消失、不触发建行 | 逐个构造路径，核对创建结果与提示；新建一个空文件夹后刷新 |
| 8 | **重命名**：文件路径改变、内容不变；目标已存在（文件或文件夹）被拒；`SKILL.md` 没有改名入口，服务端也拒绝以它为源；重命名到原路径是空操作（页面短路，不发请求）；打开中的文件跟随新路径 | 重命名一个文件、一个目录里的文件、到一个已存在的目标、到原路径 |
| 9 | **删除**：确认后文件从这一版消失；`SKILL.md` 没有删除入口；删除立即写入；删除一个还有未保存正文的文件时，确认框说明这些改动也会丢失 | 删一个文件、刷新；看 `SKILL.md` 的菜单；在一个有未保存改动的文件上删除 |
| 10 | **冲突不吞内容**：另一个会话改了这份草稿后保存，页面保留本地内容并显示冲突；「重新加载」取服务端最新内容并丢弃本地改动；「覆盖」用本地内容按最新基线再写一次，成功后服务端是本地这份内容 | 两个浏览器改同一份草稿；分别走两条路；读服务端 |
| 11 | **内容重复说清楚**：写出来的内容已经是同一 skill 的另一版时，页面写出那一版的**版本号（`@1.2.3`）**并提供入口；不静默合并、不覆盖 | 把草稿改回线上版本的原文再保存；读横幅里的版本号、链接与服务端两个版本的状态 |
| 12 | **权限按梯子**：`write` 能编辑自己提交的草稿，不能编辑别人的（没有入口；直接访问时页面显示「没有这一版」，读接口仍返回内容，第一次写 403 `forbidden`）；`maintain` 及以上能编辑任何草稿；线上 / 历史版本 / 已下架 / 已丢弃没有编辑入口；已发布/历史版本对 `write` 写接口 409 `version_is_not_draft`，已下架/已丢弃对 `write` 404、`maintain` 及以上 409 | 五个可授档位加所有者 × 自己的草稿 / 别人的草稿 / 线上 / 已下架 / 已丢弃 |
| 13 | **上限与校验沿用 v7**：超过 512 文件或 16 MiB 被拒且不写入；路径不合规被拒；根 `SKILL.md` 缺 frontmatter 或 `name` 与地址不符被拒 | 逐个构造；拒绝后重新读这一版，确认没有部分写入 |
| 14 | **二进制只读**：二进制文件出现在树里、可以选中；编辑器说不能在此编辑，并提供下载；「保存」不可用 | 打开二进制文件 |
| 15 | **离开保护**：有未保存正文改动时，点页面上的返回链接或关闭标签页会先问；选「继续编辑」后内容原样，选「放弃并离开」才走 | 改一行、点返回、两种回答各走一次 |
| 16 | **窄屏可用**：400px 宽下文件树收成一条可展开的栏，编辑器占满宽度，页面没有横向溢出 | 400px 视口打开编辑页与展开文件树 |
| 17 | **两个入口都能进**：可编辑草稿的版本页有「编辑文件」，版本列表里那一行的「更多操作」有「编辑」；两者都打开编辑页并默认 `SKILL.md`；不可编辑的草稿没有这两个入口 | 从版本页与列表各进一次；用别人的草稿再看一次 |
| 18 | **失败如实**：保存失败（网络、校验、权限、冲突）都显示原因；失败时「未保存的改动」仍在，不显示成功 | 断网、构造超限、用无权限的账号、制造冲突各一次 |
| 19 | **键盘**：`⌘/Ctrl+S` 保存当前文件；`Esc` 关闭菜单与弹窗并把焦点还给打开它的控件 | 键盘走一遍 |
| 20 | **文件搜索**：树上的搜索按路径筛选；没有匹配时是一句话加清除，不是一张空树 | 输入一个匹配词与一个不匹配的词 |
| 21 | **名称与说明在编辑页里可改**：已有草稿失焦或回车即写，字段下面分别说「版本名称已保存。」「说明已保存。」；写入失败保留输入并说明原因；名称清空后恢复原值并说明；名称 1–40、说明 0–200 个码点，页面按码点挡在上限，服务端对绕过页面的超长回 400。两者都不进 digest、不改地址、不改状态 | 改名称写成与失败、改说明写成与失败、清空名称、第 40/41 个名称字符、第 200/201 个说明字符（emoji 放在边界前）各一次；核对字段下的提示与服务端 |

**成立条件**：验收 #3、#10、#11、#12 是不满足就不算交付的四条——它们分别保证「不会凭空多出一个版本」「冲突不会吞掉人的内容」「重复内容不会被悄悄合并」「权限不会因为多了一个写入口而变宽」。

### 指标

| 指标 | 定义 | 怎么量 | 目标 |
|---|---|---|---|
| 一次保存的写请求 | 从按下「保存」到收到结果，服务端收到的写请求数 | 服务端审计 / 测试计数 | 恰好 1；无改动时 0 |
| 第一次内容改动后的可见性 | 保存成功到版本列表出现这一行的页面刷新次数 | 手工 + IT | 1 次刷新内 |
| 冲突可见 | 另一个会话改动后，保存返回的 409 是否在页面上被看见 | 两个会话的 IT | 100%，且本地内容不丢 |

本版不设性能指标：编辑的是文本，服务端上限沿用 v7；吞吐与延迟的测量（T-PERF）不在这一版。

## 依赖与前置

- **外部依赖**：无。不需要新的第三方服务，也不需要新的运行时。
- **内部前提**：
  - 版本状态机与六档权限（[ADR 0047](../../decisions/0047-permissions-are-a-ladder.md)、[ADR 0051](../../decisions/0051-the-author-plane-serves-by-tier.md)）；
  - 草稿内容可变、发布内容冻结（[ADR 0064](../../decisions/0064-a-draft-may-change-a-published-version-may-not.md)）；
  - 草稿有必填名称（[ADR 0055](../../decisions/0055-drafts-have-a-required-name.md)）、草稿由 8 位版本码寻址（[ADR 0063](../../decisions/0063-a-draft-is-addressed-by-a-short-code.md)）；
  - 生命周期动作在版本页（[ADR 0054](../../decisions/0054-lifecycle-actions-happen-on-a-version-page.md)）；
  - v7 的文件写用例、路径与 frontmatter 校验、512 / 16 MiB 上限、blob 回收（[ADR 0065](../../decisions/0065-blob-reclamation-waits-for-a-grace-period.md)）。
- **排除了什么前置**：
  - **不需要改数据模型**：本版不新增列、不改唯一约束；「第一次内容改动才落库」就是为了不碰 `UNIQUE (skill_id, digest)`。
  - **不需要新的编辑器依赖**：编辑器是一个等宽的文本域加行号，不引入 CodeMirror / Monaco。
  - **不需要新的 ADR**：没有跨版本的结构性取舍；`write` 不新增一类权限，编辑仍发生在草稿上。
