## 目标

让作者在版本列表点「新建版本」，以线上版本为底稿，在浏览器里直接新建、编辑、重命名与删除文件，并在同一个页头改这一版的名称与说明；第一次内容改动时在服务端建出草稿，之后逐文件保存，上线仍在版本页。细节见 [`prd.md`](prd.md) §用户与场景。

## 验收标准

一句话：**点「新建版本」能以线上版本为底稿打开编辑页，名称、说明与文件改动都能保存并刷新回读；新版本只在第一次内容改动时成为一个草稿；文件操作、权限、上限与冲突基本沿用 v7 的服务端规则（本版新增一条只查本次写入目标路径的树检查：新建/重命名不能与已有文件或目录同名；既有草稿里历史遗留的同名不会被追溯拒绝），不静默、不合并。**

完整清单与判定方式见 [`prd.md`](prd.md) §验收与指标（映射见 [`test-plan.md`](test-plan.md) §验收映射）。

**成立条件**：验收 #3（第一次内容改动才产生草稿）、#10–#11（冲突与内容重复不静默）与 #12（权限）——不满足就不算交付。

## 这一版明确不做什么

摘要三条最要紧的；**完整范围与每条的理由在 [`prd.md`](prd.md) §范围**。

- 不做**上传 zip / 从本地目录导入**——导入已经是 `skill submit` 与 API 的能力，网页编辑针对的是「改已有的内容」
- 不做**在编辑页上线、丢弃**——改变版本状态的动作仍在版本页（[ADR 0054](../../decisions/0054-lifecycle-actions-happen-on-a-version-page.md)）；名称与说明属于这一版本身，编辑页里可以改
- 不做**语法高亮、Markdown 预览、多文件批量保存与协作**——编辑器先解决「能改、能存、冲突不丢」，其余是另一条线

## 与目标态的关系

[`target/`](../../target/README.md) 描述的是完整形态。

- **保留的部分**：服务端权威、内容寻址、提交与上线分开、草稿可变而发布内容冻结——一个字不改。
- **走近的半步**：第一次可以完全不装 CLI、不打包 zip，在浏览器里从线上版本开始改一版。
- **仍然分叉的部分**：没有本地工作区、没有离线草稿、没有版本内编辑历史；浏览器只是一个编辑面，服务端的草稿仍是唯一事实。

## 影响最大的三个已定取舍

完整列表与理由见 [`technical-design.md`](technical-design.md) §开放问题 §已定。按重要性排前三条：

1. **第一次内容改动才建草稿**——直接复制线上版本会撞上 `UNIQUE (skill_id, digest)`（v7 明确拒绝「同内容两版」）。本版把「新版本」做成一张尚未落库的底稿，第一次内容改动（正文或文件结构）与建行在同一请求里完成，因此不改数据模型；代价是新版本在第一次内容改动前不出现在版本列表里。只建空文件夹不算内容改动，不触发建行。
2. **覆盖的语义**——冲突时「覆盖」是重新读基线后按同一路径再写一次；它不撤回别人对**其它文件**的改动，只在这一次写里让本地版本胜出。
3. **空白底稿**——没有线上版本、也没有可作底稿的草稿时，编辑页只带一个最小 `SKILL.md`；模板在 [`technical-design.md`](technical-design.md) §数据模型，设计件有 `editor-blank` 态。
