## 用例

### E1 · 新建版本的入口

**前置**：一个已上线的 skill；四个账号分别是所有者（owner）、被授为 `write`、`browse`、`invoke` 的协作者。

**步骤**：四人各自打开版本列表；点「新建版本」。

**期望**：owner / write 看得到且点得动，地址进入 `/skills/{ns}/{name}/new`；browse / invoke 看不到按钮。点击不触发服务端写，版本列表仍是原来的行数。

### E2 · 底稿的三种来源

**前置**：三个 skill——A 有线上版本 `1.2.3`；B 只有一份**由别人提交**的草稿（`write` 能读到）；C 的版本都已被丢弃（`write` 看不到任何版本，`maintain` 看得到）。

**步骤**：以 `write` 分别打开三者的新版本编辑页；再以 `maintain` 打开 C。

**期望**：A 的树列出 `1.2.3` 的全部文件，默认打开 `SKILL.md`，页头「基于线上版本 @1.2.3」；B 复制那一份别人提交的草稿（复制是读，`write` 允许），页头「基于草稿 <版本码>」并显示提交人；C 页头「空白底稿」，树里只有 `SKILL.md`，内容是 TD §数据模型「空底稿」的模板。**以 `maintain` 打开 C 时仍是「空白底稿」——已丢弃不作底稿**；模板的 `name` / `description` 取 skill 行（`?base=none` 的顶层字段），不是那一版已丢弃的副本。三者的文件数、大小与底稿一致；**名称与说明两个输入都是空的**（底稿只提供内容，名称与说明从空开始，prd #11）。

### E3 · 第一次内容改动才落库

**前置**：一个已上线的 skill，`write` 账号。

**步骤**：三条路各走一次：
1. **正文保存**：打开新版本编辑页（填名称、打开 `SKILL.md`），在改动前读一次版本列表与版本页；改一行并保存；再读版本列表；刷新编辑页。
2. **结构操作**：另开一个新版本，填名称，点击「新建文件」建出 `references/api.md`（不保存正文）；读版本列表；再建一个空文件夹 `guides`。
3. **空文件夹**：只新建一个空文件夹，不改任何文件。

**期望**：三条路在改动前都没有这一版。① 保存后多出一行草稿，名称是页头填的，状态「草稿」，地址是 8 位版本码；编辑页地址变成 `@<版本码>/edit`，状态章从「尚未保存」变成「草稿」；刷新后仍是这份草稿与同一个文件；服务端审计里有一条 `version_file_write`，`op=create`。② 新建文件后同样多出一行草稿、地址换成 `@<版本码>/edit`；再用空文件夹时列表不再增加。③ 只建空文件夹时列表与地址都不变，刷新后空文件夹消失。**名称为空时**，第一次新建文件 / 重命名 / 删除不发送请求，页面提示先填写版本名称；新建空文件夹不受影响。

### E4 · 名称必填

**步骤**：新版本编辑页清空名称；直接向 `POST /web/skills/{ns}/{name}/versions` 发一个没有 `name` 的请求。

**期望**：名称为空时「保存」不可用；请求被 400 `draft_name_required` 拒绝，消息说明缺少名称，不插入任何 `skill_version` / `version_file` 行。

### E5 · 保存能回读

**步骤**：打开一份草稿的 `SKILL.md`，改一行，保存；刷新页面，再读同一文件；从版本页重新进入编辑页再读。

**期望**：改动后出现「未保存的改动」；保存成功后标记消失；刷新与重新进入读到的都是保存后的字节；`digest` 前移一次，`file_count` / `total_bytes` 与服务端 `digest` 一致。

### E6 · 无改动不写

**步骤**：打开一份已有草稿，不输入任何字符；对同一个文件发一次内容相同的写请求。再在一个新版本上填名称，提交一段与底稿完全相同的正文。

**期望**：已有草稿的按钮不可用；相同内容的请求返回 200 且 `digest` 不变，服务端不新增审计行、不新增 blob。新版本的建行请求返回 409 `content_already_exists`（建行必须带来一次不同的内容）。

### E7 · 新建文件、文件夹与路径校验

**步骤**：依次新建 `references/api.md`、`../escape.md`、`/abs.md`、`a\b.md`、`a//b.md`、``（空）、`SKILL.md`（已存在）；新建文件夹 `guides` 与 `guides/advanced`；在 `SKILL.md` 下新建文件夹 `SKILL.md/x`；刷新页面。

**期望**：第一条成功并打开，内容为空；其余六条被拒并指出路径——`../escape.md`、`/abs.md`、`a\b.md`、`a//b.md`、空路径五条由页面与服务端回 400 `invalid_path`，已存在的 `SKILL.md` 由**页面**回「该路径已存在文件。」且**不发请求**（服务端的 `write` 是新增或替换，不会回 `file_already_exists`）；`guides` 与 `guides/advanced` 作为页面内的分组出现，但**不发送请求、不落库**；`SKILL.md/x` 被拒（文件不能同时是目录；页面拒绝，服务端由写路径的树不变量回 400 `invalid_path`）；刷新后空文件夹消失，版本的文件清单与 `digest` 没有变化；拒绝后文件清单不变。

### E8 · 重命名

**步骤**：重命名 `references/split.md` → `guides/split.md`；重命名到一个已存在的文件；重命名到一个已存在的文件夹；重命名到某个文件内部（`SKILL.md/x.md`）；重命名到原路径；打开 `SKILL.md` 的菜单；直接向写接口发一条以 `SKILL.md` 为源的重命名。

**期望**：第一条成功，内容不变，树与打开的路径跟着变；第二条 409 `file_already_exists`（目标是文件）；第三、四条被 400 `invalid_path`（目标是文件夹 / 在文件内部，树不变量：文件与目录不能同名）；第五条是空操作，缓冲区与地址不变（**页面按同一路径短路、不发请求**；绕过页面直接请求时，v7 的 `MoveDraftFileUseCase` 会把它当作目标已存在回 409 `file_already_exists`）；`SKILL.md` 没有菜单；直接请求返回 409 `skill_md_cannot_be_deleted`；打开中的文件跟随新路径，缓冲区不丢。

### E9 · 删除

**步骤**：删除 `references/legacy.md`（确认）；看 `SKILL.md` 的菜单；在一个有未保存正文的文件上点删除；删除最后一个非 `SKILL.md` 文件后刷新。

**期望**：删除成功后文件从树与服务端消失，`file_count` 减一；`SKILL.md` 没有删除项；有未保存正文时，确认框说明「该文件未保存的改动也会丢失。」；删除后刷新不再出现；删除只删 `version_file` 行，不写 blob；失去引用的旧 blob 由 sweep 按 grace 回收（ADR 0065）。

### E10 · 冲突

**前置**：同一份草稿，两个浏览器（A、B）同时打开。

**步骤**：A 改 `SKILL.md` 并保存；B 也改 `SKILL.md` 后保存；B 分别走「重新加载」与「覆盖」。

**期望**：B 的保存返回 409 `digest_mismatch`，页面显示冲突且 B 的本地内容还在；「重新加载」后 B 看到 A 的内容，本地改动被丢弃；重新来一次，B 选「覆盖」后服务端是 B 的内容，`digest` 前移；A 的其它文件改动不受影响。删除一个已被别人删掉的文件时，覆盖视为已完成并重载。

### E11 · 内容重复

**步骤**：把一份草稿的全部改动撤回，使它的内容与线上那一版 `1.2.3` 完全相同，再保存。

**期望**：409 `content_already_exists`，页面写出那一版的版本号 `@1.2.3` 并提供入口（服务端的 `error.details` 里 `state=published`、`pin` 给这一版）；本地内容仍在；不静默合并、不把草稿改成那一版。

### E12 · 权限

**前置**：`write`、`maintain`、`admin`、`browse`、`invoke` 五个可授档位与所有者；一份由 `write` 提交的草稿与一份由别人提交的草稿；线上、已下架、已丢弃各一版。

**步骤**：各档位分别尝试：新建版本；打开自己的草稿；打开别人的草稿；打开线上 / 已下架 / 已丢弃版本的编辑地址；直接向写接口发请求。

**期望**：`write` 能新建、能改自己的草稿；别人的草稿没有编辑入口，直接访问时**读接口返回 200**、页面显示与「没有这一版」同一屏，第一次写返回 403 `forbidden`；`maintain` / `admin` / 所有者能改任何草稿；`browse` / `invoke` 不能新建也不能写，带草稿 pin 的读是 404。**非草稿按状态与档位分开**：已发布 / 历史版本对 `write` 及以上 409 `version_is_not_draft`；已下架 / 已丢弃对 `write` 不可见（404），`maintain` 及以上 409。名称/说明 PATCH 对**能看见且能改**的非草稿是 400 `draft_name_is_frozen` / `note_is_frozen`；看不见的仍是 404，别人提交的在权限检查处就是 403。

### E13 · 上限与校验

**前置**：一份已有草稿。

**步骤**：通过 `POST …/versions/{version}/edits` 依次构造：513 个文件、超过 16 MiB、路径不合规（`../x.md`）、缺 frontmatter 的 `SKILL.md`、`name` 与地址不符的 `SKILL.md`；各写一次。

**期望**：五者都被拒——超过 512 / 16 MiB 回 400 `invalid_upload`（明细 `too_many_files` / `too_large`）；路径不合规回 400 `invalid_path`；缺 frontmatter 的 `SKILL.md` 回 400 `invalid_upload`（明细 `missing_frontmatter`）；`name` 与地址不符回 400 `invalid_upload`（明细 `name_mismatch`）。拒绝后重新读这一版，文件清单、`digest`、`total_bytes` 与请求前一致。

### E14 · 二进制

**前置**：底稿里有一个 `assets/manual.pdf`（`is_binary=true`）。

**步骤**：在树里选中它。

**期望**：编辑器显示「二进制文件不能在此编辑」与下载入口；「保存」不可用；下载到的字节与原文件一致。

### E15 · 离开保护

**步骤**：改一行不保存；依次点面包屑的「版本」、页头的「查看版本详情」、重复横幅里的「查看 @1.2.3」；每次选「继续编辑」；再点面包屑，选「放弃并离开」；再改一行，直接关闭标签页。

**期望**：三个页内离开链接都会弹窗，焦点放在「继续编辑」；留下后内容原样；选离开才导航；关闭标签页触发浏览器的 `beforeunload` 提示。没有未保存改动时，导航不拦。

### E16 · 窄屏

**步骤**：400px 视口打开一份已有草稿的编辑页（页头是 `查看版本详情` 与 `保存`）；看页头；展开文件树；打开一个文件。

**期望**：页头第一行折行——标题占满一行，`查看版本详情` / `保存` 落到下一行右对齐；文件树收成一条可展开的栏，编辑器占满宽度；页面没有横向溢出；输入、保存、新建/重命名/删除都还可达；展开后树与编辑器不重叠。组件测试断言行位置与可达性；400px 截图只作视觉验收，不替代断言。

### E17 · 两个入口

**步骤**：从一份可编辑草稿的版本页点「编辑文件」；从版本列表那一行的「更多操作」点「编辑」；用一份别人提交的草稿重复。

**期望**：前两者都进入 `/skills/{ns}/{name}@<pin>/edit` 并默认 `SKILL.md`；不可编辑的草稿没有这两个入口；直接访问编辑地址时读接口 200、页面显示「没有这一版」、第一次写 403。

### E18 · 失败如实

**步骤**：断网保存；保存一份超限内容；用一个已被撤权的账号保存；制造 409。

**期望**：四种情况都显示原因，`未保存的改动` 标记仍在，不出现成功提示；原因后面说明「修改后可再次保存。」；恢复后能在原地重试。

### E19 · 键盘

**步骤**：聚焦编辑器，按 `⌘/Ctrl+S`；打开文件菜单后按 `Esc`；打开删除弹窗后按 `Esc`；在新建行按 `Esc`；在重命名行按 `Esc`；在离开弹窗按 `Esc`。

**期望**：保存当前文件；菜单关闭并把焦点还给打开它的按钮；删除弹窗取消并把焦点还给删除项；新建/重命名取消后焦点回到打开它的图标 / 行菜单；离开弹窗的 Esc 等同于「继续编辑」，焦点回到打开它的链接。

### E20 · 文件搜索与文件夹树

**步骤**：默认打开编辑页，看文件夹是否收起；点 `references` 展开；在树上的搜索框输入 `split`；输入 `references`；输入 `zzz`；按 `Esc`；清除搜索。

**期望**：默认所有文件夹收起，根上只有文件夹与 `SKILL.md`；点 `references` 展开、子文件缩进一层；`split` 收窄到 `references` 展开、里面是 `split.md`；`references` 同样展开文件夹并带出里面的文件；`zzz` 显示「没有匹配的文件。」与清除；`Esc` / 清除后回到搜索前的展开状态；搜索时不画空文件夹。

### E21 · 名称与说明

**前置**：一份由 `write` 账号提交的草稿；一个新版本编辑页（尚未保存）。

**步骤**：在草稿上改名称并失焦（写成）；再改一次名称并断网（失败）；改说明并失焦（写成）；再改一次说明并断网（失败）；清空名称并失焦；输入 40 与 41 个码点的名称；输入 200 与 201 个码点的说明（emoji 放在第 199 个位置，不放在末尾）；直接向 PATCH 发一条 201 码点的说明。在新版本上只填名称与说明、不改正文，读版本列表；再改一处正文并保存。

**期望**：名称为空时「保存」不可用；名称与说明各发一条 `PATCH`，字段下面分别出现「版本名称已保存。」「说明已保存。」，`digest`、地址与状态不变；断网时输入保留、字段下面显示失败原因（危险色），恢复网络后能原地再失焦重试；清空名称后输入框恢复原名并显示「版本名称不能为空，已恢复原名称。」，不发请求；名称第 41 个码点、说明第 201 个码点**在页面里进不去**（按码点挡在上限，emoji 算一个）；绕过页面直接发 201 码点的说明，服务端回 400 `note_too_long`，不静默截断。新版本只填名称与说明、不建行时列表不变；再改一处正文后保存，建出来的一行带着这两项（prd #3、#11）。
