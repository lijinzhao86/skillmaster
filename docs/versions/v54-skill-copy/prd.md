# v54-skill-copy · 需求

## 用户与场景

**能看见一个 skill 的内容、想按自己的需要改的人。** 产品面向不熟悉技术的用户；他们能看见公开 skill 或别人共享给他们的 skill 的内容，却没有一条路径把内容变成自己可改的一份。

今天只有两条路，都不对：

- **入库**只是收一条引用：内容仍属于原作者，你改不了；`skill join` 也不复制内容。
- **导入本地**要先下载 zip、解压、改名，再上传；而公开 skill 最多给到「浏览」档，`CreateDraftFromVersionUseCase` 要求对该 skill 有「写入」档，所以连“在原作者那里起一份草稿”都走不通。

三个具体场景：

1. **业务同事**在公域看到 `skillmaster/合同审阅`，想加上公司自己的条款口径；需要一份能改的副本。
2. **同事把一个私有 skill 共享给我**（「浏览」档），我想基于它改一份自己的版本，而不是每次都在原 skill 上申请更高档位。
3. **agent 用户**在 CLI 里看到一个能浏览的 skill，想复制到自己的库，再用 `skmr skill write` 改文件。

现在替代做法是「下载 → 解压 → 改 SKILL.md 的名字 → 导入」，三步且容易丢来源；或者找运营帮忙，那不是自助。

## 范围

### 做

1. **入口与权限**：任何调用者达到**浏览**及以上档、且不是自己拥有的 skill，都能复制——入口只在**详情页页头**的「⋯」菜单里；发现页的列表行不放这个动作。库条目休眠或不可加入时也不出现「⋯」。**入库仍是页头一级的主动作，复制不在一级**（2026-11-09 用户定：入库是平台推荐用户做的动作，复制不是）。只有「调用」档、没有关系、已下线、或没有调用者读得到的已发布版本的 skill 没有入口。
2. **复制哪一版**：默认**线上版本**；也允许选调用者读得到的**已发布历史版本**。草稿、已丢弃、已下架不可选——已下架是作者主动收回的版本，复制它会绕过作者的意图。新 skill 落在调用者的**个人命名空间**，**私有**，带一条**草稿**，不自动上线。
3. **名字必填**：要给出复制后的 skill 名字。控制台在弹窗里填（预填源名字，必填）；`skillmaster` 是官方保留前缀，控制台先拒，服务端同样拒绝。CLI 用 `--name` 直接给，**不做二次确认**，没给就报错并给出用法。目标命名空间已有同名 skill 时**拒绝并让改名**，**被拒绝之后把「复制」置灰，名字一改就恢复**；不自动加后缀，不把内容追加到已存在的 skill。改了名字时，新内容的 `SKILL.md` 的 `name` 与新地址一致。
4. **出处**：新版本记录来源（源地址、源版本标识、复制时间）；信息页显示「复制自 …」；导出 zip 时 `LicenseSidecar` 的 `attribution.md` 写「复制自 `<源地址>` @`<版本>`」——源未声明许可时也写。
5. **许可随行，不作为条件**：新版本沿用源版本的许可（SPDX、全文、状态）；源未声明时照常记录「未声明」。复制不因许可缺失而拒绝。
6. **不携带**：分类、公开标签、我的标签、收藏与调用量、协作者、服务凭据、可见性（新 skill 固定私有）。
7. **不回流**：v1 不建立与源 skill 的持续关联，不自动合并上游，不通知原作者；公域仍只由运营按白名单同步。
8. **失败原子性**：任一步失败（源读取失败、名字冲突、超限、存储失败）不留下没有草稿的 skill，也不留下半个 skill。
9. **成功后停在弹窗里**：请求成功先显示「复制成功」，给两个去向——主按钮「查看新 skill」进新 skill 的信息页（推荐），次按钮「留在当前页」关闭弹窗。**不自动跳转**。CLI 成功直接输出新地址与草稿，没有这一步。
10. **审计**：每次复制写一条审计事件：谁、源地址、源版本、新 skill、新草稿。
11. **限制**：复制受普通新建 skill 的上限（文件数、单文件、总量）；超限拒绝并说清撞了哪一条。
12. **文案定义**：「复制」从此固定指**从一个库复制到另一个库**；页面上剪贴板动作必须写明对象（如复制地址 / 复制版本码 / 复制指令 / 复制名称 / 复制内容摘要），不再单用「复制」指剪贴板。

### 不做

| 不做 | 理由 | 什么时候可能做 |
|---|---|---|
| 从自己拥有的 skill 复制 | 目的地是自己的命名空间；要改自己的 skill 直接新建版本，复制只会多一个改名的副本 | 有明确需求时 |
| 复制草稿、已丢弃、已下架的版本 | 草稿是作者未定稿的内容；已丢弃与已下架是作者已经收回的版本。已发布的历史版本可以复制（见「做」#2） | 版本页出现明确需求时 |
| 把内容复制到本机 | 「复制」定义为库到库；取到本地仍走已有的「下载」 | 不改定义 |
| 跨命名空间或复制到官方命名空间 | 目的地固定为调用者的个人命名空间；官方命名空间只由运营同步 | 命名空间成员可写落地后 |
| 自动加后缀 / 自动改名 | 会造出用户没起的地址；重名让用户当场改 | 不改 |
| 与上游关联、自动合并、回流 | 第一版不做回流，公域只由运营白名单同步 | 另开版本 |
| 复制标签、分类、统计、协作者、服务凭据 | 这些是源 skill 的私有事实，跟着内容走会制造错误归属 | 用户反馈需要时逐项评估 |
| 批量复制 / 整个库复制 | 一次一个；批量要先定目的地的命名与冲突规则 | 有批量需求时 |
| 原作者通知与署名界面（除来源行与 `attribution.md`） | v1 只保证可追溯；来源卡第二期再做 | 与来源卡一起 |
| 移动端入口 | 没有移动端 | 不计划 |

## 控制台操作与 CLI 对应

| 操作 | 界面 | CLI / API / 其他面 |
|---|---|---|
| 复制一个 skill | 详情页页头「⋯」› 复制 → 弹窗（选版本，默认线上；填名字，必填、预填源名字） | `skmr skill copy <命名空间>/<名字>[@版本] --name <新名字>`；`--name` 必填、不二次确认。网页 `POST /web/skills/{ns}/{name}/copy`，CLI/API `POST /api/v1/author/skills/{ns}/{name}/copy`（路径形状以技术设计为准） |
| 看到来源 | 信息页「复制自 <地址> · @<版本>」 | 副本上线后 `skmr skill show` 打印「复制自」；信息接口同一字段（草稿阶段的副本只在控制台可读——消费面只服务已发布版本） |
| 复制后去改 | 成功后停在弹窗；主按钮进新 skill 的信息页，次按钮留在当前页 | CLI 输出新地址与草稿 pin，`skmr skill write` 接上 |

## 验收与指标

| # | 验收标准 | 怎么判定 |
|---|---|---|
| A1 | 达到浏览及以上、不是所有者、且有读得到的已发布版本时，详情页页头「⋯」里有「复制」——公开 skill 与共享给我的私有 skill 都算；发现页列表行没有这个入口；入库仍是页头唯一的主色实心按钮；只有调用档、没有关系、自己拥有、已下线、没有已发布版本、库条目休眠都没有入口 | 七种身份各打开一次详情页，再看发现页行与休眠条目 |
| A2 | 默认复制线上版本；可以改选调用者读得到的已发布历史版本，复制内容与所选版本逐项一致；草稿、已丢弃、已下架的版本不出现在选择里 | 复制线上一次、历史版本一次；再试三个不可选版本 |
| A3 | 名字必填：控制台不填不能提交；CLI 缺 `--name` 报错并给出用法，不进交互；控制台预填源名字；改名后新地址是 `<你>/<新名字>`，`SKILL.md` 的 `name` 与新地址一致；源的 `SKILL.md` 无法安全改名时拒绝并提示用原名复制 | 控制台提交空名、CLI 不带 `--name`、各复制一次改名/不改名；用不可改名的源试一次 |
| A4 | 目标命名空间已有同名 skill：拒绝并提示改名，**被拒绝之后「复制」置灰，名字一改就恢复**；源 skill 不产生新版本 | 先造同名 skill，再复制；看按钮置灰与改名后恢复 |
| A5 | 新版本记录源地址、所选版本标识、复制时间（`skill_copy` 与审计）；信息页显示地址与版本；副本上线后 `skmr skill show` 打印同一行（草稿阶段的副本没有消费面读路径） | 读响应、信息页与 `skmr skill show` |
| A6 | 新版本带源许可与状态；源未声明时照常记为未声明；复制不因许可缺失被拒绝；导出 zip 的 `attribution.md` 写「复制自 地址 @版本」，无许可的副本也写 | 复制有许可、无许可两种源各一次，再导出 |
| A7 | 不携带分类、公开标签、我的标签、统计、协作者、服务凭据；新 skill 为私有 | 复制前后逐项对比 |
| A8 | 只有调用档、没有浏览档的账号直接调接口复制被拒绝；不能绕过内容读取限制 | 用只有调用档的账号调接口 |
| A9 | CLI 与网页是同一件事：CLI 输出新地址与草稿；网页成功后**停在弹窗里显示「复制成功」**，主按钮「查看新 skill」进入新 skill 的**信息页**（来源展开里能看到「复制自」），次按钮「留在当前页」关闭弹窗；不自动跳转。两边选同一版本复制，结果内容一致 | 两边各做一次，比对结果；两个按钮各点一次 |
| A10 | 名字冲突或提交失败时不产生新 skill 或半成品；超限在任何行写入之前被拒；源读取失败发生在写任何行之前 | 名字冲突（S18）、提交失败（S19）、超限（S17 的判定顺序） |
| A11 | 超过普通新建 skill 的文件数 / 单文件 / 总量上限时拒绝，并指到 [`limits.md`](../../current/limits.md) | 跑 `requireWithinLimits` 的「上限 +1」边界样本（数值以 [`limits.md`](../../current/limits.md) 为准）；源版本本身受同一条上限约束 |
| A12 | 每次复制写一条审计，含源地址、源版本、目标名字与草稿 | 查审计表 |
| A13 | 按钮叫「复制」；剪贴板动作写清对象——今天的结果行是「复制地址」、版本事实是「复制版本码」，今后新增的按「复制名称 / 复制内容摘要」这一档命名；没有单用「复制」指剪贴板 | 走查页面文案 |
| A14 | `check_docs.py`、`impact.py --check`、`generate.py` 后工作区干净；服务端 / 控制台 / CLI 测试与设计检查**无新增失败**（本机既有 3 条更新器夹具失败，干净 HEAD 同样失败） | 跑命令，并对照干净 HEAD |

**成立条件**：A2（内容一致）、A5（出处）、A7（不携带私有事实）不满足就不算交付——它们分别是这个动作的内容、可追溯性与边界。

**指标**：本版不新增采集。复制写一条审计（沿用现有出口）；上线后可从审计量出复制次数，以及复制后是否继续提交新版本。

- [ADR 0081](../../decisions/0081-every-console-operation-has-a-cli-command.md)：网页每一处操作都要有 CLI 命令；本版的「复制」「看来源」都有对应命令。
- [ADR 0146](../../decisions/0146-public-is-platform-endorsement.md)：只有官方命名空间能设公开；复制出来的新 skill 是私有，所以不受这条限制。
- 需要一条新 ADR（0173）：复制的取值、名字冲突、出处与许可携带、不回流。
- 出处用新表 `skill_copy`（迁移 `V43`）；`skill_source` 继续只表示外部来源（[ADR 0173](../../decisions/0173-a-copy-is-a-snapshot-in-your-own-namespace.md) 决定 4）。
- 复制后是草稿，`CreateDraftFromVersionUseCase` 要求「写入」档的现状不适用于本路径——本版新增的是“从公开快照建新 skill”，不是“在源 skill 上建草稿”。
