## 目标

让一个能浏览 skill 的人（公开的，或别人共享给他的），用一次「复制」得到一份落在自己个人命名空间、可以改的私有 skill；默认复制线上那一版，也可以选历史已发布版本，带来源与许可。细节见 [`prd.md`](prd.md)。

## 验收标准

摘要：浏览及以上且有一版可读的已发布版本才出现「复制」；名字必填、重名拒绝；复制后是自己的私有 skill + 一条草稿，内容与所选版本一致，带来源与许可，不携带标签/统计/协作者/凭据。完整验收与成立条件见 [`prd.md`](prd.md) §验收与指标。

## 这一版明确不做什么

摘要三条最要紧的；**完整范围与每条的理由在 [`prd.md`](prd.md) §范围**。

- 不从自己拥有的 skill 复制 —— 要改自己的 skill 直接新建版本，复制只会多一个改名的副本
- 不把内容复制到本机 —— 「复制」定义为库到库；下载仍是「下载」
- 不做与上游的关联、自动合并与回流 —— 复制是一份快照，不是分支

## 与目标态的关系

[`target/`](../../target/) 描述的是完整形态：skill 是内容，身份与寻址不随复制改变。这一版是它的子集，**不分叉**目标态：

- 保留的部分：内容寻址（[ADR 0005](../../decisions/0005-content-addressing.md)）、版本不可变（[ADR 0064](../../decisions/0064-a-draft-may-change-a-published-version-may-not.md)）、个人命名空间与档位梯子。
- 已经分叉的部分：无。这是既有模型上新增的一个动作，不改身份、寻址或权限语义。

## 影响最大的未决问题

完整列表见 [`technical-design.md`](technical-design.md) §开放问题（共三条），按重要性排：

1. **已删除的同名 skill**：本版只给一句冲突提示并让换名字，弹窗里没有「去恢复」链接（设计只有一个冲突态）。
2. **`attribution.md` 是否上溯到源的 GitHub 来源**：本版只写源 skill 地址与版本，源页自己显示 GitHub。
3. **源被软删除后复制记录是否保留**：倾向保留，读取只按新 skill 的身份。
