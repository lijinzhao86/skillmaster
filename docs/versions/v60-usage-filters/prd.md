# v60-usage-filters · 产品需求

> **最后更新**：2026-11-11
> **所属版本**：[`README.md`](README.md)
> **状态**：需求已锁定（所有者确认 2026-11-11）

## 用户与场景

**谁在用**：

1. **使用 skill 的人**。过几天想找回一条具体的记录，记得大概哪几天、记得是哪条 skill，不记得当时搜了什么词。使用记录页是他唯一的「我做过什么」入口；90 天一条长表，翻到具体那一段只能一页页点。
2. **skill 的所有者与协作者**。在 skill 详情的「使用」页签看这条 skill 的使用情况；现在所有数都是固定的近 90 天，回答不了「这个月比上个月多还是少」「这周有没有人用」。

**在什么场景下用**：

- 「上周三我调的那条 PDF 工具，到底调了几次？」——时间清楚、skill 清楚，只有搜索词不清楚。
- 「这个月 `demo/pdf-tools` 被调用了几次？搜到它但没调的有几次？」——按 skill 名看一条链路的真实采用。
- 「这条共享 skill 这周还有没有人在用？」——所有者在 skill「使用」页签按时间段看聚合与使用者表。
- 以上场景在 CLI 同样成立：agent 或脚本要拿同一份结果，不打开网页。

**现在的替代做法是什么**：

| 替代做法 | 代价 |
|---|---|
| 在使用记录里一页页翻，按时间列肉眼找 | 90 天、每页 10 条，最坏要翻九页；找一条七周前的记录不可行 |
| 去浏览器历史 / 终端 scrollback 里找 | 两处都不按账号、不按 skill 归集，找到也不知道当时搜了什么 |
| 把 `skmr usage --json` 导出来自己 grep | 要求用户会写过滤；网页侧仍然做不到 |

## 范围

### 做

| # | 做什么 | 交付形态 |
|---|---|---|
| 1 | **使用记录页：时间筛选**。预设 `今天` / `近 7 天` / `近 30 天` / `近 90 天`，加「自定义」起止日期；**默认 `近 30 天`**——与账单 / 报表 / 采用看板的主流一致，7 天会把「上周三」藏起来，90 天首屏偏满、筛选感弱。**整页生效**：明细与统计同一区间，统计的调用、搜索、使用过的 skill、最近使用、按调用次数全部按所选区间重算。 | 控制台 |
| 2 | **使用记录页：按 skill 名称过滤**。页面上方一个搜索框，按 skill 地址做大小写不敏感的包含匹配；**命中这条 skill 参与过的交互**——搜索结果里出现过它（只按记录的前 50 条判定），或调用了它。搜索返回了它、最后没调用的行**也算命中**，行上照旧写「未调用」；统计按同一批行重算（见下面的统计口径）。筛选对明细与统计同时生效。 | 控制台 |
| 3 | **skill 详情「使用」页签：时间筛选**。同一组预设与自定义起止；所有者「全部使用」的数卡、使用者表与「我的使用」的数卡、按版本表都按所选区间重算（使用者表的调用次数、提交版本、最近活跃同样按区间；档位仍是当前值）。**「入库人数」保留累计，标签改为「累计入库」**。公开 skill 的「全部使用」同样是区间视图，调用与账号仍分桶，**没有使用者表**。结果行与 skill 页头上的平台信号（累计调用）不动；近 30 天账号分桶只在 `skmr skill show`，同样不动。默认 `近 30 天`。**非所有者看到的「我的使用」同样有时间筛选**。 | 控制台 |
| 4 | **筛选状态写进地址**。`?days=7` 或 `?from=…&to=…`、`?skill=…`、页签与页码与既有参数并存；刷新、转发、从 skill 页回到使用记录都还原同一屏。清除筛选回到默认 30 天。 | 控制台 |
| 5 | **CLI 同步**。`skmr usage` 明细接受 `--days <N>` 或 `--since <日期> --until <日期>`，以及 `--skill <关键词或地址>`；`skmr usage --stats`、`skmr usage <地址>`、`--users`、`--mine` 接受同一组时间参数。`--json` 带相同的过滤字段。CLI 与网页同一口径、同一结果。 | CLI |
| 6 | **服务端两个平面接受同一组过滤参数**：`/api/v1/usage/*` 与 `/web/usage/*`。时间范围按用户本地日期换算后的时刻传入；超过 90 个自然日 + 时区余量（2 小时）、结束早于开始、日期在未来一律拒绝，并在响应里说明是哪一条。 | API |
| 7 | **先改设计稿**：使用记录页与 skill「使用」页签的筛选控件、状态、地址参数、空态与错误态写进 `design/`，重出演示件；控制台照设计稿实现。 | 设计件 + 控制台 |
| 8 | **顺手修掉线上使用记录页的两处 v58 偏差**（2026-11-11 所有者定，随本版交付）：统计页数卡与页签分隔线之间补 20px；明细折角按钮 `padding:0` + `box-sizing:border-box`，悬停改用 `:not(:disabled)` 的底色——线上深色模式下它被全局 `button` 的 padding 撑大、悬停变主按钮蓝底，箭头几乎看不见。 | 控制台 |

**时间口径**（预设与自定义共用）：按**用户本地自然日**，含首尾两天。`今天` 从本地 00:00 到现在；`近 7 天` 是今天与前 6 个自然日（共 7 天）；`近 30 天` / `近 90 天` 同理。**默认近 30 天**。自定义的起止日期不能早于今天与前 89 天中的第一天，结束不能晚于今天。

**按 skill 过滤后的统计口径**（明细与统计读同一批行，不另算一份；与 [Algolia 每条结果的 count / clickCount / conversionRate](https://www.algolia.com/doc/guides/search-analytics/concepts/metrics)、[Datadog 一份过滤驱动全部聚合](https://docs.datadoghq.com/logs/explorer/)同一形状）：

| 统计项 | 按 skill 关键词过滤后是什么 |
|---|---|
| 调用次数 | 命中集合被调用的次数 |
| 搜索次数 | 搜索结果里出现过命中集合中任意一条的搜索次数（只按记录的前 50 条判定） |
| 转化 | 其中最终调用了命中集合中任意一条的搜索次数 |
| 未调用 | 上面两者之差：出现过、但没调用命中集合中任何一条的搜索次数 |
| 使用过的 skill | 区间内调用过的命中 skill 数；只出现过没调用、或完全没出现时为 0 |
| 最近使用 | 命中集合最近一次被调用的时间；一次都没调用时为「—」 |
| 按调用次数 | 有调用时逐行列命中集合里的 skill；只出现过、没调用时没有这一行（表只统计调用） |

**关键词命中多条地址时，统计按命中集合算**：调用数是这些 skill 被调用的次数，搜索数是结果里出现过其中任意一条的搜索数，转化是其中调用了任意一条的搜索数，「使用过的 skill」是被调用过的命中 skill 数，「最近使用」是命中集合里最近一次调用，「按调用次数」逐行列命中集合里的 skill。

**不按 skill 过滤时**，统计仍是 v58 的口径：全部搜索与调用参与计算。两种情况下统计都从同一批明细行现算，数字对得上。

**明细行与统计的单位不同**：一条搜索可能同时调用了别的 skill；明细行保留整次交互（调用列照常列出全部），统计只数被筛选的这条 skill 自己的次数。两者读的是同一批行，数的是不同单位——这是「一条搜索可以有多次调用」的直接结果，不是两套口径。

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | 不做 90 天以前的时间范围 | 明细在线只保留 90 天，更早的分区在 OSS 归档里，不在本版查询路径上；放开等于让一个筛选去读归档，成本和口径都不是这一版的事 | 需要查归档时另开版本，先定归档查询的接口与延迟目标 |
| 2 | 不把「出现」追溯到未记录的搜索结果（第 51 名以后） | 一次搜索只记录前 50 条结果；第 51 名以后当时返回了什么，库里没有，按它筛选与统计就是编的 | 搜索结果的记录上限提高时，这条跟着改 |
| 3 | 不把平台信号（结果行与 skill 页头的累计调用、`skmr skill show` 的近 30 天账号）改成区间口径 | 累计调用由 [ADR 0152](../../decisions/0152-cumulative-calls-are-their-own-signal.md) 定义、近 30 天账号由 [ADR 0149](../../decisions/0149-use-is-counted-per-account-per-day.md) 定义，回答「这条 skill 被用得多不多」；使用页签的区间视图回答「这段时间用得多不多」。两者各有名字，混成一套会丢掉累计与 30 天的分桶口径 | 平台确实需要按区间展示公开信号时，另开 ADR 重定义 |
| 4 | skill 过滤不做多选 | 一次看一条 skill 的使用链路；多选只是把不同 skill 混进一张表，回答不了「这条 skill 怎么用的」 | 需要横向比较多条 skill 时，另做统计视图，不做在明细表里 |
| 5 | 不做按事件类型 / 版本 / 结果状态的其它筛选 | 这一版只补用户提出的两项；每多一个筛选都要有 CLI 对应与设计稿，先收口 | 用户提出且能说清场景时 |
| 6 | 不做保存的筛选视图 / 收藏条件 | 单账号、90 天窗口，地址已经能转发；保存视图的收益要等条件组合变多 | 同一组条件被反复使用时 |
| 7 | 不做「今天 / 近 7 天」之外的更细预设（本周、本月、上个月） | 自然周 / 自然月的边界与本地日历绑定更紧，规则也多一档；自定义起止已经覆盖 | 用户明确要按自然周 / 自然月看时 |
| 8 | 不把默认值改成 7 天或 90 天 | 7 天会把「上周三」这类记录藏起来；90 天首屏偏满、筛选感弱。30 天与账单 / 报表 / 采用看板的主流一致 | 使用场景变化时再评估，不随「老用户习惯」自动回到 90 天 |

## 控制台操作与 CLI 对应

**每一处新增的控制台操作都有 CLI 命令，没有例外**（[ADR 0081](../../decisions/0081-every-console-operation-has-a-cli-command.md)）。本版没有高风险操作，也没有产品负责人逐条确认的豁免项。

| # | 控制台操作 | CLI 命令 | 备注 |
|---|---|---|---|
| 1 | 使用记录 → 明细 → 选时间预设 | `skmr usage --days <1–90>`；`--days 1` 即今天 | 默认不带参数就是近 30 天 |
| 2 | 使用记录 → 明细 → 自定义起止 | `skmr usage --since <YYYY-MM-DD> --until <YYYY-MM-DD>` | 含首尾两天；本地日期 |
| 3 | 使用记录 → 明细与统计 → 按 skill 名过滤 | `skmr usage --skill <关键词或地址>`；统计加 `--stats` | 与服务端同一口径：出现或调用都算 |
| 4 | 使用记录 → 统计 → 选时间范围 | `skmr usage --stats` 加 `--days` 或 `--since/--until` | |
| 5 | skill 详情 → 使用 → 全部使用 → 选时间范围 | `skmr usage <地址>` 加 `--days` 或 `--since/--until` | |
| 6 | skill 详情 → 使用 → 使用者表 → 选时间范围 | `skmr usage <地址> --users` 加时间参数 | |
| 7 | skill 详情 → 使用 → 我的使用 → 选时间范围 | `skmr usage <地址> --mine` 加时间参数 | |
| 8 | 清除筛选 | 去掉对应的 `--days` / `--since` / `--until` / `--skill` |

### CLI 的格式（2026-11-11 定）

```text
skmr usage [<地址>] [--stats] [--expand] [--users] [--mine]
           [--days <1–90> | --since <YYYY-MM-DD> --until <YYYY-MM-DD>]
           [--skill <关键词或地址>]
           [--page <页码>] [--limit <条数>] [--json]
```

- **时间**：`--days N` 取 1–90（`1` 是今天），与 `--since/--until` 互斥；自定义必须成对、本地自然日、含首尾，可选范围是今天与前 89 天（共 90 个自然日），止不晚于今天。**不带任何时间参数 = 近 30 天**，与网页默认相同。底层换算成两个时刻（开始日本地 00:00、结束日次日本地 00:00，不含），请求只发 `since` / `until`。
- **skill**：`--skill` 接受一段地址关键词，大小写不敏感的包含匹配，语义与网页一致（结果里出现过或调用了）；只用于我的明细与 `--stats`，与 `<地址>` 互斥——地址已经指定了一条 skill。
- **报错**（都退出 2，指出是哪一条）：天数越界、两种时间写法同时给、`--since/--until` 缺一个、日期格式不对、起晚于止、早于可选的 90 个自然日、晚于今天、地址与 `--skill` 同时给、`--skill` 超过 100 个字符。
- **组合**：`--users` / `--mine` 必须带 `<地址>`；`--stats` 不接地址；`--expand` 只用于我的明细。
- **文本输出**：明细尾行、`--stats` 首行、地址视角（含 `--users` / `--mine`）首行都写区间——预设是「近 7 天（2026-11-05 至 2026-11-11）」，自定义是「2026-11-01 至 2026-11-10」；带 skill 过滤时再挂一句「· skill 地址含 “…”」。`--stats` 按 skill 过滤后，搜索效果那句换成「N 次搜索结果里出现了这条 skill，M 次最终调用了它，K 次未调用。」。筛掉时为空态「没有匹配的使用记录。去掉 `--skill` 或换个时间再看。」，没记录时仍是原句。「入库人数」改叫「累计入库」。公开 skill 的地址视角在首行下写「公开 skill 仅提供聚合，不按协作者统计。」，并接一句说明区间数不是平台信号：累计调用与近 30 天账号分桶看 `skmr skill show`。
- **`--json`**：仍原样透传服务端字节；五个响应都带 `window_days`（本次实际覆盖的自然日数）与 `since` / `until`（服务端实际用的两个时刻，RFC3339 UTC）。过滤词 `skill` 只在 `interactions` / `stats` 上（没过滤时为 `null`）；`skills/{ns}/{name}` 与 `/mine` 的 `skill` 是 skill 地址，不是过滤词。

## 验收与指标

### 验收标准

| # | 验收标准 | 怎么判定 |
|---|---|---|
| A1 | 使用记录页选「近 7 天」：明细只剩本地今天与前 6 天的行，统计的调用、搜索、使用过的 skill、最近使用、按调用次数都按同一区间重算；页头同时写明当前区间与「数据只保留近 90 天」 | 控制台断言 + 集成测试（固定时钟） |
| A2 | 自定义起止 `2026-11-01` 至 `2026-11-10`：包含 11-01 00:00 与 11-10 整天；结束早于开始、或开始早于今天与前 89 天中的第一天、或结束晚于今天时被拒绝，页面字段下方与 CLI 都说明是哪一条不合法 | 集成测试 + 控制台断言 + CLI 测试 |
| A3 | 明细输入 skill 关键词：留下搜索结果里出现过它、或调用了它的行；搜索返回了它但没调用的行也出现并标「未调用」；与它无关的行不出现；匹配大小写不敏感；清空后回到全部 | 集成测试（造三类行）+ 控制台断言 |
| A4 | skill 详情「使用」页签选「近 30 天」：私有 / 共享 skill 的所有者数卡与使用者表、「我的使用」的数卡与按版本表都按 30 天算（使用者表的调用次数、提交版本、最近活跃按区间；档位是当前值）；「入库人数」不变且标签写「累计入库」；公开 skill 的「全部使用」同样是 30 天区间视图、调用与账号仍分桶、**没有使用者表**；协作者与库内用户也看到时间按钮，按区间重算「我的使用」，但没有视图开关 | 集成测试 + 控制台断言 |
| A5 | 同一组条件与控制台同一页大小（`skmr usage --days 7 --skill <关键词> --limit 10`）时，CLI 与页面明细的 `total` 相等、首页 `items` 相同；`--json` 的 `total` / `items` / `window_days` / `since` / `until` / `skill` 与同一契约 | 集成测试（同一账号、同一时钟；CLI 显式 `--limit 10`） |
| A6 | 非法参数：`--days 0` / `--days 91`、`--since` 晚于 `--until`、日期早于今天与前 89 天中的第一天、日期在未来 → CLI 退出 2 并指出是哪一条；接口返回 400 `invalid_request`（含 `since` 在未来）；页面在字段下方说明原因、「应用」不可点并保留已有结果；手工写坏的地址静默落回默认 30 天（另一条规则） | CLI 测试 + 集成测试 + 控制台断言 |
| A7 | 90 天边界不变：91 天前的记录在默认视图与任何筛选下都不出现；**页面与 CLI 不带时间参数是近 30 天**，接口不带 `since`/`until` 仍是 v58 的 90 天（旧客户端兼容）；30 天以前的记录要主动选 90 天或自定义才会出现 | 集成测试（造 >90 天与 30–90 天的旧数据） |
| A8 | 地址可分享：带 `?days=7`、`?from=…&to=…`、`?skill=…` 的链接打开后，控件、页头、结果都还原；页签与页码不丢失 | 控制台断言 + `console-states` |
| A9 | 筛选后没有记录：显示空态并给「清除筛选」；不是错误态，不清空页头。账号在保留窗口内本来就没有搜索或调用时，无论是否带筛选都写「暂无使用记录」——两句空态按「有没有记录」而不是按「筛没筛」区分 | 控制台断言 |
| A10 | 明细与统计共用同一组筛选：时间与 skill 过滤在两个页签都生效，切页签不丢条件；统计的各张卡按同一批行重算 | 控制台断言 |
| A11 | CLI 是第一前端：网页上能做的每一处筛选都能在 CLI 完成；`skmr usage --help` 列出 `--days` / `--since` / `--until` / `--skill`；**不带时间参数时按近 30 天（与网页默认相同）**；明细尾行、`--stats` 首行、地址聚合与 `--mine` / `--users` 首行都写「预设名 + 具体日期」（自定义只写两个日期），带 `--skill` 时再挂「skill 地址含 “…”」 | CLI 测试 + help 快照 |
| A12 | 查询性能：单账号 90 天、一页 50 条，加时间与 skill 过滤后 p95 < 300 ms；走既有索引，不因新增条件退化为全表扫 | 集成测试（`EXPLAIN` + 计时） |
| A13 | 按 skill 过滤后的统计口径：搜索次数等于「结果里出现过命中集合中任意一条的搜索数」，转化等于「其中调用了任意一条的搜索数」，未调用等于两者之差；调用次数等于命中集合被调用的次数；「使用过的 skill」等于被调用过的命中 skill 数；「最近使用」等于命中集合最近一次调用，没调用过为「—」；这些数与明细同一批行现算，能对上 | 集成测试（造出现未调用 / 出现并调用 / 直接调用三类行，以及关键词命中两条）+ 控制台断言 |
| A14 | 平台信号不变：结果行与 skill 页头的累计调用、`skmr skill show` 的近 30 天账号不随使用页签的时间筛选变化；使用页签的区间数按所选区间算且仍分桶；两处各有名字，不互相冒充 | 集成测试 + 控制台断言 + CLI 测试 |
| A15 | 线上两处偏差修掉：统计页数卡距页签分隔线 20px（不再顶着线）；明细折角按钮 28×28、`padding:0`，深色模式下悬停是灰底上的浅色箭头，不是主按钮蓝底 | 控制台断言 + 深色模式肉眼对照 |

**成立条件**：A1、A4、A5、A13、A14 是「不满足就不算交付」——整页同一区间、skill 页同样生效、两端结果一致、明细与统计同源、平台信号不被区间视图冒充，正是这一版要立住的五条。

### 指标

| 指标 | 定义 | 怎么量 | 目标 |
|---|---|---|---|
| 找回一条记录所需动作 | 从「知道大概哪几天、哪条 skill」到看见目标行 | 按 §用户与场景 计一遍 | 默认 30 天视图下不超过 2 次操作（选时间 + 输入 skill） |
| 两端一致 | 同一账号、同一时钟、同一条件下控制台与 CLI 的 `total` 是否相等 | 集成测试逐条对照 | 100% 相等 |
| 本人明细查询延迟 | 单账号、任意合法区间、一页 50 条 | 集成测试计时 | p95 < 300 ms |
| 所有者聚合延迟 | 单 skill、任意合法区间、按协作者分组 | 集成测试计时 | p95 < 300 ms |

## 依赖与前置

- **决策**：沿用 [ADR 0179](../../decisions/0179-personal-usage-is-visible-only-to-its-owner.md) 的可见性四层与 90 天窗口；新增 [ADR 0182](../../decisions/0182-owner-usage-is-a-period-view.md)——所有者「使用」页签是**区间视图**，平台信号（结果行 / 页头的累计调用、`skmr skill show` 的近 30 天账号）是另一份独立口径，两者不互相替代。筛选只改变「看哪一段」，不改变「谁能看」。
- **内部前提**：v58 的明细、统计、所有者聚合、使用者表与我的使用五条查询已经存在；本版只给它们加参数，不新建数据表、不改采集点。
- **数据前提**：在线明细只保留 90 天；筛选请求一律落在保留窗口内，不触达 OSS 归档。
- **设计前提**：`design/` 是界面权威；筛选控件、地址参数与所有状态先写进设计稿，控制台照抄。设计稿没有覆盖的状态先问所有者，不自行发明。
- **外部依赖**：无。
