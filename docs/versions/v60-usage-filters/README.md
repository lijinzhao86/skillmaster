# v60-usage-filters · 使用记录与 skill 使用的时间、skill 筛选

> **最后更新**：2026-11-11
> **状态**：进行中（已实现，循环审计收口；测试见 [`test-plan.md`](test-plan.md) §结果；待合并）
> **含收费**：否

## 目标

给「使用记录」页加按时间与 skill 名称筛选，给 skill 详情的「使用」页签加时间筛选；控制台与 CLI 同一口径，默认近 30 天，数据边界不变。skill「使用」页签成为**区间视图**，与结果行 / 页头的累计调用、`skmr skill show` 的近 30 天账号分开。细节见 [`prd.md`](prd.md)。

## 验收标准

时间预设与自定义起止、按 skill 名过滤「出现或调用都算」、整页同一区间、明细与统计同源、平台信号不被区间视图冒充、两端结果一致、非法参数可判定。完整验收见 [`prd.md`](prd.md) §验收与指标。

**成立条件**：整页同一区间（A1）、skill 页同样生效（A4）、控制台与 CLI 结果一致（A5）、明细与统计同源（A13）、平台信号不变（A14）不达标，就不算交付。

## 这一版明确不做什么

- 不做 90 天以前的时间范围——更早的分区在 OSS 归档里，不在本版查询路径上。
- 不把平台信号改成区间口径——累计调用与近 30 天账号各有自己的 ADR，与所有者区间视图各有名字。
- 不做 skill 多选、保存的筛选视图、更细的自然周 / 自然月预设——先收口用户提出的两项。

完整的八条见 [`prd.md`](prd.md) §不做。

## 关键决定

- [ADR 0182](../../decisions/0182-owner-usage-is-a-period-view.md)：所有者「使用」页签是区间视图，平台信号（结果行 / 页头的累计调用、`skmr skill show` 的近 30 天账号）保持独立口径。

## 与目标态的关系

[`target/`](../../target/) 没有个人使用记录的筛选这一层；这一版是 v58 个人使用记录之上的细化，不改变可见性与数据保留的远期形态。这条差异由目标态文档的差异清单在交付后吸收。
