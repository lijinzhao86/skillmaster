# v9-skill-transfer · 一版 skill 的整包下载与导入，以及网页从零新建 skill

> **最后更新**：2026-10-21
> **状态**：进行中（PRD、设计稿、技术设计与测试方案已定稿；**代码已实现**，服务端单测 238 / 三条新 IT 18 / CLI `go test` / 网页 468 全绿，另有一次本地接口实测（见 test-plan §结果）。**待**：浏览器与视觉的人工验收，以及开放问题里三条设计补态——它们不在本版实现范围，句子未自拟）
> **含收费**：否

## 目标

让一整版 skill 能从浏览器或 CLI 取成一个 zip，也能把一个本地 zip 带回来变成一版草稿；网页还能不经过上传、从零新建一个 skill 与它的第一份草稿。细节见 [`prd.md`](prd.md)。

## 验收标准

一句话：整包由服务端一次产出（单个快照、ETag 对得上），导入沿用既有的 zip 契约并保持幂等，权限沿用梯子。完整 20 条与指标见 [`prd.md`](prd.md) §验收与指标。

成立条件（不满足就不算交付）：#1、#2、#9、#10、#12、#16、#18、#19——整包取得对、往返不多版本、坏包零写入、快照一致、权限不变宽、元数据不是内容、新建 skill 不落空壳、拒绝或失败不留半行。

## 这一版明确不做什么

- **本地工作区 / pull-push 同步** —— 导出是一次性快照，不是第二份事实。
- **匿名整包下载（消费面路由）** —— 整包只对能读这一版文件的作者面开放；`invoke` 仍只能按路径取单文件。
- **平台字段随包往返**（可见性、协作者、发布状态） —— 授权与可见性是改变「谁读到什么」的动作，不能藏在包里。

完整范围与每条理由见 [`prd.md`](prd.md) §范围。

## 与目标态的关系

- **保留的部分**：服务端是唯一真相、不落常驻副本；内容寻址；提交与上线分开；按档可见（[`target/README.md`](../../target/README.md) 第 4 条的分叉不变）。
- **这一版新增的出口**：用户显式发起的一次性导出（一个 zip）。它不是本地缓存，也不改变「本地不落副本」——下载目录归用户自己管，产品不读它、不同步它。
- **分叉**：目标态里的多层分发与运行时门控仍不在本版；本版只做作者面的一整包进出。

## 影响最大的未决问题

完整列表见 [`technical-design.md`](technical-design.md) §开放问题。**仍开放的三条都是「设计稿要先补一句话」，不是实现口径没定**；本版实现已在没有它们的情况下完成——缺句子的一律**回落（导入与编辑器回服务端原句，新建 skill 的网络态回应用既有的网络句）、不自拟**，补态是这一版之后的**设计债**，不阻塞代码：

1. **编辑器里新建 / 重命名到保留路径**——要新增一个 `editor-reserved-path` 状态（下一版前补）。
2. **一部分导入拒绝的上屏句子**（非 zip、空包、目录名不符、超上限、重复路径、符号链接、反斜杠）——设计稿给了要求、没给句子（下一版前补）。
3. **文件栏钉住一版已丢弃的版本时，文件区写什么**——设计稿只写了「作为禁用项出现」（下一版前补）。

其余五条（临时文件、reader 余量、create-only 入口、不处理 `If-None-Match`、无版本号行的文件名）已在 TD 里定下实现口径，留「实测确认」一列。
