## 用户与场景

**谁在用**：

- **作者**（`write` 及以上）与**维护者**（`maintain` 及以上）：在浏览器里点、或在本机敲 CLI 的人。
- **装了 CLI 的人与 agent**：需要把一整版取到本地做检索、处理或留档。
- **手里已经有 skill 文件夹、但没装 CLI 的人**：运营、产品、刚加入的同事。他们的本机有一个 `SKILL.md` 和几份文件，今天没有入口把它们带进来。

**在什么场景下用**：

- **取一版到本地**：线上版本要在本地用 `rg` / `sed` / 编辑器处理，或交给某个只认本地目录的工具。作者在版本页点「下载」，或敲 `skill download`，得到一整包。
- **备份与迁移**：维护者把某一版留档，或者交给另一个环境、另一个仓库。
- **网页导入到已有 skill**：本地改好了一版，压成 zip，在版本列表的「新建版本」菜单里点「导入压缩包」，落成草稿；检查后仍在版本页上线。
- **没有 CLI 的人第一次把 skill 带进来**：在「我的 skill」页的「新建 skill」菜单里点「导入本地 skill」；压缩包里的 `SKILL.md` 决定 skill 名字，落成草稿，网页里就能上线。
- **没有 CLI 的人从零写一个 skill**：同一个「新建 skill」菜单里点「在线编辑」，填名字、描述与第一条草稿的版本名称，直接进编辑页写完；不必先在本机拼一个压缩包。
- **agent / 脚本的往返**：`skill download` 取一版 → 本地处理 → `skill submit` 交回；内容没变时服务端认得出来，不会多出一版。下载的包里带一份 `.skillmaster/metadata.json`（这一版的名称与说明），交回时不用重填。

**现在的替代做法是什么**：

- **下载**：CLI 只有 `cat`（单个文件写到标准输出）与 `ls`（清单）。要一整包，得自己写循环、建目录、逐个重定向——二进制还得小心别被 shell 或编辑器改写。网页只能逐文件打开；编辑器里只有二进制文件那一格给了「下载文件」。
- **导入**：CLI 的 `skill submit [目录]` 已经能做到（对装了 CLI 的人是够的）；网页完全没有入口——v8 明确把「上传 zip / 从本地目录导入」列为不做（[v8 PRD](../v8-web-editor/prd.md) §不做 #1）。
- **新建一个全新的 skill**：今天只有「提交一个包」这一条路——CLI 的 `skill submit`，或 API。网页既没有上传入口，也没有「从零写一个」的入口；`skill` 行只由提交产生。

**这一版为什么还要做**：

1. **一版是一个整体。** 逐文件取既没有快照保证（中途有人写草稿，取到的文件来自两个时刻），也没有「这一包就是这一版」的身份。整包下载把版本 digest 一起交出去，往返才对得上。
2. **把「有文件夹、没 CLI」的人挡在门外的，正是缺一个网页入口。** 导入的校验、上限与幂等大部已经在服务端（`ZipReader` / `SkillUploadValidator` / `submit`），缺的不只是两条会话鉴权的路与能点的按钮：**要让平台元数据不进清单、不进上限，解压 / 校验 / manifest 生成里需要一处统一的保留路径过滤**；写路径（`skill write` / `mv` / `cp` 与编辑器）另有一条只作用于**目标**的规则，两者的位置以技术设计为准。

## 范围

### 做

| # | 做什么 | 交付形态 |
|---|---|---|
| 1 | **CLI 整包下载**：`skillmaster skill download <命名空间>/<名字>[@版本 \| @版本码] [--into <目录>]`。不带钉取线上版本；`@1.2.3` 取已发布版本；`@<版本码>` 按行 id 解析（新行 8 位短码、旧行 26 位 ULID，任何状态都可寻址，[ADR 0063](../../decisions/0063-a-draft-is-addressed-by-a-short-code.md)）；**可下载的状态与网页同一口径——线上、历史、草稿、已下架可以，已丢弃不下载**（[§不做 #8](#不做)）。省略 `--into` 时落到 `./<名字>`。**目标目录必须不存在或为空**；非空 → 拒绝、非零退出、一个文件都不写；已是空目录 → 直接改名到它（它是空的，不往里面解）。先解到 `<目标>.partial`，整包成功后改名；失败时清掉本次创建的临时目录，不留半个 skill。**目的地用 `--into` 而不是 `--to`**：`submit --to` 的 `--to` 指「提交到哪个 skill」，同一个词在同一族命令里指两个地方会让人按错。 | CLI + 服务端一条归档路由 |
| 2 | **服务端一次出包**：一次读定这一版的 manifest 与 digest，再按 blob 逐个流进 zip；一个请求返回整包，不逐文件拉。响应头带这一版的 digest 作为 `ETag`，往返时能对上「这包就是这一版」。包内的**内容条目**就是版本里的相对路径（没有外层目录）；这一版的内容里没有同路径文件时，另有一份 `.skillmaster/metadata.json`（见 #9）；压缩包本身是标准 zip、无密码。文件名 `<名字>@<版本号>.zip`（草稿用版本码），非 ASCII 走 RFC 5987。 | 服务端 |
| 3 | **网页下载**：能读到这一版文件的版本，页头次级动作里多一个「下载」，与「查看文件」同条件出现：**线上与历史版本 `browse` 及以上；草稿 `write` 及以上；已下架 `maintain` 及以上**（[ADR 0051](../../decisions/0051-the-author-plane-serves-by-tier.md) §决定 2、[ADR 0054](../../decisions/0054-lifecycle-actions-happen-on-a-version-page.md) §决定 5）。它是一条直链，浏览器自己落盘，不经页面脚本。**已丢弃的版本没有这个入口**——产品里这一态不展示文件列表与「查看文件」（[`design/README.md`](../../../design/README.md) §导入与下载与「文件栏」两节是权威：文件栏里它不列，地址钉住时作为禁用项出现）。**既有产品在文件栏按版本码直接打开时，`maintain` 仍会看到已丢弃版本的文件；v9 一并收掉**，让「这一态不展示文件」真的成立。 | 网页 |
| 4 | **网页导入到已有 skill**：版本列表的「新建版本」菜单里有「导入压缩包」（`write` 及以上）。对话框收一个 **zip 文件**、这一版的**名称**（必填，1–40 个码点，[ADR 0055](../../decisions/0055-drafts-have-a-required-name.md)）与**说明**（可选，至多 200 个码点）。**内容不同才产出新草稿，页面落到它的版本页；相同则幂等返回既有版本，弹窗不关，在表里显示「这个 skill 已经有一版同样的内容…」那一行（逐字句子以设计稿为准）并给出既有那一版的入口——读不到那一版就不给链接**；**线上指针不动**（[ADR 0031](../../decisions/0031-submitting-and-publishing-are-two-actions.md)）。 | 网页 + 服务端一条导入路由 |
| 5 | **网页导入到「我的 skill」**：「我的 skill」页的「新建 skill」菜单里有「导入本地 skill」（任何登录账号；**空态里也在**）。名字由压缩包里的 `SKILL.md` 决定，只写进**调用者自己的个人命名空间**；没有就建一个，已经有就往它名下加一版——**不会出现第二个同名 skill**；内容相同则幂等返回既有版本。**新建 skill 时保持「未上线」；已有 skill 时线上指针不动。** 两个导入入口共用同一张表：版本名称必填、说明可选。 | 网页 + 服务端一条导入路由 |
| 6 | **导入的说明与校验**：只收 zip（[§不做 #3](#不做)）。对话框写清三件事：只接受 `.zip`；`SKILL.md` 要在压缩包根部，或者**所有文件都在同一个顶层目录里**、且目录名与 frontmatter 的 `name` 相同（规则是「所有条目共享同一个首段」，不是「只有一个目录」）；最多 512 个文件、**解压后合计** 16 MiB（`SKILL.md` 计入；请求体另有 32 MB 的传输上限）。拒绝原因按入口分：**两个入口都可能有**——非 zip、空包、缺根 `SKILL.md`、重复路径、符号链接、目录名与 `name` 不符、超过 512 个文件 / 解压后 16 MiB、路径不规范、压缩包本身超过 32 MB（请求体上限）、内容里出现保留路径 `.skillmaster/metadata.json`（它留给平台元数据，不能当内容文件）；**只有版本列表导入有**——地址名与内容名不一致（`name_mismatch`，**两个名字都写出来**；我的 skill 那一路没有地址名可比）；**只有「我的 skill」导入与新建 skill 有**——名字被已删除的 skill 占着（版本列表那一路根本看不见已删除的 skill，是 404），**新增码 `skill_deleted`，并给「去恢复」**。各有具名原因，**拒绝时零写入**。 | 服务端既有校验 + `details` 带上两个名字 + 新增 `skill_deleted` + 网页提示 |
| 7 | **往返不变**：把下载下来的目录原样 `skill submit`（或压回 zip 再导入），内容相同则服务端认出来并答「内容未变」——不产生第二版（[ADR 0005](../../decisions/0005-content-addressing.md)）。**例外：内容里含保留路径 `.skillmaster/metadata.json` 的历史版本**——下载成功、包原样，但它不满足「可以再导入」这条承诺（导入会被具名拒绝，见 #9）；这是保留路径规则的代价，不是漏项。**唯一再例外**：那条历史文件**本身就是 sidecar 形状**（顶层带 `schema_version` 的 JSON 对象）时，判别式把它当元数据剥掉、导入成功、文件不进新版本——否则平台自己导出的包就永远不能再导入（同见 #9）。 | 验收条件，不新增交付物 |
| 8 | **CLI 的导入命令仍是 `submit`**：`skill submit [目录] [--to <命名空间>/<名字>]`。本版让它支持**从包内 metadata 读版本名称**：包里有 `version.name` 时 `--name` 可以省略（[ADR 0055](../../decisions/0055-drafts-have-a-required-name.md) 的提交必填口径随之修订为「必须有名称，来源可以是显式参数或包」）；**CLI 不带 `--to` 的个人命名空间提交**碰到已删除的同名 skill 时改用新码 `skill_deleted`（今天拿到的是 `invalid_request`，[ADR 0050](../../decisions/0050-deleting-a-skill-can-be-undone.md) 的记录随之修订）；**带 `--to` 的地址式提交与版本列表导入一样是 404**（它看不见已删除的 skill）。并补帮助与 README。 | CLI + 文档 |
| 9 | **本地元数据文件**：下载时在包里写 `.skillmaster/metadata.json`（`schema_version` + `version.name` / `version.note`；映射到内部 `draft_name` / `note`）；导入时由服务端读它、**解析成版本字段**。**它不会成为版本里的文件**：不进清单、不进 digest，文件列表与 `grep` / `cat` 都看不到它；同一份内容带它不带它，digest 相同、仍然幂等；**它不计入 512 文件 / 16 MiB**。v9 只带**版本名称与说明**；请求显式给了非空值就用请求的，**空字符串与没给同义**，此时用文件里的；两者都没有 → `draft_name_required`。未知字段、不认识的 `schema_version`、类型不对 → 具名拒绝（码与优先级在 TD）、零写入；缺文件 = 默认值。**先校验包与元数据的格式，再判内容是否已存在**：格式不合格的包永远具名拒绝，哪怕内容已经存在。**内容相同时幂等返回既有版本**：那一版的名称与说明不被包里的值覆盖——内容身份优先，元数据只在产生新版本时用。**保留路径**：**上传**不能再把它当内容文件；**既有版本若已含该路径，原样保留**——下载时那个文件原样进包、只是不写 sidecar（元数据是可选的附带品，丢掉它不算丢掉内容），从它复制新草稿也把它带过去（不静默丢一个用户看不见的文件，也不因此把历史 skill 锁死在不能编辑）；把这样的包再导入时，这个路径作为内容出现 → 具名拒绝并说清怎么改（那是一条历史数据，不因此让下载本身多出一个失败态）。**sidecar 的判别式**：这个路径上的文件若是**顶层带 `schema_version` 键的 JSON 对象**，就按 sidecar 处理，随后每一条 schema 规则都给出具名的 `metadata_*` 原因（不认识的版本号也算在内）；不是这个形状（纯文本、或没有这个键的 JSON）就按「保留路径上的内容」具名拒绝——绝不静默当元数据丢掉，也绝不静默当内容收下。**这两个规则在一个角上只能二选一**：那条历史文件**本身就是这个形状**（顶层带 `schema_version` 的 JSON 对象）时，判别式把它当 sidecar，导入成功、那个文件不进新版本——否则平台自己导出的包就永远不能再导入。这是保留路径规则的代价，与 #7 的例外同源。 | CLI + 网页（名称由人填；说明留空时用包里的）+ 服务端 |
| 10 | **网页新建 skill（在线编辑）**：「新建 skill」菜单里的「在线编辑」。对话框收**名字**（必填，至多 64 个码点）、**描述**（必填，`SKILL.md` 的 `description`）、**版本名称**（默认「第一版」，必填，1–40 个码点）。一次事务建出 skill 与它的第一条草稿，**草稿里带一份最小的根 `SKILL.md`**（frontmatter 的 `name` 与 `description` 就是表单填的这两个），落在这条草稿的编辑页；列表里这一行是「草稿」，**线上指针不动**。名字已被占用 → 拒绝并给 `查看 <名字>`；名字属于已删除的 skill → 拒绝并给 `去恢复`（`skill_deleted`）。**名字的长度按码点算**：今天 `SkillDocument` 用的是 UTF-16 码元（`String.length()`），v9 把它与版本名称统一成码点，否则同一个名字在网页与 CLI 两条路上限不同（依赖见下）。 | 网页 + 服务端一条建行路由 |

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | **本地工作区 / pull-push 同步 / 改完自动回传** | 下载是一次性快照，不是第二份事实。服务端仍是唯一权威（[ADR 0001](../../decisions/0001-server-authoritative.md)）；改完再交就是一次普通的 `submit` | 不做（结构性） |
| 2 | **`--force` / 覆盖已有目录 / 增量 / 断点续传** | 往一个已经有东西的目录里解压，可能冲掉人的本地改动；这个 CLI 没有本地副本的概念，也就不该替人决定覆盖。目录非空就拒绝，删不删由人自己决定 | 若真有反复下载到同一目录的用法，先加「只覆盖本包带来的同路径文件」而不是全量 `--force` |
| 3 | **网页选本地文件夹（只收 zip）** | 服务端与 CLI 的导入契约本来就是「一个 zip」；网页多一条文件夹上传就是第二套 intake，校验与错误态都要再来一遍。系统里「压缩文件夹」本来就是一步 | 未定 |
| 4 | **匿名整包下载（消费面路由）** | 「公开 · 浏览」今天承诺的下载由逐文件路由满足；整包是一条新的公开面，要单独想清楚缓存与滥用 | 未定 |
| 5 | **导入时合并 / 覆盖已有版本** | 导入要么产出一份**新的草稿**，要么在内容已存在时**幂等返回既有版本**（不新建、也不动它）；任何已有版本的内容都不动（[ADR 0005](../../decisions/0005-content-addressing.md)、[ADR 0064](../../decisions/0064-a-draft-may-change-a-published-version-may-not.md)）。合并需要一套冲突规则，是另一件事 | 不做 |
| 6 | **导入时改 frontmatter / 自动补 `SKILL.md`** | 提交的是作者的字节，服务端不改写内容（[ADR 0005](../../decisions/0005-content-addressing.md)）；缺 `SKILL.md` 就拒绝并说清楚，不替人编一个 | 不做 |
| 7 | **保留空目录** | 版本里只有文件，没有目录实体；空目录不构成内容 | 不做 |
| 8 | **下载已丢弃的版本** | 产品里这一态不展示文件列表与「查看文件」，也就没有能点的地方；丢弃是终态，没有任何恢复入口 | 未定（服务端内容还在，放开只是产品决定） |
| 9 | **给 zip 加密码、分卷、自定义压缩级别** | 标准 zip 是导入导出的公共格式；加这些会让「下载后原样提交」不再成立 | 不做 |
| 10 | **平台字段随包往返**（可见性、协作者、发布状态、描述覆盖） | 可见性与授权是改变「谁读到什么」的动作（[ADR 0037](../../decisions/0037-visibility-has-two-states.md)、[ADR 0048](../../decisions/0048-visibility-hands-out-a-rung.md)、[ADR 0034](../../decisions/0034-skill-level-sharing.md)）；协作者随包走就是一条权限提升路径；描述覆盖（[ADR 0049](../../decisions/0049-an-edited-description-outranks-the-version.md)）还没实现 | 描述覆盖随元数据那一版；可见性与授权不做 |

**范围里没有「后续再看」「视情况而定」。** 需要先定的技术选择都在 [`technical-design.md`](technical-design.md) §开放问题里，写成能回答的问法。

## 验收与指标

### 验收标准

| # | 验收标准 | 怎么判定 |
|---|---|---|
| 1 | **CLI 下载整包**：`skill download <ns>/<name>@1.2.3 --into <空目录>` 写出这一版的全部文件；**内容路径与内容文件数**（不含 `.skillmaster/metadata.json`）与 `skill ls` 一致，二进制逐字节一致（**唯一例外**：历史版本在该路径上的内容文件本身是 sidecar 形状时，CLI 无法与元数据区分，这一角报 N−1，见 #9）；响应头的 `ETag` 是 `"sha256:" + 这一版的 digest` | 夹具含文本、二进制、中文路径与非 ASCII 的 skill 名；下载后比对 `skill ls`、`cmp` 与响应头 |
| 2 | **往返不变**：下载后的目录原样 `skill submit --to <同一个 skill>`（`--name` 可省，包里带着；**v6 之前的老行没有版本名称时包里没有这个键，`--name` 仍要给**），服务端答「内容未变」，版本总数不变，digest 与源版本相同。**这一条不覆盖含保留路径的历史版本**——那个例外见 #16 | 下载 `@x.y.z` → 提交 → 读返回、读版本列表（夹具不含保留路径） |

| 6 | **包内名字必须与地址一致**：zip 的 `SKILL.md` 声明 `name: B`、地址是 `A` → 拒绝，页面同时写出两个名字；什么都没写 | 构造一次不一致 |
| 7 | **网页导入到「我的 skill」**：任何登录账号在「新建 skill」菜单里看得见「导入本地 skill」；导入一个不存在的名字 → 出现新 skill（未上线）与一条草稿；同一个包再导一次 → 内容已存在、仍只有一个 skill 与一个版本；换一份内容再导 → 这个 skill 多一个版本，始终不出现第二个同名 skill | 新名字、同一个包、换一份内容各导一次 |
| 8 | **名字被已删除的 skill 占着**：拒绝，并给出「去恢复」的入口；服务端给出具名原因（`skill_deleted`），不是一句泛泛的失败；**CLI 不带 `--to` 的个人命名空间 `submit` 也拿到同一个码，带 `--to` 的地址式提交是 404** | 造一个已删除的同名 skill（它的行是前置，不算写入），网页导入一次、CLI 不带 `--to` 提交一次、带 `--to` 提交一次；读三家表在拒绝前后的行数差，**新增 0 行** |

| 10 | **快照一致**：下载一个草稿的过程中，另一个会话修改这份草稿；下载到的包仍是发起时那一份 manifest（**内容文件数**与那次读到的版本 digest 一致，不含 sidecar），不出现两个时刻的文件 | 两个会话：一个下载、一个写入；比对 manifest 与 digest |
| 11 | **一次请求**：整包由服务端一次生成；CLI 与网页都不逐文件拉取 | 服务端访问日志 / 测试计数 |
| 12 | **权限沿用梯子**：下载与「查看文件」同条件（线上/历史版本 `browse`+；草稿 `write`+；已下架 `maintain`+）；导入需要 `write`（版本列表）或本人账号（我的 skill）；新建 skill 只在本人账号的个人命名空间；`invoke` 既没有入口，也拿不到包 | 五个可授档位加所有者各试一次 |
| 13 | **失败如实**：网络中断、上传超时、服务端拒绝时，两张对话框都显示原因；CLI 非零退出；页面不显示成功。**直链下载不在此列**：它没有页面中转，失败就是浏览器拿到的那份响应（见 #4） | 断网、超时、构造超限各一次 |
| 14 | **两张对话框可用**（导入、新建 skill）：400px 宽下不溢出；`Esc` 关闭并把焦点还给打开它的控件；提交中按钮显示进行中、取消与提交都不可再点 | 400px 视口；键盘走一遍 |
| 15 | **文案与设计稿一致**：四处入口的位置、文案、显隐，以及「`SKILL.md` 要在包根，或所有文件都在同一个顶层目录里」的说明，与设计稿逐条一致 | 对照设计稿与 [`design/voice-spec.md`](../../../design/voice-spec.md) |
| 16 | **元数据不是内容**：下载的包里有 `.skillmaster/metadata.json`；这一版的文件列表里没有它，`grep` / `cat` 读不到它；同一份内容带它、不带它各提交一次，digest 相同、版本数不变，**既有版本的名称与说明也不被包里的值覆盖**；**512 个内容文件 + 元数据仍接受、16 MiB 内容 + 元数据仍接受**；**既有版本的内容里已经含着这个路径时，下载成功但不写 sidecar，那个文件原样在包里**；把这样的包再导入 → 具名拒绝（**那条历史文件本身是 sidecar 形状时例外：导入成功、文件不进新版本**，见 #9）；**从这样的版本新建一版草稿 → 成功，那个文件随草稿保留**（历史数据不被静默丢掉，也不把旧 skill 锁死在不能编辑） | 下载后读 `skill ls`；两次提交比对返回的 digest 与版本数、再读既有版本的名称与说明；两个上限各造一个带元数据的包；构造**两个**含该路径的旧版本——一个普通文本（导入被拒）、一个 sidecar 形状（导入成功）——各下载一次、再导入一次、再从它新建一次 |

| 18 | **网页新建 skill（在线编辑）**：「新建 skill」菜单里点「在线编辑」，填名字、描述与版本名称（默认「第一版」）→ 服务端一次建出 skill 与第一份草稿，**草稿里有一份根 `SKILL.md`，frontmatter 的 `name` / `description` 等于表单填的两个值**，页面落在这一版的编辑页；返回列表，这一行是「草稿」且未上线；编辑页里写下的内容提交后就是这条草稿。**名字按码点计**：64 个 emoji 接受，65 个拒绝 | 走一遍创建 → 读版本文件列表 → 读列表 → 在编辑页写一个文件并提交；再各造一个 64 / 65 个 emoji 的名字 |
| 19 | **建 skill 的两种拒绝**：名字已被自己的 skill 占用 → 拒绝、零写入，并给「查看 `<名字>`」；名字属于已删除的 skill → 拒绝、零写入，码 `skill_deleted`，并给「去恢复」；**事务中途失败时三张表都新增 0 行** | 两种各构造一次；每种拒绝后比对 `skill` / `skill_version` / `version_file` 三张表在拒绝前后的行数差；再注入一次写入失败 |

**成立条件**：验收 #1、#2、#9、#10、#12、#16、#18、#19 是不满足就不算交付的八条——它们分别保证「整包真的能取到、路径与字节都对」「往返不会多出版本」「坏包不会悄悄留下半份内容」「下载的包真的是一个快照」「权限不会因为多了两个入口而变宽」「元数据不会变成内容、不会改变 digest」「新建 skill 不会只建出一个没有内容的空壳」「拒绝或中途失败时不会留下半行」。

### 指标

| 指标 | 定义 | 怎么量 | 目标 |
|---|---|---|---|
| 一次整包下载的服务端请求数 | 从命令或点击发出，到收到完整响应；不含认证与重定向 | 服务端访问日志 / 测试计数 | 恰好 1 |
| 下载包与清单的一致率 | 包内**内容路径集合**（不含 `.skillmaster/metadata.json`）与字节逐一比对 | 自动化用例 | 100% |
| 坏包拒绝后的写入 | 被拒绝的导入是否留下 `skill` / `skill_version` / `version_file` 行 | 拒绝后查库 | 0 |
| 往返 digest 相等率 | 下载后原样提交得到的 digest 与源版本比对 | 自动化用例 | 100% |
| 带/不带元数据文件的 digest 相等率 | 同一份内容分别带 `.skillmaster/metadata.json` 与不带，各提交一次 | 自动化用例 | 100% |
| 建 skill 的服务端请求数 | 从点「创建」到落在编辑页；不含页面自己的读取 | 服务端访问日志 / 测试计数 | 恰好 1（一次事务建出 skill 与第一份草稿） |

本版不设性能指标：整包上限沿用 16 MiB（**解压后内容合计**，`SKILL.md` 计入；zip 头、目录条目与 sidecar 会让下载包略大），延迟不是这一版要回答的问题。

## 依赖与前置

- **外部依赖**：无。不需要新的第三方服务、新的运行时或客户端 zip 库——导入只收 zip，下载是一条直链。
- **内部前提**：
  - 服务端权威、内容寻址、提交与上线分开（[ADR 0001](../../decisions/0001-server-authoritative.md)、[ADR 0031](../../decisions/0031-submitting-and-publishing-are-two-actions.md)、[ADR 0005](../../decisions/0005-content-addressing.md)）；
  - 服务的判断是权威、客户端校验只是礼貌（[ADR 0011](../../decisions/0011-server-and-cli-stack.md)）；
  - **五档可授 + 所有者**的权限梯子与作者面按档可见（[ADR 0047](../../decisions/0047-permissions-are-a-ladder.md)、[ADR 0051](../../decisions/0051-the-author-plane-serves-by-tier.md)）；已下架的版本只对 `maintain` 及以上可读（[ADR 0054](../../decisions/0054-lifecycle-actions-happen-on-a-version-page.md) §决定 5、[ADR 0063](../../decisions/0063-a-draft-is-addressed-by-a-short-code.md) §决定 3）；
  - 草稿有必填名称、由版本码寻址（新行 8 位短码，旧行 26 位 ULID；[ADR 0055](../../decisions/0055-drafts-have-a-required-name.md)、[ADR 0063](../../decisions/0063-a-draft-is-addressed-by-a-short-code.md)）；
  - 草稿可变、发布内容冻结（[ADR 0064](../../decisions/0064-a-draft-may-change-a-published-version-may-not.md)）；
  - 共享让 `write` 档的人可以给别人的 skill 加版本（[ADR 0034](../../decisions/0034-skill-level-sharing.md)；今天在梯子上是 `write`）；
  - **名字按码点计 64 上限**（与版本名称同一条量法）。今天 `SkillDocument` 用的是 UTF-16 码元，v9 改过来；这会**放宽**可接受的名字集合（64 个星平面字符今天算 128 个单元），既有名字不受影响。
- **本版要补的四条 ADR**（写文档阶段交付；已落盘为 0068–0071）——
  1. **导出是一次性快照，不是工作区**（它同时否掉 pull/push 同步）。**这条取代 v7 TD §「安全边界：整版字节不出服务端」与 T-SEC-01 的绝对禁令**：新边界是「整版只对能读这一版文件的人开放（线上/历史 `browse`+；草稿 `write`+；已下架 `maintain`+），已丢弃不导出；`invoke` 仍只能按路径取单文件」。ADR 0001 / 0035 的「本地不落副本」指 CLI 的常驻读路径与模型上下文，不指用户显式发起的一次性导出。
  2. **`.skillmaster/metadata.json` 是旁路，不是内容**（它不会进入版本清单或 digest，也不计入上限）。这条同时记录对 **ADR 0055 §决定 1** 的口径修订：「版本必须有名称，来源可以是显式参数或包」，而不是「每次提交都必须由人显式给出」。
  3. **新建 skill 与它的第一份草稿是一个动作**（要么两者都落，要么都不落）。
  4. **提交到已删除的名字答 409 `skill_deleted`**（拒绝而不复活不变，换的是状态码与码名，好让页面把人送到「去恢复」、CLI 翻成中文）——记录对 ADR 0050 中 `400 invalid_request` 那一条的修订。
- **数据标准的落点**：不新造一套分层，沿用 [`docs/architecture/model.md`](../../architecture/model.md) 既有的四个身份——**命名空间 / skill / 版本 / 文件**。版本名称与说明属于「版本」；可见性、授权、线上指针属于「skill / 命名空间」；内容属于「版本 / 文件」；`.skillmaster/metadata.json` 只是传输时对「版本」那一层的旁路表示。模块归属留在版本 TD，不在 model.md 复制一份。
- **错误信封的两层**：`skill_deleted` 是顶层 `error.code`，并且**替换今天所有走到 `SkillDeletedException` 的路径**（包括既有的 CLI `skill submit`；由本版 ADR 记录对 [ADR 0050](../../decisions/0050-deleting-a-skill-can-be-undone.md) 中 `400 invalid_request` 那一条的修订；实现时只在 0050 的文件头加引用，正文不改）。`name_mismatch` 仍是 `details[].issue`；页面要把两个名字都写出来。**信封形状不变**：沿用既有的「值放在 `issue`、`field` 说明它是哪个值」约定（先例：`Detail("state", row.state())`、`Detail("current_digest", …)`），本版用 `address_name` / `content_name` 两条 detail。
- **排除了什么前置**：
  - **不需要改数据模型**：不新增表、不新增列、不改唯一约束。整包由既有 manifest 与 blob 现算；「建 skill + 第一份草稿」用的是既有两张表。
  - **不需要新的上传格式**：导入仍是既有的 zip 契约。但**不是零改动复用**：解压要放宽一个固定余量，校验那一段要落**唯一一处**保留路径过滤与上限排除，写路径另有一条只作用于目标的判定——这是本版的服务端交付物，不是顺手；具体落点见 TD §架构。
  - **不需要新的权限档位**：下载沿用「查看文件」，导入沿用 `write` 与个人命名空间；新建 skill 只在个人命名空间，沿用「本人账号」。
  - **不需要客户端打包**：网页只收 zip、只发直链，不引入 zip 库。
