# v19-skills-retrieval · PRD

## 用户与场景

**谁**：库里有几十到几百个 skill 的人，以及在会话里替他们找工具的 agent。

**他要什么**：不用记得库里有什么、也不用逐个读描述，就能找到「能完成这件事的那一个」。今天的两条路都不够：默认列表只给前 50 条（大库列不完），关键词检索要求**提问与描述有字面重合**——`怎么把 PDF 拆成单页` 这种口语问题，名字与描述里都没有那几个字。

**这一版补的**：一套**语义检索**，私域与公域共用同一套排序，范围只由权限谓词决定。它回答的是「有没有一个 skill 能做成这件事」，不是「哪个 skill 的名字里有这个词」。

**冷启动的边界**：先只做「向量召回 + 前 N 条 + 分数」，把重排、混排、查询前缀留到后续迭代——先验证向量本身够不够，再谈叠加。

**证据**：2026-10-25 在真实的 33 个本机 skill 上，用 66 条标注问题测得 `Recall@10`——关键词（二元组近似）0.73，向量（`text-embedding-v4`，文本为 name + title + description + when_to_use）0.92。这是这一版值得做的直接依据；它同时暴露了向量最大的风险：**它永远返回前 N 条，不理解时也不说「没有」**。

## 范围

### 做

| 做 | 内容 |
|---|---|
| 独立的检索模块 | `modules/retrieval` 拥有向量表、embedding 调用与近邻查询，对外只有 `search(scope, query, filters, limit)`；**不判断可见性**（候选集由 M12 给）、**不拥有描述文本**（经 `EmbeddingTextSource` 从 M12 的投影读） |
| 私域与公域同一策略 | 同一份向量、同一套排序，`scope` 只改变可见性过滤。候选集 ≤ 20000 时先收窄再排序（精确）；超过时按近似路径，结果可能额外受前 200 名截断影响（见 TD §检索链） |
| 向量与业务同一个 PostgreSQL | pgvector 扩展；候选集由 skills 模块先按可见性收窄，向量查询只查自己的表；不产生第二份真相（软删除不动向量行，检索时由可见性谓词滤掉） |
| 向量化的文本 | `name + title + description + when_to_use` 的**已发布版本**；一个 skill 一条向量。草稿不索引 |
| 发布即索引 | 向量在**发布事务内**计算：事务提交才算发布成功，失败则指针、审计、向量一起回滚。代价是发布要等一次向量往返，且 provider 不可用时发布不可用（可关闭语义开关恢复） |
| 返回形状 | 默认前 **10** 条，`limit` 可调（上限 50）；每条带**相似度分数** |
| 无匹配的表达 | 分数低于阈值的结果不返回；整批为空时明确说「没有足够相关的 skill」，不拿 10 条凑数。阈值先给保守值，按真实查询再调 |
| CLI 对应 | **只扩 `skills search` 一个动词，不新增 `find`**（预发布阶段语义可改——ADR 0088（在 v17 分支，尚未合入 main） 约束的是已发布版本）：默认 `--scope library` + 语义；`--scope public\|all`；`--my-tag` / `--public-tag` / `--category` 按范围生效，配错是用法错误；`--semantic=false` 退回字面；`--limit` 默认 10、上限 50，语义档不接受 `--cursor`。检索只读、无高风险，按 [ADR 0081](../../decisions/0081-every-console-operation-has-a-cli-command.md) 必须有 CLI 对应；**本版不新增控制台操作**，发现页跟随同一接口 |
| 隐私开关 | 部署级可关闭向量化；关掉之后检索退化为关键词，其余功能不受影响，且缺少 embedding 配置不导致启动失败 |
| 发布的等待态 | 向量在发布事务内计算，所以发布要等一次向量往返。控制台在这一段时间里必须有明确反馈（"正在发布"），不能是一个没有反应的按钮。**这一态设计稿尚无，实现前要先补进 `design/`** |

### 不做

| 不做 | 原因 |
|---|---|
| 重排（rerank）、混排（RRF）、查询侧指令前缀 | 冷启动先验证向量召回本身；这三项是最可能的下一步优化，且都需要新的评测数据才能判断有没有用 |
| 独立向量库（DashVector / Milvus / OpenSearch） | 几百到几千条，pgvector 足够；外部索引意味着同步、双写与「删了 skill 忘了删向量」 |
| 网页搜索引擎 / 检索 API（Bing、Tavily、Exa） | 只索引公网，看不到私域；用它们就得把私域发布出去，与产品主张冲突 |
| 多语言、跨模型迁移、维度变更 | 先只服务中文与一个模型；换模型时的重算策略留到下一次 |
| 关键词那一半的重写 | 现有 L1 保持不动，本版只增加语义一路 |
| 用向量做「推荐」 | 检索回答「有没有」，推荐回答「你可能还想」，后者需要行为数据，本版没有 |

## 验收与指标

| # | 验收 | 怎么判定 |
|---|---|---|
| 1 | 标注集上的 `Recall@10` ≥ **0.90** | 用随仓库的 `src/test/resources/retrieval/labeled.tsv`（**99 行：66 条语义式 + 33 条名字式**，33 个 skill）跑真实接口，**分两组各报一次**；目标 skill 出现在前 10 即命中。低于 0.90 不发布 |
| 2 | 结果不带无关项：低于阈值的不返回 | 造 10 条库里确实没有答案的问题；返回条数应显著少于 10，且整批为空时给出「没有足够相关」的明确句子 |
| 3 | 私域与公域同一策略，只换范围 | 同一个问题分别在两个 scope 下跑：排序机制相同，结果集合只差权限谓词 |
| 4 | 条数生效且有上限 | `--limit 3` 返回 3 条；`--limit 100` 被截到 50 并说明；语义档下 `--cursor` 是用法错误（退出码 2） |
| 5 | 权限不出错 | 别人私有的 skill 在私域 scope 下不出现；公域只返回公开且 live 的 |
| 6 | 发布即索引 | 发布返回成功的那一刻，新文本就能被语义检索到（没有「等几秒」的窗口）；回滚发布同样立即生效；删除 / 下线后立即消失 |
| 7 | 故障可降级 | **检索侧**：embedding 服务不可用或超时，检索退化为关键词并明说「语义检索暂不可用」，不阻塞（`scope=all` 没有字面形式，那一档只回说明与空结果）。**发布侧**：同一故障下发布失败并明确告知，且没有留下半个状态（见 14） |
| 8 | 隐私开关有效 | 关掉向量化后，检索走关键词，接口不因缺少 embedding 配置而启动失败 |
| 9 | 成本可算 | 每次语义检索与每次发布索引的耗时与 token 数打印在日志（**不含用户写下的任何文本**），据此可算出费用。换模型的全量重算不在本版 |
| 10 | CLI 与控制台一致 | `skills search` 与发现页对同一问题、同一范围返回同一批结果与同一排序 |
| 11 | 离线评测可复跑 | 99 行标注集随仓库走（`skillmaster-server/src/test/resources/retrieval/labeled.tsv`），任何人能复跑出第 1 条的数字 |
| 12 | 不拖慢既有路径 | 不开启语义档时，`skills search` 的响应时间与今天相比无显著变化（p95 增幅 < 10%） |
| 13 | 默认就是私域 + 语义 | 不带任何旗标跑 `skills search "…"`：只返回自己库里的 skill，按语义排序，前 10；同一句加 `--semantic=false` 变成字面命中，`--scope public` 变成公域 |
| 14 | 发布失败不留下半个状态 | 让 embedding 服务失败后发布：返回错误；再读该 skill，指针、版本、描述与索引都与发布前一致；重试一次成功后一切正常 |
| 15 | 发布等待态有反馈 | 用一个慢 2 秒的 embedding 桩发布一个 skill：控制台在等待期间显示进行中的状态，结束后显示结果；期间按钮不可重复触发 |

**指标口径**：`Recall@10` 按「目标 skill 是否出现在前 10」计，不看排名；**按语义式 / 名字式两组分别报告**，不合并成一个数。

## 依赖与前置

- **pgvector**：目标 RDS 的 PostgreSQL 17 **已确认提供**该扩展（2026-10-25，阿里云 CLI `DescribePostgresExtensions`）；**扩展版本是否 ≥ 0.8 未核实**，低于 0.8 时改用不过滤的精确扫描（本版规模下没有损失）。
- **embedding 服务**：百炼 `text-embedding-v4`（已在 spike 中验证可用）。需要一把 `DASHSCOPE_API_KEY`，存在部署环境变量里；spike 期间外泄的那把必须吊销。
- **新 ADR**：本版**取代 [ADR 0084](../../decisions/0084-l1-search-extension.md) 对「向量检索」的否决**，要写清三件事——为什么现在接受（有 0.92/0.73 的数据）、可解释性怎么补（分数 + 阈值 + 明确的无匹配）、描述出境到百炼的隐私边界（部署级开关、不记录用户查询文本）。
- **既有的 L1 不变**：关键词、分类、标签、排序规则都保持原样，语义是新增的一路。
