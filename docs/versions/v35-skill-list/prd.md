# v35 · 产品需求

> **最后更新**：2026-11-01 · **所属版本**：[v35](README.md)

## 用户与场景

**谁在用**：库里有几十个 skill 的账号主人——他自己提交的、别人共享给他的、他从「发现」加进来的。他打开「我的 skill」，是为了**找到某一条**：要改它、要上线它、要把它发给别人。

**在什么场景下遇到问题**：库里的 `description` 不是一句话，是 `SKILL.md` 的一段 frontmatter 正文。实测本机 55 个真实 skill，**中位 281 字、平均 337.5 字、最长 949 字；55 个里 46 个超过 200 字、9 个（16%）超过 400 字**。口径与命令写在这里，换一个人重跑应当得到同一组数：

```bash
cd ~/Developer/skill-inbox && ruby -ryaml -rjson -e '
lens = Dir.glob("*/*/SKILL.md").filter_map do |f|
  lines = File.read(f).split("\n"); next unless lines[0].strip == "---"
  stop = (1...lines.size).find { |i| lines[i].strip == "---" }; next unless stop
  d = YAML.safe_load(lines[1...stop].join("\n")) rescue next
  v = d["description"] if d.is_a?(Hash); next unless v.is_a?(String)
  v.split(/\s+/).reject(&:empty?).join(" ").length
end.sort
puts({ n: lens.size, median: lens[lens.size / 2], mean: (lens.sum.to_f / lens.size).round(1),
       max: lens.last, over200: lens.count { |x| x > 200 }, over400: lens.count { |x| x > 400 } }.to_json)'
```

它做四件事：取 frontmatter（`---` 之间）、**按 YAML 解析**（`description` 写成多行带引号或 `>-` 时按 YAML 的规矩折成一行——55 个里两类各有 7 个与 2 个，手工只认第一行就会算少，把 `#` 注释行当成正文就会算多）、把连续空白折叠成一个空格、按字符计。而列表把它当成一行副标题来画：

- 第二行 `<p class="skill-title">` **没有任何截断**；
- 行高被 `--row-max`（`12vh`，900px 高的窗口下 = **108px**）钉住，内容超出的部分直接画在外面（`overflow` 默认 `visible`）。

于是在 1440×900 里实测：一段 588 字的描述占 **6 行、126px**，行被截在 108px，**文字越过本行下边框 22px，压到下一行的名字与状态章上**。一整屏十条的名字、来源、状态、日期全部互相叠着，**这一页读不了**。

「发现」页是同一个根因的另一处：卡片也是把 `description` 整段铺开。一张卡片宽 **349px**；`?long=1` 下实测，321 字的说明在那儿铺开是 **8 行**、949 字的是 **24 行**（行高 22.4px，把 `-webkit-line-clamp` 去掉量的）——卡片被撑成一条竖条，一屏并排看不了几张。

**现在的替代做法**：肉眼在叠字里找名字；或者干脆去命令行 `skmr skills list` 按名字过滤。

**第二件事：找到之后，还要决定用不用它。** 库里 23 条在用、3 页，逐条比的时候要「进去、退出来、再进去」——skill 页的「信息」那一栏才有描述全文、适用场景、版本与调用地址。**预览把其中关于「用不用它」的那几件——描述、适用场景、更新于，加上行上没有的分类与我的标签——提前到列表旁边**（版本号与调用地址不在预览里，它们回答的是「怎么用它」），一趟看完十条里哪条对。

> **这个毛病一直没被看见，原因在夹具上。** 演示件的两条夹具（`LibrarySkill`、`DiscoverSkill`）把那一句说明叫 **`title`**，产品叫 **`description`**；夹具里每条都只有一个短句（实测 10–40 字，多数十几到三十字）。演示件因此永远画的是"一行副标题"，而产品里那个字段天生是一段话。**这一版把夹具改回产品用的那个名字**，让设计件与检查都对着真实的形状。

## 范围

### 做

| # | 做什么 | 为什么 |
|---|---|---|
| 1 | **列表行的描述压成一行**，超出用省略号；**行宽收到 `--measure-row`（640px）**，字号 13px | 列表是拿来扫名字的，不是读文章的；行高可预期，名字、状态、日期才成列。**行宽是另一半**：改前那一列有 884px，14px 字能排约 **118 个西文字符/行**，是舒适行宽（45–75）的 1.5 倍——截断只解决了"不越界"，没解决"读起来太长" |
| 2 | **全文在悬停时给**（`title` 属性放完整描述），**主路径仍是 skill 页「信息 › 描述」**（那里本来就画 `description` 全文） | 截断而不给出处，是"截断"这类问题里最常被点名的一条（`secondsky/design-review/SKILL.md:214`） |
| 3 | **行高固定**：名字行 22.5px ＋ 间距 4px ＋ 描述 19.5px ＋ 上下内边距 20px ＝ **66–67px**（实测），**与库里有多少条无关**；**≥951px 的窗口里**一屏十条仍然成立（更矮的窗口整页退回文档）。**卡片跟着行收，分页条是卡片的最后一行**（2026-10-31 定）：一页只剩三条时框就是三个行高加一条脚，再往下是页面背景 | 早先行高平分帧里的剩余高度（`flex:1` ＋ `--row-max`），同一行在满页是 67px、只剩三条时是 108px，列表不像列表；固定的行高让每一页看起来是同一张表 |
| 4 | **发现页卡片：描述最多 3 行、适用场景最多 2 行**，超出省略号，同样给悬停全文 | 同一根因；卡片是并排看的，高度必须有界 |
| 5 | **夹具改用产品字段名 `description`**（库与公域两条夹具） | 让设计件对着真实字段设计；名字对齐之后，这一处毛病在演示件上再也藏不住 |
| 6 | **新增可复现状态 `?long=1`**：把前几条换成两条原文（321 字 / 949 字），列表与发现页都支持；进状态表、进检查 | 默认夹具保持短句（它是演示数据）；长描述这一态必须有一条能反复跑的地址，否则修完也证明不了 |
| 7 | **主从预览：点一行，右侧展开这一条的预览**（分类 ＋ 我的标签、描述、适用场景、更新于）；**进 skill 页的入口在标题上**（名字是链接，旁边一枚「往外开」的图标）；**描述与适用场景都超过 8 行才折、给「展开全文」** | 这一页的尽头是「找到并去用它」。现在看完十条里哪条对，要进去、退出来、再进去——预览把同样的四件事提前一格 |
| 8 | **宽屏并排、窄屏浮起**：视口 ≥1300 时列表让出 404px，预览**绝对定位**站进右侧那一列（它从不进流）；<1300 时同一个元素盖在列表上，列表宽度一个像素不动 | 列表最少要留 560px（描述 376 ＋ 日期 172 ＋ 间距 12）才读得下去；预览 380 ＋ 间距 24 合起来 964，列表页的内容栏是 `min(1420, vw − 342)`，断点因此落在 1306，取整到 1300（那一档列表实测 539，比 560 少 21，读得下去）。**公式算的是布局宽度，实测还要再减 15px 视口滚动条**：1440 下页宽 1083、列表 679，1200 下页宽 843；`1024` 的窗口里内容栏 682（含滚动条 667），再让出 404 只剩 278（263），名字都放不下 |
| 9 | **选中态进地址**：`?sel=<命名空间>/<名字>`，刷新与转发都还在（那条不在当前页时，控制台按地址补读一次，见 technical-design §接口 4）；**翻页不关预览**，只有被筛掉或切到「已删除」时才从地址里清掉。**带搜索词时补读要逐页走**：`q` 会被原样带上（换成名字去查是另一个问题），最多读五页；五页之后还没见到那一条就按「说不准」处理——预览关着，地址里的 `sel` 保留，不清掉 | 仓库的规矩：一屏的状态都在地址里。翻页与「看的是哪一条」是两件事，混在一起等于每翻一页都得重新点开 |
| 10 | **可键盘打开**：行可聚焦，`Enter` / 空格开预览；预览收焦点后 `Esc` 关闭 | 「可点的行只有鼠标能到」是门禁里的失败项。代价（名字链接嵌在 `role="button"` 里）写进 design/README.md |
| 11 | **每页几条：10 / 20 / 50，默认 10**（2026-10-31 用户定）。写在地址里（`?per=20`），与筛选、排序、页码同一套规矩；**换档回到第 1 页**；服务端 `/web/library` 只收这三档，其余是 400 | 一屏十条在矮窗口里装不下时，人能自己把一页放大；把「每页」写进地址，是为了这一屏的每个事实都能被转发 |
| 12 | **只有一页时页码与「上一页 / 下一页」不画**（2026-11-01 用户定），只留计数与每页；**不足一页（≤10 条）时整条分页脚不画**，卡片到最后一行收口 | 这条脚的判据是「只放还能动的控件」：一页装下时那一排页码与两个箭头全都动不了（上一页是禁用态、页码只有一个「1」）；≤10 条时连计数都用不上，数量已经写在标题旁边 |

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | **在列表行里加「展开 / 收起」** | 列表里给它就等于每一行多一颗控件，而全文在 skill 页本来就有；悬停提示已经覆盖"想马上看全"的那一半 | 有人反复抱怨"必须点进去才能看全"时 |
| 2 | **给 `description` 加长度上限**（服务器拒收超长） | 它是 `SKILL.md` 的正文，检索要用它；问题在显示层，不该拿数据层去补 | 不做 |
| 3 | **改 CLI 的输出** | `skmr skills list` 有它自己的形状，这一版不动 | 不做 |
| 4 | **改「十条一屏」这个默认**（比如默认每页二十条） | 一行方案下 66px，十条照样成立；要改成别的默认，是另一个产品判断，而「每页几条」已经交给人自己选（§做 #11） | 不做 |
| 5 | **让名字在行里折成多行** | 名字是这一行的身份，折行会把行高撑得不可预期，也会把状态章与档位章挤走。行里的做法是**省略号 ＋ `title` 全文**（长地址那一态），预览标题则**折行、一个字都不截**——身份在那一格必须完整 | 不做 |
| 6 | **改默认夹具的长度** | 默认那 25 条（在用 23 条）是演示数据，短句让别的屏（筛选、计数、空态）读得清；长文字由 `?long=1` 单独给。**一个例外写在夹具里**：`pdf-tools` 默认就是两段都长（949 字的说明 ＋ 341 字的适用场景，预览折行那一态要能点得到） | 不做 |
| 7 | **改「待上线」队列、版本表、标签页里的同名样式** | 它们各自有自己的宽度与用途；截断规则收在 `.skill .skill-title` 里，只作用于列表那一格（skill 页的版本标题也用这个类名，2026-10-31 审计发现后被排除了） | 不做 |
| 8 | **预览里放编辑动作**（改名、上线、删除） | 那会让预览变成第二个操作面板，而每一个动作都有自己的位置（上线在「待上线」、改名在设置、删除带确认） | 不做 |
| 9 | **预览与 skill 页各写一套文案** | 它是同一份信息提前一格，不是第二处真相。两边读同一组字段；防漂的办法只有这个 | 不做 |
| 10 | **覆盖整个视口的抽屉、加遮罩** | 遮罩会让它变成模态，而这一格要支持「挨个看几条」——点另一行直接换。非模态才配得上这个用法 | 不做 |

## 控制台操作与 CLI 对应

这一版新增**一处**控制台操作——分页脚上的「每页几条」（见下，记为已确认的例外）——其余不变，改的是元素怎么画。按 [ADR 0081](../../decisions/0081-every-console-operation-has-a-cli-command.md) 仍然给出映射表：

| 行为 | 在哪 | CLI |
|---|---|---|
| 看我的 skill 列表 | 控制台「我的 skill」 | `skmr skills list` —— 输出形状不变；它的摘要行本来就是 `description`（有 `when_to_use` 时再拼上它，`Card.Summary()`），这一版没有动它 |
| 看一条 skill 的描述 | 控制台 skill 页「信息」 | `skmr skill invoke <名字>` 的头部与 `skill read` —— 不变 |
| 看发现页的卡片 | 控制台「发现」 | `skmr skills search --scope public` —— 输出形状不变 |
| 打开一条 skill 的详情 | 预览标题上的名字与那枚「往外开」图标 | `skmr skill show <命名空间>/<名字>` 读到的同一份信息 —— **预览不新增信息**，它是那一页的提前一格 |

**「每页几条」是这一版新增的一处控制台操作，按 [ADR 0081](../../decisions/0081-every-console-operation-has-a-cli-command.md) 记为已确认的例外：**CLI 的列表一次全出、根本没有分页（`skmr skills list` 打印整份库），给它一个 `--per` 就是一个不改变任何输出的控件——与界面上刚被收掉的那种「动不了的控件」同类。**2026-11-01 由产品负责人确认不带 CLI 命令。** 其余几处仍然没有新操作。

## 验收与指标

| # | 验收标准 | 怎么判定 |
|---|---|---|
| 1 | **一行**：`?page=skills&long=1` 下，每一行 `.skill-title` 的高度 **正好一行**（13px × 1.5 = 19.5px），且 `scrollWidth > clientWidth` 标明有省略 | `console-states --only list` 里的断言——它数**行数**而不是像素，字号改一档不会误报 |
| 2 | **不越界**：同一屏下，每个 `.skill-title` 的底边 **不越过** 它所在 `.skill` 的底边（改前 +22px） | 同一条断言，输出最大越界量，要求 ≤ 0 |
| 3 | **≥951px 的窗口里一屏十条仍然成立，行高不随窗口变**：952px 高的窗口里十条都在、卡片底（分页条）在演示条之上；1200px 高时**行高与 952px 时相同**，卡片跟着行收、多出来的是**页面背景**；窗口矮到 **≤950px** 时整页退回文档、页底留 64px | `console-states --only list` 的「卡片的脚（分页条）没被底部演示条压住」＋ `--only layout` 的「分页条是卡片的最后一行」「矮窗口退回文档，页底留 64px」 |
| 4 | **省略号看得见**：截图里能在被截断的描述末尾看到 `…` | 人看 `skills-long` 那一态——跑 `console-states --only list` 现生成 `design/shots/console/skills-long.png`（图不进版本库） |
| 5 | **悬停给全文**：`.skill-title` 的 `title` 属性等于完整描述 | 断言比对两者文本 |
| 6 | **卡片高度有界**：`?page=discover&long=1` 下，每张卡片的 `.result-title` ≤ 3 行、`.result-when` ≤ 2 行 | `console-states --only discover` 的断言 |
| 7 | **400px 不横滚**：`?page=skills&long=1` 与 `?page=discover&long=1` 在 400px 宽下横向溢出为 0 | 两张窄屏图 + 既有横滚断言 |
| 8 | **这一版新增的十个状态都在状态表里**：`skills-long`、`skills-per50`、`skills-last-page`、`skills-preview`、`-long`、`-tags`、`-address`、`-overlay`、`-narrow`、`discover-long`，能被 `console-states --list` 列出并被 `--only` 选中 | `node design/scripts/console-states.mjs "<产物>" <目录> --list` |
| 9 | **设计稿与产品同一份取值**：三条规则里决定截断的那几项声明（`min-width` / `overflow` / `text-overflow` / `white-space` / `display` / `-webkit-line-clamp`）在两个 `styles.css` 里逐项相同 | 按 [`technical-design.md`](technical-design.md) §接口 6 的命令各抽一遍，`diff` 无输出 |
| 10 | **行宽与字号**：列表行的 `.skill .skill-title` 的 `max-width` 是 `--measure-row`（640px）；实测每行文本不超过 640px，与「更新于」之间至少留 24px；字号 13px，与日期同档 | `console-states --only list` 的三条断言，输出最宽、最窄间距与字号 |
| 11 | **并排**：1440 下预览是 `position:absolute`、宽 380，站在列表右侧留出的那一列里，列表剩 679（页宽 1083 − 404），页面不横滚 | `console-states --only list`（断言 `position` / width / listWidth / overflow） |
| 12 | **浮起**：1200 下预览绝对定位、宽 380，**列表仍占满整页 843**（一个像素没让），页面不横滚 | 同上 |
| 13 | **同一份信息**：预览里的描述与那一行的描述逐字相同 | 同上（比对面板文本与行文本） |
| 14 | **开、换、关**：地址带 `sel` 能直接打开；点另一行换成那一条且地址跟着换；`Esc` 关掉且 `sel` 被清掉；**翻到第 2 页时预览仍开着、`sel` 也还在**（带搜索词时按同一条件逐页找，最多五页；超了只关面板、不清地址）；被选中那一条被搜索筛掉、或切到「已删除」时 `sel` 才被清掉 | `console-states --only list` 四条 ＋ `tests/skills-list.test.tsx` |
| 15 | **长文本在预览里封顶**：949 字的描述与 341 字的适用场景**都折在封顶那个行数（8 行）**、各挂一颗「展开全文」（名字带上是哪一段）；**折着的时候面板自己不出滚动条**；展开后全文都在、面板自己滚，**列表行高不变**；两段都装得下时一颗按钮都不多挂。**适用场景一段尤其不能假设短**——服务端对它没有长度上限 | `console-states --only list` 的六条断言 |
| 16 | **进 skill 页的门在标题上**：预览的标题是名字链接，右边一枚带边界的「往外开」图标，两处都指向 `/skills/<ns>/<name>`；**底栏那一行「打开 skill 页」不再出现** | `console-states --only list` 一条 ＋ `tests/skills-list.test.tsx` 一条 |
