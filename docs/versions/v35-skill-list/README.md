## 目标

三件事，同属「我的 skill」这一页的视觉与交互优化。

**一、长描述不再撑破行。** 真实 skill 的 `description` 是一段话（**本机 55 个真实 skill**：中位 281 字、最长 949 字，口径与复现命令见 [`prd.md`](prd.md) §用户与场景），而列表把它当成一行副标题画：不截断、行高又被钉死，**文字越过行边框压到下一行上**；「发现」页的卡片是同一个根因的另一处。这一版把两处截断、把行宽收到 640px，并让夹具第一次画出真实长度。

**二、列表右边多一格预览。** 点一行，那一格的描述全文、适用场景、版本就在旁边展开，省掉「进去、退出来、再进去」那一趟；宽屏并排、窄屏浮起，断点是从「列表还剩多少」算出来的。

**三、一条 skill 在这两处都能被认出来。** 行首写地址 `命名空间 / 名字`（自己的命名空间不写前缀），行上的章从「来源」改成「档位」；预览里分类与我的标签各占一行、各带自己的名字，长文本封顶后折、标签多了收进「+N」。

细节见 [`prd.md`](prd.md)。

## 验收标准

**列表行仍然是两行 66–67px（≥951px 的窗口里一屏十条；更矮的窗口整页退回文档），长描述压成一行加省略号、行宽 ≤640px；卡片描述 ≤3 行、适用场景 ≤2 行；点一行在右边展开预览，宽屏并排、窄屏浮起且列表宽度不动；400px 不横滚；行首是地址、自己的不写前缀；行上的章是档位；预览里分类与我的标签各一行各带名字。** 完整 22 条见 [`prd.md`](prd.md) §验收与指标。

**成立条件**：验收 1（一行）、2（不越界）、3（一屏十条）、11（并排）、12（浮起时列表不动）——这五条里任何一条不满足，这一版就没有交付。

## 这一版明确不做什么

- **不在列表行里做「展开 / 收起」**——全文在 skill 页本来就有，列表里多一颗控件换不来什么。（预览里那两颗是另一回事：那里不折就没法一屏看完，见 prd §做 #7。）
- **不给 `description` 加长度上限**——问题在显示层，不该拿数据层去补。
- **不动「十条一屏」这个默认**——一行方案下内容恒为 66px（实测），一屏十条照样成立；**每页 10 / 20 / 50 是人自己选的那一档**（2026-10-31 定，见 prd §做 #11），不是新的默认。
- **不把名字折成多行**——名字是这一行的身份，但它现在也**不许把别的章挤出去**：过长时在行里省略（全文在 `title` 与预览里），预览标题则折行不截。见 prd §不做 #5。
- **预览里不放编辑动作**——那会让预览变成第二个操作面板。
- **不给抽屉加遮罩**——遮罩会让它变成模态，而这一格要支持「挨个看几条」。
- **不让预览与 skill 页各写一套文案**——它是同一份信息提前一格，不是第二处真相。

逐条理由见 [`prd.md`](prd.md) §范围 › 不做。

## 记录的性质

**这一版不改「对外能验收的能力边界」**——它改的是元素怎么画。按仓库的流程，界面改动先改设计稿、三份文档可以省；这三份是随这一版留下的记录，不是「必须新开一个版本」的理由。

**接口改动有两处**：卡片多一个 `standing`（档位），只加不改、null 时不发，`source`、筛选、CLI 输出都不动（[`technical-design.md`](technical-design.md) §接口 0）；`/web/library` 多一个 `per`（10 / 20 / 50，其余 400，§接口 0.5）。它不新增任何「能做的事」，所以仍按界面改动那一档走流程。

[`target/`](../../target/) 这一版没有分叉：它让列表兑现它本来就承诺的事（"十条一屏、两行一行"），不改任何边界。
