# v69-ops-service · 把自动导入平切进独立的运营服务

> **最后更新**：2026-11-14
> **状态**：进行中（实现完成，循环审计已收敛；端到端验证未跑）
> **含收费**：否

## 目标

把自动导入从线上服务里搬出去，作为一个独立的 `skillmaster-ops` 服务、用独立的库、单独部署在第二台 ECS 上——**行为不变，只换进程**。细节见 [`prd.md`](prd.md)。

## 验收标准

一句话：导入在 ops 里跑完，server 只收到草稿提交，`/internal` 退役、`/inner` 从公网不可达，用户可见的东西一条都不变。完整验收见 [`prd.md`](prd.md) §验收与指标。

成立条件：**A8（用户可见行为不变）不满足就不算交付**——平切的意义就是不改变产品行为；任何对外可见的差异都说明切错了。

## 这一版明确不做什么

- 不做自动打标与标签候选表——先平切，再在稳定的骨架上做打标。
- 不动在线库的标签表（V53 删列、收表）——它是打标工作的收尾，留给下一版。
- 不做运营界面与 skill 评测——`/admin` 继续拒绝；评测等骨架稳定。

  其余五条范围排除（金标闸、周抽样、搬用户数据、多实例、改词表与对外输出）见 [`prd.md`](prd.md) §不做。

## 与目标态的关系

目标态（[`target/`](../../target/README.md)）描述的是产品形态，没有「后台运营服务」这一层——服务怎么切是工程形态，不是产品能力。

- 保留的部分：收录仍只产生草稿、仍由运营者发布（[ADR 0155](../../decisions/0155-open-source-sync-passes-three-gates.md)、[ADR 0157](../../decisions/0157-sync-is-a-source-neutral-pipeline.md)）。
- 已经分叉的部分：这一版不改变任何产品行为，与目标态的差异清单没有新增条目。

## 影响最大的未决问题

完整列表见 [`technical-design.md`](technical-design.md) §开放问题；按重要性排前三条：

1. 镜像怎么上第二台 ECS：阿里云 ACR，还是 CI 出包后 `docker save`/`scp`/`docker load`；大陆机器连不上 Docker Hub 这一点卡过一次部署。
2. 切换时要不要双跑：当前倾向不双跑，回滚靠把 workflow 与镜像指回去。
3. 来源白名单放部署目录还是镜像：当前倾向部署目录，改来源不重建镜像。
