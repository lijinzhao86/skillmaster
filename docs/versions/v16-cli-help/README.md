# v16-cli-help · 命令行自述：每条命令都接受 --help

> **最后更新**：2026-10-24
> **状态**：进行中——PRD 已过三轮循环审计（2026-10-24 修订）；技术设计与测试方案未开始
> **含收费**：否

## 目标

让 `skillmaster` 的每一条命令都能自己说清怎么用：`skillmaster skill invoke --help` 有答案，分组会列出它的全部动词，敲错一个词会得到建议而不是一屏帮助，退出码能直接告诉脚本「凭据这块要处理」（登录 / 续期 / 检查环境变量）。AWS CLI、GitHub CLI、阿里云 CLI 都是这么引导 agent 的——agent 的第一反应就是 `<命令> --help`，这一条不通，外面的文档再好也到不了它手里。细节见 [`prd.md`](prd.md)。

## 这一版明确不做什么

完整的理由与「什么时候可能做」在 [`prd.md`](prd.md) §不做。

| 不做什么 | 原因 |
|---|---|
| 文档本身 | 那版已回退（`git tag archive/v16-agent-docs`）；先让每条命令能自述 |
| shell 补全 | 给终端里的人用，agent 不按 Tab |
| AI 模式那样的输出契约 | 改动面远超帮助；错误里已经有 `hint` |
| MCP server / agent toolkit | 另一条分发通道，不能替代命令自述 |
| 交互式提示 | agent 不按回车 |
| 改正常调用路径的参数与输出 | 本版只改帮助、用法错误提示、退出码，以及 `auth status` 把服务端拒绝原因原样带出（PRD 做 #5 的既有缺陷）；参数与成功输出不动 |
| 英文帮助 | 产品面向中文用户；标识符照抄代码 |
| 全量命令参考（`gh reference` 那样） | 预算下会成为第二份权威，会漂 |

## 验收标准

21 条，逐条写成「跑什么、看到什么算过」；其中**命令覆盖率 100%**与**新增命令必须带帮助的测试**是成立条件。验收条数与指标以 [`prd.md`](prd.md) 为准。

## 与目标态的关系

[`docs/target/`](../../target/README.md) 讲的是分层付费、权限阶梯与 skill 的形态，不涉及 CLI 的自述能力。本版不是目标态的子集，而是一条**交付纪律**：它决定以后每一次 CLI 能力变更是否自带说明书。它与文档那一版的关系是分工——帮助回答「这条命令怎么用」，文档回答「我该用哪条」。
