# v51-skill-runtime · 产品需求

> **最后更新**：2026-11-08
> **所属版本**：[`README.md`](README.md)
> **调研依据**：[`docs/research/skill-code-execution.md`](../../research/skill-code-execution.md)

## 用户与场景

**谁在用**：两类人——把带 `scripts/` 的 skill 拿来用的 agent 用户；以及把这些 skill 写出来、上传到平台的作者。

**在什么场景下用**：

- 用户让 agent 用某个 skill 做事，这个 skill 的正文写着「运行 `python3 plan_validation.py --input x.csv`」。agent 手里有正文、也常常有一份文件（`get --all` 或同步落过盘），缺的是一个**受支持的入口**：该 `cd` 到哪、相对路径以什么为基准、权限位还在不在，都得自己猜。
- 作者本机上 `chmod +x` 过的脚本、和同级模块互相 import 的脚本，在本地跑得好好的；用户从平台取回后，`./run.sh` 报 `permission denied`，`python x.py` 报 `No such file`。作者不在场，用户不知道找谁。
- 用户第一次 `skmr login` 或 `get --all`，什么都没发生，只看到「失败」——其实是被 agent 的沙箱拦了。

**现在的替代做法**：把 skill 直接放进本地 skills 目录绕过平台；或者 `git clone` 上游仓库；或者手工 `skmr skill get --all`，再自己 `cd` 进去跑。前两条等于不用平台，第三条要懂路径。

**这一版要保证的一句话**：**同一份 skill，在本机能跑，经 SkillMaster 之后，在同一台机器上还能跑。**

## 范围

### 做

| # | 做什么 | 交付形态 |
|---|---|---|
| 1 | **`scripts/` 之下的文件可执行**：位由路径决定，与它从哪来无关（本地打包、同步、控制台新建/编辑都一样）；分发与落盘按这个规则贴回，存量由一次数据迁移对齐 | `ExecutableMode` + `version_file.mode` + 分发 zip 设 mode + CLI 按 mode 落盘 |
| 2 | **`scripts/` 是唯一可执行面**：只在 `scripts/` 下解析要执行的脚本，也只把 `scripts/` 下的文件标成可执行——两件事是同一条规则 | `run` 的路径解析规则（见做 #4）+ 位的派生规则 |
| 3 | **符号链接给可读的错**：上传时不再让作者从「提交的内容有问题」里猜，改说「这里有快捷方式，改成真实文件」 | CLI 的错误文案 |
| 4 | **`skmr run <地址>[@版本] [--cwd <目录>] [--cache-in <目录>] [--no-cache] [--yes] [--json] -- <命令...>`**：落到 `$TMPDIR/skmr/cache/<digest 前 16 位>-r<规则版本>/`、按 digest + 规则版本命中、把命令里的相对路径解析到 `scripts/`、默认 cwd、原样继承调用者环境、首次执行前确认一次 | 新 CLI 命令 |
| 5 | **状态目录分层**：短期（下载缓存）默认 `$TMPDIR`；中期（凭据）全局一份；长期（CLI 本体）在项目外。**读与写分开解析**：写到第一个可写候选，读已有状态则看它在哪个候选里；新增 `SKILLMASTER_HOME` 显式指定 | CLI 状态目录解析 |
| 6 | **凭据**：钥匙串优先，**写失败立刻降级到文件、不弹窗不等审批**；凭据始终全局一份，**不落项目目录** | CLI 凭据存储 |
| 7 | **`skmr doctor`**：一次报清状态目录、凭据落在哪（含钥匙串是否可用）、网络可达、skills 目录、当前是否在沙箱里——能点名就点名（Codex / Cursor / Gemini 各自的标记，Claude Code 靠 `CLAUDECODE`），都没有时只能说「多半在沙箱里」（WorkBuddy） | 新 CLI 命令 |
| 8 | **沙箱的改法可复制**：`doctor` 按四家客户端各给一段配置片段（只打印，不改任何配置） | 输出文案 |

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | 依赖安装、缺环境自动修复、错误归因（把 `ModuleNotFoundError` 翻译成「装什么」） | 本版只保证「本地能跑的不因搬运而失效」，不负责让它从不能跑变能跑 | 缺依赖类报错的量足够大时 |
| 2 | 平台沙箱执行（代码在服务端跑） | [ADR 0008](../../decisions/0008-no-script-execution.md) 的平台侧结论仍然成立，且服务端隔离与资源配额是独立的工程 | 公开市场向非技术用户开放时 |
| 3 | Windows 的可执行位语义 | Windows 没有 `+x` 这个概念，同一条修复在那台机器上不发生 | 不做 |
| 4 | 发布时的环境审计（声明的运行环境与实际依赖、安装说明不符） | 规范里描述环境的只有 `compatibility` 一段散文，没有结构化字段可审；与「不做 1」同源 | 与「不做 1」同一版，先有环境声明格式 |
| 5 | 下载缓存的自动回收 | 本版只给 `--no-cache` 与按 digest 命中；回收涉及策略与用户预期 | 缓存占用成为实际问题时 |
| 6 | 控制台任何改动 | 本版全部能力在 CLI 面，没有需要人看着点的操作 | 不做 |
| 7 | 发布闸对 `scripts/` 之外的可执行脚本给警告 | 平台没有「警告、不拦」这种发布结果——它只有通过与被拒两种；新增一种要在提交与同步两条链路上各开一条通道，而本版的目标是「本地能跑的不会因搬运而失效」 | 作者反馈「脚本放在别处、跑不起来」累积到足够多时 |
| 8 | 把 `operation not permitted` 一类失败统一翻译成「被 X 拦了」 | 客户端拦截发生在系统调用层，错误文本与 errno 由宿主决定，无法稳定识别；`doctor` 给的是事前的自查与改法，这条路更可靠 | 有稳定的识别特征时 |
| 9 | 记一条执行记录（命令、退出码、耗时） | 只写本地状态就没有跨机器价值，上报又超出本版；确认标记已经回答了「这个版本在这台机器上被允许跑过」 | 需要审计「谁跑过什么」时 |

**范围里没有「后续再看」「视情况而定」**；不确定的进 [`technical-design.md`](technical-design.md) §开放问题。

## 验收与指标

### 验收标准

| # | 验收标准 | 怎么判定 | 用例 |
|---|---|---|---|
| 1 | `scripts/` 下的脚本，经 `get --all` 落盘后可执行；`scripts/` 之外的文件不可执行 | 落盘后 `scripts/x.sh` 的 `test -x` 为真、`./x.sh` 退出码 0；根目录的 `notes.txt` 不是 | T1、T1b、T1c |
| 2 | `skmr run <地址> -- python3 <脚本> --args` 与本地同名命令的退出码一致 | 同一份 skill、同一台机器，两边退出码与 stdout 逐字比对 | T2 |
| 3 | 命令里的 `x.py` 能解析到 `scripts/x.py`；找不到时报错列出 `scripts/` 下有什么；同名多个时列候选、不猜一个执行 | 正面：带子目录的脚本可解析；反面：错名与重名都返回非 0，输出含候选清单，且重名时什么都没执行 | T3、T3b |
| 4 | `run` 的默认 cwd 是 `scripts/`，脚本里「打开旁边的文件」可用 | 用例脚本读同目录 `data.csv` 成功；把 cwd 指到 skill 根再跑会失败 | T4 |
| 5 | `run` 原样继承调用者的环境变量 | `PATH` / `PYTHONPATH` / `HTTP_PROXY` 在子进程里与调用者逐字相同 | T5 |
| 6 | **缓存存在时**，同一 digest 第二次 `run` 不重复下载 | 第二次没有档案请求（只确认当前版本）；缓存被系统清理后能重新下载并跑通 | T6 |
| 7 | 状态目录不可写时能降级并继续工作 | 把 `SKILLMASTER_HOME` 指向只读目录，`doctor` 仍成功，并说出是哪个目录被拒、状态改放哪 | T7 |
| 8 | 钥匙串不可用时 `login` 降级到文件且成功 | 模拟钥匙串拒绝，`login` 退出码 0，`doctor` 指出凭据落在文件、并带上降级说明 | T8 |
| 9 | 沙箱内 `doctor` 能识别并给出对应客户端的配置片段 | 在四家客户端里各跑一次；有标记的客户端输出各自的沙箱标记（Codex / Cursor / Claude Code），没有标记的（WorkBuddy）走状态目录回退那句，探测到沙箱（或状态目录回退、或某项失败）时四家都含可复制的配置；`doctor` 报 ok 时不打印片段 | T9 |
| 10 | 被拒的符号链接给的是人话 | 上传含符号链接的包，`submit` 的错误文本含「快捷方式」与「改成真实文件」 | T10 |
| 11 | **断网时，已缓存且本机解析过的地址仍能跑** | 先联网跑通一次，再让服务端不可达：`run` 仍成功并说明用的是上次解析到的版本；**从未**解析过的地址失败，报错含「这一步需要联网」 | T11 |

**成立条件**：**验收 1 与 2 不满足就不算交付**——它们就是「搬运不改变行为」这条承诺本身。

### 指标

| 指标 | 定义 | 怎么量 | 目标 |
|---|---|---|---|
| 从 `get` 到跑起来的手工步骤 | 用户从拿到 skill 到第一条命令跑通，需要人做的步骤数 | 数一下：今天 ≥3（下载、找目录、cd） | ≤1 |
| 首跑失败的归因率 | 首跑失败时，`doctor` 或错误文案能指出原因的占比 | 拿 4 家客户端各复现 2 个场景（共 8 个） | ≥6/8 |

## 依赖与前置

- **外部依赖**：**首次拉取需要能连到 `skillmasterai.com`**。四家客户端默认都不放行（Claude Code 允许域名为空、Codex 断网、Cursor deny；WorkBuddy 5.8.3 的连接层实测放行，但它的可写目录仍需用户加），所以首次拉取要么用户在客户端加域名，要么该命令走沙箱外。**连不上服务端时，已经解析过一次的地址用本机记住的 digest 跑缓存并明说**（验收 11）。
- **内部前提**：三条新 ADR——状态目录分层与读写分开解析（[0164](../../decisions/0164-state-is-tiered-by-what-it-writes.md)）；`skmr run` 的路径解析、cwd 与 digest 记忆（[0165](../../decisions/0165-run-resolves-inside-scripts.md)）；可执行位由路径决定（[0166](../../decisions/0166-the-executable-bit-follows-the-path.md)）。
- **已定的决策**：[ADR 0101](../../decisions/0101-the-cli-never-deletes-files.md)（CLI 不删，因此缓存只能靠 `--no-cache` 或用户自己清）、[ADR 0117](../../decisions/0117-content-is-canonicalized-at-the-door.md)（字节在入口归一化）、[ADR 0129](../../decisions/0129-onboarding-delivers-a-skill-not-a-memory-line.md)（安装交付技能包）。
- **排除了什么前置**：不需要平台侧执行环境，不需要服务端沙箱，不需要改控制台。
