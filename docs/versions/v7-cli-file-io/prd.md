## 用户与场景

**谁在用**：用 CLI 与 agent 维护托管 skill 的人。agent 手里只有终端，没有网页；它读文件、改一个错字、加一个 `references/` 子文件，然后把草稿交给人在浏览器里确认。

**在什么场景下用**：一份草稿已经在服务端（由 `skill submit` 产生）。agent 被要求「把 `SKILL.md` 里那句写错的命令改掉」，或「把 `references/api.md` 里过期的字段删掉」。它需要像在本地目录里一样先看、再改，改完这件事就结束——上线仍然由人在网页上按。

**现在的替代做法是什么**：读有 `skill files` / `skill read`（`read` 带行号与续读提示，是给模型看的渲染，不能进管道）；写只有整包 `skill submit`——**改一个错字就要产生一份新的草稿**，旧的草稿无法更新。这既制造了无意义的版本，也把「这份草稿就是我要改的那一份」这个身份丢掉了（草稿有稳定地址——今天是 `@draft:<ULID>`，本版起是 `@<短码>`——本可以原地改）。本地编辑的那一整套知识（`cat` / `grep` / `head` / `rm` / `mv`）因此完全用不上。

## 范围

### 地址与钉

`namespace/name[@钉]`。钉可以是 `@<短码>`、版本号（`@1.2.3`）、`@sha256:<hex>`，以及过渡期仍接受的旧拼写 `@draft:<26 位 ULID>`。

- **草稿的钉是 `@<短码>`，而短码就是行 id**：8 位 Crockford base32（没有 I / L / O / U），草稿创建时确定、此后不变。**新行用短码，旧行保持 ULID 不迁移**，两种长度都解析；唯一性由主键保证，插入撞上时换码重试（[ADR 0063](../../decisions/0063-a-draft-is-addressed-by-a-short-code.md)）。**网页上它叫「版本码」**，就是这里的短码（旧行显示 26 位 ULID）。
- **地址里不写状态**：同一行从草稿变成线上、已下架或已丢弃，短码不变。状态由查询回答，不由地址回答。**短码只在作者面解析**；消费面仍按版本号或 `sha256:` 摘要寻址——短码是作者面的行标识，不是消费地址。

- **读**：钉可选。写了钉就用它；没写就用 `invoke` 记在本机的钉；再没有就按下面的缺省钉规则解析（与 `invoke` 同一口径，含没有上线版本时的回落）。
- **写：钉按 `invoke` 的记法解析，解析结果必须是草稿。** 顺序与读相同：地址里写了钉就用它；没写就用本机 `invoke` 记下的钉；两者都没有则拒绝。**钉住哪一版就处理哪一版，直到下次 `invoke` 换版本为止**——这是本版要的体验。解析到的钉不是草稿时，按门序拒绝：`browse` / `invoke` 进不了写路由（入口档不够）→ 403；能进写路由的 `write`+ 里，**线上**的行可见 → 409 并说清「写只针对草稿，它现在是 `@X`」；**已下架 / 已丢弃**的行对 `write` 不可见 → 404，`maintain`+ → 409 并说状态。
- **短码是给人和 CLI 的**：网页上的草稿单版页显示完整地址 `namespace/name@<短码>` 并可复制（剪贴板不可用时按设计件的复制失败提示「复制失败，请手动选择」，不谎报成功）；复制到的整串直接粘进 CLI 能解析。
- **草稿没有版本号**：`version` 为 NULL，版本号在上线那一刻才分配；作者给草稿起的名称（`draft_name`）是作者面标签，**不进地址**。

### invoke 的规范

`invoke` 是**唯一会移动本机钉的命令**：它加载正文、把解析到的版本记在本机；后续命令默认作用于它，直到下次 `invoke` 换版本。

| 写法 | 指到哪 | 走哪个面 | 需要 |
|---|---|---|---|
| `invoke <地址>@<短码>` | 一行版本（任何状态，可见性按档位） | 作者面 | 按行状态：草稿 `write`+、线上 `browse`+、已下架/已丢弃 `maintain`+；外加 `skills:read` |
| `invoke <地址>@1.2.3` | 线上的版本 | 消费面 | `invoke` 及以上 + `skills:read` |
| `invoke <地址>@sha256:…` | 无名版本（旧数据） | 消费面 | 同上 |
| `invoke <地址>` | 缺省 | 先消费面；没有上线版本时 `write`+ 回落作者面 | 见下 |

- **缺省钉 = 指针指向的当前版本**，不是 semver 最大的那个。没有上线版本时：**能看见草稿的凭据（`write`+）**回落到**最新一个可见版本**（正常是一份草稿；`maintain`+ 也可能是已丢弃或已下架），并写明「当前没有上线版本，钉在最近可见的版本 `@X`（草稿 / 已丢弃 / 已下架）」；**`browse` 档**得到「这个 skill 还没有上线版本」；`invoke` 档得到与「不存在 / 这一档看不见」同一条 404——消费面刻意不区分这三件事，不声称 skill 存在。
- **短码只在作者面认，可见性按行状态**：线上版本的短码 `browse` 及以上可见（网页上显示并可复制，CLI 也能用它寻址）；草稿的短码要 `write` 及以上；已下架与已丢弃的短码要 `maintain` 及以上。`invoke` 档没有**作者面 API** 入口，拿不到任何短码；网页上他能打开版本栏，但一行版本码都没有；**消费面用短码（或旧 ULID）寻址一律 404**。**消费面的 detail 也不向他返回文件列表**（只给 `metadata` 那一层与单文件路径）。
- **`@sha256:…` 保留**：旧的无名版本只能靠它点名（[ADR 0033](../../decisions/0033-version-names-are-semver.md)）；它不是主推形式，只在无名版本上出现。
- **已下架的版本**：`invoke @1.2.3` 指向它时消费面回 410；作者面要 `maintain` 及以上才看得到——`browse` / `write` 能进作者面但看不到这一版（404），`invoke` 档根本没有作者面 **API** 入口（403）。维护者可用 `cat` / `ls` / `wc`（`grep` 只在草稿上，见做 #5），或用 `version show` / `skill read`；`invoke` 不把 410 改写成作者面的读。
- **显式钉不移动钉**：`cat <地址>@<短码> SKILL.md` 作用于那一版，但本机记下的仍是 `invoke` 选的那一版。新的内容命令（`ls` / `cat` / `wc` / `grep`）每次用钉都在 **stderr** 打印一行「按 X 操作」——它在管道里不污染 stdout；`read` 保持现状（验收 #20 只保 `read`），`files` 作为 `ls` 的别名跟 `ls` 走。
- **写命令在解析出目标之后检查状态**：`state = draft` 才写。**线上**的行对能进写路由的 `write`+ 可见，回 409 并说清「写只针对草稿，它现在是 `@X`」；**已下架 / 已丢弃**的行只对 `maintain`+ 说明状态，`write` 按 404（不泄露状态）；`browse` / `invoke` 在入口就 403。
- **403 / 404 的门序**：⓪ **skill 不存在或对该凭据不可见 → 404**（与 `accessFor` 同一条，先于档位比较；不泄露存在性）；① **入口档**（这条路由要求的最低档）不够 → 403（例如 `invoke` 档打开作者面、`browse` 档调写路由）；② **状态对该档是否可见** → 404（例如 `browse` 读草稿、`write` 读已下架/已丢弃）；③ **归属**——可见但不是我提交的草稿、写它 → 403。⓪的 404 与①的 403 都不依赖目标的状态。
- **命令按面给**：`browse` 及以上的**读**命令走作者面（`ls` / `cat` / `wc` 对任何可读版本都能用，`grep` 只对草稿）；写命令仍只认草稿。`invoke` 档走消费面，只能按路径 `cat` 单个文件（[ADR 0047](../../decisions/0047-permissions-are-a-ladder.md) 的「能取用、不能发现」），没有 `ls` / `wc` / `grep`。skill 下线时消费面回 503；作者面照常（`browse`+ 仍能读、`maintain`+ 仍能维护）。

### 做

| # | 做什么 | 交付形态 |
|---|---|---|
| 1 | **地址与钉**：写按 `invoke` 的钉解析（显式钉优先，其次本机记下的钉），解析结果必须是草稿；读沿用三种钉（另接受旧拼写 `@draft:<ULID>`）；草稿用 `@<短码>`（8 位，旧 ULID 与旧 `draft:` 前缀过渡期兼容；地址不带状态前缀） | CLI 参数校验 + 服务端拒绝 |
| 2 | **`skill ls`**：列出这一版的相对路径、大小、是否二进制（`files` 正名为 `ls`、保留别名；**大小是新输出的列**）；`read` 保持原样（行号、上限、续读提示） | CLI |
| 3 | **`skill cat`**：把文件原始字节写到 stdout；可多个路径；流式，不缓冲、不加行号、不加提示 | CLI + 服务端原样字节 |
| 4 | **`skill wc`**：`-l` / `-w` / `-c`；由服务端计数，不传输字节 | CLI + 服务端 |
| 5 | **`skill grep`**：只作用于**草稿**（作者面）；`-F` / `-i` / `-n` / `-l`，可按路径前缀收窄；输出照本地 `grep`（`-n` 才有行号、`-l` 只列路径）；服务端按版本作用域扫描（[ADR 0062](../../decisions/0062-grep-is-a-scoped-scan-not-an-index.md)），只回命中，命中过多时截断并说明；正则语义与不支持的写法写进帮助；线上版本用 `cat \| grep` | CLI + 服务端 |
| 6 | **`skill write`**：从 stdin 覆盖一个文件；不存在则新增 | CLI + 服务端写接口 |
| 7 | **`skill edit`**：`--old` / `--new` 精确替换；默认要求恰好一处匹配，`--replace-all`（`--all` 为别名）才允许多处；0 处一律拒绝 | CLI + 服务端写接口 |
| 8 | **`skill rm`**：删除一个或多个文件；`SKILL.md` 不能删；不能删到 0 个文件 | CLI + 服务端写接口 |
| 9 | **`skill mv` / `skill cp`**：在同一 skill 内移动/复制路径；目标已存在时拒绝；不搬字节（内容寻址） | CLI + 服务端写接口 |
| 10 | **服务端草稿写接口**：改、增、删、移、复制；每次写重算摘要并更新版本行，**短码不变**；上线后内容冻结 | 服务端 |
| 11 | **权限**：见下一节，读写各一把尺，凭据 scope 另算 | 服务端 |
| 12 | **并发**：写请求带 `If-Match: <digest>`；基线已变则 409，不静默覆盖 | 服务端 |
| 13 | **上限与校验**：沿用 512 文件 / 16 MiB；路径规范、`SKILL.md` 与 frontmatter 校验、二进制检测复用 ingest 的规则 | 服务端 |
| 14 | **管道契约**：stdout 只有内容；stderr 只有错误与非致命的提示（如「按 X 操作」）；退出码照 Linux（`grep` 0/1/2，`cat` 失败 1，`rm` 成功 0）；内容命令（`ls` / `cat` / `wc` / `grep`）不接受 `--json` | CLI |
| 15 | **审计**：每次写留一条（谁、哪个 skill、哪个路径、什么动作） | 服务端 |
| 16 | **网页显示地址与版本码**：草稿单版页显示 `namespace/name@<短码>` 与复制；**版本列表每一行的说明子行右端也显示版本码 + 复制**（`browse`+；调用档不画，复制按钮压在整行链接之上、不截断、位于作者与时间之前）；线上版本页（`state = published`）显示版本号与**版本码**（作者面；调用档不显示版本码）；**草稿页的 `?version=` 用行 id（新行短码、旧行 ULID），线上页仍是版本号或摘要**；复制到的整串可被 CLI 直接解析 | 设计稿 + 网页 |
| 17 | **短码就是行 id**：新行的 `skill_version.id` 是 8 位短码；旧行保持 ULID；解析两种；`@draft:<短码>` 不接受、`@draft:<26 位 ULID>` 过渡期接受；消费面拒绝两种 id 形钉（404）；插入撞码时换码重试（重试在新事务里），`ON CONFLICT` 只点名 `(skill_id, digest)` | 服务端 |
| 18 | **发现钉**：复用已有的 `version list`（`--query` 按名称/版本号/说明/提交人搜、`--status` 筛、`--limit` / `--cursor` 分页），每行第一段就是可复制的完整地址（草稿行是 `@<短码>`）；不新增重复的搜索命令 | CLI |
| 19 | **`invoke` 按钉选面**：短码走作者面（按状态/档位）并记住它；版本号/摘要走消费面并记住它；缺省取当前版本，没有上线版本时 `write`+ 回落作者面的最新可见版本；**写命令只接受行 id 钉**（显式 `@<短码>` 或 invoke 记下的行 id），命名/摘要钉拒绝 | CLI + 服务端 |
| 20 | **调用档不暴露文件结构**：只有 `invoke` 档的凭据对**用户 skill**拿不到文件列表、文件树、文件内容的递归检索（`grep`）——作者面清单 403、消费面 detail 403（现有 `browse` 门）、`/metadata` 无 `files`、CLI `ls` / `wc` / `grep` 403；只能按路径读单个文件。**消费面** `GET /api/v1/skills/{ns}/{name}/versions`（只列线上）与**网页版本栏**（只列可读版本）、网页版本搜索仍在；作者面版本列表 / `version show` 对 `invoke` 仍是 403。公共网关索引是匿名公开面，只暴露公开的 gateway skill，不受这条限制 | 服务端 + CLI + 网页 |

### 谁能做什么

| 动作 | 需要档位（[ADR 0047](../../decisions/0047-permissions-are-a-ladder.md)） | 需要 scope |
|---|---|---|
| 读线上版本的文件与清单 | `browse` 及以上 | `skills:read` |
| 读草稿的文件与清单 | `write` 及以上（同 skill 内所有草稿都可见；写别人的草稿另见下一行） | `skills:read` |
| 写草稿 | `write` 且**提交人是我**，或 `maintain` 及以上 | `skills:write` |
| 读已下架的版本 | `maintain` 及以上 | `skills:read` |
| 读已丢弃的版本 | `maintain` 及以上 | `skills:read` |
| 按路径取单个文件（消费面，不能列目录） | `invoke` 及以上 | `skills:read` |

**scope 是上限，档位是授权**，两把尺都要过。`invoke` 档列不出清单、没有 `ls` / `wc` / `grep`，但能按路径 `cat` 单个文件（[ADR 0047](../../decisions/0047-permissions-are-a-ladder.md)：挡发现，不挡取用）；`browse` 档能读、不能写；`write` 档看得到别人的草稿、改它是 403（看得见，但这一档不够）。

**读与写是两把独立的尺，谁也不蕴含谁。**
- **档位**：`invoke` / `browse` 是**读档**；`write` 是**写自己草稿**的档；`maintain`+ 才能写别人的草稿。
- **scope**：skill 与文件路由里，读路由只认 `skills:read`，写路由只认 `skills:write`（`GET /api/v1/me` 只要已认证，是这条规则的例外；`HEAD` / `OPTIONS` 按读算）。
- **组合**：`invoke` / `browse` 即使带 `skills:write`，五条写命令仍然全部 403（档位不够）；`write` 档缺 `skills:write` 也 403（scope 不够）；`write` 档有 `skills:write` 但缺 `skills:read` 时，**API 层**按路径 `PUT` 仍可（写路由只认 `skills:write`），但读不了——skill 与文件路由上的 `GET` 全部 403（`GET /api/v1/me` 除外），包括 `cat` / `ls` / `grep` / `wc`、`edit` 先做的 GET，以及 CLI 取 `If-Match` 基线摘要的那次 `GET …/files`；所以 **CLI 的写命令在拿不到摘要时做不了**（本机钉里已有一次读留下的 digest 的情况除外）。**这条组合在 API key 签发时不会出现**：签发会把 `skills:read` 补进带了 `skills:write` 的行（[ADR 0039](../../decisions/0039-api-key-defaults-and-their-edges.md) §决定 2）；只注册 `skills:write` 的 OAuth 客户端可以产出这样的令牌。鉴权仍按两条路由各自的 scope 判，不依赖签发时的补齐。

| 档位 | 读 | 写 |
|---|---|---|
| `invoke` | 消费面单文件（线上）；无清单、无草稿、无版本码 | **无**（带 `skills:write` 也 403） |
| `browse` | 线上文件 / 清单 / 计数；无草稿、无已下架/已丢弃 | **无**（带 `skills:write` 也 403） |
| `write` | 线上 + 同 skill 所有草稿；`grep` 草稿；版本码 | **自己提交的**草稿；别人的草稿 403 |
| `maintain` / `admin` / 所有者 | 线上 + 草稿 + 已下架 / 已丢弃 | 任何可见草稿；已上线 409 |

**`invoke` 档的「不能发现」是文件发现的属性，不只是 CLI**：消费面 detail 对它是 403（现有 `browse` 门），`/metadata` 本来就没有 `files`，作者面清单 403，单文件路径仍开放；网页不画文件树。**版本列表（仅可读版本）、版本事实与版本列表搜索保留**——它们不是文件结构。公共网关索引是匿名公开面，只含公开的 gateway skill，其字节本来就由 `/gateway/…` 公开提供，**豁免**。

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | **网页端编辑器** | 本期只交付 CLI 的读写；网页只改版本页与版本列表行的地址/版本码/复制，文件栏仍是只读（它的不可读版本禁用项沿用 v6 现状）。编辑器要画未保存、冲突、二进制等状态，是一整次设计交付 | 下一版 |
| 2 | **新建草稿 / 上传 zip / 网页「新建版本」** | 本期只改**已有**草稿；新草稿仍由 `skill submit` 产生 | 下一版（创建与编辑一起做） |
| 3 | **上线 / 回滚 / 下架 / 重新上架 / 下线 / 删除** | 改变调用者所读的内容，只有浏览器面（[ADR 0031](../../decisions/0031-submitting-and-publishing-are-two-actions.md)、[ADR 0061](../../decisions/0061-what-a-credential-may-do-to-versions.md)） | 不做 |
| 4 | **undo / 文件级历史** | 数据库没有文件级历史；`version_file` 被覆盖就没了。git 那套「改错能回去」本期不提供 | 未定；需要一张草稿修订表 |
| 5 | **三方合并** | 并发写同一文件时只有「谁先谁赢」；冲突即 409，由人/agent 重新读一遍再改 | 不做（先有需求再说） |
| 6 | **元数据（改描述）与改 skill 名** | 各自是独立的一条线（[ADR 0049](../../decisions/0049-an-edited-description-outranks-the-version.md)） | 元数据那一版 |
| 7 | **跨 skill 的 `cp` / `mv`** | 本期只在一个 skill 内操作；跨 skill 是另一种授权问题 | 未定 |
| 8 | **目录对象、符号链接、设备文件** | 技能包是文件集合，没有目录行；提交时已拒绝符号链接 | 不做 |
| 9 | **`tail -f`** | 文件不会变，跟随没有意义 | 不做 |

## 验收与指标

### 验收标准

| # | 验收标准 | 怎么判定 |
|---|---|---|
| 1 | **写只认草稿，跟着 `invoke` 走**：显式 `@<短码>` 能写；`invoke` 钉住草稿后省略钉也能写；钉指向 `@1.2.3` / `@sha256:…` 或没有任何钉时拒绝，错误说清「写只针对草稿」；`invoke` 换到另一份草稿后，写命令跟着换目标 | 五条命令各跑一次；线上版本的字节不变 |
| 2 | **草稿身份稳定**：写完短码不变，摘要（digest）变化，`version show` 的文件数与字节数跟着变 | 写前写后各 `version show` 一次，比对短码、digest 与计数 |
| 3 | **`cat` 原样**：读到的字节与本地同一文件逐字节相同（含 CRLF、无末尾换行、二进制） | `cmp` 本地副本与 `cat` 输出 |
| 4 | **管道等价**：`cat \| head -n 20`、`cat \| tail -n 20`、`cat \| wc -l`、`cat \| grep -n` 的结果与本地同样命令相同；输出里没有行号与提示 | 同一文件在本地与线上各跑一遍，diff 输出 |
| 5 | **流式与提前退出**：拿一个 1 MiB 文件跑 `cat \| head -n 5`，服务端实际发出的字节远小于 1 MiB | 服务端日志或抓包量出传输字节 |
| 6 | **stdout / stderr 分离**：`cat \| wc -l` 只数内容；任何提示与错误都不进 stdout | 对一个不存在的路径跑一次，stdout 为空、stderr 有一句 |
| 7 | **退出码**：`cat` 成功 0、文件不存在 1；`grep` 命中 0、无命中 1、出错 2；`rm` 成功 0 | `echo $?` 逐条断言 |
| 8 | **`wc`**：`-l` / `-w` / `-c` 与本地 `wc` 相同，且不传输文件字节 | 三个数字比对 + 传输量 |
| 9 | **`grep`**：只在草稿上；输出照本地（`-n` 时 `path:line:text`，否则 `path:text`，`-l` 只列路径）；`-F`、`-i`、`-n`、`-l` 与路径前缀都正确；命中过多时有截断说明；对线上版本拒绝并提示用 `cat \| grep` | 固定夹具上逐项断言 |
| 10 | **`write`**：从 stdin 覆盖后，`cat` 读到新内容；不存在则新增；空 stdin 写空文件 | 三个用例各跑一次 |
| 11 | **`edit`**：恰好一处匹配时只改那一处；`--replace-all`（`--all` 为别名）时改所有匹配；0 处一律拒绝，多处未给替换全部也拒绝且不改 | 四种情况各跑一次，比对文件字节 |
| 12 | **`rm`**：删除后清单里消失；`SKILL.md` 拒绝；删到 0 个文件拒绝 | 三条命令 |
| 13 | **`mv` / `cp`**：路径变化、内容不变；目标已存在时拒绝 | 移动前后逐字节比对 |
| 14 | **权限（读不蕴含写）**：`invoke` 列清单 / `ls` / `wc` / `grep` 被拒、按路径 `cat` 仍允许，消费面 detail 对它是 403、`/metadata` 无 `files`；`browse` 写被拒、用线上版本的短码 `invoke` 成功；`write` 改自己草稿成功、改别人草稿 403；`maintain` 与 `admin` 改别人草稿成功。**另外三种组合必须拒绝**：① `invoke` / `browse` 即使带 `skills:write`，五条写命令全部 403（档位不够）；② `write` 档缺 `skills:write`，写 403（scope 不够）；③ `write` 档有 `skills:write` 缺 `skills:read`，读 403、`edit` 的 GET 403（API 层带摘要的 `PUT` 可写；CLI 拿不到摘要，实际写不了） | **五个可授予档**（invoke / browse / write / maintain / admin）各一把，外加一把所有者账号的凭据（owner 不可授予，不在梯子上）；再加三把交叉 scope 的凭据（读档 + `skills:write`、写档只有 `skills:read`、写档有 `skills:write` 缺 `skills:read`） |
| 15 | **并发**：两个会话从同一摘要写同一路径，第二个 409，内容保持先到的那一份 | 两个 CLI 并发写，检查 409 与最终字节 |
| 16 | **上限与校验**：超过 512 文件或 16 MiB 被拒且不写入；`..`、绝对路径、反斜杠被拒；写坏的 `SKILL.md`（缺 frontmatter / `name` 不符）被拒 | 逐个构造 |
| 17 | **状态语义**：已下架版本在消费面 `@版本号` 读 410、作者面 `maintain`+ 可读；skill 下线时消费面 503、作者面照常；**skill 不存在或对该凭据不可见**是 404（第一道门，与 `accessFor` 同一条）；**状态对该档不可见**（`browse` 读草稿、`write` 读已下架/已丢弃）是 404；**入口档不够**（`invoke` 打开作者面、`browse` 调写路由）是 403——这两类 403 不依赖目标状态；同一 skill 内可见的别人的草稿是 403（写），不是 404 | 逐档各一次 |
| 18 | **不改变消费面**：任何写之后，当前线上版本与 `@版本号` 读到的字节不变 | 写前写后各读一次线上版本 |
| 19 | **审计**：每次写留一条记录 | 读审计表 |
| 20 | **`read` 不变**：仍带行号、上限与续读提示；`cat` 与它并存 | 两个命令各跑一次 |
| 21 | **内容命令不接受 `--json`**：帮助里没有，解析时明确拒绝 | 跑一次 `cat --json` |
| 22 | **网页与终端对得上**：草稿单版页显示完整地址与复制，**地址栏的 `?version=` 是行 id（短码 / 旧 ULID）**；复制到的整串粘进 `skill cat` / `skill write` 能解析；线上版本页（`state = published`）的**地址**是版本号或摘要，不是行 id（`?version=` 仍是版本号或摘要）；作者面另有「版本码」一栏（行 id）；**版本列表每一行的说明子行右端也有版本码 + 复制**（`browse`+，位于作者与时间之前、不截断、复制不触发整行导航）；调用档看不到任何版本码。**旧 v6 `?version=draft:<ULID>` 不兼容**（设计稿只认裸 id），落「没有这一版」 | 打开草稿页复制，粘进 CLI 执行；再打开线上页与版本列表对照；旧 `draft:` 链接落「没有这一版」 |
| 23 | **短码就是行 id**：新行的钉匹配 `^[0-9A-HJKMNP-TV-Z]{8}$`；旧草稿的 `@draft:<26 位 ULID>` 仍能解析（规范输出是不带前缀的 ULID）；`@draft:<短码>` 拒绝；消费面用短码或旧 ULID 寻址都 404；插入撞码时重试（新事务），不产生重复行 | 新建草稿看钉；旧夹具解析；消费面各取一次；人为撞码一次 |
| 24 | **发现钉**：`version list --query <名称或版本号>` 返回命中行，第一段是可复制的完整地址；`--status draft` 的草稿行第一段是 `@<短码>`，复制后 `skill cat` 能解析；`--limit` / `--cursor` 能翻页 | 造三个版本，按名称与版本号各搜一次，再翻一页 |
| 25 | **invoke 三种钉**：`invoke <地址>@<短码>` 加载草稿正文并记住它，随后的 `cat` / `write` 跟着这一版；`invoke <地址>@1.2.3` 加载线上版本，随后的写命令被拒并说明「写只针对草稿」；`browse` 用线上版本的短码同样能 `invoke` 并读到内容，`invoke` 档用短码被拒（作者面 **403**：这一档能看见 skill，但低于 `browse`）；再 `invoke` 回草稿后写命令恢复 | 三串命令各跑一遍，检查目标与拒绝理由 |
| 26 | **状态变了，地址不变**：钉住的行被上线后，读命令仍按短码读到那一版（作者面），`write`+ 写命令 409，消息以「写只针对草稿」开头并指出它现在是 `@X`；被丢弃后，`maintain`+ 写 409 并说清「已丢弃」，`write` 写 404（不泄露状态），`browse` / `invoke` 写 403（入口档不够），读同样按档位；两种情况都不会静默改读另一版 | 上线/丢弃各做一次，再跑 `cat` 与 `write` |
| 27 | **缺省钉**：`invoke <地址>` 在已上线时钉当前版本；没有上线版本时，`write`+ 凭据回落到最新可见版本并在输出里写明；`browse` 档得到「这个 skill 还没有上线版本」，`invoke` 档得到与不存在/不可见相同的 404，都不会静默钉到别处；**读命令（`cat` / `ls` / `wc` / `grep`）的缺省钉与 `invoke` 同一口径** | 三种状态各跑一次，再各跑一次不带钉的读命令 |
| 28 | **`ls` 与多路径 `cat`**：`ls` 列出相对路径、大小、是否二进制；`skill files` 别名仍可用；`cat a b` 按参数顺序输出原始字节 | 三条命令各跑一次，与本地输出比对 |
| 29 | **撞摘要**：写后的内容与同 skill **另一版**完全相同（例如把草稿改回某一版的原文）→ 409 `content_already_exists`，detail 指出已有那一版的 `pin` / `state`；草稿不被删除、合并或修改；CLI 说清「内容已存在，在 @X」。**写相同内容（digest 未变）是 no-op，不 409** | 构造两份同内容版本，再写回原文；另写一次相同内容确认 no-op |
| 30 | **写 `SKILL.md` 的元数据**：根 `SKILL.md` 的 frontmatter 改动后，该版本的 `title` / `description` / `frontmatter` 跟着更新；**skill 行的元数据不动**；上线时按现有规则取该版本的值；缺 frontmatter / `name` 不符仍被拒 | 改 title/description 后写，再读版本事实与 skill 行 |
| 31 | **调用档不暴露文件结构**：只有 `invoke` 档的凭据对**用户 skill**拿不到文件列表、文件树或文件内容递归检索——作者面清单 403、消费面 detail 403（现有 `browse` 门）、`/metadata` 无 `files`、CLI `ls` / `wc` / `grep` 403；只能按路径读单个文件。**消费面** `GET /api/v1/skills/{ns}/{name}/versions`（只列线上）与**网页版本栏**、网页版本搜索保留；作者面版本列表 / `version show` 仍是 403。公共网关索引（匿名、只含公开 gateway skill）豁免 | 用 `invoke` 凭据逐个接口取一次：作者面 403、消费面 detail 403、`/metadata` 无 files、CLI 403；消费面版本列表 200、网页版本栏可开；单文件 200；网关索引只含公开 gateway skill |

**成立条件**：#1（写只认草稿）、#14（权限）与 #31（调用档不暴露结构）。这三条不满足就不算交付——它们守的是「改错对象」「改不该改的」与「不把目录树交给调用方」。

### 指标

| 指标 | 定义 | 怎么量 | 目标 |
|---|---|---|---|
| 单次写延迟 | 一次 `write` 从发出到返回的墙钟时间，本机 CLI + 本地数据库，文件 ≤64 KiB | 连续 20 次取 P95 | < 300 ms |
| `cat \| head` 的传输量 | 1 MiB 文件跑 `cat \| head -n 5`，服务端实际写出的响应字节 | 服务端访问日志或抓包 | < 100 KiB |

## 依赖与前置

- **外部依赖**：无（不新增服务、不新增扩展）。
- **内部前提**：
  - [ADR 0062](../../decisions/0062-grep-is-a-scoped-scan-not-an-index.md)：grep 在服务端按版本作用域扫描，不建索引；它成立的前提是 512 文件 / 16 MiB 的上限。
  - [ADR 0001](../../decisions/0001-server-authoritative.md) / [ADR 0035](../../decisions/0035-the-pin-lives-on-the-client-machine.md)：本地不落**可复用的**内容副本（缓存）；`read` 对二进制写出的临时文件不属于缓存。所以不做客户端内容缓存；`cat` 的省流量只能靠流式与提前退出。
  - [ADR 0055](../../decisions/0055-drafts-have-a-required-name.md)：草稿的稳定身份是行 id（v6 拼作 `draft:<ULID>`），名称是作者面标签、不进地址；[ADR 0063](../../decisions/0063-a-draft-is-addressed-by-a-short-code.md) 修订了它的拼写——新行 8 位短码，旧行仍是 ULID，两种都解析。
  - [ADR 0061](../../decisions/0061-what-a-credential-may-do-to-versions.md)：凭据能对版本做什么；本版把「内容编辑」加进「不改变调用者所读」的那一栏，沿用改名/改说明的判据。
  - [ADR 0047](../../decisions/0047-permissions-are-a-ladder.md) / [ADR 0051](../../decisions/0051-the-author-plane-serves-by-tier.md)：档位与作者面按档位分。
  - **v6 的一条不变量要改写**：v6 已经是「内容不可变，状态/名称/说明可变」；本版把「内容」也放开给草稿——「**上线后的内容只插不改；草稿的 `digest`、`file_count`、`total_bytes` 随每次写更新**」。这一条要落成新 ADR（或回写 v6 的数据模型），不能只在代码里发生。
- **排除了什么前置**：不需要新表（undo 不做）；不需要对象存储；不需要内容索引（ADR 0062）。**网页要改**：版本页的地址、版本码与复制（以及草稿页的 `?version=`），设计稿已在本版交付（见做 #16），不是「本期只 CLI」；文件栏与它的禁用项沿用现状。
