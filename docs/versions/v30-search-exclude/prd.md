## 用户与场景

**谁在用**：用 `skmr` 找 skill 的 agent，以及替它们配置规则的人。

**在什么场景下用**：一次搜索没命中时，规则段要求「换说法再查一次」。第二次搜索通常返回与第一次高度重叠的结果，每条都带着 2–3 行描述——同一段文字在上下文里出现第二次、第三次。

**现在的替代做法是什么**：

| 做法 | 差在哪 |
|---|---|
| 不管它，让内容重复进入上下文 | 今天的状态。实测有会话里同一个 skill 出现 4 次 |
| agent 自己从上一轮输出里挑出地址、手动跳过 | CLI 没有这个能力；agent 只能整套重读，无法「只加载新的」 |
| 把 `--limit` 调小 | 只是少看几条，不解决重复；而且会漏掉真正新的结果 |

**实测口径**（本机 Claude Code 会话记录里 `skills search` 的实际返回地址，2026-10-29 抽两个会话）：`b8f8d834` 会话 9 次调用、21 个不同 skill、13 个地址重复出现（`skillmaster/startup` 与 `lijinzhao/skillmaster` 各 4 次）；`7b34fb9b` 会话 4 次调用、23 个不同地址、7 个重复。

## 范围

### 做

| # | 做什么 | 交付形态 |
|---|---|---|
| 1 | **`skills search --exclude <地址[,地址…]>`**：可重复、可逗号分隔；这些地址不出现在本次结果里 | CLI + 服务端 |
| 2 | **服务端在候选集 / 排序 / 分页之前施加排除**，语义路径与字面路径都是 | 服务端 |
| 3 | **结果非空且没带 `--exclude` 时，输出首行给一句提示**，教下次换说法重查时带上它 | CLI |
| 4 | **结果为空且带了 `--exclude` 时**，说明两种可能（本来就没有匹配 / 都排除了），不复用「没有匹配的 skill」 | CLI |
| 5 | **帮助与声明同步**：Usage / Flags / Output / Examples | CLI |

**参数边界**：地址写 `<命名空间>/<名字>`，不接受文件路径、不接受 `@版本`；最多 50 个（按去重后的个数）；空白项忽略；地址合法但不存在时**静默忽略**（过滤器选中空集，不是错误）。

**输出契约的取舍**：提示放在 stdout 首行，意味着 v13 §3 的「卡片第一行是地址、卡片之间不混其它内容」在 `skills search` 上被本版取代（`skills list` 不变）。理由是与截断的对抗——尾部提示在主流 harness 上会被截掉；代价由 [ADR 0114](../../decisions/0114-search-exclusion-is-caller-supplied-and-applied-before-ranking.md) 记录。

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | 不改 `skills list` | 本版只收 `search`；list 的重复问题是一次性列全库，形态不同 | v31 评估 |
| 2 | 不做本机「给过」记录，也不让服务端记住「最近返回过什么」 | 跨会话会撒谎（另一个 agent 没见过「上面」）；服务端记忆会让同一条查询不再幂等 | 不做 |
| 3 | 不改 `block.md` 规则段 | 规则段随二进制发布，v27 起 CLI 不再更新用户文件；老用户拿不到，且它是用户自己的指令文件 | 不做 |
| 4 | 不在响应里回报「排除了几条」 | 空结果话术已如实覆盖两种情况；计数对调用方没有可行动价值 | 未定 |
| 5 | 不让排除参与排序权重（「已看过」降权） | 「排除」与「降权」是两个产品问题；本版只做前者 | 未定 |
| 6 | 不给 `skill invoke` / `read` / `cat` 加任何前置提示 | 内容类命令的 stdout 是文件字节或指令正文，前置提示会破坏字节契约 | 不做 |
| 7 | 不为排除新增控制台界面 | 控制台没有「反复搜索」这个问题，CLI 是唯一入口 | 不做 |

## 控制台操作与 CLI 对应

**本版没有新增或改动的控制台操作**，因此没有映射表条目。这条不是例外，而是本版范围里没有控制台一侧。

## 验收与指标

### 验收标准

| # | 验收标准 | 怎么判定 |
|---|---|---|
| A1 | 排除生效：`skmr skills search "<q>" --exclude a/b` 的结果里没有 `a/b`；同一查询不带 `--exclude` 时 `a/b` 在结果里 | 前置：`a/b` 会命中该查询。对比两次输出的地址集合 |
| A2 | 两种写法等价：`--exclude a/b --exclude c/d` 与 `--exclude a/b,c/d` 得到同一结果 | 两次输出逐字节相同 |
| A3 | 格式非法 → 用法错误：三段地址、缺 `/`、带 `@版本` 都退出 2，并说明地址形状 | stderr 含「exclude 要写」与 `用法见：skmr skills search --help` |
| A4 | 不存在 / 看不见的地址 → 静默忽略 | 不报错、不把它写进结果；退出码 0 |
| A5 | 语义路径不缩水（填页）：排除前两条后，若候选足够，仍返回 `--limit` 条 | 结果条数 = `--limit` |
| A6 | 字面路径不缩水且分页正确：`--semantic=false` + 排除前两条 + `--limit 5`，仍返回 5 条；`next_cursor` 只说明「还有更多」，不因排除提前消失 | 结果条数与「还有更多结果」行 |
| A7 | 前置提示：默认语义、有结果、未带 `--exclude` 时，**首行**是提示，地址在提示（以及可能出现的 `--limit` 夹取说明）之后开始；带了 `--exclude` 或结果为空时没有这一行 | 看 stdout 第一行；再跑一次 `--limit 100` 确认提示在第 1 行、夹取说明在第 2 行、地址从第 3 行开始 |
| A8 | 空结果 + 排除：不带 `--exclude` 时文案不变；带了时另补一句「也可能是 `--exclude` 排掉的」并给出去掉它的下一步（不把原因说死，服务端不回报是否由排除造成），且不出现「没有匹配的 skill」 | 对比两种情况的首行；语义空结果带 note 时也要出现这句 |
| A9 | 帮助：`skmr skills search --help` 的 Usage、参数表、输出、例子都包含 `--exclude` | 读帮助页 |
| A10 | 上限：超过 50 个地址，CLI 退出 2；直接打 API 同样被拒（400） | 命令行与 `curl` 各一次 |

**成立条件**：A1、A5、A7 三条不满足，本版不算交付——它们分别是「排除有效」「服务端做才有意义」「提示能看见」。

### 指标

| 指标 | 定义 | 怎么量 | 目标 |
|---|---|---|---|
| 重复地址占比 | 同一会话内连续 `skills search` 的返回地址中，非首次出现的占比 | 从会话记录里抽 `skills search` 的实际返回地址（口径同 §用户与场景） | 首版不设硬目标；观察带 `--exclude` 的调用是否下降 |

## 依赖与前置

- **决策**：[ADR 0114](../../decisions/0114-search-exclusion-is-caller-supplied-and-applied-before-ranking.md)（本版新增）——排除由调用方提供、在服务端排序之前施加。
- **外部依赖**：无。不依赖检索模型、控制台或平台技能。
- **内部前提**：服务端与 CLI 同版发布——API 参数与 CLI flag 必须一起上线，否则 CLI 会发出服务端不认识的参数。
- **排除了什么前置**：不需要给检索模块加排除接口——候选集已经是 M12 交出来的 id 列表，排除在这一层做即可。
