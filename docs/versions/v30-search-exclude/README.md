## 目标

`skills search` 新增 `--exclude`：调用方把上一轮已经看过的地址带上，服务端在候选集、排序与分页之前把它们去掉；结果非空且没带这个 flag 时，首行给一句提示教它下次这么用。细节见 [`prd.md`](prd.md)。

## 验收标准

排除生效、语义与字面两条路径都不缩水、首行提示能看见。完整验收见 [`prd.md`](prd.md) §验收与指标。

**成立条件**：A1（排除生效）、A5（语义路径不缩水）、A7（前置提示）——这三条不满足，本版不算交付。

## 这一版明确不做什么

摘要三条最要紧的；**完整范围与每条的理由在 [`prd.md`](prd.md) §范围**。

- 不改 `skills list` —— list 的重复问题形态不同，下一版单独评估
- 不做本机 / 服务端「给过」记忆 —— 跨会话会撒谎，且会让搜索不再幂等
- 不改 `block.md` 规则段 —— 随二进制发布、老用户拿不到，且那是用户自己的文件

## 与目标态的关系

[`target/`](../../target/) 描述的是「agent 按需取用、不关心库有多大」的形态。这一版补的是**取用的入口**：让反复搜索不再把同一份说明搬进上下文。

- 保留的部分：检索在服务端（[0006](../../decisions/0006-search-server-side.md)）、服务端权威；排除是请求谓词，不产生新状态。
- 已经分叉的部分：无新增分叉。

## 影响最大的未决问题

完整列表见 [`technical-design.md`](technical-design.md) §开放问题。按重要性排前三条：

1. **「已看过」是排除还是降权** —— 降权会改变排序语义，本版只做排除。
2. **`skills list` 是否也要** —— 当前倾向不要；它的重复问题不是同一形态。
3. **要不要回报排除计数** —— 当前倾向不回报；空结果话术已如实覆盖两种情况。
