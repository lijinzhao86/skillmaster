# v40-code-writing · 需求

> **最后更新**：2026-11-02

## 用户与场景

**用户**：改这个仓库的人，以及被派来审这个仓库的 agent。

**场景**：每交付一版，审计要通读 `docs/` 与代码注释。现状是三份文本互相复述——`docs/` 有 345 篇、36,922 行，其中版本文件夹占 74%；服务端 Java 里 37% 是注释，CLI Go 里 23%。同一个上限在 27 个文件里出现，同一张模块表有三处声称权威。

**现在的替代做法**：每次审计从头读一遍，人肉比对文档与代码。结果是审计轮次降不下来（v39 跑了 10+ 轮，第 3 轮之后几乎全是文档与文案）。

**要解决的不是"写得不好"，是"同一事实有多个家"**——改的时候只改了两处，第三处第二天开始撒谎，而它没有检查器。

## 范围

### 做

| # | 做什么 | 为什么现在做 |
|---|---|---|
| 1 | `docs/architecture/` 改名为 `docs/current/`，成为唯一的现状权威 | 现在"现状"散在各版 TD 里，39 个 TD 只有 7 个链接到该轴 |
| 2 | 三个索引改为生成：`docs/README.md`、`docs/versions/README.md`、`docs/decisions/README.md` | 手写索引已漂 36 个版本：写着 44 条 ADR（实际 133）、只列 v1–v3（实际 39） |
| 3 | 修 ADR 索引与文件头的 12 处不一致、补 2 条缺失的状态行 | 同一事实两个家的最小样本，先清零 |
| 4 | v1–v39 标记为「归档」、只读；新版本改为写 delta | 冻结比改写便宜；改写会把历史变成今天的理解 |
| 5 | 从代码生成现状事实：模块表、上限、错误码、表结构、命令语法、配置项 | 这些能派生，不该手抄 |
| 6 | 按 `code-writing` 清注释：只留不变量、陷阱、指针 | 注释是最大的第三份副本：877 处 ADR 编号、815 处版本号 |
| 7 | 三个 skill 重新分工：在哪 / 怎么写 / 什么时候 | 现在 `docs-architecture` 已经 542 行，归属与写法混在一起 |
| 8 | 建反向索引与引用检查：`scripts/docs/impact.py` | 审计一直靠全仓 grep；关联项应当一次查出来，而不是每次重搜 |
| 9 | 再补三份生成的现状文档：`schema.md`、`cli.md`、`config.md` | 表结构、命令语法、配置项原本只存在于迁移/代码/yml 里，`current/` 不是完整的事实源 |
| 10 | 写 [ADR 0134](../../decisions/0134-an-audit-has-a-scope.md) 锁定审计的四个范围 | 没有范围，审计就会把冻结的历史反复读；这是本版要消灭循环审计的那一半 |

### 不做

| 不做 | 理由 | 什么时候可能做 |
|---|---|---|
| 重写 v1–v39 的正文 | 27,211 行；改写会让"当时怎么想"变成"今天怎么想"，与 ADR 不修改正文的理由相同 | 不做，历史就该是历史 |
| 全量清理 20,323 行注释 | 自动改注释无法判定语义；一次全量重写本身就是新的漂移源 | 增量：动到哪个文件清哪个；每版做一小批 |
| 把 `target/` 并入 `current/` | 一个是远期形态、一个是当前形态，时间点不同 | 等 `target/` 的差异清单清零后再议 |
| 改任何产品行为、接口、表结构、前端 | 本版要证明文本能独立重构 | 不做 |
| 上文档站点（MkDocs / Docusaurus） | 渲染解决不了唯一性，只多一份产物 | 不做 |

**范围里没有「后续再看」「视情况而定」**——不确定的进 [`technical-design.md`](technical-design.md) §开放问题，并且都是能回答的问法。

## 控制台操作与 CLI 对应

**本版没有任何控制台操作**，因此没有需要对应的 CLI 命令。生成与校验走仓库脚本：

| 动作 | 命令 |
|---|---|
| 重新生成索引与派生文档 | `python3 scripts/docs/generate.py` |
| 校验文档 | `python3 .claude/skills/docs-architecture/scripts/check_docs.py` |
| 校验生成物与源一致 | `python3 scripts/docs/generate.py --check` |

## 验收与指标

每条都能回答"过没过"：

| # | 验收标准 | 怎么判定 |
|---|---|---|
| A1 | `docs/architecture/` 不存在，`docs/current/` 存在；没有链接指向旧路径 | `check_docs.py` 退出 0；`grep -rnE '\]\([^)]*/architecture/' --include='*.md' .` 为空（`docs-architecture` 这个 skill 名不算） |
| A2 | 三个索引由脚本生成 | 删掉三份文件后跑 `generate.py`，内容与提交前逐字节一致 |
| A3 | ADR 索引与文件头状态零不一致 | 生成器自检：不一致数 = 0 |
| A4 | v1–v39 全部标为「归档」，索引列出 40 个版本 | `grep -rl '归档' docs/versions/v*/README.md \| grep -v v40 \| wc -l` = 39；注意标记词是「归档」，不是「已归档」 |
| A5 | 模块表、表结构、上限、错误码、CLI 语法、配置项由源生成 | `docs/current/` 的六份生成物都带生成头；改动源之后重跑，内容跟着变 |
| A6 | 三个 skill 无重复规则 | 人工逐条对：每条规则只在一个 skill 里定义，另两处只链接 |
| A7 | 源码注释里不再有重复的全局数值与历史叙述 | `check_comments.py --all` 输出「共 0 处」（该命令恒退出 0，判据是 stdout）；范围是服务端 `src/main`、CLI、控制台与站点的源码注释 |
| A8 | 引用都能解析 | `impact.py --check` 退出 0：活文档与代码注释里的 `Class.MEMBER`、`ADR NNNN`、`vNN`、测试类名、自有配置键（`skillmaster.*`）全部指得到 |
| A9 | 代码零改动 | `git diff -U0` 中被改的 `.java` / `.go` 行，全部是注释行（`//`、`/*`、`*`） |

**指标**：

- **短期**：A1–A9 全过。
- **长期**：下一个版本的审计轮次 ≤ 2。本版只负责建立可测的判据，不承诺立刻达到。

**口径**：注释计数用"匹配到的行数"，不是"问题数"——同一行可能同时命中两条规则，统计时去重。
