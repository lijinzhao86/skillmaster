**这一版为什么是一个版本文件夹，而不是一条迭代记录。** 它不改任何「对外可验收的能力边界」——按 [`dev-sop`](../../../.claude/skills/dev-sop/SKILL.md) §六 的判据，它甚至不需要走全流程。但它需要三件版本文件夹才能装下的东西：一份**范围**（做什么、明确不做什么）、一份**分期**（39 个文件按什么顺序搬、每期怎么验收）、一份**测试方案**（怎么证明「什么都没变」）。文档体系里只有这一个格子放得下这三样，所以用它。

## 目标

把 `skillmaster-web/` 的运行时从 Vue 3 换成 React 19，**视觉、交互、接口、页面地址、界面文案全部不变**。一句话：换引擎，不换车。决定见 [ADR 0075](../../decisions/0075-the-browser-client-is-react.md)。

## 验收标准

**「一切不变」是可判定的**：`styles.css` 与 `design/` 零 diff、同一页面的 DOM 骨架逐字一致、24 个测试文件 1:1 搬家且断言不减少、`qa/role-matrix` **134 passed / 4 skipped**（共 138 个用例，4 条 skip 是固定的「allowed 那侧跑在 scratch skill 上」）原样通过。完整验收见 [`prd.md`](prd.md) §验收与指标。

**成立条件**：**prd 的 #1 与 #2 是「不满足就不算交付」的那两条**——#1（本版内 `design/` 与 `src/styles.css` 零 diff）是前置，#2（每个页面的 DOM 骨架逐字一致）是它的落地形式。为什么这两条能代表视觉，推导见 [ADR 0075](../../decisions/0075-the-browser-client-is-react.md) §后果，本文不复述。**边界要说清**：它约束的是本版；如果期间发生一次真实的设计交付，本版应当停下来重新界定基线，而不是把设计改动判成迁移漂移。

## 这一版明确不做什么

摘要三条最要紧的；**完整范围与每条的理由在 [`prd.md`](prd.md) §范围**。

- 不引组件库、不引 UI 原语、不引路由、不引状态库 —— 迁移的验收是「不变」，同时改架构会让失败无法归因（[ADR 0075](../../decisions/0075-the-browser-client-is-react.md) §理由）
- 不改任何界面 —— 设计稿**已经**覆盖了若干窄屏 / 平板条款（控制台断点 1024 / 900 / 720 / 640，另有 400px 窄屏状态；首页 1000 / 720），但没有覆盖全部页面与完整手机形态；补齐它是设计任务，不在本版
- 不动服务端与 CLI —— 接口、路由、文案一个字都不改

## 与目标态的关系

[`target/`](../../target/) 描述的是**完整形态**。这一版不朝目标态前进，也不与它分叉：它换的是实现，目标态说的「有哪些屏、能做什么」一个字都不变。
