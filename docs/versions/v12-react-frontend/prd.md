## 用户与场景

**谁在用**：这一版有两类使用者，要分开说，否则验收标准会写错。

- **今天的用户**：用控制台管理 skill 的人、用 CLI 登录的人、第三方 agent 背后的开发者。**他们要察觉不到任何变化**。他们不是这一版的获益者，而是这一版要保护的对照组。
- **这一版的真实受益者**：接下来写下一批页面的人。每一次新增一屏，今天都要手写行为语义——下拉的 `role="listbox"`、上下键、Esc、焦点返回；对话框的焦点陷阱；命令面板。这些不是业务逻辑，是每个控件都要重付一次的租金。

**在什么场景下用**：下一个人要加一屏带下拉或对话框的设置页时。他不会去想「焦点返回该给谁」——他会照着旁边那个手写的 `MenuSelect` 抄一遍，或者抄漏一条。ADR 0057 已经证明抄漏的代价：它花了整整一篇 ADR 去逐条规定键盘与 ARIA 行为。

**现在的替代做法是什么**：手写，或者抄上一个手写的。1,665 行、35 个代码文件里散着 `aria-*` / `keydown` / `.focus()`。这套办法能用，但它把「可访问性正确」压在每个人的记性上——而 ADR 0057 的原话是「键盘与可访问性不是换掉原生控件的代价，而是它的验收项」。

**所以这一版做什么**：把运行时换成 React。**不是为了今天更好，是为了下一批页面有一个更成熟的池子可用**——而换的过程必须让今天的用户什么都察觉不到。

## 范围

### 做

| # | 做什么 | 交付形态 |
|---|---|---|
| 1 | 运行时换成 React 19，构建仍是 Vite，语言仍是 TypeScript | `skillmaster-web/` 内，服务端零改动 |
| 2 | 39 个 `.vue`（12,237 行）逐页改写成 `.tsx`，DOM 骨架逐字保留 | 同上 |
| 3 | 24 个测试文件全部保留：**17 个挂载型**（9,360 行）从 `@vue/test-utils` 搬到 `@testing-library/react` 并 1:1 保留断言；**5 个原样搬回**（`client`/`errors`/`time`/`validation`/`markdown`，722 行）；**2 个随依赖重写**（`captcha` 随 `useCaptcha`、`session` 随 `store.ts`） | `skillmaster-web/tests/` |
| 4 | 类型检查从 `vue-tsc` 换成 `tsc --noEmit` | `skillmaster-web/package.json` 的 `scripts.type-check`（CI 的 `web.yml` 只调 `npm run type-check` / `test` / `build` 三个脚本，换的是脚本实现，**workflow 不需要改**） |
| 5 | 建一座「对照台」：同一屏、同一份数据，分别在 Vue 与 React 下渲染，逐字比对 DOM 骨架 | `qa/role-matrix/` 新增一层 |
| 6 | 切换入口，删除 Vue 实现与 `vue` / `@vitejs/plugin-vue` / `@vue/test-utils` / `vue-tsc` 依赖 | `skillmaster-web/` |

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | 不引路由库（react-router / TanStack Router） | ADR 0015 当初否掉客户端路由的理由今天仍然成立：整页加载天然让会话与 CSRF cookie 重新一致，而登录那一刻服务端换了 session id。**迁移的同时改这个，页面出错时分不清是框架还是路由** | 出现「页与页之间要传状态」或「需要路由守卫」时，按 ADR 0015 写的推翻条件单独评估 |
| 2 | 不引状态库（Redux / Zustand / Jotai） | 理由见 [ADR 0015](../../decisions/0015-web-frontend-stack.md) §理由（0075 继承）；React 侧怎么对应见 TD §架构 | 出现客户端权威的状态时 |
| 3 | 不引组件库、不引 UI 原语 | ADR 0032 的推翻条件**已经触发**，但那是**另一件事**：引哪一套、设计稿与代码怎么共用一个组件层，要单独一条 ADR。混在迁移里会让「视觉不变」这条验收失效 | 迁移完成后立即评估（见 TD §开放问题 Q1） |
| 4 | 不改任何界面、不改文案、不改设计稿 | 本版验收是「一切不变」。设计稿已覆盖若干窄屏 / 平板条款（控制台断点 1024 / 900 / 720 / 640，另有 400px 窄屏状态；首页 1000 / 720），但没有覆盖全部页面与完整手机形态——补齐它是设计任务，不是迁移任务 | 移动端那一版 |
| 5 | 不动服务端与 CLI | 接口形状、路由、错误码一个字都不改——这是「整页加载的路由」之所以还能用的前提 | — |
| 6 | 不借机升 TypeScript、不引 ESLint/Prettier | 一次只动一个变量。ADR 0015 里「停在 5.9.3 是因为 vue-tsc」这条理由消失了，但升级要单独验证 | 单独一次 |
| 7 | 不做渐进式双运行时共存（React 挂在 Vue 里） | 理由见 [ADR 0075](../../decisions/0075-the-browser-client-is-react.md) §理由 | 不做 |

## 验收与指标

### 验收标准

| # | 验收标准 | 怎么判定 |
|---|---|---|
| 1 | `design/` 与 `skillmaster-web/src/styles.css` 在本版内**零 diff**（即：分支没有改动过这两处；它**不**证明实现与设计一致，那由 #2 与 #8 承担） | `git diff main -- design/ skillmaster-web/src/styles.css` 输出为空 |
| 2 | 每个页面的 DOM 骨架与迁移前逐字一致（标签、类名、`id`、`name`、`role`、`aria-*`、`hidden` / `disabled` / `checked` / `selected` / `value` / `type`、嵌套顺序），文本节点（空白归一化后）与 `placeholder` / `title` / `alt` / `aria-label` 也一致 | 对照台对同一屏在两套实现下取骨架、文本、属性文案三份 diff，全部为空（T1） |
| 3 | 24 个测试文件全部保留，断言不减少 | 逐文件对照：每个 React 测试能指出它对应原测试的哪一条（T3） |
| 4 | 类型检查与构建通过，构建产物能真服务一次 | `npm run type-check`、`npm run build` 退出码 0，且 `preview` 下能完成一次登录（T4、T5） |
| 5 | CLI 层全部按原样通过：`CLI_READ_PROBES` 的 **12 个探针** + 2 个额外用例（1 个写路径 + 1 个上线交接），各 × 6 档 = **84 个用例** | `qa/role-matrix` 的 CLI 层（T6） |
| 6 | `/web/**` 全部按原样通过：rung 视图 1 个 + **5 个门**，各 × 6 档，加 2 个生命周期 = **38 个用例** | `/web/**` 那一层（T7） |
| 7 | 控制台那一层全部按原样通过：**2 个屏**（版本列表 / 上线交接）× 6 档 = **12 个用例** | 控制台那一层（T8） |
| 8 | 六档截图与迁移前并排看，人判定一致 | T9，**由人判定**，不由断言代替 |
| 9 | 页面地址、查询参数、跳转方式与迁移前一致 | 地址表逐条走查（T2） |
| 10 | 包体测量并如实记录 | 构建产物 raw / gzip 与迁移前对比（T10） |

**成立条件**：**#1 与 #2 是「不满足就不算交付」的那两条。** 它们是「视觉不变」唯一可判定的形式——Claude 看不到渲染结果，而样式**以类选择器为主，但还依赖标签、属性与 `aria-*` 状态**，所以类名、标签、`aria-*` 与嵌套一起构成视觉证据。**在本版内**，任何一处样式改动都要停下来查清原因，不是接受它；若期间发生一次真实的设计交付，按 [ADR 0075](../../decisions/0075-the-browser-client-is-react.md) §后果 的边界停下来重新界定基线。

**2026-10-22：一处设计修正让 #1 的基线动了一次（用户看图指出，已按上面那条走）。** 「我的 skill」的空态——「没有匹配的 skill。」「没有删掉的 skill。」——被一个空的 `<ul class="skills">` 的 `flex:1` 顶到帧脚，中间是一整屏空白。改的是设计本身（**设计件也有同一个问题**）：`design/` 加 `.skills:empty{display:none}` 并在 `design/README.md` 写下这条规则；`skillmaster-web/src/styles.css` 照同一条规则改，另补 `.empty{margin:0}`——设计件有一条全局 `p{margin:0}`，产品没有，缺它那句会低 15px。**两边一起动，所以不算 #1 说的漂移**：#1 判的是「产品单方面改了样式」，而这里产品只是跟着设计走。证据见 [`test-plan.md`](test-plan.md) §结果。

## 依赖与前置

- **外部依赖**：`npm` 上当前的 `react` / `react-dom` 19.3.1、`@vitejs/plugin-react` 6.1.2、`@testing-library/react` 16.3.3（2026-10-21 查得，实现时逐个钉死，不用 `^`）。
- **内部前提**：
  - [ADR 0075](../../decisions/0075-the-browser-client-is-react.md)（本版的依据；已采纳）
  - [ADR 0015](../../decisions/0015-web-frontend-stack.md) 的**其余七项纪律**（路由 / 状态库 / UI 组件库 / CSS 框架 / `axios` / i18n / ESLint·Prettier）**继续有效**，本版不碰（已被 0075 引用为继续生效）
  - [ADR 0032](../../decisions/0032-ui-primitives-on-demand.md) 的判据继续有效，但它点名的库在 React 下失效——留给组件层那条 ADR
- **排除了什么前置**：
  - **不需要改设计稿**。这一版不改界面，所以 SOP 阶段 4 的设计稿锁定不适用；`design/` 只作为**不变量**参与验收。
  - **不需要新开版本级别的验收标准**。本版的验收标准是「旧行为原样通过」，不是新能力。
  - **不需要真机 / 真浏览器的矩阵扩展**。`qa/role-matrix` 的控制台层本来就用真 Chrome，原样复用。
