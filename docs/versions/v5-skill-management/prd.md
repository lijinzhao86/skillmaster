## 用户与场景

**谁在用**：把一个 skill 托管上来的作者，以及他要把它交给的**别人**。

**在什么场景下用**：三件事今天做不到。它们不是三个愿望，是三条**今天就撞得到的墙**：

1. **「把 skill 交给别人」只有两个答案，而真实的分法有六个。**
   今天能给的只有 `viewer`（能读）与 `editor`（能读 + 能提交版本），而 `editor` **还给不了上线**——那是有意留的（[ADR 0034](../../decisions/0034-skill-level-sharing.md) §理由：编辑器若能上线，所有者只会在事后发现自己的 skill 被换掉了）。
   于是实际发生的是：有人只想让同事**用**这个 skill，而 `viewer` 把整个文件树一起给了；有人想让同事**维护**它（设计件那一档写的是「上线 / 回滚、改描述、丢弃别人的草稿」），而今天**没有任何一档**能给到那里——只有所有者能做那些事，而所有者是唯一的、不可让渡的。设计件把这条线画成了一条梯子——六行（五档可授，加上不授的所有者），`design/README.md:581-596` 逐档写了能力，而代码停在前两档。

2. **删掉一个不用的 skill——今天在整个产品里无处可做。**
   API 面那条删除路由在 v4 被撤掉了（[ADR 0046](../../decisions/0046-deleting-a-skill-happens-in-the-browser.md)），因为它只由「凭据 + 你是所有者」把关，而控制台一个按钮都没有。ADR 0046 明说那个入口**属于 skill 管理模块**，并如实记下代价：「在这一版与控制台入口之间那一段时间里，删除在整个产品里无处可做」。**这一版就是那个模块。** 连带地，删错了也没有任何办法找回来。

3. **看得见它的人想参与，却没有地方开口。**
   公开档让所有人看得见这个 skill，「调用」与「浏览」也让人拿得到它——但想提交一个版本、想帮着维护，只能等有权的人想起来给他一档。今天的替代做法是**离开产品去说**：在聊天里找到那个作者。于是这条真实的流程没有入口、没有记录，也不会有任何东西提醒有权的人去处理它。

**现在的替代做法是什么**：第 1 条——多给（整个文件树）或少给（什么都不给），然后在聊天里口头约定「别上线」；第 2 条——**直接改库**；第 3 条——**去产品外面找人开口**。三条替代做法的共同点是：它们都绕过了产品，所以都没有留下任何痕迹。

## 范围

### 做

| # | 做什么 | 交付形态 |
|---|---|---|
| 1 | **权限从两档扩成一条梯子**：`调用` / `浏览` / `写入` / `维护` / `管理` 五档可授，每档**包含它下面的全部**；`所有者` 是**这个 skill 所在命名空间的所有者**（ADR 0047；不是 `created_by`——本版没有组织模型，两者今天总是同一个人），**不进授权表、不授予任何人**。梯子逐档的能力照 `design/README.md:581-596` | `skill_grant.role` 的词表与判定（服务端）+ **控制台那一屏长成设计件的形状**（分区 信息 / 文件 / 版本 / 设置，设置的二级菜单 常规 / 协作者 / 详细信息——今天产品没有设置那一屏）+ CLI 的档位词**与取数路径**（`skill share --role` 换词表；`invoke` / `read` 不再先读清单，否则「调用」档在 CLI 上跑不了） |
| 2 | **可见性 = 「公开之后陌生人拿到哪一档」**：`私有` / `公开 · 调用`（梯子第一档）/ `公开 · 浏览`（前两档）。**读与搜索认这个档位**——公开之后不再需要授权就够得到，这正是「公开」的全部含义（[ADR 0037](../../decisions/0037-visibility-has-two-states.md) §决定 2） | 两列（`visibility` + 陌生人拿到的那一档）+ 控制台**设置 › 常规里的可见性那一块**；消费面的读与搜索跟着认它 |
| 3 | **删除一个 skill，以及把它找回来** | **只在浏览器面**：一处入口、点下去**先问后果**（[ADR 0046](../../decisions/0046-deleting-a-skill-happens-in-the-browser.md)）；恢复在「我的 skill」的**已删除**那一份列表里 |
| 4 | **看得见它的人可以申请一档；管理与所有者批准或拒绝** | 申请是**独立的对象**（谁、想要哪一档），不授予任何东西；**设置 › 协作者** 的末尾列出待处理的申请（只在有申请时出现），批准时定档并授权，申请人可撤回（[ADR 0052](../../decisions/0052-a-request-is-not-a-grant.md)）。入口画给**还有比自己高的档**的人——调用 / 浏览 / 写入 / 维护；已经在名单里的人按钮写「申请」，还不是协作者的人写「申请成为协作者」；私有 skill 对陌生人仍是 404。**没有通知**——二级菜单上的条数是唯一的提示 |

**第 1 条的真实体量是「每一个操作一条门槛」，不是「把两个角色换成五个名字」。** 梯子定的是**档位**，而**每一档能做哪些操作**是逐条定的——读 L1、读正文、取单个文件、拿详情（含清单）、列版本、进作者面、提交、丢弃草稿、上线、改可见性、授权、删除、恢复，**各有一条**。**逐条的门槛表在 [`technical-design.md`](technical-design.md) §接口**，那里是它的权威，**这里不复制**（复制一份就是两个会漂的真相），也**不报一个总数**——那个数会随门槛表改而漂。

相对今天，那些门槛做的是三件事：**放宽三处**（上线、授权、丢弃别人的草稿——今天全都只有所有者能做）、**新增三处**（改可见性、删除、恢复）、**加一档更低的**（`调用`：够得到正文，但列不出目录，所以发现不了没被正文点名的文件）。

**第 1 条与第 2 条是同一条梯子的两个用法**：授权是「把这一个 skill 的某一档给某一个人」，可见性是「把某一档给所有人」。它们不是两套机制——这就是为什么它们必须一起做。

### 不做

| # | 不做什么 | 为什么 | 什么时候可能做 |
|---|---|---|---|
| 1 | **组织 / 命名空间成员**（把一个人加进命名空间，一次授给他名下**全部** skill） | 它要一整套组织模型：邀请流、成员列表、一个全新的外发动作。而它与 skill 级授权**没有共同依赖**——[ADR 0034](../../decisions/0034-skill-level-sharing.md) §理由已经论证过这一点，并且 `namespace_member.role` 声明了 `owner \| editor \| viewer` 却只写 `owner`、从不读，就是这个决定留下的形状 | v6 以后 |
| 2 | **改名** | 改名就是换地址（[ADR 0004](../../decisions/0004-opaque-id-primary-key.md)），所以它必须回答「旧地址是 404 还是重定向」——而 [ADR 0012](../../decisions/0012-addressing-and-version-pinning.md) 说地址解析不出就一律 404、**没有重定向这个概念**。它是一条独立的 ADR，不该塞进权限这一版 | 未定 |
| 3 | **版本废弃 / 版本删除 / 版本历史接口 / changelog** | 四件都没有需求驱动，也都没有设计件。[`architecture/model.md`](../../architecture/model.md) 明说废弃「留到需要时加，成本几乎为零」；`changelog` 那一列从 v1 起就永远是空串 | 未定 |
| 4 | **API key 的档位扩展** | key 今天只有 `skills:read` / `skills:write` 两个 scope，**本版不动**。理由是两条轴不能合：scope 回答「这把凭据能做**哪一类动作**」（可转让、给 CI 用），梯子回答「这个人**在这一个 skill 上**是什么」。一把 key 代表一个人，而那个人在 A skill 上是「管理」、在 B skill 上是「浏览」——**key 带不了一个档位**。两者取交集 | 不做（结构性） |
| 5 | **发现页 / 新的排序 / 推荐** | 公开的 skill 这一版起会进搜索结果（那是「公开」的定义），但不做独立的发现页、不为公开内容调整排序权重、不做推荐 | v6 以后 |
| 6 | **在线编辑 SKILL.md 正文** | v1 §不做 #6 已界定的边界（「在线 SKILL.md 编辑器」）。本版**既不动正文、也不动描述**——描述归元数据那一版（见 §不做 #8） | v1 起就不做 |
| 7 | **匿名读面**（不带任何凭据就能搜到、能调用公开的 skill） | 「公开」在本版指**任何持凭据的账号**——今天 `/api/v1/**` 一律要认凭据，匿名面只有网关那两条索引路径。真做匿名读要连带回答速率限制、滥用防护与「公开即被爬」三件事，而那是另一个平面的事，与权限粒度无关 | 未定 |
| 8 | **元数据整块**（改描述；以及 `name` / `title` / `description` 三个字段各自的地位） | **按模块切版**：元数据是独立的一条线（`title` 与 `description` 的分工、覆盖压在版本上、界面上的编辑），而它与权限**没有共同依赖**；整块做完才自洽——半做会造出一个「作者编辑的那一列与读者看到的那一列不是同一列」的状态 | v6 |
| 9 | **申请的通知**（邮件、站内信、推送） | 本产品**还没有任何通知面**：没有邮件队列，也没有消息中心。为这一件事单独造一条外发通道，会把「通知」从一个不存在的能力变成一个只有一种用途的半成品；而申请本身不依赖它——条数在设置里看得见 | 与通知面一起做（未定） |

**范围里不许出现「后续再看」「视情况而定」。** 不确定的进 [`technical-design.md`](technical-design.md) §开放问题，并且必须是一个**能回答的问法**。

## 验收与指标

### 验收标准

每条都必须是**能判定过没过**的。

| # | 验收标准 | 怎么判定 |
|---|---|---|
| 1 | **五档能授、能改、能撤，而且每一档的能力与设计件逐条对得上** | 对同一个 skill 依次授出五档，逐档验：`调用` 能 invoke 与按路径取单个文件、**拿不到文件清单**（详情接口那一份），但**看得到已上线的版本清单**（草稿不给）；`浏览` 拿到清单、网页上「文件」栏也打得开（`调用` 打开同一页时是「信息」与「版本」两栏，版本只列已上线；`浏览` 多出来的那一半是**网页作者面的**文件清单、文件栏与详情 / 正文——API 面的正文与单文件那一档本来就取得到，见 [ADR 0051](../../decisions/0051-the-author-plane-serves-by-tier.md) §决定 2a）；`写入` 能提交新版本、能丢弃**自己提交的**草稿、不能丢弃别人的；`维护` 能上线与回滚、能丢弃任何人的草稿；`管理` 能授权/撤销、能改可见性。**再往上一步都不行**：被授 `管理` 的人**删不了**这个 skill。**两处写明的例外**：设计件那一行还给「管理」写着**改名**、给「维护」写着**改描述**，而本版**两样都不做**（改名见 §不做 #2，改描述见 §不做 #8）——它们是设计件画了、而这一版不交付的能力 |
| 2 | **所有者不是一档，而且它不可让渡** | 「所有者」不出现在任何可授档位的名单里（接口与界面两处都不出现）；被授 `管理` 的人试图删除 → **403**（不是 404：他看得见这个 skill，是**这一档**不够）；试图再往上一步（改归属、改所有者）根本没有这条路 |
| 3 | **已有的两条授权按语义平移，消费面能力一条不变** | 迁移前是 `viewer` 的，迁移后 `browse`（能读、能列、能 invoke）；迁移前是 `editor` 的，迁移后 `write`（再加提交与丢弃自己的草稿）。**消费面逐条相同**；唯一的新增是 `browse` 按 [ADR 0051](../../decisions/0051-the-author-plane-serves-by-tier.md) 获得**作者面读**，那是本版有意加的，不算翻转。用同一组断言在迁移前后各跑一遍 |
| 4 | **三种可见性选择真的按档位放开，而且只放开那一档** | `私有`：没被授的人一律 404（与今天相同）。`公开 · 调用`：任何持凭据的账号能 invoke、能按路径取单个文件，**但详情接口里的文件清单要不到**；控制台里打得开「信息」与「版本」两栏（版本只列已上线的）。`公开 · 浏览`：能拿到清单、能一个个读过去；控制台的**文件栏与详情 / 正文**打得开（「信息」与「版本」两栏调用档已有）。三种情形下**写操作一律仍被拒** |
| 5 | **可见性与授权取较高的一档，而不是互相覆盖** | 一个 `公开 · 调用` 的 skill 上，被授 `写入` 的人仍然能提交版本（授权比公开高）；一个 `公开 · 浏览` 的 skill 上，被授 `调用` 的人实际拿到的是 `浏览`（公开比授权高）。两条都验 |
| 6 | **改可见性要「管理」档** | 被授 `维护` 的人改不了可见性（**403**）；被授 `管理` 的人能改；被授 `写入` 的人也不能 |
| 7 | **删除只由所有者发起，只在浏览器面，而且凭据删不了** | 控制台上点删除 → **先问后果**、确认之后才生效；`skillmaster login` 换来的登录态与任何 API key 都**没有**这条路由（`DELETE /api/v1/skills/{ns}/{name}` 仍然不存在——可观察的结果是打过去得到 **405 + `Allow`**，不是 404：那个路径本身以 `GET` 服务）。被授 `管理` 的人在网页上也没有这个按钮 |
| 8 | **删除之后地址立刻失效，而它还能被找回来** | 删除后：消费面与作者面的地址**都是 404**（与「不存在」同一个答案）；「我的 skill」的**已删除**那一份列表里能看见它；点恢复之后地址立刻恢复可用。**恢复要重新问一遍所有权**——别人恢复不了 |
| 9 | **删除不释放名字** | 删掉 `alice/pdf-tools` 之后，提交一份同名的 skill **不成功**（与今天撞上已删名字的行为一致：明确拒绝而不是静默复活）；恢复之后那个名字仍然是原来那一个 skill |
| 10 | **看得见它的人能申请一档，管理与所有者能批准或拒绝，而申请本身不授予任何东西** | 一个被公开档覆盖（或持有 `调用` / `浏览`）的账号申请 `写入` → 成功；一个已经持有 `写入` 的人申请 `维护` → 同样成功。两次都**一步也没多出去**（逐条与申请前相同）。待处理的申请只有 `admin` 能列；批准之后那一条消失、`skill_grant` 多一行、当事人按**批准的那一档**得到能力；拒绝之后申请消失、能力不变；申请人能撤回。**私有 skill 上，没被授的人拿到的仍是 404**，页面上也没有申请入口——申请只对看得见它的人存在 |

**成立条件：第 1 条。** 它不是附带要求——这一版最容易做成的事是「把两档换成五个名字」，而那样做出来的东西读起来对、一条能力都不对。第 1 条要求的是**每一档的能力逐条与设计件对得上**，包括「调用档拿不到清单」这种容易被做没的负向能力。

### 指标

这一版**不加指标**。它改的是权限的粒度与几处 CRUD，产不出可量化的产品指标；调用次数那一类要等统计真的能算（v1 §指标已记：「现在拍一个没有依据的数只会自欺」）。要加时另开一条迭代记录。

## 依赖与前置

- **外部依赖**：无。这一版不引入任何第三方服务。
- **内部前提**：本版实现的**六条** ADR——权限是一条梯子、可见性把一档交给所有人、删除可恢复且名字不释放、**作者面按档位分**、**申请不是授权**、**元数据拆成自己的模块**（ADR 0053，模块边界的前提）。逐条见 [`decisions/`](../../decisions/README.md)，**这里不重列**（列一份就等于给它第二个会漂的副本）。
  **一条不属于本版的**：[ADR 0049](../../decisions/0049-an-edited-description-outranks-the-version.md)「作者改过的那句描述压着版本」是本版讨论时定下的，但它属于**元数据那一版**（§不做 #8）——所以它在那里，而本版不实现它。它落在 `decisions/` 里是对的：决策跨版本存活。
- **排除了什么前置**：**不需要组织模型**。第 1 条只用到「一个 skill」与「一个用户」，两个实体今天都已经存在——这正是 [ADR 0034](../../decisions/0034-skill-level-sharing.md) §背景论证过的那件事，本版只是把它从两档扩成一条梯子（五档可授，加上不授的所有者）。
