# ADR 0017 · 密码只允许 ASCII 可打印字符

- **状态**：已采纳
- **日期**：2026-10-02
- **依赖**：[ADR 0013](0013-phone-login-and-username-slug.md)；收窄 [ADR 0016](0016-password-blocklist-not-composition.md) 里「只看长度」那句话的字符集范围（黑名单决定不动）

## 背景

[ADR 0016](0016-password-blocklist-not-composition.md) 定的是「用黑名单代替组合规则」，其中一句是「密码策略保持只看长度」——**字符集本身没有任何限制**，中文、全角、emoji 都能设。同一天就发现这个默认有三处问题：

1. **全角可以绕过黑名单（实测）。** `ｐａｓｓｗｏｒｄ` 每个字符 3 字节，8 个字符 24 字节，长度合法；而名单是 ASCII 的，查不到。这对中文用户不是什么刁钻输入——输入法留在全角模式，打出来就是这个。
2. **全角与半角肉眼不可区分**，于是用户会设出一个自己再也打不回来的密码。国内有真实线上事故记了这个模式的代价：客服日均 5–8 起「密码正确但登不进」，日志里失败请求的长度比正常**多 1**（正常 12 位、失败 13 位），肉眼比对完全一致；复现方式是输入法全角模式误触，根因是全角空格 U+3000 与半角空格 U+0020 加密后不同值。
3. **归一化没做**，而这个问题恰好只有两类解法：归一化（把多种编码折叠成一种），或限制字符集（让多种编码根本不存在）。Unicode 让「看起来一样」的文字拥有多种编码，这是这份复杂度的**唯一**来源。

业界两侧的答案不同：国际大厂（Google / Apple / GitHub）**允许** Unicode；国内站点的通行做法是**限制**——学信网注册页写明「英文字母、数字和特殊字符」，流传最广的那条中文密码正则明确排除中文（`[^一-龥]`）、全角标点与全角空格。

三个选项：(1) 归一化（宽度映射 + NFC，保留中文，即 RFC 8265 的 OpaqueString）；(2) **只允许 ASCII 可打印字符**；(3) 不动，记录进已知问题。

## 决定

**只允许 ASCII 可打印字符**（U+0020–U+007E）。中文、全角、emoji、控制字符一律拒，回 `invalid_format`；密码的「空」判断同时从 `isEmpty` 改成 `isBlank`（八个空格与八个全角空格都算没填）。

判序：**空/纯空白 → 字符集 → 太短 → 太长 → 与用户名相同 → 与手机号相同 → 常见**。字符集排在长度之前，理由与用户名的「字母表先于长度」相同：对一个中文密码答「太短」，作者会去补更多中文。注册页与找回密码页的提示文案直接写明这条规则——既然它是**用户看得见**的限制，就要在他敲的时候说，而不是事后拒绝。

## 理由

**被否掉的归一化不是因为它错**——它就是 RFC 8265 的做法，技术上正确。否掉的是它在我们这里的**收益与代价不成比例**。

- 归一化买到的是**中文口令**。但国内用户不期待它（学信网那个量级的站点都写明只收英文），而我们**已经没有任何组合规则**，所以限 ASCII 之后用户依然可以写 `correct horse battery staple`——**长口令友好这条没有丢**，丢的只是「用中文写长口令」这一种写法。
- 归一化的代价是确定的：一层 Unicode 代码（宽度映射 + NFC + 相应测试），外加一个用户看不见的语义——「我的密码是我看见的那些字符」与「我敲下的那些码点」不是一回事。**复杂度是被管理，而不是消失。**
- 选 ASCII 之后那三类问题**一起消失**，而且不需要那一层：全角不存在了，所以绕不过名单；看起来一样的文字只有一种编码，所以没有「打不回来」；**字节数等于字符数**，连 NIST「按码点计长」与 BCrypt「按字节截断」之间那个别扭也不存在了。

**代价必须写清楚**：这违背我们自己在 0016 里引用的 NIST / OWASP 建议——OWASP 的原话是「不应有限制字符类型的规则」，而这就是一条限制。它换来的是一整类失败模式的消失；对中文市场这个交换我们认为划算，但**它不是规范推荐的做法**，不要在对外材料里说成「符合最佳实践」。

时机是决定性的：**没有真实用户，迁移成本为零**。上线之后再收紧，凡是用中文或全角设过密码的人**会直接登不进去**，只能走重置。

## 后果

- 密码多一条被拒的理由（`invalid_format`），两个页面的提示写明规则；**存量账号不受影响**（没有真实用户；登录本来也不校验密码形态）。
- **中文口令不再可用，而且这个方向不可逆**：将来若要支持，必须连同归一化一起做（否则全角那一套问题立刻回来），并且那时要处理存量。所以这是一条「现在不做、以后几乎做不了」的决定。
- **以中文密码为 fixture 的测试全部改掉**：服务端 `countsBytesRatherThanCharacters`、前端两条字节边界用例、以及两个页面里拿 25 个汉字当「太长的密码」的用例。这些**不是把断言值改成新值**就完事——它们测的「字节与字符不一致」现在**不可观测**，因为非 ASCII 到不了长度那一步；字节语义因此移回它还能被观察的地方（`BCryptPasswordHasherTest` 的 72 字节截断）。旧断言与新规则直接矛盾时，正确的动作是重新问「这条属性现在还可测吗」，而不是让它继续绿着。
- 前端多一条字段专属文案（`FIELD_SPECIFIC.password.invalid_format`）。**判序的字符集那一步两侧同改**，否则同一个密码在客户端与服务端会得到不同的码。
- 本文**不动 ADR 0016**：黑名单照旧，判序里它仍在派生规则之前；本条只是收窄 0016 里「只看长度」那句话的字符集范围。
