# 0044 · 终端的范围：CLI 管桌面与服务器，移动端将来由 App

> **状态**：已采纳
> **日期**：2026-10-16
> **依赖**：[0025](0025-cli-credential-storage.md)（凭据存哪）、[0028](0028-cli-uses-a-fixed-loopback-port.md)（回调用固定回环端口）、[0043](0043-the-browser-session-is-bounded-and-revocable.md)（浏览器会话可见可撤销）
> **事实底稿**：[`research/credentials-across-terminals.md`](../research/credentials-across-terminals.md)。**本文不复述那里的事实**（RFC 8252/8628 的分档、MCP 规范对回调的硬约束、各平台存储的坑），只写我们据此选了什么、以及否掉了什么。

## 背景

「凭据在所有终端存哪」这个问题把三类终端摆到了一起：**桌面**、**服务器**、**移动端（手机与平板）**。而 CLI 的浏览器登录同时要求三件东西：一个**能起回环监听的进程**、一个**浏览器**、一个**能放凭据的地方**（钥匙串或配置目录）。这三件在手机上都不成立——第三方 App 起不了那种浏览器能回访的回环监听、回调地址是**逐字预注册**的、而钥匙串后端只认桌面三档。

于是有三种走法：

1. **把 CLI 做到移动端**：认领 https 回调 + 平台安全存储 + 新注册一个客户端。
2. **移动端只做网页**，原生客户端连口都不留。
3. **把范围划清**：CLI 明确只面向桌面与服务器；移动端将来若有需要，由**独立的 App** 承担，那一天的凭据存哪由那个 App 自决。

## 决定

1. **CLI 的浏览器登录只面向桌面。** 服务器上不走浏览器那条路，走 `login --with-key` / `SKILLMASTER_API_KEY`（已实现）——服务器没有浏览器，这不是缺陷，是范围。
2. **「跨系统」这件事的待办是验证，不是重写。** 三处 OS 差异都已经封好了（分平台的浏览器打开、凭据存储、路径），剩下的是**在别的系统上真的跑过**：CI 里今天没有 CLI 的 job，Mac 之外从未执行。
3. **不做移动端的 CLI。** 将来若移动端需要一个原生通道，那是一个**独立注册的公开客户端**（按 MCP 那套，回调只能是 `localhost` 或 HTTPS），**凭据存哪由它自决**（iOS Keychain / Android Keystore）。
4. **那个 App 动工之前必须先回答：它的主体是「人」还是「agent」。** 人 → 它连的是网页平面那一套，本质是**第二个控制台**；agent → 它要按 MCP 那套实现，而今天移动端 agent 的主流形态是**云端宿主代连**。两者的规范与平面都不同，选错了等于重做。
5. **今天移动端能用的东西不变**：手机浏览器里的网页会话，纳入 [0043](0043-the-browser-session-is-bounded-and-revocable.md) 那条可见、可撤销的面。

## 理由

**为什么不是 1（把 CLI 做到移动端）。** 三件前提一件都不成立，而修它们不是配置问题：回环监听在第三方 App 里不成立；回调地址逐字预注册，换回调就是换客户端；钥匙串那三档里没有一档是移动端。更硬的是规范——**MCP 要求回调只能是 `localhost` 或 HTTPS**，自定义 scheme 不合规，所以"移动端 CLI"连自己的回跳都要另起一套。而收益（在手机上跑命令行工具）与代价（第二套客户端 + 第二套授权 + 第二套存储）不成比例：**那三件前提里没有一件是"多做一点就能有"的**。

**为什么不是 2（只做网页，连 App 的口都不留）。** 网页今天够用，但把"原生通道"写死为不做，等于替将来的自己否掉一个还没有结论的选项——推送、后台 agent、设备上的本地能力都还没有答案。**留口不等于承诺**：本文不承诺做 App，只是**不把它排在 CLI 里**。

**为什么不在移动端加设备码流程来绕开回跳。** 设备码（[RFC 8628](https://www.rfc-editor.org/rfc/rfc8628)）解决的是「没有浏览器」或「输入受限」，而手机恰恰有浏览器；它的病是「收不到回跳」，而设备码的药是让用户在**同一块屏幕上**打一串码再确认——把最短的路径换成最长的那条。

**为什么跨系统的动作是验证而不是重写。** 三个 OS 差异都已经在接口后面了，剩下的是"在别的系统上真的跑过"。**没有被执行过的分支等于不存在**，这条在本仓库有先例：macOS 上钥匙串锁着会**弹窗等人**，正是靠真跑才发现的（`internal/credentials/responsive.go` 的注释记着 2026-10-04 那次——`login` 在 `keyring.Set` 里一直等下去，什么都不写、什么都不报，把一个调用它的 agent 挂住了）。

## 后果

- **服务器上的凭据不是会话，是 API 密钥。** 它撤销在控制台的密钥那一页，**不进入** [0043](0043-the-browser-session-is-bounded-and-revocable.md) 的登录设备列表。两条路各有各的撤销面，不要混为一谈——「把服务器的登录退掉」这件事不存在，能做的只有撤销那把密钥。
- **跨系统的待办要具体**：CI 加一个 CLI job（至少 Linux 上 build + test），并把两个已知坑记在案——Linux 的 Secret Service 需要一个 session D-Bus（`keychain_linux.go` 已在探测），macOS 未签名构建每次升级都会重新弹钥匙串授权（那是签名问题，不是检测问题）。
- **App 会新增一份控制台看不见、也撤销不了的授权**，与 CLI 那份同一个病（[`known-issues.md`](../versions/v3-sessions/known-issues.md) 条目 002）。手机丢了的概率高于笔记本，所以**「授权列表与撤销」要先于 App 解决**；否则 App 做完了，撤销面依然只有「重置密码」。
- **本文不改变任何现有接口**，也不改变 0025 / 0028 / 0043 的任何结论。
