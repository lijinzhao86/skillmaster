# ADR 0151 · 许可全文链回来源，不做站内许可页

- **状态**：已采纳
- **日期**：2026-11-06
- **所属版本**：[`v49-public-signals`](../versions/v49-public-signals/README.md)
- **依赖**：[ADR 0148](0148-a-license-belongs-to-the-version-and-not-to-the-file-tree.md)（许可属于版本、全文存 `license_text`、不挂 `version_file`）

## 背景

信息页的许可证要能读到全文。导入时我们已经把上游的 LICENSE 原文存进 `skill_version_license.license_text`（ADR 0148），但它今天只有一个消费者：下载/安装时生成 `.skillmaster/LICENSE` 侧车。没有任何 HTTP 路由把这段文本发出来，所以页面上的「查看许可全文」只能指向来源仓库的那一份。

站在这里有两个方向：**加一条读路由、做一个站内许可页**；或者**继续指向来源原文**。站内页不是难事——数据已经在库里——但它要同时定下版本钉、读取门槛（调用还是浏览）与一个只读页面，而这份文本的读者真正要对账的，恰恰是「上游当时怎么写的」。

## 决定

1. **「查看许可全文」指向来源仓库的许可原文**（GitHub 的 `blob/…/LICENSE`），新标签打开；没有来源 URL 的许可见状态说（仅声明 / 未声明 / 冲突 / 其他），不画链接。
2. **不做站内许可页，也不为它新增读路由。** `license_text` 继续只服务下载与安装时的 `.skillmaster/LICENSE` 侧车。
3. 信息页只写许可名、版权行与这个链接；允许做什么 / 要履行什么留在 CLI 的「许可要点」里。

## 理由

- **许可的读者要对账的是上游。** 站内页要么把上游文本复制一遍（读者仍会去翻原文），要么替上游背书；而来源仓库的原文就是那一份，不需要我们再讲一遍。
- **站内页是一项完整的能力，不是一条链接。** 它要版本钉（新版本发布会改变「全文」指向的内容）、要定读取门槛（调用的读者能不能看、看的是不是内容字节），还要一个页面。为一个只读展示开这三样，成本与收益不成比例。
- **离线读者已经有路。** 下载 / 安装会把全文写进 `.skillmaster/LICENSE`；需要带走的人本来就该拿包。

被否掉的：**站内页**（多一个路由、一个页面与一侧权限判断）；**站内纯文本路由**（同样要有路由，且页面上没有「来源：原文」可对账）；**把全文塞进版本内容**（ADR 0148 已否，会改摘要）。

## 后果

- 上游删库或私有化后，链接会断；此时状态仍是 `ok`（我们存的是当时读到的那一份），页面不报错，需要全文的人走下载。
- 想改成站内页的那天，数据不用再抓：`license_text` 已经在库，缺的只是一条读路由与一个页面。
