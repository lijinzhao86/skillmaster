# ADR 0102 · 规则段随 CLI 版本发布

- **状态**：已采纳（**部分取代** [ADR 0096](0096-guidance-lives-on-the-platform.md) 决定 1 里「规则段是技能内容」那一半；旅程正文仍留在平台上）
- **日期**：2026-10-27
- **依赖**：[`versions/v25-cli-self-update-and-prompt/`](../versions/v25-cli-self-update-and-prompt/)

## 背景

[ADR 0096](0096-guidance-lives-on-the-platform.md) 把两段引导内容都搬进了平台上的官方技能 `skillmaster/startup`：旅程正文（多文件、逐步加载）与规则段（`steps/03-prompt.md` 里 `<!-- skillmaster:begin -->` 到 `end` 之间的三行）。当时的理由是内容速度——改一句话不用等一次 CLI 发版。

两个成本后来显形了：

1. **规则段可以领先于用户的二进制。** 它写在平台上，改完对所有人生效；而用户机器上的 CLI 可能还是三个月前那个。于是提示词会让 agent 去跑一条那版二进制里没有的命令——正是 v22 用一整版去消灭的那类不一致。
2. **任何「规则段是不是最新的」检查都要凭据、一次 API 请求和节流。** 没有凭据的机器查不了；每条命令都查就是每条命令打一次网。

而规则段的内容本身，只描述 CLI 的命令面（`skills search` / `skill invoke` / `help`）。它的权威本来就该是它描述的那个东西。

## 决定

1. **规则段的权威位置改为 CLI 源码**：`skillmaster-cli/internal/prompt/block.md`，`go:embed` 进二进制、随版本发布。
2. **文本逐字不变**：沿用 v20 批准并实测的三行，含两行标记；搬的是位置，不是措辞。
3. **旅程正文仍留在平台技能**：`skillmaster/startup` 的 `SKILL.md` 与 `steps/` 还是内容，仍按需加载、仍可不发版就改。
4. **技能的第三步改为调用 CLI**：`steps/03-prompt.md` 不再携带可粘贴的正文，改为让 agent 运行 `skillmaster prompt install --file <路径>`，并要求先问人。

## 理由

- **同源**：规则段与命令一起发布，才可能在机制上保证它不会指向一个不存在的命令。两处各改各的，靠人守是守不住的——v22 修的就是这一类。
- **检查从网络变成算术**：新旧比对变成「二进制自带的那段摘要」比「上次写进用户文件的摘要」，不联网、不要凭据、不用节流，每条命令都能查而几乎零成本。
- **代价可控**：改一句规则要发一版。有了 [ADR 0103](0103-the-cli-updates-itself.md) 之后，一版到用户手里是当天的事，而不是「等用户想起来重装」。
- **被否的第 2 条（发到 `dl.` 上的 `prompt.txt`）**：它确实能不要凭据地检查、也能热修，但它又重新制造「规则段领先于二进制」——一个热修过的 `prompt.txt` 照样能点名旧二进制没有的命令。多一个发布物、多一个版本标记，换回来的是同一个问题。
- **被否的第 1 条（维持现状）**：上面两个成本都不会消失，而「让用户知道规则段旧了」这件事仍然无解。

## 后果

- **`steps/03-prompt.md` 要改并上线**：这是平台内容的一次发布，由技能主人点上线，不是 CLI 发版能代劳的。
- **v20 验收 5 的比对对象变了**：从「技能的第三步文件」改成「CLI 源码里的 `block.md`」。原验收记录保留为历史，新的比对在 v25 的 T12 / T17。
- **改规则段进发布流程**：谁改都不再影响「谁在什么时候拿到」，一切按 CLI 的发版与自更新走。
- **没有平台的兜底**：技能里不再有那段正文，所以「平台可用、CLI 很旧」的组合下，用户拿到的规则段就是他那版二进制自带的——这正是想要的，但意味着「平台能改、用户立即看到」这条能力没有了。
