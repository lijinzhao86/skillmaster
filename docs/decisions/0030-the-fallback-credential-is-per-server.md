# ADR 0030 · 兜底凭据文件按 server 分

- **状态**：已采纳
- **日期**：2026-10-05
- **依赖**：[ADR 0025](0025-cli-credential-storage.md)（keychain 优先、`0600` 文件兜底）
- **扩展**：ADR 0025 —— 它定的那条「钥匙串优先、拿不到就落一个 `0600` 文件并告知」不变，变的是**那个文件叫什么名字**

## 背景

ADR 0025 定下兜底文件落在 `~/.config/skillmaster/credentials`。**钥匙串那一侧从来不是这样**：它的条目名（`keychainService` 之外的 account 字段）就是 **server URL**，而那句注释自己写了为什么——「两台 server——本地那套和线上那套——否则共用一个条目，症状是从第二次用的那台收到 401，而能用的那份凭据躺在一个没人看的名字底下」。

于是同一次实现里，**两个存储对「这是哪台 server 的凭据」给出了相反的答案**：钥匙串分，文件不分。而文件的加载路径会在两处去问它（钥匙串答「没有」时、以及决定两份副本哪份更新时），**都不带 server**。

后果是一条很安静、方向很坏的链：

1. 用户有 A 的凭据落在文件里（headless 机器，或某次钥匙串超时那一次的遗留）
2. 他设 `SKILLMASTER_SERVER=B`，跑一条命令
3. 加载路径把 **A 的**凭据给他，于是 **A 的 bearer token 被发给了 B**
4. B 回 401，CLI 走「一次续期」那条路，把 **A 的 refresh token 递给 B 的令牌端点**
5. B 说 `invalid_grant`，CLI 照设计把它翻译成「授权已被撤销」——**并删掉本地凭据**

**用 A 反而把 B 注销了。** 而 B 那边本来就有自己的授权，一次都没用过。

## 决定

**兜底文件按 server 命名**：`~/.config/skillmaster/credentials-<server URL 的 sha256 前六字节>`，与刷新锁同一套哈希。文件名里不带 URL 本身，理由与锁相同——base URL 有斜杠和冒号，一个需要转义的路径迟早是一个没人期望过的目录。

不加第二个机制：**不往 blob 里塞 server 字段做校验**。文件名已经让「另一台 server 的凭据」不可能被读到，而 blob 里再记一个字段只会是同一个事实的第二处权威（与「一个事实只有一个权威位置」相抵）。

## 理由

**被否掉的第一条：保持一个共用文件，加载时比对 server。** 这需要一个「这份凭据属于谁」的字段——而它**今天就该存在**：凭据结构里没有 server，文件里也没有。加了它之后，读到不匹配的副本该做什么？拒绝（那用户在一台机器上就用不了第二台 server 了）还是覆盖（那就是现在这个 bug）？名字里带上 server 把这个问题**消掉**而不回答它：两个文件各自存在，谁也不会读到谁的。

**被否掉的第二条：不加 server，只让 `Load` 在有多个 server 时报错。** 这让「两台 server」从「静默地互相破坏」变成「明说不能用」——比现在好，但客户端明明有能力把这件事实记住（钥匙串早就记住了），却选择不做。

**为什么不是 ADR 0025 的就地修改**：0025 的正文记的是**当时**在「钥匙串 / 文件 / 不存」之间怎么选的——那段历史不变。这一条扩展的是它没展开的那一半：**「属于哪台 server」是凭据的一部分**。

## 后果

- **两台 server 的机器上会多一个文件**，各 `0600`，各不相干。这是目的，不是代价。
- **换 server 不再需要先登出**：以前换过去会读到另一台凭据并把它毁掉，现在读到的是「没有凭据」。
- **旧名字的文件不会被读到，也不会被删**：`logout` 只删它打开的那个存储。这一条在本次变更集里**没有发布过**（旧拼法只存在于更早的中途构建），所以没有迁移代码；真要遇到，就是手工删一个文件。**如果将来这个文件名再变一次，「旧文件静默残留」就是一次真正的迁移问题，不能照抄这一次的处理。**
- **刷新锁本来就是按 server 分的**，现在两者对齐了——锁保护的正是它旁边那个文件。
