# 0142 · CLI 退出时结束服务端这次登录

- **状态**：已采纳（收窄 [ADR 0038](0038-default-credential-is-an-api-key.md) §决定 7 到 API 密钥）
- **§决定 4 的边界**：那里的「拒绝撤销」指服务端没能完成撤销（5xx / 网络）；`token_revoked` / `token_expired` / `token_idle` 三种 401 表示登录已经结束，按「已经结束」处理——验收见 [v46 A13](../versions/v46-account-identity/prd.md)，实现细节见该版技术设计 Q3
- **日期**：2026-11-05
- **依赖**：[ADR 0040](0040-api-key-in-the-cli-now-the-browser-path-later.md)（终端登录换来的凭据是一台「登录设备」）、[ADR 0141](0141-a-logout-stops-on-a-guide-screen.md)（退出后的引导页让 agent 运行 `skmr logout`）
- **范围收窄**：收窄 [ADR 0038](0038-default-credential-is-an-api-key.md) §决定 7 的「`logout` 只删本机」——它继续适用于 **API 密钥**；**CLI 登录凭据**由本 ADR 改成「清本机 + 结束服务端那次登录」。0038 的正文不动

## 背景

今天 `skmr logout` 只清本机，服务端「登录设备」里那一行留到过期（最长 7 天）。v46 的退出引导页让用户把一句话交给 agent、由 agent 运行 `skmr logout`，目的正是**不再把人送回登录页**。但命令跑完，CLI 自己的输出仍会写「服务端那份在控制台的「登录设备」里结束」——等于又把用户指回控制台，绕路没有消失。

ADR 0038 §决定 7 的理由是「一把 key 可以贴在多台机器上，本机一撤就把 CI 断了」。**CLI 登录凭据不是这个形状**：它由 `skmr login` 在一台机器上换来，服务端有它自己的一行「登录设备」，本机退出时把它一起结束不会影响任何别的机器。

## 决定

1. **`skmr logout` 面对 CLI 登录凭据时，先结束服务端那次登录，再清本机。** 结束通过一个用该凭据自身认证的端点完成；端点不接受设备 id——出示的凭据就是它要结束的那次登录。
2. **控制台「登录设备」里那一行立即消失**；该凭据之后再用会被拒绝（已结束／不认）。
3. **API 密钥不变**：`skmr logout` 不撤销 key，只清本机；输出仍按 [ADR 0038](0038-default-credential-is-an-api-key.md) §决定 7 指向控制台。
4. **服务端不可达或拒绝撤销时，本机凭据仍然清除**；输出明确说「服务端那份还在」并给出控制台地址，不谎称已结束。
5. **旧版遗留凭据**（浏览器登录换来的授权、无人值守登录留下的那份）保持现有说法，不新增行为。

## 理由

- **为什么可以把 0038 §7 收窄，而不是推翻它。** 那条决定保护的是「同一把 key 在多台机器」；CLI 登录凭据是机器专属的，服务端还有一行给它。留着它，就是人已经退出了、控制台却还显示这台机器登录着——这正是 v46 要消灭的那种「以为退了、其实没退」。
- **为什么端点用凭据自己认证，而不是让 CLI 报一个设备 id。** CLI 手里只有令牌，不知道服务端的登录 id；而且一个能被调用方指定 id 的「撤销」端点，就得再证明「这个 id 是你的」。让令牌自己回答它是谁，既少一个参数，也少一类越权。
- **为什么服务端失败时仍然清本机。** 本机那份才是还能继续干活的东西；为了报告一个失败把它留下，等于在一台用户认为已经退出的机器上留一把能用的钥匙。清掉本机、如实说服务端那份还在，是两半都诚实。
- **为什么不加 `--revoke` 开关。** 那会让普通的 `logout` 继续留下服务端那一行，也就是这一版要修的问题；开关只是把默认的错藏起来。

## 后果

- **ADR 0038 §决定 7 收窄到 API 密钥**；0038 的正文不修改，文件头标明这次收窄。
- **`skmr logout` 对登录凭据开始依赖网络**：离线时仍清本机，但会明确说服务端那份还在。命令的退出码与措辞由技术设计定。
- **新增一个服务端端点、CLI 的一次调用与两侧测试**；成功路径的输出从「去控制台结束」改成「服务端那份也已结束」。
- **API 密钥与旧版遗留凭据的文案不变**；它们仍指向原有的出路。
- **退出引导页那句话现在完全成立**：agent 运行 `skmr logout` 之后，本机与服务端都不再有这次登录。
