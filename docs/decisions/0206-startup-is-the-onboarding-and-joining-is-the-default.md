# 0206 · Startup 是新人引导，公开库默认 join

> **状态**：已采纳
> **日期**：2026-11-14
> **依赖**：[0096](0096-guidance-lives-on-the-platform.md)（旅程正文住在平台上）、[0106](0106-the-checklist-is-recomputed-not-recorded.md)（清单按实际状态重算，不记进度）、[0129](0129-onboarding-delivers-a-skill-not-a-memory-line.md)（安装交付技能包，不写全局记忆）
> **关联**：[v71-onboarding](../versions/v71-onboarding/README.md)

## 背景

安装流程的最后一步是 `skmr startup`。它今天的正文只有一件事：**把电脑上的技能传上来**。新用户装完 CLI、登录完，得到一个能用的工具，但不知道 SkillMaster 能做什么——公开库在哪、怎么找、怎么用、怎么写自己的第一条。这条空白在 [`docs/current/TODO.md`](../current/TODO.md) 的「新人旅程（人侧引导）」里已经记了一阵。

有三个候选做法：

| 选项 | 做法 | 代价 |
|---|---|---|
| A | 新建一个官方 skill（例如 `skillmaster/onboarding`），`startup` 继续管迁移 | 两个「装完接上」的官方入口，内容会分叉；用户还要知道该跑哪一个 |
| B | 把 `startup` 的正文改成新人引导；迁移降为可选的最后一块 | 老用户跑 `startup` 时会先看到引导，需要一条跳过前两块的路 |
| C | 在 `skillmaster-guide` 里加一节教程 | 指南是查手册用的，不是带着人做的；新用户不会主动翻 |

## 决定

1. **`startup` 的正文是新人引导。** 安装收尾先问一次「要不要做新人引导」；只有选「现在开始」才运行 `skmr startup`、加载正文。选「以后再说」不加载，CLI 直接可用；以后随时可以再运行 `skmr startup`。
2. **引导是三块**：① 找 → 加进库 → 用一次；② 做一条自己的（从头写或从本机导入）→ 发布上线；③ 可选批量搬本机技能。第 2 块恰好一次 `skmr version publish`。
3. **公开库的默认使用方式是 `join`，不是 `copy`。** 第 1 块只把公开 skill 收进自己的库，并解释「加到库里」的作用；然后让他用自己的话说一句想做什么，在自己的库里搜到、加载一次，把「库」从概念变成动作。引导里不教 `copy`；要做自己的，第 2 块走从头写或本机导入。
4. **迁移本机技能降为可选第 3 块。** 只在发现本机有可迁移技能时问；没有就不出现。
5. **不记录引导进度。** 中途停下，下次从头走；已上线的 skill 搜得到，就是进度的证据。
6. **引导全程用 Agent 自己的选项卡，每张卡片带推荐项，问句要能独立读懂。** 凡是需要用户表态的地方都出卡片；每张卡片至少一个推荐项，放第一个并写「（推荐）」；需要他说需求时给 2–3 个常见例子当卡片，最后放「我自己说」。目标是点着卡片走完主线，全程不用打字。**卡片问句里带上判断所需的信息**（名字、数量、页面上该看到什么），选项写「点下去会发生什么」——用户不该为了看懂一张卡往上翻。
7. **引导里教 `/skillmaster`，缺了就补装。** 走完主线后告诉他：以后直接说要做的事就会被自动找，想强制触发就输入 `/skillmaster`。收尾前确认这个 Agent 实际加载的目录里有 `skillmaster`；没有就先问一次要不要装，同意才按安装说明第 0 步判定、第 2 节装；拒绝或装不上，收尾不说 `/skillmaster`。**安装流程本身不变。**

## 理由

**为什么不新建一个 onboarding skill。** `startup` 本来就是「装完把用户接上」的那一步，语义最贴；再建一个官方入口，两个入口的正文会各自漂，用户还要先判断该跑哪个。把 `startup` 改成引导，入口只有一个，迁移也能自然降成它的最后一步。

**为什么安装后先问一次。** 10 分钟的引导是打扰；不问就加载，等于替用户决定「你现在要上课」。问一次、把推荐放在前面、允许以后再说，既守住「不替他决定」，也让引导只发生在用户同意时。

**为什么默认 `join` 而不是 `copy`。** `copy` 会在用户还没理解「库」是什么的时候，先制造一份私有副本；用户容易以为「用别人的 skill 必须先复制」。`join` 先教会更常用的动作：收进库，以后自己和 Agent 都直接搜得到、加载得到，而原作者那一份不会被改到。复制不在引导里教，留给 guide 的 `copy` 篇——想做自己的，第 2 块走从头写或本机导入。

**为什么只上线一次。** 10 分钟的预算里，一次完整的「做一条自己的 → 检查 → 上线 → 搜得到」已经足够让用户看到闭环；第二次上线要多一次网页确认，收益只是再走一遍相同的动作。第 3 块的迁移如果发生，沿用现有 import 流程，它自己的上线不算进这条规则。

**为什么迁移还要留着。** 已经有一批用户把 `startup` 当成「迁移本机技能」的入口；直接拿掉，他们会失去一条明确的路径。降为可选第 3 块，既不给新用户增加负担，也不拿走老用户的能力。

**为什么卡片问句必须自带上下文。** 真跑时暴露过一次：上线那一步的卡片只问「弄好了吗」，用户在浏览器里既找不到按钮、也分不清「弄好」指什么，只能反问。卡片一旦脱离上文就变成哑谜——用户看到的是问题，不是刚才那段对话。把「该看到什么」写进问句，他就能自己判断要不要点第一个选项；给两个选项而不是三个，是因为判断式的问题多一个选项就多一次犹豫。

**为什么把 `/skillmaster` 的兜底放在引导而不是安装流程。** 安装流程已经装过一次技能，再查一遍会把它拉长；引导才是「人真的在用」的时刻——这时发现技能不在，补装的代价最小，也能顺带让他看见补装这件事会发生。用 `/skillmaster` 当开关，是因为它是唯一一个用户主动、且每个支持斜杠命令的 Agent 都认得的入口，不依赖他记住某句措辞。

**为什么全程用卡片。** 新用户装完看到的是一个空对话；第一句就让他「说说你想让 AI 帮你做什么」，多数人答不上来——不是不会答，是不知道这个工具能吃进什么。卡片把这个开放问题换成三个具体的例子，他只需要认出一个；推荐项再兜住「都不知道选哪个」的人，回车就能往下走。他真有别的主意时，最后一张「我自己说」还留着自由输入，所以卡片不是限制，是默认路径。没有卡片时，Agent 会把问题原样丢回去——这正是这类引导最容易卡住的地方。

**为什么不记录进度。** 与 [0106](0106-the-checklist-is-recomputed-not-recorded.md) 一致：记录会和实际状态漂。用户中途停下，重新进入时从第 1 块开始最省事；已经上线的 skill 在库里看得见，不需要另一份「做到第几块」的记录。

## 后果

- **安装文档多一问**：`skillmaster-site/public/install/skillmaster.md` 的步骤与「话术定稿」都要加这一问，以及「以后再说」的收尾句。
- **平台上的 `skillmaster/skillmaster-startup` 换正文**：地址不变，描述与 `when_to_use` 要改成「新人引导」；老用户如果只想迁移，需要一条跳过前两块的入口（[technical-design](../versions/v71-onboarding/technical-design.md) §开放问题）。
- **`skillmaster-guide` 的 `start/agent.md` 也跟着改**：它原来把 `startup` 说成「走一遍迁移」，并拿「打招呼 → 问他传不传」当完成信号；这一版已改成三块主线，发布顺序上 guide 的 patch 排在 startup 之后。
- **仓库多一份源**：`skills/skillmaster-startup/` 进仓库，发布仍走 `skmr skill submit`；与 `skillmaster-guide` 同一做法（[0174](0174-two-help-layers.md)）。
- **公开库的默认动作变清楚**：`join` 是第一选择；`copy` 不在引导里教，留给 guide 的 `copy` 篇。这不改变 `join` / `copy` 的服务端语义，只改变引导先教哪一个。
- **卡片是正文的一部分，但形状由 Agent 定**：不同 Agent 的选项卡组件不同（Claude Code 是 AskUserQuestion），正文只写「用这个 Agent 自己的选项卡」，并保留「没有卡片时把选项写进一句话、推荐的排在前面」的兜底；新增或改动提问处时要同时给卡片和兜底。
- **没有新的 CLI 命令、没有服务端接口、没有控制台改动**；将来要加第二次上线或进度记录，需要新 ADR 或改这一条。
