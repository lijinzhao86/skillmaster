# ADR 0105 · 写进用户文件的动作先出计划，`--yes` 才落笔

- **状态**：已采纳
- **日期**：2026-10-27
- **依赖**：[`versions/v26-startup-guidance-and-agent-paths/`](../versions/v26-startup-guidance-and-agent-paths/)

## 背景

`prompt install` 在 v25 的行为是分叉的：目标文件里已经有规则段、且内容不同时，不给 `--yes` 只打印差异并退出 1；但目标文件里**没有**规则段时（也就是第一次写），它直接追加，不问。旅程里最常见的一步恰好就是第一次写。

面向非技术用户时这不可接受：用户在审批框里看到的是命令，不知道要动哪个 AI 的哪个设置、做完会怎样、不想做了怎么退。而 agent 在这个流程里是代做者，它需要一份能原样转述的材料。

当时的选项：

1. 维持 v25：第一次写直接写，替换才问；
2. 加一个可选的 `--dry-run`，默认仍然直接写；
3. **默认先出计划，`--yes` 才写**；
4. 在 CLI 里用 TTY 交互式确认。

## 决定

**凡是会改用户文件的动作，默认只出计划：**

- `prompt install` 需要写入时、`prompt update` 需要更新时、`prompt uninstall` 需要去掉标记段时，**不给 `--yes` 只打印计划并退出 1**，用户文件一个字节不变；其中 install / uninstall 打印五句话，update 打印逐文件差异；
- `--force` 只越过「不在主目录下」这一条检查，**不等于同意写入**，仍然要 `--yes`；
- 文件里已经有**逐字相同**的段时是唯一例外：不重写文件，只补记录（含 `--agent` 标签），退出 0——这不算「改用户文件」；
- `startup --plan` 本身**完全只读**：跳过「规则段旧了」的一次性提示与自动更新（两者都会写 `prompt.json` / `update.json`），自己那次版本检查只读不写；
- CLI **不读 stdin、不等 TTY**：确认就是带 `--yes` 再跑一次。

install / uninstall 的计划按五句话排：我要做什么 / 只会动到什么 / 做完会怎样 / 不想做了怎么办 / 不做会怎样。agent 把计划用同样五句话转述给人，人同意后带 `--yes` 重跑——**审批框里是什么，人看到的就是什么**。

## 理由

- **默认安全，而不是默认方便。** 一个会写别人主目录里文件的命令，不该在「没说同意」的情况下写。「默认写、可选 dry-run」把安全性放在一个 agent 可能忘记的开关上。
- **计划是请示的材料。** 非技术用户不理解命令，但理解「我要给 Codex 加一段说明，只动这个文件里的两行，不想用了可以去掉」。计划让 agent 有东西可转述，而不是自己编。
- **无头环境没有 TTY。** 交互式确认在 agent 里会挂住，或者被空 stdin 当成同意；「再跑一次带 `--yes`」是唯一在脚本与对话里都成立的形状。
- **被否的第 1 条（维持 v25）**：第一次写恰恰是最需要说清的时候——文件从「没有」变成「有」，用户却什么都没看到。
- **被否的第 2 条（可选 `--dry-run`）**：默认不安全，等于把责任推给调用方；而调用方是 agent，不是人。

## 后果

- **一次写入要跑两次命令**（先计划、后 `--yes`）。脚本与自动化必须显式带 `--yes`；不带就是「我要先看」。
- **退出码 1 不再只表示失败**：计划已打印、什么都没写也是 1。调用方要读输出，不能只看退出码；这与 v25 的 `prompt update` 一致，本版只是扩到 `install` 与 `uninstall` 的全部写入路径。
- **「逐字相同只补记录」是明文例外**：它不改用户文件，但仍会写 `prompt.json`；计划模式的承诺是「用户文件不变」，不是「磁盘不变」。
- **旅程第三步必须写明 `--yes` 两段式**，并要求先问人；CLI 侧无法替 agent 问。
- **`startup --plan` 的只读承诺要在代码里守住**：`run` 的前后钩子按命令形状跳过，不能只在文档里写。
