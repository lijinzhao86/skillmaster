# 0136 · CLI 读写命令按意图分，整份覆盖前先读

- **状态**：部分被取代（§决定 4 的放行条件由 [ADR 0177](0177-read-proof-binds-to-file-content.md) 取代；其余决定仍有效）
- **日期**：2026-11-04
- **依赖**：[v44 PRD](../versions/v44-cli-read-write-contract/prd.md)、[ADR 0068](0068-export-is-a-one-shot-snapshot.md)（整版导出是一次性快照）、[ADR 0035](0035-the-pin-lives-on-the-client-machine.md)（钉在本机）、[ADR 0101](0101-the-cli-never-deletes-files.md)（状态原地写）

## 背景

写侧有 `write`（从 stdin 读文本）与 `put`（从本地路径读、按字节存）；取侧有 `get`（一个文件）与 `download`（整版）。两组命令都是按**内容从哪来 / 数据形态**长出来的，而人真正要选的是三种意图：局部改、整文件改、整版重排。

代价已经发生：2026-11-03 改 `lijinzhao/code-dev-sop` 时，agent 刚读过「别搬回本地」，仍选择 `download` 整版、`put --overwrite` 回写 **31 次**；2026-11-04 同一份 skill 用了 14 次 `edit`、每次写两个临时文件。`--overwrite` 是一个布尔开关，只表达「允许覆盖」，不表达「覆盖的是哪一版、会改掉多少」。

## 决定

1. **`write` 收编 `put`**：`write <地址>@<版本码> <远端路径|目录/> --from <本地文件>...`，可重复；文本由服务端归一（换行 / BOM / NFC），二进制按原字节保存；多个文件时远端以 `/` 结尾，按 basename 落进目录。`put` 删除，旧名字只给一句迁移提示并非零退出。
2. **`get` 收编 `download`**：`get <地址>@<版本码> --all [--into <目录>]` 把整版写进一个空目录，沿用 `download` 的「目标目录必须为空」、`.skillmaster/metadata.json` 旁车与约 17 MiB 的内存上限；`download` 删除，旧名字给迁移提示。
3. **`@new` 退场**：建草稿是 `draft create`（[ADR 0135](0135-a-draft-may-be-copied-from-a-version.md)）；`write` / `edit` / `rm` / `mv` 只对已有版本码工作。
4. **整份覆盖前先读**：`--overwrite` 只在「本机完整读过这一版里的这个文件，且读后版本摘要未变」时放行；没读过或读后变过 → 拒绝并要求先 `read`。**没有 `--force`**。放行时先打印将改动的行数（新增 + 删除）。
   - 算数的是完整读：`read`（不带 `--offset` / `--limit`）、`cat`、单文件 `get`。`head` / `tail` / 部分 `read` / `get --all` 都不算——它们没有让你看见那一份的全文。
   - 「读过」记在本机的版本钉记录里，键是版本 + 路径，值是读时的版本 ETag；草稿任何一次写入都会换掉 ETag，旧记录随之作废。
5. **隐藏的 `--new`**：`draft create` 与 `skill submit` 在「我自己已有未上线草稿」时默认拒绝；`--new` 不写进 `--help`，只在报错里出现；报错要求「先问用户」。不做 TTY 交互确认。

## 理由

**为什么按意图分。** 文件是不是二进制、内容在 stdin 还是本地，都是数据形态；把它们做成命令的选择条件，等于让调用方先回答一个与意图无关的问题。`edit` / `write` / `submit` 才是人要选的三种改动规模。

**为什么没有 `--force`。** Claude Code 覆盖本地文件的前提是「本次会话 Read 过它」，没有「我知道，强行写」的开关。把「读过」当作许可证，比再加一个布尔开关更接近「知道自己在覆盖什么」；`--force` 只会变成习惯性的确认键。

**为什么用版本 ETag 作废记录。** 文件摘要只能说明「字节没变」，版本 ETag 同时覆盖「同一草稿里别的文件变了」——后者也意味着你手里那份不是当前草稿。代价是保守：读过一个文件、别人改了同版另一个文件，你也要重读；这是可接受的方向。

**为什么 `--new` 不是墙。** CLI 没有可靠的「人 vs agent」信号。真正的闸门只有交互终端，而 agent 可能拿到 PTY 并挂住（v44 PRD §问题 7）。所以选择「默认拒绝 + 隐藏放行 + 报错要求先问用户」：挡住顺手就建，不假装能挡住执意要建。

**为什么旧动词硬删。** 保留别名会让「两个入口都行」的混淆多活一版，而这正是本版要消除的东西。beta 阶段硬删，迁移提示足够。

## 后果

- **这是 CLI 契约的破坏性变更**：`skill put` / `skill download` 不再执行；`write` / `edit` / `rm` / `mv` 的 `@new` 形式失效。既有脚本、指南与测试要同步改，旧命令只给迁移提示。
- **`write --from` 与 `edit` 的 stdin 共用标准输入**：同一条命令不能既从 stdin 读内容又从 stdin 读编辑文本；实现按命令区分，不新增约定。
- **`get --all` 仍受约 17 MiB 内存上限**：更大的版本继续逐个 `get`。解除上限是 v39 的技术欠账（流式落盘），不在本版。
- **读记录是本机状态**：换机器、清掉状态目录、或记录损坏，都会退化成「没读过」，要求先 `read`。这只是多一步，不会写错内容。
- **不硬拦「整版取回 → 本地改 → 整份写回」**：整份重写是合法路径；降低动机靠 `edit` 的 stdin / 批量与删除 `download`，不靠禁止覆盖。
