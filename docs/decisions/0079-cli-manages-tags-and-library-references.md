# ADR 0079 · CLI 管贴法、新建、定义编辑与库引用，不管删除

- **状态**：已采纳
- **日期**：2026-10-23
- **依赖**：[ADR 0077](0077-the-cli-grammar-is-singular-and-plural.md)（CLI 按单复数分组）、[ADR 0047](0047-permissions-are-a-ladder.md)（权限是梯子）、[ADR 0048](0048-visibility-hands-out-a-rung.md)（加入不是访问门禁）、[ADR 0056](0056-dangerous-actions-are-confirmed-in-a-modal.md)（改变用户看到的东西之前先确认）

## 背景

v14 给 skill 加了三层词：**公开分类**是平台词表、每个 skill 最多一个；**公开标签**是作者的自由词、公开、用于搜索召回；**我的标签**是本人私域、只属于库。本版的 PRD 与设计稿要求控制台信息页就地贴、摘、换；标签页能新建定义、改名、写说明、删除；发现页与信息页能加入 / 移除库；库的行上显示来源（实现尚未开始）。

CLI 在本版原先只有读命令（`skills list` / `skills search` 的过滤与三条词表命令）。产品负责人问：网页上这些操作，CLI 有没有对应？无头环境里没有控制台，agent 能看见词表，却不能在用户要求时整理一个 skill 的标签、新建 / 改名一个定义、或者把一个公开 skill 收进 / 移出用户的库。

产品负责人进一步指出：**改名不算高风险**——改错了改回来就好。这个判断是对的，而且它把边界从“定义”移到了“破坏性”：改名与改说明都是可逆的；删除会摘掉所有 skill 上的贴法（含休眠的），不能恢复。

## 决定

1. **一个 skill 上的贴 / 摘 / 换进 CLI**：`skill tags <地址>` 读三组；`skill tag add` / `remove <地址> <名字> [--public]`（默认我的标签）；`skill category set <地址> <名字>` / `skill category clear <地址>`。`add` / `remove` / `set` / `clear` 是新动作，不复用 `share` / `unshare`（那是访问授权），也不另造同义词。
2. **定义的新建、改名、改说明进 CLI；删除不进**：`skills my-tags add <名字> [--describe <说明>]` 新建一个定义（不贴 skill）；`skills my-tags rename <旧名> --name <新名>` 改名；`skills my-tags describe <名字> --text <说明>` 写 / 改 / 清空说明。**删除**会摘掉所有贴法（含休眠的），仍只在控制台的红色弹窗里。
3. **加入 / 移除库进 CLI**：`skill join <地址>` / `skill leave <地址>`。加入是引用，不复制内容、不产生版本、不改变访问权；移除只删“我加入的”引用，标签休眠、重新加入后回来。**两条都要求 `--yes`**：没有它时只打印后果与完整命令，不执行。已有加入引用（含休眠）是 no-op；来源是创建 / 共享（没有加入引用）时按信息页的规则拒绝并说明。
4. **读的补充**：`skills list --source created|shared|joined`（可重复取「或」，按显示来源筛）；`skills my-tags [q]` 按名字 / 说明筛；`skills public-tags [q] [--all]` 按名字筛，默认 50 行 + “还有更多”，`--all` 取全。
5. 权限沿用梯子：分类与公开标签是所有者 / `admin`；我的标签是本人且**库条目生效**。写审计，**我的标签的审计不存名字**；本版不做 `--json`。一个 skill 上的贴 / 摘、定义的新建 / 改名 / 改说明都是可逆的，不要 `--yes`；加入 / 移除库改变的是用户的目录，要 `--yes`。

## 理由

- **无头环境没有控制台。** CLI 是 agent 的入口；只读会让 agent 只能看见词表，不能在用户要求时整理，得让用户切到浏览器。
- **边界放在“破坏性”上，而不是“定义”上。** 改名与改说明都可逆：改错了再改回来；它们只影响自己的私有标签，不删任何贴法。删除会摘掉所有 skill 上的贴法（含休眠），不能恢复，属于危险操作，留给控制台的确认与弹窗（ADR 0056）。
- **改名确实有连带，但连带是可见且可逆的。** 所有贴过它的 skill 一起显示新名字，计数不变，旧名在 CLI 的过滤里失效；网页链接用 id，不受影响。重名或撞公开分类拒绝，不做合并。
- **加入 / 移除库是引用操作，不是权限操作。** 公开 skill 不加入也能直接调用（ADR 0048）；加入只是把它放到用户的私有货架上。因为它在改用户的目录，所以要求 `--yes` 确认；移除是可逆的（标签休眠），但仍是一次目录变更。
- **来源用过滤，不用每张卡都打印。** `--source` 直接回答“共享给我的有哪些”，不增加默认列表的字节；卡片保持 L1 预算。
- **公域词表不能默认全量吐给终端。** 公开标签会随内容增长；默认 50 + `--all`，和 `skills list` 同一套截断口径。
- **权限不另造一套。** 控制台与 CLI 将共用同一套判据（随本版一起实现）；CLI 只是换一个入口，服务端仍是同一套权限与审计。

被否掉的：**保持只读**（无头环境无法整理）；**把定义的改名 / 改说明也留在控制台**（它们可逆，留在控制台没有理由）；**把删除也放进 CLI**（跨 skill、不可恢复，CLI 没有控制台的确认界面）；**加入 / 移除库不带确认**（它改的是用户的目录）；**只写我的标签**（公开标签是作者的召回词，agent 代作者整理是常见场景）；**`public-tags` 继续一次给全**（公域词表无界）；**用 `--verbose` 打印来源**（过滤更省字节，且直接回答“哪些是共享的”）。

## 后果

- v14 的 PRD、TD、test-plan 增加 `skill tags` / `skill tag` / `skill category` / `skills my-tags add` / `rename` / `describe` / `skill join` / `skill leave` 的命令、权限、确认、错误与测试；`skill help` 与 `skills help` 更新；网关 skill 写一句“用户要求整理标签或加入 / 移出库时怎么做”。
- 控制台仍是**定义删除**的唯一入口；CLI 可以新建、改名、改说明，删除要去控制台的红色弹窗。
- `skill` 组增加 `tags`、`tag`、`category`、`join`、`leave`；`skills` 组增加 `my-tags add` / `rename` / `describe` 与 `[q]` / `--all` 参数。这是一次对外契约的扩展，按 [v13 CLI 契约](../versions/v13-cli-grammar/prd.md) §9「新增命令检查清单」走。
- **标签与库**从此都有两个写入口：控制台与 CLI。两者必须共用同一套服务端用例、权限与审计，否则会漂。
