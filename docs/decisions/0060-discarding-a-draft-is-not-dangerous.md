# 0060 · 丢弃草稿不是危险动作，但它无法找回

> **状态**：已采纳
> **日期**：2026-10-20
> **依赖**：[0056](0056-dangerous-actions-are-confirmed-in-a-modal.md)（危险动作的确认方式与「染红」的含义）、[0054](0054-lifecycle-actions-happen-on-a-version-page.md)（生命周期动作在单版页上）
> **本条件取代 0056 的一处归类**：0056 把「丢弃」列进危险区，与下架、删除同档；本条把它移出来。0056 的其余决定（弹窗、取消默认焦点、染红的含义）不变，正文不改。

## 背景

ADR 0056 定下：染红表示这个动作会拿走东西，危险动作一律进页底危险区、用红按钮、弹窗确认。当时把**草稿的丢弃**和下架、删除、下线放在一起，理由是「丢弃是草稿永久失效」。

2026-10-20 用户指出这里也混了两件事：

1. **丢弃影响谁**。草稿对消费面不存在：没有任何调用者读得到它，线上指针也不动。丢弃只结束作者自己这一版——它是作者面的一个终态，不是对外能力的变化。
2. **不可逆不等于危险**。丢弃之后这一版找不回来，这件事必须说；但「说」的落点是确认弹窗的正文，不是危险区的红色。把丢弃染红，会让真正让调用者立刻失败的动作（下架）失去区分度。

## 决定

1. **草稿的丢弃不是危险动作**：它在单版页的「操作」栏里，与上线并列，按钮是描边的普通按钮（`.button.is-quiet`），不进页底危险区。草稿页因此没有危险区——页底那一块不画。
2. **丢弃仍然弹窗确认**，确认钮用普通强调色（`danger: false`），不染红。弹窗正文的第一句必须说清「这一版无法找回，也不会再出现在版本表里」；「没有发布名、不占用版本号」跟在后面。
3. **红色只留给让消费面立刻受影响的动作**：下架、下线整个 skill、删除。判断一个动作是不是危险动作，看的是「调用者会不会立刻读不到东西」，不看「它是不是不可逆」。

## 理由

**为什么「不可逆」不足以让它进危险区。** 危险区的颜色在这个界面里只承担一个含义：**调用者依赖的东西要没**。草稿没有人依赖，红在这里不传达新信息，只稀释真正危险的那几个动作。反过来，不可逆是必须被说出来的事实——所以它进弹窗正文，而且放在第一句：人点「确认丢弃」之前只该被问一件事——「你知道它找不回来吗」。

**为什么不是「留在页底但去掉红色」。** 那会让危险区的位置继续承载「不可逆」，下一次有人往里加动作时判据就更糊了（ADR 0056 拒绝「回滚留在危险区、只把确认改成弹窗」是同一个理由）。丢弃既然不影响消费面，它就该和上线一样排在「操作」的动作流里。

**被否掉：一键丢弃、不给确认。** 丢弃是终态，没有恢复入口（[ADR 0058](0058-a-version-is-readable-or-not.md) 的两轴里它落在「不可读且不回到可读」），误点一次就少一版。一次弹窗的代价远小于一次误丢。

**被否掉：把丢弃的不可逆当成警告色、另开一种颜色。** 调色板里没有警告色（`design/README.md` 记过这一点），为一个动作发明第四种颜色，比换一个位置贵得多。

## 后果

- 设计件与 `design/README.md`：草稿单版页的「操作」栏变成「上线 + 丢弃」两块，丢弃按钮描边、确认弹窗不染红，正文先说「无法找回」；危险区只剩历史版本的下架。
- v6 文档（`prd.md` §动作在哪里发生、`technical-design.md` §架构与 P1、`test-plan.md` 的界面用例）按此回写。
- 以后新增动作的归类：**影响消费面 → 危险区 + 红按钮 + 弹窗**；**只影响作者自己的东西 → 「操作」栏 + 普通按钮 + 弹窗，若不可逆就在弹窗正文第一句说出来**。
