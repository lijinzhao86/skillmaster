# ADR 0075 · 浏览器端改用 React，其余纪律照 0015 不变

- **状态**：已采纳
- **日期**：2026-10-21
- **取代**：[ADR 0015](0015-web-frontend-stack.md)（只取代「用 Vue」这一条；它的**其余七项纪律**——路由 / 状态库 / UI 组件库 / CSS 框架 / `axios` / i18n / ESLint·Prettier——**原样保留**，见 §决定 2）
- **依赖**：[ADR 0032](0032-ui-primitives-on-demand.md)（组件按需引原语——本条不推翻它的判据，只使它的**命名库**失效，见 §后果）

## 背景

ADR 0015 定下 Vue 时，浏览器端只有三个表单页（注册、登录、找回密码）。它原文写得很清楚：选 Vue「**不是技术优越性判断**」，是「在三个都很好的选项里选最不费解释的一个」。那句话在当时是真的——三个表单不值得为框架写一篇选型论文。

今天是 **39 个 `.vue` 文件、16,226 行源码、6,087 行 CSS、24 个测试文件**。0015 当初的适用范围已经不成立，需要重新回答同一个问题。

重估由三件事触发，按证据强度排：

**一、组件层的胶水已经变成债务。** ADR 0032 写下了它自己的推翻条件：

> 若某一版出现「同一批页面里有多个需要行为语义的控件」——比如一块设置区要同时有对话框、下拉、自动完成、提示——那么逐个引原语所要写的胶水代码本身会变成一类债务。**那时应当重新测量并新开一条 ADR 取代本条**。

这个条件已经触发。实测：行为型控件手写 **1,665 行**（`MenuSelect` 358、`CommandMenu` 243、两个 dialog 466、`ConfirmDialog` 133、`CodeInput`/`CodeField`/`CaptchaField`/`PasswordField` 314、`VersionPicker`/`RungMenu` 151），`aria-*` / `role` / `keydown` / `.focus()` 散在 **35 个代码文件**里（口径：`grep -rlE "aria-|\brole=|keydown|\.focus\(" src --include='*.vue' --include='*.ts'`；其中 `App.vue` 只有一处 `aria-hidden`，不计它则是 34）。ADR 0057 整篇就是在为同一件事付账——它逐条规定了「上下键、Home/End、Esc、焦点返回、`role` 与 `aria-selected` 都要自己给全」，并如实写下「它是这个替换唯一的真实风险」。

**二、这一层的生态，React 是原型、Vue 是移植。** 这不是「有与没有」的差别，是「第一等公民与跟得慢一拍」的差别：`shadcn/ui` 基于 Radix，`shadcn-vue` 基于 Reka UI；TanStack 的 Query / Table / Virtual 在 React 侧是主线；RTL 比 Vue Test Utils 成熟，而本仓库还有 9,360 行测试要写、还要写更多。

**三、移动端取决于要做哪一种。** 响应式 Web（手机 / 平板浏览器）与框架无关——设计稿**已经**覆盖了若干窄屏与平板条款（控制台断点是 1024 / 900 / 720 / 640，另有 400px 窄屏状态；首页 1000 / 720），缺的是**全部页面与完整手机形态**，那是设计工作，不是框架工作。原生 App 才轮到 React Native，而它在那一格无可替代。**这一条单独不足以支撑迁移**，但它改变了迁移的下行风险：做响应式 Web 不需要换框架，做原生 App 只有 React 这条路。

## 决定

1. **浏览器端运行时换成 React 19**（`react` / `react-dom` 19.3.1）。构建仍是 Vite（8.3.2）加 `@vitejs/plugin-react`（6.1.2），语言仍是 TypeScript（5.9.3），产物仍是纯静态文件，服务端一行不动。
2. **ADR 0015 的其余纪律原样保留**：不引路由、不引状态库、不引 UI 组件库、不引 CSS 框架、不引 `axios`、不引 i18n、不引 ESLint/Prettier。页面选择仍读 `window.location.pathname`，链接仍是真正的 `<a href>`，跳转仍是整页加载。**理由继承 0015，本文不复述。**
3. 类型检查从 `vue-tsc --noEmit` 换成 `tsc --noEmit`；测试仍是 vitest + jsdom，挂载层从 `@vue/test-utils` 换成 `@testing-library/react`（16.3.3）。
4. **这次迁移的验收标准是「一切不变」**：视觉、交互、接口形状、页面地址、界面文案，逐条与迁移前一致。迁移**不携带**任何功能改动。
5. **组件层不在这条 ADR 里定。** shadcn/Radix 那条路是第 2 条理由的由来，但「引多少、怎么引、设计稿与代码如何共用一个组件层」需要单独一条 ADR——0032 的推翻条件已触发，届时由它承接。

## 理由

**为什么换：因为要换的那个东西，Vue 侧有对应物但都在跟。** 说清楚这一点的意义在于：如果差距是「有与没有」，Vue 侧的答案是「自己写」，那是一个可接受的选项；而实际差距是「原型与移植」，自己写反而更贵——ADR 0057 已经用一整篇 ADR 证明了这笔账。而本仓库恰好走到「需要成体系的、带行为语义的组件」这一步（1,665 行、35 个代码文件）。

**为什么保留 0015 的其余纪律：因为迁移的验收是「不变」，同时改架构会让失败无法归因。** 如果这一版同时把路由换成 react-router、把状态换成某个 store，那么任何一个页面出错时，分不清是框架换坏了、还是路由换坏了。**一次只动一个变量**，是这个版本能被证明的前提。这些纪律将来该不该破，是各自的决定，不是这次迁移的搭头。

**为什么是 React 而不是 Svelte / Solid / 继续 Vue。** Svelte 的编译期语义对读代码的人多一层（0015 已经用过这条理由，它今天仍然成立）；Solid 的生态体量撑不起第 2 条理由——换过去等于用一次迁移换一个更小的池子；继续 Vue 是**成本最低**的选项，但它把第 2 条理由原样留着，且 1,665 行胶水仍然要自己写。

**为什么否掉「两套运行时共存」（React 挂在 Vue 里，或反过来）。** 39 个文件、整页加载的路由、一个全局 CSS——这个规模不需要渐进式共存，而共存会让两个运行时同时进包、两套心智同时进团队，且页面逐页切换的边界正好落在 ADR 0015 刻意选择的「整页加载」上：既然每次跳转都是整页，共存换不来任何东西。

**为什么否掉「换 React 的同时引整套组件库」。** 那会**改视觉**，而第 4 条决定要求视觉不变；更重要的是，整套库会推翻「设计稿是界面的唯一权威」——那是产品决定，不是技术改造决定。两件事必须分开排期，否则迁移出问题时无从归因。

## 后果

- **搬迁量是实数**：16,226 行源码 + 10,280 行测试。其中 **9,360 行测试（17 个文件）用 `@vue/test-utils` 挂载组件**，必须逐个重写；另有 **920 行 / 7 个文件**不直接 import Vue——但「不 import Vue」不等于「与框架无关」：`captcha.test.ts` 测的 `useCaptcha`、`session.test.ts` 测的 `useSession` 都自己 `import { ref } from 'vue'`，断言里还有 `.value`。所以**真正能原样搬回的只有 5 个文件 / 722 行**（`client` / `errors` / `time` / `validation` / `markdown`）。另有 `tests/support.ts`（122 行）是共用的测试脚手架，与框架无关，但它不在那 7 个测试文件里（`tests/*.test.ts` 的 glob 取不到它）。这不是「几天」的量级。
- **包体会变大**：React 运行时实测**约 68.9 KB gzip**，Vue 是**约 25.6 KB gzip**，净增约 **43 KB gzip**（口径见附录，两者同一测法；两次测量相差不到 0.2%，引用精确值时当场重测）。ADR 0032 里那张「整库约 5 倍」的表因此要重算基数。
- **`design/` 与 `src/styles.css` 在本版内必须零 diff。** 样式是全局 CSS，以类选择器为主但不止类选择器（937 个选择器里，**307 个含后代组合子**、30 个不含 class/id、10 个是属性选择器，其中 **7 个依赖 `aria-expanded` / `aria-selected`**），所以只要 JSX 输出**同一棵 DOM 与同一组属性**，视觉就成立；多包一层、少包一层、或用 Fragment 顶掉一个容器，都会静默走样而测试未必发现。**这份零 diff 是这次迁移最硬的一条不变量**：它一变，说明迁移漂了。要强调的边界是——它约束的是**本版**；如果期间发生一次真实的设计交付，本版应当停下来重新界定基线，而不是把设计改动判成迁移漂移。
- **ADR 0032 的命名库失效**：它第 2 条写的是「引 Reka UI 的那一个原语」，Reka UI 是 Vue 专用。0032 的**判据**（按需、无样式、不引整套）继续有效，**具体引哪一个**要在组件层的 ADR 里重答。
- **0015 里「TypeScript 停在 5.9.3 是因为 vue-tsc」这条理由消失**；本版仍停 5.9.3（不夹带升级），是否升到 7.x 是单独一次验证。
- **迁移期间功能开发要冻结**（或至少与新页面错开）：两套实现并存的那几周，同一处改动要写两遍，而写两遍的东西一定会漂。
- **可复用的资产比想象中少**：真正跨框架、跨端能复用的是 `src/api/`（1,973 行，**零 Vue 依赖**）加六个纯 TS 模块 `rungs` / `time` / `validation` / `version` / `markdown` / `login`（793 行），**合计 2,766 行**。12,237 行 `.vue` 与 6,087 行 CSS 在原生 App 里一行都用不上——所以「为了移动端复用代码」不是这次迁移的理由，上面第 3 条才是它正确的说法。
