# 0128 · CLI 的帮助不宣传确认开关

- **状态**：已采纳
- **日期**：2026-11-01
- **依赖**：[0056](0056-dangerous-actions-are-confirmed-in-a-modal.md)（危险动作先确认——但它只管浏览器面，见其 §后果）、[0087](0087-cli-exit-codes-are-a-public-contract.md)（退出码与错误码是对外契约）、[0127](0127-never-published-skills-may-be-deleted-by-a-credential.md)（凭据删除的确认）

## 背景

v37 给 CLI 添了 `skill delete`：它先把后果说出来，只有带上确认开关才执行。`version discard` 早就是同一形状。两条命令的帮助此前都把确认开关列在用法、参数与例子里。

帮助是复制入口。列出开关，等于把「一步删掉」放在第一条可复制的命令上——而 0056 的用意恰恰相反：危险动作要先说明后果、再确认。0056 当时明确写了自己**只约束浏览器面**，CLI 的破坏性命令是否要确认不在它的射程内；所以这条规则需要单独记一笔，而不是从 0056 推导。

## 决定

**CLI 的确认型命令，帮助不列确认开关**（`--yes`）：不进用法、参数、例子、失败码的句子。开关仍然被接受，完整命令只由命令自己在「先说明后果」之后打印出来。

目前适用的是 `skill delete` 与 `version discard`。**`skill join` / `skill leave` 不在此列**：加一条库引用、移出一条库引用不拿走任何内容，只是改变自己看得到的列表。

**判定不了时不给命令。** `skill delete` 的预检读不到作者页时，只说「没能确认它是否上线过」并给网页地址，不把带开关的命令交出去——避免一个按错误码补开关的脚本绕过「先确认可删」这一步。

## 理由

- **否掉「帮助照常列 `--yes`」**：第一条可复制的命令必须是只说明后果的那条。帮助里少写一个字面开关，换来的是危险动作不会被一步复制。
- **否掉「不接受 `--yes`，只做交互确认」**：CLI 的主要使用者是 agent，没有终端可以回答提示；确认必须是一条可以重复执行的完整命令。
- **否掉「所有确认命令一律适用」**：`join` / `leave` 不拿走东西。0056 把「红」留给拿走东西的动作，这里沿用同一条判据。

## 后果

- **帮助里看不到开关。** 想删除或丢弃的人要先跑一次、读到后果与那条完整命令，再执行。多一次往返，这正是确认。
- **机器消费者靠输出而不是帮助。** `--json` 的拒绝对象带着完整命令（`discard`）或网页地址（`delete` 判定不了时），脚本读输出即可。
- **测试侧有一张白名单。** `flagattribution_test.go` 的 `unadvertisedPerCommand` 让「命令读了开关但帮助不宣传」通过；新增确认型命令时要同时登记，否则测试会红——这是有意的。
- **错误码要能区分「缺确认」与「判不了」。** `confirmation_required` 只表示前者；后者是 `precheck_unavailable`，它的帮助下一步不承诺命令。
