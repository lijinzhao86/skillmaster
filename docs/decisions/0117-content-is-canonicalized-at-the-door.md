# 0117 · 入库前把跨系统差异统一掉

> **状态**：已采纳（2026-10-30；部分取代 [0005](0005-content-addressing.md) §后果「上传时不得改写内容」）

## 背景

[ADR 0005](0005-content-addressing.md) §后果写着「上传时不得改写内容」——不做格式化、不做换行符或编码规范化。当时的理由是保真：digest 描述的是作者上传的字节。

但同一段文字在不同系统上不是同一串字节：

- Windows 保存的 `SKILL.md` 是 CRLF，macOS / Linux 是 LF；
- 记事本可能加 UTF-8 BOM，也可能存成 UTF-16；
- macOS 输入法产生的重音字符常是 NFD，Windows 多为 NFC；
- 文件名有大小写差异（`A.md` / `a.md`）、Unicode 归一差异、Windows 不允许的字符与保留名。

后果是具体的：**同一段文字在 Windows 与 macOS 上提交会得到两个 digest**，成为两版看起来一样的内容；编辑与对比时显示「全文件都变了」；而文件名问题要到下载那一刻才暴露——在 macOS / Windows 上，`A.md` 与 `a.md` 解压时**静默覆盖**，用户少一个文件且毫不知情（2026-10-30 实测：`unzip` 报两条 extracted、退出码 0，目录里只剩一个）。

两个方向：继续保真（接受跨平台不一致，把问题留给下载方），或在入口统一（改字节，换取一致性与可还原）。

## 决定

**在写入口把差异统一掉。** 具体：

- **文本**：CRLF / 单独 CR → LF；去掉 UTF-8 BOM；带 BOM 的 UTF-16 转 UTF-8；Unicode 统一 NFC。二进制与 `.bat` / `.cmd` 原样。
- **路径**：路径段统一 NFC；归一后碰撞、大小写碰撞、Windows 非法字符与保留名、段尾的空格与结尾的点、路径过长 → **拒绝**，并说清哪条路径、为什么、怎么改。
- **打包垃圾**：`__MACOSX/`、`._*`、`.DS_Store`、`Thumbs.db`、`desktop.ini`、`~$*`、`.git/`、`.svn/` 丢弃并报告。
- **四个写入口共用**：zip 上传、`write`、`edit`、从底稿建草稿。
- **旧版本不回写**：线上与历史版本保持原样（[ADR 0064](0064-a-draft-may-change-a-published-version-may-not.md)）；旧内容在复制成草稿再改时自然归一。
- **读取路径仍原样服务存储字节**：归一化只发生在写入时，不发生在读取时。

## 理由

- **「同一份内容」必须真的是一份。** 内容寻址的前提是可复现；跨平台不一致会让同一份东西算成两版、无谓地多出草稿、让 diff 失真。
- **文件名的问题不能留到下载那一刻。** 大小写碰撞是**静默丢失**：解压成功、退出码 0、文件少一个。作者改个名字的成本，远小于用户事后发现链接断了。
- **拒绝比警告可靠。** 「接受但警告」把问题推迟给下载者，而那时作者不在场、无法修；平台承诺的是「谁下载都能原样还原」。
- **统一发生在入口，只发生一次。** 读取路径继续原样服务字节，digest 与内容仍然一一对应；审计记录这次归一化了哪些文件。

## 后果

- **取代 [ADR 0005](0005-content-addressing.md) §后果里「上传时不得改写内容」这一句**；内容寻址、digest 算法、幂等、blob 回收都不变。
- **digest 描述的是归一化之后的字节**，不是上传时的那一串。这是本决定的代价，也是它的目的。
- 旧版本不重写：已经入库的 CRLF / BOM 内容保持原样，digest 不变。
- `.bat` / `.cmd` 例外：cmd.exe 对只有 LF 的批处理可能出错，这两个扩展名按二进制对待。
- 拒绝的原因码与句子要同时出现在 CLI 与网页；控制台的展示以 `design/voice-spec.md` 为准，需要先补设计稿。
- 若将来要放宽（例如「可见失败的文件接受但警告」），需要一条新 ADR 取代本条的相应部分。
