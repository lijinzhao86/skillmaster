# ADR 0092 · 本机副本在平台已可用、且已备份之后才下线

- **状态**：已采纳
- **日期**：2026-10-25
- **依赖**：[`versions/v17-cli-startup/`](../versions/v17-cli-startup/)（旅程第四步）、[ADR 0089](0089-no-local-skills.md)（本机不装 skill）、[ADR 0090](0090-batch-publish-confirms-once.md)（批量上线）

## 背景

v17 原先把「处置本机副本」整条推迟：搬上去的全是草稿，`skills list` 默认只列 live，此时撤掉副本等于把用户仅有的可用副本收走。推迟的前提是「上线要逐个点」，而一次旅程要搬几十个 skill。

v18 交付了批量上线：控制台可以一次确认放行所选草稿。于是「平台已经可用」不再是几十次点击之后的事，而是**一次操作之后**的事——处置本机副本可以回到这段旅程里。

剩下的问题是**删除的安全模型**。三个候选：

1. **用户确认就全删**——带 `--yes` 就把扫描到的本机副本全部删掉。
2. **只删平台上已 live 的**——逐条核对，草稿保留。
3. **不删，改成指针**（本机留软链指向平台缓存）。

## 决定

1. **旅程顺序固定为**：登录 → 搬运 → **控制台批量上线（人做）** → **写系统提示词** → **验证** → **下线本机副本**。提示词在倒数第二步、下线在最后一步：提示词是「以后都从平台取」的开关，**先切换、验证新路径能用，再拆掉旧副本**。顺序反过来的话，提示词一旦写错或规则跑不通，人手上已经零副本、agent 也不认识平台，只能从备份包往回捞；按这个顺序，验证没通过时本机副本原封不动，提示词还能用 `.bak` 退回。
2. **只删平台上已 live 的同名 skill，而且只要还有一条同名 skill 是草稿，整批一条都不删**（候选 2，2026-10-25 收紧）。停在「下线之前」：草稿还在，说明平台还没准备好，此刻删掉已上线的那些会让人手上剩下「已删的副本 + 不可用的草稿」。判据是服务端的状态，不是用户的复述。平台上根本没有的本地 skill 保留并报告，不阻塞——它们从来不在这次迁移里。
3. **删除之前先打包**：本次扫描到的**全部**本机 skill 原样进一个 `skills-backup-<时间戳>.zip`，放在 `~/.skillmaster/` 下。包内路径是本机绝对路径去掉开头的 `/`，`unzip -d /` 就回到原位。
4. **备份的范围是「现有的本地 skill」，不是「将被删的那些」。** 打包发生在核对之前，不做第二次筛选：范围一致、可解释，且核对或删除中途失败时，包里仍是完整的原始状态。
5. **下线只有一种形状：备份后删除**（候选 3 被否）。`skillmaster skills retire [<目录>…]`，不带 `--yes` 只打印清单与完整命令；同意的表达方式与仓库既有约定一致（`version discard`、`skill join` 同款）。

## 理由

- **候选 1 会重演这条旅程要消灭的损失。** 用户很容易只上线一部分就回来跑下线——一次确认单里漏勾几条，或者批量发布里有几条失败。全删之后，那几条既不在平台上（草稿不可用），也不在本机（被删了），用户手上只剩一个还没意识到的 zip。这也是为什么旅程把**验证**放在下线之前：旧副本还在的时候，任何一步都还能退回。
- **候选 3 不是省事的替代，而是另一个产品形态。** 指针化要求平台侧有一份可离线随取的本地缓存，还要处理缓存失效、版本漂移与跨机器一致性；它换来的「本机还有一份」正是本版要清掉的那样东西。备份已经给了「需要时能拿回来」，不需要再用软链维持一份活副本。
- **备份做全量，是因为筛选的成本高于收益。** 只备份将被删的那些，要求先完成核对、再打包、再删除，中途任何一步失败都要重算范围；全量打包一次完成，包的含义也简单：**这台机器上原来有什么**。
- **删除留在 CLI，是因为删的是本机文件。** 平台上的删除（skill / 版本 / 标签）按 [ADR 0031](0031-submitting-and-publishing-are-two-actions.md) 与 [ADR 0046](0046-deleting-a-skill-happens-in-the-browser.md) 留在浏览器面；本机目录不归平台管，[ADR 0081](0081-every-console-operation-has-a-cli-command.md) 的映射表不适用。

## 后果

- **本机多一个新目录** `~/.skillmaster/`，只放备份包。**包不会自动清理**——它可能几十 MB（`~/.claude/skills` 的样本 33 个 skill），由用户自己删；CLI 在汇总里打印它的路径与大小。
- **`retire` 需要联网**：live 状态只能问服务端。断网时它拒绝执行，不猜。
- **同名不同内容的本地副本会被删。** 判据是名字 + live，不比对内容；真正的兜底是备份包。这一点在 `retire` 的清单里如实写出来。
- **有草稿时 `retire` 整批拒绝**，所以「跑两遍」不是 Partial 的补丁：先把草稿全部上线，再跑一次，才删得干净。平台上没有对应条目的本地 skill 会一直留着，汇总里逐条列出。
