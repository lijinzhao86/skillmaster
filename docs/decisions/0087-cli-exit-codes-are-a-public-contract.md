# ADR 0087 · CLI 的退出码是公开契约

- **状态**：已采纳
- **日期**：2026-10-24
- **依赖**：[`versions/v16-cli-help/prd.md`](../versions/v16-cli-help/prd.md)（做 #5 定义这三类；验收 #9–#11 给它们各自的可复现场景）

## 背景

今天 `skillmaster` 的失败几乎都是 **1**。`skill grep` 有 **2**，但它把认证失败（`files.go:507`）与服务端拒绝（`files.go:514`）也报成 2，所以「2 = 用法错误」在这台机器上并不成立。`internal/credentials` 的读取失败、`SKILLMASTER_API_KEY` 填错、服务端 401，最后都收敛成同一个数字。

这个 CLI 的主要调用者是 agent 与 CI。失败之后要回答的第一个问题是：**该改命令、该换凭据，还是该重试？** 一个数字答不了，于是每一处调用方都只能去读中文错误串——而错误串是给人看的，措辞一变脚本就断。

候选有四条：

1. **保持 0 / 1**——最省事，但把判断留给读文案的人。
2. **0 / 1 / 2**：2 = 用法错误——能分开「命令敲错了」，分不开「凭据该换了」。
3. **0 / 1 / 2 / 4**：2 = 用法错误，4 = 凭据不可用且重试无用——本次采纳。**码的取值与 GitHub CLI 相同，含义按我们自己的失败分类定**（gh 的 2 是「取消」、4 是「需要认证」；这里 2 是「命令敲错了」、4 是「要换一份凭据」）。
4. **sysexits（64 / 65 / 77 …）**——为「数据格式错」「权限不足」这类 Unix 工具的问题设计，我们的失败里没有对应的稳定分类，而且 agent 不认识这些码。

## 决定

1. **`0`** 成功；**`1`** 普通失败（含可重试的失败）；**`2`** 用法错误（命令或参数本身不对）；**`4`** 凭据不可用，且重试无用——**要换一份凭据**。
2. **判 4 的只有三类**：① 命令带了 `--no-login` 且本机没有凭据；② `SKILLMASTER_API_KEY` 不是一把 key（判据是既有的 `apikey.IsKey`）；③ 服务端 401 且码是 `unauthenticated` / `token_idle` / `token_expired` / `token_revoked`。
3. **其余一律 1**，包括 `account_suspended`（换凭据也没用，要换的是账号）、登录流程本身失败（可重试）、本机有凭据但读不出来（修环境比重登更对）、401 没有码或码未知。
4. **优先级：帮助（0）→ 用法校验（2）→ 认证（4 / 1）。** 一条既写错地址、又没有凭据的命令报 2。
5. **码表只有一份**：`internal/help` 里的 registry 是权威，顶层帮助与 `skillmaster-cli/README.md` 都是它的投影，测试比对三处。
6. **`--json` 的错误对象形状不变**，`code` 仍是服务端 / CLI 的既有词汇；**退出码是另一根轴**，不改变对象内容。

## 理由

- **2 与 1 分开，是因为下一步不同。** 参数敲错，下一步是看 `--help` 改命令；服务端 500，下一步是重试。今天两者都是 1，agent 只能把整条命令重来一遍。
- **4 与 1 分开，是因为动作不同。** 「换一份凭据」是重新登录、续期或新签，重试再多次也不会变；而网络抖动重试就会好。把这两件事压进 1，等于让调用方每次都去读文案猜。gh 的 4 就是同一件事。
- **4 故意定得很窄。** `account_suspended` 重试无用，但换凭据也无用——能救它的是账号本身，不是一个凭据动作；登录失败则是可以重试的。把它们算进 4，等于告诉调用方一个做不到的下一步。
- **被否的第 2 条**（只有 0/1/2）保留了 grep 今天最大的问题：认证失败和用法错误同码，而这正是本版要修的那处缺陷；只把 grep 改对而不把 4 定下来，等于让它独特的编码消失。
- **被否的第 4 条**（sysexits）不是坏设计，是不匹配：它的码对应文件与权限这类 Unix 语义，我们没有稳定的映射，而且每加一个码都要再决定一次。

## 后果

- **每一条失败路径都要被分类**：到今天为止，39 处纯 `errors.New(<用法串>)`、38 行引用用法串的 `fmt.Errorf`（grep 口径，不是调用数）（其中一部分不是用法错误）、以及只写句子的用法错误（如 `versionInAddress` 的 `@` 拒绝）、grep 的 `exitError{2}`、凭据读取失败，都没有类型；这一版把它们变成 `usageError` / `credentialError` / 原样错误，由 `reportError` 一处决定退出码。
- **依赖「非零就是 1」的脚本会看到 2 与 4**。两处公开说明（顶层帮助与 CLI README）要同步，验收 #19 比对三处。
- **`--no-login` 从此不只是「别开浏览器」**：它是「本机没有凭据」这一类产生 4 的唯一入口（另外两类 4 是 key 形状不对与四个 401 码）；不带它的命令在**能开浏览器时**照旧先自动登录，登录失败仍是 1；不能开浏览器时直接返回「没有凭据」，也是 1。
- **服务端零改动**：401 的四个码本来就在服务端的 `ErrorCode.java` 里（`TokenValidation.Rejected` 只是它们的白名单）；这一版只是让 CLI 把它们映射成退出码。
- **`skill grep` 的「没有命中」保持 1**（`files.go:538` 的 `exitError{code:1}`），与普通失败同码。它是既有的、被脚本依赖的行为，这一版不改；要分开「没找到」与「该重试」，看消息里的「没有命中」，或将来给一个自己的码——那需要另一条 ADR。
