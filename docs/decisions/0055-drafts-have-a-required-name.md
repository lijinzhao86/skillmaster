# ADR 0055 · 草稿有一个必填的名字，与说明和发布名分开

- **状态**：已采纳
- **日期**：2026-10-19
- **依赖**：[ADR 0031](0031-submitting-and-publishing-are-two-actions.md)（提交与上线是两个动作）、[ADR 0033](0033-version-names-are-semver.md)（版本名是 semver；发布时命名由 v6 另一条 ADR 修订）、[ADR 0005](0005-content-addressing.md)（内容寻址）

## 背景

v6 的第一稿把草稿期唯一的文本叫「自由内部名」，并明确它就是那句说明（`skill_version.changelog`）。理由是「不逼作者起名」：草稿还没有对外的版本号，多一个字段就多一次命名负担。

2026-10-19 用户指出这个说法混了两个概念：**说明是 description，回答「这一版改了什么」；名字是 name，回答「这是哪一条草稿」**。一个 skill 可以同时有多条草稿（不同内容各提交一次就是一行；v5 的 `draft_count` 测试按 1 → 2 验过），只有一段描述时，描述一长、为空或彼此相似，作者就无法在列表里指代「把 compress 补文档的那一条」。稳定身份 `draft:<id>` 能区分，但它是给人寻址的，不是给人念的。

同时，v6 已经决定正式版本号在发布时才分配（[ADR 0033](0033-version-names-are-semver.md) 的修订）。所以草稿不能拿发布名当名字，发布名也不能在提交时提前产生。

## 决定

1. **草稿有一个必填的 `draft_name`。** 提交时必须给，1–40 个 Unicode 码点，单行、纯文本；缺省或空白 → 400 `draft_name_required`，超长 → 400 `draft_name_too_long`。
2. **它是作者面的标签，不是命名空间。** 不进地址、不进 digest、不参与内容身份；草稿的地址身份仍是 `draft:<id>`。
3. **名字不要求唯一。** 两条草稿可以同名；区分靠说明、提交人、时间与 `draft:<id>`。
4. **草稿期可改名。** `write` ∧ 提交人是我，或 `maintain` 及以上；入口在草稿自己的单版页上，与改说明同一档。
5. **发布后冻结，但不消失。** 发布名 `@1.2.3` 与草稿名在作者面**分开展示**：版本表两列（发布名 / 草稿名），单版页标题是发布名、元信息行写草稿名。消费面永远不返回草稿名。
6. **旧行不编造名字。** v6 之前提交的行 `draft_name` 为 NULL，作者面该格留空；新提交必须带名字。

## 理由

**为什么说明不能兼任名字。** 说明的职责是回答「改了什么」，它天然较长、可空、可以多句；名字的职责是回答「是哪一条」，它必须短、必填、能在列表一行里读完。让一个字段同时承担两件事，就会在两端都不合适：要么名字被写成一句描述，要么说明被压成一个标签。v6 已经让说明不参与内容身份；名字同样不能参与，否则改名会变成发新版本。

**为什么必填，而不是可选 + 短 id 兜底。** 可选的名字在最需要它的时候恰好为空：多数 agent 提交不会主动发明一个名字，于是列表退回一串 `draft-7f3a`，用户仍然无法指代。必填把负担放在唯一知道「这次改的是什么」的那一端——提交方（通常是 agent，它已经要写说明）；交互式 CLI 会追问，非交互提交则必须显式给出。代价是旧的提交流程要升级（见后果）。

**为什么发布后保留、并与发布名分开展示。** 名字记录的是「这一版在开发时叫什么」，是作者面的历史；发布名是对外的契约。两者不是同一件事，发布时删掉名字会让作者在回看时失去线索。分开展示也避免把草稿名误当成对外名字——消费面根本不返回它。

**为什么不做全局唯一。** 唯一性需要额外的冲突处理与错误码，而名字只是标签；两条草稿同名仍然能靠说明、提交人与 `draft:<id>` 区分。把唯一性留到真正出现「按名字指代」的稳定需求时再说。

**被否掉：提交时就分配正式版本号。** 那会退回 v6 之前的模型——草稿占号、丢弃烧号，发布时刻反而不命名；这正是 v6 要解决的问题。

**被否掉：把草稿名做成发布名的别名。** 发布名是 semver、对外可见、一次分配不可改；草稿名是自由文本、作者面可见、草稿期可改。合并会让两套规则互相污染。

## 后果

- `skill_version` 新增 `draft_name TEXT`（可空，只有旧行为 NULL）；`V22` 迁移加列，不回填。
- 提交接口与 CLI 增加必填的 `name`；v6 之前的客户端提交会得到 400 `draft_name_required`——**读不受影响，提交必须升级**。
- 新增 `PATCH …/versions/{version}/name` 与 `UpdateDraftNameUseCase`；错误码 `draft_name_required` / `draft_name_too_long` / `draft_name_is_frozen`。
- 作者面响应增加 `draftName`；版本表增加「草稿名」列；草稿单版页增加改名动作；发布后的单版页在元信息行写草稿名。
- 验收新增 #24（`test-plan.md` T32）；旧客户端验收 #9 收窄为「读兼容、提交要升级」。
- 名字不参与搜索、索引与内容摘要；它不进 M12 的列表投影（与说明同一条边界）。
