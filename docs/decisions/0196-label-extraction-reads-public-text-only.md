# 0196 · 自动打标只读公域已发布文本，默认不外发

- **状态**：已采纳
- **日期**：2026-11-14
- **所属版本**：后续打标版（未开版；v69 只做导入平切，不含打标）
- **依赖**：[0193](0193-public-labels-are-extensible-claims.md)（标签是主张）、[0194](0194-public-labels-are-agent-produced-and-sampling-audited.md)（Agent 打标与抽样验收）
- **相关**：[`docs/research/skill-taxonomy-and-labeling.md`](../research/skill-taxonomy-and-labeling.md) §五（行业置信度与抽样做法）

## 背景

v66 的 P1 要让 Agent 自动产出分类、属性标签与 `outcome`。抽取要读 skill 正文，而正文在别人的仓库里；一读，就必须回答三个问题：

1. **谁的正文可以读？** 公域、私有、草稿都在同一张 `skill` 表里；私有的可能含作者未公开的内容，草稿可能还没准备好。
2. **读多少、发到哪？** 语义检索已经把 `name` / `title` / `description` / `when_to_use` 发给阿里云百炼（[ADR 0095](0095-semantic-retrieval-is-accepted.md) 的开关与理由），但 `SKILL.md` 正文是更大的外发面，可能包含脚本、路径、内部地址。
3. **要不要执行正文里的代码？** 标签只需要「用户缺什么」的证据，不需要运行结果；执行未知来源脚本是另一类风险。

可选的路线：

| | 做法 | 问题 |
|---|---|---|
| a | 不抽，靠上游 frontmatter | 覆盖率低；绝大多数开源 skill 不写这些字段 |
| b | 本地模型 | 无外发，但首期要自建推理与运维，质量与成本未验证 |
| c | **只把公域已发布文本发给现有 provider** | 需要明确边界与开关；正文外发面比检索大 |

## 决定

1. **只处理公域、已发布、公开的 skill。** `visibility='public'` 且 `current_version_id` 非空才入队；草稿、私有、未上线一律不发。
2. **只发文本，不执行。** 输入只有 `SKILL.md` 文本、文件清单（路径与大小）、frontmatter 的公开字段与上游仓库简介；不发二进制、不发文件内容以外的数据，不运行 skill 里的任何命令或脚本。
3. **接收方沿用语义检索的 provider**：阿里云百炼 DashScope 的兼容模式，使用同一个 `DASHSCOPE_API_KEY`；模型名与版本写进配置与每条 run 记录。
4. **默认关闭，部署级显式开启。** `skillmaster.labeling.enabled=false` 时服务不发起任何抽取调用，读接口保持 P0 的空值行为。
5. **最小留存。** 不保存组装后的完整输入；只存输入摘要 `input_digest`、提示词版本、模型版本与每条主张的证据引用（短引文 + 文件 + 行号）。
6. **正文是不可信数据。** 提示词把它当数据而不是指令；输出走严格 JSON schema、封闭词表与服务端证据校验（见技术设计）。
7. **换接收方另开 ADR。** 同 provider 换模型只需重跑金标集；把正文外发给新的接收方，是一条新的决定。

## 理由

- **为什么只读公域。** 公域内容本来就要被公开检索与展示；外发给模型不增加「谁会看到正文」的范围。私有与草稿没有这个前提，外发等于把作者没打算公开的内容交给第三方。
- **为什么只发文本。** 标签的证据是「用户要准备什么」，读命令与前置条件就够；执行代码既不能提高证据质量，又会把攻击面从「读一个文件」扩大到「跑一段未知脚本」。
- **为什么沿用现有 provider。** 密钥、网络、数据驻留与故障处理已经为检索解决过一次；新供应商要多一套凭据、合规评估与运维。代价是抽取质量受限于该 provider，用金标集验收。
- **为什么默认关闭。** 外发是部署选择，不是代码默认行为；关闭时产品仍然可用（标签为空，列表显示描述），与 P0 的契约一致。
- **为什么最小留存。** 正文已经在源仓库里；平台只保存「哪一句话支持了哪条主张」，既够审计，也不再造一份正文副本。

被否掉的：**不抽 / 只映射 frontmatter**（覆盖率低）；**本地模型**（首期没有质量与成本证据，运维是新负担）；**执行 skill 代码取证**（攻击面扩大且对标签无增益）；**默认开启**（未经部署方同意的外发）；**保存完整抽取输入**（多一份正文副本，隐私与存储都没有收益）。

## 后果

- **新增配置与开关**：`skillmaster.labeling.*` 默认关闭；开启前必须完成金标集与影子期。
- **抽取只对公域**：私有与草稿的标签为空，作者仍可自己选分类；这与 [ADR 0193](0193-public-labels-are-extensible-claims.md) 的「公域由平台生产」一致。
- **证据可审计**：每条 `skill_label` 与 `outcome` 带短引文、文件与行号；引文必须能在被评估版本里找到。
- **provider 变更**：同 provider 换模型走金标集回归；换接收方需要新的 ADR。
- **提示词注入**：这条决定不解决注入本身；技术设计用严格输出、封闭词表与证据校验兜底。
