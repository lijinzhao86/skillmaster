# ADR 0031 · 提交与上线是两个动作

- **状态**：已采纳
- **日期**：2026-10-06
- **依赖**：[ADR 0001](0001-server-authoritative.md)（服务端权威）、[ADR 0005](0005-content-addressing.md)（内容寻址与幂等发布）、[ADR 0012](0012-addressing-and-version-pinning.md)（寻址与版本钉）
- **修订**：ADR 0012 §决定 5「v1 不做草稿，也不做废弃」与 §理由 里「为什么 v1 不做草稿」那一节。**该 ADR 正文四段保持原样**，改动记在这里。

## 背景

实现里**提交与上线是同一个动作**：`POST /api/v1/skills` 收一个 zip，在同一个事务里插入一条 `skill_version` 并前移 `skill.current_version_id`，而搜索与详情都经这个指针读。于是「把一个版本变成对外生效的版本」不是一个动作，是上传的副作用——**上传成功的那一刻，agent 就能取到它**。

要拆开时有三个选项：

1. **保持现状**：提交即上线。
2. **给发布加一个「是否上线」开关**（`?live=false` 一类），不做状态，只做动作。
3. **把两个动作分开**：提交产生版本并停在草稿态；上线是另一个动作、另一条路径。

## 决定

1. **`submit` 产生一个 `draft` 版本，不动指针。** 目标是**一个 skill 名称**（zip 里 frontmatter 的 `name`）：没有这个 skill 就建它，有就往它名下加一版。同一个 skill 名下可以多次提交。
2. **`publish`（上线）把某一版变成对外生效的版本**：指针前移，该版转 `published`。它是**另一个动作、另一条路径**，且**只在浏览器面存在**（§4.1 的 `/web`，会话 + CSRF）。
3. **版本有三态**：`draft` / `published` / `discarded`，是**显式的一列**，不从时间戳推断。「**当前生效**」由 `skill.current_version_id` 说，**不塞进状态**——被顶替的版本仍然是 `published`。
4. **上线可以指向一个已经上线过的旧版本**（指针回移）。那就是回滚，v1 因此提前拿到了它。
5. **丢弃只对 `draft` 生效**，一票不可反悔；行与字节都留着。
6. **重复内容不产生新版本**（ADR 0005 原样成立）。「每次提交产生一个版本」的准确说法是「每次**不同内容**的提交」。
7. **网关是唯一的例外**：它由服务端在启动时自己提交并上线——没有人会给它点。
8. **可见性按面分，不按人分**：消费面（`/api/v1`，Bearer）只看得到 `published` 的版本；作者面（`/web`，会话）看得到自己的全部版本。
9. **`skill` 行是「当前上线版本的投影」**：`title` / `description` / `frontmatter` 只在 promote 时写入。

## 理由

**为什么不是「保持现状」——也就是回答 ADR 0012 §决定 5。** 它当初否掉草稿的理由是：v1 里所有 skill 都是 `private`、只有作者能读，所以草稿与已发布**在可见性上没有任何区别**，为一个不存在的差别引入一张表、一条状态机、一处 GC 集成不划算。

那个论证有一条隐含前提：**消费者是另一个人**。今天不是——消费者是**作者自己的 agent**，它拿着同一个账号的令牌经 `/api/v1` 读。于是 `submit` 一跑，半成品立刻可被那个 agent 取用：作者在写第九版的时候，agent 可能已经照着第八版半成品把任务做完了。**「可见性上没有区别」这句话在「自己也读」的时候正好反过来**：区别不在「谁能看见」，而在「**哪个面**能看见」。

**为什么给版本加状态，而不是另开一张草稿表。** ADR 0012 §后果 与 `model.md` 都记着同一个坑：草稿若另立一张表，`BlobGc.sweep()` 算的是 `SELECT DISTINCT blob_sha256 FROM version_file`，**下一次发布就会把只被草稿引用的字节删掉，而且不报错**。草稿就是普通 `skill_version` 行时，`version_file` 照样引用着它，这个坑**不存在**——不需要让 GC 认识一个新概念。这是这个形状相对「另立一张表」的硬优势，不是偏好。

**为什么状态要显式一列，而不是从时间戳推。** 同 [ADR 0029](0029-an-authorization-revocation-is-a-state.md)：靠推断维持的不变量会自我维持地漏，`discarded` 尤其无法用时间戳表达。

**为什么上线必须能指向已经上线过的旧版本。** 两条。一是**网关**：它的源文件回退到某个旧提交时，提交是幂等的（同 digest 不产生新版本，ADR 0005），而 §5.2 要求服务中的网关与运行的服务一致——指针必须能回移，否则服务端要么在说谎、要么起不来。二是**回滚本来就该是这个形状**：既然上线是一个动作，回移与前进就是同一个动作的两种取值。§7 原把「回滚」排给 P2，这里如实把它提前。

**为什么上线只在浏览器面。** 上线改变 agent 能读到什么，所以它要一个刻意的人工动作；而浏览器面的写请求同时受会话 cookie（HttpOnly）与双提交 CSRF 令牌保护，是三个面里唯一能承载「一个人当场确认」的。CLI 那条路因此**只给深链、不带任何凭据**：能跑 CLI 的人不该因此获得上线的权力，否则「高风险动作」只是换了个措辞。

**为什么 `skill` 行的元数据只在 promote 时写。** 那三列是搜索热路径读的东西。若提交时照旧写它们，提交 v2 会立刻改掉消费面的标题与描述、而正文还是 v1——**等于提交已经部分上线了**，正好推翻这次拆分的理由。所以版本自己存一份元数据，`skill` 行退化成一棵「当前上线版本的投影」，`updated_at` 也只由 promote 推动。

**为什么把「是否上线」做成参数是错的。** 那会让它变成一个默认值问题：任何一处忘了传、任何一次重构把默认值写反，都变成一次静默的上线。做成另一条路径、另一个端点，是让「谁能触发它」由**面的边界**回答，而不是由参数回答。

**被否掉：提交即上线 + 事后撤回。** 那要求已经取走字节的客户端配合，而 [`model.md`](../architecture/model.md) 与 [`target/design.md`](../target/design.md) 都写着同一件事——**内容一旦落到客户端就收不回**。

## 后果

- **`skill_version` 加 `state` 与 `state_at` 两列，并让版本自己存一份元数据**（`title` / `description` / `frontmatter`）；`published_by` / `published_at` 改名成 `submitted_by` / `submitted_at`（留着 `published_*` 指「提交」就是说谎的列名）。V1 里「Never updated, only inserted」那句表注释与 `current_version_id` 的列注释随之订正。**内容仍然不可变**：`state` 不进 digest、不改地址、至多由 draft 转出一次。
- **消费面的每一次读都必须带 `state = 'published'`**：省略版本时解析 `current_version_id`（它是 NULL 现在是**正常态**，不再是「不变量被破坏」）；显式 `@N` / `@sha256:` 也要求那一版是 `published`。写漏了，「v1 已上线、v2 刚提交」时 `@2` 会直接把没人批过的内容发出去。**指针非空却指向非 `published` 的版本仍然抛**——那是应用写不出来的状态，「bug 要响，miss 要静」。
- **迁移必须给已有行回填 `state = 'published'`**：在这个决定之前，每个版本都是插入即上线。不回填，每个已有的 `@N` 都会开始 404，而那正是 ADR 0012 存在的意义。
- **验收链路中间多了一个人**：干净环境里 agent「自己搜到、读到、用到」之前，必须有人上线过一次。这是产品判断，`prd.md` §验收照实写。
- **`submit` 不再改消费面的任何东西**——标题、描述、`updated_at` 都不动。这是这次拆分的核心断言，要写成测试。
- **CLI 的写命令从 `publish` 改名 `submit`**；`publish` 此后只属于网页。§4.6 与 CLI 的 README 跟着改。
- **新增一条依赖**：行级 diff 用 `io.github.java-diff-utils`（Apache-2.0），只在 M9 里用到。diff 是作者面才有的读法，消费面不提供。
- **回滚提前到 v1**：§7 的 P2 清单里划掉它。
- **一条要还的债**：`discard` 只标记不删，被丢弃版本引用的字节在 v1 永远留着（v1 本来一次都删不掉东西）。版本裁剪仍归 P2。
