# ADR 0106 · 安装清单按实际状态重算，不记进度

- **状态**：已采纳
- **日期**：2026-10-27
- **依赖**：[`versions/v26-startup-guidance-and-agent-paths/`](../versions/v26-startup-guidance-and-agent-paths/)

## 背景

`skillmaster startup` 是一条多步旅程：小工具、登录、传技能、正式上线、让 AI 先来 SkillMaster 找技能、让 AI 用 SkillMaster 自己的文件夹、电脑上原来的那份。第一次安装的人可能做到一半停下，第二天再来；也可能在这一台机器上做过几步，换了一台机器；也可能某一步被外部改变（CLI 自己更新了、别人帮他传了技能、他已经在网页上点了上线）。

如果用一个 `progress.json` 记「做到第几步」，它立刻带来三个问题：记录与事实会漂移；中断、换机器、外部改变时不知道信谁；多一个需要迁移、需要清理、会损坏的状态文件。

当时的选项：

1. 记一份本地进度文件；
2. 把进度存到服务端；
3. **每次按本机与平台的实际状态重新计算清单**；
4. 每次问用户「你做到哪了」。

## 决定

**不存进度。** `startup --plan` 每次都从可观察的事实重算七项：

| 项 | 事实来源 |
|---|---|
| 小工具 | 当前二进制的版本与是否有更新 |
| 登录 | 本机凭据；有凭据时问服务端这个账号是否有效 |
| 传技能 | 本机技能目录的扫描结果 |
| 正式上线 | 服务端的待上线队列与可见技能列表 |
| 让 AI 先来 SkillMaster 找技能 | `prompt.json` 的记录 + 目标文件里的标记段 |
| 让 AI 用 SkillMaster 自己的文件夹 | 本机有没有要清理的副本；CLI 读不到 agent 的权限设置，所以只给提醒，不断言已加 |
| 电脑上原来的那份 | 本机技能目录里与平台上已上线名字相同的目录（可选） |

每步做完重新跑一次，报「还差 N 件」；已完成收成「已经好了（M 件）」；跳过项单列；未知项写「登录后检查 / 暂时读不到」，**不参与已完成计数**，也不说成 0。清单打印即退出 0（包括「先登录」），只有完全算不出来才 1。

## 理由

- **事实只有一个来源。** 能做到就是能做到，不需要另一份文件说「他做到第几步」。重算不会漂移，因为它没有副本。
- **中断与换机器是常态。** 用户可能第二天再来、可能在另一台电脑上；一份本地进度文件在这两种情况下要么过期，要么不存在，而实际状态一直在那里。
- **外部改变会被正确吸收。** CLI 自更新、网页上点了上线、别人帮忙传了技能——这些都不经过我们的进度文件，但下一次重算会看见。
- **被否的第 4 条（问用户）**：用户恰恰是不知道「还差什么」才来跑的；把这个问题还给他，等于没有解决第一个问题。
- **被否的第 2 条（服务端进度）**：多一套写接口与状态迁移，而它记的仍然是「我们以为的进度」，不是事实；未登录时还读不到。

## 后果

- **每次清单都要做只读的状态收集**：本机扫描、凭据读取、最多两个有超时的服务端请求（账号与待上线/可见列表）、一次有超时的版本检查。预算 5 秒 p95；任何一段超时只把对应项写成「暂时读不到」，不拖住整张清单。
- **清单必须诚实标注未知**：没登录写「登录后检查」，断网写「暂时读不到」；不能把未知算成 0，也不能猜。
- **没有「继续上次」的指针**：下一步永远是清单里第一个待做项；这是有意的——它总是对的。
- **「已经写进全局记忆」由 agent 告知，不是清单项**：CLI 不能验证 AI 是否会在新任务里加载它；写完只告知用户，不把这件事做成待做项，也不要求重启。
- **清单的读操作不能有副作用**：它跳过的两个「顺手写一下」的钩子（规则段旧了的一次性提示、自动更新）见 [ADR 0105](0105-writing-to-a-user-file-starts-with-a-plan.md)。
