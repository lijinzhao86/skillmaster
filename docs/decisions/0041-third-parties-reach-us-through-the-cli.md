# ADR 0041 · 第三方走我们的 CLI 进来，本版不做 MCP 适配器

- **状态**：已采纳
- **日期**：2026-10-15
- **依赖**：[ADR 0003](0003-api-primary.md)（API 是主契约，MCP 是可选适配器，按需再加）、[ADR 0038](0038-default-credential-is-an-api-key.md)（第一方的默认凭据是自己签发的 API key）、[ADR 0040](0040-api-key-in-the-cli-now-the-browser-path-later.md)（本版 CLI 只从 stdin / 环境变量收 key）
- **不改**：[ADR 0003](0003-api-primary.md) 的结论（MCP 仍是可以按需加的适配器，接口形状仍然刻意对齐它）。本文只是把「谁来用 API」这一句说清楚

## 背景

v1 的设计里有两个「客户端」的位子：**CLI** 和**将来的 MCP 适配器**。凭据换成 key 之后（0038），一个之前没被问过的问题浮出来了：**一个不是我们的第三方 agent——别人的 Claude Code、Cursor、自研的 agent、CI 里的一段脚本——怎么接进来？**

摆在桌上的两种答法：

- **给它一条独立的路**：写 MCP 适配器（或一个 SDK），让第三方宿主「原生」发现并调用我们的 skill。这需要 CIMD、需要跟着 MCP 的修订走。
- **让它用我们已经有的那条路**：装我们的 CLI，拿一把 key。

而 [`prd.md`](../versions/v2-credentials/prd.md) 里原先那句「**第三方接入本身仍是 P2**」把这件事说错了——它把「MCP 适配器」和「第三方接得进来」当成了同一件事。

## 决定

1. **第三方 agent 通过我们的 CLI 接入**：装 CLI（`setup` 装网关 skill）、拿一把 key（`login --with-key` 或环境变量）。**就是第一方那条路，同一套命令、同一种凭据**，不为第三方新开 SDK，也不新开登录方式。
2. **本版不做 MCP 适配器，也不做 CIMD**。这与 [ADR 0003](0003-api-primary.md) 一致——MCP 仍是「按需再加」的那个适配器，不是这一版欠下的东西。
3. **OAuth 那条路仍然留着**（0038 §决定 8）。但它在**本版没有第三方宿主在用**：唯一走它的是 CLI 不带参数的那个 `login`——那是 [ADR 0040](0040-api-key-in-the-cli-now-the-browser-path-later.md) §决定 5 定下的过渡形态，将来会被「点一下、铸一把 key」替换掉。
4. [`prd.md`](../versions/v2-credentials/prd.md) 那句错话**就地改掉**（版本尚未实现，属定义阶段）。

## 理由

- **为什么 CLI 够。** 一个第三方 agent 跑在**有 shell 的地方**——这几乎是「agent」这个词的当前用法。而 CLI 正是 v1 里那个**覆盖所有能被脚本驱动的地方**的客户端（[`v1-hosting/technical-design.md`](../versions/v1-hosting/technical-design.md) §1.7 的结论：MCP 的宿主支持矩阵大面积空白，而 CLI 不挑宿主）。所以第三方接入不需要新机制，只需要**把已有机制说清楚是给谁用的**。
- **为什么 MCP 适配器买不到它看上去能买到的东西。** MCP 的三条硬边界（v1 的技术设计里核过）：**skill 是宿主特性，MCP 无法注入 skill**；resources **不会自动注入**，只在模型主动列举或用户点名时可见；prompts **对模型完全不可见**。合起来就是：MCP 适配器**只能把同一批文本当作工具结果返回**——而 CLI 已经在做这件事，并且**原生地**做（网关 skill 就是给宿主读的）。为一件「拿到了也不能自动装上」的体验，去承担一份协议 churn 与一份兼容矩阵，不划算。
- **为什么现在把它写成一条决定。** 因为不写，就会有人（包括下一步实现的我）按 PRD 那句「第三方接入是 P2」把这一版做成「第三方接不进来」。**这个仓里已经有过一次同形状的事故**（§2.3：一句话被读成它没有的意思），所以这里不留模糊。
- **为什么 OAuth 那条路不趁机拆掉。** 拆掉它的成本是负收益：它是已经有实现、有测试、有 ADR 的一条路，而 [ADR 0040](0040-api-key-in-the-cli-now-the-browser-path-later.md) §决定 3 将来那条「点一下」的路**就架在它的 loopback 实现上**。本版让它闲着，比让它消失便宜。

## 后果

- **没有 shell 的宿主，本版接不进来**：纯桌面客户端、手机、只提供「填一段 URL 当 MCP server」那种配置面的聊天助手。**这是这条决定真实的缺口**，而它恰好是「MCP 适配器」这个念头最初想补上的那块。本版接受它：那一类宿主目前连 MCP 的 Skills 扩展都还没支持（同上 §1.3 的支持矩阵），为它们先造一条路，是在为不存在的地基浇混凝土。
- **「OAuth 只服务第三方宿主」在这版的实际读法是**：机制留着、无人使用。**不是**「第一方不再用」——过渡期那个 `login` 还在用（决定 3）。写在这里，是为了 0038 §决定 8 那句话不会被读成与代码相反。
- **将来若真做 MCP 适配器，它仍然是薄封装**：接口形状对齐这件事在 v1 就已经做掉了（[ADR 0003](0003-api-primary.md) §后果）。这条决定没有把那份对齐作废。
- **第三方的接入文档要写**（装 CLI、拿 key、`setup`）——那是**用户可见的产物**，不是可选的附件：本版把第三方统一到 CLI 上，代价就是这条路的说明书必须写清楚，否则「统一」只存在于我们的架构图里。
