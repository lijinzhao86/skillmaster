# ADR 0182 · 所有者的「使用」页签是区间视图，平台信号不跟着变

- **状态**：已采纳
- **日期**：2026-11-11
- **所属版本**：[`v60-usage-filters`](../versions/v60-usage-filters/README.md)
- **依赖**：[ADR 0149](0149-use-is-counted-per-account-per-day.md)（按账号 × 天去重、只展示分桶）、[ADR 0152](0152-cumulative-calls-are-their-own-signal.md)（累计调用是独立信号）、[ADR 0179](0179-personal-usage-is-visible-only-to-its-owner.md)（可见性四层与 90 天窗口）

## 背景

v58 给所有者一个固定的近 90 天聚合：调用次数、使用账号数、入库人数、最近使用，以及使用者表。公开 skill 的那组数另有平台信号——**累计调用**（`skill_usage_total`，ADR 0152）与**近 30 天账号**（`skill_usage_day`，ADR 0149），都只给分桶。

v60 要给「使用」页签加时间筛选。这里出现一个口径分叉：

- 如果页签直接复用平台信号，选了「近 7 天」之后，卡片上的「累计调用」仍然是从上线到今天的总数——筛选看起来没生效。
- 如果把平台信号改成区间口径，发现页与 skill 卡片上的「1k+ 次调用」就不再是累计值，跨 skill 比较的基准变了，ADR 0152 的「累计是一份独立信号」被推翻。
- 如果不给所有者时间筛选，管理时回答不了「这个月还有没有人在用」——而采用类看板普遍是**按区间看**（2026-11-11 的产品判断，未逐家保留链接；形态见 [`prd.md`](../versions/v60-usage-filters/prd.md) §用户与场景）。

## 决定

1. **所有者「使用」页签是区间视图**：调用次数、使用账号数、最近使用、私有 / 共享 skill 的使用者表（调用次数 / 提交版本 / 最近活跃）、按版本表，全部按上方所选区间现算。公开 skill 只有聚合数卡，没有使用者表。档位是当前值，不随区间变。
2. **「入库人数」保留累计并改叫「累计入库」**：入库回答「现在有多少人在库里」，不是区间内的事件；名字把口径写清，不和区间卡读成同一段时间。
3. **平台信号不动**：结果行与 skill 页头的累计调用、`skmr skill show` 的近 30 天账号仍是 ADR 0149 / 0152 的口径，使用页签的区间数不改变它们。公开 skill 的区间聚合只给所有者、仍分桶，不暴露具体的人。
4. 同一个 skill 的页头（平台信号）与「使用」页签（区间数）可以同时出现两个不同的数；界面必须让两个口径各有名字，并在公开 skill 的说明里点明不是同一套。

## 理由

- **两个问题不同。** 平台信号回答「这条 skill 从上线到现在被用得多不多」，跨 skill 可比；区间视图回答「这段时间还有没有人在用」，用于续共享、投入维护、找回不活跃的人。用一份数答两个问题，其中一个一定答错——与 ADR 0152 否掉「用去重行数冒充累计」是同一条理由。
- **管理需要区间。** 采用类看板的时间范围不是装饰：它支撑「这个月比上个月少了吗」「改完之后有人回来吗」这类决定。累计值给不了。
- **不改公共信号，比较基准不变。** 累计值是公开面上跨 skill 比较的那把尺；把它改成区间，等于让所有已发布的比较失去意义，还要重写 ADR 0152。
- **入库是名单，不是事件。** 把它算成「区间内新入库」既要求历史成员快照，又会让使用者表的当前名单与卡片对不上；保留累计、改个名字更诚实。

被否掉的：**页签复用平台信号**（筛选对累计数无效，选 7 天与 90 天看到同一个数）；**公开聚合也按区间重算并把公共信号一起改**（动摇 ADR 0152，影响发现页与所有卡片）；**不做时间筛选**（管理场景回答不了区间问题）；**把入库人数按区间算**（与当前名单对不上，且需要历史成员快照）。

## 后果

- 同一个 skill 的页头与「使用」页签可以出现两个数：页头是平台信号的累计调用，页签是所选区间的数；近 30 天账号分桶在 `skmr skill show`，不在这两处。公开 skill 的说明里多一句「不是同一套口径」；私有 skill 的「累计入库」标签自己说明了范围。
- 服务端要为公开 skill 多一条**所有者专属、分桶的区间聚合**（调用、账号、最近使用），与现有的平台信号并存；私有 skill 的区间聚合也改读原始事件（`activity_event` / `audit_event`），因为区间要按本地自然日切、并且要包含今天。`skill_collaborator_day` 与 `ActivitySummaryJob` 保留，但不再是该页的读路径。
- 任何人再想改公共信号的口径，需要新开一条 ADR 取代本条与 ADR 0152 的相关部分；本条不阻止那种改动，只规定两套数不能互相冒充。
