# ADR 0032 · 组件按需引无样式原语，不引整套组件库

- **状态**：已采纳
- **日期**：2026-10-06
- **依赖**：[ADR 0015](0015-web-frontend-stack.md)（前端栈与「刻意不引 UI 组件库」）
- **扩展**：ADR 0015 —— 它定的「Vue 3 + Vite + TS，运行时依赖只有 `vue`，刻意不引 UI 组件库」不变，变的是**那句话的形式**：从一条禁令改成一条**带判据的触发线**

## 背景

ADR 0015 写下「刻意不引 UI 组件库」时，浏览器端只有三个表单页（注册、登录、重置），原生 `<input>` 就是正解，那句话几乎没有代价。

作者面（skill 的列表 / 内容 / 单文件 / diff，加版本选择器与 Markdown 渲染）把这些页面撑大了，于是同一个问题被重新问了一遍——**是不是该引一套成熟的组件库了？**

摆上桌的有四条路：整套组件库（Element Plus / Ant Design Vue / Naive UI / Arco / TDesign 一类）、无样式原语（headless，Reka UI 与 shadcn-vue 那条路）、现成后台模板（vue-pure-admin 一类），以及维持手写。

这次不凭印象，本机实测。

**口径**：macOS 本机，esbuild `--bundle --minify --format=esm`，`NODE_ENV=production`，`gzip -9`；每个探针只有 import，没有别的代码；探针目录在项目外，不落进 `skillmaster-web`。依赖事实取自 `npm view <包> version license dist.unpackedSize`，2026-10-06。

| 探针 | raw | gzip |
|---|---|---|
| `vue` 运行时 | 64,597 | 25,578 |
| `markdown-it` 15.0.2（渲染 `SKILL.md` 用的，**已经在用**） | 99,637 | **40,984** |
| Element Plus，10 个组件（Button / Table / TableColumn / Dropdown / DropdownMenu / DropdownItem / Tabs / TabPane / Tag / Message） | 1,006,495 | **329,161** |
| Element Plus 自己的 CSS（整份 `dist/index.css`） | 361,441 | **47,729** |
| Reka UI，9 个原语（DropdownMenu / Tabs / Tooltip / Dialog 及其子组件） | 209,910 | **75,036** |

对照：`skillmaster-web` 现在的产物是 **210,630 B JS（83.10 KB gzip）+ 9,290 B CSS（2.49 KB gzip）**，运行时依赖两个——`vue` 与 `markdown-it`，而后者自己就占 41 KB gzip。探针是「vue + 该库」的一个包，所以某个库的净代价是它减去 `vue` 那一行：Element Plus 约 304 KB gzip（另加它自己的 48 KB CSS），Reka UI 约 49 KB。

## 决定

维持「不引整套组件库」，并把它写成一条**带判据的触发线**，而不是一句禁令：

1. **现在不引**任何组件库、原语或模板。
2. 出现需要**焦点陷阱 / 键盘导航 / ARIA 语义**的控件（对话框、菜单、自动完成、tooltip、toast）时，引 **Reka UI 的那一个原语**，不引整套。MIT、无样式、`peer vue>=3.4`，用多少付多少。
3. 出现**真正的数据表格**（排序、分页、列固定、虚拟滚动）时**单独评估**一次，候选是 headless 的表格方案，不是整套组件库。
4. 日期选择器、富文本编辑器一类重控件同样**单点评估**。
5. **整套组件库与现成后台模板不在候选里**，除非满足「后果」里写的推翻条件。

## 理由

**为什么否掉整套组件库。** 两条，任一都足够。

其一，**收益是零**。作者面现在需要的控件是：一个 `<select>`（版本选择器）、一个名字列表、一批链接、两个按钮、一段 Markdown、一段 diff。这些没有一个是组件库能帮上忙的——原生 `<select>` + `<optgroup>` 就是 GitHub 分支下拉的形状，Markdown 用 `markdown-it` 而不是组件库。为用不上的东西把包体从 **约 86 KB gzip 推到约 437 KB（约 5 倍）**不划算。注意这笔账里没有一分钱是预付的：`markdown-it` 那 41 KB 确实在渲染每一个 skill 的 `SKILL.md`，而组件库那 350 KB 一行都不会被用到。

其二，**设计方向相反**。本项目的排布是照着 GitHub 定的（左侧导航栏 → skill 分栏 → 管理 tab → 名字列表 → 内容页 → 分支式版本选择器），组件库带来的恰恰是「标准后台」的外观。两者不是配色差异而是形状差异，引进来等于把已经写好的页面按库的语言重写一遍。

**为什么否掉现成后台模板。** 它是**整套替换**而不是增量：模板自带路由、状态管理、布局、主题、权限守卫。这与 ADR 0015 明确否掉的路由库、状态库直接冲突，也与「链接是真正的 `<a href>`、跳转是整页加载」冲突。它字面上是「最快部署一个主页」，实际是把已有的页面作废重来，且从此受模板的升级节奏约束。

**为什么否掉「干脆什么也不写、维持 0015 原样」。** 因为一句绝对的禁令会被下一个人**合理地**破例：他手上有一个对话框要写，而 0015 只说了「不引 UI 库」，没说「那焦点陷阱怎么办」。他要么自己手写一遍焦点管理（一个容易写错、且错在可访问性上的活），要么悄悄引进来一整套库。两种都不好。**把禁令改成触发线，是为了让破例发生在预料之内、代价最小的位置上。**

## 后果

- **手写成本是真的，并且要有人认。** 布局、chip、diff 着色、横幅全是我们自己的 CSS。这一版付得起，因为页面数量少、形状是从 GitHub 抄来的而不是自己设计的。页面数量上去以后这笔账要重算。
- **触发线是判据，不是许可。** 到点了就引那一个原语，不必把这次论证重跑一遍。反过来，没到点就不要引——「反正以后要用」不是理由，那正是预付。
- **Reka UI 不是零依赖**：它自己带 9 个直接依赖（`@floating-ui/vue`、`@vueuse/core`、`@tanstack/vue-virtual` 等，定位与虚拟滚动需要）。上表那 75 KB 已经把依赖算进去了，所以它是按原语引的**真实**价格，不是库本身的裸价。
- **表里的数字会过期。** Vue 与各库都在演进，这张表的价值在**量级**（整套库约 5 倍，按原语引约 1.6 倍），不在小数位。要引用精确值就当场重测，别抄这里。
- **推翻条件**：若某一版出现「同一批页面里有多个需要行为语义的控件」——比如一块设置区要同时有对话框、下拉、自动完成、提示——那么逐个引原语所要写的胶水代码本身会变成一类债务。**那时应当重新测量并新开一条 ADR 取代本条**，而不是硬撑。这条触发线管的是「按需」，不是「永不」。
