# ADR 0057 · 下拉一律是页面自己的菜单，不用原生 `<select>`

- **状态**：已采纳
- **日期**：2026-10-19
- **依赖**：[ADR 0015](0015-web-frontend-stack.md)（前端栈）、[ADR 0032](0032-ui-primitives-on-demand.md)（组件按需引原语）

## 背景

设置 › 协作者里的「档位」在 2026-10-18 从原生 `<select>` 换成了**按钮 + 页面自己画的菜单**：原生 `<select>` 弹出的那一层由系统画——深色底、系统蓝的高亮，`<option>` 在浏览器里没有可用的样式——它和这一页的白纸语言对不上。

但那一次只换了权限那一屏。产品的其他下拉仍是原生的：「我的 skill」的排序、文件栏的版本选择器、单版页改动栏的对比基线、线上版本的回滚目标。2026-10-19 用户在看到回滚下拉弹出深色系统菜单时指出：**所有下拉框都用权限那一屏的统一格式**。

## 决定

1. **控制台里不再出现原生 `<select>`。** 所有下拉都是同一个控件：一个按钮（`.menu-trigger`，与 `.control` 同边框、同右箭头、同尺寸）加一张页面自己画的菜单（`.menu-list` / `.menu-item`），当前项带强调色的勾。
2. **一个组件覆盖四种形态**：不分组（排序、回滚目标）、按状态分组（文件栏的版本选择器、对比基线）、含禁用项（地址钉住一版读不到的版本）、整体不可用（一版都读不到时写「未上线」）。
3. **分组名进菜单。** 版本选择器的线上 / 历史版本 / 草稿 / 已下架是菜单里的分组标题，不是原生 `<optgroup>`；禁用项灰着、不可选，但仍显示在它所属的分组里。
4. **语义与键盘照 listbox**：`aria-haspopup` / `aria-expanded` / `role="listbox"` / `role="option"` / `aria-selected`；上下键移动、Esc 关闭并把焦点还给按钮、点外面或滚动到别处收起。
5. **菜单用 `position:fixed`**：名单卡片的 `overflow:hidden` 会裁掉绝对定位的菜单；位置按触发器矩形算，下方放不下就翻到上面。长列表最高 320px，自己滚。

## 理由

**原生弹层的样式不可控，而它出现在每一个下拉上。** 系统浅色 / 深色主题、系统高亮色、圆角与阴影都由操作系统决定；一个页面里出现一块深色系统菜单，等于把产品的视觉语言交给读者的操作系统。控件本身的边框与箭头可以画，弹出的那一层不能——所以只能整块换掉。

**统一比逐个好看更重要。** 权限那一屏已经有一个画好的菜单；再为版本选择器写第二套（哪怕更贴合内容）就是第二种下拉，读者要学两次，两个组件也会各自漂移。版本选择器需要的分组、禁用项与长度上限都能在同一种菜单里表达，没有必须用原生控件的理由。

**键盘与可访问性不是换掉原生控件的代价，而是它的验收项。** 原生控件自带键盘行为；换成菜单后，上下键、Home/End、Esc、焦点返回、`role` 与 `aria-selected` 都要自己给全。这一条写进决定，是因为它是这个替换唯一的真实风险。

## 后果

- 设计件（`design/demos/dir3-hara-console.html`）里统一的 `menuSelect(groups, value, config)` 覆盖四处；权限页原来的档位下拉成为它的一个不分组的薄包装。
- 设计检查（`console-states.mjs`）按菜单读选项、分组与禁用项，并检查打开 / Esc / 焦点返回；截图里不再出现系统弹层。
- 以后新增下拉，默认用这个组件；确实需要例外的（例如富内容、多选），另开 ADR 说明，而不是就地放一个原生控件。
