# ADR 0076 · 设计稿用 React 写，前端整段搬过去

- **状态**：已采纳
- **日期**：2026-10-22
- **依赖**：[ADR 0075](0075-the-browser-client-is-react.md)（浏览器端已经是 React 19——本条要复用的正是那个运行时）

## 背景

`design/skillmaster-控制台演示.html` 是界面的权威，`skillmaster-web/` 照它实现。它今天是一份**自包含单文件**：3,276 行 CSS、约 1,600 行静态标记、**7,370 行命令式 JavaScript**（源码 `design/demos/dir3-hara-console.html` 12,284 行，交付件 14,551 行）。

这份代码的问题是结构性的，不是行数：

- **它不能复用。** 前端是 React，设计稿是 `document.createElement` 与 `getElementById`。同一屏要写两遍，而写两遍的东西一定漂。现成的证据：`ConsentPage.tsx` 与设计件同一屏**差了六处**（标题、名称字段、引子、权限两条、边界那一行、披露语那两句），`design/README.md` 末尾还写着「首页与控制台的真实代码是两套东西」。
- **它不可局部修改。** 一页的行为散在几十个函数里，靠 id 抓节点；改一处要同时读标记、CSS 与脚本三段，而三者之间没有编译期的连接。
- **它的「检查」只到行为为止。** `console-states.mjs` 能证明导航对、状态在、该滚的滚，但证明不了页面长得对；那一步一直由人做。

设计稿本身不连后端、不真的发请求，这是它作为「可被看见、被点击、被修改的设计」的前提，本条不改。要改的只是**它的源码形态**，以及**它与前端之间的距离**。

## 决定

1. **设计稿的源码是 React（TSX）**，放在 `design/src/{console,home}/` 与 `design/src/shared/auth/`（两份演示共用的登录浮层），一页一个文件、一个组件一件事。两份 `demos/*.html` 退回成模板：`<div id="app">` 加两条构建标记。旧的命令式共享浮层 `design/partials/auth-overlay.html` 已删除，构建脚本不再认 `@partial` 这个标记。
2. **交付件仍是自包含单文件。** `build-demo.mjs` 用 esbuild 把 React、组件与 CSS 打成一份 IIFE 与一份 CSS，内联回 HTML。双击能开、`file://` 下的检查脚本不用改、能直接发给别人——这条承诺一个字都不动。
3. **组件按 `skillmaster-web/src/` 的形状写**：同样的文件名、组件名、目录名；props 进、标记出；不 import 接口、会话、路由；夹具单独放 `fixtures/`。**复制到前端时只改「谁提供 props」**。
4. **复用方式是「照搬」，不是「共享」。** 前端不 import `design/` 下的文件：design 仍是唯一权威，前端的构建不被设计稿的目录结构牵连。代价是复制那一刻可能手滑，收益是两边可以各自演进、各自验证。
5. **演示件的地址契约不变。** `?page=` / `?state=` 仍要能发出去、刷新、复现同一屏；React 只换实现，不换这个性质。
6. **新增 `design-react` skill**，把「设计稿怎么写、怎么验、怎么搬进前端」写成后续每次改设计都要走的规则，而不是这一条 ADR 的附录。

## 理由

**为什么是 React。** 前端已经是 React（ADR 0075）。设计稿用同一个运行时，组件才可能从「重写」变成「复制」；用 Vue 或原生 Web Components 都会在复制那一步重新引入翻译，而翻译就是漂移开始的地方。

**为什么保留单文件。** 交付件的第一用途是「被打开」：设计师双击、发给别人、在 `file://` 下被 Puppeteer 驱动。改成 Vite 工程会同时失去这三样，并让两套检查脚本重写成「先起 dev server」。为工程化付这个代价，收益只落在写代码的人身上；而单文件 + 构建完全可以兼得——esbuild 一次打包，React 内联进 `<script>`。

**为什么是「照搬」而不是「共享组件库」。** 共享听起来更彻底，但它要求本期同时改前端的页面结构、Vite 配置与 TS 配置——那会让「设计稿迁 React」与「前端重构」两件事互相污染，出问题时无从归因（与 0075 拒绝「迁移时顺便引组件库」是同一条理由）。照搬把风险锁在「复制」这一个动作上，而那个动作有清单（`design-react` §四）。

**为什么不是「继续手写 HTML，只把渲染函数抽干净」。** 那只解决可读性，不解决复用：前端仍然要重写一遍。而复用是这条决定的起点。

**为什么不在这一版引组件库。** 与 0075 §后果 同一条：设计稿是界面的权威，引一套库等于让库的形状参与决定界面长什么样。要引哪一套，是另一条 ADR。

## 后果

- **`design/` 有了构建依赖**：`design/package.json`（react / react-dom / esbuild / typescript）。`npm install` 一次，之后 `npm run build:console`。交付件仍是单文件，但**源不再是单文件**——这改变了「改设计稿」的动作：改 `src/`，然后构建。
- **「产物 = 源」的比对从「拼片段」变成「拼片段 + 打包」**：`check-all.mjs` 的逐字节比对仍然成立，只是重出的那一步要走 esbuild。esbuild 版本必须钉住，否则同一份源可能打出不同的字节。
- **新增一道闸：`design/scripts/dom-compare.mjs`。** 它把一个状态压成三样人看得见的东西（骨架 / 文本 / 属性文案）并逐条 diff，用来证明「搬一页 React 没有改变这一页」。它不是视觉验收（像不像仍由人看），但它是搬迁时唯一能逐状态说「没变」的机器证据。
- **两份演示的迁移是分期的，但三份源已经全部迁完**（2026-10-22）：控制台先（它是 14.5k 行的那一份），首页与共享登录浮层次之。`design/README.md` 的「已知的取舍」按实际进度改，不提前写「已经统一」。
- **控制台的交付件反而更小了，首页的更大。** 实测（2026-10-22，三份源都迁完、两个交付件都重新构建）：控制台 **709,897 → 553,801 字节**原始大小，**212,652 → 149,706 字节** gzip；首页 **210,724 → 373,515 字节**原始大小，**99,327 → 147,035 字节** gzip。（这是当天审计修完之后的数；当天早些时候第一版构建是 553,421 / 373,388，差的是同一批修复。）原因是**每个交付件各自内联一份 React**（19 + ReactDOM 的生产包约 60–90 KB gzip）：控制台删掉的命令式脚本与重复标记远多于 React；首页本来只有 210 KB，React 一进来就净增约 48 KB gzip。**这是单文件承诺的价格，本条接受它**——两份交付件各自独立打开，不共享运行时。**单文件承诺不变**——发给别人的仍是那一个文件。
- **旧的命令式实现是历史**：`design/demos/*.html` 不再手改，要改行为改 `design/src/`；旧的共享浮层 `design/partials/auth-overlay.html` 已删除。要对照旧实现，看 `git show 49a98b0:design/demos/dir3-hara-console.html`（首页与浮层同在那个提交里）。
- **文案与样式的权威没有移动**：仍是 `design/voice-spec.md` 与 `styles.css`。本条只改「谁来写这份界面」，不改「这份界面是什么」。
