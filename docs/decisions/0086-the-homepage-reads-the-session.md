# ADR 0086 · 营销首页读取会话，登录后显示已登录态

- **状态**：已采纳
- **日期**：2026-10-24
- **依赖**：[`versions/v15-marketing-home/prd.md`](../versions/v15-marketing-home/prd.md)（www / console 的分域由那一版的文档定；[ADR 0085](0085-rename-web-to-console.md) 只定了项目改名，明确把分域留给 v15）

## 背景

v15 最初把 `www` 定成**不持有会话、不发任何 API 请求**的纯静态页：登录发生在 `console`，首页只是营销内容。那条决定换来三件事——零运行时依赖、没有跨源认证契约、以及「www 不知道谁在看」。

产品随后要求：**人登录之后回到首页，应该看到自己是登录的**（`进入控制台` + 账号），而不是再看到一次 `登录 / 开始使用`。这与「www 不持有会话」正面冲突，必须选一边，并把代价写下来而不是藏进实现。

候选有四条：

1. **保持零请求**——产品要的正是这一态，否。
2. **www 读一个可被脚本读的「已登录提示」cookie**——在会话之外再立一份身份信号，两份会漂；可读 cookie 又意味着任何脚本都能改它。
3. **把营销首页搬进 console**——违背分域的目的：首页是公开面，不该带控制台外壳，也不需要随 console 一起发布。
4. **www 对 console 做一次只读的会话查询**——本次采纳。

## 决定

1. **www 只读会话**：页面启动时请求 `GET {CONSOLE_URL}/web/session`（`credentials: 'include'`）。2xx **且响应体是账号** → 已登录态；401、2xx 但不是账号、网络失败或超时 → 未登录态。**fail-open。**
2. **www 不做任何会话写**：登录、注册、退出、找回密码仍然只在 `console`。www 上没有表单、没有浮层，也不接收 CSRF 令牌。账号菜单里的「退出登录」因此是**一条指向 `console/logout` 的普通链接**——那是导航，不是写；控制台为它加一个只做「结束当前会话 → 回到首页」的页面路由。
3. **会话 cookie 的 `Domain` 放宽到 `skillmasterai.com`**（`HttpOnly` 与 `SameSite=Lax` 不变——同一注册域下的子域请求属于 same-site，Lax 不会拦；**不带前导点**：Tomcat 的 cookie 处理器会拒绝 `.skillmasterai.com`，而 RFC 6265 本来就把前导点当作可忽略），并给 `https://www.skillmasterai.com` 放行一条 **只针对 `GET /web/session`** 的 CORS 规则（带 credentials）。**只有会话 cookie 放宽**：`XSRF-TOKEN` 必须保持主机级（它故意可被脚本读，放宽就等于把写能力交给每一个子域）。域名以部署时核实的那个为准；若与 `skillmasterai.com` 不同，这两处配置要一起改，否则首页会安静地永远显示未登录。
4. **开发环境用代理，不用 CORS**：`skillmaster-site` 的 dev server 把 `/web/` 代理到**本地服务端**（`localhost:8080`，不是控制台的 dev server），请求因此同源；生产才走真正的 CORS。
5. **首屏先按未登录渲染，拿到响应后再换导航**；不为这一态做骨架屏或占位块。

## 理由

- **只读，而不是把会话搬到 www。** 一次读只回答「我是谁」；写才要求 CSRF、跨源错误处理与一套两处都要维护的令牌契约。读写分开之后，www 的那条路只有一个失败模式：查不到就当没登录。
- **fail-open。** 一个查不到会话的首页，最坏是让人再点一次「登录」；卡住或留白则挡住所有人，包括本来就没登录的多数访客。
- **先未登录渲染再换。** 骨架屏会让「未登录的人占多数」这件事付出一次空白；而先渲染未登录态，最坏是一瞬间的「登录 / 开始使用」——它的错误方向是安全的（不会把人误认成已登录）。
- 被否的第三条（搬进 console）见上面的候选表；被否的第二条（可读提示 cookie）是这条决定最想避免的形状：**身份只有一个来源**。

## 后果

- **服务端两处配置**：会话 cookie 的 `Domain`，以及一条只允许 `www` 源、只允许 `GET /web/session` 的 CORS 规则。两处都要有测试，因为少了任何一条，www **永远**只显示未登录——它不会报错，只会安静地少一个状态。另有一条要钉住的**不变项**：`XSRF-TOKEN` 不带 `Domain`。
- **暴露面变大**：会话 cookie 从此发给**每一个**子域，不只是 `www`。将来的 `docs.` 子域、任何挂在子域上的东西都会收到它。这是放宽 `Domain` 的直接代价，比「www 知道谁在看」更大，因此**不往子域上放第三方内容**。
- **会话活动的口径变了**：每次打开首页（以及将来的重新可见重查）都会刷新会话的闲置计时与「登录设备」里的最近活动。一个只是来看看营销页的已登录用户，也在续自己的会话。这是可接受的——它确实是一次带凭据的访问——但要在 ADR 0043 的「最后活动」口径里知道这件事（控制台「登录设备」那一列把它写作「最近活动」）。
- **隐私代价，写在这里**：`www` 从此知道「谁在看」。本版没有埋点、没有第三方脚本，这一信息只用于渲染导航；将来若引入分析，不得把它作为维度。这是本决定最主要的一项代价。
- **首页不再零请求**：未登录访客也会打一次 `/web/session`（401）。这是为已登录态付的固定成本。
- **会话的时效**：在另一个标签页里退出，www 不会立刻知道。**本版不做重新可见时的重查**——它会让「每次页面加载恰好一条请求」这条验收变成「每次可见还要再来一条」，口径要先改清楚；v15 TD 的 Q9 记着这件事与它的倾向（查，且 ≥30s 节流），留给下一版。
- **验收要改**：v15 验收 #2 从「不请求 `/web/*`」改为「每次页面加载恰好一条 `GET /web/session`，且不发起任何写」；验收 #7 从「两种访问看到同一页」改为「两种访问的导航不同、首屏内容相同」；并**新增验收 #15**——带真实控制台会话访问首页确实看到已登录态，且 cookie `Domain`、只读 CORS、`XSRF-TOKEN` 主机级三项都在。这三项是这条决定唯一会**安静失败**的地方，所以要有端到端的那一条。
- **测试要能分别跑**：`www` 的会话态是运行期行为，设计演示件用 `?signed-in` 复现两种态；两者的对应关系写进设计说明，免得有人拿演示件的两种态当产品的验收证据。
