# 0157 · 同步是来源无关的底座，来源只提供适配器

- **状态**：已采纳
- **日期**：2026-11-06
- **所属版本**：[`v50-open-source-sync`](../versions/v50-open-source-sync/README.md)
- **依赖**：[ADR 0147](0147-a-source-is-a-typed-connection-plus-signals.md)（来源是有类型的连接 + 适配器）、[ADR 0155](0155-open-source-sync-passes-three-gates.md)（三闸）、[ADR 0156](0156-sync-writes-as-the-official-namespace.md)（官方写入与版本映射）

## 背景

v50 要把外部开源仓库的 skill 搬进官方命名空间。最直接的写法是把 GitHub 的取文件、找许可、读 commit 写进同步流程；接第二个来源时再在流程里加分支。这样每加一个来源，清单格式、许可判定、幂等、写入、说明都要跟着改一遍，底座会退化成一串按来源分的 `if`。

v49 已经为来源元数据定过同一条原则：来源是「有类型的连接 + 适配器解释的通用信号」，加一种来源只加适配器（[ADR 0147](0147-a-source-is-a-typed-connection-plus-signals.md)）。v50 要搬运的是**内容**，需要把同一条边界再立一次：底座与来源分开。

2026-11-06 产品负责人明确要求：先有通用的外部获取 pipeline，GitHub 只是其中一根管子；以后加 SkillHub 这类来源，不动底座。

## 决定

1. **同步分成两层：底座与来源适配器。** 底座负责清单、调度、失败隔离、幂等与版本映射、许可闸、安全扫描、草稿写入、来源与许可落库、草稿说明；适配器只负责「这个来源怎么取内容、怎么找许可」。
2. **底座只认统一契约，不认具体来源。** 清单条目写成「来源类型 + 定位 + 目录 + 可选许可路径」；适配器返回统一结果：文件集、revision、许可文件（清单指定了就用指定的，否则最近的）。`SKILL.md` 的 `license` 声明由底座用同一个解析器读取，适配器不解析 frontmatter。底座不 import 任何具体来源的类。
3. **适配器按来源类型注册。** 未注册的类型在启动时拒绝，与 v49 的适配器注册表同一做法。本版只注册 `github`。
4. **加一个来源只加一个适配器加测试。** 表结构、调度、许可闸、扫描规则、幂等、写入、草稿说明、API、控制台与 CLI 都不改。来源特有的东西（比如 SkillHub 的 API、许可文件放在哪、revision 怎么取）全部留在适配器里。
5. **适配器的失败是数据，不是异常。** 超时、限流、404、内容为空都返回带状态的结果，由底座记录为该条失败或阻断（`failed` / `blocked`），不影响其它条目，不把异常抛到整个同步任务外。
6. **底座的可测性由测试替身证明。** 测试里用一个不联网的替身适配器跑通完整流程；GitHub 适配器单独测。底座测试不依赖 GitHub。

## 理由

- **与 v49 同一条边界。** 来源的元数据已经用适配器解释；内容也照同一形状切，读者与实现者不用学第二套模型。
- **加来源的成本要可预测。** 只加适配器意味着新增来源的改动面是「一个类 + 一组测试」；底座里出现来源分支，成本就会随来源数量增长。
- **许可判定必须统一。** 白名单、未声明留空、冲突待校准是平台政策，不能由每个来源各写一遍；适配器只提供事实（许可文件），判定与声明解析留在底座。
- **安全扫描也必须统一。** 规则与来源无关；如果放在适配器里，接一个新来源就等于可以绕过扫描。
- **测试替身是边界是否真的成立的证据。** 只写在文档里的「可扩展」不算数；能用一个假适配器跑通，才能证明底座没有偷偷依赖 GitHub。

被否掉的：**把 GitHub 逻辑写进同步流程**（加来源要改底座）；**按来源建表或建列**（同一件事被拆成多份）；**做一个万能 URL 抓取器**（URL 抓取解决不了来源语义、revision 与许可位置规则）；**让适配器自己判定许可与扫描**（政策分散，来源可绕过）；**只在文档里承诺可扩展、不写替身用例**（没有证据）。

## 后果

- 适配器的契约要定义清楚：文件集如何表示、revision 是什么、许可候选包含哪些字段；这些进 `technical-design.md`。
- 底座测试必须用一个不联网的替身适配器；GitHub 适配器另有一组自己的测试（含限流、404 与网络错误）；超时由请求超时与解包截止的代码路径保证，本版的 HTTP 层没有慢速对端用例。
- 新增来源的交付单元变小，但适配器契约不能随手改：改契约等于改所有来源。
- 来源特有的异常（比如 SkillHub 的分页、限流）要在适配器里消化成统一结果，不能漏到底座。
- 本版只注册 `github`；SkillHub 是否接、怎么接仍是后续版本的事，本文只保证接的时候不用动底座。
