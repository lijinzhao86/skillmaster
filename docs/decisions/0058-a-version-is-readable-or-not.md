# ADR 0058 · 版本只有「可读 / 不可读」；弃用不是状态，撤回叫下架

- **状态**：已采纳
- **日期**：2026-10-19
- **依赖**：[ADR 0031](0031-submitting-and-publishing-are-two-actions.md)（提交与上线是两个动作）、[ADR 0054](0054-lifecycle-actions-happen-on-a-version-page.md)（生命周期动作在单版页）、[ADR 0056](0056-dangerous-actions-are-confirmed-in-a-modal.md)（危险动作弹窗确认）
- **修订**：[ADR 0059](0059-delist-reason-is-optional.md) 取代 §决定 3 中「下架必须写一句原因」——原因改为选填

## 背景

v6 初稿有六个并列的状态：草稿 / 线上 / 历史版本 / 已弃用 / 已撤回 / 已丢弃。其中「已弃用」与「已撤回」只差一个字，用户在看版本表时提出分不清，并问「已弃用是不是就是历史版本」。

答案是：**从调用者能做什么看，是。** 两者都可读、都不是当前版本；「已弃用」额外给调用者一个「别再用它了」的信号。「已撤回」改变的是另一件事——消费面根本读不到它（410）。也就是说，「弃用」是**建议**，「撤回」是**可用性**，把它们画成并列的状态，等于把两个轴上的值放进同一列。

同时，「下线」这个词已经被整个 skill 占用：设置页里「下线这个 skill」让所有调用返回 503，版本与指针都不动。如果一个版本不可读也叫「下线」，同一个页面会出现两个「已下线」。

## 决定

1. **版本的可用性只有这几档**：`草稿`（还没发布）、`线上`、`历史版本`、`已下架`、`已丢弃`。**所有已发布、非当前的版本都是历史版本**，不再区分「已弃用」。
2. **去掉弃用。** 没有 `deprecated` 存储状态，没有弃用 / 取消弃用动作，消费面也不再返回 `Deprecation` 头。一个按旧版本钉住的调用拿到的是一条普通的成功响应——旧版本本来就是旧版本，裸地址一直指向当前版本。
3. **版本级「撤回」在界面上叫「下架」。** 动作是 `下架` / `重新上架`，状态章是 `已下架`。它只作用于消费面：按这一版钉住的读失败（410），作者面仍看得到、可以重新上架，下架必须写一句原因。
4. **skill 级的「下线」不动。** 它停的是整个服务（503 `skill_offline`），与版本级的下架是两个作用域、两个词。
5. **存储与接口里的状态值保留 `revoked`**（它描述的是权限被收回），界面统一读作「已下架」；这个映射只在状态词那一处发生，不散落到各处。

## 理由

**弃用不是生命周期的一站，是一句建议。** 生命周期回答「这一版还能不能被读到」；弃用回答「你该不该继续用它」。把所有历史版本都标成「不推荐」没有信息量——它们本来就不是当前版本；只在某个版本上额外警告，又需要一套动作、信号与权限。这一版选择不做这层建议，把模型收敛到读者真正会问的那一个问题：**现在还能读吗？**

**为什么叫「下架」而不是「下线」。** 用户的第一反应是「撤回就是下线」，语义上完全正确；问题只在词已经被占用。版本从消费面拿下来，用「下架」；整个 skill 停止服务，用「下线」。下架可以重新上架；下线可以恢复服务。两对词各自成对，作用域不会混。

**为什么「已弃用」不改成「不再推荐」留着。** 「不再推荐」比「弃用」清楚，但它仍然是一个状态、一套动作、一个消费面信号，解决的是「怎么称呼」而不是「要不要有」。在用户已经指出「它其实就是历史版本」之后，保留它只会把同一个疑问换个字再问一次。

**为什么界面与状态值可以不同名。** `revoked` 是权限被收回这件事在存储与接口里的名字；「已下架」是它在界面上对读者说的话。两者的映射集中在状态词一处，不形成第二套产品概念。

## 后果

- 状态从六个降为五个；存储状态从五个降为四个（草稿 / 已发布 / 已下架 / 已丢弃），「线上 / 历史版本」由指针派生。
- 删除 `deprecated` 状态、弃用 / 取消弃用接口与动作、`Deprecation` 响应头；prd 的范围 #7 与验收 #12 改写成「历史版本只有一种」的负面验收，验收 #15 / #17 / #23 收窄为下架 / 重新上架与五态。
- 界面文案与设计件：`已撤回` → `已下架`，`撤回这一版` → `下架这一版`，`恢复这一版` → `重新上架`；时间线事件、状态条、事实栏、版本选择器分组、回滚候选同步改。skill 级的「下线」不动。
- 回滚的候选只剩历史版本；已下架的版本必须先重新上架，才能再上线或回滚。
- 版本选择器分组变为 `线上 / 历史版本`，地址钉住不可读版本时以禁用的 `草稿 / 已下架` 组出现。
- 本版尚未实现，所以没有数据迁移；旧版本状态里若已有 `deprecated`，实现时按历史版本读（只影响尚未写入的数据模型，不涉及线上）。
