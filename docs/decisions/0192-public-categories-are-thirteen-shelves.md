# 0192 · 公域分类是十三个一级货架，单选、无二级

- **状态**：已采纳
- **日期**：2026-11-13
- **所属版本**：[`v66-skill-labels`](../versions/v66-skill-labels/README.md)
- **取代**：[0078](0078-a-category-is-one-shelf.md) §决定 1 的「10 个词」与「作者选」两半，以及 §后果 里「`skills categories` 打印公域计数」一句；0078 的「平级、单选、无父子、召回交给标签」不变
- **依赖**：[0146](0146-public-is-platform-endorsement.md)（公开是平台背书）、[0156](0156-sync-writes-as-the-official-namespace.md)（同步以官方命名空间写入）
- **相关**：[`docs/research/skill-taxonomy-and-labeling.md`](../research/skill-taxonomy-and-labeling.md)（SkillHub 与 ClawHub 的实测）

## 背景

[ADR 0078](0078-a-category-is-one-shelf.md) 把分类定成「平级 10 个、单选、没有父子」，由作者选，召回交给公开标签。当时的理由是：发现页是搜索 + 推荐，没有分类树页面；分类只需要一个稳定的粗坐标。

今天的前提变了两处：

1. **公域内容由平台收进来，作者不填分类。** [ADR 0146](0146-public-is-platform-endorsement.md) 之后只有官方命名空间能公开，[ADR 0156](0156-sync-writes-as-the-official-namespace.md) 让同步以官方身份写入。开源同步进来的 skill 没有作者在发布页上选分类。
2. **10 个词装不下现在的公域。** 旧 10 个里，「文档与演示 / 办公与协作」会并成办公效率，「设计与界面 / 图像与音视频」会并成设计多媒体；同时缺 AI Agent、商业运营、教育学习、行业专业、生活服务五个域。旧 10 个不是「分类不准」，是「覆盖不全」。

更具体的缺口是 **`grilling` 这类元技能**。它不产出某个领域的交付物，只改变 agent 和你一起思考、提问、交接、教学的方式。SkillHub 的 12 个一级里没有它的位置：同一族技能在实测里散在 `ai-agent`、`knowledge-management`、`life-service`、`dev-programming` 四个货架；`ai-agent` 的 8 个二级（框架、任务自动化、多 Agent、工作流、提示词、上下文、记忆、工具调用）描述的是「造/跑 Agent」，不是「用 Agent 跟你协作」。ClawHub 的 14 类里有一个 `agents`，官方描述是「Change how an agent plans, reflects, learns, remembers, or collaborates」——**这个货架行业里已经有，只是 SkillHub 没有。**

摆上桌的选项：

| | 做法 | 为什么行/不行 |
|---|---|---|
| a | 保持 10 个 | 缺 5 个域，元技能继续挤在 `ai-agent` |
| b | 照搬 SkillHub 12 个 | 对齐了域，但 grilling 仍然没有家 |
| c | **SkillHub 12 个 + 「AI 协作」** | 采纳：域对齐，元技能有独立货架 |
| d | SkillHub 12 个 + 96 个二级 | 96 个筛选项会让界面和维护面都爆炸；SkillHub 自己也不用二级做筛选 |
| e | 不加类目，把 `ai-agent` 改名扩定义 | `ai-agent` 会变成杂物间，用户看到「AI Agent」不会想到 grilling |

## 决定

1. **公域分类是 13 个一级词**：办公效率、内容创作、开发编程、数据分析、设计多媒体、AI Agent、知识管理、商业运营、教育学习、行业专业、IT 运维与安全、生活服务、**AI 协作**。前 12 个与 SkillHub 同名同义；第 13 个是我们补的。
2. **单选、平级、没有父子。** 一个 skill 最多一个一级分类，可以为空。分类是一个「货架」，不是标签。
3. **「AI 协作」的边界**：不产出领域交付物，只改变你和 agent 怎么一起工作——需求拷问、头脑风暴、任务寻路、会话交接、教学式讲解、为 Agent 写文档、交互向导、决策复盘。与「AI Agent」相对：**AI Agent 是造/跑 Agent，AI 协作是用 Agent 和你一起工作。** 与知识管理相对：知识管理处理资料，AI 协作处理你的思考过程。与开发编程相对：开发产出代码/测试/审查意见，AI 协作产出共识/决策/路径/交接单。
4. **公域由 Agent 打分类；私有 skill 仍可由作者选一个一级分类。** 公域没有作者可问，分类是平台元数据；私有 skill 没有平台背书，作者自己选一个粗货架仍然成立。
5. **旧 10 个一次性重映射到 13 个，保留映射表。** 映射不是删除历史：旧值在迁移日志与映射表里可查，回滚按映射表反向执行。旧 10 个里被合并的两组，按「主要产出」落新类。
6. **SkillHub 的 96 个二级词不进数据模型。** 它们转为打标时的候选标签词库：Agent 从里面挑词，写进自由标签，只做搜索召回，不做层级、不做筛选条。
7. **分类词表由平台维护**：新增/停用走迁移，不让用户造词；停用的词已有 skill 仍能筛出来，但不能新选。

## 理由

- **为什么是 13 而不是 12 或 10。** 12 解决了「域不全」，但解决不了 `grilling` 这类元技能——它们会被继续塞进 `ai-agent` 或知识管理，同一族技能散在四个货架。加第 13 个不是发明新概念，是把 ClawHub 已有的 `agents` 货架补上。10 个则连域都不全。
- **为什么仍然单选。** 分类是货架，不是标签。多选会让同一个 skill 出现在多个货架、重复计数，也会让「这条到底属于哪」失去答案。跨领域靠搜索与自由标签解决——这正是用户说的「我们更加倾向于让用户去搜索」。
- **为什么不做二级。** 96 个二级词适合「描述」，不适合「筛选」：SkillHub 自己把 `subCategories` 标成仅展示，不进筛选参数。做成第二层会同时增加词表维护、迁移和界面成本，而收益只是「更细的标签」——那件事交给自由标签更便宜。
- **为什么公域由 Agent 打。** 公域是同步进来的，没有作者填；[ADR 0146](0146-public-is-platform-endorsement.md) 已经把公开变成平台背书，平台有责任把货架放对。私有 skill 没有这层背书，作者自选仍然是最便宜的来源。
- **为什么「AI 协作」不叫「协作方式」。** 中文里「协作」不加限定词默认指人与人；加上「AI」之后，「和 AI 协作」与「AI Agent（造 Agent）」形成「用 / 造」的对照，误读最小。备选「与 AI 协作」「AI 工作方法」「人机协作」都被比较过：前者略长，中者偏生产力，后者学术味重。

被否掉的：**保持 10 个**（域不全）；**只照搬 12 个**（元技能无家）；**加 96 个二级**（筛选与维护成本）；**把元技能折进 `ai-agent`**（杂物间）；**把「方式」做成独立属性轴**（用户要理解两层，且 SkillHub 无对应物）；**多选一级**（重复计数、货架语义丢失）。

## 后果

- **词表迁移**：`skill_category` 从 10 行扩到 13 行；旧 10 个 key 按映射表重写；映射表随迁移脚本保留，可回滚。
- **ADR 0078 部分被取代**：被取代的是「10 个词」与「公域作者选」；保留的是「平级、单选、无父子、召回交给标签、分类只做粗坐标」。
- **控制台与 CLI 的词表变长**：结果行的分类胶囊、信息页的分类菜单、`skmr skills categories` 从 10 个变成 13 个；停用词仍按旧规则置灰。
- **元技能搬家**：`grilling`、`brainstorming`、`handoff`、`wayfinder`、`teach`、`writing-for-agents` 一类从 `ai-agent` 或知识管理移到「AI 协作」；旧分类的计数会变化。
- **96 个词变成候选标签**：自由标签的词库变大，但不新增筛选层；标签仍然只做召回。
- **将来要加二级，必须新开 ADR**：与 ADR 0078 的立场一致——不是今天留的坑，是重新决定模型。
