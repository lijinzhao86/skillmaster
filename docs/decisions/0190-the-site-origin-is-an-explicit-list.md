# 0190 · 首页入口保留 home，CORS 来源是一个显式列表

- **状态**：已采纳
- **日期**：2026-11-13
- **所属版本**：[`v63-home-subdomain`](../versions/v63-home-subdomain/README.md)
- **修订**：[ADR 0086](0086-the-homepage-reads-the-session.md) §决定 3（来源从「一个」放宽为「显式列表」）；[ADR 0187](0187-the-marketing-home-can-run-on-a-subdomain.md) §决定 2（不再按原计划把 `home` 301 回 `www`）与 §决定 3（CORS 不再只放行一个来源）
- **依赖**：[ADR 0086](0086-the-homepage-reads-the-session.md)（首页读取会话、会话 cookie、CORS 只覆盖 `GET /web/session`）

## 背景

v63 的 P0 把 `home.skillmasterai.com` 做成可用入口，`www` 保持原样。所有者随后明确：`www` 要作为一个**独立页面**保留，任何页面都不要链到它；`home` 作为营销首页的主入口；`www` 的页面内容不改，连登录态也保持原样。

原方案（[ADR 0086](0086-the-homepage-reads-the-session.md) §决定 3）只放行一个 CORS 来源，理由是来源只有一个值、任何多值都按拼写错误处理。现在有两个名字同时要读会话，且两边都不能错。

可选做法：

- **A 只放行 `home`。** `www` 变成永远未登录——页面还在，但登录态没了。
- **B 让 `www` 下线。** 与「`www` 保持可访问」直接冲突。
- **C 放行一个显式列表。** 两个名字都读会话；通配与空项仍然拒绝。

## 决定

1. **`home` 是营销首页的主入口**：控制台的三处站外链接与裸域 `skillmasterai.com` 的 301 都指向 `home`。
2. **`www` 保持原样、可访问、内容不改**，但不再有任何页面链到它——它是一个独立页面。
3. **CORS 接受一个显式来源列表**（当前 `www` 与 `home`），仍只对 `GET /web/session`、仍带凭据；通配、空项与条目**内部**的空白在启动时拒绝（逗号两侧与条目两侧的空白会被去掉）。解析只拒绝这几种形状，不校验一个值是否真是 origin——没有 `://` 或带路径的值仍会被接受，并在浏览器里静默匹配不上。
4. **不再执行「许可证后把 `home` 301 回 `www`」**；两者的长期关系由许可证结果决定（见 [`v63 TD`](../versions/v63-home-subdomain/technical-design.md) §开放问题）。

## 理由

- **否掉 A。** `www` 是所有者要保留的页面，登录态是它「原样」的一部分。
- **否掉 B。** 与「`www` 保持可访问」直接冲突。
- **列表而非常量。** 两个名字是过渡期的真实状态；写成配置里的显式列表，既不让 `www` 静默失去登录态，也不把规则放宽成通配。空项与通配仍然让启动失败，因为它们的症状在浏览器里看不见。

## 后果

- `SiteConfig` 的来源解析与测试要改；`SKILLMASTER_SITE_ORIGIN` 现在是逗号分隔的列表。
- 控制台要重出一次（`VITE_SITE_URL` 指向 `home`）；服务端要重新部署两次：先上带列表支持的代码（变量仍是单值），再把变量改成两个值并再部署一次——每次 Deploy 都按当前变量重写 `server.env`，变量只在部署时生效。
- **变量变成列表后，回滚到本文之前的服务端 release 要先改回单值。** 回滚同样会用当前变量重写 `server.env`，而旧 jar 遇到逗号会在启动时拒绝；不先改回单值，回滚会失败并自动切回当前 release（线上不中断，但回滚没有发生）。
- `www` 与 `home` 内容相同但互不链接；`www` 不承担「主入口」职责。
- ADR 0086 的「一个来源」与 ADR 0187 的「切回时 301」「CORS 只放行一个来源」由本文取代。
