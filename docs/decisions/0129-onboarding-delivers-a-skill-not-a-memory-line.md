# 0129 · 安装交付一个技能，而不是一段全局记忆

- **状态**：已采纳
- **日期**：2026-11-02

## 背景

v38 之前，安装过程的最后一步是 `skmr startup` 往用户的全局记忆文件写一段说明（Claude Code 是 `~/.claude/CLAUDE.md`），告诉 Agent「技能都去 SkillMaster 找」。

这条路有四个代价：

1. **改用户的文件**——装一个工具顺手改了他的全局配置；
2. **快照会旧**——CLI 行为变了也传不到老用户；
3. **不跨端**——每个 Agent 的路径与格式不同，要各写各的；
4. **难撤销**——要删得从用户自己的文件里挑出那几行。

当时的隐含理由是「只有写进记忆，Agent 才会默认来查」。这个理由在 2026-11 被实测推翻了。

**实测（口径：本机 `deepseek-v4-flash`，无头会话，每格 3–8 次，判据是会话里有没有出现 `skmr skills search`；闲聊不计入）**：

| 放置方式 | 触发率 |
|---|---|
| 全局记忆 | 23/25 |
| skill 描述里放全文 | 24/25 |
| skill 描述里放一句门铃、正文放全文 | 23/25 |
| 都不放 | 3/15（那 3 次全是用户点名 SkillMaster） |

三者统计上分不出来。**记忆不再占优。**

## 决定

安装过程改为**交付一个技能包**：

- 站点构建、部署时上传到下载桶：`https://skillmaster-dl.oss-cn-hangzhou.aliyuncs.com/beta/skillmaster.tgz`，源是仓库 `skills/skillmaster/`；`www` 上留同一次构建的副本，文档不指向它（那个名字会重置只用 TLS 1.2 的客户端）；
- 安装文档的第一步是把它解包到**这个 Agent 自己的技能目录**（不维护路径表）；
- 之后由技能里的 `sop/06-install.md` 指引安装 CLI；
- `skmr startup` 去掉「写全局记忆」这一步，只保留登录与导入技能。

**描述只放「查」和「调」两步，其余规则在正文**：绝大多数任务只需要先搜、命中就调，这两步写进描述，模型不加载正文也会做——那正是我们要的。代价是描述带命令时，模型有 86% 的情况不读正文（同一批实验，描述=全文那组只有 14% 加载了正文），所以**正文的规矩不能指望描述兜住**：描述只讲查和调，并明说「其它操作先加载正文再照它做」。**本版没有为这段描述单独测触发率**：它和「描述=全文」那组结构相同（命令在描述里），那组是 24/25，而「门铃 + 正文」是 23/25——两者在统计上分不出来（口径见上表）。所以这不是拿触发率换加载率，是把两条路分开。

## 理由

**被否掉的方案一：继续写全局记忆。** 上表说明它在触发上不占优；而它仍然要付四个代价中的每一个。**唯一真正只有它能做的事**是「管住 Agent 的其它行为」（回答语言、提交纪律）——那件事本版不需要。

**被否掉的方案二：只给技能，不写描述。** 实测 3/15，20%——不点名就不会来查。技能必须有描述。

**被否掉的方案三：把规则全文塞进描述。** 触发率与门铃版相同，但只有 14% 会读正文，等于规则散在两处；正文改了描述不改，行为就停在旧版。

**为什么每个 Agent 自己判断目录**：Agent 知道自己的技能目录在哪，我们维护一张表等于把它的知识抄一份到我们这边，还会过期。代价是**路径判错没有兜底**——判断不出来时它会停下（不自作主张，也不问用户），但自信地判错时用户只会看到技能没出现，重走安装即可。这一条如实记着，不假装有护栏（[v38 technical-design](../versions/v38-install-delivers-skill/technical-design.md) Q3）。

## 后果

- **新增一条分发通道**：技能源进仓库、确定性打包、部署时上传到下载桶。技能内容从此是产品的一部分，跟版本走。
- **`skmr prompt` 失去调用方**。不立即删除（对外契约变更），先观察一版。
- **老用户的机器上还留着那段记忆**。本版不做迁移——2026-11 时产品没有真实用户，迁移没有对象。**如果以后有人已经装过旧版，这条后果要重新评估。**
- **技能的更新没有机制**：本版只能重走安装。自动更新需要判断「用户改过没有」，是一个独立问题。
- **跨端未验**：分发包解包依赖 `tar`，Windows 只按 `tar` 自带这一前提写，没有真机验证。
