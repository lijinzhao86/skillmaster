# ADR 0103 · CLI 自己更新自己

- **状态**：已采纳
- **日期**：2026-10-27
- **依赖**：[`versions/v25-cli-self-update-and-prompt/`](../versions/v25-cli-self-update-and-prompt/)

## 背景

CLI 装到用户机器上之后就再也拿不到新版：唯一的更新方式是重跑安装说明里那条命令，而它要求用户记得、并要求用户知道有新版本。内测期这一点尤其贵——同一天可能发好几个构建。

`dl.skillmasterai.com` 已经有自更新所需的三样东西：`version.txt`（一行，发布流程保证最后写）、`checksums.txt`、以及**不带版本号**的产物名（[`RELEASE.md`](../../skillmaster-cli/RELEASE.md) §4、§6）。缺的只是二进制里知道这个地址——今天它只活在安装脚本和 workflow 里。

三条路：只提示、交给包管理器、自己替换。

## 决定

1. **默认自动装**：检测 → 下载 → 核对 SHA-256 → 换位，下一条命令生效。
2. **检测跟二进制自己的通道走**（正式用根、内测用 `beta/`），通道来自编译期注入；比较按 [ADR 0099](0099-the-cli-has-a-beta-channel.md)——内测的版号不动，**提交号才是构建身份**。
3. **只更新官方安装位置的两个目录里的二进制**（`~/.local/bin`、`%LOCALAPPDATA%\SkillMaster\bin`，符号链接会先解析）：自动路径在别处一声不响，`skillmaster update` 拒绝并给出重跑安装命令的办法，`update --check` 仍可只读地报告。
4. **macOS / Linux 用 `rename` 覆盖同一路径**；**Windows 由父进程退出后、新二进制把自己换到位**（helper 模式）。全程不调任何删除原语（[ADR 0101](0101-the-cli-never-deletes-files.md)）。「已经下好、还没换位」的文件在每个平台都会记进状态，下一次运行先应用它；应用前比一次版本，比现在这个旧就不应用（用户可能已经重跑过安装命令）。
5. **检查是命令的一部分，不是常驻进程**：进程启动后、执行命令前，24 小时一次，跳过帮助、版本与 `prompt` 组；`SKILLMASTER_AUTO_UPDATE=0` 关闭。**传输失败静默，但「下载下来没通过校验」要说一次**——一个在发坏字节的镜像不该永远没人听见；下载失败后一小时重试，不等一整天。
6. **写不进去就退化**：命令照常成功，每个新版本提示一次重跑安装命令。
7. **显式入口不受节流**：`skillmaster update` 与 `update --check`；前者与自动路径拿同一把锁。

## 理由

- **被否的「只提示」**：用户已经证明不会回来重装——这正是这一版要解决的问题。提示只是把同一个负担换个说法交回去。
- **被否的「交给包管理器」**：我们没有 brew / winget / apt 分发；Codex 那样做的前提是它已经在那几个渠道里。
- **被否的「改名腾位」**（Windows 上先改名再放新的）：实现简单，但安装目录会留下一个 8 MB 的 `.old`，而 CLI 又不能删它；两步之间还有一段「`skillmaster.exe` 不存在」的窗口。helper 方案把换位推到「没有人跑它」的时刻，只有一次 rename，**没有残留、没有空窗**。
- **为什么 helper 是新二进制自己**：不用维护第二个可执行文件，也不用它证明自己可信——它就是校验过、准备上位的那个。Windows 允许改名正在运行的映像（映射跟着文件走），所以它能把自己换到位。
- **为什么检查放在命令里**：Codex 那种常驻、每小时自更新的 daemon 是用户没同意的常驻进程，社区已经因此争议不断。命令里检查有明确的代价（触发更新的那条命令最多多等 10 秒），但它是可见、可预期、可关闭的。

## 后果

- **多了本地写**：`update.json` 平时每次检查写一次（最多每天一次），一次成功的安装再写两次；下载失败后一小时内重试，失败期间可能每小时写一次；helper 卡住时每条命令写一次（最多四次，之后丢掉记录）。另有 `update.lock` 在第一次检查时创建、之后一直存在。这与 v24「读命令零写」的努力有出入，明记在 PRD 里——不落盘就没法节流，不节流就是每条命令打一次网。
- **Windows 未签名的自替换会被杀软盯上**：未签名二进制 + 周期性自我替换是启发式最喜欢的形状。缓解只有代码签名，本版不做，记成已知风险。
- **发布流水线多一个必须注入的变量**：`internal/version.UpdateBase`。没注入的构建静默不更新，所以流水线要像断言 `DefaultServer` 一样 grep 它——否则「忘记注入」与「没有新版」在用户那里长得一模一样。
- **内测用户每天可能拿到新构建**：`beta/version.txt` 每次 workflow_dispatch 都重写，这是内测的定义，不是缺陷。
- **旧文件仍然不删**：**下载失败什么都不留**（包在内存里校验通过才落盘）；只有「已经落盘、但换不动」时才会在安装目录留下 `<exe>.new-<rev>`，由 `pending` 记录在下次运行重试，用户也可以自己删。
