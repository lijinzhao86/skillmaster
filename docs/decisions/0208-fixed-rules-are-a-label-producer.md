# 0208 · 固定规则是标签的独立产出者，命中即最终结果

- **状态**：已采纳
- **日期**：2026-11-14
- **所属版本**：[v72-fixed-labeling](../versions/v72-fixed-labeling/README.md)
- **依赖**：[0193](0193-public-labels-are-extensible-claims.md)（标签是主张）、[0196](0196-label-extraction-reads-public-text-only.md)（只读公域文本）、[0197](0197-production-tables-hold-only-final-claims.md)（生产表只存最终结果）
- **相关**：[0194](0194-public-labels-are-agent-produced-and-sampling-audited.md)（Agent 打标与抽样验收）

## 背景

v66 的 P1 把「自动打标」设计成 Agent 抽取：模型输出带置信度的候选，经三档路由、影子期、周抽样与金标闸之后才提升进最终表（[0194](0194-public-labels-are-agent-produced-and-sampling-audited.md)、[0197](0197-production-tables-hold-only-final-claims.md)）。

但 `runtime` 这一维的大部分值是**能从仓库事实确定性判断**的：有没有 `requirements.txt`、命令里有没有 `docker run`、`SKILL.md` 的 `compatibility` 写没写「仅 macOS」。这些判断不需要模型，也不存在「模型说有 0.86 的把握」这种中间态——同一条规则对同一份内容永远给同一个答案。

可选路线：

| | 做法 | 问题 |
|---|---|---|
| a | 等 Agent 一期一起做 | 读者继续看不到刚需要的信息；规则部分本可以现在就交付 |
| b | 规则产出候选，再走影子期与抽样，最后提升 | 给可复算的输出套一层为不可复算输出设计的闸；开关与人工成本买不到新的确定性 |
| c | **规则是独立产出者，命中即写最终表** | 需要定义它与未来 Agent 产出者的关系 |

## 决定

1. **固定规则是标签的独立产出者。** 规则命中即写最终表，不走影子期、不进抽样、不等金标闸。
2. **没有证据不写。** 每条规则产出必须带 `{file, line, quote}`；证据在被评估版本的清单里找不到，这条就不写。
3. **规则的输入只有公域已发布版本的内容**：`SKILL.md` 文本、文件清单（路径 / 大小 / 是否二进制）、frontmatter 的公开字段。本版**不调用任何模型**，因此不触及 [0196](0196-label-extraction-reads-public-text-only.md) 的外发边界。
4. **规则是代码，不是配置。** 规则随服务发版、进 git、过测试；每条产出记 `rule_version`，能回答「这个标签是哪一版规则给的」。
5. **生产表仍只存最终结果**（沿用 [0197](0197-production-tables-hold-only-final-claims.md)）：在线库 `skill_label` 只有 `(skill_id, definition_id)`；证据、规则版本与运行记录留在 OPS 库。规则没有置信度与拒绝态，OPS 侧记的是「每次评估的命中集合」，不是带 confidence 的候选。
6. **与 Agent 的先后关系不在本条决定。** 本版规则是唯一产出者；Agent 期若也产出 `runtime`，两者的优先级与覆盖规则由那一期另定。

## 理由

- **为什么规则可以直接进最终表。** 抽样验收要解决的是「同一个输入，模型可能给不同答案」；规则的输出可复算，回归靠单测与固定夹具，不靠抽检。给规则套上影子期与周抽样，增加的是人工成本，换不到新的可信度。
- **为什么不等 Agent 一起做。** 语言运行时与是否要 API key 是读者最先问的问题；它们有确定的取证方式，晚做只是让空标签多存在一版。
- **为什么规则不能放配置。** 「这条标签是哪一版规则给的」必须能从版本追溯；配置热更新会让同一份内容在不同时间得到不同答案，而生产表里没有来源列可以解释差异。
- **为什么 OPS 侧不记 confidence。** 规则命中没有概率可言；写一个恒为 1.00 的置信度会让后来的读者以为它是模型输出。命中与未命中就是全部信息。

被否掉的：**等 Agent 一期**（空标签继续存在，且规则部分本可独立交付）；**规则走影子期与抽样**（为不可复算输出设计的闸，套在可复算输出上没有收益）；**规则放配置文件 / 热更新**（来源无法版本追溯）；**给规则产出记 confidence**（制造不存在的信息）。

## 后果

- **新增一个产出者**：`runtime` 维度的值可以由规则直接写入最终表；读模型不需要任何新开关。
- **证据的权威在 OPS**：在线库不再存证据；「这条为什么被标上」由 OPS 的 `label_claim` 回答，排查时按 `(skill_id, definition_id)` 取最近一次评估。
- **规则改动要重跑**：新增或修改规则后要跑一次全量刷新；`rule_version` 让「哪些标签是旧规则给的」可查。
- **与 v66 P1 的接缝**：Agent 期若产出同一维度的值，必须先定优先级与覆盖规则；在那之前 [ADR 0194](0194-public-labels-are-agent-produced-and-sampling-audited.md) 的抽样与金标闸只约束模型输出，不约束规则。
- **生产库迁移**：[0197](0197-production-tables-hold-only-final-claims.md) 的收表（删列、删运行表、`skill_label` 收成两列）在本版执行；生产库当前没有标签行，迁移不丢数据。
