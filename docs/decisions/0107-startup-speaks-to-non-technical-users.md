# ADR 0107 · 启动旅程面向非技术用户，控制台不变

- **状态**：已采纳
- **日期**：2026-10-27
- **依赖**：[`versions/v26-startup-guidance-and-agent-paths/`](../versions/v26-startup-guidance-and-agent-paths/)

## 背景

v26 的第一版措辞范本按 [`design/voice-spec.md`](../../design/voice-spec.md) 写。那份规范的前提是「技术用户是你的读者」，句式是「书面陈述，不用口语」。2026-10-27，产品负责人走了一遍 startup 的交互，判断「回答还是过于生硬且技术」，并明确：**目标用户是一群不懂代码和技术的人**。

现场的例子能说明差在哪。第一版范本对用户说：

> 会改：`/Users/me/.codex/AGENTS.md`，追加 3 行规则和两行起止注释……进度 6/7。

一个不懂技术的用户无法用这句话判断自己在批准什么：路径不知道是哪、3 行规则不知道是什么、6/7 不知道还剩什么。他能判断的是另一句：

> 我会在 Codex 的设置里加一小段说明，让 Codex 每次开始先来 SkillMaster 找技能。只会加这一段，别的内容不动。以后不想要了，我可以把这段去掉，文件本身不会动。

当时有三个选项：

1. **维持 voice-spec**：所有界面都按技术读者写。
2. **整份重写 voice-spec**：把控制台也改成口语。
3. **只给启动旅程开一个口子**：启动旅程面向非技术用户，控制台仍按 voice-spec。

## 决定

1. **启动旅程说的是人话。** `skillmaster startup`、`prompt install` / `prompt uninstall` 的计划输出，以及 agent 在安装对话里对用户说的话，一律：短句、口语、一次只问一个问题、先讲做完会怎样；技术动作由 agent 代做，用户只回答做不做。
2. **技术词不进入对话。** 要说的东西是「小工具 / 传技能 / 正式上线 / 让 AI 先来 SkillMaster 找技能 / 让 AI 用 SkillMaster 自己的文件夹 / 电脑上原来的那份」，不是「CLI / 提交 / 上线 / 系统提示词 / 本机副本 / 重启」。用户自己说「系统提示词」时可以跟着说，但不主动用。
3. **路径与命令不主动展示。** 用户必须自己运行时，给一行可复制的内容，并说清粘贴到哪里、做完说什么。
4. **出错说三件事**：发生了什么、什么没变、你可以怎么办。不责备、不开玩笑、不道歉。
5. **控制台仍按 voice-spec。** 这次只改启动旅程；`design/voice-spec.md` §一 记下这个例外，并指向本 ADR。
6. **启动旅程的权威范本**：v26 的「给用户的措辞」与技能内容里的 `voice.md`（本版交付）；控制台的权威仍是 voice-spec。两处不互相覆盖。

## 理由

- **为什么否掉第 1 条（维持 voice-spec）**：用户的判断就是它的失败。审批说的是「追加 3 行规则和两行起止注释」，而用户要判断的是「要不要让 Codex 以后先来 SkillMaster 找技能」——后者与前者不是同一件事。看不懂的审批只能盲批或拒绝，这正是 v26 要修的现场问题 1。
- **为什么否掉第 2 条（整份重写 voice-spec）**：控制台的读者是管理 skill 的作者，那份规范的名词表（提交 / 上线 / 草稿 / 登录设备）是硬约束，整份改成口语会丢掉精确性；而这次反馈说的是「安装过程」，不是控制台。把两个不同的读者混成一份语气，是另一种偷懒。
- **为什么例外是持久的**：启动旅程是第一次接触。用户在这里看不懂，就走不到控制台；控制台可以保持正式，因为走到那里的人已经选择管理 skill。这不是一次文案补丁，是「哪个界面对谁说话」的分界。
- **为什么否掉「只把词换短、结构不动」**：路径、行数、`6/7` 这些结构本身就在要求用户懂技术；换几个词救不回来。要换的是「用户判断什么」——从「文件里加几行」换成「Codex 以后会怎样」。

## 后果

- **启动旅程比控制台不精确**：路径、文件名、命令被藏起来，代价是用户看不到细节；需要细节时由用户问，agent 再给。这个代价用「五句话请示」兜底：只会动到什么、不想做了怎么办必须说清。
- **CLI 的输出要跟着变**：`startup --plan`、`prompt install` 的计划不能只给 agent 看，它本身就是人话；验收按 v26 的范本逐句对照（v26 验收 18）。
- **`design/voice-spec.md` §一 有了一条例外**：以后改文案先判断「这是哪个界面、读者是谁」；控制台仍按原规范。
- **控制台是否也要口语，本 ADR 不回答**：如果产品负责人确认控制台的读者同样不懂技术，那要另开一条决策，不能拿这条 ADR 直接套过去。
- **`voice.md` 是平台内容**：改它要技能主人上线，不是 CLI 发版能代劳的；窗口期里老旅程仍能走。
