# ADR 0038 · 第一方的默认凭据是用户自己签发的 API key

## 背景

v1 的默认凭据是 [ADR 0007](0007-self-built-oauth-as.md) 那一套：授权码 + 同意页 + loopback 回调 + PKCE + refresh 轮换（[ADR 0024](0024-refresh-replay-grace-window.md)、[ADR 0028](0028-cli-uses-a-fixed-loopback-port.md)）。它解决的是**第三方客户端**的问题——同意、权限范围、用户不把自己的秘密交给别人。

而 v1 只有一个客户端，是我们自己的 CLI（[ADR 0011](0011-server-and-cli-stack.md)：只做预注册）。于是这套机制的成本与收益开始错位：

- **loopback 要求浏览器与 CLI 在同一台机器上**，这是硬限制而非偏好：`login` 只有 `--client-credentials` 一个参数，没有「不开浏览器」「手动粘贴授权码」的退路（已核实）。`ssh` 到开发机、容器里、agent 沙箱里，这条路都不成立。
- **代价在现在付，正当性指向一个还不存在的未来。** 同意页给的三条理由里，只有「为 P2 的 CIMD 省一次重写」是硬的；另外两条（告诉用户交出去的是什么、同意被记住）换一种形态同样成立。
- **最要紧的一条：这套东西没有可见面。** 「已授权的凭据列表」被明确推迟，而模块文档自己承认存在**既看不到、也撤不掉**的孤儿授权——同一台机器登录两次，旧那条的 refresh token 已不在任何地方。
- **外部参照。** GitHub 两条都有：`gh auth login` 默认走 OAuth，PAT 是给自动化用的那条；GitLab 也是两条都有，而且它的项目／群组访问令牌**没有自己的表**——那是一行 `personal_access_tokens`，行主是一个合成用户。GitLab 还留下一条被验证过的教训：它先做过「不过期」，又被拉回「默认必填、缺省 365 天、且部署可配」。

要定的是：**第一方的默认凭据是什么形状。** 三个候选——(1) 维持 OAuth，另加设备码补 headless、另建授权列表补可见面；(2) 粘贴式 API key，用户自己在控制台签发；(3) 两者并存、key 当默认。

## 决定

1. **第一方的默认凭据是 API key**：用户在控制台自己签发，粘贴给 CLI。
2. **key 的形状**：属于一行 `app_user`；有名字、scope、有效期、`last_used_at`、可单独撤销；整串**只在创建那一屏显示一次**，库里只存 sha256（同 [ADR 0021](0021-opaque-tokens-not-jwt.md)）；整串带可识别前缀 `skm_`，让密钥扫描认得出它。
3. **有效期**：缺省 365 天，**做成部署可配**（关掉则新 key 可以不过期），照 GitLab 的做法；并支持**续期**——换一把新的、scope 继承，而不是撤销再新建。
4. **scope 默认最小**：新建时默认只勾 `skills:read`，`skills:write` 要显式选。
5. **权限实时取交集**：一次请求能用什么 = `key 声明的 scope ∩ 用户此刻的权限`。降权、停用当场生效，不需要谁去清点。
6. **CLI 怎么收**：`login --with-key` 从 **stdin** 读，或读环境变量 `SKILLMASTER_API_KEY`。**不收命令行参数**——那会进 shell history 与 `ps`。
7. **`logout` 只删本机那一份**，不再撤销服务端；撤销在控制台。
8. **OAuth 那一条路保留**，但降级为**第三方宿主专用**（P2 的 CIMD）。
9. **`client_credentials` 与手工种的那行客户端被取代**——第一方的无人值守走 key。
10. **主体类型不改**：`AuthenticatedSubject(userId, scopes)` 仍然是「一个人」，只增加一个凭据 id 字段，供审计与 last-used。
11. **本轮不做**：组织拥有的 key（合成用户／bot）、个人-群组-项目三级归属、设备授权码、过期邮件提醒。

## 理由

- **为什么 headless 不是理由。** 「loopback 不成立」只对**授权码**那一种成立：设备授权码（RFC 8628）不需要同机、凭据也不经过用户的手，而我们用的框架里就有它（核实过 jar 里有 `OAuth2DeviceAuthorizationEndpointFilter` 一整套）。所以「CLI 跑在远程机器上，所以必须用 key」这个论证**不成立**，不能拿它当依据。真正的依据是下面两条。
- **为什么第一方不需要那层保护。** 「用户不手持一个秘密」值钱的地方，是客户端**不是你自己的**的时候——第三方宿主不能拿你的 key。第一方要它为它付的是一整套机械成本：授权码 + 同意 + 轮换 + 宽限窗口 + 框架三处覆盖 + loopback 固定端口；换来的是「凭据会转」。而今天这套**恰好看不见自己签了什么**——在这个产品的场景里，**看得见比会转值钱**。
- **为什么不选「维持 OAuth + 设备码 + 授权列表」。** 它的优点是真的：不引入第二种凭据。但它把机械复杂度留着，还要新增设备码那一整套（verification 页、user code、device consent）。而「CLI 要跑在多种环境」要求的是**一种到处能用、而且自助的**凭据——**自助这一点是关键**：今天的无人值守路径要运维先种一行客户端，key 不需要。
- **为什么 key 必须带有效期，而不是 LLM 那种永不过期的一把。** 因为这一改**换掉的正是轮换**：轮换那条路唯一的、不可替代的收益是「盗窃会被发现」，而一张静态凭据泄漏是**永远静默**的。所以要拿别的东西补回来——有效期（不永存）、last-used（异常可见）、前缀（可被扫描）、单把撤销（收得回）。GitLab 先试过不过期又拉回来，是这条的现成证据。
- **为什么叫 API key 而不是 access token。** `access token` 这个词在本系统里**已经指那个 1 小时的凭据**（`access_token` 表、`IssuedTokenValidator`）。拿它命名一个 365 天的东西，等于让同一个词指两种相反的寿命——这正是 `architecture/model.md` 的术语表要防的那种漂移。
- **为什么 `logout` 只删本机。** 一把 key 可以贴在多台机器上，而 CLI **无从知道另外几台的存在**——本机一撤就把 CI 断了。这与 GitHub 的分法一致：本地退出清本地，服务端那把在网页上撤。
- **为什么不做组织拥有的 key。** GitLab 已经证明它**不必改主体类型**——建一个合成用户即可，令牌就是它的。但那要等组织模型，而且要新增「合成用户不能登录」这类规则。**这不是漏做，是范围。** 本 ADR 只答第一方：用户签自己的。
- **为什么保留 OAuth 而不是删掉。** P2 的第三方宿主（Claude Code / VS Code / ChatGPT 经 MCP）**不能拿用户的 key**，那是它们唯一的路径。删掉它等于把 P2 变成一次重写。

## 后果

明确的价钱（都不是意外）：

- **用户开始手持一个秘密。** 它会进 dotfile、shell history、CI 的 secret、截图。缓解是上面四条（前缀／有效期／last-used／单把撤销），**不是消除**。所以「不收命令行参数」这一条是硬的。
- **失去「盗窃会被发现」。** 这是明确买掉的。一张静态凭据泄漏之后，唯一的发现途径是用户自己去看 last-used。
- **一把 key 贴到多台机器之后，无法按机器撤销。** 要按机器分就得按机器签——那是给用户的建议，不是产品保证。
- **`logout` 变弱。** 今天是「先撤服务端、再删本地」，两步都对；之后「我登出了」这句话只剩本机那一半，而同一把 key 在另一台机器上照旧能用。
- **OAuth 那条路变成一条「没有用户的路径」**：跑得起来、有测试、但没人走。模块文档自己记着「三处覆盖里唯一会在框架升级时主动红的那个断言」——那正是这类代码的维护负担形状。
- **验收标准的判定方式变了**：`prd.md` 的验收 #1 从「CLI 拿到令牌」变成「控制台签一把 key，CLI 用它」，#8 那条链路的入口也跟着换。按仓库约定，改验收标准属于换交付形态，不是小版本迭代。

要还的债与随后的改动：

- **`app_user.status` 必须每次请求都看。** 今天只在校验登录那一刻看，被记为「要还的债」；对一小时的令牌是债，对 365 天的 key 是**必需**。
- **审计与 last-used 需要主体带上凭据 id。** 一个用户五把 key，出了事必须知道是哪一把干的；这同时是 `last_used_at` 的来源。
- **「谁有权签发」这条只答了一半。** 第一方（用户签自己的）由本条答；**组织那半留给组织模型**——写在这里，否则半年后会有人以为只是漏做。
- **几个值要落进配置**：有效期开关与缺省值（部署可配）、前缀字符串、以及「key 允不允许不过期」。
