# 0176 · 发布到公开市场即转出个人命名空间

- **状态**：已采纳（原则；实现留给允许普通用户发布公开的那一版）
- **日期**：2026-11-09
- **依赖**：[ADR 0048](0048-visibility-hands-out-a-rung.md)（可见性）、[ADR 0146](0146-public-is-platform-endorsement.md)（公开是平台背书）、[ADR 0175](0175-account-deletion-is-immediate-with-a-fixed-retention.md)（注销的内容归属）

## 背景

今天公开市场只收官方命名空间（v48），普通用户发不了公开。一旦将来允许普通用户发布，「公开条目」如果仍然只是个人命名空间里的一条 skill 的引用，就会出问题：作者注销，条目跟着消失；依赖它的固定任务与流程全部报错。

地址是 `命名空间/名字`。要保住调用方的地址，只有两条路：永久保留作者的用户名与命名空间，或让公开条目拥有**独立于个人命名空间的身份**。前者把一次发布升级成永久占位，且与「用户名 30 天后释放」冲突；后者是市场型产品的通行做法。

平台实践：npm 的公开包不随账号删除自动下架，撤包是单独政策；知乎把已发布内容保留并改为匿名名称；GitHub 自己名下的仓库随账号删除，但别人仓库里的贡献保留并改挂 `ghost`。差别在于**公开内容是否有依赖者**：包与帖子有，个人代码仓库没有。

## 决定

- **发布到公开市场是一个所有权动作，不是可见性开关。** 发布时平台取得一份可继续托管的副本与许可，公开条目由**市场命名空间**（平台持有）承载，地址不再依赖作者的个人命名空间。
- 作者个人命名空间里的那份是**源**，不是公开条目的本体；源可以继续演进、也可以删除，公开条目按自己的版本节奏存在。
- **作者注销账号不删除公开条目**；作者显示为「已注销账号」。撤下公开条目是**单独的 unpublish 动作**，不是注销的副作用。
- 发布条款里写明这份持续托管许可与「注销后仍展示、可单独申请下架」两条；律师审阅排在内测版上线之后，先按本 ADR 写进条款。
- **实现留给允许普通用户发布公开的那一版**。这一版只把原则写进条款与 ADR；不建市场命名空间、不改地址模型、不做 unpublish。
- 在此之前，官方/团队公开条目本来就不属于个人命名空间，成员注销不影响它们（[ADR 0175](0175-account-deletion-is-immediate-with-a-fixed-retention.md)）。

## 理由

- **否掉「永久保留作者命名空间」**：用户名不能重注册、个人空间永久占位，等于让一次发布买断一个地址；与注销后释放用户名的承诺直接冲突。
- **否掉「注销即下架公开条目」**：公开条目有依赖者，下架等于让作者的注销替所有调用方做决定；npm 与知乎都不这么做。
- **为什么不现在实现**：普通用户还发不了公开，现在建市场命名空间、改地址模型是在为不存在的路径付成本；但原则必须现在写，否则那一版会在注销逻辑上打补丁。
- **为什么需要许可**：PIPL 第四十七条的删除权针对个人信息；公开内容要在作者注销后继续存在，必须有发布时取得的许可与清楚披露。这是律师审阅的核心条款之一。

## 后果

- 公开市场的地址模型要独立于个人命名空间：需要一个新的「市场命名空间」或等价的平台持有者，以及条目到源 skill 的引用关系；具体形状在那一版的 PRD/TD 里定。
- 发布、撤下、作者去标识化、侵权下架都要各自有动作与审计；注销只触发作者去标识化，不触发下架。
- 条款现在就要写这条许可；功能到那一版再做，避免「条款里有、产品做不到」。
- 对 v56 没有代码影响；它是 v56 注销规则的上游约束，防止将来把公开条目继续当个人资产处理。
