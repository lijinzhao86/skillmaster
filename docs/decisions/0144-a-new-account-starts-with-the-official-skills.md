# ADR 0144 · 新账号注册后带上两个官方 skill 的库引用

- **状态**：已采纳
- **日期**：2026-11-05
- **依赖**：[ADR 0082](0082-public-and-private-with-my-library.md)（库是引用，公域只搜不列）

## 背景

新账号注册完，库是空的。而 `skmr skills search` **默认只搜自己的库**——于是新用户连官方指南都搜不到，得先知道地址再 `skill join`，而新用户恰恰不知道地址。平台自己的两个 skill（`skillmaster/skillmaster-startup`、`skillmaster/skillmaster-guide`）本该是入门的第一步，现在却要靠介绍页或别人的转述才找得到。

问题不在搜索：默认只搜库是 [ADR 0082](0082-public-and-private-with-my-library.md) 定对了的（公域无界，不能整表列）。缺的是「新账号的库里先有什么」。

## 决定

1. **注册成功后，平台把两个官方 skill 的库引用插进新账号的库**：`skillmaster/skillmaster-startup` 与 `skillmaster/skillmaster-guide`。用户仍可自己 `skill leave` 掉。
2. **加入是引用，不是复制**：不复制内容、不产生版本、不改变访问权；官方发新版，用户的库跟着新版（[ADR 0082](0082-public-and-private-with-my-library.md) §决定 2）。
3. **这一步在注册事务之后单独执行，失败只记日志**，不改变注册结果；skill 不存在、不可加入时跳过。重复执行是 no-op。
4. **只对新注册生效；存量账号不补**（产品负责人 2026-11-05 定）。已有账号的库不被静默改动，他们仍可自己 `join`。
5. **默认清单放在服务端配置里**：`skillmaster.welcome.skills`，逗号分隔的「命名空间/名字」（`SKILLMASTER_WELCOME_SKILLS` 可覆盖）。格式写错在启动时拒绝；不做管理界面。
6. 这两个 skill 仍受 [ADR 0143](0143-public-skills-need-confirmation-in-the-cli.md) 的约束：用户把它们 leave 掉之后，再 `invoke` 同样要确认。

## 理由

- **默认清单放服务端。** 这是「新账号的初始状态」，不是某个客户端的偏好；浏览器、CLI、以后的客户端都该看到同一个库。放客户端会让换客户端就换默认。
- **引用不是复制。** 复制会切断作者更新，这是 [ADR 0082](0082-public-and-private-with-my-library.md) 已经否掉的那条；官方指南更新后用户自动读到新内容，正是这里想要的。
- **注册之后、事务之外。** 注册不能被一个可选步骤连累：加入失败时应该退化成今天的行为（空库），而不是让账号创建失败。反过来，把它放进同一个事务，任何一次默认加入的异常都会变成一次注册失败。
- **不补存量账号。** 静默改动已有用户的库，比「老用户仍然搜不到」更难解释；要不要补、什么时候补，留给一次明确的产品决定。
- **清单是配置，不是常量。** 加第三条官方 skill 时改一行配置、重启即可，不必改代码、也不必为一个地址再走一次代码评审；格式写错在启动时就拒绝，而不是等到注册时才静默跳过。

被否掉的：**首次使用时弹一次提示**（多一步，而且提示之后仍要回答「加不加」；库里的「我加入的」已经让这件事可见）；**复制一份到用户账号下**（切断更新）；**存量账号统一补**（产品负责人否决）。

## 后果

- 注册链路多一步，跨进 M12（库引用）；那个步骤失败不影响注册。
- 新增一个配置键（`docs/current/config.md` 由生成器列出）；部署时可用 `SKILLMASTER_WELCOME_SKILLS` 覆盖。
- 新用户第一次 `skills search` 就能搜到官方指南；控制台的库里会多两条「我加入的」。
- 存量账号与新账号的初始库不同，这个分叉会一直在，直到某天决定补。
- 本地与测试环境没有这两个 skill 时，这一步是 no-op；要验它，测试里得先把 skill 造出来。
