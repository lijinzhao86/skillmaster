# 0155 · 开源同步只收宽松许可，并必须过许可、安全、人工发布三闸

- **状态**：已采纳
- **日期**：2026-11-06
- **所属版本**：[`v50-open-source-sync`](../versions/v50-open-source-sync/README.md)
- **依赖**：[ADR 0146](0146-public-is-platform-endorsement.md)（公开是平台背书）、[ADR 0154](0154-v49-does-not-adjudicate-license-conflicts.md)（v49 不裁决许可冲突，留到入库流程）

## 背景

v50 让平台按清单自动把外部开源仓库的内容收进官方命名空间。这是第一个「内容不经作者、由平台主动进入公域」的入口，[ADR 0146](0146-public-is-platform-endorsement.md) 明确说过：等 v50 有了来源、许可与安全扫描，官方收录才成立。

开源不等于可以随便再分发。仓库可能没有许可、只有自定义条款，或使用 GPL / AGPL 这类带传染性义务的许可；skill 包还可能带硬编码凭据、私钥、下载即执行的命令或可执行二进制。平台把这些内容收进来并公开展示，就是在替它们背书。今天平台的内容都来自已登录作者，安全与合规责任在作者；自动同步改变了这个前提。

2026-11-06 产品负责人定了边界：人工白名单、仅宽松许可、同步只产生草稿、内置静态扫描；并进一步定了三处细节——冲突以许可文件为准并交人工校准、不做单独的变更提醒表、上游取消许可时仍同步但平台许可留空。

## 决定

1. **来源只来自人工维护的同步清单。** 运营者逐条写明仓库与目录；平台不做自动发现、不按 topic 或搜索批量抓取。
2. **许可只有一个权威来源，按优先级取一个值。** 清单指定的许可文件（`license:`，可选）> 离 skill 目录最近的许可文件 > `SKILL.md` 的 `license` 声明 > 未声明。清单指定了路径却在该 commit 里找不到时阻断，不退回「未声明」——否则上游一次改名就会把本该拦下的内容放进来。识别出的许可必须是宽松许可白名单之一：MIT、Apache-2.0、BSD-2-Clause、BSD-3-Clause、ISC、MPL-2.0、Unlicense、CC0-1.0、CC-BY-4.0。
3. **许可闸的规则：前三条规定拦截与同步，第四条决定何时重新看许可。**
   - **识别出非白名单许可**（GPL-2.0、GPL-3.0、AGPL-3.0、自定义、`NOASSERTION`）：不同步，记录原因。
   - **完全没有任何许可**（没有文件、也没有声明）：照常同步，但平台上的许可为空、展示为「未声明」；草稿说明里标注「未声明」。上游取消许可时按同一规则处理，草稿说明写「已取消」。
   - **文件与声明不一致**：以文件为准照常建草稿，草稿说明里标注「待校准」；不做单独提醒表，运营按草稿说明人工校准。
   - **仅许可变化不触发同步**：revision 只看 skill 目录最近的 commit；根 `LICENSE` 单独变化不会下载，等下一次内容 commit 时新许可才生效（2026-11-06 用户定）。
4. **安全闸：内置静态检查，分阻断与警告两级。** 阻断项（硬编码凭据与私钥、破坏性命令、下载即执行、可执行二进制）命中即不建草稿；警告项（外链脚本、宽泛权限声明、可执行文本脚本、非文本资源）记录后继续。规则清单放在服务端资源文件，测试逐条覆盖。
5. **发布闸：同步只产生草稿。** 同步永不自动发布、永不自动设为公开；内容要经运营者登录官方账号、在现有发布流程里确认后才能上线，发布并可公开后才进入公域。
6. **每一道闸的结果写在草稿说明里。** 同步草稿的 `changelog`（一行，≤200 字）写明来源 `owner/repo@commit` 与许可结论；冲突、取消、未声明都在这一行里标出，运营按说明筛选。

## 理由

- **为什么只收宽松许可。** 平台要把内容复制、托管、分发给所有用户；GPL / AGPL 的传染性义务要逐条履约（提供源码、同许可再分发），平台今天没有能力也没有流程去承担。MPL-2.0 是文件级弱 copyleft，义务只跟随被修改的 MPL 文件，保留版权与许可文本即可履约，因此放进白名单；GPL 系不满足「整个平台不必跟着开源」这个前提，排除。
- **为什么未声明许可仍然同步。** 产品负责人 2026-11-06 的判断：宁可如实显示「未声明」并让人看到上游现状，也不要因为缺一份许可文件就把内容挡在门外；平台上「公开」与「许可」是两件事，许可留空本身就是一条信息。**代价要如实写下**：没有许可依据的内容被平台再分发，法律风险由平台承担，人工发布是最后一道判断。
- **为什么冲突以文件为准、写进草稿说明。** 文件是仓库里可验证的事实，声明是作者的叙述；两者不一致时取事实。单独的提醒表会多一套状态与查询入口，而草稿说明已经会出现在运营的待发布列表里，够用。
- **为什么人工白名单。** 「谁进公域」是平台背书的范围。自动发现会把背书变成算法推荐，而平台今天没有审核标准与责任主体去支撑推荐。
- **为什么内置静态扫描而不是接第三方。** 第三方扫描器带来外部依赖、限额、数据出境与报告口径差异；已知高风险（凭据、破坏性命令、下载即执行、二进制）用规则就能覆盖。
- **为什么必须人工发布。** 扫描与许可判的是形式合规，判不了「这个 skill 适不适合我们的公域」。公开是平台背书，最后一步必须由能负责的人确认。
- **为什么阻断项不建草稿。** 建了草稿就进入运营的待发布列表，等于把一个已知危险的东西推给人；阻断并记录，让运营先处理上游或清单。

被否掉的：**自动发现候选**（背书变成算法推荐）；**允许 GPL / AGPL 并标注 copyleft**（平台无法逐条履约）；**未声明许可一律不收**（产品负责人改为留空并同步）；**冲突时暂停同步、等人工校准后再建草稿**（拖慢上线，且草稿说明已能承载校准线索）；**建一张许可变更提醒表或发通知**（多一套状态；草稿说明够用）；**扫描通过即自动发布**（形式合规不等于适合公域）；**只做来源与许可校验、不扫内容**（自动同步改变了安全前提）；**接第三方扫描作为唯一闸门**（外部依赖与数据出境）；**只做展示、不拦截**（v49 只展示是因为没有自动入口；同步必须在写入前拦）。

## 后果

- 公域的开源内容只覆盖宽松许可仓库；GPL / AGPL 内容不走自动同步，需要时只能另开渠道并单独定履约方式。
- **未声明许可的内容会进入草稿并可能被发布**：平台在没有明确再分发依据的情况下托管与分发它，这是产品负责人明确接受的代价；风险由人工发布这一步兜底。
- **根许可单独变化不会立刻反映**：已发布版本的许可按它自己的 commit 保持；新许可要等下一次内容 commit 才生效。
- 冲突的校准依赖运营查看草稿说明；说明被改动或发布后冻结，历史线索留在版本记录里。
- 同步的覆盖面受人工清单限制；每次扩大范围都要改清单，这也正是背书的范围。
- 静态扫描会有误报与漏报：误报会让可用 skill 被跳过，漏报靠人工发布兜底。规则需要按实际命中持续调整。
- 上线速度受人工发布限制；同步只保证「内容就绪」，不保证「当天上线」。
- 同步结果必须可读（哪些通过、哪些被哪一闸拦下、为什么），否则运营无法区分「上游没更新」与「被拦住了」。
