# ADR 0002 · 交付形态：一个通用网关 skill + 自研 CLI

- **状态**：**部分被取代**——决定 1（在本机装一个通用网关 skill）以及决定 2 里「安装与更新网关」那一半，均由 [0089](0089-no-local-skills.md) 取代：本机不装任何 skill，三条规则写进系统提示词，`setup` 命令随之删除，因此「两条分发路径」（§后果）也只剩 CLI 一条。仍然有效的是：CLI 主导（登录、持有凭据、检索与取用）、凭据不进模型上下文、服务端权威
- **日期**：2026-09-26
- **依赖**：[ADR 0001](0001-server-authoritative.md)

## 背景

服务端权威（[0001](0001-server-authoritative.md)）之后，客户端还需要一个"引导物"告诉 agent：服务在哪、怎么用。

有一条路被排除了：**MCP 无法把 skill 注入宿主的加载器**。skill 是宿主特性，SDK 不提供编程注册接口；MCP resources 不会自动注入，MCP prompts 对模型完全不可见。所以不能靠协议把 skill 推进客户端。

另一条路也排除了：把目录下发到本地（原生加载）。那与 [0001](0001-server-authoritative.md) 矛盾。

## 决定

客户端侧只装两样东西：

1. **一个通用网关 skill。** frontmatter 常驻上下文；正文记录服务地址与调用协议（先搜索 → 看清单 → 按需读正文 / 文件）。**它是本地唯一常驻的东西，也是协议本身。**
2. **一个自研 CLI。** 负责登录、持有凭据、安装与更新网关、以及实际的检索与取用。

网关**只有一个**（不按领域拆多个）。

## 理由

- **L1 成本。** 本机 30 个真实 SKILL.md 实测 L1 平均 318 字符、约 33% 为 CJK，折算**约 160 tokens**；500 个全量安装约 **8 万 tokens** 常驻。一个网关把目录成本从 O(N) 降到 O(1)。多网关（按领域拆）能提高触发准确度，但一个通用网关成本最低，且发现体验可以全部交给服务端检索（[ADR 0006](0006-search-server-side.md)）。
- **凭据不能进模型上下文。** 若让 agent 裸 `curl`，token 会出现在 Bash 命令、模型上下文与 shell 历史里。CLI 从系统 keychain 读 token，token 永不外露。
- **网关是协议产物，必须能更新。** API 变了而用户本地的网关是旧的，agent 会按旧协议调用。CLI 负责比对版本并更新它——**这就是"安装必须由 CLI 主导"的原因**（well-known 那条路没有可靠的更新机制）。
- **只有 CLI 能覆盖无人值守场景。** 见 [ADR 0007](0007-self-built-oauth-as.md)。

## 后果

- **网关 skill 的 `description` 成为整个发现体验的入口。** 目录不常驻，"这个任务正好有个 skill 能用"完全靠这句写得够广。它是全项目最需要打磨的一段文字，且需要回归测试。
- 检索与排序成为产品核心，不是附属功能（[ADR 0006](0006-search-server-side.md)）。
- **well-known 索引通道只用来发布网关这一个产物。** 该通道无认证、无门控，只适合公开的单一入口；其余一切走鉴权后的 API。
- 要维护两条分发路径（网关 + CLI），但网关只是 CLI `setup` 的一个产物，实际只有 CLI 一条引导路径。
