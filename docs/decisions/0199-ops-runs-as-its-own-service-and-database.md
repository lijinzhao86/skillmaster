# 0199 · 内容运营作为独立服务与独立库部署

- **状态**：已采纳
- **日期**：2026-11-14
- **所属版本**：[`v69-ops-service`](../versions/v69-ops-service/README.md)
- **依赖**：[0196](0196-label-extraction-reads-public-text-only.md)（只读公域文本）、[0197](0197-production-tables-hold-only-final-claims.md)（生产表只存最终结果）、[0198](0198-api-planes-are-named-by-audience.md)（五个 API 面）

## 背景

自动导入今天跑在线上服务进程里，靠回环触发；自动打标与将来的一类 skill 评测也只会长在这里。三件事叠在一起：运营任务与用户请求抢同一份 CPU 与数据库连接；一次导入的故障与线上故障混在同一个日志与进程里；打标的中间态（候选、置信度、证据、审核状态）只能落进生产表，而产品负责人要求生产表只存用户能看到的最终结果（[0197](0197-production-tables-hold-only-final-claims.md)）。

另一个条件变了：第二台 ECS 已经申请下来。

| | 做法 | 问题 |
|---|---|---|
| a | 保持同进程、同库 | 故障、发布、资源都不分；中间态仍在生产表 |
| b | 同进程、独立库 | 表干净了，但运营任务仍然让线上服务跟着重启，故障域还是同一个 |
| c | **独立服务、独立库、独立机器** | 多一套发布链路与网络配置，换来发布与故障解耦 |
| d | 独立服务、共享在线库 | 服务分了，表又混回去；仍是两个进程写同一张表 |

## 决定

1. **新服务 `skillmaster-ops`**：独立进程、独立代码目录，不编译 `skillmaster-server` 的类，也不引用它的库。
2. **独立数据库 `skillmaster_ops`**：与在线库同一台 RDS 实例、不同 database；迁移与连接池各自一套，Flyway 版本号各自从 V1 开始。
3. **部署在第二台 ECS**：Docker 镜像由 CI 构建；大陆机器连不上 Docker Hub，所以镜像走阿里云 ACR 或离线装载，不假设能直接拉。
4. **只走 `/inner/v1` 互通**（[0198](0198-api-planes-are-named-by-audience.md)）：ops 不拿在线库的读写权限，server 不读 ops 库；提交草稿与写最终标签两条通路在 inner 面上；公开内容的抓取由 ops 直接访问来源（v69 的导入如此，打标读正文也走公网接口）。
5. **触发只有两种**：ops 自己的定时任务、CI 通过 SSH 打 ops 回环地址。ops 不向公网暴露任何端口。

## 理由

- **为什么不选 b（同进程独立库）。** 数据库只是问题的一半；另一半是「发线上版本要顺带重启运营任务、运营任务调参要重启线上服务」。第二台机器已经在手，这道边界不划就再也不会划。
- **为什么不选 d（独立服务共享库）。** 分库的直接收益就是「两边都碰不到对方的表」；共享在线库会让候选表与最终表又躺在一起，0197 的干净生产表就落空了。
- **为什么 ops 不碰在线库。** 拿写权限等于把 0197 的两层结构交给约定去守；走接口则让「最终结果」只有一个写入口，也只有一个地方能写脏。
- **为什么不做成 server 的一个模块。** 同进程里拆包只能拆代码，拆不掉资源与发布；这与「后台运营不要跟线上服务绑在一起」是两件事。

被否掉的：**同进程同库**（三件事都没解决）；**同进程独立库**（发布仍绑在一起）；**独立服务共享库**（表又混回去）；**把 ops 暴露到公网**（没有用户需要访问它，多开一个面就是多一个攻击面）。

## 后果

- **两套发布**：ops 的镜像、迁移与健康检查独立；它们失败不影响线上，但也没有「一起回滚」这回事。
- **网络成为显式前提**：server 需要一个只绑私网的 `/inner` 连接器；安全组、RDS 白名单、两台机器的私网可达都要在发布清单里核对，且没有代码测试能证明。
- **数据不共享**：ops 要知道「哪些 skill 已发布」，只能通过 inner 读接口；两边对同一个 skill 的标识（`skill_id`、版本 id）必须在契约里写死。
- **单实例**：ops 不做高可用，任务互斥用库里的行锁；这在一台机器上是够的，扩成两台时要先解决互斥。
- **成本**：多一台机器、多一个库、多一套部署脚本；换来的是线上发布不再带运营任务，生产表不再有中间态。
