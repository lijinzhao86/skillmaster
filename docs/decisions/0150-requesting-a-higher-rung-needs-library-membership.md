# ADR 0150 · 申请更高档位要求先入库

- **状态**：已采纳
- **日期**：2026-11-05
- **所属版本**：[`v49-public-signals`](../versions/v49-public-signals/README.md)
- **依赖**：[ADR 0082](0082-public-and-private-with-my-library.md)（库是引用，入库不改变档位）、[ADR 0048](0048-visibility-hands-out-a-rung.md)（公开把一档交给所有人）、[ADR 0047](0047-permissions-are-a-ladder.md)（权限是一条梯子）

## 背景

信息页底部那一块「需要更高权限？」，原先只按梯子判断：只要你上面还有更高的档，它就画；按钮在低于「写入」时写「申请成为协作者」。于是公域里一个路过的读者——他连这个 skill 都还没入库——看到的就是「申请成为协作者」。

服务端也只查两件事：看得见这个 skill，以及目标档高于你现在的档。公开 skill 交给所有人一档（ADR 0048），所以这个读者在接口上真的能把申请写进 `skill_access_request`，落进所有者的待批队列。

而入库本身**不改变任何档位**（ADR 0082）：它是库里的一个引用，不是一条授权。也就是说「入库」与「申请」在权限模型里本来毫无关系——把它们连起来是产品选择，不是权限推导。

## 决定

1. **申请更高档位要求这个 skill 在调用者的库里**：`source` 非空（created / shared / joined）。没有库关系的申请一律 400 `invalid_request`，`details[].issue` 为 `not_in_library`。
2. **界面只在已入库时画这一块**：公域里没入库的详情页没有「需要更高权限？」，它的主按钮是「入库」。按钮文案一律写「申请」，不再写「申请成为协作者」——能看到这一块的人都已经在库里了。
3. **入口留在信息页，不挪进「设置」**：设置是「管理」档才有的栏位，刚入库的人一般停在调用或浏览档，打不开它；唯一的入口挪进去等于对最需要它的人消失。
4. **控制台与 CLI 是同一条规则**：`skmr skill request` 得到同一个 400，以及一句能照做的指引（先 `skmr skill join`）。

## 理由

- **协作的前提是采用。** 一个人刚在公域里看见一条 skill，还没入库就来申请「写入」，所有者收到的是一串没采用过这个东西的敲门声；而申请方自己也没有一个「我在用它」的事实作依据。
- **这是调用者能自己修的事**，所以是 400 而不是 403：先入库，再申请，两步都在他手里。
- **规则必须落在服务端。** 只在界面上藏按钮，`skmr skill request` 依旧能写进队列——ADR 0081 之后，界面上有的操作都有 CLI 对应，藏起来不等于不存在。
- **入库是比共享更合适的门槛。** 用「已被共享」当条件会排除掉最常见的申请人：自己把公开 skill 收进库、想参与维护的人。

被否掉的：**只改界面、服务端不查**（CLI 绕过）；**挪进设置**（管理档才可见）；**要求已被共享**（把最常见的申请人挡在外面）。

## 后果

- `SkillAccessService.request` 多一条判断；CLI 的 `issueMessages` 多一句 `not_in_library`。
- 只拦新建申请：此前已经挂着的申请不受影响，仍可被批准或撤回。
- 这条规则属于权限模型，跨版本存活；它与 ADR 0082 并存——入库不提升任何档位，但它是申请的**资格**。
