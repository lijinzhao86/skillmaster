# ADR 0056 · 危险动作在弹窗里确认；回滚不是危险动作，但也确认

- **状态**：已采纳（**丢弃的归类被 [ADR 0060](0060-discarding-a-draft-is-not-dangerous.md) 取代**；其余决定不变）
- **日期**：2026-10-19
- **依赖**：[ADR 0046](0046-deleting-a-skill-happens-in-the-browser.md)（删除只在浏览器面）、[ADR 0050](0050-deleting-a-skill-can-be-undone.md)（删除可恢复）、v6 的回滚（[prd #11](../versions/v6-version-management/prd.md)）

## 背景

v6 的单版页原先把回滚画在页底的**危险区**：红色描边、红色确认，和下架、丢弃、下线、删除排在一起。理由只有一条——「回滚是高风险动作」。

2026-10-19 用户指出这里混了两件事：

1. **危险动作的确认方式**。危险区里原先有页面内联的两步确认，也有直接执行的动作。用户定下一条适用于以后所有界面的规矩：**危险操作一律弹窗展示并让用户确认**。页面本身不该被改造成一个确认框——确认时人应该还能看见动作所在的上下文，而不是页面自己换了一副样子。
2. **回滚算不算危险动作**。回滚把线上指针从一版移到另一版，但**不拿走任何东西**：每一版都还在，内容不变，版本号不变，随时可以再回滚回来。它与下架（消费面立刻读不到）、丢弃（草稿永久失效）、删除（skill 消失）、下线（整个服务停摆）不是一类。把它染红，等于把「会移动指针」说成「会毁掉东西」。

## 决定

1. **破坏性动作一律用同一个确认弹窗**（`.confirm` 壳）：下架、丢弃、设置页的下线 / 恢复服务、删除，以及以后新增的同类动作。标题说这一步，正文说它拿走什么；**取消是默认焦点**，Esc 与取消是同一个答案；需要原因的（下架）原因填在弹窗里，空着时确认按钮不可用；确认后焦点回到打开它的那个按钮。
2. **弹窗与红色是两件事。** 「染红」表示这个动作会拿走东西；「弹窗」表示这个动作不该被一次点击静默执行。危险动作两者都要；回滚只要后者。
3. **回滚不是危险动作。** 它的入口在单版页的「操作」栏，与上线 / 下架 / 重新上架这些生命周期动作并列；按钮是普通按钮，不进危险区。
4. **回滚仍然弹窗确认。** 它移动的是线上指针，默认目标还可能不是用户此刻想的那一版；弹窗让人在指针动之前看一眼「移到哪一版、现在的线上会变成什么」。

## 理由

**为什么危险动作用弹窗，而不是页面内联确认。** 页面内联确认有两种写法，都不好：把按钮换成「取消 / 确认」两个按钮，会让人在同一个位置误点第二下；把整块内容改造成确认页，则确认时看不见动作所在的上下文。弹窗把决定抬到一层之上，背景仍然可见，并且有一个明确的「取消」出口。它也让焦点管理只有一套：打开时落在取消上，关闭时回到打开它的按钮。

**为什么回滚不该染红。** 颜色在这个界面里有一个具体的含义——「这会拿走东西」（与设置页的 Danger Zone 同一含义，见 ADR 0050）。回滚之后每一版都还在，用户反悔可以再回滚一次；把它染红会让真正不可逆的动作（下架、丢弃、删除）失去区分度。风险来自「指针动了」，不来自「东西没了」。

**为什么回滚仍要弹窗。** 不染红不等于可以一键执行。回滚改变的是所有按裸地址调用的人读到的内容，而且默认目标是推断出来的（发布顺序的上一版），不一定是用户此刻脑子里那一版。一次弹窗的代价远小于一次错误指针移动——尤其是它还能顺手把默认目标摊开给人看。

**被否掉：回滚留在危险区，只把确认改成弹窗。** 那会让危险区的含义从「会拿走东西」退化成「改变状态」，下一次有人再往里加动作时就没有判据了。

**被否掉：回滚一键执行，靠「再回滚一次」兜底。** 指错了版本，消费面在发现并纠正之前读的一直是错的那一版；「可逆」不构成跳过确认的理由。

## 后果

- 设计件（`design/demos/dir3-hara-console.html`、`design/README.md`）：回滚移入单版页的「操作」栏，确认走弹窗且确认钮不染红；危险区只剩会拿走东西的动作（下架、丢弃、设置页的下线 / 恢复服务、删除），它们的确认全部改为弹窗。
- v6 文档（`prd.md` #11 / #21、`technical-design.md`、`test-plan.md` T28 / T29）按此回写。
- 以后新增任何破坏性动作，默认就是「危险区 + 弹窗 + 红色确认钮」；新增任何改变状态但不拿走东西的动作，默认是「「操作」栏 + 弹窗 + 普通确认钮」。若某条需要例外，另开 ADR 说明，而不是在实现里直接偏离。
- 本规矩约束的是**浏览器面**。API 平面没有弹窗，它靠权限、幂等与显式请求体；CLI 的破坏性命令是否要交互确认，不在本条射程内。
