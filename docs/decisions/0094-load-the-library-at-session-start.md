# ADR 0094 · 会话开始时先加载库，而不是等着被问

- **状态**：被取代（[ADR 0096](0096-guidance-lives-on-the-platform.md) 取代了规则文本与它的存放位置；本条「这是指令不是保证」的判断仍然成立）
- **日期**：2026-10-25
- **依赖**：[`versions/v17-cli-startup/`](../versions/v17-cli-startup/)、[`docs/research/agent-context-loading.md`](../research/agent-context-loading.md)

## 背景

[ADR 0089](0089-no-local-skills.md) 把触发压在系统提示词里的三条规则上：先查我的库、先 invoke 再取用、不要逐个试。它假定 agent 在「需要一项能力」时会去看库。

2026-10-25 的调研推翻了这个假定的一半：**skill 的描述只有在本地时才会自动进上下文**——要么装成 skill 目录（渐进披露原生的 name + description），要么抄进指令文件。前者被 ADR 0089 否掉（本机不装任何 skill），后者是一份会过期的副本，而且每个客户端的指令文件各叫各的名字、长度上限也不同。

剩下的选择不是「怎样自动加载」，而是**「什么时候去加载」**。三个候选：

1. 需要时再查（现状）——零开销，但 agent 得先意识到「可能有」，而这正是它不知道的。
2. **会话开始时先列一次（本次采纳）**——把「先看有什么」变成每个会话的第一个动作。
3. 把目录抄进指令文件——描述确实每次都在，但那是第二份会过期的数据，且撞长度上限。

## 决定

1. **规则的第一条改成「会话开始时先运行一次 `skillmaster skills list --no-login`」**，其余三条顺延为第二、三、四条。写进用户指令文件的就是这份快照。
2. **允许这一个旗标出现在规则里**（`--no-login`），这是对 ADR 0089「规则里不许出现参数名」的**唯一例外**，理由见下。其余参数名仍然不许出现。
3. **如实说明它不是保证。** 这是写给模型的指令，不是一个会执行的机制；模型可能漏做，CLI 也不会知道。所以：
   - 文档与 `help usage` 都写「会话开始先做这件事」，不写「已自动加载」；
   - `skills list` 自己在列表被截断时提示「先看有哪些标签」，作为漏做之后的第二次机会（v17 TD §列表截断）。

## 理由

- **`--no-login` 是安全属性，不是参数教学。** 会话开始时的 shell 常常没有人看着：没有凭据时，`skills list` 会打印一句提示并**打开浏览器**，等待一个不会来的回调——整个会话卡在那里。`--no-login` 让它立刻失败并说「先登录」，agent 转述给人，会话继续。规则里出现它，是为了让这条规则不会引发副作用，而不是为了介绍一个旗标。
- **每次会话一次的代价是可变且可预期的。** 默认 50 条一页；一页列表通常几 KB。库更大时 `skills list` 自己会说「还有更多」，那是给人看的信号，不是让 agent 无限翻页。
- **被否的第 3 条不是错的技术，是错的位置。** 把目录抄进指令文件确实能让描述每次都在，但它把「数据」放进了「规则」的位置：库一变就要重写提示词，各家长度上限还会静默截断。**规则应当只描述行为，不携带会变的数据。**
- **被否的第 1 条是这个决定的动机。** 「需要时再查」假设 agent 知道自己有库；新会话里的 agent 不知道，除非有人告诉它。

## 后果

- **触发从「被动等待」变成「每个会话一次主动读取」**，代价是那一次调用的输出进了上下文。
- **ADR 0089 的规则文本被取代**，其余决定（本机不装 skill、旅程正文在服务端、`setup` 删除）仍然有效。
- **`help usage` 的快照要改**，验收 18 的口径跟着改：除 `--no-login` 外不出现参数名。
- **漏做没有补救机制。** CLI 无法知道一个会话有没有读过库；下一次机会是 agent 真去检索时，或列表被截断时那句话。这是这条路的固有代价，不假装有解。
