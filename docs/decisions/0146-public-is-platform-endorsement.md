# ADR 0146 · 公开是平台背书：只有保留命名空间能把 skill 设为公开

- **状态**：已采纳
- **日期**：2026-11-05
- **所属版本**：[`v48-official-only-public`](../versions/v48-official-only-public/README.md)
- **依赖**：[ADR 0037](0037-visibility-has-two-states.md)（可见性只有私有与公开两态）、[ADR 0048](0048-visibility-hands-out-a-rung.md)（公开是把梯子的一档交给所有人）、[ADR 0082](0082-public-and-private-with-my-library.md)（公域 / 私域：库是引用）
- **补充**：[ADR 0048](0048-visibility-hands-out-a-rung.md) §后果 里「本版给了它一条路（`admin` 档能改）」——那句只说**在 skill 内谁有权限改**，没说**哪些命名空间可以把 skill 设为公开**。本 ADR 补的是后一层。

## 背景

[ADR 0048](0048-visibility-hands-out-a-rung.md) 定下了「公开之后陌生人拿到哪一档」，也就是公开的**深度**。它没有定公开的**主体**：任何一个 skill 的 `admin` 档持有者都能把可见性改成 `public`，服务端只校验值域（`private` / `public` 与 `invoke` / `browse`），不校验这个 skill 属于谁。控制台的设置页也把「私有 / 公开 · 调用 / 公开 · 浏览」摆给所有作者。

2026-11-05 产品负责人判定这是一条安全风险：公开意味着任何人搜得到、调得到，而平台没有审核、没有下架流程、没有对内容负责的人。于是定了方向——**现在不开放用户公开，只允许官方账号 `skillmaster` 公开**。

这条决定要回答的不是「公开有多深」，而是「公开这件事由谁来做」。它同时是下一版（公域信息与排序）与再下一版（开源 skill 自动同步）的前提：只有公域里的内容都由平台收进来，「公开 = 平台背书」才成立，信息面才有一致的来源与许可可讲。

## 决定

1. **只有 `official = true` 的命名空间能把 skill 设为 `public`。** 其他命名空间一律拒绝：服务端返回 403，错误码 `public_is_official_only`；skill 的 `visibility` 与 `public_rung` 保持原值。本版种子里被标为官方的只有保留命名空间 `skillmaster`。
2. **`public` 的语义从「作者的选择」变成「平台的背书」。** 公开仍然表示「谁都能搜到、谁都能调用」，深度仍由 `public_rung` 决定；改变的是**谁有权把它放进去**。[ADR 0037](0037-visibility-has-two-states.md) 与 [ADR 0048](0048-visibility-hands-out-a-rung.md) 的两态与档位不变。
3. **官方性是命名空间上的一个列，不是配置里的字符串清单。** `namespace.official` 由迁移/种子写，注册永远写 `false`；服务端读这一列，不读任何 slug 配置。作者面响应带一个只读布尔 `can_publish_public`，页面只按它决定摆不摆公开选项。加一个官方命名空间要走一次迁移/种子，不是改配置。
4. **存量一次转私有。** 迁移把 `official = false` 的命名空间里 `visibility = 'public'` 的行改成 `private`、`public_rung` 置空；**不删除 skill、不删除版本**。当前生产只有测试账号的两条（2026-11-05 盘点：公域共 4 条，2 条官方 + 2 条 `skillmaster-test`），产品负责人确认可以清掉或转私有。
5. **本版不提供用户公开的申请或审批流。** 将来要开放，必须新增一条 ADR，回答谁审核、审核什么、下架与申诉怎么走；在此之前，用户的公开诉求走再下一版的官方收录。
6. **`namespace.visibility` 沿用同一限制。** 它今天没有写入路径；将来若有，允许公开的命名空间与 skill 用同一个 `official` 标记。

## 理由

- **没有审核的公开，就是平台替任意内容背书。** 公开的 skill 会被任何持凭据的账号搜到、调用；平台既不审内容，也没有在出事时能找到的责任主体。把公开收回到官方，是用「少一类内容」换「公域里每一条都有出处」。
- **公开与私有是质变，不是设置项。** 私有 skill 只属于作者与协作者；公开之后它进入发现、被 agent 加载、可以被复制。这种动作不应该和改标题一样随手可选。
- **为什么不是先做一个审批流。** 审批需要审核标准、审核人、响应时限、拒绝理由、下架与申诉；这些今天都没有，做出来也是一个没人负责的队列。先关闭公开，等 v50 有了来源、许可与安全扫描，再把「官方收录」作为唯一入口，责任主体才是清楚的。
- **为什么不是只把前端选项藏掉。** 直接调 `PATCH …/visibility` 就能绕过去；公开是服务端发出去的票，必须由服务端挡。
- **为什么是命名空间上的一个列，不是配置里的 slug 清单。** 命名空间的 slug 就是账号的 handle，而注册允许人自己选 handle。如果官方性来自一份 slug 配置，那么运维把 `partner` 加进清单、而 `partner` 还没被平台占住时，任何人都可以注册 `partner` 并因此获得公开权——平台把背书发给了一个自己没控制的名字。列由迁移/种子写，注册路径不碰它，这才是用户造不出来的事实。
- **为什么存量转私有而不是删。** 内容仍然属于作者，删是不可逆的；转私有之后作者还能自己用、自己改。公域里少两条，比丢掉两份内容更容易解释。
- **为什么不留存量公开。** 留下的每一条都是没有背书的公域内容，而规则只对新写入生效会让公域长期处于「一半有背书、一半没有」的状态；这次盘点证明存量只有测试账号，代价可以接受。

被否掉的：**做审批流**（没有责任主体与流程，先关闭更诚实）；**只改控制台**（服务端可绕过）；**删除存量 skill**（不可逆，且没有必要）；**按账号白名单而不是命名空间**（地址的第一段就是命名空间，按命名空间判定与寻址一致，也能覆盖将来官方命名空间下的多个维护者）；**按配置里的 slug 清单**（slug 是用户可注册的 handle，见上一条理由）；**保留存量公开、只禁止新增**（公域会长期带着未背书内容）。

## 后果

- **非官方账号失去公开能力**：控制台的设置页只显示「私有」，API 直接返回 403；CLI 的 `skill visibility` 仍打开网页，页面按能力字段渲染。
- **生产公域从 4 条降到 2 条**：`skillmaster-test/pdf-table` 与 `skillmaster-test/meeting-notes` 转私有，不再出现在 `--scope public`、`/web/discover` 与公开标签的计数里。已经加入过它们的库条目会按 [ADR 0082](0082-public-and-private-with-my-library.md) §决定 6 进入休眠，不丢失。
- **测试环境沿用同一个种子**：`skillmaster` 的 `official` 由迁移置为 true，集成测试不需要额外配置；新注册的命名空间永远是 false。
- **公开能力的判定多一个只读字段**：作者面响应新增 `can_publish_public`，旧客户端忽略它；这是滚动升级安全的加法。
- **将来开放用户公开要新开 ADR**：本 ADR 只关闭入口，不定义重新开放的形状。
- **下一版与再下一版以本决定为前提**：公域信息与排序的信任信号、开源同步的来源与许可，都建立在「公域内容由平台收进来」之上。
