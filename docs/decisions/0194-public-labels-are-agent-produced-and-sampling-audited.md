## 背景

公域是开源同步进来的，没有作者在发布页上填分类与标签。1000+ 条（实际条数未核实）要人工逐条标，不可行；全部交给模型又会产生错标，而错标会直接进入用户的搜索结果。

三种做法：

| | 做法 | 问题 |
|---|---|---|
| a | 全人工标 | 质量最高，但不随公域规模扩展；运营会被打标淹没 |
| b | 只映射上游 frontmatter | 零幻觉，但绝大多数开源 skill 不写这些字段，覆盖率会很低 |
| c | **Agent 自动打 + 抽样验收** | 覆盖率可扩展；用统计验收代替逐条审核 |

「人工逐个查看比较麻烦」是这次要解决的核心问题。答案不是「看得更快」，是**不要逐条看**。

## 决定

1. **Agent 在线跑。** 输入是 `SKILL.md`、文件清单与上游仓库简介；输出是结构化标签：一级分类、属性标签、`outcome`。每个值带 `confidence` 与 `evidence`（引用的原文行或文件路径）。
2. **没有证据就不落标签。** 证据可以是 SKILL.md 的一句原文、文件清单里的一项、上游 `repo.description`；找不到就留空，不猜。
3. **三档路由**：
   - **高置信**（阈值以上，且证据存在、多次采样一致）→ 直接生效，进抽样池。
   - **中置信** → 生效但标「待确认」，进异常队列。
   - **低置信** → 不生效、留空，进异常队列。
   阈值不是拍死的，由金标集实测后定；首版倾向 `高 ≥ 0.85`、`中 0.50–0.85`、`低 < 0.50`。
4. **抽样验收，不逐条审核。** 每周从「高置信自动通过」里随机抽 **30–50 条**，算准确率；目标 **≥ 95%**。达标继续自动；不达标收紧阈值、改提示词，或把该维度退回人工。
5. **异常聚合成簇。** 运营看的是「同一来源仓库批量低置信」「同一类目大面积空缺」「标签互相矛盾」「用户纠错集中」这类簇，不是 1000 条清单。异常队列 / CI 报告的默认视图是簇；**不提供运营专用 CLI**。
6. **金标集回归。** 人工标 **100–200 条**作为金标集；每次改提示词、换模型、调词表，先跑金标集，精度不过线不上线。
7. **用户纠错闭环。** 信息页与 `skmr skill show` 提供「这个标签不对」；纠错进异常队列，并作为改进提示词的 few-shot 样本。
8. **随版本重算，运营覆盖优先。** 上游发新版重抽；运营改过的值保留；冲突留痕（谁、何时、旧值、新值）。

## 理由

- **为什么是抽样而不是全检。** 人工成本要随「异常数」增长，而不是随「公域条数」增长。全检在 1000+ 条时不可持续，而且大部分条目是模型有把握的——逐条看是在为少数异常付全量的钱。
- **为什么高置信也要抽检。** 模型的错误不是均匀分布的；只在中低置信里找异常，会漏掉「高置信但系统性错」的那一类。抽样是唯一能发现这类错误的便宜手段。
- **为什么要有金标集。** 没有金标集，「改完提示词后变好还是变坏」只能靠感觉。金标集让每次改动可回归，也让阈值可以按精度而不是按意见来调。
- **为什么异常要按簇看。** 1000 条里逐条看是 O(N)；同一个来源仓库的结构相似、同一个类目的边界相似，错法也相似。按簇处理，是把 O(N) 降到 O(簇)。
- **为什么用户纠错要接进来。** 它是最便宜的持续校准来源，也是唯一能覆盖「模型与运营都没想到」的错法。

被否掉的：**全人工标**（不随规模扩展）；**只映射上游字段**（覆盖率低）；**模型标完全信**（错标直接进用户视野）；**逐条人工确认**（等于全检，成本不可接受）；**只在中低置信里找错**（漏掉高置信的系统性错误）。

## 后果

- **新增一条抽取任务**：同步建草稿或发布时触发；首次是全量回填，之后按版本增量。
- **模型成本**：每次约 1–3k tokens 输入；条数与单价决定总成本，首轮实测后再估。
- **运营面走覆盖文件 + CI 报告，不提供 CLI**（2026-11-13 用户定）：所有 `skmr` 命令都面向用户，不是运营工具。运营校准写 `deploy/label-overrides.yml`，抽样判定写 `deploy/label-audit.yml`，异常簇与准确率由 CI 报告呈现；这一期不做控制台工作台。
- **审计与版本**：每次写入记 `model`、`model_version`、`taxonomy_version`、`confidence`、`evidence`、`source`；人工改过再记 `actor` 与时间。
- **阈值可调**：95% 与 30–50 条是首版目标，首轮金标集实测后可调；调整不改变「抽样验收」这条决定。
- **失败可见**：抽取失败或低置信集中时，异常队列要能按来源/类目聚合；不能只沉在日志里。
