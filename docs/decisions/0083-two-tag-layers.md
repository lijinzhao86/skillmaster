# ADR 0083 · 两套标签：公开分类、公开标签与我的标签

- **状态**：已采纳
- **日期**：2026-10-23
- **依赖**：[ADR 0078](0078-a-category-is-one-shelf.md)（分类是一个货架）、[ADR 0079](0079-cli-manages-tags-and-library-references.md)（CLI 管贴法、新建、定义编辑与库引用）、[ADR 0082](0082-public-and-private-with-my-library.md)（公域 / 私域与我的库）、[ADR 0031](0031-submitting-and-publishing-are-two-actions.md)（标签改完立即生效）

## 背景

v14 需要三层词，而它们回答的问题不同：**分类**是平台给的粗坐标（一个货架），**公开标签**是作者给内容写的召回词，**我的标签**是用户对自己库的组织。前两层属于 skill、公开可见；第三层属于“人 + skill”、只有本人可见。

目标态与旧设计只把标签当成一层，没有区分公开与私人，也没有「库」这一层。私人标签因此没有落脚点：它不能贴在库外，也不能在共享被撤销时凭空消失。这一版把两层一次做完：我的标签落成，公开标签也落成最小闭环（贴 / 摘 / 召回），不只是一层画出来的壳。

## 决定

1. **公开分类**是平台词表：平级 10 个词、每个 skill 只贴一个、单选替换不是追加（[ADR 0078](0078-a-category-is-one-shelf.md)）；所有能看见该 skill 的人都能看到；所有者与 `admin` 可编辑。
2. **公开标签**是作者的自由词：每个 skill ≤10 个，名字 1–24 字；公开可读、用于搜索召回；同一 skill 内按规范化名字唯一（NFKC、去首尾空格、内部连续空格压成一个、大小写不敏感），不得与公开分类重名。贴 / 摘立即生效、不产生版本。
3. **我的标签**是私人组织层：每个 skill ≤20 个生效贴法，每个账号 ≤100 个定义（含只有休眠贴法的）；每个定义可以有一句**说明**（选填 ≤200 字），说什么时候该贴它，人和 agent 读同一句。只有本人可见，且**只属于库**：不在库、条目休眠、不可见时不能读写。
4. **范围出生即定**：我的标签不能转公开，公开标签不能转私人；用户不能自建公开分类。三层的权限、可见性与生命周期各自独立。
5. **定义与贴法分开**：改名让所有贴法一起显示新名字、计数不变、旧名失效；改说明不动贴法；**删除定义会摘掉所有贴法（含休眠）且不能恢复**，因此留在控制台的红色确认弹窗。
6. **休眠与恢复**：库条目休眠时，我的标签一起休眠（读路径不返回、计数不算）；条目恢复可见或重新加入时回来。
7. **CLI 分组（更正 [ADR 0077](0077-the-cli-grammar-is-singular-and-plural.md) §决定 2 的那句）**：读**一个** skill 的三组词是 `skill tags <地址>`，写一个 skill 的贴法 / 分类是 `skill tag add|remove` / `skill category set|clear`——它们作用于一个已存在的 skill，按 0077 §决定 1 归 `skill` 组。集合侧的词表与定义是 `skills categories` / `skills public-tags` / `skills my-tags` 与 `skills my-tags add|rename|describe`，归 `skills` 组。
8. **`skills my-tags add` 新建的定义没有贴法**；由 `skill tag add` 顺手新建的定义没有说明（要写说明先 `skills my-tags add --describe`）。

## 理由

- **三层词的用途不同，混成一层就必然打架。** 分类要稳定、可筛选、平台可控；公开标签要自由、可增长、服务召回；我的标签要私密、可组织、跟着库的生命周期走。合成一层会让其中两个需求都失败。
- **公开标签是搜索召回的主要来源。** 分类只有 10 个粗货架，覆盖不了“这个 skill 到底解决什么问题”；作者写的自由词更接近用户的问题语言。先做最小闭环（贴、摘、搜到），治理留到有信号时。
- **我的标签必须挂在“人 + skill”上。** 它服务的是一次共享结束之后仍然存在的组织关系；挂在 skill 上会让它变成公开元数据，挂在用户上又表达不了“对这一个 skill 的归类”。
- **说明是给 agent 选标签的那一句。** agent 能读词表却不知道什么时候该贴，说明把“为什么”从人的脑子里搬到数据里；它不值一列宽，所以住在名字右边同一行。
- **删除是唯一不可逆的动作。** 改名、改说明、贴、摘都能改回来；删除会连坐休眠贴法，因此留在控制台（[ADR 0079](0079-cli-manages-tags-and-library-references.md)）。

被否掉的：**只有一层标签**（三种用途打架）；**我的标签参与版本**（标签是发现用的元数据，改完立即生效，变更留在审计）；**导入 SKILL.md 的 `metadata.tags`**（两个来源会打架）；**多选分类 / 多级分类树**（[ADR 0078](0078-a-category-is-one-shelf.md)）；**公开标签的同义词合并、改名 / 合并、审核与全局标签页**（治理需要独立信号与运营）；**我的标签转公开**（范围出生即定）。

## 后果

- 新增标签定义的存储（公开分类词表来自迁移种子；我的标签定义按用户唯一；公开标签没有独立定义表，词形即标识），新表落 M12。
- 控制台信息页三组词就地编辑；标签页两个页签；库的筛选与管理页计数链接。
- CLI 新增 `skill tags` / `tag` / `category`、`skills categories` / `public-tags` / `my-tags` 与三个定义写命令；`skill` 组的读命令是 [ADR 0077](0077-the-cli-grammar-is-singular-and-plural.md) 的更正。
- 审计记录贴 / 摘 / 定义 CRUD，但**不存我的标签的名字**，避免私域内容进日志。
- [ADR 0078](0078-a-category-is-one-shelf.md) 的写作前提（公开标签尚未实现）已过时，它的分类单选决定不变；本 ADR 记录了公开标签的落版。
