# 0173 · 复制是把一版已发布内容放进自己的命名空间

- **状态**：已采纳
- **日期**：2026-11-09
- **所属版本**：[`v54-skill-copy`](../versions/v54-skill-copy/README.md)
- **依赖**：[ADR 0048](0048-visibility-hands-out-a-rung.md)（公开最多给到浏览）、[ADR 0051](0051-the-author-plane-serves-by-tier.md)（按档位服务）、[ADR 0064](0064-a-draft-may-change-a-published-version-may-not.md)（版本不可变）、[ADR 0070](0070-creating-a-skill-creates-its-first-draft.md)（建 skill 即建第一条草稿）、[ADR 0160](0160-imports-are-renamed-by-an-optional-source-prefix.md)（改名的内容改写规则）
- **被 [0183](0183-deleting-a-skill-releases-its-name.md) 修订**：复制到一个刚被删除、名字因此空出来的地址不再撞上已删行；**正文按原样保留**。
- **被 [0184](0184-taking-a-public-skill-down-is-a-service-lifecycle.md) 确认**：下线中的源仍可复制——被拒的是新入库，不是复制（复制正是下线中给出的迁移出路）。

## 背景

第一版的上线承诺是「找到 → 复制 → 改」。今天两条路都不通：

- **入库**（`skill join`）只收一条引用，内容仍属于原作者；`CreateDraftFromVersionUseCase` 要求对该 skill 有 `write`，而公开最多给到 `browse`（0048 §决定 3）。
- **下载 → 解压 → 改 `SKILL.md` 名字 → 导入**要三步，容易丢掉来源，而且导入走的是 `findOrCreate`：同名 skill 已经存在时会把内容追加进去，不是拒绝。

可选的做法：

| | 做法 | 问题 |
|---|---|---|
| A | 把公开档位提到 `write` | 等于「任何人改任何人的 skill」；0048 已经否过 |
| B | 下载 zip 再走 `SubmitSkillUseCase` | 多一次完整的字节往返与重新归一化；`findOrCreate` 的语义不对；改名的目标名字要另找地方校验 |
| C | 读源版本的 manifest，建一个新 skill 和一条草稿 | 采纳 |
| D | 只在库里记一条「复制自」的引用 | 仍然不是一份可改的、属于自己的内容 |

## 决定

1. **复制读的是已发布版本，源必须对调用者达到「浏览」。** 公开的、别人共享给你的私有 skill 都算；源是调用者自己拥有时**不允许**——要改自己的 skill 直接新建版本。草稿、已丢弃、已下架不复制。
2. **目的地永远是调用者的个人命名空间，产出是一个私有的新 skill 和一条草稿**，不自动上线。内容取源版本的 manifest，不复制 zip、不重新归一化；只有目标名字与源 `SKILL.md` 的 `name` 不同时才改写那一个字段（0160 的规则），相同就一个字节都不动。
3. **名字必填，冲突拒绝，不自动加后缀。** 同名活 skill 是 `skill_already_exists`，同名已删除是 `skill_deleted`；客户端在拒绝后把动作置灰，直到名字改掉。
4. **出处是一条 `skill_copy` 行，不是 `skill_source`。** 行里记源 skill / 源版本 id、复制那一刻的源地址与版本标识、谁与何时。`skill_source` 继续只表示外部来源（GitHub 等），不把内部复制混进去，也不让来源刷新任务去碰它。
5. **许可随行，不作为复制的门槛。** 源版本的 `skill_version_license` 复制到新版本；源未声明时照记未声明。复制不检查许可。
6. **不带走的私有事实**：分类、公开标签、我的标签、收藏与调用量、协作者、服务凭据、可见性。
7. **v1 不回流**：不建立与源的持续关联，不自动合并上游，不通知原作者；公域仍只由运营按白名单同步。

## 理由

- **A 被否，因为「所有人」不是一个能对维护负责的主语。** 公开是背书，不是把写权限交出去；这条线在 0048 已经画过。
- **B 的正确性成本更高。** 复制是「把已经存在的一版搬过去」，不是一次新的上传：manifest 与源共享同一批 blob（内容寻址），重新打包再解包只会多一次字节往返、一次重新归一化，以及一个得绕开 `findOrCreate` 的补丁。`createOwned` 本身就是「没有人有这个 名字」的答案，复用它比在导入路径上加一个开关更直。
- **C 的代价是源版本必须可读。** 这正是「浏览」档的含义；调用档读不到文件清单，复制就会把作者没打算公开的文件交给调用者，所以不放开。
- **出处独立成表，因为它是内部血缘。** `skill_source` 的语义是「内容从哪个外部来源来」，参与来源刷新与导入去重；一条内部复制混进去，会让刷新任务把同平台的另一个 skill 当成上游仓库。`skill_copy` 只被信息页与 CLI 读，不被任何后台任务碰。
- **不改名时零改写。** 复制最常见的路径是「原名复制」；这时内容与原版本逐字节相同，最该证明的一件事是「它真的没有动过」。
- **不加后缀，因为地址是用户记住的东西。** `-2` 这类后缀会让两个 skill 的名字无法预测；冲突时让人起名，地址始终由人决定。

## 后果

- **源被删除或下架后，副本仍在。** 这是一份快照，不是引用；作者收回的是源，不是已经交出去的内容。这正是「复制」与「入库」的区别，也是 `skill_copy` 记下源地址文本而不是只记 id 的原因。
- **出处是快照，不跟随源改名。** 源 skill 以后改名，副本的信息页仍显示复制那一刻的地址；精确身份在 `source_skill_id` / `source_version_id` 两列里。
- **副本是私有的，普通命名空间不能把它设为公开**（[ADR 0146](0146-public-is-platform-endorsement.md)）。复制解决的是「我能改」，不是「我能再发布到公域」。
- **许可状态跟着源走。** 源未声明时副本也显示未声明；平台不因为一次复制把「未声明」洗成可用。
- **复制写一条审计**（`copy`），源地址、源版本、新 skill 与草稿都在里面；上线后可以从审计量复制次数。
- **后续版本不自动带出处外的关联。** 副本的第二版、第三版仍属于这个新 skill；`skill_copy` 描述的是「这个 skill 从哪来」，不是每一版都与源逐版对应。
