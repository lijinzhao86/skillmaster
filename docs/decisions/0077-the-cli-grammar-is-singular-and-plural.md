# ADR 0077 · CLI 的命令按单复数分组

- **状态**：已采纳（`tags` 的归属由 [0083](0083-two-tag-layers.md) 更正：读单个 skill 的标签归 `skill` 组）
- **日期**：2026-10-22
- **依赖**：[ADR 0002](0002-gateway-skill-and-cli.md)（网关 skill + CLI）、[ADR 0011](0011-server-and-cli-stack.md)（CLI 用 Go）

## 背景

CLI 的 `skill` 组里有两个只差一个字母、都合法的命令：

- `skill list` 列**多个** skill（调用者读得到的目录）；
- `skill ls`（`files` 是别名）列**一个**版本里的文件。

两者都不算错，所以没有报错能把人拦住。2026-10-22 产品负责人把 `skill list` 读成“列一个 skill 里的文件”——这不是记错，是命名让人这么读：`list` 在 Unix 里最自然的联想就是列文件，而 `ls` 又真的就在旁边。

帮助自己也不一致：`skill` 组的帮助把 `ls` 当主命令、说 `files` 是别名；顶层帮助写的是 `files`；代码里的主命令其实是 `files`。一个人看两份帮助会得到两个不同的“正名”。

紧接着 v13 要往集合这一侧加“发现 / 标签过滤”的命令。如果继续往 `skill` 组里塞，问题只会放大：同一个组里既有“作用于一个 skill”的动词，又有“作用于多个 skill”的动词，每加一个都要重新解释它属于哪一边。

## 决定

1. **`skill` 是一个 skill 上的动作。** 这个组里作用于**一个已存在 skill** 的动词都带一个 skill 地址；`create` 与裸 `submit` 是新建/提交一个 skill 的例外，不接收已存在地址；不作用于一个 skill 的命令不属于这里。
2. **`skills` 是多个 skill 的集合。** 这一版是 `list` 与 `search`；v14 的标签命令（`tags` / `my-tags`，以及可能的 `discover`）也放这一组。
3. **文件枚举的正名是 `skill files`。** 帮助只宣传 `files`；`ls` 不进入正式命令面。
4. **旧的 `skill list` / `skill search` 不进入正式命令面。** 这个产品还没上线，旧命令没有用户迁移成本；上线前直接把命令收干净，比带着一批马上要删的别名更稳。
5. **网关 skill 跟着改。** 第 1 步改成 `skillmaster skills list`，检索改成 `skills search`；`metadata.platform_api_version` 从 `8` 加到 `9`，`setup` 重装时会把版本变化说出来。
6. **顶层 `login` / `logout` / `setup` 与 `version` 组不动。** 前者作用于这台机器，后者是作者面的版本管理，各自有自己的名词。

## 理由

**单复数是一条可记住的规则，不是又一对需要解释的命令。** `skill` 下的每个动词都作用于一个对象，`skills` 下的每个动词都回答“哪些”；看到一个命令就知道它属于哪边，不需要先查帮助。

**未上线就不需要兼容旧命令。** 兼容期是给已经发布给用户的契约准备的；这里还在上线前，旧脚本、旧网关与 QA 探针都是仓库里的开发态资产，应当随正式命令面一起改掉。把 `skill list` / `skill search` / `skill ls` 保留下来，只会让帮助之外又多一套“其实也能跑”的语言。

**stdout / stderr 的边界仍然成立。** 这条边界用于正式命令与将来的已上线迁移：stdout 是命令的答案，stderr 是提示、进度、错误。只是本次没有旧命令迁移提示要输出。

**`ls` 不做隐藏别名。** 它确实是 Unix 的肌肉记忆，但这里列的是远端版本清单，不是本地目录；既然产品还没上线，就不把这个歧义作为兼容接口发布出去。

**否掉“只改帮助、保留 `skill list`”。** 词本身仍然让人读成列文件；帮助写得再清楚，也改不了第一眼的理解。

**否掉“保留一版别名”。** 兼容期是给已经发布给用户的契约准备的；这里还没上线，旧脚本、旧网关与 QA 探针都是仓库内的开发态资产，应当随正式命令面一起改。保留别名只会让帮助之外又多一套“其实也能跑”的语言，而收益只是少一个转发分支。

## 后果

- **没有旧命令兼容期。** `skill list` / `skill search` / `skill ls` 都不进入正式命令面；现有实现分支与 QA 探针要改到新命令。
- **当前文档跟着改**：`skillmaster-cli/README.md`、`gateway/skillmaster/SKILL.md`；历史版本文档（`docs/versions/v*`）按文档架构的规矩不改写，它们是记录。
- **v14 的标签命令有位置了**：集合侧的命令放 `skills`，`skill discover` 若要保留，只能是 `skills list` 的薄别名，默认带上限，不能是 `skill` 组的动词。
