# ADR 0101 · CLI 永不删除文件

- **状态**：已采纳
- **日期**：2026-10-27
- **依赖**：[`versions/v24-cli-file-footprint/`](../versions/v24-cli-file-footprint/prd.md)、[0025](0025-cli-credential-storage.md)（凭据的两个存放处）、[0035](0035-the-pin-lives-on-the-client-machine.md)（钉在客户端）、[0038](0038-default-credential-is-an-api-key.md) §决定 7（`logout` 不调服务端）
- **修改**：[0025](0025-cli-credential-storage.md) 里「`logout` 要清两处」的**兜底文件**那半，从「删掉」改为「清空」；钥匙串那半不变

## 背景

CLI 是给 agent 用的，而 agent 越来越多地跑在沙箱里。沙箱对工作区之外的每一个文件动作逐次审批，**删除**是其中最难跨过的一类：它看起来像 agent 要拿走东西，审批界面会停下来等人。

现在的 CLI 有九处会发出删除（清单与行号见 [v24 PRD](../versions/v24-cli-file-footprint/prd.md) §事实）。它们没有一处是产品要求删除的：

- 五处是「临时文件 + `rename`」的收尾：`defer os.Remove(tmpName)` 在 rename 成功之后照样执行，删的是一个已经不存在的名字，**必然失败**——pin 与凭据都从未被删掉，只是 unlink 系统调用发出去了；
- 两处是 `logout`（清掉本机的凭据）；
- 两处是下载失败时的半成品清理。

摆在面前的三条路：

| | 方案 | 代价 |
|---|---|---|
| 1 | 保留删除，让宿主按路径放行 | 每个沙箱、每个人各配一遍；配置是隐形的，新机器/新同事都会再撞一次 |
| 2 | **CLI 不再删除任何文件** | 失败时半成品留在原地，要人来清；状态写入不再原子 |
| 3 | 把状态搬进工作区 | 改 [0035](0035-the-pin-lives-on-the-client-machine.md) 的语义；而且只搬走了删除点，没有消灭删除 |

## 决定

1. **发布出去的 `skillmaster` 二进制不在任何路径上发起 `unlink` / `rmdir` 类调用**：`os.Remove`、`os.RemoveAll`、`syscall.Unlink`、`syscall.Rmdir` 等在非测试代码里为零，失败路径也不删。
2. **状态写入改成不产生临时名的形态**：
   - pin：一 skill 一文件，**原地覆写**（`OpenFile(O_CREATE|O_WRONLY|O_TRUNC)`）；
   - 凭据：先写同目录下固定的 `.new` 兄弟文件，再 `rename` 覆盖——原子性保留，收尾不再删临时名；
   - `logout`：把凭据文件**截断为 0 字节**（空文件＝没有凭据），不删文件；
   - `download`：档案在**内存里**解包，写入一个本次独有的 staging 目录，成功后 `rename` 到位；失败时 staging 留在原处，错误句点出它的路径。
3. **这条约束由可执行检查强制**：一个 `go/ast` 测试扫描本模块非测试源码，发现删除原语即失败；它随 `go test ./...` 在 CI 里跑。**测试代码**（`_test.go`，用 `t.TempDir` 清理自带目录）与**安装脚本**（`install.sh` / `install.ps1`）不在约束范围内。

## 理由

**为什么否掉方案 1（让宿主放行）。** 沙箱审批的意义就是「这件事有人看过」。把删除放进白名单，等于要求每个使用沙箱的人替我们做一次安全判断，而判断的依据（CLI 本来就不需要删）只能从源码读出来。这条约束一次修好，所有宿主都受益；配置放行则是一台机器一次、一个沙箱一次。

**为什么否掉方案 3（搬进工作区）。** 它改的是 [0035](0035-the-pin-lives-on-the-client-machine.md) 的语义（钉是**机器**的事，不是项目的事），而且 `logout`、下载失败清理这些删除点并不因为搬家而消失——它们只是换了目录。真正的目标是「不删」，不是「删在别处」。

**为什么 `logout` 用截断而不是删。** 空文件与不存在，对读取方是同一个事实；`Load` 因此必须把空文件读成「没有凭据」（见[后果](#后果)）。截断满足「清掉本机凭据」这个动作的全部语义，却不发出删除。

**为什么宁可在失败时留垃圾。** 下载失败留下 staging、凭据保存失败留下 `.new`，都是本次运行自己创建的东西。留着的代价是占一点磁盘、需要人看一眼；删掉的代价是每个沙箱里的一次审批。前者可以靠错误句点名来收，后者无法靠产品收。**人来做删除**——这与「危险动作要显式确认」是同一条线。

**为什么失败路径也不留例外。** 失败一次就删一次，等于把「零删除」变成「正常时零删除」；而沙箱不区分这两者。要守就守成不变量，否则它会在最不巧的时候被打破。

## 后果

- **失败会留下半成品**：`<target>.<后缀>-staging-*`、`credentials-<hash>.new`。错误句必须点名路径，否则用户不知道磁盘上多了什么。这是本 ADR 明确接受的代价。
- **pin 的写不再原子**：同一 skill 被两个 agent 同时 `invoke` 时，原地覆写可能交错出一份解析不了的文件。旧形态（读整表 + 临时文件 + rename）在那时是「后写者赢、两份都有效」。新形态把这一类竞态从「静默选一个」变成「读的时候响亮地报错」——按本项目的取向，后者更好，但它确实是退了一档，记在这里而不是藏起来。不同 skill 不受影响（各写各的文件），而旧形态在**不同 skill** 之间是会丢更新的。
- **旧文件永远留着**：`pins-<server 哈希>` 单文件降为只读回退，不删；`logout` 之后凭据文件以 0 字节的形态留着。磁盘上的“空壳”是本约定的可见痕迹。
- **`Load` 的语义要跟上**：凭证文件的空内容必须读成「没有凭据」，否则截断之后会被当成一把空 token。
- **凭据的 `.new` 兄弟文件是固定名字**，所以同一台机器上两个 `login` 同时写时可能交错出一份解析不了的凭据；旧形态（`os.CreateTemp`）每次一个新名字，没有这一档。窗口是「同一个人在同一台机器上同时开两个登录」，失败在下次 `Load` 时响亮报出——记在这里，而不是藏起来。
- **以后真要删除时，先改这条 ADR**：任何新加的删除都必须同时改 `internal/nodelete` 的检查与这条记录，否则 CI 会红——这是有意的摩擦。

## 后果之外的边界

- 钥匙串条目的删除（`keyring.Delete` / `security delete-generic-password`）不是文件删除，不受本约束；`logout` 仍要清钥匙串。
- `rename` 不是删除：它在系统调用层是 `rename(2)`，沙箱不把它算作删除，本约束也不限制它。
- 安装脚本的 `rm -rf` 不在范围内（见 v24 PRD「不做」第 6 条）。
