# 0120 · 文件枚举的正名改成 `skill ls`（取代 0077 决定 3）

> **状态**：已采纳
> **日期**：2026-10-30
> **取代**：[0077](0077-the-cli-grammar-is-singular-and-plural.md) 决定 3（`skill files` 是文件枚举的正名、`ls` 不进入正式命令面）

## 背景

0077 把文件枚举的正名定为 `skill files`，并明确禁止 `ls` 进入命令面。当时它同时写了两条理由：`skill list` 与 `skill ls` 只差一个字母、都合法，而 `list` 在 Unix 里最自然的联想就是列文件；以及「`ls` 列的是远端版本清单，不是本地目录」，这个语义借用不该作为兼容接口发布出去。

这两条前提在 v34 前都变了：

- **混淆源没了。** 0077 决定 4 自己把 `skill list` / `skill search` 收掉，`skill` 组里不再有一对只差一个字母的命令，`ls` 没有邻字可混。
- **命名的目标变了。** v34 的整版路线是「命令名与语义跟 Linux 一致，agent 不需要另学一套」（v34 PRD §目标）：`ls` / `find` / `stat` / `head` / `tail` / `grep` 都在，只有文件枚举还叫 `files`，它是这套词里唯一的自造名。agent 的肌肉记忆里没有 `files`，敲出来要靠查。

0077 的另外两条理由仍然成立，只是不再指向 `files`：「未上线就不需要兼容旧命令」（那正是直接退役 `files` 的依据）与「`ls` 确实容易和本地目录混淆」——后者是语义边界的事，靠输出形状与帮助说清楚，不靠换名字。

## 决定

1. **文件枚举的正名是 `skill ls`。** 现行文档、帮助、子命令建议、错误句一律只写 `ls`。写 `files` 只剩三种场合：退役那句话（不然它指不到自己）、描述**改版前现状**的表、以及**历史记录**（历史 ADR、带日期的实测记录）。
2. **`skill files` 退役**，按 [0112](0112-retiring-a-command-within-one-generation.md) 的形态：名字还在，回一段含「已经退役」的说明并同时指向 `ls` 与 `find`，退出 2。
3. **0077 只有决定 3 被本条取代。** 决定 1 / 4 / 5 / 6（单复数分组、旧命令不进命令面、网关跟着改、顶层不动）继续有效；决定 2 的那句早在 [0083](0083-two-tag-layers.md) 就更正过，不是本条改的。
4. **`ls` 借用的是名字，不是语义。** 它列的是**一个远端版本里的条目**：目录带 `/`、`-l` 给类型与字节、`-R` 递归——形状按 v34 自己的规格，不因为换了名字而变。凡是需要「这是远端清单」的地方（版本注记、地址写法）照旧写清楚，不用命令名去暗示本地目录。

## 理由

- **否掉「保留 `files`，让 `ls` 当别名」**（[0088](0088-cli-major-version-is-the-api-generation.md) 决定 2 的改名形态）：产品未上线，按 0077 决定 4 的原则直接收干净；两个名字并存意味着帮助、建议列表、错误句三处都要维护两种说法，而调用方还得挑一个来记。
- **否掉「继续用 `files`」**：它是这套命令里唯一的自造名，agent 要为它单独学一个词，而这个词在别处不存在。
- **接受「远端清单上轻微借用 `ls` 的语义」**：可理解性优先于严格的目录语义，与 v34 整版的取舍一致。代价写在决定 4 里——用输出与帮助把「远端」说出来，而不是靠命令名。
- **不把 0112 当作本条的退役依据**：0112 决定 1 的前提是「功能换了归属」，而 `files` → `ls` 是同一个 CLI 面内的改名。本条退役依据是 0077 决定 4 的「上线前收干净」；退役的**形态**（一句话、退出 2、指向新去处）才来自 0112。

## 后果

- **早期 ADR 里写 `files` 的句子是历史原话，不改**：0036 决定 5、0098 的索引行等仍会出现 `files`。这些记录的是当时的命令面，以本条为准，不再逐条回写。
- **`skill files` 的退役句是命令契约的一部分**：必须含「已经退役」、退出 2、同时给出 `ls` 与 `find`，由 `TestFilesSaysItBecameLs` 钉住。
- **v34 之后新增的文件类命令按 Linux 的名字取**（`ls` / `find` / `stat` / `head` / `tail` / `grep`），不再出现第二个自造名；`skill wc` / `skill check` 保持原名。
- **改名发生在 `1.x` 之内，没有换 API 代次**（「代次」在 [0088](0088-cli-major-version-is-the-api-generation.md) 里指主版本号）：写在 1.x 里的旧脚本会拿到退出 2 与一句指向 `ls` 的话，而不是继续跑。产品未上线，没有外部调用方要迁。
