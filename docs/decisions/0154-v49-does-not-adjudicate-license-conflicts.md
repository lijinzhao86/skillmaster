# 0154 · v49 不裁决许可冲突，冲突校验放到下一版的入库流程

- **状态**：已采纳
- **日期**：2026-11-06

## 背景

v49 原计划把「仓库 LICENSE 与 SKILL.md 的 `license` 不一致」显示成第五种状态 `conflict`（「许可待核」），并列两个值、不下结论。展示层只陈述不一致，**不能阻止一个许可不明的 skill 被继续导入、发布或使用**；而真正能执行判断的时机是内容进入平台的那一刻。下一版要做完整的许可逻辑，v49 再保留一个只用于展示的冲突状态，会多一套状态、多一套文案，也不会带来执行上的保护。

## 决定

- v49 的许可状态只有四种：`ok`、`declared-only`、`missing`、`other`。
- 有来源许可文件时，**文件的值就是这一版的值**；SKILL.md 的声明保留在 `detail` 里，但不用来裁决、也不在页面并列。
- 声明与文件不一致不在 v49 拦截、不产生第五种状态。
- 冲突检测与拦截属于 **下一版的入库流程**：在内容进入平台时校验声明与文件是否一致，并决定拒绝、要求确认还是记录例外。

## 理由

- **在能执行的地方判断。** 展示层的「待核」只是把问题交回给读者；入库校验可以在写入前拦住它。
- **状态要对应页面能做的事。** v49 页面只能展示，不能核验，多一个冲突态没有增加信息，只增加了两套文案与两条测试路径。
- **不重复实现。** 下一版的许可逻辑会重新定义校验规则；在 v49 先写一套展示规则，之后要再改一次。

## 后果

- [ADR 0148](0148-a-license-belongs-to-the-version-and-not-to-the-file-tree.md) 的「五种状态」部分被本决定取代；「许可按版本存」「全文按版本」「missing 不默认 MIT」仍有效。
- 页面、CLI、设计件与测试只覆盖四态；`conflict` 不再出现在 v49 的任何输出里。
- 下一版开版时必须增加入库校验，并决定不一致时的产品动作（拒绝、确认或例外记录）；在此之前，展示层按来源文件的值如实展示。
- 表结构没有状态约束，本决定不需要迁移；v49 尚未发布，不存在需要转换的 `conflict` 行。
