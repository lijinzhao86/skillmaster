# 0061 · 凭据能对版本做什么：不改变调用者所读的都可以，改变的不行

- **状态**：已采纳
- **日期**：2026-10-20
- **依赖**：[0031](0031-submitting-and-publishing-are-two-actions.md)（上线只在浏览器面）、[0046](0046-deleting-a-skill-happens-in-the-browser.md)（删除只在浏览器面）、[0054](0054-lifecycle-actions-happen-on-a-version-page.md)（生命周期动作在单版页上）、[0060](0060-discarding-a-draft-is-not-dangerous.md)（判据是「调用者会不会立刻读不到东西」，不是「可不可逆」）、[0051](0051-the-author-plane-serves-by-tier.md)（作者面按档位分）
- **这一条是 0031 §决定 2 那条规矩的第三次应用，而且第一次把它的正面写出来。** 前两次都是在**收回**一条路由（上线、删除）；这一次要回答的是「剩下的那些，凭据能不能做」，因为 agent 开始需要一个管理版本的 CLI 面。0031、0046 的正文不改。

## 背景

v6 给版本补齐了作者面：版本有必填的名称与一句说明，有草稿、线上、历史版本、已下架、已丢弃五个产品状态，改名、改说明、丢弃、上线、下架、重新上架都在那一版自己的页面上（[ADR 0054](0054-lifecycle-actions-happen-on-a-version-page.md)）。这些动作今天**只有网页那条路**：`/web/**` 是会话 + CSRF；`/api/v1` 上有提交、消费面的读与共享（`grants`），但**没有一条作者面的版本路由**。

但 v6 的读者不只是人。agent 在本地写、提交草稿、看这个 skill 有哪些版本、比较草稿与线上差在哪、给草稿改一个名字或一句说明、丢掉一个提交错了的草稿——这些是 agent 该做的事，而它手里只有一把凭据（API key 或 `skillmaster login` 换来的登录态）。让它在每一步都打开浏览器，等于把「准备」也交给一个人，而[产品对提交与上线分开](0031-submitting-and-publishing-are-two-actions.md)的本意恰恰是：**准备可以无人值守，让调用者读到什么不行。**

于是问题只剩一个：**凭据能对版本做的事，到哪里为止？**

## 决定

1. **判据是「这个动作改不改变调用者读到什么」，不是「它可不可逆」，也不是「它危不危险」。**
   - **改变调用者所读**：上线（含回滚）、下架、重新上架、整个 skill 下线 / 恢复服务、删除 skill——**只有浏览器面**，API 平面**没有路由**，任何凭据都做不到。
   - **不改变调用者所读**：读作者面的版本、提交草稿、给草稿改名与改说明、丢弃草稿——**凭据可以做**，条件是它在这个 skill 上的档位够（[ADR 0047](0047-permissions-are-a-ladder.md)），以及凭据自己的 scope 够。
2. **作者面在 API 平面上有一个自己的路径**：`/api/v1/author/skills/{namespace}/{name}/…`，Bearer + scope，档位用同一把梯子判。**列表与单版在入口要求 `browse`+**——网页那条路对 `invoke` 还给一个只读投影，CLI 不需要第二个「调用者看作者面」的入口（调用者用 `skill versions`）。它是作者投影（含草稿、说明、状态），不是消费面的另一种参数——消费面的 `GET …/versions` 仍然只回答「可以 invoke 哪些」。
3. **CLI 用 `version` 组承接它**：`version list` / `show` / `diff` / `rename` / `note` / `discard` / `open`（提交仍是 `skill submit`）。写命令必须带钉；`@draft:<id>` 是可写的目标（草稿的稳定身份是 id，不是摘要），已发布 / 已下架的钉照常发给服务端，由它回答冻结或 404；不默认「当前那一版」；`discard` 还要求 `--yes`，没有它只打印后果与完整命令，不执行。机器可读输出统一走 `--json`。
4. **页面专属的动作在 CLI 里不是命令，只是一句拒绝。** `version publish|rollback|revoke|restore|offline|online|delete` 都停在错误里，说清「这个动作由人在网页上确认」并给出 `version open` 的完整命令。它们不列进帮助，也不在服务端留路由。
5. **同意屏与产品文案跟着说真话**：`skills:write` 的含义从「以你的身份提交新版本、管理共享」改为「以你的身份提交新版本、管理草稿与共享」（措辞以 [`voice-spec.md`](../../design/voice-spec.md) 为准；「管理草稿」指改名、改说明、丢弃，不含内容编辑）；清单仍然**不出现「发布」「删除」**——凭据确实做不到。

## 理由

**为什么不是「加一个 `versions:publish` scope」。** 那会留下第二种答案：换一把凭据就能上线，而「上线由人在网页上确认」就退化成「换一种凭据」。0031 与 0046 拒绝的正是这个（删除那条 ADR 的原话是「这条规矩要的答案是唯一的」）。这里也一样：**不是权限不够，是这条路不存在。**

**为什么「可逆」不能当判据。** 回滚可逆（再回滚一次就回来），但它改变所有裸地址调用者下一次读到的内容；丢弃不可逆，但没有任何调用者读得到草稿。按可逆性分，会把这两件正好分反——[ADR 0060](0060-discarding-a-draft-is-not-dangerous.md) 已经为丢弃做过一次同样的纠正。**看调用者。**

**为什么 agent 需要这些，而不是「提交就够了」。** 提交只解决「内容进来了」。一个 agent 被要求「把上一版的说明补清楚，然后等我上线」，它需要看见上一版、比较、改说明；一个交错的草稿需要被丢掉；一个准备上线的草稿需要被交给一个人。没有读与草稿期编辑，这些都得回到浏览器里做，agent 只能停在「提交完就结束」——那是 v5 的形状，不是 v6 的。

**为什么作者面要单开一个路径，而不是给消费面的版本列表加 `?view=author`。** 那会让同一个地址按参数返回两份不同的契约：一份是「调用者可以 invoke 的」，一份是「作者拥有的」；读的人分不清自己拿到的是哪一份，写的人也不知道该给哪一份加字段。路径分开，契约就各是各的。这也是 0031 对「参数决定谁能触发」的同一判断，用在读上。

**为什么页面专属的动作还要在 CLI 里留一句拒绝。** 不是为了让它们看起来存在，而是为了让**边界可发现**：一个 agent 试 `version publish` 时，得到的是一句「这由人在网页上确认，点这里」，而不是「未知的子命令」——后者会被读成「CLI 不完整」，前者说的是「这条路有意不存在」。这与 0046 撤掉删除路由之后、同意屏不再写「不能删除」是同一条诚实的两种落点：**做不到的事，要么不出现在承诺里（同意屏），要么在被问到的时候说清楚（CLI）。**

**被否掉的：让 CLI 拿浏览器会话。** 会话是 cookie + CSRF 的东西，`login` 的凭据交换已经在 0040 定成「签发只在控制台」；让 CLI 持有会话等于把「一个人当场确认」的那层保护拆掉。

## 后果

- **新增一条作者 API 路径族**（`/api/v1/author/skills/…`）：版本列表与单版、改动、草稿的改名 / 改说明 / 丢弃、草稿与已下架版本的文件读。它们走 `/api/v1` 已有的 Bearer 链与 scope 闸（读要 `skills:read`，写要 `skills:write`），档位在用例里判；**不新增安全链**。
- **API 平面从此有一份作者面的稳定契约**：字段与错误码进 v6 的 `technical-design.md`，以后改动要按契约对待（旧客户端不能读坏）。
- **没有任何「无人值守的上线 / 下架 / 回滚 / 删除」**，以后要它得另开一条 ADR，不能塞回一个 scope。
- **CLI**：新增 `version` 组与 `--json`；`skill files` / `skill read` 接受 `@draft:<id>` 与（有权限时）已下架的钉，按钉所在的面路由；`skill submit` 仍是提交的入口。README 与测试跟着改。
- **网页文案**：第一方同意屏与「登录请求」屏的 `skills:write` 那一行改为「以你的身份提交新版本、管理草稿与共享」；`design/` 是权威，先改设计件再改产品（本条的 P2 交付里做）。第三方那条 `/consent` 不动。
- **同意屏仍然不写「不能发布」「不能删除」**：那些话在 2026-10-16 被移除，理由是「一张列出做不到什么的同意屏读起来像一张要担心的清单」。凭据确实做不到，清单不写它不算隐瞒；但**清单里有的每一句都必须是真的**——所以 `skills:write` 那句要随这条扩张。
- **只读的 API key 能读到草稿**（只要这个人在这个 skill 上够 `write`）：scope 是上限，档位是授权；读草稿不是写。写命令要一把带 `skills:write` 的凭据。
