# 0109 · 规则段默认先查：只有闲聊免查

- **状态**：已采纳（2026-10-28）
- **关联**：[0102](0102-the-rule-block-ships-with-the-cli.md)（规则段随 CLI 发布）、[0101](0101-the-cli-never-deletes-files.md)（同一版里 CLI 不再碰用户文件）、[0110](0110-the-block-is-a-paragraph-the-cli-stops-managing.md)（同一版里去掉标记段）、`skillmaster-cli/internal/prompt/block.md`

## 背景

v20 批准、v25 搬进二进制的规则段是**条件式**的：「要按某个外部系统的规矩做事、要产出有固定格式的东西、你正要凭记忆写多步流程，或用户让你按我们的做法做时，先用它；**拿不准就查一次**。」

这条把「这次要不要查」交给模型自己判断。而模型的自我判断在两个方向上并不对称：它可以放心地说「我需要」而几乎不承担代价，说「这次不用」却省下一次调用——于是它天然偏向后者，越是能干的模型越容易直接动手。产品负责人在自己机器上另写了一份与之相反的「铁律」：**任何任务都先查**，不判断拿不拿得准。

## 决定

规则段改成**默认先查**：

1. 除**闲聊**（打招呼、情绪、没有任务的对话）外，任何任务动手前先 `skillmaster skills search`；不判断「拿不拿得准」，不因「一次性的」「手边有现成工具」跳过。**不列举产物类型**——列举永远漏（代码、设计一漏，就等于反过来暗示没列到的不必查），边界收口在一句话上：**拿不准算不算闲聊时，当作任务去查**。
2. 命中就先说清用哪个（地址＋拿它做什么）再 `skill invoke`，不许先调后说；没命中换说法再查一次，两次都没有才自己做，并明说「没找到相关 skill」。
3. 默认只搜自己的库；只有用户明确说「搜公开库」时才加 `--scope public`，公开 skill 加载前仍须用户确认。
4. 本地 / 内置列表不完整，电脑上的旧副本也不是来源，都不能当「没有」的依据。
5. 改 skill 在线做：`skill write <地址>@new <路径> --name <版名>`，新建用 `skill create`；上线由人在网页上点（CLI 没有发布命令）。

## 理由

**被否掉的选项一：保持条件式。** 条件式把召回责任放在模型的自我评估上，而这条规则存在的意义正是**把判断变成默认动作**——让模型去评估「拿不拿得准」，等于让最容易被跳过的那一步由最容易被说服的一方来决定。实测的结论是调用率偏低。

**被否掉的选项二：照抄产品负责人本机那份五条。** 那份里有 `~/.local/bin/skillmaster` 的绝对路径和 beta 安装脚本地址——那是**一台机器的环境**，写进所有人共用的规则段会随安装方式漂移，也违背「规则段只描述这个 CLI 的命令面」。所以取它的是**实质**（默认查、说清再调、两次没中才自己做、公开库要用户开口、改 skill 在线做），不是逐字。

## 后果

- **正文随二进制走**：装了新版二进制就是新正文，旧二进制仍打印旧正文；同一版里「规则段是旧版」的一次性提示与 `prompt update` 一起退役（[0110](0110-the-block-is-a-paragraph-the-cli-stops-managing.md)），所以已经写过说明的机器不会被告知要更新——要换正文得重跑 `startup`。
- **规则段随 CLI 发布**（0102），所以改它必须出 CLI 版本，不能只改平台技能。
- **误触发会上升**：每次任务多一次 `skills search`。成本被「两次查询封顶」与「默认只搜自己的库」限制住；换来的是「该用的时候真的会去查」。
- **规则段由 5 行变成 9 行**，长期驻留在每个会话的上下文里，是有代价的；以后再加规则要先减。
