# 0169 · 第一版只做注入，本地反代与平台代转都推迟

- **状态**：已采纳
- **日期**：2026-11-08
- **依赖**：[ADR 0168](0168-hosted-credentials-are-api-keys-not-identity-passwords.md)（托管边界）、[ADR 0167](0167-sandbox-compatibility-is-capability-based.md)（沙箱能力探测）、[ADR 0025](0025-cli-credential-storage.md)
- **后续**：§后果里那句「控制台只有凭据名、绑定的 skill、env 名、最后使用时间」是当时写的列；控制台列的当前形状以 [`design/README.md`](../../design/README.md) 的「服务凭据」两节为准。

## 背景

凭据托管之后，「怎么把值送到第三方请求里」有四种形状：

1. **直接注入环境变量**：CLI 把值放进子进程环境。最省事，覆盖一切形状（API key、cookie、JSON、任意文本）；代价是拿到进程的人（包括 agent）能读到。
2. **CLI 本地反代**：`skmr run` 起 `127.0.0.1` 临时端口，子进程只拿到 localhost 地址 + 一次性 token。agent 看不到；机器主人能提取。
3. **平台代转**：请求打 `console.skillmasterai.com/connect/...`，平台加真实 key 转发。key 永不离开平台，是唯一能对协作者保密的形状。
4. **本地钥匙串**（不托管）：平台不存任何东西，只在用户本机注入；跨机器与共享解决不了。

关键事实是**第 2 种的覆盖面比听起来窄**。它只覆盖这样的 skill：脚本自己发 HTTP 请求、请求地址取自 `SKILLMASTER_CONNECTION_<SERVICE>_URL`、凭据能表达成固定 header。以下都不在覆盖内：

- 浏览器自动化（Playwright / Puppeteer）——请求由浏览器发，本地代理不在那条路上；
- 凭据要放进 body 或 query——反代不改报文；
- 脚本把真实域名写死——请求根本不经过 `127.0.0.1`。

而它的成本不低：要为每家客户端做沙箱能力探测与降级。2026-11-07 实测：WorkBuddy 默认放行回环；Claude Code 开沙箱后需要 `sandbox.network.allowLocalBinding: true`，UDS 全被拒；Codex / Cursor / Gemini 未实测，默认策略可能直接拒绝 `127.0.0.1`（[ADR 0167](0167-sandbox-compatibility-is-capability-based.md)）。

## 决定

- **第一版只做注入**：平台存一段**不透明密文**，`skmr run` 启动前把绑定到该 skill 的值放进子进程环境变量。值可以是 API key、cookie、JSON 或任意文本，平台不解析内容。
- **不做 CLI 本地反代**，也不做 `SKILLMASTER_CONNECTION_*` 这套地址注入。
- **不做平台代转**。它是公开 skill 时代「帮你保住密钥」的增值功能，不是这一版的一部分。
- **不做服务注册表**：注入模式下平台不需要知道上游域名与认证形状。
- 绑定粒度仍是 `(用户, skill, env 名)`；声明（`metadata.requires.credentials`）保持可选、只用于提示。

## 理由

- **注入覆盖全部形状**，包括本地反代覆盖不了的浏览器自动化与 body/query；而「agent 看不到」这个唯一优势，只对最规整的一小类 skill 成立。
- **同一笔投入放在保险箱、撤销、审计上，回报更大**：用户真正要的是「换机器不用重贴、不再随包泄露、作者能收得回」，不是「agent 读不到」——后者是安全评审的加分项，不是用户提出的需求。
- **代理要么不做，要么做服务端的**：本地反代的复杂度和沙箱矩阵停在中间，最不划算。平台代转在公开 skill 时才真正值得，因为那时协作者不再拥有 key 所在的机器。
- **删掉一整套东西**：注册表、地址注入、能力探测与降级、按客户端的注入方式矩阵。v52 的实现面因此小一截。

## 后果

- **「agent 看不到值」不是承诺**。产品文案只能写：不进对话、不随 skill 包下发、换机器不用重贴、作者可撤销、每次使用有审计。agent 与脚本能读到注入的值——这是设计选择，要在文档与 `doctor`/帮助里说清，不能留给用户猜。
- **共享的承诺是「信任共享」**：对方能在他的机器上使用，也能提取明文。共享动作必须**显式确认**，确认文案说清这一点（[0168](0168-hosted-credentials-are-api-keys-not-identity-passwords.md)）。
- **公开 skill 或「共享给所有人」必须等平台代转**：否则等于把某个人的 key 交给陌生人。
- **不引入 `service_key`**：数据模型少一个概念；控制台也就没有「上游服务」这一列，只有凭据名、绑定的 skill、env 名、最后使用时间。
- **将来若做平台代转**：需要重新引入服务注册表（上游与认证形状）与短命 token；那时先解决「第三方域名逐个加白名单」的问题，能力探测的现成基础在 `internal/sandbox`。
