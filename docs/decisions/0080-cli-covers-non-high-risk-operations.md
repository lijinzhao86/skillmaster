# ADR 0080 · CLI 覆盖所有非高风险操作

- **状态**：已采纳
- **日期**：2026-10-23
- **依赖**：[ADR 0077](0077-the-cli-grammar-is-singular-and-plural.md)（CLI 按单复数分组）、[ADR 0056](0056-dangerous-actions-are-confirmed-in-a-modal.md)（改变用户看到的东西之前先确认）、[ADR 0079](0079-cli-manages-tags-and-library-references.md)（标签与库引用进 CLI 的具体边界）

## 背景

v14 的计划是把标签的贴 / 摘 / 新建 / 改名 / 改说明、库的加入 / 移除、词表检索与来源筛选放进 CLI（实现尚未开始）。产品负责人提出一个更宽的判断：**只要不是高风险的，都应该有 CLI**——AWS CLI 几乎能做完所有事，agent 在无头环境里不该因为“这件事只有网页能做”而停下来。

这条原则需要一个可执行的边界，而不是“尽量都加”。本轮盘出来的剩余项里，既有纯读（排序、逐行字段、完整库视图、单个 skill 的详情），也有可逆写（恢复软删除的 skill），还有页面动作（发布 / 回滚 / 下线 / 上线 / 撤销 / 删除）与页面展示（「为你推荐」流）。

## 决定

1. **边界**：CLI 覆盖**可逆、且不改变可见性设置（public / private）与访问权**的操作；**不可逆或改变可见性 / 访问**的操作留在控制台，用弹窗或 `--yes` 确认。恢复一个软删除的 skill（`skill restore`）不改变它的可见性设置与访问权，属于可逆操作。
2. **v14 的补齐**：`skills list --sort recent|name`；`skills list --show live|draft|offline|deleted|all`；`skills list` / `skills search --verbose`；`skill restore`；`skill show`。
3. **「为你推荐」不进 CLI**。它是**消费型页面流**，用于用户闲逛 / 发现，不是解决问题；agent 要解决问题用 `skills search` 按需找。推荐算法也不因这条原则提前。
4. **v13 的页面动作另开一版评估**：`publish` / `rollback` / `revoke` / `restore` / `offline` / `online` / `delete` 仍是“只交接、不执行”。它们里有低风险项，但改动会推翻 v13 的交接契约，不该在标签版里顺手做。
5. **未来的新操作默认有 CLI**，除非落在高风险清单：删除我的标签定义、删除 skill、删除 / 撤销版本、把可见性改成公开 / 私有。高风险项仍以控制台确认为主。

## 理由

- **无头环境没有控制台。** CLI 是 agent 的入口；能脚本化的操作都应该能在终端完成，AWS CLI 的强大正是这个方向。
- **风险边界比“功能边界”更稳定。** 按“可逆 / 不可逆、是否改变可见性”划分，新功能不用每次重新争论；按“网页有 / 网页没有”划分，就会不断漏。
- **推荐流不是操作。** 它是一次消费型浏览，没有明确目标，也没有可判定的“完成”；把它做成 CLI 只会让 agent 多一个与解决问题无关的入口。解决问题的读是 `skills search`。
- **v13 的交接是有意的。** 七个页面动作需要页面上的上下文与确认；在标签版里改掉它们，会让 v13 的契约漂，也会把这一版的审计面撑大。另开一版，才能单独评估每一项的确认与回滚。
- **高风险清单要短而明确。** 删除、撤销、可见性变化是用户会失去东西或暴露东西的操作；它们留在控制台，CLI 只在明确确认后执行已经存在的部分（如 `version discard --yes`）。

被否掉的：**只做读命令**（可逆写也该有 CLI）；**把推荐流也做成命令**（消费型浏览，不是问题解决）；**这一版顺手改 v13 的页面动作**（契约漂、审计面大）；**所有操作都留在控制台**（无头环境无法脚本化）。

## 后果

- v14 增加 `--sort` / `--show` / `--verbose`、`skill restore`、`skill show` 的命令、权限、错误与测试；默认卡片与 v13 契约不变，`--verbose` 是 opt-in。
- 推荐流仍是控制台「发现」页的一段；`skills search` 是 agent 的问题解决入口。
- v13 的七个页面动作仍只交接；它们的 CLI 化是下一版 / 另一条 ADR 的事。
- 未来的功能评审先问两个问题：**可逆吗？改变了可见性设置（public / private）或访问权（`skill_grant`）吗？** 两个都“否”的，默认进 CLI；撤销一次删除不改变这两者。
