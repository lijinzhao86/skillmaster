# ADR 0024 · refresh token 重放：宽限窗口内算竞态，窗口外整链撤销

- **状态**：已采纳
- **日期**：2026-10-02
- **依赖**：[ADR 0007](0007-self-built-oauth-as.md)（轮换与 `rotated_from` 链）、[ADR 0021](0021-opaque-tokens-not-jwt.md)（不透明令牌，撤销立刻生效）、[ADR 0023](0023-spring-authorization-server-with-our-own-storage.md)（存储自带，所以这条规则落在我们自己的实现里）
- **被扩展**：[ADR 0029](0029-an-authorization-revocation-is-a-state.md)（正文不变；「这次授权结束了」从「令牌行的推断」改成记在父行上的状态，本窗口的「家族还活着」因此改为问父行）

## 背景

**轮换不是可选项。** [RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html)（已发布的 OAuth 2.0 Security BCP）§2.2.2 是一条 MUST：公共客户端的 refresh token **必须** sender-constrained 或者用轮换。我们的 CLI 是公共客户端（PKCE、没有 `client_secret`），所以我们轮换。

**但轮换撞上并发。** 刷新不是由一个常驻进程做的——**CLI 是一条命令一个进程**，刷新是每个进程按需做的（[ADR 0011](0011-server-and-cli-stack.md)：选 Go 的理由之一就是「agent 一个任务会调它好几次」）。于是：

1. 两个进程同时看到 access token 过期
2. 两个都拿**同一个** refresh token 去换
3. 一个拿到新的一对；另一个递上去的是**已经被轮换掉的旧 token**

这不是理论风险：`search` 与 `show` 并行、一次网络重试、开两个终端，都会撞上。

**三种成熟答案，三个方向**：

| 谁 | 旧的被再次使用时 |
|---|---|
| [RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html) §4.14 | 一律当泄露，**撤销活动令牌**（最严；规范也承认「无法判定是谁提交的」） |
| **Keycloak 默认** | **只撤销被重放的那一张，整条链还活着**（最宽松，天然容错并发） |
| **Airwallex** | **60 秒宽限窗口**，窗口内算竞态、容错；窗口外撤销整个 token family |

## 决定

**两段式，窗口长度可配，起点 60 秒：**

- **轮换后 N 秒内**再次看到刚被轮换掉的那一张 → **算竞态**：按正常刷新处理，发一对新的，**不撤销任何东西**。
- **窗口之外**再次看到 → **算重放**：撤销整条链，该用户重新走一次授权。
- **客户端另加一把锁**（keychain 旁边），让并发刷新尽量不发生。

**撤销沿 `rotated_from` 回溯，而不是按 `(client_id, user_id)` 一锅端**——后者会误伤同一个用户在另一台设备上的另一条链。

## 理由

**为什么两段都要。** 只留严格段，一次并发刷新的输家就把用户踢下线，而用户的机器上什么都没做错；只留宽松段（Keycloak 默认），偷到旧令牌的人换出新令牌之后，正经用户只收到一个报错——**偷的人赢**。宽限窗口是唯一同时成立的形状：几秒之内容忍竞态，几秒之外仍能检出盗用。

**为什么窗口要短。** 窗口一开，偷来的 refresh token 在窗口内使用**就不会被发现**——窗口多长，被漏掉的时间就有多长。60 秒够覆盖一次网络重试与同机并发，不够让攻击者从容使用。

**为什么还需要客户端锁。** 因为宽限窗口本身是有代价的（上一段）。锁把竞态变稀，让窗口可以更短。锁只解决**同机**并发——而这正是我们的场景（agent 在一台机器上并发调 CLI）；跨设备不共享同一张 refresh token，本来就不会撞。

**为什么读库而不是读内存。** Keycloak 有一个现成的教训（CVE-2026-9802）：它的陈旧令牌检测拿集群启动时间与上次刷新时间比，**服务重启后启动时间归零，已轮换的旧令牌又被接受**。我们的判断读 `rotated_from` 与库里的时间戳，重启不影响。

## 后果

- **逼出一个 schema 细节**：要能回答「这一张是什么时候被轮换掉的」。`rotated_from` 把链串起来了，但窗口判定还需要一个**时间戳**（轮换时间或 `revoked_at`）。这是本决定唯一逼出来的表结构变化。
- **允许分叉。** 窗口内放过的那次刷新会**再发一对新的**，于是同一条链在一个点上分成两支。不允许分叉就等于没放过。清扫要按 token 逐个过期，**不能假设一条链是一条直线**。
- **窗口内的盗用不会被发现。** 这是买那几秒容错的价钱，要说出来而不是忘掉。
- **CLI 要能翻译这个错误。** 整链被撤销后，用户看到的不该是一个裸的 `invalid_grant`，而是「请重新登录」。
- **窗口数字要能被复算。** 它在配置里，默认值记在这里（60 秒）；改了它，上面那条「被漏掉的时间」跟着变。
