# ADR 0078 · 分类是一个货架：平级、单选；召回交给标签

- **状态**：已采纳（写于公开标签进入本版之前；公开标签的落版与两套标签的边界见 [0083](0083-two-tag-layers.md)——分类单选的决定不变）
- **日期**：2026-10-23
- **依赖**：[ADR 0006](0006-search-server-side.md)（检索在服务端）

## 背景

v14 引入两类词：平台预置的**公开分类**，与作者贴的**公开标签**。在此之前的定义里，分类是**一棵最多 4 层的树、每个 skill 最多贴 5 个**；公开标签那一层已经画进设计稿，负责搜索与推荐的召回。

产品负责人提出一个直接的问题：**有了公开标签，分类还重要吗？** 抖音、TikTok、小红书都没有让作者选分类，它们靠话题/标签与平台自己的归类。我们据此把主流平台的做法核了一遍（口径：公开资料与创作者平台界面，2026-10-23）：

| 平台 | 分类 | 标签 | 备注 |
|---|---|---|---|
| 抖音 | PC 创作者平台 2023-07 起有「视频分类 + 视频标签」：**1 个分类 + ≤10 个标签**；手机端没有入口；**用户端不可见、发布后不可改** | 视频标签 + 话题 | 官方口径是帮助推荐策略识别内容（创作者社区转述，未在官方帮助中心原文核实） |
| B 站 | 投稿**必选 1 个一级分区**；**2025-03 起取消二级分区**，二级由平台判定 | ≤10 个（官方手册建议 8 个以上，前 3 个最关键） | 趋势是弱化分区、强化话题/标签 |
| 小红书 | 普通笔记没有必填分类，系统按内容语义归类 | 话题 3–5 个（上限 10） | 推荐流产品 |
| TikTok | 创作端没有分类；平台内部约 20 类，靠音频、画面、文字、互动推断 | Hashtag 是弱信号 | 推荐流产品 |
| YouTube | 分类必选（约 15 类） | Tags 角色很小（官方：minimal role，主要用于拼写纠错） | 搜索 + 推荐 |
| GitHub | **没有分类字段** | Topics 自由词，≤20 | 搜索 + topics |
| ClawHub（同类产品） | **有** category | tags + 语义搜索 | 搜索 + 分类 + tags |

四条规律：**推荐流产品把分类藏起来或交给算法；保留分类的产品都是单选；召回交给标签/语义，不交给分类；层级在退**（B 站 2025 年刚取消二级分区）。

SkillMaster 的形态更接近 GitHub / ClawHub：发现页是搜索 + 推荐，没有分类树页面；但公域冷启动、库的筛选与 CLI `skills categories` 仍需要一个稳定的粗坐标。原来的「最多 4 层、每 skill 最多 5 个」把分类做成了第二种标签，且没有对应的浏览入口。

## 决定

1. **分类保留，但只是一个「货架」**：平台词表、**平级 10 个词、没有父子**；每个 skill **最多一个**分类（可以为空），由作者选，所有者与 `admin` 可改。再选一个会**替换**，不是追加。
2. **不预留层级**。以后真要加一层，是重新决定模型，不是今天留的坑。
3. **召回交给公开标签**；分类负责粗归类、公域冷启动、筛选与 CLI 的稳定词表。卡片与信息页上最多一枚分类胶囊。
4. **筛选可以同时选几个货架**（公域取「或」，与我的标签组合取「且」）——那是对词表的查询，不是对一个 skill 的贴法。

## 理由

- **单选才让分类与标签分开。** 抖音 1 个、B 站 1 个、YouTube 1 个；多选分类与公开标签在界面上长得一样、语义也重叠，读者没有理由把它们读成两件事。
- **没有浏览树，就不该有分类树。** 我们唯一的分类入口是筛选下拉；B 站有分区页与频道，仍然在 2025 年砍掉了二级分区。为不存在的浏览场景维护层级与子树筛选，是在付没有回报的成本。
- **现在不能删掉分类。** 公开标签在本版只是一个画出来的层，产品尚未实现；删掉分类会让公域只剩搜索与推荐，失去冷启动与筛选的兜底。
- **也不把分类退到平台侧（抖音模式）。** 那需要一个可靠的归类来源（编辑或算法）；本版没有，硬做会让这一层变成随手的猜测。作者选一个粗货架是当前最便宜、最可解释的做法。

被否掉的：**保持多选与 4 层树**（把分类变成第二种标签，且没有浏览场景）；**本版直接去掉分类**（在公开标签落地前没有结构化入口）；**分类由平台指派**（没有归类来源）。

## 后果

- v14 的 PRD、设计稿与检查同步收窄：每个 skill 一个分类、平级 10 词、选择器是单选菜单（可清除）；库里同一个 skill 不再出现两枚分类胶囊。
- CLI `skills categories` 仍列出这 10 个词与公域计数，`--category` 取名字（可重复，取「或」）；模型里不再有「选中一个节点等于整棵子树」的语义。
- 公开标签落地后，分类仍保留为粗坐标；如果真实的检索数据显示 10 个平级词装不下，或分类筛选长期没人用，那时再按新证据决定加层或退到平台侧——两者都会是新的 ADR。
- 调研的来源是公开资料与创作者平台界面，其中抖音与 B 站的具体入口属于社区转述；若要作为对外承诺引用，需要到官方帮助中心与创作者平台再核实一次。
