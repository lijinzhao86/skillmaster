# 0064 · 草稿的内容可以变，已发布版本的内容不能变

- **状态**：已采纳
- **日期**：2026-10-20
- **依赖**：[0004](0004-opaque-id-primary-key.md)（身份不变、状态是属性）、[0005](0005-content-addressing.md)（内容寻址、blob 不可变）、[0031](0031-submitting-and-publishing-are-two-actions.md)（提交与发布是两个动作）、[0055](0055-drafts-have-a-required-name.md)（草稿有必填名称）、[0063](0063-a-draft-is-addressed-by-a-short-code.md)（草稿由短码寻址）

## 背景

v6 的行模型里有一条没有写下来的不变量：「`skill_version` 的内容只插不改，状态、名称、说明可变」。它成立是因为当时没有任何操作会改一版的内容——提交产生一行，发布改状态与版本号，丢弃改状态。代码与注释都按这个前提写。

v7 加入作者面对草稿的文件读写（`write` / `edit` / `rm` / `mv` / `cp`），这个前提第一次被打破：写一份草稿，就是改这一行的 `digest` / `file_count` / `total_bytes` 与 `version_file`。摆在桌上的三种做法：

| | 做法 | 代价 |
|---|---|---|
| 1 | **任何行都能改内容**，发布过的也行 | 一个版本号（或摘要）在一刻钟内指向两份内容；调用方钉住的东西会变 |
| 2 | **只有草稿能改**，已发布 / 已下架 / 已丢弃的内容冻结 | 想改已上线的版本，得先提交一份新草稿、再发布 |
| 3 | **每次写都产生新版本** | 一次编辑一个版本号，版本列表变成编辑历史；与「提交/发布是两个动作」冲突 |

## 决定

1. **只有 `state = draft` 的行可以改内容。** `published` / `revoked` / `discarded` 的 `digest` / `file_count` / `total_bytes` / `version_file` 不随 v7 的任何命令变化。作者面其余可变字段（`draft_name`、`note`、`state`）不在本条约束内。
2. **写一份草稿改的是这一行自己的四类事实**：重算并更新 `digest` / `file_count` / `total_bytes`，增删改它自己的 `version_file`。`state` 保持 `draft`，`version` 保持 `NULL`，`number` / `submitted_at` / `submitted_by` 不变。
3. **写根 `SKILL.md` 时，`title` / `description` / `frontmatter` 跟着这一版变**——它们是这一版自己的快照；`skill` 行的同名三列不动，那是元数据线（ADR 0049），只有发布流程按现有规则处理。
4. **内容仍是内容寻址的**：每次写只为改动过的文件产生新 blob；没改的文件继续引用原 blob。blob 本身仍然只增不改（ADR 0005）。
5. **写后 digest 与同一 skill 的另一行相同时拒绝**：409 `content_already_exists`，不静默合并、不删草稿。唯一约束仍是 `UNIQUE (skill_id, digest)`。

## 理由

**为什么已发布版本不能改。** 版本号与 `sha256:` 摘要是对外的寻址方式（ADR 0012）。调用方把它们记在配置里、写进锁文件、贴进文档；如果内容能变，同一个地址在不同时间会给出不同答案，所有「钉住」的承诺都失效。摘要更直接：`sha256:` 描述的就是内容，内容一变，地址立即说假话。

**为什么不是做法 3（每次写一个新版本）。** 提交与发布是两个动作（ADR 0031）：草稿阶段本来就在改，一行草稿就是「正在编辑的那一份」。每次写都编号会把编辑历史伪装成版本历史，而编辑中间态对调用方没有意义。要留一版，正确动作是提交或发布，不是保存。

**为什么草稿名称与说明不冻结。** 它们是「这一份草稿」的属性，不是内容的一部分；ADR 0055 让草稿在发布前有一个可复制的名字，本版不改那条规则。

**为什么摘要冲突要拒绝而不是合并。** 合并会说「你的草稿变成了另一版」，但作者的意思通常是「撤回这次修改」——把内容退回某一版的原文。库里已经有这份内容，不删它、也不假装写成功，而是把已有那一版的状态告诉作者（已上线时连 `pin` 一起），由人决定下一步。静默合并会让一次写既成功又没写。

## 后果

- **`rm` 会造出孤儿 blob**：删掉 `version_file` 行后，这一份内容的 blob 失去引用。回收规则由 [0065](0065-blob-reclamation-waits-for-a-grace-period.md) 定。
- **没有「最后编辑时间」**：版本行没有 `updated_at`，本版不加列；写的时间只进审计。版本事实里不展示「最后编辑」。
- **已发布版本要改，走新草稿**：这是有意保留的唯一路径，不是遗漏。将来若要「在线改已上线版本」，先回来重读这一条。
- **网关路径不受影响**：`PublishGatewaySkillUseCase` 仍只提交新行，不写已有行。
