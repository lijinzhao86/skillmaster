# 0074 · 交接可以携带预选，不能携带执行

- **状态**：已采纳
- **日期**：2026-10-21
- **所属版本**：[`v11-publish-handoff`](../versions/v11-publish-handoff/README.md)

## 背景

[0072](0072-the-handoff-points-at-the-page-that-owns-the-action.md) 把「交回给人」的落点修对了：拒绝句给出拥有动作的那一页。但它只解决了**去哪**，没解决**带什么**。

agent 在对话里已经判断过「这次改动影不影响旧调用」，CLI 却没有位置放它；人打开页面，看到的是页面按线上版本算出来的默认档。决定在交接处丢了。

摆上桌的四种做法：

| | 做法 | 结果 |
|---|---|---|
| A | 地址只指页，不带任何值 | 现状：人得自己重建 agent 的结论 |
| B | 地址可以带「页面本来就有的选择」之一（这里是三档之一） | 页面打开就是点完那一下的样子 |
| C | 地址可以带任意版本号（`release=1.7.0`） | 单选项与输入框在**打开那一刻**就不一致 |
| D | CLI 拿到确认后自己执行 | 越过 [0061](0061-what-a-credential-may-do-to-versions.md) |

## 决定

**交接可以携带「预选」，不能携带「执行」。** 一个值要进交接地址，必须同时满足：

1. **页面本来就有这个选择**——不是为交接新造的一种输入；
2. **携带它本身不改变调用者读到什么**——真正生效仍要人在页面上确认；
3. **它只是打开时的初值**——不写回地址，不成为页面状态；刷新丢了就回到页面的默认。

本次落地的就是 `bump ∈ {patch, minor, major}`：上线表单已有的三个单选项。

## 理由

- **A 被否**：交接要解决的问题正是「决定跟着人走」。只给落点，等于把判断留给了没有上下文的读取者。
- **C 被否**：三个单选项编码的是「旧调用会不会坏」，不是版本号本身。任意版本号会让**打开时**选中的那一行成为假话（选着「只是修正」，框里却是 1.7.0）。设计件的输入框确实可以手改，人与框不一致是允许的中途状态；但设计没有画「一打开就不一致」，为它发明一个开局状态违反 `design/` 是唯一权威这条规矩。
- **D 被否**：上线、回滚、下架改变调用者能读到什么，只在浏览器面由人确认（[0061](0061-what-a-credential-may-do-to-versions.md) §决定 1）。预选不是执行，两者不能混。
- **B 成立**：它落在设计件已经画好的三态之一（点完「新增能力」的那一面），不新增画面、文案或名词；人打开后仍然要按「上线」并确认，所以它没有拿走任何判断。

## 后果

- 控制台地址多一个查询参数 `bump`（v6 TD §地址表随之修订）；它不进服务端，服务端不读也不校验。
- CLI 的页面专属动词里，`publish` 接受 `--bump` 并转发进拒绝句；其余三个不接受。
- **后续的交接要按这三条判据逐条问**：页面有没有这个选择、它会不会直接生效、它是不是只当初值。三条全过才准带。
- 预选不写回地址：人改了单选项，地址仍写着交接时的档；刷新回到交接档。这是有意的——地址里的是「谁要求了什么」，不是「表单现在是什么」。
- 「任意版本号」不在本决定之内。若将来要支持，先给设计件补上「打开时单选与输入框不一致」的含义，而不是绕过本决定。
