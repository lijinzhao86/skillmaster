# ADR 0108 · 传技能是可选步骤，不挡后面的旅程

- **状态**：已采纳
- **日期**：2026-10-27
- **依赖**：[`versions/v26-startup-guidance-and-agent-paths/`](../versions/v26-startup-guidance-and-agent-paths/)

## 背景

v26 的第一次旅程把七项排成一条链：小工具、登录、传技能、正式上线、让 AI 先来 SkillMaster 找技能、让 AI 用 SkillMaster 自己的文件夹、电脑上原来的那份。其中「传技能」被当作必做项：本机还有没传的技能时，清单把它放进「还差」，下一步指向 `steps/01-import.md`；人不传，旅程就停在那里。

2026-10-27 用真实机器走查时，本机唯一的技能有 62 MB（其中 `.git` 31 MB、音频 27 MB），`skill submit` 被服务端以 413 拒绝；用户明确说「我不传那个技能，但是我想把流程走完」。此时清单仍写着「还差 1 件」，后面几步都走不到。这不是那一个技能的特例：本机技能可能很大、含不适合上传的内容，或者用户只想先把 AI 配置好。

当时的选项：

1. **保持必做**：没传完就不能往下走；
2. **加一个「这次跳过」的状态或开关**：人拒绝后记录下来，下次 `--plan` 不再把它算作待做；
3. **把传技能改成可选**：它永远不进「还差」，没传或只传一部分都不挡后面的步骤；
4. **自动把所有本机技能都传上去**。

## 决定

**传技能是可选的。** 具体规则：

- `startup --plan` 里「传技能」永远不进「还差」，也不进「还要确认」：
  - 本机没有技能 → 跳过「本机没有可上传的技能」；
  - 本机有技能、且都已在平台上 → 已完成；
  - 本机还有没传的 → 跳过「可选；还有 N 个没传，想传的时候再跑一次」；
  - 未登录 / 服务端读不到 → 跳过「可选；登录后 / 稍后再看」，不把未知说成 0。
- 人不传、只传一部分、传到一半停下，旅程都继续往下走；`--plan` 的下一步不会指向 `steps/01`。
- 只有真的上传成功的草稿才需要正式上线；一份都没传时，「正式上线」直接算已完成。
- 旅程完成不再要求本机技能全部上线；完成条件是说明已写入并验证、已经告知用户「以后新任务会用 SkillMaster」。
- 状态行的下一步不再让「还有没传的副本」压过草稿与说明：有草稿 → 上线；没有草稿 → 写说明；库里有线上、本机没有副本 → 已完成。本机有多少已上线仍然显示在状态行里，让人看见没传，但不阻止下一步。

## 理由

- **第一次旅程不能有死路。** 一个 62 MB 的技能就能把整条链卡在第一件；用户已经明确不想传，再要求他先处理这个技能，等于把「开始用 SkillMaster」变成「先解决这个大文件」。
- **「这次跳过」需要一个状态，而 v26 已经决定不存进度。** [ADR 0106](0106-the-checklist-is-recomputed-not-recorded.md) 让清单每次从事实重算；要记住「他上次拒绝了」，就得新增一份状态文件或服务端字段，并处理它和事实漂移。可选化不需要任何新状态：本机还有没传的，就一直在「跳过（可选）」里，人想做的时候随时能做。
- **部分上传本来就该继续。** 已经传上去的草稿是真实进度；因为还有几个没传就停住，反而让用户没法上线已经传好的那部分。
- **被否的第 1 条（保持必做）**：它把「传技能」当成使用 SkillMaster 的前提，但前提其实是「说明写进 AI、AI 会从平台取用」。本机技能是存量，不是前置条件。
- **被否的第 2 条（跳过状态）**：违反 ADR 0106，还多一份要迁移、会损坏的状态；同一次旅程里人改主意时，状态也会和事实对不上。
- **被否的第 4 条（自动全传）**：上传是写服务器、可能公开内容的动作，必须先问人；自动传等于把审批一次用完，也绕开了「同名不同内容先比较」的规则。

## 后果

- **清单的「还差」少了一项。** 第一次走的用户可能看到「还差 1 件：登录」甚至直接「全部好了」，而本机技能一个都没传；这是有意的——旅程完成不等于迁移完成。
- **状态行的 KI-1 防线换了位置。** 旧行为是「本机还有没传的副本就必须指向搬运」；新行为是「必须显示本机有多少已上线」。`其中 0 个已上线` 仍然让人看见没传，但不再替人决定下一步。KI-1 的原始 bug（1.0.0 把「本机有 33 个、线上有 2 个但名字不重合」读成「都传过了」）仍然由名字集合防住。
- **正式上线的计数不变**：只算本人命名空间里真实存在的草稿；没传技能时自然是 0，清单写已完成。
- **要迁移时的入口还在**：`steps/01-import.md`、`skill submit` 都不变；人想传的时候跑一次 `startup --plan` 就能看到还剩几个。
- **文档与技能正文同步**：PRD、TD、test-plan、`SKILL.md`、`steps/01`、`voice.md` 都要写明「传技能可选、不传不挡后面」；安装说明页那句「按步骤把已有 skill 搬到平台上」也要改成「想搬的时候搬」。
