# ADR 0112 · 「平台接管」后，只服务旧写法的命令可以在同一代次内退役

- **状态**：已采纳
- **日期**：2026-10-29
- **依赖**：[`versions/v27-rule-block-and-prompt-retirement/`](../versions/v27-rule-block-and-prompt-retirement/)；部分取代 [0088](0088-cli-major-version-is-the-api-generation.md) 决定 2

## 背景

[0088](0088-cli-major-version-is-the-api-generation.md) 决定 2 规定：同一主版本内，CLI 的命令面**只增不减**，删除与语义改变一律留到下一个主版本；决定 6 再补一句——真的要破坏时，先写一条取代它的 ADR，不许靠次版本号糊过去。

v27 正好撞上这条。服务端没有换代（仍是 `/api/v1`），但有两组东西必须退役：

- `prompt install` / `status` / `update` / `uninstall`——写这段说明的动作搬给了旅程技能（[0110](0110-the-block-is-a-paragraph-the-cli-stops-managing.md)）；
- `startup --plan` / `--agent` / `--file`——清单搬进了旅程正文（[0111](0111-startup-takes-no-flags.md)）。

它们不是「我们不想维护了」，而是**同一件事换了归属**；留着它们，人们会以为还能用旧写法，于是两套口径同时存在。

## 决定

在同一代次内允许退役一个命令或一个参数，**三个条件必须同时满足**：

1. **功能换了归属**：同一件事现在由别的面做（平台技能、网页），不是被放弃，也没有被悄悄砍掉；
2. **名字还在**：命令仍然敲得到，回一段固定的退役说明（首行含「已经退役」）并指出新去处，退出码 **2**；参数级别的删除（如 `--plan`）按同一条处理——它属于那条命令，命令本身仍在；
3. **本版文档里点名**：当版 PRD 的「做」或发布说明列出被退役的命令、替代去处与退出码。

三条缺一，仍然留到下一个主版本。

## 理由

0088 决定 2 要防的是**调用方无声地坏掉**：一条命令突然不存在，脚本拿到的是语法错误，人拿到的是「没有这个命令」。

「退役」与「删除」的差别正在这里——这四条现在回的是「已经退役 + 去哪做」，退出码 2 而不是「命令不存在」。用它换掉「一律等下一主版本」，换来的是不必把一次已经做成的搬迁挂上半年、让两套写法与两套文档口径并存。

**否掉「一律等下一个主版本」**：搬迁已经完成，旧命令留着只会继续误导。

**否掉「直接发 2.0」**：主版本说的是 **API 代次**（0088 决定 1），服务端仍是 v1；发 2.0 会让 `skillmaster --version` 里的「API v2」变成假话。

## 后果

- 0088 决定 2 的「只增不减」收窄为：**只增不减，除满足上面三条的退役**；决定 6 的「先写 ADR」这一次就是本文件。
- 每次这样的退役都要在本版文档里点名，读发布说明的人能据此改自己的脚本。
- 代价如实记：`1.x` 之内仍可能出现「以前能用、现在退出 2」的命令。这是有意的，代价由文档点名承担，不由版本号承担。
