# ADR 0081 · 每处控制台操作都要有 CLI 对应

- **状态**：已采纳
- **日期**：2026-10-23
- **依赖**：[ADR 0080](0080-cli-covers-non-high-risk-operations.md)（CLI 覆盖所有非高风险操作）、[ADR 0002](0002-gateway-skill-and-cli.md)（网关 skill + CLI 是 agent 的入口）、[ADR 0077](0077-the-cli-grammar-is-singular-and-plural.md)（CLI 按单复数分组）、[ADR 0056](0056-dangerous-actions-are-confirmed-in-a-modal.md)（改变用户看到的东西之前先确认）

## 背景

[ADR 0080](0080-cli-covers-non-high-risk-operations.md) 定的是**原则**：CLI 覆盖可逆、且不改变可见性的操作。但原则没有落成流程闸口时，它会以同一种方式失效——控制台先做，CLI 记成“以后补”，然后一直欠着。v14 就是这样发现的：设计稿把标签、库、词表操作做完之后才回头盘 CLI 的映射，一次性补出二十多个缺口（实现尚未开始）。

产品负责人在 2026-10-23 提出把它变成一条**开发规则**：以后开发的所有控制台操作，除了高风险的，都要有 CLI 命令；像「为你推荐」这种确实不该有命令的，**要经过他确认才能不给**。

## 决定

1. **每处控制台操作，交付时必须有 CLI 对应。** 这条落在版本 PRD 上：PRD 必须带一张映射表，逐行列出一版里新增或改动的每一处控制台操作，以及对应的 CLI 命令。
2. **PRD 阶段就写 CLI 那一行。** 新增控制台操作时，需求里同时写它在 CLI 上的入口（命令、参数、确认、输出形状归 §CLI 命令面）。写不出来，说明需求还没定完，不是“实现时再说”。
3. **例外只有两类**：
   - **高风险操作**——不可逆，或改变可见性设置（public / private）与访问权（`skill_grant`）：删除我的标签定义、删除 skill、删除 / 撤销版本、把可见性改成公开或私有。撤销一次删除（`skill restore`）不改变这两者，不算高风险。它们留在控制台，用弹窗或 `--yes` 确认（[ADR 0056](0056-dangerous-actions-are-confirmed-in-a-modal.md)）。
   - **产品负责人逐条确认的例外**——非高风险、但确实不该做成命令的。目前只有一项：「为你推荐」流（[ADR 0080](0080-cli-covers-non-high-risk-operations.md) §决定 3，消费型页面流，不是解决问题）。
4. **例外必须显式记录，不能默认省略。** 每个例外写进当版 PRD 的「不做」，写明**是什么、为什么、哪天由产品负责人确认**。没有这三项的不算例外，按第 1 条补 CLI。
5. **已有控制台操作按版本逐步补齐。** v13 的页面动作（publish / rollback / revoke / restore / offline / online / delete）仍另开一版评估；补齐之前它们是“欠账”，不是“不做”。

## 理由

- **没有闸口的原则会一直欠着。** 控制台的工期永远比 CLI 显得紧急；不把 CLI 写进同一张需求表，它就永远排在后面。
- **映射表让“漏”变成看得见的。** 一行一个操作，交付前逐行对；这比事后回头盘一次便宜得多，v14 已经付过一次这个代价。
- **例外需要确认，是因为“看起来不该有命令”经常是错的。** 「为你推荐」被排除是因为它没有可判定的完成；但如果不要求确认，任何操作都可以用“好像没必要”省略掉，规则就退回成建议。
- **边界仍然只有一条。** 高风险清单短而明确；其余默认有 CLI。新功能评审不用每次重新争论。

被否掉的：**只写原则、不落闸口**（v14 的缺口就是这么来的）；**让实现者自己判断哪些不用做**（“好像没必要”无法复核）；**把推荐流当作默认例外**（它需要产品负责人的确认，不是一条通用豁免）；**这一版顺手补齐 v13 的页面动作**（会推翻 v13 的交接契约，另开一版）。

## 后果

- PRD 模板增加一节「控制台操作与 CLI 对应」；版本 PRD 交付前必须填完。
- 开发 SOP 的开工前 / 交付前清单各加一条：映射表存在、每一行都有命令或已确认的例外。
- v14 的 PRD 把这条 ADR 列进依赖，并把「为你推荐」的排除标注为产品负责人确认的例外。
- 以后新增控制台操作时，没有 CLI 那一行就不算需求完整；高风险与已确认例外之外，不允许静默省略。
