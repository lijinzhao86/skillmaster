# 0180 · 个人适用场景按证据分级排序，只在库内生效，v1 不训练

- **状态**：已采纳
- **日期**：2026-11-11
- **所属版本**：[`v59-personal-scenario`](../versions/v59-personal-scenario/README.md)
- **相关**：[ADR 0181](0181-text-limits-use-unicode-code-points.md)（三个字段的上限与契约）、[`research/search-ranking-and-personal-triggers.md`](../research/search-ranking-and-personal-triggers.md)

## 背景

库内检索今天有两条路：

- **关键词**：名字、标题、描述按不同权重计分；`when_to_use` 只参与过滤，不计分；库内没有相关性排序，按更新时间或名字排。
- **语义**：每条 skill 一条作者文本的向量（名字 + 标题 + 描述 + `when_to_use`），精确扫，默认阈值 0.40。

用户用自己的话找一条 skill 时，作者写的那套词可能对不上（作者写「法务审查」，用户说「循环审计」）。个人层要解决的正是这件事：让用户/agent 写一句「我什么时候会找它」，参与库内排序。

要定的是它在排序里的位置，以及它与作者文本、公域检索的关系。候选：

1. 同义词表 / 关键词加权；
2. 纯语义（个人文本也走向量）；
3. 训练一个 LTR 模型；
4. 证据分级（按「谁写的、有多确定」分层，层内再比分数）。

## 决定

1. **按证据分级排序，先层后分**：S0 名字/标题 > S1 个人精确 > S2 个人语义 > S3 作者内容 > S4 通用语义。同一层内再按各自的分数排。
2. **个人层只在库内生效**：`scope=library`，以及 `scope=all` 的库内行；公域检索完全不变，个人文本不进公域向量。
3. **两段都参与召回**：我的适用场景在 S1/S2；作者的 `when_to_use` **仍在 S3，不因个人层被删除**。两段都命中时按我的 S1/S2 排；只有作者命中时仍召回。「覆盖」是显示与排序上的优先级，不是把作者那句从召回里删掉。
4. **精确命中用最长公共子串**：查询与说明的 LCS ≥ 3 个汉字或 ≥ 5 个拉丁字符；**语义命中**把说明按句切、每句一条向量，查询取最大 cosine。**不做同义词表**——用户明确否掉，维护也不现实。
5. **v1 不训练**：只记录 `search` / `adopt` / `exclude` / `note` 事件与 `search_id` 关联；训练与 LTR 要等样本与离线评测。
6. **阈值与 margin 可配置**：S2 用高阈值 + `top1 - top2 ≥ margin`，具体值用 20–50 条标注集扫 precision/recall 后定，不拍数字。

## 理由

- **否掉同义词表**：用户明确说「什么规则的同义词替换就算了，这个一点都不友好」；换说法交给语义，词表只会越维护越漏。
- **否掉纯关键词加权**：关键词无法处理「反复审查」这类改写；而名字/标题的精确命中又不该输给泛语义，所以需要分层而不是把所有信号压成一个分数。
- **否掉纯语义**：名字/标题是零歧义的强信号；个人写的触发句是用户自己定义的强信号。两者都比「作者内容的泛语义」更硬，不能同层比 cosine。
- **否掉训练**：现在没有样本、没有离线评测集；训练还会把个人说明的隐私面扩大。先用规则提高召回，等事件管道跑出 1–3 个月样本再评估。
- **保留作者那句**：它是 skill 的正式字段，也是公域与别人的兜底；个人化不应该以丢失作者信息为代价。

## 后果

- 库内检索的成本是 `O(M)`（M = 我的库大小），公域仍是 `O(N)`；个人层不影响公域。
- 作者文本仍在 S3 参与召回；两段都命中时按 S1/S2，作者那句不额外压过个人层。
- S2 要把个人说明发给 DashScope `text-embedding-v4`；**隐私政策 §五 的 DashScope 条目必须先补**，否则 S2 不上线。
- 事件关联（P3）依赖「个人调用记录」管道（尚未开版）；没有样本前不训练。
- 标注集不达标（个人触发组 Top-1 / 改写组 Recall@5）不算交付；阈值与 margin 的实现值以评测结果为准。
- 个人说明的字段上限与写入/发布契约由 [ADR 0181](0181-text-limits-use-unicode-code-points.md) 定；本 ADR 只管排序与作用域。
