# 0168 · 托管的是调用第三方服务的 API 凭据，不是身份密码

- **状态**：已采纳
- **日期**：2026-11-08
- **依赖**：[ADR 0025](0025-cli-credential-storage.md)（CLI 凭据存储）、[ADR 0038](0038-default-credential-is-an-api-key.md)（平台自己的 API 密钥）、[ADR 0081](0081-every-console-operation-has-a-cli-command.md)

## 背景

[`target/design.md`](../target/design.md) §2.1 的边界原文是「不存储第三方密码，不代管组织外的身份」。这句话当时的语境是**身份**（飞书只作 SSO，不做通讯录同步），但字面上把「代管第三方凭据」整类挡在门外。

现实是另一回事（2026-10-31 [调研](../research/third-party-credentials.md)）：

- skill 说明要求用户把 key 发进聊天框（`lijinzhao/byted-web-search` 原文如此），key 因此进入模型上下文与对话记录；
- 作者把 key 写进包的 `.env`，`skmr skill download` 会把它原样落下（实测），包一共享就泄露；
- 用户各自 `export`，换机器重来、没有审计、协作者只能发明文。

2026-11-07 用户把「跨机器」提成硬需求：**同一份 skill 换台机器不用重贴 key**。这句话把「平台不托管」这条排除了。

当时可选的有四条：

1. **完全不托管**，只做本地钥匙串 + `skmr secret run`（[调研](../research/third-party-credentials.md) §六 P1 的原始建议）；
2. **托管调用第三方服务的 API 凭据**；
3. **连身份密码一起托管**；
4. **交给第三方密码库或 agent 授权平台**（1Password / Doppler / Infisical / Vault / Composio / Nango）。

## 决定

- 平台托管**用户明确授权、用于调用第三方服务的 API 凭据**；**不托管身份密码**（登录第三方的账号密码）。
- 粒度分两层：**值属于用户**（一条值可以有多条绑定），**绑定是 `(凭据, skill, 环境变量名)`**，也是唯一的暴露途径。默认只有主人能用；共享是**按 skill 的使用权**（凭据 + skill + 人），不是密钥副本。
- 产品名 **「服务凭据」**；CLI 命名空间 `skmr secret`；不复用「API 密钥」这个词——那一把的方向是「用户 → 我们」（[ADR 0038](0038-default-credential-is-an-api-key.md)），混用会让用户分不清「我的 key」和「给 skill 用的 key」。
- **删除承诺**：生产库立即删除；备份按 **30 天**保留期自然过期。**不做「加密粉碎」承诺**——wrapped key 与密文在同一份备份里，删行不等于删备份。
- `target/design.md` 的正文字句不动，边界变更登记在 [`target/README.md`](../target/README.md) §十。

## 理由

- **否掉 1（完全不托管）**：本地钥匙串解决不了「换机器」与「协作者」，而这两条是 2026-11-07 明确的硬需求。本地方案没有消失，它降为离线兜底。
- **否掉 3（连密码一起托管）**：密码不能轮换、通常不能在第三方侧撤销，托管它等于代管身份；责任面、同意流程与删除承诺都与 API 凭据不同。要做必须另开一条 ADR。
- **否掉 4（第三方密码库）**：计价单位是「人」或「凭据」、数据出境、控制面（谁能用哪条、绑定哪个 skill）仍然要我们自建（[调研](../research/third-party-credentials.md) §三、§四）。
- **为什么叫「服务凭据」**：用户要理解的是「这是给 skill 调用外部服务用的」，不是「我的账号凭据」。

## 后果

- **平台成为托管方**：拖库的后果从「密码哈希泄露」升级为「用户的第三方账号被接管」。需要 KMS（[0170](0170-the-root-key-lives-in-a-cloud-kms.md)）、审计、事件响应、删除承诺与隐私政策。
- **共享的文案必须说真话**：第一版的注入在用户机器上完成（[0169](0169-the-first-version-injects-without-proxying.md)），协作者拥有那台机器，**能提取明文**；产品里不能写「协作者拿不到」。
- **目标态出现一处边界变更**：仍在 `target/README.md` 的差异清单里登记；再遇到「代管身份」的需求，需要新 ADR，不能援引这一条。
- **删除承诺受备份保留期约束**：30 天这个数字要与隐私政策一致；若要真加密粉碎，只能每条凭据独立根密钥，成本按条线性增长，不采纳。
