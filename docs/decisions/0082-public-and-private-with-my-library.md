# ADR 0082 · 公域 / 私域：库是引用，公域只搜不列

- **状态**：已采纳
- **日期**：2026-10-23
- **依赖**：[ADR 0034](0034-skill-level-sharing.md)（skill 级共享）、[ADR 0047](0047-permissions-are-a-ladder.md)（权限是梯子）、[ADR 0048](0048-visibility-hands-out-a-rung.md)（可见性只是发一张票，不是门禁）、[ADR 0006](0006-search-server-side.md)（检索在服务端）

## 背景

v14 要在 skill 上做两套标签，而私人标签依赖一层今天没有的东西：**一个“我这边的 skill 目录”**。旧的 `skills list` 回答的是「我能看见什么」——自己的、被授权的、**以及全部公开的**。公开 skill 会越积越多，这条查询迟早无法加载；而用户真正需要的是一份自己整理过的目录，不是整个市集。

产品负责人同时要求把 skill 分成公域与私域：公域可以搜、可以加入自己的库；私域是自己创建、别人共享、自己加入的那一份。加入必须是**组织动作**，不能变成权限动作——否则 v1 里「公开即可调用」的语义会被悄悄改掉。

## 决定

1. **两层**：**公域**是公开、有当前版本、未下线、未删除的 skill，**只能搜、不能整表列**（关键词、公开分类、公开标签至少一个）。**我的库**是私域目录：我创建的 + 共享给我的 + 我加入的。
2. **加入是引用**：不复制内容、不产生版本、不改变访问权、不挡加载（[ADR 0048](0048-visibility-hands-out-a-rung.md) 不动）。未加入的公开 skill 仍可直接 `skill invoke`。加入幂等。
3. **来源按优先级显示一个**：我创建的 > 共享给我的 > 我加入的；来源是行内标签，不是第三个页签。
4. **`skills list` 默认只列可消费的库**（三类里有当前版本、未下线、未删除的）；公开但未加入的不出现。完整库（含草稿、下线、作者面的已删除）由 `--show` 打开。
5. **加入的边界**：只能加入同时满足 `visibility = public`、有当前版本、未下线、未删除、我不拥有、没有授予我的 `skill_grant` 行、没有库加入引用（含休眠）的 skill。已有加入引用是 no-op；来源是创建 / 共享（没有加入引用）是 409 + 可读原因；不可见或非公开是 404；可见但当前不可加入（下线 / 没有当前版本）是 409。
6. **库的生命周期**：我加入的条目分**生效 / 休眠**。下线时，我加入的与 `browse` / `invoke` 共享的休眠，我创建的与 `write` 及以上共享的留在「在用」并显示「已下线」；软删除时，我创建的进作者面的「已删除」，其余休眠；撤销共享时，共享来源消失——有加入引用且仍可读则条目留下、来源变我加入的、标签继续生效，否则条目离开库、标签休眠。移除只删引用、不留墓碑；重新加入后标签回来。
7. **推荐流仍留在控制台**：它是消费型页面流（一批 6 张、按更新时间倒序、不在我库里），不是 CLI 命令（[ADR 0080](0080-cli-covers-non-high-risk-operations.md) / [0081](0081-every-console-operation-has-a-cli-command.md)）。

## 理由

- **公域无界，整表列一定撑不住。** 搜索有明确的输入；列表没有。把“全部公开”做成默认列表，是在为一个不可能加载的页面写查询。
- **复制会切断作者更新。** 加入若做成复制，作者发新版与用户手里的副本从此分叉，还要回答内容归属与许可；引用没有这些问题。
- **组织不是权限。** 加入只改变“我在哪里找得到它”，不改变“我能不能用”。把两者混在一起会让 [ADR 0048](0048-visibility-hands-out-a-rung.md) 的公开语义失效。
- **来源是一个标签，不是第六个页面。** 一个 skill 在库里只可能出现一次；“我创建的 / 共享的 / 加入的”是它的来源，不是它的分类。
- **休眠而不是删除。** 共享被撤销、条目下线时，标签对应的组织关系没有消失，只是当前看不见；删掉会教用户不敢整理。

被否掉的：**复制 / 派生公开 skill**（切断更新、内容归属）；**未加条件的公开全量列表**（无法加载）；**公开 skill 的加载门禁**（推翻 0048）；**给来源单开一个页签**（一个条目只有一个来源）；**库的团队 / 共享视图**（组织模型未落地）；**显示调用次数与「调用最多」排序**（产品今天没有用量信号）。

## 后果

- 新增库条目表（`skill` 所在模块 M12，见 [ADR 0053](0053-skill-metadata-is-its-own-module.md)），记录“人 + skill + 加入引用”的生效 / 休眠。
- `skills list` 的结果集、默认页（100 → 50）与 `--show` / `--source` 是新契约；`skills search` 收窄为只搜公域。
- 控制台新增「发现」页，重塑「我的 skill」为完整库（来源、页签、三种空态、行内状态）。
- CLI 新增 `skill join` / `skill leave`（带 `--yes`）与 `skills list --source` / `--show`；网关 skill 先读库、再搜公域。
- 目标态文档没有「库」这一层，它是本版的显式扩展，已登记在 [`target/README.md`](../target/README.md) §五。
