# SkillMaster · 产品文案与语气

> **最后更新**：2026-10-23（v14：公开分类收窄为平级单选；公开标签与 `#名字` 写法）
> **管什么**：**界面内**出现的每一句话——按钮、标签、标题、说明、错误、空态、确认、通知。
> **不管什么**：营销文案（首页那套，见 [`spec.md`](spec.md)）、品牌气质与视觉禁区（见 [`brand-spec.md`](brand-spec.md) §气质与禁区）。

**三份文件的分工，一句话**：`brand-spec.md` 说**这个品牌听起来像谁**，本文件说**界面里的这句话该怎么写**，[`README.md`](README.md) 保留**每一屏自己**的设计理由（为什么这一屏这么排、这句话为什么出现在这里）。**一处一个权威**：用一个词、禁一个词，只在本文改；README 里那些逐屏的说法不重复本文的规则，只引用。

**这份文件是怎么来的**：2026-10-16 定。规则**借自 [`product-content-strategist`](https://github.com/xzjh/product-content-strategist)**（一份把 NN/g、Material 3、Apple HIG、Carbon、Mailchimp、Microsoft、Atlassian、Polaris 的界面文案规范合起来的 skill）里**适用于中文**的那几条。**它英文专有的那几条明确不收录**——句首大小写、缩写（We'll）、阅读年级目标，这三条在中文里没有对应物，抄进来只会让人去改一个不存在的问题。词表同理：它的禁用词是英文的，本文只搬**类别**（见 §五）。

## 一、声音与温度

**声音是常量，温度随情境变。** 同一个人在计费错误页和空态里是同一个人，但说话的冷热不同。

**声音（永远不变）**：正式、克制、说事实。技术用户是你的读者，他们**不需要被鼓励，只需要被准确告知**。

**温度（随情境）**：

| 情境 | 温度 | 表现 |
|---|---|---|
| 正常态、列表、说明 | 平静 | 陈述事实与边界，不推销功能 |
| 空态 | 平静 + 一句「为什么空」 | 说清这个列表是什么、下一步在哪；不画插画、不打气 |
| 错误 | 冷静，且**必须给出路** | 发生了什么 + 你还能做什么。不道歉、不解释账号没事（除非真的有人会这么担心） |
| 不可逆动作的确认 | 明确，先说后果 | 用后果代替「确定吗」；两个答案各自说清自己去哪 |

## 二、人称

- **对读者一律称「你」**，不用「您」（我们的读者是开发者，客气会拉远距离，而「您」在本产品的既有文案里从未出现过）。
- **第一方自称「我们」**，且**只在解释边界时用**——「我们不知道这一项的含义」（同意页）、「我们没能读到…」。**不用「本系统」「平台」这类自我指称**：它们把一句话的主语换成一个不存在的东西。
- **不用「用户」自称读者**：「用户可以在这里撤销」→「你可以在这里撤销」。

## 三、名词表：一个东西一个名字

**这一节是硬约束。** 同一个东西在界面上只能有一个名字，换名字等于换概念。

| 东西 | 界面上的名字 | **不用** |
|---|---|---|
| 访问凭据（用户自己签发的） | **API 密钥**（首述）／**密钥**（同一屏后续） | 令牌、token、凭证、访问凭据 |
| 一把密钥的换发 | **续期** | 轮换、刷新、更换 |
| 结束一把密钥 | **撤销** | 删除、作废、失效（那是状态，不是动作） |
| 一次登录在一台设备上留下的东西——浏览器里的那次，或 CLI 在一台机器上换来的那次 | **登录设备** | 会话、session、设备（单独用）、凭据、授权 |
| 结束一台登录设备 | **退出**（「退出该设备」） | 踢掉、下线、踢下线、登出 |
| 从控制台离开自己的账号 | **退出登录** | 登出、注销 |
| 一个版本成为对外生效的版本 | **上线** | 发布、deploy |
| 把一个版本交给服务端（落成草稿，还没上线） | **提交** | 上传、push、发布 |
| 浏览器里把本地压缩包变成一版草稿（与 CLI 的 `skill submit` 是同一件事的两个入口；菜单项与标题都用「导入」起头——「导入本地 skill」「导入压缩包」「导入 skill」「导入新版本」，不写「提交」「上传」。「提交人 / 提交于」是另一件事） | **导入** | 上传、import、引入 |
| 把一整版取到本地（一个 zip） | **下载** | 导出、export、拉取 |
| 从零建一个 skill（名字 + 描述 + 第一条草稿的版本名称）——浏览器与 CLI 是两个入口，同一件事 | **新建 skill** | 创建 skill、从零开始、空白 skill |
| skill 的名字（地址的最后一段） | **名字** | 名称（在 skill 语境里；版本那一层叫「版本名称」；API 密钥与登录设备的「名称」是它们自己的字段）、slug、标识 |
| 一个 skill 的改动集 | **版本** | revision、commit |
| 一个 skill 适合被用在什么情境 | **适用场景** | 使用时机、什么时候用、用例、场景 |
| 跑这个 skill 需要的环境（`compatibility`） | **运行环境** | 兼容性、环境要求、依赖 |
| 可见性两档 | **私有**／**公开** | 内部、unlisted、仅自己可见 |
| 梯子上的一格（调用／浏览／写入／维护／管理） | **档位** | 角色、级别、role |
| 平台预置的 10 个平级词，**每个 skill 只贴一个**，用于公域发现与筛选 | **分类**（界面上）／**公开分类**（文档与 CLI 里的精确称呼） | 标签、tag、类别、分区 |
| 每个用户自己的一套词，贴在库里的 skill 上，只有本人看得见 | **我的标签**（界面、文档、CLI 同一个名字）。信息页那一组、库的筛选、管理页的页签都写「我的标签」；侧栏的「管理 › 标签」与那一页的标题仍是「标签」——那是一个管两份清单的页面的名字 | 私人标签（那是模型与 ADR 里的叫法）、个人标签、自定义标签、收藏 |
| 作者给 skill 贴的公开自由词，用来做搜索召回（推荐以后可用）（**本版做最小闭环**；同义词合并、改名/合并与审核仍不做，见 PRD 不做 #25） | **公开标签**（界面、文档、CLI 同一个名字），在界面上显示成 `#名字` | 话题、主题、关键词、公开词、content tag |
| 我这边的 skill 目录（我创建的 + 共享给我的 + 我加入的） | **我的 skill**（页面标题）／**库**（文档内部简写） | 我的库存、收藏、目录 |
| 一个 skill 怎么进到我的库里 | **我创建的 / 共享给我的 / 我加入的**（三个词，按这个顺序取一个显示） | 自有、他人共享、收藏、订阅 |
| 把一个公域里的公开 skill 收进我的库 | **加入**（说明句写「加入我的 skill」） | 收藏、添加、订阅、导入 |
| 把它从我的库里拿走（只删我这条引用） | **移除** | 删除、取消加入、移除引用 |
| 创建这个 skill 的那个人，唯一且不可让渡 | **所有者** | 拥有者、管理员、owner |
| 结束一次共享（把某个人在某一个 skill 上的档位撤掉） | **撤销**——与结束密钥同一个词 | 撤回（申请用「撤回申请」）、取消、移除 |
| 请有权限的人给你一档更高的档位（**不授予任何东西**，见 [ADR 0052](../docs/decisions/0052-a-request-is-not-a-grant.md)） | **申请**；结束它是**撤回申请** | 请求、请求访问、申请权限 |
| 把一个删掉的 skill 找回来 | **恢复** | 还原、取消删除、undelete |
| 已经被删掉的那些 skill 的那一份列表 | **已删除** | 回收站、垃圾桶、已归档 |
| 作者给一版起的短名字（`draft_name`） | **名称**（版本名称） | 版本名、草稿名、标题（`title` 是内容字段） |
| 一版改了什么的那一句话（`changelog`） | **说明** | 描述（那是 skill 的描述）、changelog、备注 |
| 一个标签什么时候该贴的那一句（选填，≤200 字；`skills my-tags` 也读它） | **说明** | 描述、备注、标签描述、标签简介 |
| 发布时分配、调用者用来寻址的号 | **版本号**（`@1.2.3`） | tag、版本名（那是另一个东西） |
| 一行版本在作者面的稳定 id（新行 8 位短码，旧行 26 位 ULID；只展示、不参与消费面寻址） | **版本码** | 版本标识、短码、行 id、draft id、草稿 id |
| 提交后、还没上线的一版 | **草稿** | 未发布版本、待发布版本 |
| 新版本编辑页里、第一次内容改动前的那一份内容（线上版本、一份草稿，或空白） | **底稿** | 基础版本、来源版本、基线 |
| 当前对外生效的那一版 | **线上** | 当前版本、最新版 |
| 已发布、非当前、仍然可读的那些 | **历史版本** | 旧版本、归档版本 |
| 作者让一个非当前版本对调用者不可读 | **下架** | 撤回、收回、下线（下线留给 skill） |
| 让已下架的版本重新可读 | **重新上架** | 恢复（恢复留给 skill 与删除）、上架 |
| 把线上指针移回一个历史版本 | **回滚** | 降级、回退 |
| 结束一个从未上线的草稿 | **丢弃** | 删除、废弃、作废 |
| 整个 skill 停止服务 | **下线**（skill 级） | 关闭、停用、下架（下架留给版本） |
| 让下线的 skill 重新服务 | **恢复服务** | 上线、恢复（恢复留给删除的 skill） |
| 凭据或人对草稿能做的三件事 | **管理草稿**（改名、改说明、丢弃） | 编辑草稿、维护草稿；**它不含内容编辑** |
| 被下架、对调用者不再可读的那一版（状态） | **已下架** | 已撤回、已下线 |
| 被作者丢弃、从未上线的那一版（状态） | **已丢弃** | 已删除（那是整个 skill）、作废、废弃 |

**「不用」列管的是名字，不是句子。** 它禁的是**第二个名字**——状态标签、按钮、菜单项、标题里出现的同义词。解释性的句子里为了把话说明白而写「这一版会成为当前版本」「指定旧版本的调用不受影响」「恢复后不需要重新上线」，指的还是**线上**、**历史版本**、**恢复服务**，界面上并没有多出第二个标签，这样写不算换名。判据只有一条：**那个词是不是被当作这个东西的名片在指认它**（出现在标签、按钮、标题、菜单项里）——是，就用左列；只是在一句完整的话里描述状态怎么变，照常写。

**skill 名写「名称」的三处，现状是「一处已改、两处还在」。** 我的 skill 的排序项在 v14 已从「名称」换成**「名字」**（设计件 `SkillsPage.tsx` 的 `SORT_GROUPS`）；**产品里剩下删除确认的正文与标题（`SkillPage.tsx`）两处**，它们与本表冲突，下一次改到那一屏时一并换掉。

**为什么界面上现在写「分类 / 公开标签 / 我的标签」（2026-10-22 定，2026-10-23 改）。** 2026-10-22 只有一种分类、一种标签，所以标题里不写限定语；2026-10-23 设计稿把作者的公开标签画出来之后，两种标签并存，限定语重新必要——信息页的三组写成「分类」「公开标签」「我的标签」，库的筛选与管理页的页签写「我的标签」，只有侧栏的「管理 › 标签」与那一页的标题仍是「标签」（那是一页管两份清单的页面名）。**可见性仍然说出来，说在需要它的句子里**：标签页的空态写着「只有你看得到」。**新建那一行不再重复这句**（2026-10-23 用户定）：这一页本身就是每个人的私域，句句都挂一条可见性只是噪音。文档与 CLI 保留「公开分类 / 我的标签」这两个精确称呼（CLI 的命令 `skills categories` / `skills my-tags` / `skills public-tags` 与 `skill tag` / `skill category` 本来就不带限定语）；公开标签那一层不叫话题、不叫主题，也不叫关键词。

**公开标签写成 `#名字`**（2026-10-23）：卡片、信息页的胶囊、管理页那一份清单都带井号；分类与我的标签都不带。井号是这一层在界面上的写法，不是名字的一部分——搜索、文档与 CLI 里写的仍是名字本身。本版做最小闭环（PRD #17 / §公开标签）：贴、摘、召回；同义词合并、改名/合并与审核仍不做。

**四个词有两种意思，是有意的，不是漏改**：

- **「管理」**既是 SKILL 组里那条可展开的一级项（装着管理类页面：今天是「标签」，以后都放这里），也是梯子上的 `admin` 那一档。两者都在用户面前出现，且都不便换个说法——它们本来就是这个产品里「管理」的两面。**库入口不再叫「管理」**（2026-10-22）：它现在叫「我的 skill」，与页面标题一致；「管理」这个名字留给管理类页面的家。
- **「说明」**既是版本的那句 changelog，也是标签的那句「什么时候该贴它」（2026-10-22 加）。两处都是**一句话解释一件事**，各在自己的那一屏里出现，从不并排；换成「描述」反而会撞上 skill 的描述。按语境分，与「管理」同一种已批准的用法。
- **「发现」**是一个动词，而导航项的名词短语规则要求名词。它留下是因为这一组里没有第二个东西会叫「发现」，而「公域」是文档里的词、不是界面上该出现的词。**这是导航命名规则的唯一例外**，不要拿它去给别的导航项开口子。
- **发现页没有看得见的页标题**（2026-10-23 用户定）：导航里已经有「发现」，页头再报一次名字只是重复。这一天早些时候曾把它写成一句「找到能直接用的 skill」（后改「找到可直接使用的 skill」），但一句祈使句压在搜索框旁边读起来像指令、像公文，用户判「突兀」，于是整句拿掉——页头只留搜索与分类。文档结构里的 `h1` 写「发现」，**只给读屏看**。**这是标题规则的一个例外**，别的页标题仍然是名词短语（「我的 skill」「账号」「我的标签」）。

**为什么「发布」出局（2026-10-16 改，改的是这张表自己的一个错误）。** 这一格原先写着「**发布**（"发布"留给 CLI 的动词）」——**这句话是错的，而且它就是那处文案错误的源头**：授权屏照它写出「以你的名义**发布**、更新和删除 skill」，而 CLI 发不了、也永远发不了。[ADR 0031](../../docs/decisions/0031-submitting-and-publishing-are-two-actions.md) §决定 2 定的是：提交与上线是**两个动作**，而上线**只在浏览器面存在**（`/web`，会话 + CSRF），API 平面（Bearer 密钥生效的那个平面）**根本没有 publish 这条路由**——`WebSkillRoutes.PUBLISH` 的注释写着它是「系统里唯一一个」，「故意」放在那个平面。所以：CLI 只**提交**（落草稿），人**上线**。**一个没有任何主体会执行的动作，不该留在名词表里**——留着它，它就会像这次一样被写成一句承诺。

**为什么「登录设备」这一格在 2026-10-16 放宽了。** 它原先写「**浏览器**登录留下的一次会话」，因为那时只有浏览器里的登录会留下东西。v4 之后 CLI 也能从浏览器换来一次登录（`skillmaster login` → 点一下 → 这台机器登录着），而那一次**与浏览器那次是同一类东西**：同样的两条尺子（闲置 24 小时 / 绝对 7 天）、同样的动作（退出）、同样出现在这一屏上。所以这一格改成按**"一次登录"**定义，而不是按"哪个客户端发起的"——**按来源命名会让名字随每一条新路增长**（以后有第三方宿主怎么办），而按它是什么命名只写一次。**同时把「凭据」「授权」列进禁用列**：它们描述的是机制，不是人在这一屏上看到的东西；机制叫什么都行，界面上它叫**登录设备**。

**为什么「退出」而不是「踢掉」**：参照产品的用词是 *Revoke*，而它的**禁用类别里正好有一条「隐喻/暴力动词」**（`kill the process` → `stop`、`bulletproof` → `reliable`）。「踢掉」正是这一类：它**用一个不存在的动作来描述一个存在的动作**，而这个动作的真实语义——**那台设备上的登录结束**——正好有一个现成的字面词。**隐喻词读起来更生动，但它需要读者先做一次翻译**，而界面文案的每一次翻译都是一次可能的误解。（"登出"同理不用：它是"退出登录"的生造简写，而"退出登录"已经是两个字的动词短语。）

## 四、句式（按界面类型）

| 类型 | 怎么写 | 例子 |
|---|---|---|
| **按钮** | **动词开头**，2–6 字；同一个位置上不出现两个同义动词。图标按钮（发现页卡片右上角的书签）可见的是图标，**可访问名仍用动词**「加入 / 移除」 | 「新建密钥」「续期」「退出该设备」「重试」 |
| **标题 / 导航项** | 名词短语，不带动词、不带标点 | 「登录设备」「API 密钥」「账号」 |
| **说明句** | 一到两句。**先说这是什么，再说边界** | 「CLI 与 agent 使用这些密钥访问你的 skill。**密钥仅在创建时显示一次**，之后只保留名称、权限与使用记录。」 |
| **错误** | **发生了什么 + 你还能做什么**。字段级的错误**与字段名用同一个词**；空栏给**指令**，格式错给**描述** | 「无法加载登录设备列表，请稍后重试。」「名称不能超过 60 个字符。」 |
| **空态** | 这个列表是什么 + **为什么是空的** + 下一步在哪。**不复述上面那句计数已经说过的话** | 计数说「暂无菌钥」，列表里就说「在控制台签一把，交给要用的机器」——不写「还没有密钥」 |
| **不可逆动作的确认** | **先说后果**，再给两个**各自说清去向**的答案。**不写「确定吗」**（它一个信息都不给） | 「续期后，这把密钥立即失效，换上一把新的。」／「确认续期」「取消」 |
| **计数 / 状态** | **名词短语**，不是句子 | 「5 个密钥（活跃）」「3 台设备」「仅当前设备」 |

## 五、禁用

### 词

- **营销腔**：轻松、一键、强大、极速、极致、全新体验、赋能、助力。
- **对读者能力的判断**：简单、容易、快速、轻松——**这四个词是在替读者评价他自己**，而你不知道他是不是第一次用。（这一条借自英文规范里的 *easy / simple / quick*，中文产品同样在犯。）
- **隐喻与暴力动词**：踢掉、杀掉、干掉、一键清空（见 §三）。
- **责备**：你忘了、你没有填写、错误的输入——**描述状态，不评价人**。
- **万能词**：提交（按钮上要写清提交**什么**）、确定、是/否（在不可逆的流程里）、点击这里、了解更多（**链接文字必须能脱离上下文读懂**——读屏软件会把链接排成一个列表念出来）。

### 写法

- **不用感叹号。** 一个也没有。成功也不加：成功由状态说，不由标点说。
- **错误里不开玩笑、不道歉。** 反复出现的玩笑会腻，道歉则把一次技术问题变成一次社交。
- **不写「后续再说」「敬请期待」。** 没有的东西不提。
- **不靠语序承载信息**（本地化与读屏都会打碎语序）：「三天后，若仍未使用，密钥将失效」优于「密钥三天后仍未使用将失效」。

## 六、标点与排版

- 中文标点一律全角；**中文与拉丁字母、数字之间留一个空格**（既有文案就是这么排的：`到期 2027/01/13`、`skills:read`、`读 pdf-tools 用的`）。
- **短标签不加句号**（按钮、导航项、计数、状态），**句子加句号**。
- 并列用「　·　」（全角空格 + 间隔号 + 全角空格）——控制台既有做法。
- 数字与日期照已有的写法：日期 `2026/10/16`，相对时间「今天 09:41」「昨天 03:12」「刚刚」「从未使用」。

## 七、交付前过四道

改完一屏文案，按顺序过一遍；四条都过不了就不算写完：

1. **动词检查**：每个按钮是不是动词开头？有没有两个按钮在说同一件事？
2. **出路检查**：每一句错误，读的人**知道下一步做什么**吗？
3. **禁用词检查**：§五 那四类词，一个都没有吗？
4. **名词检查**：§三 表里的东西，这一屏用的是**表里的那个名字**吗？

**还有一条不属于这四道、但比它们更容易漏**：**同一件事有没有说两遍**。计数说「只有这一台设备登录着」，下面那行就不该再说「只有这一台」——两句话在争同一件事时，读的人得先判断它们是不是在说同一件事。**这一条断言量不到，只能靠看图**（2026-10-16 就是这么发现的）。
