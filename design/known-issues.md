# 设计件的已知缺陷

这份文件记**已经确认、这一次决定不修**的界面缺陷。它们是演示件自己的问题（不是产品的），修起来要动设计稿，所以先记下来，等改到那一屏时一并处理。

体例照 `docs/versions/*/known-issues.md`：每条写清状态、是什么、影响、为什么先不修、建议怎么修。

## 001 · 六格验证码打完六位后，第一次点「重新获取验证码」没有反应

**状态**：已复现（2026-10-22；旧交付件 `git show 49a98b0:design/skillmaster-首页演示.html` 与新实现都能复现）

**是什么。** 找回密码第二步（`src/shared/auth/views/ResetCodeView.tsx`）与注册第二步（`RegisterCodeView.tsx`）共用六格验证码控件。填满六位后，输入框**失焦**那一刻才判定这一格并画出「✓」；提示行从 0 高变成 22px，把它下面的 `.dialog-foot`（「重新获取验证码」·「去登录」）整体往下顶约 15px。鼠标按下时指针还在链接上，抬起时链接已经移走，浏览器因此不把这一下算作点击。第一次点没有反应，第二次（此时布局已经稳定）才生效。

**影响。** 拿到一个怪异的交互：点一下没反应，容易以为演示件坏了。键盘（Tab + Enter）不受影响，因为焦点移动不依赖坐标。

**为什么这次不修。** 两个修法都要动设计稿，而这是设计件的缺陷、不是实现的漂移：一种要给字段提示行预留固定高度（所有字段的垂直间距都会变），一种要把链接改成按下即触发（鼠标按下后拖开不再能取消这次点击）。取舍该由设计定，不该在迁移里顺手改掉。

**建议修法。** 二选一：

1. **给提示行预留高度**（`.field-error` / `.field-ok` 始终占位，只在有话说时显形）。视觉更稳，但整张卡的字段间距都会变，需要重新出图与人看。
2. **链接改为 `onPointerDown` 触发**（或把这一行移出会移位的流）。DOM、类名与样式一个字节不动，代价是鼠标按下后拖开不再能取消这次点击。

修的时候两屏都要看：找回密码与注册的第二步是同一个控件。
