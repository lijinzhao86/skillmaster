# SkillMaster 界面演示

**这两份演示件是产品界面的权威**：`skillmaster-web/` 的每一处界面都照它实现，**不许自行发挥**——规则见仓库根的 [`CLAUDE.md`](../CLAUDE.md)。

**这是两份纯前端的设计与交互演示件：都不连后端、不真的发短信、不发任何网络请求。**

用途是让设计和交互可以被看见、被点击、被修改——包括由设计师通过 agent 来改。

| 交付件 | 是什么 |
|---|---|
| `skillmaster-首页演示.html` | 营销首页 + 登录 / 注册 / 找回密码 / 授权请求四套流程（同一个浮层里换视图） |
| `skillmaster-控制台演示.html` | 登录之后的控制台：外壳 + 我的 skill / 一个 skill / 设置 |

两份都是**自包含单文件**，双击就能开（图片已内联，不依赖任何其他文件、不依赖网络）。

下面「首页演示」与「控制台演示」两节各讲一份；「让 agent 帮你改」「重新出图和跑交互测试」「目录里还有什么」「已知的取舍」四节两份共用。

## 首页演示：里面有什么

一屏营销首页 + 一个浮层，浮层里装三条流程（在同一个浮层里换视图，不跳页）：

**首页** 可以处在**未登录**和**已登录**两种状态，导航不一样。

**登录** 点导航「登录」或 hero「开始使用」打开。手机号与密码可以真的输入，密码框右侧的眼睛图标能切换明文。

**注册** 两步：先是**用户名 + 手机号 + 密码**（+ 条件出现的图形验证码），点「下一步」发码 → 再填**六位短信验证码** → 注册成功。**退回第一步时填过的值还在。**

**找回密码** 三步：**手机号 + 图形验证码** →「下一步」发码 → **六位短信验证码**（填满六位就**自动**判定并前进，错了清空六格重填）→ **新密码** → 重置成功。

**授权请求**（OAuth 确认）**只有地址能进**，页面上没有任何入口——见下一节。

浮层的关闭方式：点遮罩、点右上角 ×、按 `Esc`。

## 怎么打开「授权请求」

这一屏**故意不给页面入口**。真实产品里它不是从网站点进去的：你在终端跑 `skillmaster login`，**CLI 把浏览器领到一个带参数的地址**上。演示件照抄这件事，所以入口也是地址：

| 在地址栏给这个文件加上 | 看到 |
|---|---|
| `?client_id=skillmaster-cli&state=abc123&scope=skills:read%20skills:write` | **授权请求**（正常态）：客户端名、两条权限说明、**一行边界**（它不能上线）、「同意并继续」/「拒绝」 |
| `?client_id=skillmaster-cli`（**故意缺 `state`**） | **链接不完整**态：说清缺什么，让你回终端重跑 `skillmaster login` |

判定很简单：**地址里带了 `client_id` 或 `state`，就当作「CLI 交过来的」，直接开授权屏；不带就是普通首页。**

（`scope` 里那个 `%20` 是空格——真实的 redirect 也是把多个 scope 用一个空格分隔的参数传过来的。）

**这一屏说三件事，第三件才是它存在的理由。** 谁在请求（客户端名；认不出来就原样显示那个 id 并加一句警告）、**它能做什么**（两条权限，写成后果而不是 scope 名字）、以及**它做不到什么**——「它不能上线——把版本对外公开，是你在网页上确认的动作。」这最后一句**单独占一行，不塞进上面那一条的末尾**：一份同意书里最容易被人搞错的就是「这个工具做不到的事」，而挂在列表项尾巴上的从句读起来像对那一条的补充说明，不像一条边界。

**「发布」这个词是 2026-10-16 从这里删掉的，而它当初是被写进名词表的。** 原话是「**发布**（"发布"留给 CLI 的动词）」——**这句是错的，也正是这处文案错误的源头**：上线只在浏览器面存在（`/web`，会话 + CSRF），API 平面（Bearer 凭据生效的那个平面）**根本没有 publish 这条路由**（[ADR 0031](../docs/decisions/0031-submitting-and-publishing-are-two-actions.md) §决定 2；`WebSkillRoutes.PUBLISH` 的注释写着它是「系统里唯一一个这么做的接口」，且「故意」放在那个平面）。所以这份凭据永远发不了东西——它只**提交**（落成草稿，要人在网页上确认才上线）。名词表那一格连同它的理由一起改了，见 [`voice-spec.md`](voice-spec.md) §三。

**两处一起对齐了，各有一条断言守着**：演示件这里（`interaction-check.mjs` §8 钉「权限那条不许出现'发布'」＋「边界那句在」）与产品 `skillmaster-web/src/pages/ConsentPage.vue`（`tests/consent.test.ts` 钉同样两件）。

点「同意并继续」或「拒绝」之后会落到「授权成功」/「授权未完成」，那两句话是 **CLI 回环页的原话**（`skillmaster-cli/internal/auth/callback.go`），不是这里编的。

完整地址长这样（把路径换成你自己的）：

```
file:///Users/lijinzhao/Developer/skillmaster/design/skillmaster-首页演示.html?client_id=skillmaster-cli&state=abc123&scope=skills:read%20skills:write
```

⚠️ **别用 macOS 的 `open` 打开这条地址。** `open` 会先把 `file://` 地址解析成**文件路径**再交给浏览器，`?` 后面那截在这一步就掉了——浏览器里落地的是**普通首页**，看起来就像「授权屏根本没做」。实测确认过。要命令行打开就把地址直接交给浏览器本体：

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  "file://$PWD/design/skillmaster-首页演示.html?client_id=skillmaster-cli&state=abc123&scope=skills:read%20skills:write"
```

**在地址栏手动粘**这条地址是没问题的（不走 `open`），双击打开文件也没问题。

## 想改东西，去哪里改

只有一个文件要动：`skillmaster-首页演示.html`。它按区块写了注释，照着搜就能定位。**这张表只给区块名，不给行号**：行号每次改动都会漂，而这里原先那一整栏已经全对不上了——2026-10-15 的审计逐个核过（结论是这些行号当时已经全线对不上）：改文案那张表的**营销那八行整整偏了 279 行**（`<header class="nav"` 写着 783，实际 504），**浮层那九行偏了 72 行**（`id="loginForm"` 写着 959，实际 1031）；改交互那张表偏 71–91 行，另有两行（`background:rgba(253,252,250` 与 `.overlay.is-standalone`）偏了 228–231 行。**一个「平均」盖不住这种偏法**——一半偏 279、一半偏 72，平均下来哪个数都不是。（这一条原先写的是「平均差了 280 行、脚本那段差了 70–90 行」，而那时表已经被删了，读者无从复算。）**能搜的名字才是稳定标识符。**

⚠️ **改交互前先知道的三件事**：

1. **「手机号或密码不正确。」必须挂在表单顶部，不能挂到密码字段上。** 真实服务端对「没注册的号」「密码错」「账号停用」回的是同一句话，挂到字段上等于告诉别人这个号存在。

## 控制台演示

**登录之后的界面**——左侧导航、右侧内容。真实产品里这些页在 `skillmaster-web/`（Vue），这份演示件是照它做的设计稿，**不接任何接口**。

它有两个会话状态，由地址决定：

| 页 | 地址 | 是什么 |
|---|---|---|
| 我的 skill | `?page=skills` | 这个账号的 skill 列表：搜索、排序、分页，一栏一个 |
| 一个 skill | `?page=skill` | 版本、文件树（可进目录、可点文件）、正在读的文件 |
| 一个 skill › 设置 | `?page=skill&tab=settings` | 这个 skill 的设置：左边一列二级菜单，右边是选中的那一页 |
| 设置 | `?page=account` | 账号与命名空间 |
| **访问凭据** | `?page=keys` | API 密钥：四格计数即筛选、一个筛选片、一个壳 + 白底两层的列表盒子；新建与续期各有一屏 |
| **登录设备** | `?page=sessions` | 权限 › 登录设备：这个账号登录过的设备各一行（**完整地址**、客户端、登录于与最近活动），**当前设备没有退出的控件**；另有「仅当前设备」与加载失败两态 |
| **登录** | `?page=login` | 没登录时的样子：只有那张纸，控制台不在它下面 |
| **注册** | `?page=register` | 同上，落在注册第一步 |
| **找回密码** | `?page=reset` | 同上，落在找回密码第一步 |

**打开**：双击 `skillmaster-控制台演示.html` 落在「我的 skill」。去别的页点左侧导航，或直接在地址栏改 `?page=`。

### 我的 skill：搜索、排序、分页

一共 24 个 skill，**一页 10 个**，一栏一个。

**一屏十条，而且窗口越高、行越高。行高不是个定值**——这十条分掉页头与分页条之外剩下的高度：**1200px 高的窗口下行高约 96px、960px 下约 72px**（口径：1440 宽、本机 Chrome 实测）。**十条一屏的门槛是 929px：928px 及以下就装不下了**——900px 的窗口在这里退回普通文档（可以滚，底下不留一片空）。这个点在加上顶栏那一次从 **880px 挪到了 928px**，正好是顶栏自己的高度（48px）；`@media (max-height:928px)` 那个断点就是它。**（这一处 2026-10-15 改过：原先写 924px，而我当时没有量——量出来 928px 装不下、929px 装得下，断点也在 928。一个自己都没量过的数字被写进这里，是这一节最不该发生的事。）**

**分页条落在帧脚上，和侧栏的「退出登录」齐平。** 两栏各自的最后一行处在同一个高度，读起来像一条横贯整页的线。做法是让分页条固定在内容栏的脚上（`#page-skills` 的底部内缩 **16px**——不是 18：内容外面那张框上下各加了 1px 边，正好是分页条原先比侧栏那条线高出的两个像素。**侧栏那个「退出登录」已经不在了**，账号搬去了顶栏，所以这一处对齐的现在只是两栏自己的收底），中间那段落差由行高吃掉。`--row-max`（12vh）挡的只有「只剩一两条」的情况：一页十条永远到不了这个上限，所以分页条总能落到帧脚。窗口矮到十条都装不下时（**928px 及以下**）这一页退回普通文档的底部留白，否则分页条会被底部那条演示带压住。

检查脚本里守着这些的断言，名字就是它们的口径：「十条一屏放下，没被底部演示条压住」量 960px 下末行底与演示条顶之间还剩多少、「窗口高出来的部分进到行里，不是留在页脚」量 1200px 下行高确实长了**并且分页条下面的留白不超过 40px**（实测 27px——这个上限原先是 80，三倍于实际值，那种上限在它要防的那种失败里照样通过）、「导航栏与正文面板在同一个高度收底」量两个高度下各差多少（现在都是 0.0px）。**这里原先是第三条「分页条和侧栏的「退出登录」在同一条水平线上」——断言和它量的那个东西一起没了**：账号搬去了顶栏，侧栏不再有脚。

每栏**两行**：第一行是名字 + 「已上线 @版本」，右端是**调用次数**；第二行是说明，右端是**更新于**。日期原先独占一行，那是用一整行只说一件事；挪到说明的右端之后，两栏数字沿页面排成一条竖线，行高也少了三分之一。

- **搜索**同时搜名字和说明，边打边筛，不刷新页面。
- **三种排序**：最近更新（默认）、调用最多、名称。**没人调用过的沉到最后**，不该排在一张列表的头上。
- **结果装得下就不出现分页条**：只有一个「1」的控件是个没有作用的控件，而数量已经在标题旁边了。
- **整个演示件都不提「待上线」了**，连同它牵出来的五处一起（见下面的「已知的取舍」）。判据是：它是 draft 的**计数**，不是这个 skill 的**状态**。

三样都进地址，所以筛完的列表可以直接发给别人：

| 参数 | 意思 |
|---|---|
| `q=` | 搜索词，例如 `?page=skills&q=pdf` |
| `sort=` | `calls` / `name`，缺省是最近更新 |
| `p=` | 页码，从 1 开始；填越界会收在末页，不是空白页 |

⚠️ **这 24 条是演示数据**，而且**「调用次数」在产品里还产不出来**——见下面的「已知的取舍」。

### 一个 skill：照一张仓库页

**顶上三个带，和仓库页一样**：第一行是账号标记 + 名字 + 一个「私有」标（旁边还有一行说明）；第二行是**版本选择 + 版本数 + 这个 skill 的地址**（地址占了仓库页放 clone 按钮的那个位置，但它不是按钮。**这条理由后来被实测推翻了**——`file://` 页面在 Chrome 里剪贴板是够得到的，见「访问凭据：单独一页」那一节末尾的实测。做成死字现在只剩另一个理由：那行地址首先是给人**读**的，不只是给人拷的；要不要给它一个复制按钮是一次单独的决定，本次没有动它）；第三行是**这一页的分区**：`文件` / `版本` / `设置`——**`设置` 是全页唯一有第二级的一项**，点进去左边会多出一列菜单（见下面「设置：协作者与可见性」）。

**列表一次只列一层**：进到哪一层，就只看见那一层的东西。文件夹（带 `/`、带文件夹标记、没有大小）点进去是它自己那一层；文件点下去，下面的内容换成那一个文件。默认落点是根目录 + `SKILL.md`。

**一行三列**，和仓库页的文件表同形：名字（固定列宽，所以中间那一列在每一行都从同一个位置开始）／**「最后改它的版本 · 那天」**／大小。GitHub 中间那一列是每个文件最后一次提交的说明——产品里没有每个文件的提交记录，但能从两个版本的清单比出来「这个文件最后在哪个版本被改过」，那个版本的时间也是它自己的。文件夹的这一列同样有（是里面最新那次），大小那一列空着。

**两样东西各是一个带边框的表格块**，表头一行压在它的行上面；「版本」那一栏也是同一个盒子。这是全页唯一出现边框的地方（见「这一版有意做的决定」）。

| 在哪 | 地址 | 看到 |
|---|---|---|
| 文件 · 根目录 | `?page=skill` | `SKILL.md` / `references/` / `scripts/`，下面渲染 `SKILL.md` |
| 文件 · 某一层 | `?page=skill&path=references` | 只有 `split.md`；**还没点文件，下面就不给内容** |
| 文件 · 读一个文件 | `?page=skill&file=references/split.md` | 列表仍是 `references/` 那一层，下面换成 `split.md` |
| 版本 | `?page=skill&tab=versions` | 三个版本各一行：版本、线上/历史、说明、谁在什么时候提交 |
| 设置 › 协作者 | `?page=skill&tab=settings` | 被授权的人的名单 + 「共享给」那一行；**二级不写就落在这里** |
| 设置 › 可见性 | `?page=skill&tab=settings&sub=visibility` | 三选一；`&vis=public-invoke` / `public-browse` 是另外两档 |

**两个路径参数不会同时出现。** 一个文件的身世已经在它自己的路径里了，所以列表跟着文件走，不必再被告知一次——换来的是「下面那个文件必定在上面那张列表里」。地址里的目录不存在时落回根目录，不认识的分区落回「文件」，都不是空白页。

**标题那一行就是面包屑**：`dev / pdf-tools / references`。`pdf-tools` 是回根目录的链接——即使你已经在根目录，它也仍然是链接；一个「有时候是链接有时候不是」的面包屑比一个永远是的更难懂。往下还有几层时，每一段都回它自己那一层。

**版本这三件事只有一个出处。** 头上那个「3 个版本」、文件表表头那一行、以及「版本」那一栏的三行，都读同一份 `VERSIONS`——三个副本就是三次它们互相矛盾的机会。

五件刻意没做的事：

- ~~**表头行没有底色。**~~ **已改（2026-10-15）**：表头行现在有底色（`--wash`）。原先的理由是「边框已经把它框住了，再加一块底色是同一件事说两遍」，而那条理由属于「全页不填色」那一整套——**那一套已经退出控制台**（见「控制台换到了产品那一档」）。一条与它下面的行同色的表头不是表头；`console-states.mjs` 里那条断言也一并从「不靠底色」翻成了「靠底色」。
- **没有把「当前读的这个文件」做成蓝色或加个标记块。** 用的是字重——导航标「你在这里」的同一个做法。
- **没有做「..」那一行。** 面包屑已经说了你在哪、也已经能往上走，两件事不必两个控件。
- **没有做「在文件里找」那个搜索框。** GitHub 那一行有一个；这里三个文件不值得一个搜索框，而一个搜不出东西的控件比没有更糟。文件要是多起来，它应该是「在整棵树里找、点一下跳过去」。
- **没做右栏**（About / Releases / Contributors / Languages）。贡献者和语言构成在这个产品里没有对应的东西。

列表的标题（`文件（3）`）和内容块的标题都在标记里，只是 `visually-hidden`——去掉的是看得见的标签，不是结构。

不是 markdown 的文件（`scripts/compress.sh`）按**源码**读，不做渲染：等宽、小一号、没有底色，长行在块内横向滚动而不是把页面撑宽。

### 设置：协作者与可见性

**二级菜单照的是仓库设置页的形状**：上方横栏点进 `设置` 之后，左边多出一列——一个分栏标题（访问），下面两项（协作者 / 可见性），右边是选中的那一页。全页只有这一项有第二级。两个问题分成两屏，因为它们是两次不同的决定，而**一个地址只能是一屏**。

**两个问题，产品把它们分开，这一页也分开。** `visibility` 管的是「任何人」，授权管的是「某个人」——ADR 0034 §10 的原话是「被授权的 skill 仍然是 `private`」。所以在二级菜单里它们是并列的两项，不是一层套一层。

**二级也是地址**：`&sub=collaborators` / `&sub=visibility`，不写就落在第一项，认不出的也落回第一项——不是空白页。

**两项的链接都带着当下选的那一档。** 从「可见性」走到「协作者」再走回来，不会把刚选的档丢掉。这是二级菜单唯一真正的坑：静态链接会让 `&vis=` 在半路掉下去，而这一页的规矩是「地址就是全部状态」。检查脚本有一条断言守着它。

#### 一条梯子，六档

**这是这一页的核心，而且它只有一份。** 六档从低到高，**每一档都包含它下面的全部**：

| 档 | 能做什么 |
|---|---|
| **调用** | 能调用它，也能按路径点名取单个文件——但**看不到里面有哪些文件**（列不出目录），所以只有正文点名提到的那些够得到。**网页上看不到它**，只能用 agent |
| **浏览** | 上面全部，**加**：能看到整个仓库（列目录、一个个读过去）；网页上也能打开 |
| **写入** | 上面全部，**加**：提交新版本、丢弃自己的草稿 |
| **维护** | 上面全部，**加**：上线 / 回滚、改描述、丢弃别人的草稿 |
| **管理** | 上面全部，**加**：授权 / 撤销、改可见性、改名 |
| **所有者** | 上面全部，**加**：**删除这个 skill**。只有一个，就是创建它的人，**不授予任何人** |

**下面两档的来源是 `get` / `list`**——S3 的 `GetObject` / `ListBucket`、K8s RBAC 的 `get` / `list`、NTFS 的「遍历文件夹/执行文件」与「列出文件夹/读取数据」，都是同一条线：**能取你叫得出名字的，但发现不了有什么**。**中间三档是 GitHub 官方简中的原词**（对应它的 Write / Maintain / Admin，一个没改）。**「所有者」是我们加的**——GitHub 的 Admin 里含删除，我们把它拿了出来，单独一档。

#### 可见性只有两态

**公开即会被搜到。** 没有「公开但搜不到」这一档（这一条已经写成 [ADR 0037](../docs/decisions/0037-visibility-has-two-states.md)）。

**公开之后作者还要答一个问题：陌生人拿到梯子上的哪一档。** 于是三选一：

| 档 | 陌生人拿到什么 |
|---|---|
| 私有 | 什么也没有——只有你和被授权的人碰得到它 |
| 公开 · 调用 | 梯子的第一档 |
| 公开 · 浏览 | 梯子的前两档 |

**「公开 · 调用」当场写出代价。** 没有目录，就只有**正文点名提到过的**文件存在。这个 fixture 的正文一个文件名都没提，所以页面把三个文件列出来说清这件事（「它不止一个文件（`SKILL.md`、`references/split.md`、`scripts/compress.sh`），而正文一个文件名都没提」），而不是默默允许。

#### 每一行的档位是可以改的

**列表里的档位不是一行字，是一个控件。** 谁能往外授权（**所有者**与**管理**），谁就能把**任何一个人**往上或往下挪——包括不是自己加进来的那些人。页面在表单下面把这条写明了，因为这一页演的是所有者，光看是看不出区别的。

**往上挪之后，行上那句「公开之后不再需要」会自己消失。** 那句话说的是「你这一档公开已经盖住了」；人挪到盖不住的地方，这句话就不成立。检查脚本有一条断言守着它。

**GitHub 那种「你必须至少留一个管理员」的提醒，这里不需要。** 它的 Admin 是顶层，全被降完就没人管得动了；我们的顶上是**所有者**——他不在这个列表里、也不是授出来的，永远有人兜着。

#### 四处由梯子算出来，不是写死的

- **能授哪几档。** 只列**比公开那一档高**的——公开盖住的那些，授了等于没授。授到「管理」为止，**「所有者」不在可授的名单里**（页面在表单下面写明了这一点）。
- **每行控件里的选项。** 同上，只多一项：**它自己当前那一档**。控件得能说出真话——「公开之前授出去的浏览」正是这种情况，所以那一档留在选项里并选中着。
- **「不再需要」那行。** 已经授出去、而公开已经盖住的行，自己写「公开之后不再需要」——那行不删，因为「谁被邀请过」是一件事实。公开到「调用」时「浏览」那行不受影响，公开到「浏览」时才标出来。
- **表单上面那句话。** 「公开之后「调用」、「浏览」不用再授了」是从同一份梯子读出来的，不是另一句写死的文案——否则它会和右边那份列表漂开。

检查脚本对这几条各有一条断言。

**这两页里唯一不进地址的东西是被授权的人的名单。** 名单不是地址（谁都不是一个地址），所以「共享给」加一行、以及改某一行的档位，都是当场生效、刷新即失；可见性、分区、二级分栏、路径、文件全都在地址里。

### 访问凭据：单独一页

**左栏「权限」下唯一的一项**（不在「账号」下面——「账号」是它旁边那个平级项），不再挂在「设置」里当一个 block。这是参照产品的排法：**「你是谁」与「谁能以你的名义做事」是两个问题**，而一串凭据放进设置页里，读起来就像它是众多设置中的一项。

**借的是它那一页的信息架构，也借了它的卡片配方。** 从上到下：一句说明 → 四格计数 → 一个筛选片 → 一个**壳 + 白底两层**的盒子。

- **四格计数**（活跃 / 两周内到期 / 已撤销 / 已过期），**每一格都是一次筛选**，而且**数的是你正在看的那张列表**——搜索也算：四格的链接带着搜索走（`filterAddress` 读的是地址），所以一个写着「3」的格子点进去只看到 1 行，是计数和自己的去处打架。（2026-10-15 改：原先按全部密钥数，与它自己那条「计数为 0 点进去就是 0」的承诺相反。）它们**就是四张卡片**：外一层 `--wash` 的壳，里一层白底，圆角比壳小一档——那是照参照产品自己的 `card.scss` 读出来的配方，也正是这一页读起来「做完了」的原因。**（2026-10-15 改：原先写的是「不是四张卡片……这一版不画面」。控制台已经换到产品那一档调色板，那句话早就不成立了，而且和下面「有了面——统计是四个盒子」那一条自相矛盾；同一份文档里两句话打架，读的人只能猜哪句是真的。）**每格右下那句「筛选列表」是**常驻**的。（早先这里写的是「只在指针停上去时出现」，措辞是「只看这些」；句子改过词、实现也一直是常驻，而这一句没跟着回来。**把可点的东西做成只有指针停上去才说明它可点，键盘和触屏的人就得自己猜**，所以现在按实现记：常驻。）
- **筛选在地址里**（`?page=keys&filter=revoked`），所以筛完可以整段发给别人。**默认是「活跃」**——凭据列表多数时候是用来回答「现在什么在工作」的，死掉的那几把该在一击之外，而不是杵在路中间。筛选片自带一个 ×，因为**取掉一个筛选比在两个之间换更常发生**。
- **列表那一个盒子是全站第二处允许画框的地方**（它画的是**面**，不是边框：外一层 `--wash` 的壳 + 里一层白底，只有表头那一行带一条 `border-bottom`；skill 页那张文件表才是真带 1px 边框的那种），和 skill 页的文件列表同一个理由：那是「仓库页的形状本身」。表头一行压在行上面，表头**五格**与行内**五格共用一个 grid 模板**（名称 / 说明 / 权限 / 状态 / 操作；两份就是两份要同步的东西，而它出错的样子是表头悄悄偏几像素，没人看得出来，直到截图看得出来）。**表头与它自己的数据对齐**：状态与操作这两列右对齐，表头也右对齐。**这一处原先自己对不上**（2026-10-15 审计核到）：规则是按**位置**写的 `nth-child(3)`／`nth-child(4)`——那是这张表还只有四列时写的——于是权限得到一个右对齐的表头、压在一个左对齐的格子上，操作反过来。表头行与数据行各自自洽、彼此不一致，正是这段话在防的那种失败。
- **空的有三种，句子各不相同**：账号一把都没有（「暂无密钥。CLI 与 agent 通过密钥访问你的 skill，无需在浏览器中登录。」）、这一类里一把都没有（「该状态下暂无密钥。」）、以及**搜索一个都没匹配上**（「没有名称包含「…」的密钥。」）——后两句都不解释凭据是什么，因为读的人已经知道。**第三句判的是「搜索匹配到几个」，不是「搜索框里有没有字」**（2026-10-15 改）：在活跃那一档里搜「机器」，原来会说「没有名称包含「机器」的密钥」，而它上面那格计数正数着这个名字里带「机器」的密钥——一句话和一个数在争同一件事。**（原先这里写「两种」，引的是「这一类里一把都没有」那句——那是标记里的默认文案，`renderKeys` 一渲染就把它换掉了，所以它从来没在屏幕上出现过。）**

#### 三种状态，只有一种要你动手

**活跃的什么都不显示**（大多数行是活跃的，给它们一个标记就是噪音）。说话的是另外三种，而**它们的轻重不一样**：

| 状态 | 画法 | 为什么 |
|---|---|---|
| 已撤销 | 危险色底 + 危险色字 | 有人刻意结束过它 |
| 已过期 | 灰底 + 灰字 | 它已经死了，是信息不是任务 |
| **两周内到期** | 灰底 + **正文墨色** | **三者里只有它要你去做一件事** |

**为什么「两周内到期」不用黄色。** 我们的调色板里没有警告色（只有危险与成功），而这一版不允许凭空发明颜色。所以往上抬一档的手段只能用页面自己的墨色——比灰色响，仍比那个真正该红的东西安静。这是这一页唯一一处「受调色板限制」的设计决定，值得记下来：**如果将来加了警告色，这一格该换成它。**

**阈值只有一个数，14 天**，落在 `SOON_DAYS` 上，计数与行标记读的是同一个常量。参照产品在这件事上自己不一致（行徽章 14 天、统计卡 15 天，调研核到，不是有意为之）——**同一个事实写了两遍**，我们不重复那个错。

**「已于 X 撤销」而不是它的到期日。** 这一处我们有参照产品没有的东西：它的撤销是一个布尔，模型注释承认唯一的时间痕迹是 `updated_at`；而我们的表里有一列 `revoked_at`（[ADR 0038](../docs/decisions/0038-default-credential-is-an-api-key.md) 决定 2）。**日期是设计画得出来的，前提是表里有那一列。**

**两件不可撤销的事，用同一个形状先问后果，不先问「确定吗」。** 问句落在**那一行自己身上**（状态格换成后果，操作格换成两个答案），焦点落在「确认」上；**Esc 回答「取消」**，「取消」之后焦点回到你刚才按的那个按钮上——原先取消一次，焦点掉到 `<body>`，读屏和键盘的人得自己重新找路。点「撤销」之后，那一行的**状态格**换成一句后果——「撤销后，使用该密钥的客户端将立即失去访问权限」——操作格换成「确认撤销 / 取消」；**「续期」现在问的是同一套**（「续期后，这把密钥立即失效，换上一把新的」），因为它是两者里更该被拦住的那个：新串出现的那一刻旧串已经死了。**原先只有撤销问，而那没有理由**——两个动作在同一个处理器里，只差一行。**不新开一个对话框**：一个页面整页都是发丝线，弹出一个填色的盒子会是上面唯一一块填色。**已经撤销的那一把也不能续期**：撤销过的东西没有可延续的，这既是参照产品的规矩（它的 `RotateService` 第一句就是「Token already revoked」），也是对的——从一把已经交出去的凭据里再铸一把活的，是它不该有的第二次机会。**过期的那一把反过来：必须续得动。**

#### 续期真的把那一把续上了

**续期换的是有效期，不只是整串。** 新签出来的是一把全新的凭据，所以它拿到的是**签发的默认有效期**（演示件里 90 天，`EXPIRY_DAYS` 写一次，表单的预选值和它读的是同一个常量），而不是继承旧的那个日期；日期从**列表自己的「今天」**（`KEYS_AS_OF`）算，所以它进了地址之后，明天打开还是同一天，发给别人的链接也一样。**表单预选的那个日期跟着这个值**——取「按真实日历算的 90 天」与「列表那个 90 天」里靠后的一个：两者今天相同，等演示件那个日子过去之后才跟着日历走，而那也正是表单不会一打开就是一个过期日期的原因。（原先两处各算各的：明天打开，表单写 2027-01-14、而续期与演示条写 2027/01/13——一个说「只有一个 90 天」的设计，屏幕上有两个。）参照产品的 `rotate` 也是重新给新令牌定日期（按实例的有效期策略；它另有一个「保持原有效期」的开关，我们的界面没有那个开关，所以不实现）。

**这一处原先是个死结，而且是产品文档自己指的那个死结。** 列表在**已过期**的那一行上照样给「续期」，点完、确认完、复制完，回到列表——那一行还是 `已过期`，日期一个字符都没变，「最后使用」也照旧。而 PRD 让终端在 key 过期时说清是「过期」并**指向控制台续期**（[`prd.md`](../docs/versions/v2-credentials/prd.md) §验收 1、§范围 第 5 条），所以那条指向在演示件里是个死胡同：**除了续期，这一页没有任何地方能改一个有效期**。现在续期把那一行的到期日换成新的、把「最后使用」清成「从未使用」——那正是这次续期改掉的两件事，而那一刻的卡片也会说出来（「权限 可读 · 到期 2027/01/13」）。

**「那一行换了个日期」是演示件的取景，不是数据模型（2026-10-15 核过参照产品源码之后的定论）。** 上面那句说的是这一屏画出来的样子：演示件把续期建模成**同一行**换到期日、清使用记录，因为这一页要回答的是「我点的那一行现在怎么样了」。而真的数据模型是**旧的作废 + 发一把新的——两条记录**：`references/gitlab/app/services/personal_access_tokens/rotate_service.rb` 里就是 `token.revoke!` 之后 `create_access_token`，新记录带着 `previous_personal_access_token_id: token.id`（我们这边是审计事件里的 `replaced: <旧 id>`，[`technical-design.md`](../docs/versions/v2-credentials/technical-design.md) §接口写的是「作废旧的、按同一名字、说明与 scope 发一把新的」）。它那边看起来像「同一行被刷新」，靠的是列表**默认落在 `state = ACTIVE`**（`personal_access_tokens/constants.js` 的 `DEFAULT_FILTER`）——续期出来的同名新记录就在这一栏里，被撤的那条落在「已撤销」那一格，而它那四张计数卡与我们这四格正是同一个东西。**所以产品那边续期后落「全部」（= 这一屏自己的出口规则），新旧两条并排可见；这是事实，不是缺陷。** 留旧那条还有用：一把被换掉的旧串再出现时，服务端认得出它并记一条 `api_key_revoked_reuse`（[ADR 0039](../docs/decisions/0039-api-key-defaults-and-their-edges.md) §决定 4 买回的两条审计信号之一）——那是最常见的「某台机器还攥着旧 key」的发现方式；就地刷新会把旧哈希覆盖掉，这条信号对续期掉的旧串就永远查不到了。**若哪天想让读者落回「活跃」那一栏（像它那样只看一行），那是出口地址一处的事，模型不用动。**

**续期进地址（`&rotated=<id>`，可以重复），所以熬得过刷新**，和撤销一个道理。一屏上有好几条 `rotated` 时，**最后一条**是这一屏在说的那次——续期是追加进去的，先后顺序就在地址里。

#### 新建之后的这一把，在列表里是真的

**表单问的四件事都进了地址**（`made-id` / `made-name` / `made-scope` / `made-expires` / `made-note`）。于是：创建那一屏说得清它是什么——**「密钥详情」这四个字原先是一句空话，那一屏从不提权限、也从不提到期日**；离开那一屏之后它**真的以一行出现在列表里**，刷新还在，发给别人的链接也还在。**这一处原先是自相矛盾的**：提交只把名字带进地址，于是刚说完「密钥已创建」，下一屏搜这个名字答「没有名称包含它的密钥」。

**`list` 只在两屏「那一刻」上活着。** 它是「这一屏是从哪一份 fixture 进来的」那一小段记忆（`list=empty`）——两屏都离开它，所以**两屏都记着它**（2026-10-15 改：原先只有新建记，于是「暂无密钥」里签一把、再续期它，完成之后落回五把那个账号上——读的人中途换了个账号）。取消与完成都把它丢掉，演示条也不带着它走，所以 `?page=keys&list=empty` 不再是 `?page=keys` 的第二个地址。（那两份 fixture 里都含着刚建的那把，所以回到 `state=empty` 看到的是「1 个密钥」——不是空。）

**面包屑和这个按钮去同一处。** 那一屏的面包屑（「API 密钥」）是**这一屏的父亲**，不是「去别处」，所以它必须带上这一屏手里的事实——它原先是一个写死的 `href="?page=keys"`，于是刚说完「已创建」、点一下面包屑，那把密钥就没了（`made-*` 是它唯一的存放处）；续期那一屏更明显：点面包屑，刚刚报过的续期被悄悄撤回。（2026-10-15 改：现在两屏的面包屑与各自的出口算的是同一个地址，表单那一屏与「取消」算的也是同一个。）

**离开那一屏时，筛选与搜索被放下，而且是用 `filter=all` 放下的——这是全页唯一一处会放下它们的地方。** 别的链接都带着列表自己的状态走（统计卡、筛选片的 ×、取消），因为那两件事说的是同一张列表；而这一刻手里多了一个**新事实**，一个被筛选挡在外面的新事实是读者核对不了的：从「已撤销」里建一把密钥，回去的列表只有一行，不是你的那一行。参照产品的这一屏，`Done` 也是回到没有筛选的列表。**表单问的四件事本身不在这里丢**——它们留在地址里，所以刷新、发给别人，那一行都还在。

**为什么是 `all`，而不是把 `filter` 删掉。** 因为在这一页上**「没写」就是「活跃」**——默认不写进地址是这里的规矩，所以删掉 `filter` 等于选了活跃。而表单允许把日期填成今天（`min` 就是今天），一把今天到期的密钥是**两周内到期**：那一刻刚说完「已创建」，落到的列表上却没有它。`all` 是唯一能说「不筛」的写法。

**一行的身份是 id，不是名字。** 名字是人自己起的标签，**允许重名**：参照产品的模型只校验名字非空（`validates :name, :scopes, presence: true`），它的撤销与续期路由收的是 id（`POST /personal_access_tokens/:id/rotate`），我们的契约也是（`POST /web/keys/{id}/rotate`，见 [`technical-design.md`](../docs/versions/v2-credentials/technical-design.md) §接口）。所以地址里三处行身份都是 id：新建带 `made-id`（演示件在提交那一刻铸一个，像服务端会做的那样），撤销是 `&revoked=<id>`，续期是 `&rotated=<id>`。**这一处原先按名字找行**：两把同名时，撤销作用在名字相同的**第一行**上——也就是你刚建的那一把，而不是你点的那一行，而且地址把同一次错原样发给了别人。`name` 参数因此整个去掉了：一屏说的是哪一把，现在由事实本身说了算。

**撤销与续期都进地址**（各自可以重复，因为这是这一页上会不止发生一次的两件事）。撤销原先只是一个内存标记：行离开列表、计数跟着动，而刷新——或者你发出去的那个链接——会把它悄悄放回来。**创建那一把是同一个道理的反面**：它进地址，所以它熬得过刷新。

#### 那一刻：整串只出现一次

**创建与续期走同一个形态**，因为它们是同一件事：一个只存在一次的字符串。**整块换形**（连列表一起），不是在列表里插一行——它不是关于某个物件的通知，它**就是**那个物件。

**出口只有一个，而它在复制之前是禁用的。** 按钮上写的是它自己的前提（「复制后方可完成」），而不是一个不解释为什么灰掉的「完成」。那一刻这一屏**自己没有第二个出口**：没有叉，也没有遮罩可点（它是一个页面，不是一个浮层）。参照产品这一屏同样如此——它的 `Done` 绑在 `copied` 上，**这一条是照它的组件核过的，不是照图猜的**。**但控制台的外壳照常活着**：导航、品牌、顶栏那个搜索框、底下那条演示带都点得动——真实产品里也一样，那一屏是一条独立路由。**这里原先写着「唯一的另一条路是关掉标签页」，那是错的**（2026-10-15 审计实测：那一刻页面上可点的东西一应俱全）。**那一刻之所以还读得出「不能走」，靠的是那个禁用按钮在说自己的前提，不是靠锁死整页**——锁死整页是参照产品没有的发明，而且会挡住「我先把串存到别处」这条正路。

**离开是自由的，只是不再安静（2026-10-15 改，产品侧同一轮跟进）。** 整页能点走、点走就丢整串，这是审计当场量出来的事实，而当时它没有任何提示：一个读者从侧栏离开，丢掉的东西连一句话都没有。现在**这一页上任何会导航的东西都先问一次**——面包屑、导航、品牌、顶栏搜索、退出登录，以及底下那条演示条（它是链接，也一样会把整串带走）；**问句落在那块本来就是出口的地方**（`.key-exit`，此刻站着一个禁用的「复制后方可完成」），形状与撤销/续期同一套：先说后果（「这把密钥还没复制——离开后取不回来，只能撤销后重建。」），两个答案各自说自己去哪（「仍然离开」／「留在这一屏」，这里**不写「取消」**——取消是撤销一件事，而这里是一个可以待着的地方），**Esc 回答「留在这一屏」**，焦点落在「仍然离开」上；回答留下，出口那块与整串都还在。**「仍然离开」不是另写一遍那个动作，而是把读者刚按的那个控件再按一次**——一个事实一个写者，退出登录的地址与搜索表单自己的规矩都不在这里抄第二遍。**问题挂着时再按另一个出口，也不会被放行**（2026-10-15 改）：原先这个守卫在问题已经挂着时直接返回——于是读者按了第二个出口（面包屑、导航、顶栏搜索），它就那么走了，整串跟着走，而问题一次都没被回答。现在第二个出口也被拦住，问题**移到它身上**：答「仍然离开」走的是最后按的那一个，也正是读者的本意；重新问一次是**换掉**问题而不是再叠一份（一个块里四颗按钮，重放按的是先来的那颗）。产品与交付件同一条，`console-states.mjs` 两条断言钉住。

**仍然不做的两件事**：锁死整页（那是参照产品没有的发明，而且会挡住「先把串存到别处」）；**浏览器自己的刷新、后退、关标签页不在拦截范围内**——那一类离开这一页看不见，而原生框说不出丢的是什么，所以这一页不用它，卡片上「如未保存：请撤销该密钥后重新创建，或对原密钥直接续期」正是为它写的。

**这一屏的形态也是参照产品自己的**（同样照它的组件读出来）：标题说的是**结果**（「密钥已创建」／「密钥已续期」），面包屑说的是**你从哪条路来**（「新建 API 密钥」／「续期密钥」）——它那屏正是这一对分工；下面一张带栏头「密钥详情」的卡，卡里一行警告加上那个字符串；**出口在卡片外面**，跟它的 `Done` 一样。整串默认**掩掉**，用的是它自己的属性 `-webkit-text-security: disc`——字符都还在，只是字形换成圆点，所以掩着复制拿到的仍是整串。（它那边反过来要特判：密码框被选中复制拿到的是圆点。）

**复制之后主色交棒。** 复制按钮原本戴着主色——那一刻它是这一屏唯一要做的事——按下去换成勾、把主色让出去，`完成` 才成为唯一的填色按钮。**（2026-10-15 修：勾一直没出现过。`hidden` 是 HTML 元素的属性，`<svg>` 不是——`svg.hidden = true` 只是给对象挂了个自造字段，属性没变、样式表也就没反应，于是这只眼睛和这个勾都停在标记画下的那一刻。同一个缺陷在共享浮层的密码眼睛上，而它服务两份演示。现在图标一律走属性，检查脚本里加了**三条**断言量这件事（登录那把眼睛、那一刻那把眼睛、那一刻的复制勾）：`display` 从 `block` 换成 `none`，也就是「图标是那个说出来的东西」这句设计说明能不能成立的地方。）**两个填色按钮并排时每一个都在声称自己是你要找的那个，而这一页的规矩是**只有一个**——所以灰掉的出口也**不画成淡掉的主按钮**，而画成它将要停止是的那个静默按钮。

**刷新之后整串不再出现，而且这一屏会自己说出来。** 这一屏拿着的不是一把密钥的**记录**，是创建那一刻的**响应**——整串只存在于那个响应里（服务端只存 sha256）。演示件没有响应可留，只能把它建模成一个地址，于是多出一件产品里没有的事：**那个地址是可以刷新的**。

`performance` 的导航类型把这两件事分开：**抵达**是 `navigate`，**刷新**是 `reload`，**后退进来**是 `back_forward`。所以整串熬得过抵达（从表单、从演示条、从粘来的地址），**熬不过刷新**——真实产品上按一下刷新会看到的一样：串已经不在了，而页面应该说清楚，不该印一把新的出来。**修之前它正是印了一把新的**：每次加载都跑 `newSecret()`，刷新后是另一个串，而上面那句还写着「仅此时显示一次」。演示件可以编一把凭据，不能编第二把。

刷新后那一屏：句子换成「整串已经不在这里了…」，字段整块收掉，出口不再是「复制后方可完成」——复制这个前提不成立了，所以它就是一个可以直接走的「完成」。演示条上的「已创建」「已续期」照旧显示整串（那是一次抵达），所以要看那一刻的样子还是走演示条。

**续期那次比新建那次更该被拦住，而参照产品在这里是反的**（照它的组件核过：创建那屏的 `Done` 绑在 `copied` 上；续期那屏是一张**可以随手关掉的 alert**，根本没有出口）。那个不对称多半是结构上的方便——创建有独立路由，续期发生在列表页上——但**续期丢了的代价更大**：旧的那把已经撤了，丢的是这份凭据本身。所以两次都不让走。

#### 复制这件事实测过，旧记录是错的

`README.md` 的「一个 skill」那一节原先记着「本地打开的 HTML 够不到剪贴板」，那一页的地址因此被做成死字而不是按钮。

**2026-10-15 实测推翻了它**：`file://` 页面在 Chrome 里是 secure context（`window.isSecureContext === true`），`navigator.clipboard.writeText()` 会 resolve，**而且整串真的进了系统剪贴板**——用一个随机值前后比对 `pbpaste` 确认。

**所以这一页的复制是一个真按钮。** 代码里另留两条退路：先试 `document.execCommand('copy')`（参照产品自己那个复制按钮用的也是它，从一个用户手势里它在异步剪贴板够不到的地方照样工作），再不行才退到**选中**整串、让人按自己的复制键。**退到选中那一步时这个按钮不再说「已复制」**——它说「已选中，请按你的复制快捷键」。（这一处 2026-10-15 改过：原先选完就照跑复制成功那套状态，勾也打上、`aria-label` 也写「已复制」，而剪贴板一个字节都没动。把演示件架在一个明文 http 地址上发出去，`navigator.clipboard` 就是 undefined，于是这条假话是**默认**会发生的那条。门在三种情况下都还有意义——整串在被拿走之前都出不去——但**门不能靠谎报自己的名字来关**。）

### 登录设备：与密钥同类的一屏

**位置**：左栏 `权限` 下的第二项，与 `API 密钥` 平级——**不是** `账号` 下面。这条排法是照参照产品读出来的：它设置里的 **`Access` 组**装的正是 SSH 密钥、personal access tokens 与 **Active sessions**（`lib/sidebars/user_settings/menus/access_menu.rb`），也就是「**能以你的名义做事的东西**」，与我们自己「你是谁 / 谁能以你的名义做事」那条分组理由给出同一个答案。**一个登录会话正是一种以你的名义做事的东西**，所以它和一把密钥同类：一个你**踢**得掉，一个你**撤**得掉。

**一行竖着堆三段**，不是排成五列——参照产品那一屏也不是表格（它是一个 `list-group`，没有表头），而且这三段读起来是「从哪儿来 / 是什么 / 什么时候」，不是可以横向比较的字段：

| 段 | 内容 | 口径 |
|---|---|---|
| 一 | **完整地址** | 参照产品也完整显示、不打码。它是判「这台是不是我」唯一有效的一条——**所以它必须在被踢掉时随之删除**（会话属性随会话行级联删，见版本 TD §数据模型） |
| 二 | 客户端 | 粗解析成 `Chrome · macOS` 一类。**不画设备类型图标**：那是要有解析库才准的东西（参照产品用 `device_detector` 才画得出手机/平板/电脑/车），而**画错比不画更糟** |
| 三 | 登录于 + 最近活动 | 两个时间分开说：一个回答「什么时候登进来的」，一个回答「它还在用吗」 |

**当前设备：一行「当前设备」的标记，而且没有退出的控件**（照参照产品——那个按钮会结束正在读这一页的人自己的会话）。所以它在那一行里是**被拿掉**，不是置灰。

**两个动作共用撤销/续期那套「先问后果」**（`askBefore`，一处写者）：后果落在**那一行自己的格子**里，两个答案接在它的动作格上，Esc 答「取消」，取消之后**焦点回到按下的那个按钮**。**不弹对话框**：参照产品这里是一个 modal（文案是 *"Are you sure? The device will be signed out of GitLab and all remember me tokens revoked."*），而我们的设计稿明确不新开对话框（整页发丝线，一块填色的盒子会是页面上唯一一块填色）。

- **退出该设备**：「退出后，该设备需要重新登录；当前设备不受影响。」
- **退出其他所有设备**：「退出后，其他 N 台设备都需要重新登录；当前设备不受影响。」→ 确认之后只剩当前这一台，**那个按钮自己也消失**（没有可退出的了）。
  **这一条参照产品的界面上没有**：它的 `destroy_all_but_current` 只被 2FA 与 Passkey 的注册流程调用，从没接在这一页上。我们加它，因为它是「我在别人的电脑上登录过」**唯一能一次解决**的按钮。

**用词是「退出」，不是「踢掉」**（2026-10-16 改，依据 [`voice-spec.md`](voice-spec.md)）：参照产品的动词是 *Revoke*，而它的禁用类别里正好有一条「**隐喻 / 暴力动词**」（`kill the process` → `stop`、`bulletproof` → `reliable`）。「踢掉」正属于那一条——**它用一个不存在的动作去描述一个存在的动作**，而这个动作的真实语义（那台设备上的登录结束）正好有一个现成的字面词。**隐喻词更生动，但它要求读者先做一次翻译**，而界面上的每一次翻译都是一次可能的误解。（「登出」同理不用：它是「退出登录」的生造简写，而后者已经是现成的。）

**不分页，也不设上限。** 行数由会话自己的两把尺子限住（被遗忘的机器最多活 24 小时，常用的浏览器只占一行），所以真实长度是「几个」。参照产品存 100 条、超出时**静默丢掉最旧的**（`ALLOWED_NUMBER_OF_ACTIVE_SESSIONS` + `clean_up_old_sessions`）——我们不需要那个上限，也就不需要那次静默丢弃。

**计数是名词短语，空态那句只说计数没说的那半**（2026-10-16 改，依据 [`voice-spec.md`](voice-spec.md) §四）：计数从句子（「共 3 台，其中 2 台可以踢掉」/「只有这一台设备登录着」）改成 **「3 台设备」／「仅当前设备」**——与密钥那一页的「5 个密钥（活跃）」同一个句式。列表那一行原先写「只有这一台。你在别处登录过的设备会出现在这里。」，把计数刚说过的那半又说了一遍：**同一件事说两遍**，读的人还得先判断这两句是不是在说同一件事。现在它只说真正提供的信息——**在别处登录过的设备会出现在这里**。**这一条是看图看出来的**，不是跑断言跑出来的。

**读不到时是一句话，而且只关于这个列表**：「无法加载登录设备列表，请稍后重试。此处仅表示列表加载失败，不代表账号异常。」——与密钥那一页同一个句式、同一个理由：**怕的人怕的是账号出事**，所以当场说清不是。

**列表里不出现会话 id**：一行按夹具 id（`s1`…）寻址，而这一页上没有任何形如会话 id 的长串——`console-states.mjs` 里有一条断言专门量这件事。

### 登录与退出登录

**退出登录**在**右上角**（头像那一行，和参照产品同一处；它原先在左下角）。点头像 → 菜单里点「退出登录」，是两下 → 会话结束 → 落在登录屏。**登录屏没有关闭按钮，Esc 和点遮罩都关不掉**：没登录的控制台底下没有东西，关掉它就是关到一片空白。

登录、注册、找回密码三套流程**与首页演示是同一份代码**（见下面的「共享片段」），连文案与校验规则都一个字不差——注册两步、找回密码三步、图形验证码只属于发码那一步、六格验证码是一个真 `<input>`。

- **登录成功 / 注册成功** → 回到 `?page=skills`（真实产品里注册即建会话）。
- **找回密码成功** → **不自动登录**，成功页写的是「这个账号在所有设备上的登录都已经失效」。

### 怎么看到那些点不出来的状态

没有后端，所以**加载中 / 空 / 出错这些状态点不出来**——什么都不会真的失败。它们被放在**底部那条虚线**上（那是演示开关，不是设计的一部分）：

| 页 | 能切的状态 |
|---|---|
| 我的 skill | 正常 · 空 · 加载中 · 出错 |
| 一个 skill | 正常 · 没有这个 skill |
| 设置 | 正常 · 没登录 · 状态读不到 |
| 访问凭据 | 正常 · 新建表单 · 暂无密钥 · 已创建 · 已续期 · 加载失败 |

切一次地址栏就跟着变（`?page=skills&state=empty`），所以每个状态都能单独发给别人看。

**这条带进表单时也记着它是从哪一份 fixture 进来的**（`list`），和「新建密钥」那个按钮记的是同一件事——否则「暂无密钥」→ 演示条「新建表单」→ 取消会落到五把那个账号上。（`list` 不进 `PAGE_PARAMS`，是因为它一旦跟着走，`?page=keys&list=empty` 就成了 `?page=keys` 的第二个地址；所以它只在「进表单」这一个目的地上追加。）

**两个「那一刻」也在这条带上，而它们各自带着一把密钥。** 「已创建」带的是演示件自己的那把（`made-id=k6`、名字「演示密钥」），「已续期」续的是 `k2`（家里那台，离到期最近的那把）。**不带就落回「正常」**：一个没有密钥可说的「密钥已创建」是一屏在宣布一件没发生的事，所以 `?page=keys&state=created` 这种光秃秃的地址现在走的是全文件通用的那条规矩——认不出来的状态落回默认屏。带上之后这两个状态是**真的**：点「完成」落到的列表里，那一行确实在。

（地址里已经有 `made-*` 或 `rotated` 时，这条带不覆盖它们——你正看着自己刚建的那把，点「已创建」看到的还是你自己那把。）

### 这一版有意做的几个决定

- ~~**用栏宽和发丝线分区，而不是卡片。**~~ **已改（2026-10-15）**：这一条是控制台第一版的话，而它早就不是真的了——见下面「有了面」那一条（四个统计盒、带底色的表头、圆角卡片）。**同一节里留着一条已经被推翻的话，比不写更糟**：读者会以为两句话里有一句是排版错误。
- **标题、数量、搜索、排序在同一带上，一条发丝线收口。** 它们本来就是一页的同一件事：这是什么、有多少、怎么缩小范围。原先搜索框独占一带、上下各一条线，那 60px 里只夹着一个输入框——而这一页要放下十条。省下的高度还给了行距。
- ~~**页面上没有任何一块填色的区域——表格的表头也没有。**~~ **已改（2026-10-15）**：控制台换到了产品那一档调色板，于是**有了面**——内容列是白的、统计是四个盒子、表头有底色、卡片有圆角与极轻的影。这条原先是这一版最硬的一条，也是让它读起来「没做完」的那一条。**强调色仍然只有一个**，那条没变。
- **导航当前项不靠颜色单独表示**：字重和图标颜色两个信号一起变。**而「当前」在栏里只能有一处出声**：在「权限」下面那几页（API 密钥）二级项本身是收起的、根本不在屏幕上，所以出声的是**那个可展开项的标签**（走墨色）加上它的 `aria-current`。**这一处修过**：原先两个 `aria-current` 都打在隐藏的副本上，屏幕上唯一的信号是那点颜色，而它是三者里唯一一个屏幕阅读器听不到的。
- **skill 的名字不是蓝的**（悬停才变），因为一屏十个蓝名字会把层级让光。
- **说明句占满内容栏，右边缘落在它下面那张卡片的边上（2026-10-16 改）。** 原先 `.page-note` 上有一条 `max-width:74ch`——14px 字号下是 **652.56px**——而它上下的东西（页头那条发丝线、下面那张卡片）都是整个内容栏，1440px 窗口下实测 **1080px**。于是说明句在**卡片的六成处**就断了行：左边缘对齐、右边缘凭空收回来。**这条上限在本文档里从来没有记载过**，只有 CSS 那一行写着它。去掉之后，控制台仅有的两句说明句都收进**一行**（登录设备 715px、API 密钥 675px），**「断在哪」这个问题在这两句上直接消失了**。窄屏下它仍然会换行，换行位置也就是卡片的右边缘。
- **换行规则是 `text-wrap: balance`，不是 `pretty`（2026-10-16 改）。** 这一条与上一条是同一轮量出来的：`pretty` 承诺「最后一行不只剩一个孤字」，而在中文上它没有兑现——两页的说明句留着碎片，行宽 644/72 与 632/43。`balance` 改的是**断点**：358/358 与 332/343，行数不变、碎片不见。**它只在多行块上起作用**，单行的说明句它什么都不做——去掉上面那条上限之后，大多数页面正是一行，所以它只在窄屏上生效。两者都不阻止**两个汉字之间的断行**：那是这门语言在工作，不是排版失败。

## 共享片段：登录浮层

**登录、注册、找回密码、授权请求这一整套浮层，两份演示共用一份代码。**

它在 `partials/auth-overlay.html`，是一段**片段**而不是完整 HTML：三段依次是 `<style>`、浮层标记、`<script>`。构建时 `build-demo.mjs` 把源稿里那句 `@partial auth-overlay` 整段换成它——所以两份交付件里的浮层**永远是同一份**，改一处两份一起变。

片段与宿主之间只有两条约定：

- **宿主提供一组 CSS 自定义属性**（调色板、字号栈、圆角、缓动）。片段不发明颜色，清单写在片段开头。
- **宿主通过 `window.SkillMasterAuth` 驱动它**：`open(view, options)`（`dismissible` / `standalone` / `trigger`）、`close()`、`isOpen()`、`currentView()`、`openConsent()`，加上宿主赋值的两个回调——`onSignedIn`（有人登录或注册成功了）和 `onView`（对话框现在显示哪一屏）。

片段的样式**全部限定在 `.dialog` 内**，所以它落进一个自己有 `.field`、`.hint`、`.facts` 的页面也不会互相干扰——控制台正是这样一个页面。

**浮层里的提示按容器宽度摆匀，不留孤尾**（`.dialog .hint` 上的 `text-wrap:balance`，2026-10-16 加）。这一条与控制台的 `.page-note` 是同一条规矩，起因也是同一件事：一句两行的提示若在离边缘 40px 处断行，读起来像失误。授权屏自己那两句是最差的两个——「读取你能看到的 skill…」第二行只剩 **86px**，边界那句只剩 **40px**（「动作。」三个字），加了之后分别是 [193,186] 与 [169,186]。

**量法写在这里，因为我自己先量错过一次**：数行要**按块高 ÷ 行高**，不能按 `rect.top` 分组——一行里有行内 `<code>` 时，`getClientRects()` 会给出两个 top 差 1px 的矩形，按 top 取整分组就会**把一行数成两行**，我因此误报过一次「5 行变 6 行」。按高度重量：九处多行提示，八处变匀，**没有一处行数变化、高度一律不变**。产品的同一条规则在 `skillmaster-web/src/styles.css` 的 `.hint, .muted` 上（那边同一句文案常常是 `.muted`），按产品自己的宽度重量过：3 行 → 3 行、2 行 → 2 行，都不变。

**要改浮层，改片段**，然后两份都重新构建。

- **共享浮层**（登录 / 注册 / 找回密码 / 授权请求）→ `partials/auth-overlay.html`，改完**两份演示都变**；

⚠️ **改一页就跑那一页，别整套跑。** 整套是给「方向定稿」和「要交给别人」用的——它有 **197 条**、开有头浏览器、走完二十二个状态与七个分组。**成文的耗时口径**：197 条那次本机实测 78 秒（2026-10-16，Chrome、1440 宽）。**条数和秒数都会随改动变，要引用就重量一次**——别把 78 抄下来当常数。而一次改动的实际影响面通常只有一页：

```bash
# 看有哪些可以单独跑的名字
node design/scripts/console-states.mjs "…控制台演示.html" design/shots/console --list

# 只跑改动的那一页（「账号」那一组约 5 秒，「设置」那一组约 18 秒；都是 2026-10-15 实测）
node design/scripts/console-states.mjs "…控制台演示.html" design/shots/console --only account

# 也可以按事跑：auth / keys / list / detail / settings / layout
node design/scripts/console-states.mjs "…控制台演示.html" design/shots/console --only settings,layout
```

**`keys` 这个分组是 2026-10-15 补的**：访问凭据那一页在这之前**只有状态截图、一条交互断言都没有**（那个「十个状态」的版本没有进过仓库，所以这里不写那个数——按 §2.3，写出来的数要能被复算），而三轮审计每一轮都在这一页上找到东西。它现在守着这几轮修掉的那几处——续期真的换掉到期日、两次续期两条都在地址里、那一刻的卡片说的正是标题那把、两个图标真的换、Esc 与焦点回到原处、**完成落到的列表里确实有刚建的那把**（连创建成「两周内到期」的那种也算）、**面包屑与完成去同一处**、**四格计数与搜索是同一套数**、**离开那一刻屏会先问一次而且问得动**（面包屑与左侧导航各断言一次；问句说后果、两个答案说自己去哪、焦点在「仍然离开」上；Esc 回答留下之后出口与整串都还在；**整串拿走之后同一个出口不再问**）。

**每次运行都会先印出它这次跑了哪些状态与分组**——因为选择是按前缀的，而前缀会重叠（`--only skill` 会连 `skills-ready` 一起选中）。看见了比事后推断好。

⚠️ **检查脚本跑的是构建产物，不是 `demos/` 里的源稿。** 源稿里那句 `@partial` 是个洞：直接打开源稿会缺一整块浮层。改设计改 `demos/`，然后构建，然后检查。

检查脚本跑**有头模式**（会短暂弹出浏览器窗口），这是有意的：无 GPU 的 headless 会静默跳过 `backdrop-filter`，首页那份的遮罩截出来背景会是清楚的。控制台那份没有用 `backdrop-filter`，但它和另外两个一样有头，理由一样——截图应该是人看到的那一屏。

## 已知的取舍

- 🔵 **授权屏上那句「凭据可以随时用 `skillmaster logout` 撤销」已经改成真话（2026-10-16），产品侧等这一版的实现再跟。** v2 起 `logout` **只删本机那一份、不再撤销服务端**（[ADR 0038](../docs/decisions/0038-default-credential-is-an-api-key.md) §决定 7），所以那句话承诺了一件做不到的事——而它出现在**产品唯一的披露时刻**上，读的人会以为登出等于撤销，然后带着一个**还活着的授权**离开。现在写的是「要结束它，请重置密码——这会一并撤销这台机器上的授权」，与 CLI 自己那句（`whereToRevoke`：「服务端那份是浏览器登录换来的授权：控制台没有它的入口；重置密码会一并撤销它」）是**同一个事实、同一种说法**。**产品页面 `skillmaster-web/src/pages/ConsentPage.vue` 仍是旧的那句**，这一版的实现那一步一起改；缺口记在 [`known-issues.md`](../docs/versions/v3-sessions/known-issues.md) 条目 001。**这一句此前既没有断言守着、图也是旧的**（`shots/states/12-consent.png` 上还印着 `skillmaster logout` 那一句，改文案时没人重跑它）——2026-10-16 补上：`interaction-check.mjs` §8 现在有一条断言钉着「说的是重置密码、不是 logout」，那三张授权屏的图也重出了一遍。

- 🔴 **`unlisted` 已经被放弃了，但 schema 与目标态还写着它。** 这里定下的模型是**只要公开就会被搜到**——公开是一件事，不是两件；这条 2026-10-10 写成了 [ADR 0037](../docs/decisions/0037-visibility-has-two-states.md)（`skill.visibility` 与 `namespace.visibility` 两列都只留 `private` / `public`）。**产品今天只写 `private`，所以那两处列注释与 `docs/target/design.md` 的 S11 都还没动**——回改已应用的迁移会破坏 Flyway 的校验和（等下一次动那两张表的迁移），target 那边的缺口记在 `docs/target/README.md` 差异清单第 10 条。
- 🔵 **每个版本的「说明」是前瞻性字段，产品今天填不出来。** `skill_version.changelog` 这一列在 schema 里（`V1__baseline.sql` §3.3），注释写明 **Free text from the author. v1 has no endpoint that sets it.** —— 也就是说 v1 里它永远是空的。它现在出现在**两个地方**：文件表表头那一行（那是线上版本的说明）、以及「版本」那一栏的三行。**其余的（提交人、版本号、时间）都是真字段**（`published_by` / `number` / `published_at`）。做进来是为了让这一屏在有了那条接口时不用重做；**演示件里那三句说明都是编的**。同一份文件里，文件树本身（三条：`SKILL.md`、`references/split.md`、`scripts/compress.sh`）、每个文件「最后改它的版本」，也都是编的。
- 🔴 **演示件走在了产品前面：它没有「草稿」这个概念了。** 演示件现在是「提交即上线」——版本只有**线上**与**历史**两种，每个 skill 都有线上版本（所以每栏的胶囊都是「已上线 @x」，没有「未上线」），没有「待上线」「已丢弃」，也没有上线/丢弃那两个动作。skill 详情页、版本下拉、底部演示条里的对应项一并去掉了。
  - **这是刻意的分叉，产品没有跟。** 产品里 [ADR 0031](../docs/decisions/0031-submitting-and-publishing-are-two-actions.md) 把「提交」与「上线」拆成两个动作：提交产生 `draft`，上线是另一条路径、只在浏览器面。演示件按最新的设计意图把它整个去掉了。
  - **产品那边真要跟，代价是**：`skill_version.state` 那列与 `V10__submitting_is_not_publishing.sql` 这次迁移、CLI 的 `submit`／`publish` 拆分、消费面每一处 `state = 'published'` 的过滤，以及「editor 能提版本但不能上线」这条共享语义（ADR 0034）；按仓库规矩还得先写一条新 ADR 取代 0031。
  - **动手前值得再看一眼 0031 挡住的是什么**：消费者是**作者自己的 agent**，拿着同一个账号经 `/api/v1` 读——提交即上线，agent 就会在作者写第九版的时候照着第八版半成品把活干完。
  - 因此 `skillmaster-web/` 与 `skillmaster-cli/` 里仍是三态，**与这里的演示件不一致**；两条都还在，谁也没被改。

- **授权请求那一屏故意没有页面入口。** 它只能靠地址打开（见上一节），因为它本来就不由网站触发——是 CLI 把浏览器领过去的。它开起来时会**整个压掉首页**（用不透明的纸色地面），首页在它底下根本不显示：那一屏底下本来就没有网站。别为了「好点」给它加一个首页入口，那是把两件无关的事接在一起。
- 🔴 **找回密码的三步链路与已上线产品不一致。** 产品里的 `skillmaster-web/src/pages/ResetPage.vue` 是**一屏表单**（`POST /web/reset` 一次带手机号 + 验证码 + 新密码）；这个演示件按最新的设计意图做成了**三步**。两条都还在，谁也没被改。**要把产品也改成三步，是另一件事**（而且「第二步判定验证码是否正确」在现有接口里没有对应的调用——`/web/` 底下**账号那一组**十个端点里没有「校验验证码」这一个；说「账号那一组」是因为 `/web/skills` 底下还有**十个**（`WebSkillController` 里十个处理函数），光写 `/web/*` 会让人数出 20 个来）。

- ⚠️ **别删掉 `lockScroll()` 里的那两行补偿**。浮层打开时页面被锁滚动，滚动条一消失，可视宽度就宽了 15px，居中的内容会整体**右移 7px**（这是修过的一个 bug）。那两行把同样的宽度补回 body，页面才纹丝不动。`interaction-check.mjs` 里有一条测试守着它——**而且那条测试跑在强制经典滚动条的环境里**，因为在 macOS 的 overlay 滚动条下这个 bug 根本不会出现，测试会假过。
- **遮罩不是「压暗」而是「虚化」**：`rgba(253,252,250,0.86)` **加上** `backdrop-filter: blur(7px)`。这不是审美偏好，是实测结论——在这么浅的底上**只靠 alpha 藏不住背景**：0.90 / 0.95 / 0.97 / 0.98 一路试下来，大号的近黑标题始终看得清；换成深色遮罩更糟。想调强弱就改这两个值。
- **注册和找回密码没有页面级横幅**。真实产品在这两处有（限流「操作太频繁了」、发送结果不确定那句），但在没有后端的演示件里都不可达，所以没做。可触发的错误全部落在字段上，与真实实现一致。
- **图形验证码的答案能读出来**：它是内联 SVG，答案是画在里面的文字。真实产品的图是服务端随机生成的 PNG，而且是一次性的。演示件里它只在**发码**时校验，发过就换。
- **短屏要滚动**：注册第一步加图形验证码那个状态约 906px 高，在 720p 的笔记本上浮层内部会滚动。这不是漏做——`overflow-y:auto` + `align-items:safe center` 是有意为之，顶部不会被截掉，实测滚 234px 后按钮可点。
- 页面高约 2765px，是三版里最长的——这是呼吸感的代价。
- 只做了浅色。产品本身有暗色主题，这个演示件没有跟。
- 首页与控制台的真实代码是两套东西：这里改的是**演示件**，不会自动同步到 `skillmaster-web/`。

- 🔵 **「访问凭据」那一页的凭据是 fixture，产品今天签不出它们。** `api_key` 表与那几个端点已经设计定稿（[ADR 0038](../docs/decisions/0038-default-credential-is-an-api-key.md)），**表已经设计定稿**，迁移文件也写出来了（`V13__api_keys.sql`），**但它跟服务端实现一起提，不在这份设计稿里**；**端点一行代码都还没写**（`src/main/java` 底下没有任何 `api_key` 的引用）——所以这一页是「设计走在服务端前面」的第二例（第一例是「调用次数」那一行）。**那列 `note` 是随这次设计补进迁移的**：设计文档先把它写进 DDL 与接口，迁移文件里原先还没有，而那份迁移从未在任何库上跑过（本机 dev 库停在 `V12`），所以改在原地而不是加一版。**五把凭据覆盖四种状态**（活跃 / 两周内到期 / 已过期 / 已撤销），没有纯凑数的重复行。**四格计数是算出来的**，不是写死的：一份计数与自己那几行不一致的 fixture，是没人能拿它核对任何东西的 fixture。

**下面三条是循环审计（2026-10-15）确认下来、决定不修的三条**——每一条都能被当成缺陷报出来，所以写在这里，免得下一轮再报一次：

- **不认识的值一律落回默认屏，而地址不改。** `?page=bogus` 渲染「我的 skill」、`?tab=nope` 落回「文件」、`state=bogus` 落回「正常」——地址里仍留着那个不认识的值。这不是漏了：演示件对地址的承诺是**发出去的链接复现同一屏**，而这一条在兜底确定的时候成立；把兜底也写回地址是另一种做法，只是没做。**顺带一条同类的**：别的页面的参数会跟着地址走（演示条只留目的地读得懂的那些），而技能列表读不懂 `filter`——它只是躺在那里。
- **顶栏那个搜索框不会被 `q` 填上。** 它是「跳到搜索」的入口，不是当前列表的筛选框：在 `?page=keys&q=CI` 上把它填成 `CI`，会让人以为它筛的是密钥列表。
- **手写地址能让两行共用一个 id**（`?…&made-id=k2&…`，撞上 fixture 的 `k2`）。表单铸的 id 不可能撞（`k` + 6 位随机），所以这条路只有手改地址才走得通；真撞上时，按 id 找行的那几处（撤销、续期、焦点回收）取的是一致的**第一行**——也就是刚建的那把。**没有去校验它**：那会把「地址是这一页的全部状态」改成「地址还要先过一遍冲突检查」，而这是演示件里唯一一处连产品都不会遇到的情况（产品那边 id 由服务端铸，地址里是 ULID）。
- **导航与侧栏的链接是一次「新访问」，不带这一页的事实。** 侧栏那两项「API 密钥」是写死的 `?page=keys`（导航要呈现在每一页上，它没法知道某一页正拿着什么），所以刚建完一把密钥之后从侧栏再进这一页，那一把就不在列表上——它的唯一存放处是地址。**面包屑不是这一类**：它是这一屏的父亲，见上面那一节，它跟着走。（「新访问」这条与下面「不认识的参数跟着地址走」是同一类：地址是这一页的全部状态，而**别的页面上的链接说的是别的页面**。）
- **已经撤销的那把，它的「已创建」那一刻还能打开**（`?…&state=created&made-*&revoked=<id>`，只有走演示条才凑得出来）。那一屏说的是**创建那一刻的响应**，而那件事确实发生过——与「续期一把已撤销的 key」不同，后者是被拒绝的转换而不是历史。串本身已经死了，而这一屏不会替你说这句话：它是一份历史回执，不是一把钥匙的当前状态。
- **登录浮层开着的时候，底部那条演示带只能用鼠标点。** 浮层有自己的焦点陷阱（那是它对的地方），Tab 出不去；三个登录屏之间的切换还能走浮层自己的「注册 / 忘记密码 / 去登录」，所以不是死路。

### 关于共享片段这一版

- 🔴 **控制台未登录时，控制台不在那张纸下面。** 它用 `is-standalone`（不透明纸色地面）把页面整个压掉，而不是像首页那样把底下的页面虚化留着。理由：未登录的控制台**没有内容可显示**——「我的 skill」不是一个对匿名者有答案的问题——把刚才那一次的 skill 列表（哪怕虚着）留在登录屏背后，是一个不该被当成示范的状态。要改回虚化：把控制台宿主里 `SkillMasterAuth.open(page, {...})` 的 `standalone: true` 去掉，同时把 `dismissible` 改成 `true`（否则关掉就是一片空白）。
- **`dismissible: false` 是这一屏的要害**：没有关闭按钮，Esc 和点遮罩都不响应。理由同上——关掉它没有地方可去。
- ⚠️ **片段自带三条「借来的」基础样式**（品牌标记的尺寸、`.btn`、`[hidden]`）。这三样在首页由它自己的基础 CSS 顺带提供，控制台没有——第一次落进去时，标记被渲染成填满卡片的巨大色块、「登录」按钮是个没样式的方框、两个眼睛图标同时显示。**这是这个做法的真实代价**：片段与宿主之间除了那组 CSS 令牌，还潜藏着「宿主的基础样式」这一层依赖，而它不会报错，只会看起来不对。
- **代价二：多了一步构建。** 源稿不再能直接打开（`@partial` 是个洞），三个检查脚本也都改跑构建产物。好处是浮层只有一份，两份演示不会漂。
- **构建脚本按行匹配标记**，所以**片段里不能出现长得像标记的整行**——最初的片段头部把标记当例子写了出来，其中的 `--` 提前关掉了 HTML 注释，于是整段头部漏成了页面上的文字（控制台因此凭空高了 115px，而首页那 66 项交互检查一条都没抓到，因为它查的是行为不是版面）。
