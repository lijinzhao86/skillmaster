# SkillMaster 营销首页 · 三方向共同 spec

这是三个方向**唯一的共同输入**。三个方向只看这份 spec，互不参考，各自独立产出。

## 一、这是什么

**SkillMaster 的营销首页**——面向开发者的对外门面。SkillMaster 是技能托管服务：作者把 AI 技能（一个 `SKILL.md` + 若干文件）发布成带版本的 skill，团队里每个人在任何 agent 里一行地址就能加载。**产品本体是 CLI + 网页控制台；这个首页不接任何后端，是纯前端演示件**，用来做视觉与交互设计，设计师可以参与修改。

## 二、受众与场景

**开发者 / 技术用户**。他们打开这个页面时脑子里在问的是：「这东西凭什么比我直接拷文件夹好？」所以页面的活儿不是煽情，是**在三十秒内把「版本、权限、一行加载」三件事说清楚，并且让人相信做这个产品的人懂开发**。

使用场景是桌面浏览器，通常是在 GitHub、Hacker News 或同事的 Slack 里点进来。

## 三、情感基调

**克制的专业感**。不热闹、不喊口号、不堆装饰。要有「工程师给自己人造的工具」那种诚实。用户本次明确要求：**要简洁的视觉**——不要繁复、不要密集到压迫、不要花哨。

## 四、内容（真实文案，一字不改，不许用 Lorem）

**导航（未登录态）**：`SkillMaster` ｜ 文档 · CLI · 协议 · 更新日志 ｜ `登录` `开始使用`
**导航（已登录态）**：`SkillMaster` ｜ 文档 · CLI · 协议 · 更新日志 ｜ 首字母圆形头像 `d` · `dev@skillmaster.io` `控制台` `退出`

**Hero**
- 眉标：面向 AI 技能的托管服务
- 主标题：把你的 skill 托管起来，任何 agent 一行加载。
- 副标题：带版本、带权限。发布一次，你团队里每个人的 agent 拿到的是同一个。

**终端演示**（窗口标题栏 `zsh — skillmaster`）
```
$ skillmaster skill invoke demo/pdf-tools
（按 demo/pdf-tools@1.2.3 取。）
# pdf-tools

```

**第二段 · 痛点**
- 标题：现在共享 skill，靠的是拷文件夹
- 说明：拷过去的那份，改了、旧了、谁改的，没人知道。

**三个卖点（编号 1 / 2 / 3）**
1. 版本不会漂 —— 地址里钉版本（`@1.2.3`）或取当前。今天加载的，明天还是同一个——不会在你不知道的时候被换掉。
2. 谁能读，你说了算 —— 把 skill 共享给谁、给 viewer 还是 editor，一个面板管完。不给的人，连它存在都看不到。
3. 一行加载 —— 不用拷文件夹、不用配路径。`invoke` 之后，agent 手里就有它了。

**第三段 · 三步**
- 标题：三步，把你的 skill 交出去
- STEP 01 写一个 SKILL.md —— 正文加需要的文件，放在一个目录里。它是什么、怎么用，写在正文里。
- STEP 02 提交 —— 一条命令推上去，它会开网页让你确认这次改动，再决定要不要上线。`skillmaster skill submit`
- STEP 03 在任何 agent 里加载 —— 把地址给 agent，一行就加载进来。团队里谁都能用同一个。`skillmaster skill invoke <命名空间>/<名字>`

- `SkillMaster` · 把你的 skill 托管起来，任何 agent 一行加载。
- 分组一：产品 · 文档 · CLI · 协议

## 五、必须能点的交互（这是本次交付的重点，不是装饰）

整页是**一个能操作的原型**，下面每一条都要真的能用。

**浮层是一个容器，里面换视图**：登录、注册、找回密码都住在这一个浮层里，不跳页、不新开文件。外壳（遮罩、那张纸、品牌行、标题、关闭按钮）三条流程共用。

**外壳**

1. 点导航的「登录」（或 hero 的「开始使用」）→ **打开浮层**。遮罩必须覆盖**整个视口**，不是只盖住一部分。
2. 点遮罩、点右上角 ×、按 `Esc` → 关闭浮层，首页回到原状态。出现与关闭要有过渡，不要硬切。
3. **打开浮层时首页不许位移**：锁滚动会让滚动条消失、可视宽度变宽，居中的内容会右移，必须把那段宽度补偿回去。

**登录**

4. 两个输入框都能真的输入：**手机号**、**密码**。密码框右侧有个**眼睛图标在框内**，点了能在明文与圆点之间切换（用真实图标集路径，不要自创控件）。
5. 点「登录」提交，按输入走三条分支：
   - **空或格式不对** → 在**对应字段下方**给提示：「这一项必填。」/「请填写 11 位的大陆手机号。」
   - **手机号 `13800138000` + 密码 `wrongpass`** → 在表单**顶部**出一条错误条：「手机号或密码不正确。」
     ⚠️ **这条不许挂在密码字段上**。服务端对「没注册的号」「密码错」「账号停用」回的是同一句话，挂在字段上等于告诉攻击者这个号存在。
   - **手机号 `13800138000` + 密码 `skillmaster`** → **登录成功**：浮层关闭，首页**导航切成已登录态**。正文不变。

**注册（两步）**

6. 第一步是**用户名 + 手机号 + 密码**，**不是**先填手机号。用户名下方**异步查重**：输入停 400ms 后判定、失焦立即判定，三种可见状态 `检查中…` / 打勾 / 错误文案。
7. 点「下一步」发码 → 第二步填**六位验证码**。**退回第一步时，之前填的值必须还在。**
8. 图形验证码**第一次发码不出现**，之后的发码才出现。
9. 成功后进**注册成功**页；点「开始使用」关浮层并切成已登录态。

**找回密码（三步）**

10. **第一步**只有手机号 + 图形验证码，点「下一步」**发送验证码**并进入第二步。号码没注册**在这一步**就被拒（不是走到最后才说）。
     ⚠️ **这里与已上线产品分叉**：`skillmaster-web/src/pages/ResetPage.vue` 是一屏表单（`POST /web/reset` 一次带手机号+验证码+新密码）。三步是本演示件采用的设计，产品尚未跟。
11. **第二步**填六位短信验证码，**没有提交按钮**——填满六位就自动判定并前进。判错则错误落在验证码字段，并**清空六格**让人重填（留着六个错的会变成一个「看起来填好了、却没得可填」的框）。
12. **第三步**才问新密码。成功后进**密码已重置**页，写明「这个账号在所有设备上的登录都已经失效」，点「去登录」回登录视图；**不自动登录**。
13. ⚠️ **图形验证码只属于发码那一步**，第二、第三步都不校验它。发码成功后图形码框会被清空并换新图——挑战用掉就作废，若再校验一次，**没人能通过**。

**授权请求（没有页面入口）**

14. **页面上不许有任何通往它的入口。** 真实场景里它不是从网站点进去的——是 CLI 把浏览器领到一个带 `client_id` / `state` / `scope` 的地址上。所以入口就是地址：带了 `client_id` 或 `state` 之一就当「CLI 交过来的」，直接开这一屏；不带就是首页。
15. 它开起来时**整个压掉首页**（不透明纸色地面，不是别的视图那种虚化背景）——那一屏底下本来就没有网站。
16. 两个状态：**正常**（**预填、可改的名称**——值由 CLI 从地址的 `name` 带来，清空则「同意并继续」点不动 + 客户端名 + 权限写成**后果**而不是名字 + **一行寿命**「7 天或闲置 24 小时后失效」+ **一行出路**「到控制台的「登录设备」中退出」+ 同意/拒绝）、**链接不完整**（缺参数时说清缺什么，让人回终端重跑 `skillmaster login`）。**权限来自地址、这一屏上不可勾选**，也不是"长期凭据的说明"——2026-10-16 改（见 [`README.md`](README.md) §怎么打开「授权请求」）。
17. ⚠️ **焦点不许落在「同意并继续」上。** 落在那里，一个回车就等于同意了还没读的内容。
18. 同意 / 拒绝之后那两句用 **CLI 回环页的原话**（`授权成功` /「回到终端继续。」；`授权未完成` /「你拒绝了这次授权请求。」），而且这一页本身在 [`README.md`](README.md) §授权结果 里定过版式（与请求那一屏同一张卡、没有关闭按钮）与收场方式（**会走的倒计时 3 → 2 → 1，到点自己关；关不掉就当场改口**）。
19. 未知客户端显示原始 id **并给警告**；未知 scope 显示原始值**并明说不知道它的含义**——留白会被读成「无害」。

**共用规则**

20. 每条错误**落在字段还是表单顶部**，必须与真实实现一致（`verification_code_invalid` 落在验证码字段，`invalid_credentials` 落在顶部横幅）。
21. 六格验证码是**一个真 `<input>` 铺在六个装饰方格上**，点哪格光标落哪格——不是六个 input。
22. 「N 秒后可重发」的冷却状态要能看见。

## 六、输出格式与尺寸（三版必须完全一致，否则无法横向对比）

- **单个自包含 HTML 文件**，双击就能开。**不用构建、不用 CDN、不引外部字体文件**（系统字体栈即可）。
- 设计宽度 **1440px**，页面可纵向滚动（内容大约 1900px 高）。窄屏要能降级，但不是本次重点。
- 图片走相对路径 `../assets/console-light.png`（后续会内联，先按路径写）。
- 文件名 `demos/<方向名>.html`。

## 七、已知约束

- **品牌色必须保留**：主色 `#2563eb` 是唯一强调色。其余（字体、版式、密度、圆角、动效）**放开**。
- 完整的调色板、字体栈、标记 SVG 见同目录 `brand-spec.md`，直接取用，不要另发明颜色。
- **可读性硬底线**：正文 ≥14px、标签/注释 ≥12px、正文对比度 ≥4.5:1。**留白必须是构图**——首屏要有一个明确的视觉落点，不能是「大片空白 + 缩小的字」，那看起来像页面渲染坏了。
- 反 AI slop：不要紫色渐变、不要 emoji 当图标、不要每个标题都配装饰图标、不要编造数字与客户 logo。

## 八、图片

**图片不是内容必需**——这是工具型产品，靠排版与代码说话，不靠配图。**不要去找或生成装饰性配图**。

唯一允许用图的地方是**展示产品真身**：`../assets/console-light.png` 是已落地的控制台真实截图。用不用、怎么用由一个方向自己判断；若用，**必须是这张真图**，不许用色块或手绘 SVG 假装成界面。

## 九、视觉母题（每个方向都要回答「form 来自内容的哪里」）

这个内容独有的东西是：**skill 是一个地址**——`命名空间/名字@版本`，如 `demo/pdf-tools@1.2.3`。它是一串拿等宽字排出来的、可以钉死的东西。它是本产品最本质的视觉对象，也是「版本不会漂」这句话的证据。另一个母题是**「一行」**——`一行加载`、一条命令、一行地址。

每个方向交付时写一句话说明：这个设计的形式从哪里长出来。

## 十、三版必须互异

三版的**布局骨架必须结构性不同**（导航形态、主区构图、内容组织至少一项不能相同）。只换颜色和字体 = 换皮，不算三个方向。
