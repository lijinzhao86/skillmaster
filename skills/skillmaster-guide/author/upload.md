# 把本地一整个目录提上去

> 适合「一次给一大坨」：第一次搬上来、整体改版。**内容有变化就落成一份新草稿；和已有版本一模一样时，它直接返回那一版，不会再开新的。**

## 先判断用哪种

| 你的情况 | 用哪个 |
|---|---|
| 第一次把整个目录搬上来 | `submit` |
| 整个目录都变了（重排、大量文件） | `submit`，然后把旧草稿丢弃 |
| 只改一两个文件，或接着改手上的草稿 | `edit` / `write`，见 [改一个 skill](edit.md) |

## 整目录提交的命令

```bash
skmr skill submit ./my-skill --name "这一版的名字" --note "一句话说明"
```

- **地址里的名字取自 `SKILL.md` 的 frontmatter，不是目录名。** 而且 frontmatter 的 `name` 必须**和地址第二段一字不差**，否则会被拒。
- 网页上也可以：「我的 skill」→「导入本地 skill」；或者版本列表里的「导入压缩包」。

- **完成信号**：正常情况下打印版本码和审批地址。**如果提示「内容未变」**，说明这一版和已有版本完全一样，没有新草稿可发——改点东西再来。

## 提交之后

1. 先自查：`skmr skill check <地址>@<版本码>`——**它检查的是服务端那一版，不是你的本地目录**，所以只能在提交之后跑。
2. 打开打印出来的地址上线，见 [把一版草稿上线](../ship/release.md)。
3. 这次如果替代了一份旧草稿，别忘了把旧的丢弃。

## 整目录提交时要注意的

- **整包导入有 128 MiB 的临时上限。** 更大的目录改用 `write` / `put` 逐个文件传，见 [上限](../limits/quotas.md)。
- **最容易踩的是路径**：只有带 `/`、或以 `./` `~` 开头才算路径；裸名字会去 `SKILLMASTER_SKILLS_DIR` 里找，不是当前目录。
- **`--release major|minor|patch`** 说明**版本类型**（这次改动多大）——它不是版本号，版本号在上线时才算。
