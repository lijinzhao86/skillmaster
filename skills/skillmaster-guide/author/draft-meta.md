# 给这一版起名、写说明、定版本类型

> 这三样**不改变内容**，只影响别人怎么看到这一版，以及下一次上线时版本号怎么算。其中「版本类型」就是**这次改动多大**。都只能在**草稿**上改——上线之后这一版就冻结了。

## 改名称、说明、类型的三条命令

```bash
skmr version rename <地址>@<版本码> --name "新名字"
skmr version note   <地址>@<版本码> --note "这次改了什么"
skmr version note   <地址>@<版本码> --clear
skmr version release-type <地址>@<版本码> minor
```

- **完成信号**：每条命令报告改成了什么。

## 什么时候会用

| 情况 | 用 |
|---|---|
| 在网页编辑器里新建了一版，还没起名 | `rename` |
| 上线页上别人看不出这一版改了什么 | `note` |
| 这次改动比预想的大（或小） | `release-type` |

## 版本类型是什么

`major` / `minor` / `patch` / `none`。它**不是版本号**——它是下一次上线算号的依据。版本号（`1.0.0` 这种）在上线那一刻才定。

## 起名与写说明的经验

- **名称是别人在版本列表里看到的那一行。** 写「修一下」「更新」等于没写。
- **说明写「改了什么」，不是「改好了」。** 半年后回来看，只有前者有用。
- **上线之后就改不了了。** 发现名字起错，只能在下一版里改对。

## 改名称出错怎么办

- **找不到版本码**：`skmr version list <地址> --status draft` 核对。
- **提示不能改**：它多半已经上线了，见 [把一版草稿上线](../ship/release.md)。
