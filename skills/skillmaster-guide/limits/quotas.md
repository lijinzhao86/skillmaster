# 上限

> 一个 skill 能装多少、单个文件能多大。**撞上上限的表现是整份提交被拒**，不是悄悄丢一个文件。

| 项 | 上限 |
|---|---|
| 一版的文件数 | 512 |
| 单个文件 | 100 MiB |
| 一版的总大小 | 512 MiB |
| 整包导入（`submit`、网页导入压缩包） | 128 MiB，**临时上限** |

文件数是**按一版算**的，多个版本不合计。整包导入那条是临时上限：超过就改用 `skmr skill write --from` 逐个文件传，没有 128 MiB 的限制。

## 16 MiB 是什么

16 MiB 不是上限。文本超过 16 MiB 时，服务端不再统一处理换行、BOM 与编码，**按原字节保存**。也就是说：小文本会被规整，大文本保持原样。单文件 100 MiB 的线仍然在。

## 会遇到它的时候

- **把整个仓库提上来**：依赖目录、构建产物很容易把文件数顶到几百。
- **传视频、大 PDF**：单文件 100 MiB 是硬线。
- **一个特别大的文本文件**：内容不会被规整，可能和你本机看到的换行不一致。

## 撞上上限怎么办

- **文件数超了**：先清掉不该进 skill 的东西（依赖、产物、缓存）。
- **单个文件太大**：拆开或压缩。**换 `skmr skill write --from` 绕不过去**——它同样受 100 MiB 限制。
