# 上传不上去

> **先读报错原文。** 这条链路有几种完全不同的失败——没权限、版本码不对、内容有问题、内容没变化、已有一份草稿——搞混了会白试半天。分不清时先跑一次下面的命令，确认版本码对得上。

```bash
skmr version list <地址> --status draft
```

**症状**：`skmr skill submit`、`skmr skill write` 或 `skmr draft create` 报错。

## 上传报错怎么找

| 看到 | 原因 | 怎么做 |
|---|---|---|
| 内容未变 | 这一版和已有版本完全一样，没有新草稿可发 | 改点东西再来 |
| 这一版还没有名称 | 缺 `--name` | 补上再跑 |
| 没有写入档 | 权限不够 | 请对方给你「写入」 |
| 草稿或目标路径找不到 | 版本码不对，或目标路径写成了 `.` | 核对版本码；根目录的文件直接写文件名 |
| 这一版在读过之后被改动过 | 期间有人改了同一份草稿 | 重新完整读一次那个文件，再带 `--overwrite` 重跑 |
| 已有一份没上线的草稿 | `submit` / `draft create` 不另开，直接拒绝 | 接着改那一份；另开先问用户，确认后加 `--new` |

## 文件太大

见 [上限](../limits/quotas.md)——注意换 `skmr skill write --from` 绕不过单文件上限。

## 排查上传问题时要注意的

- **「内容与线上一样」不是故障。** 它意味着这次没改到点子上，回头看看改的是不是那一份草稿。
- **写文件前草稿要先存在。** 报「草稿找不到」时先 `skmr draft create`，见 [开一份新草稿](../author/draft-create.md)。
