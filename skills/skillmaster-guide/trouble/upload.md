# 上传不上去

> **先读报错原文。** 这条链路有四种完全不同的失败——没权限、版本码不对、内容有问题、内容没变化——搞混了会白试半天。分不清时先跑一次下面的命令，确认版本码对得上。

```bash
skmr version list <地址> --status draft
```

**症状**：`skmr skill submit`、`skmr skill put` 或 `skmr skill write` 报错。

## 上传报错怎么找

| 看到 | 原因 | 怎么做 |
|---|---|---|
| 内容未变 | 这一版和已有版本完全一样，没有新草稿可发 | 改点东西再来 |
| 这一版还没有名称 | 缺 `--name` | 补上再跑 |
| 没有写入档 | 权限不够 | 请对方给你「写入」 |
| 名字属于一个已删除的 skill | 这个名字被占着 | 换个名字，或请所有者恢复 |
| 草稿或目标路径找不到 | 版本码不对，或 `put` 的目标路径写成了 `.` | 核对版本码；根目录的文件直接写文件名 |
| 这一版在读过之后被改动过 | 期间有人改了同一份草稿 | 重新跑一次命令 |

## 文件太大

见 [上限](../limits/quotas.md)——注意换 `put` 绕不过单文件上限。

## 排查上传问题时要注意的

- **「内容与线上一样」不是故障。** 它意味着这次没改到点子上，回头看看改的是不是那一份草稿。
- **`put` 不新建草稿。** 报「草稿找不到」时先确认这个 skill 有草稿，见 [传二进制文件](../author/media.md)。
