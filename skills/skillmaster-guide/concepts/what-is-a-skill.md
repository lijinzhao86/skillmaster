# 一个 skill 到底是什么

> 它是一个**能装文件、能发版本的目录**，用 `<命名空间>/<名字>` 找到。别人（或对方的 agent）要不要用它，几乎只取决于 `description` 那一句，和它能不能被搜到。

## 里面必须有什么

- **`SKILL.md`**：入口，必须有，开头 frontmatter 写 `name` 和 `description`。**`name` 必须和地址里的名字一字不差**，否则写文件或提交时会被拒。
- **其余文件**：随便放，按需要才读。

## 这会带来三件事

**一、`description` 是唯一的广告位。** 别人看到的所有 skill 只有名字和描述；正文要等它决定用了才读。怎么写见 [描述、标签与分类](../author/describe.md)。

**二、入口文件每次都被读。** 把它写成一本手册，等于每个用它的人都得多读一遍。怎么组织见 [内容怎么组织](../tips/for-authors.md)。

**三、地址是长期的。** 地址全站唯一，起名要想清楚，见 [命名空间](namespace.md)。

## 对 skill 的常见误解

- **「一个 skill 就是一个文件」**——不对，是一个目录，`SKILL.md` 只是入口。
- **「改了文件别人立刻看到」**——不对，改的是草稿，上线才生效，见 [草稿和线上版本的区别](versions-and-drafts.md)。
