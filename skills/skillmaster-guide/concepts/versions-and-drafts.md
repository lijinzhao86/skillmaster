# 草稿和线上版本的区别

> 你改的永远是**草稿**；草稿上线之后才成为别人能用的版本，而**上线过的版本内容冻结**。几乎所有「以为改了其实没生效」「怎么又冒出一个草稿」的困惑，都来自没分清这两者。

## 你做的每个动作，发生在哪

| 你做的事 | 发生在 | 别人看得到吗 |
|---|---|---|
| 改文件、传文件 | 一份草稿 | 看不到 |
| 提交（submit） | 内容有变化时落成一份新草稿；和已有版本一模一样时返回那一版，不再新建 | 看不到 |
| 上线（publish） | 线上换成这一版，旧的变「历史」 | 看得到 |
| 丢弃（discard） | 这份草稿没了 | 线上不受影响 |

## 五个状态

`skmr version list <地址>` 可以按状态筛：

| 状态 | 是什么 |
|---|---|
| `draft` 草稿 | 还没上线的一版 |
| `live` 线上 | 当前对外提供的那一版 |
| `history` 历史 | 上线过、现在不是当前版本 |
| `revoked` 已下架 | 被撤下来的版本 |
| `discarded` 已丢弃 | 被丢掉的草稿 |

## 上线之后为什么不能改

别人可以按版本码固定用某一版。那一版如果还能变，同一个地址今天和明天跑出来的结果就不一样了。要改，基于它开新草稿。

## 因此，两件容易踩的事

- **提交不等于上线。** 提交只是把内容落成草稿，见 [把一版草稿上线](../ship/release.md)。
- **每轮都提交会攒草稿。** 想接着改，先看看有没有开着的草稿，见 [改一个 skill](../author/edit.md)。

## 对草稿与版本的常见误解

- **「丢弃草稿会把线上那版删掉」**——不会，丢的只是草稿。
