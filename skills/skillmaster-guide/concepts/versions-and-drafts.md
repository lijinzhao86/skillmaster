# 草稿和线上版本的区别

> 你改的永远是**草稿**；草稿上线之后才成为别人能用的**线上版本（线上版）**，而**上线过的版本内容冻结**。几乎所有「以为改了其实没生效」「怎么又冒出一个草稿」的困惑，都来自没分清这两者。

## 你做的每个动作，发生在哪

| 你做的事 | 发生在 | 别人看得到吗 |
|---|---|---|
| 改文件、传文件 | 一份草稿 | 看不到 |
| 开一份新草稿（`skmr draft create`） | 从线上或指定版本复制出一份新草稿 | 看不到 |
| 提交（submit） | 没有你名下的未上线草稿时，内容有变化就落成一份新草稿；已有一份时拒绝并列出它 | 看不到 |
| 上线（publish） | 线上换成这一版，旧的变「历史」 | 看得到 |
| 丢弃（discard） | 这份草稿没了 | 线上不受影响 |

## 版本的五个状态

`skmr version list <地址>` 可以按状态筛：

| 状态 | 是什么 |
|---|---|
| `draft` 草稿 | 还没上线的一版 |
| `live` 线上 | 当前对外提供的那一版 |
| `history` 历史 | 上线过、现在不是当前版本 |
| `revoked` 已下架 | 被撤下来的版本 |
| `discarded` 已丢弃 | 被丢掉的草稿 |

## 上线之后不能改

别人可以按版本固定用某一版。要改，基于它开一份新草稿。

## 因此，两件容易踩的事

- **提交不等于上线。** 提交只是把内容落成草稿，见 [把一版草稿上线](../ship/release.md)。
- **连着提交不会攒草稿，会被拒绝。** 已有一份时接着改它；另开要先问用户，见 [改一个 skill](../author/edit.md)。

## 对草稿与版本的常见误解

- **「丢弃草稿会把线上那版删掉」**——不会，丢的只是草稿。
