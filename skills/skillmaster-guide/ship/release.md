# 把一版草稿上线

> 上线让草稿成为别人能用的版本。上线之后**这一版的内容就冻结了**——要改只能再发一版；但「线上指哪一版」是可以退回去的。命令只负责发起，**确认在网页上点**。

## 先判断这一版能不能上线

| 你的情况 | 注意什么 |
|---|---|
| 第一次上线 | 要定**版本号**，从 `1.0.0` 起步 |
| 日常更新 | 用 `--bump` 选**版本类型**（这次改动多大）：`patch` / `minor` / `major` |
| 上线后发现问题想退回去 | 用回滚，不是重新上线旧内容 |

## 第 1 步：看有哪些草稿在等

```bash
skmr skills pending
```

- **完成信号**：列表里能看到你要上的那一版。

## 第 2 步：发起上线

```bash
skmr version publish <地址>@<版本码>
```

打开那一版的确认页，**在那里点**。网页上也可以：skill 详情 →「版本」→ 那一版 →「操作」。

- **完成信号**：`skmr version list <地址> --status live` 里能看到这一版。

## 退回去：回滚

```bash
skmr version rollback <地址>@<当前线上的那一版>
```

注意参数是**现在的线上版**，不是你想回到的那一版——要退到哪一版，在打开的网页里选。

- **完成信号**：`skmr version list <地址> --status live` 变成你要的那一版。

## 某一版下架 / 重新上架

```bash
skmr version revoke  <地址>@<版本码>   # 只能下架已经是「历史」的版本
skmr version restore <地址>@<版本码>   # 只能恢复已下架的版本
```

**当前线上那版不能直接下架。** 要让它退下来，先把另一版上线（或回滚过去），它就变成「历史」，这时才能下架。

- **完成信号**：`skmr skill versions <地址>` 里它的状态变了。

## 一次发好几版

```bash
skmr skills publish
```

打开「待上线」页：所有还在等的草稿列在一处，勾选后一次上线。只列**你有权上线**的（「维护」及以上）。这一页也能给每一版选版本类型。

## 上线时要注意的

- **上线前跑一次 `skmr skill check <地址>@<版本码>`。** 内容冻结之后再改，只能再发一版。
- **一次上线只含一件事。** 出问题能直接回滚，而不是猜是哪次改动带来的。
- **上线不等于所有人立刻用上**：别人如果固定用了某一版，还会用旧的那一版。
