# 第二块 · 检查、上线（唯一一次）

**这一步做什么**：让他第一次看到自己的 skill 上线、搜得到。主线只在这里上线一次。
**什么时候做**：第二块有了自己的草稿之后。
**做完的标志**：`skmr skills search "<名字>"` 能搜到这一条。

## 步骤

1. **检查**：

   ```bash
   skmr skill check <地址>@<版本码>
   ```

   - 退出码 0、标准输出没有断链行，才算过。有断链时每行长这样：`<路径>:<行号>: <目标> 不在这一版里`；stderr 里的版本注记不用管。
   - 有断链先修（用 `skmr skill edit <地址>@<版本码> <路径> --old <旧目标> --new <新目标>`），修完再 check；上线之后这一版就定下来了，想改要出下一版。

2. **上线**（唯一一次）：

   ```bash
   skmr version publish <地址>@<版本码>
   ```

   跟他说：

   > 还差一步在网页上：我把链接贴给你。打开的是这一条技能的「版本」页，在「操作」那一栏找写着「上线」的那个按钮（按钮上可能带版本号），点它，弹出确认单再点「确认上线」。这一步只是让这一版在你自己库里能用，别人看不到；要不要公开，以后你另外决定。

   - 命令会打印地址（第一行「还没执行：上线只能在网页上由人确认」是正常的）。能打开浏览器就打开，**同时把那条链接贴在消息里**；打不开（例如沙箱拦了）就加 `--print`，只打印地址，请他在任何浏览器里确认。
   - **浏览器里可能还要登录一次**：命令行登录不等于网页登录。碰到登录页就让他用同一个账号登，别替他要密码。
   - **不要替他点，也不要假定已经上线。**

3. **他回来后，先用卡片确认**（两个选项；问句带上「该看到什么」，不要只问「弄好了吗」）：

   > 页面上「<名字>」这一版标成当前版本了吗？

   `好了（推荐）` / `还没好`

   - 他点「好了」：往下核对。
   - 他点「还没好」：先问一句「你现在页面上看到的是什么？」，再按「出问题怎么办」里对应那行处理；**不要重复上线**。

4. **核对**：

   ```bash
   skmr skills search "<名字>"
   ```

   > 搜到了，这条现在是你自己的了，以后你的 Agent 也能直接找到它。想亲眼看见它，打开控制台的「我的 skill」页就能找到。

## 出问题怎么办

| 情况 | 对他说 | 然后 |
|---|---|---|
| 页面打不开 | 我把链接发你，你在自己的浏览器里打开就行。 | 用 `--print` 重新打印地址 |
| 网页让你登录 | 网页和命令行是两套登录：你命令行登过了，浏览器里还得登一次，用同一个账号。登完会自动回到这一页。 | 让他自己登；登进去以后回到「操作」里点「上线」。别让他把密码发给你 |
| `version publish` 命令本身报错（连不上 / 凭据） | 链接暂时生成不了，原因是<原因>。草稿还在，什么都没丢。 | 按报错处理；处理不了就停在这一步 |
| check 报断链 | 这条里面有个地方指不到，我先修一下。 | 用 `skmr skill edit <地址>@<版本码> <路径> --old <旧目标> --new <新目标>` 修完再 check；改完还报就重新看原文再改 |
| check 命令本身报错（连不上 / 凭据） | 现在检查不了，原因是<原因>。草稿还在。 | 按报错处理；处理不了就停在这一步 |
| 上线后搜不到 | 我再核对一下版本状态。 | 先重试一次 `skmr skills search "<名字>"`；仍然没有，用 `skmr version list <地址>` 看当前版本、`skmr skill show <地址>` 看内容。**已是当前版本但搜不到**就说「已经上线了，搜索可能还没跟上，控制台『我的 skill』页能看到」，**不要再上线一次** |
| 他不想上线 | 好，先停在草稿。以后想上线，跟我说一声。 | 按 `SKILL.md` 的「收尾」走（算中途停） |
