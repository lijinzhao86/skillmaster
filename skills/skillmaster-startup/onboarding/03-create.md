# 第二块 · 做一条自己的

**这一步做什么**：让他选一条路——从头写一个简单的，或把电脑上已经有的一条导入进来。
**什么时候做**：第一块完成之后。
**做完的标志**：他有一条自己的草稿（skill + 版本码），进入上线。

## 步骤

1. **用选项卡问**（没有选项卡就把两个选项写进一句话）：

   > 接下来做一条你自己的。你可以从头写一个简单的；如果电脑上已经有写好的，也可以直接导入进来。你想走哪条？

   `从头写（推荐）` / `从电脑上导入`

2. **他选「从头写」**：按 a–f 一件一件做，做完一件再做下一件。

   **a. 先问做什么**（用选项卡，不要让他打字）：

   > 你想让它帮你做什么？

   选项卡（第一个是推荐）：

   `总结一段文字（推荐）` / `检查错别字` / `写一封邮件` / `我自己说`

   - 他点了一个例子：按那个例子起草。
   - 他点「我自己说」：再问一句，按他的原话起草。

   **b. 定名字**：用英文小写字母、数字和连字符，最多 64 个字符，不能以连字符开头或结尾。（服务端只拒空格、`/` `\` `@` `%` `;`，以及 `.` / `..`——按前面这条写最稳。）中文需求按拼音或英文意译起名字，**先用一句人话告诉他这个名字是什么意思**（「这条叫 summarize-text，就是『总结文字』」），再往下走。**frontmatter 里的 `name` 必须和这个名字一字不差**——服务端写正文时会核对，写错会被拒。

   **c. 起草正文**（最短就够，3–5 句）：

   ```markdown
   ---
   name: <b 里定的名字>
   description: <做什么；什么时候用>
   ---

   1. 先看用户给了什么。
   2. 按 <他的需求> 分几步做。
   3. 做完说一句结果。
   ```

   **先给他看**，用选项卡问——**问句里带上这份草稿的关键信息，不要让他往上翻**：

   > 这份叫 <名字>，正文 3–5 句：<一句话概括它做什么>。这样写行吗？

   `可以，就这么写（推荐）` / `我想改一下`

   他点「我想改一下」才问哪里改。

   **d. 存到临时目录**，不写进他的项目：

   ```bash
   SKMR_DRAFT="${TMPDIR:-/tmp}/skillmaster-draft"
   mkdir -p "$SKMR_DRAFT"
   # 把 c 里那段正文写进 "$SKMR_DRAFT/SKILL.md"
   ```

   （`${TMPDIR:-/tmp}` 是给没设 `$TMPDIR` 的机器兜底。Windows 上写 `$env:TEMP\skillmaster-draft\SKILL.md`，建目录用 `New-Item -ItemType Directory -Force "$env:TEMP\skillmaster-draft"`。）

   **e. 建出来**，记下打印的地址与版本码：

   ```bash
   skmr skill create <名字> --description "<做什么 + 什么时候用>"
   # 实际长这样：skmr skill create summarize-text --description "把一段文字概括成几句要点；用户发来长文、想要摘要时使用"
   ```

   **f. 先读占位文件，再整份写回**（本机要记下「你见过当前内容」）：

   ```bash
   skmr skill read <地址>@<版本码> SKILL.md
   skmr skill write <地址>@<版本码> SKILL.md --from "$SKMR_DRAFT/SKILL.md" --overwrite
   ```

   （Windows 上 `--from` 换成 `"$env:TEMP\skillmaster-draft\SKILL.md"`。）

3. **他选「从电脑上导入」**：

   - 先按 `import/01-find.md` 第 2 步的目录表扫一遍本机技能（只要 `<目录>/<名字>/SKILL.md` 这一层），把找到的列成选项卡（第一个是推荐），问句写清这是在挑哪一份：

     > 你电脑上有 <N> 条技能，搬哪一条进来？（N 是这次扫到的条数）

     `<技能 A>（推荐）` / `<技能 B>` / `<技能 C>` / `我自己说`

     找到超过 3 条时只放前 3 条，剩下的靠「我自己说」；不到 3 条的少放几个。

   - 他点了一条：用那个目录。
   - 他点「我自己说」：再问一句「哪一条？说个名字」，按名字找；找不到再问一次。
   - 提交成草稿（`--name` 是这一版的名字，不是 skill 的地址名）：

     ```bash
     skmr skill submit <目录> --name <名字>
     ```

     `--name` 是这一版的名字，1–40 个字符，不能省；用技能自己的名字，超过 40 个字符就截短。
     `<目录>` 要写成带 `/` 的路径（`/Users/你/.claude/skills/foo` 或 `./foo`）——裸名字会被当成 `SKILLMASTER_SKILLS_DIR` 下的名字，不是当前目录。

   - `skill submit` 会打印地址与草稿版本码，**记下来**（后面每条命令都要带它）。
   - 告诉他：这条现在是你自己的一份草稿——草稿就是还没上线的版本，只有你看得见。

## 出问题怎么办

| 情况 | 对他说 | 然后 |
|---|---|---|
| 从头写：名字不合法 | 名字要用英文小写字母、数字和连字符，最多 64 个字符，开头结尾都别留连字符。我换一个：<新名字>。 | 用新名字重试 |
| 从头写：名字被占用 | 这个名字已经有人用了，我换一个：<新名字>。 | 用新名字重试 |
| 从头写：建不出来（网络 / 凭据） | 这条现在建不了，原因是<原因>。你的库里没有多出东西。 | 按报错处理；处理不了就停在这里，按 `SKILL.md` 的「收尾」走 |
| 从头写：写正文被拒（名字和地址对不上 / 版本刚变过） | 名字和这一版对不上，我先改对再写。／这一版刚被改过，我重读一次再写。 | 按报错改 `name`，重读占位文件后整份写回；还不行就停在这一步 |
| 从头写：读不到占位文件（网络 / 凭据） | 现在读不到这份草稿，原因是<原因>。 | 按报错处理；处理不了就停在这里 |
| 导入：目录里没有 `SKILL.md` | 这一条不是完整的技能，我们换一条，或者从头写。 | 换一条；或改走「从头写」 |
| 导入：这条下面已经有一份没上线的草稿 | 这条已经有一份没上线的草稿，我接着改那一份，不另开。 | 照 f 步的命令，用那份草稿的版本码 `skmr skill read …` → `skmr skill write … --from … --overwrite` 继续写；他明确要另开时，先问，同意才加 `--new`，旧草稿用 `skmr version discard <地址>@<版本码> --yes` 丢弃 |
| 导入：本地技能没有 `description` | 这条技能缺一句说明，我先补一句再传。 | 在本地 `SKILL.md` 的 frontmatter 补 `description`（做什么 + 什么时候用），再传 |
| 导入：目录名和 `SKILL.md` 里的 `name` 不一致 | 这条的文件夹名和技能名对不上，我改一下再传。 | 把 `name` 改成目录名（或把目录改成 `name`），再传 |
| 导入：内容没变 | 这份和之前那一版完全一样，没有新东西可传。 | 让他改点内容再传，或直接跳过这一条 |
| 导入：名字不能当地址用（空格 / 斜杠 / `@` / `%` / `;`） | 这个名字在平台上用不了，我换一个：<新名字>。 | 改本地 `SKILL.md` 的 `name` 再传；改不了就换一条 |
| 导入：这个名字是别人的 | 这个名字在平台上已经被别人用了，我换一个。 | 改本地 `SKILL.md` 的 `name` 再传 |
| 导入：传不上去（网络 / 凭据） | 这条现在传不上去，原因是<原因>。你的库里没有多出东西。 | 按报错处理；处理不了就停在这里，按 `SKILL.md` 的「收尾」走 |
| 他中途不想做了（还没建出来） | 好，先停在这里。你的库里没有多出东西。 | 按 `SKILL.md` 的「收尾」走 |
| 他中途不想做了（已经建出来） | 好，先停在这里。你的库里多了一条 <名字>（还是草稿），先留着；想丢掉的时候跟我说。 | 按 `SKILL.md` 的「收尾」走 |
