# 第一块 · 第 2 步 · 加进自己的库

**这一步做什么**：把他挑中的公开 skill 收进他的库，并解释「加到库里」有什么用。
**什么时候做**：第 1 步挑中一条之后。
**做完的标志**：他在自己的库里能看到它，并且用自己的话搜到、加载了它。

## 步骤

1. **先问一句，再动手**（用选项卡，两个选项）：

   > 「<名字>」要加进你的库吗？加了以后你和你的 Agent 在自己库里直接搜得到、加载得到它；它还是原作者维护的那一份，不会复制一份出来。

   `加进库（推荐）` / `先不加`

   - 他点「先不加」：好，先到这里，这条没加进你的库；然后按 `SKILL.md` 的「收尾」走（算中途停）。

2. **加进去**（他点了「加进库」才跑）：

   ```bash
   skmr skill join <地址> --yes
   ```

   **不要复制**：这一步不产生你自己的副本，也不上线。

3. **让他看到结果**：

   ```bash
   skmr skills list
   ```

   > 现在它在你的库里了。你可以直接用它；第二块我们再做一条你自己的。

4. **让他自己触发一次**（用选项卡，不要让他打字）：

   跟他说：

   > 现在轮到你了：你想让它帮你做什么？

   选项卡（第一个是推荐；**按他刚加的那条写，不要照抄下面括号里的例子**）：

   `<按刚加的那条写的一句话>（推荐）` / `<同一件事换一个说法>` / `我自己说`

   （比如他刚加的是「做 PPT」，就写 `帮我做个 PPT（推荐）` / `帮我做一份产品介绍` / `我自己说`。）

   - 他点了一个例子：按卡片上的那句话搜。
   - 他点「我自己说」：再问一句「那你说，想让它帮你做什么？」，按他的原话搜。

   不管是点的还是说的，都按这句话搜**自己的库**（默认就是自己的库，不加 `--scope public`）：

   ```bash
   skmr skills search "<他的原话>" --limit 5
   ```

   - 搜到刚加进来的那条（**搜到多条就挑刚加的那条，别挑别的**）：加载它。

     ```bash
     skmr skill invoke <地址> --yes
     ```

     然后说：

     > 你看，它就在你的库里，直接加载出来了——不用复制，也不用再装。

     再补一句，让他知道以后怎么用：

     > 以后想要什么，直接把你要做的事说出来就行——我会先去你的库里找，找到了就用，你不用记它叫什么。

   - 没搜到：换成那条 skill 的名字再搜一次；仍然没有，就用 `skmr skills list` 找到它，说「它在库里，按名字也能找到」，再 `invoke`。

## 出问题怎么办

| 情况 | 对他说 | 然后 |
|---|---|---|
| join 失败：凭据 / 网络 / 已下线 | 这条现在加不进去，原因是<原因>。你的东西什么都没变。 | 按报错的下一步处理；或回到第 1 步换一条 |
| 已经在库里 | 这条已经在你的库里了，不用再加。 | 进入下一步 |
| 核对时 `skills list` 读不到 | 暂时读不到你的库，先跳过核对；你点的那条我记着。 | 按报错处理；能加载就继续，不能就停在这一步 |
| 他说的搜不到 | 我再按名字找一下。 | 用名字搜；仍然没有就用 `skmr skills list` 找到它再加载 |
| 加载（`invoke`）失败：网络 / 凭据 | 这条现在加载不了，原因是<原因>。它在你的库里，没丢；以后随时能用。 | 按报错里的下一步处理；换 `skmr skill read <地址> SKILL.md` 读一次也一样能看它；都不行就进第二块，不卡在这一步 |
