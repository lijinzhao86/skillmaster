# 第 2 步 · 传上去

**这一步做什么**：把报过名单的技能目录逐个提交成草稿。
**什么时候做**：`import/01-find.md` 报过名单、同名那份也定了之后。
**做完的标志**：至少一个技能成了草稿；失败的那些有记录，留在电脑上。

## 步骤

1. **对他说**：

   > 开始传，一共 12 个。

2. **逐个提交**（**必须带 `--name`**）：

   ```bash
   skmr skill submit <目录> --name <技能名>
   ```

   - `--name` 是这一版的名字，1–40 个字符，**不能省**：本地自己写的技能没有版本信息，不带它，这一个就传不上去，命令会回「这一版需要一个名称」。用技能自己的名字；名字超过 40 个字符就截短。
   - 它把整个目录打成一个包，落成**草稿**；目录里必须有 `SKILL.md`。
   - 一次一个目录。传的时候**你自己**逐个报「第 3 个，共 12 个」——CLI 不打印这句。
   - 失败的不重试，报出哪几个没传成即可，**不要贴原始报错**；不要因为一个失败停住整批。
   - **不要传 `skillmaster`**：它是 SkillMaster 自己的技能，只装在本地。名单里万一有它，跳过。

3. **别说过头**：传上去的是**草稿**，网页上还不能用。

## 出问题怎么办

| 情况 | 对他说 | 然后 |
|---|---|---|
| 一部分失败 | 报出哪几个没传成，说明它们还留在电脑上 | 传上去的那些读 `import/03-publish.md` |
| 传了一部分，他中途不传了 | 已经传上去 N 个，剩下的还留在电脑上 | 读 `import/03-publish.md`，只上线传上去的那些 |
| 一个都没成功 | 我先停在这里：这次一个都没传成，你电脑上的东西没被动过。 | 停住，不再重试；回 `SKILL.md` 的「收尾」 |

## 下一步

有成功的 → 读 `import/03-publish.md`，只上线传上去的那些。
