# 第 4 步 · 备份，再决定清不清电脑上原来那份

**这一步做什么**：把这次上线成功的技能在本地备份一份，再问他要不要清掉电脑上原来那份——不清的话，每次开始做事都会把同一批技能读两遍。
**什么时候做**：`import/03-publish.md` 第 3、4、5 步都做完之后——队列清空、抽的那条验过、试用的例子给过了。
**做完的标志**：备份做好了、核对过里面东西齐全；他要清就清掉了，要留就明确说留。

## 步骤

1. **打包备份**——只备这次上线成功的那些，一个不能少：

   ```bash
   tar -czf <备份目录>/skillmaster-skills-<日期>-<时间>-<第几份>.tar.gz -C <技能所在目录> <技能目录>
   ```

   - **每个技能目录跑一次这条命令**，`-C` 换成那个目录——一个 `-C` 只管它后面的文件。
   - **文件名每次都要唯一**：`<日期>-<时间>` 用这次运行的时间，`<第几份>` 按 1、2、3 往后编；写之前先确认这个名字还不存在，存在就换一个。两个目录常常都叫 `skills`，重名会把前一份盖掉。
   - `<备份目录>` 是用户的主目录：macOS / Linux 用 `$HOME`，Windows 用当前 shell 的写法（PowerShell 是 `$env:USERPROFILE`）——原生命令不一定认得 `~`。
   - 备完逐个看一眼：`tar -tzf <备份>`，每个技能目录都在，数目对得上。

2. **问他**（用这个 Agent 自己的选项组件，没有就把两个选项写进一句话：「清掉，还是先留着？」）：

   > 备份好了，放在 <位置>，以后想找回来跟我说一声。这一步只会删这次上线成功、刚备份过的那 N 个技能；没传成、没上线的都不动。不删也照常用——只是留着这 N 个，每次都会读到两遍；备份在手，想拿回来随时能拿。

   `清掉，备份留着（推荐）` / `先留着`

3. **他选了「清掉，备份留着」才删**：只删第 1 步备份过的那些目录，一个一个删，每删一个报「第 3 个，共 12 个」；删完确认它们不在了。他选「先留着」就不删。

   删的命令是 `rm -rf "<技能目录>"`（Windows 是 `Remove-Item -Recurse -Force "<技能目录>"`）。**如果那个目录在 `~/.agents/skills` 这种多个 Agent 共用的位置**，先跟他说一句「清掉以后，别的 Agent 也读不到这几个了」——他改主意就停手。

   不能删的：这次没传成、没上线的，还有备份里没有的任何东西。

4. **选「先留着」**：不再删，直接回 `SKILL.md` 的「收尾」。

## 出问题怎么办

| 情况 | 对他说 | 然后 |
|---|---|---|
| 备份没做成（写不进去、空间不够） | 我先停在这里：备份没成，电脑上的技能一个都没动。 | 停住，绝不删；回 `SKILL.md` 的「收尾」 |
| 备份做成了，但里面少了东西 | 备份没做全，电脑上的技能我先都不动。 | 停住，绝不删；回 `SKILL.md` 的「收尾」 |
| 删到一半出错 | 说清删到哪一步、哪些还在、备份在哪 | 停住，不要重试，回 `SKILL.md` 的「收尾」 |
| 他说停 | 好，我先停在这里：已经删了 N 个，剩下的都还在，备份在 <位置>。 | 停在下一个目录之前；回 `SKILL.md` 的「收尾」 |
