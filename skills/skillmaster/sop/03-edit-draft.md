# SOP · 在已有的草稿上继续改

接着上次那个草稿改，**不要**再开一个新的。

## 一、先找到版本码

```bash
skmr version list <地址> --status draft
```

第一行就是 `<地址>@<版本码>`。

## 二、改已有文件：逐处 edit

**改一个已经存在的文件，用 `edit`，一处一处换。不要在本机改好整份再 `write`。**

先读平台上的原文。`--old` 要逐字匹配，用 `cat`；`read` 的输出带行号，拿来当 `--old` 匹配不上：

```bash
skmr skill cat <地址>@<版本码> <路径>
```

然后一处一处换：

```bash
skmr skill edit <地址>@<版本码> <路径> --old "<原文>" --new "<新文>"
```

- **本机那份可能已经旧了。** `write` 是整份覆盖：它会把这个草稿上别处（你或别人在网页上做的）改动一起盖掉，也看不出这次改了哪几处。
- **要动的地方多，也仍然逐处 `edit`。** 多几次调用，换来每一处都看得见、也不会盖掉别处。
- **大段替换**用 `--old-file` / `--new-file`，原文和新文各放一个文件，仍然是一次一处。
- **写完一处就往下走**，不用等；最后统一 `check`。

## 三、只有这两件事用 `write`

| 情况 | 为什么 |
|---|---|
| 新建一个文件 | 平台上还没有这个路径，没有原文可换 |
| 整份重写 | 旧内容基本不保留。先 `skill cat` 读一遍当前内容，确认没有别处的改动要留 |

```bash
skmr skill write <地址>@<版本码> <路径> --overwrite < ./文件
```

新加文件不用加 `--overwrite`。

**二进制文件不走 `write`**（图片、PDF、Office、音视频）：用 `skmr skill put`，见
[`07-files.md`](07-files.md)。`write` 只收文本，而且会对换行 / BOM / NFC 做归一。

## 四、查相对引用、交给用户上线

```bash
skmr skill check <地址>@<版本码>
skmr skill open <地址> --tab versions
```

## 做完的标志

改完草稿还在（没开出新草稿）、`check` 通过、你说了「这是草稿，上线要你自己去网页上点」。
