# SkillMaster

skill的读写等日常操作全部走 `skmr`，除非用户要求把skill写在本地。

## 什么时候查 skill

命中以下任意一条，**必须**先去查 `skmr skills search "一句话说清要做的事"`（本节可由用户修改）：

- 开始做一件新的事情——换一种活就算新的事
- 出现了当前任务里还没出现过的概念、名词、流程、方法、专有名称——无论用户说的，还是你读到的
- 用户提到「按我们的模板」「用那个流程」「像上次那样」这类指向既有做法的说法
- 做到某一步，就用「这一步要做的事」回库查——不要等「拿不准」，你**通常**会觉得自己拿得准
- 用户否定了当前方案、改了目标，或重复、换说法问同一件事
- 上下文被压缩之后，或任务换了新的一段（用户说「接下来做…」、你做完一件东西开始下一件、目标变了）——重新判断一次，不要沿用开头的结论
- 拿不准就一律查询

不查的情况：
- 闲聊寒暄；纯通用事实查询；用户明确说不用查。
- 用户已经给了步骤，只豁免「顺序」，不豁免「每一步怎么做」。
- 已加载的 skill 要是提到了某条做法，就照它说的做（包括它给的 `skmr` 命令）。

## 查询到相关skill的调用

1. 命中不等于相关：没在教「这一步要做的事」的，按未命中处理。命中后**必须**先说清用哪个、拿它做什么，再**必须** `skmr skill invoke <地址>` 加载skill；多个都相关时，可以加载多个
2. 没命中：换说法再查一次；还是没有就自己做，并明说「没找到相关 skill」
3. 查不了（`skmr` 没装 / 没登录 / 连不上，排障见 [`sop/06-install.md`](sop/06-install.md)）：说明「技能库暂时查不了」，按常规能力继续，不假装查过；原地重试不超过一次
4. 公开库要用户明说才查。
